ഈ ഭാഗത്തിൽ 🤗 Transformers-ലെ ടോക്കണൈസറുകളുടെ കഴിവുകൾ നമ്മൾ കൂടുതൽ അടുത്തറിയാൻ പോകുന്നു. ഇതുവരെ ഇൻപുട്ടുകൾ ടോക്കണൈസ് ചെയ്യാനോ ID-കൾ തിരികെ ടെക്‌സ്‌റ്റാക്കി ഡീകോഡ് ചെയ്യാനോ മാത്രമേ നമ്മൾ അവ ഉപയോഗിച്ചിട്ടുള്ളൂ; എന്നാൽ ടോക്കണൈസറുകൾക്ക് -- പ്രത്യേകിച്ച് 🤗 Tokenizers ലൈബ്രറിയുടെ പിന്തുണയുള്ളവയ്ക്ക് -- ഇതിലും ഒരുപാട് കാര്യങ്ങൾ ചെയ്യാൻ കഴിയും. ഈ അധിക ഫീച്ചറുകൾ വ്യക്തമാക്കാൻ, [അധ്യായം 1](/course/chapter1)-ൽ നമ്മൾ ആദ്യമായി കണ്ടുമുട്ടിയ `token-classification` (`ner` എന്ന് നമ്മൾ വിളിച്ചത്), `question-answering` എന്നീ പൈപ്പ്‌ലൈനുകളുടെ ഫലങ്ങൾ എങ്ങനെ പുനഃസൃഷ്ടിക്കാമെന്ന് നമ്മൾ പരിശോധിക്കും.

<Youtube id="g8quOxoqhHQ"/>

തുടർന്നുള്ള ചർച്ചയിൽ, "സ്ലോ" (slow) ടോക്കണൈസറുകളും "ഫാസ്‌റ്റ്" (fast) ടോക്കണൈസറുകളും തമ്മിലുള്ള വ്യത്യാസം നമ്മൾ പലപ്പോഴും എടുത്തുപറയും. 🤗 Transformers ലൈബ്രറിക്കുള്ളിൽ Python-ൽ എഴുതിയവയാണ് സ്ലോ ടോക്കണൈസറുകൾ; അതേസമയം Rust-ൽ എഴുതിയ, 🤗 Tokenizers നൽകുന്നവയാണ് ഫാസ്‌റ്റ് പതിപ്പുകൾ. Drug Review Dataset ടോക്കണൈസ് ചെയ്യാൻ ഒരു ഫാസ്‌റ്റ് ടോക്കണൈസറും ഒരു സ്ലോ ടോക്കണൈസറും എത്ര സമയമെടുത്തു എന്ന് കാണിച്ച [അധ്യായം 5](/course/chapter5/3)-ലെ ടേബിൽ നിങ്ങൾ ഓർക്കുന്നുണ്ടെങ്കിൽ, അവയെ എന്തുകൊണ്ട് ഫാസ്‌റ്റ്, സ്ലോ എന്ന് വിളിക്കുന്നു എന്നതിനെക്കുറിച്ച് നിങ്ങൾക്ക് ഒരു ധാരണ ഉണ്ടായിരിക്കും:

|               | ഫാസ്‌റ്റ് ടോക്കണൈസർ | സ്ലോ ടോക്കണൈസർ
:--------------:|:--------------:|:-------------:
`batched=True`  | 10.8s          | 4min41s
`batched=False` | 59.2s          | 5min3s

> [!WARNING]
> ⚠️ ഒരൊറ്റ വാക്യം ടോക്കണൈസ് ചെയ്യുമ്പോൾ, ഒരേ ടോക്കണൈസറിന്റെ സ്ലോ, ഫാസ്‌റ്റ് പതിപ്പുകൾ തമ്മിൽ വേഗതയിൽ വ്യത്യാസം എപ്പോഴും നിങ്ങൾ കാണണമെന്നില്ല. വാസ്തവത്തിൽ, ഫാസ്‌റ്റ് പതിപ്പ് കൂടുതൽ പതുക്കെയായിരിക്കാനും സാധ്യതയുണ്ട്! ധാരാളം ടെക്‌സ്‌റ്റുകൾ ഒരേ സമയം പാരലലായി ടോക്കണൈസ് ചെയ്യുമ്പോൾ മാത്രമേ ഈ വ്യത്യാസം നിങ്ങൾക്ക് വ്യക്തമായി കാണാൻ കഴിയൂ.

## ബാച്ച് എൻകോഡിംഗ്[[batch-encoding]]

<Youtube id="3umI3tm27Vw"/>

ഒരു ടോക്കണൈസറിന്റെ ഔട്ട്‌പുട്ട് ഒരു സാധാരണ Python ഡിക്‌ഷണറിയല്ല; നമുക്ക് ലഭിക്കുന്നത് യഥാർത്ഥത്തിൽ ഒരു പ്രത്യേക `BatchEncoding` ഒബ്‌ജക്റ്റാണ്. ഇത് ഡിക്‌ഷണറിയുടെ ഒരു സബ്‌ക്ലാസാണ് (അതുകൊണ്ടാണ് മുമ്പ് ആ ഫലത്തിലേക്ക് ഒരു പ്രശ്നവുമില്ലാതെ ഇൻഡെക്‌സ് ചെയ്യാൻ നമുക്ക് കഴിഞ്ഞത്); എന്നാൽ പ്രധാനമായും ഫാസ്‌റ്റ് ടോക്കണൈസറുകൾ ഉപയോഗിക്കുന്ന ചില അധിക മെത്തേഡുകളും ഇതിനുണ്ട്.

പാരലലൈസേഷൻ കഴിവുകൾക്ക് പുറമേ, ഫാസ്‌റ്റ് ടോക്കണൈസറുകളുടെ പ്രധാന സവിശേഷത, അന്തിമ ടോക്കണുകൾ വരുന്ന ടെക്‌സ്‌റ്റിന്റെ യഥാർത്ഥ സ്‌പാൻ (span) അവ എപ്പോഴും ട്രാക്ക് ചെയ്യുന്നു എന്നതാണ് -- ഈ ഫീച്ചറിനെ നമ്മൾ *ഓഫ്‌സെറ്റ് മാപ്പിംഗ്* (offset mapping) എന്ന് വിളിക്കുന്നു. ഓരോ വാക്കിനെയും അത് സൃഷ്ടിച്ച ടോക്കണുകളുമായി ബന്ധിപ്പിക്കുക, യഥാർത്ഥ ടെക്‌സ്‌റ്റിലെ ഓരോ അക്ഷരത്തെയും (character) അത് ഉൾപ്പെടുന്ന ടോക്കണുമായി ബന്ധിപ്പിക്കുക, ഇവ തിരിച്ചും ചെയ്യുക തുടങ്ങിയ ഫീച്ചറുകൾ ഇത് സാധ്യമാക്കുന്നു.

ഒരു ഉദാഹരണം നോക്കാം:

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
example = "My name is Sylvain and I work at Hugging Face in Brooklyn."
encoding = tokenizer(example)
print(type(encoding))
```

മുമ്പ് പറഞ്ഞതുപോലെ, ടോക്കണൈസറിന്റെ ഔട്ട്‌പുട്ടിൽ നമുക്ക് ഒരു `BatchEncoding` ഒബ്‌ജക്റ്റ് ലഭിക്കുന്നു:

```python out
<class 'transformers.tokenization_utils_base.BatchEncoding'>
```

`AutoTokenizer` ക്ലാസ് ഡിഫോൾട്ടായി ഒരു ഫാസ്‌റ്റ് ടോക്കണൈസറാണ് തിരഞ്ഞെടുക്കുന്നത് എന്നതിനാൽ, ഈ `BatchEncoding` ഒബ്‌ജക്റ്റ് നൽകുന്ന അധിക മെത്തേഡുകൾ നമുക്ക് ഉപയോഗിക്കാം. നമ്മുടെ ടോക്കണൈസർ ഫാസ്‌റ്റാണോ സ്ലോ ആണോ എന്ന് പരിശോധിക്കാൻ രണ്ട് വഴികളുണ്ട്. ഒന്നുകിൽ `tokenizer`-ന്റെ `is_fast` ആട്രിബ്യൂട്ട് പരിശോധിക്കാം:

```python
tokenizer.is_fast
```

```python out
True
```

അല്ലെങ്കിൽ നമ്മുടെ `encoding`-ന്റെ അതേ ആട്രിബ്യൂട്ട് പരിശോധിക്കാം:

```python
encoding.is_fast
```

```python out
True
```

ഒരു ഫാസ്‌റ്റ് ടോക്കണൈസർ നമുക്ക് എന്തെല്ലാം ചെയ്യാൻ സഹായിക്കുന്നു എന്ന് നോക്കാം. ആദ്യമായി, ID-കളെ തിരികെ ടോക്കണുകളാക്കി മാറ്റാതെ തന്നെ നമുക്ക് ടോക്കണുകൾ ആക്‌സസ് ചെയ്യാം:

```py
encoding.tokens()
```

```python out
['[CLS]', 'My', 'name', 'is', 'S', '##yl', '##va', '##in', 'and', 'I', 'work', 'at', 'Hu', '##gging', 'Face', 'in',
 'Brooklyn', '.', '[SEP]']
```

ഇവിടെ ഇൻഡെക്‌സ് 5-ലെ ടോക്കൺ `##yl` ആണ്; യഥാർത്ഥ വാക്യത്തിലെ "Sylvain" എന്ന വാക്കിന്റെ ഒരു ഭാഗമാണിത്. ഓരോ ടോക്കണും ഏത് വാക്കിൽ നിന്നാണ് വരുന്നത് എന്നതിന്റെ ഇൻഡെക്‌സ് ലഭിക്കാൻ `word_ids()` മെത്തേഡും നമുക്ക് ഉപയോഗിക്കാം:

```py
encoding.word_ids()
```

```python out
[None, 0, 1, 2, 3, 3, 3, 3, 4, 5, 6, 7, 8, 8, 9, 10, 11, 12, None]
```

ടോക്കണൈസറിന്റെ സ്‌പെഷ്യൽ ടോക്കണുകളായ `[CLS]`, `[SEP]` എന്നിവ `None`-ലേക്ക് മാപ്പ് ചെയ്യപ്പെട്ടിരിക്കുന്നതും, തുടർന്ന് ഓരോ ടോക്കണും അത് ഉത്ഭവിച്ച വാക്കിലേക്ക് മാപ്പ് ചെയ്യപ്പെട്ടിരിക്കുന്നതും നമുക്ക് കാണാം. ഒരു ടോക്കൺ ഒരു വാക്കിന്റെ തുടക്കത്തിലാണോ, അല്ലെങ്കിൽ രണ്ട് ടോക്കണുകൾ ഒരേ വാക്കിലാണോ എന്ന് നിർണ്ണയിക്കാൻ ഇത് പ്രത്യേകിച്ചും ഉപകാരപ്രദമാണ്. അതിനായി `##` എന്ന പ്രിഫിക്‌സിനെ നമുക്ക് ആശ്രയിക്കാമായിരുന്നു, എന്നാൽ അത് BERT-പോലുള്ള ടോക്കണൈസറുകൾക്ക് മാത്രമേ പ്രവർത്തിക്കൂ; ഈ മെത്തേഡ് ഫാസ്‌റ്റ് ആണെങ്കിൽ ഏത് തരം ടോക്കണൈസറിനും പ്രവർത്തിക്കും. നെയിംഡ് എന്റിറ്റി റെക്കഗ്നിഷൻ (NER), പാർട്ട്-ഓഫ്-സ്‌പീച്ച് (POS) ടാഗിംഗ് പോലുള്ള ടാസ്‌ക്കുകളിൽ, ഓരോ വാക്കിനും നമ്മുടെ പക്കലുള്ള ലേബലുകൾ ടോക്കണുകളിലേക്ക് ശരിയായി പ്രയോഗിക്കാൻ ഈ കഴിവ് എങ്ങനെ ഉപയോഗിക്കാമെന്ന് അടുത്ത അധ്യായത്തിൽ നമ്മൾ കാണും. മാസ്‌ക്‌ഡ് ലാംഗ്വേജ് മോഡലിംഗിൽ ഒരേ വാക്കിൽ നിന്ന് വരുന്ന എല്ലാ ടോക്കണുകളും മാസ്‌ക് ചെയ്യാനും ഇത് നമുക്ക് ഉപയോഗിക്കാം (_whole word masking_ എന്നറിയപ്പെടുന്ന ഒരു സങ്കേതമാണിത്).

> [!TIP]
> ഒരു വാക്ക് എന്താണ് എന്ന ധാരണ സങ്കീർണ്ണമാണ്. ഉദാഹരണത്തിന്, "I'll" ("I will"-ന്റെ ചുരുക്കരൂപം) ഒരു വാക്കായാണോ രണ്ട് വാക്കായാണോ കണക്കാക്കേണ്ടത്? അത് യഥാർത്ഥത്തിൽ ടോക്കണൈസറിനെയും അത് പ്രയോഗിക്കുന്ന പ്രീ-ടോക്കണൈസേഷൻ (pre-tokenization) ഓപ്പറേഷനെയും ആശ്രയിച്ചിരിക്കുന്നു. ചില ടോക്കണൈസറുകൾ സ്‌പേസുകളിൽ മാത്രമാണ് വിഭജിക്കുന്നത്, അതിനാൽ അവ ഇതിനെ ഒരു വാക്കായി കണക്കാക്കും. മറ്റുള്ളവ സ്‌പേസുകൾക്കൊപ്പം ചിഹ്നങ്ങളും (punctuation) ഉപയോഗിക്കുന്നു, അതിനാൽ അവ ഇതിനെ രണ്ട് വാക്കുകളായി കണക്കാക്കും.
>
> ✏️ **സ്വയം പരീക്ഷിക്കുക!** `bert-base-cased`, `roberta-base` ചെക്ക്‌പോയിന്റുകളിൽ നിന്ന് ഓരോ ടോക്കണൈസർ നിർമ്മിച്ച് അവ ഉപയോഗിച്ച് "81s" ടോക്കണൈസ് ചെയ്യുക. നിങ്ങൾ എന്താണ് നിരീക്ഷിക്കുന്നത്? വേഡ് ID-കൾ എന്തൊക്കെയാണ്?

അതുപോലെ, ഒരു ടോക്കണിനെ അത് വന്ന വാക്യവുമായി ബന്ധിപ്പിക്കാൻ ഉപയോഗിക്കാവുന്ന ഒരു `sentence_ids()` മെത്തേഡും ഉണ്ട് (ഈ സാഹചര്യത്തിൽ, ടോക്കണൈസർ റിട്ടേൺ ചെയ്യുന്ന `token_type_ids` നമുക്ക് അതേ വിവരം നൽകുമെങ്കിലും).

അവസാനമായി, `word_to_chars()` അല്ലെങ്കിൽ `token_to_chars()`, `char_to_word()` അല്ലെങ്കിൽ `char_to_token()` എന്നീ മെത്തേഡുകൾ വഴി ഏത് വാക്കിനെയോ ടോക്കണിനെയോ യഥാർത്ഥ ടെക്‌സ്‌റ്റിലെ അക്ഷരങ്ങളുമായി ബന്ധിപ്പിക്കാം, തിരിച്ചും ചെയ്യാം. ഉദാഹരണത്തിന്, `##yl` എന്നത് ഇൻഡെക്‌സ് 3-ലെ വാക്കിന്റെ ഭാഗമാണെന്ന് `word_ids()` മെത്തേഡ് നമ്മോട് പറഞ്ഞു; എന്നാൽ വാക്യത്തിലെ ഏത് വാക്കാണ് അത്? ഇങ്ങനെ നമുക്ക് കണ്ടെത്താം:

```py
start, end = encoding.word_to_chars(3)
example[start:end]
```

```python out
Sylvain
```

മുമ്പ് സൂചിപ്പിച്ചതുപോലെ, ഓരോ ടോക്കണും വരുന്ന ടെക്‌സ്‌റ്റ് സ്‌പാൻ *ഓഫ്‌സെറ്റുകളുടെ* (offsets) ഒരു ലിസ്‌റ്റിൽ ഫാസ്‌റ്റ് ടോക്കണൈസർ ട്രാക്ക് ചെയ്യുന്നു എന്ന വസ്തുതയാണ് ഇതെല്ലാം സാധ്യമാക്കുന്നത്. അവയുടെ ഉപയോഗം വ്യക്തമാക്കാൻ, `token-classification` പൈപ്പ്‌ലൈനിന്റെ ഫലങ്ങൾ എങ്ങനെ സ്വന്തമായി (manually) പുനഃസൃഷ്ടിക്കാമെന്ന് അടുത്തതായി ഞങ്ങൾ നിങ്ങൾക്ക് കാണിച്ചുതരാം.

> [!TIP]
> ✏️ **സ്വയം പരീക്ഷിക്കുക!** നിങ്ങളുടെ സ്വന്തം ഉദാഹരണ ടെക്‌സ്‌റ്റ് ഉണ്ടാക്കി, ഏതൊക്കെ ടോക്കണുകളാണ് ഓരോ വേഡ് ID-യുമായി ബന്ധപ്പെട്ടിരിക്കുന്നത് എന്ന് നിങ്ങൾക്ക് മനസ്സിലാക്കാൻ കഴിയുമോ എന്നും, ഒരൊറ്റ വാക്കിന്റെ ക്യാരക്റ്റർ സ്‌പാനുകൾ എങ്ങനെ എടുക്കാമെന്നും നോക്കുക. ബോണസ് പോയിന്റുകൾക്കായി, രണ്ട് വാക്യങ്ങൾ ഇൻപുട്ടായി നൽകി, സെന്റൻസ് ID-കൾ നിങ്ങൾക്ക് അർത്ഥവത്തായി തോന്നുന്നുണ്ടോ എന്ന് പരിശോധിക്കുക.

## `token-classification` പൈപ്പ്‌ലൈനിന്റെ ഉള്ളിൽ[[inside-the-token-classification-pipeline]]

[അധ്യായം 1](/course/chapter1)-ൽ, 🤗 Transformers-ന്റെ `pipeline()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് NER പ്രയോഗിക്കുന്നതിന്റെ ആദ്യ അനുഭവം നമുക്ക് ലഭിച്ചു -- ടെക്‌സ്‌റ്റിന്റെ ഏതൊക്കെ ഭാഗങ്ങളാണ് വ്യക്തികൾ, സ്ഥലങ്ങൾ, സംഘടനകൾ എന്നിവ പോലുള്ള എന്റിറ്റികളുമായി (entities) പൊരുത്തപ്പെടുന്നത് എന്ന് തിരിച്ചറിയുന്നതാണ് അതിലെ ടാസ്‌ക്. പിന്നീട്, [അധ്യായം 2](/course/chapter2)-ൽ, അസംസ്‌കൃത ടെക്‌സ്‌റ്റിൽ നിന്ന് പ്രവചനങ്ങൾ ലഭിക്കാൻ ആവശ്യമായ മൂന്ന് ഘട്ടങ്ങളെ -- ടോക്കണൈസേഷൻ, ഇൻപുട്ടുകൾ മോഡലിലൂടെ കടത്തിവിടൽ, പോസ്‌റ്റ്-പ്രോസസ്സിംഗ് -- ഒരു പൈപ്പ്‌ലൈൻ എങ്ങനെ ഒരുമിച്ച് ചേർക്കുന്നു എന്ന് നമ്മൾ കണ്ടു. `token-classification` പൈപ്പ്‌ലൈനിലെ ആദ്യ രണ്ട് ഘട്ടങ്ങൾ മറ്റേത് പൈപ്പ്‌ലൈനിലേതും പോലെ തന്നെയാണ്, എന്നാൽ പോസ്‌റ്റ്-പ്രോസസ്സിംഗ് കുറച്ചുകൂടി സങ്കീർണ്ണമാണ് -- എങ്ങനെയെന്ന് നോക്കാം!

### പൈപ്പ്‌ലൈൻ ഉപയോഗിച്ച് അടിസ്ഥാന ഫലങ്ങൾ നേടുന്നു[[getting-the-base-results-with-the-pipeline]]

ആദ്യമായി, സ്വന്തമായി താരതമ്യം ചെയ്യാനുള്ള ചില ഫലങ്ങൾ ലഭിക്കുന്നതിനായി ഒരു ടോക്കൺ ക്ലാസിഫിക്കേഷൻ പൈപ്പ്‌ലൈൻ എടുക്കാം. ഡിഫോൾട്ടായി ഉപയോഗിക്കുന്ന മോഡൽ [`dbmdz/bert-large-cased-finetuned-conll03-english`](https://huggingface.co/dbmdz/bert-large-cased-finetuned-conll03-english) ആണ്; ഇത് വാക്യങ്ങളിൽ NER നടത്തുന്നു:

```py
from transformers import pipeline

token_classifier = pipeline("token-classification")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

```py
from transformers import pipeline

token_classifier = pipeline("token-classification", aggregation_strategy="simple")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

```python out
[{'entity_group': 'PER', 'score': 0.9981694, 'word': 'Sylvain', 'start': 11, 'end': 18},

```

തിരഞ്ഞെടുക്കുന്ന `aggregation_strategy`, ഗ്രൂപ്പ് ചെയ്ത ഓരോ എന്റിറ്റിക്കും കണക്കാക്കുന്ന സ്‌കോറുകളെ മാറ്റും. `"simple"` ഉപയോഗിക്കുമ്പോൾ, തന്നിരിക്കുന്ന എന്റിറ്റിയിലെ ഓരോ ടോക്കണിന്റെയും സ്‌കോറുകളുടെ ശരാശരി (mean) മാത്രമാണ് സ്‌കോർ: ഉദാഹരണത്തിന്, "Sylvain"-ന്റെ സ്‌കോർ, മുൻ ഉദാഹരണത്തിൽ `S`, `##yl`, `##va`, `##in` എന്നീ ടോക്കണുകൾക്ക് നമ്മൾ കണ്ട സ്‌കോറുകളുടെ ശരാശരിയാണ്. ലഭ്യമായ മറ്റ് സ്‌ട്രാറ്റജികൾ ഇവയാണ്:

- `"first"`: ഇവിടെ ഓരോ എന്റിറ്റിയുടെയും സ്‌കോർ ആ എന്റിറ്റിയുടെ ആദ്യ ടോക്കണിന്റെ സ്‌കോറാണ് (അതിനാൽ "Sylvain"-ന് അത് `S` എന്ന ടോക്കണിന്റെ സ്‌കോറായ 0.993828 ആയിരിക്കും)
- `"max"`: ഇവിടെ ഓരോ എന്റിറ്റിയുടെയും സ്‌കോർ ആ എന്റിറ്റിയിലെ ടോക്കണുകളുടെ പരമാവധി സ്‌കോറാണ് (അതിനാൽ "Hugging Face"-ന് അത് "Face"-ന്റെ സ്‌കോറായ 0.98879766 ആയിരിക്കും)
- `"average"`: ഇവിടെ ഓരോ എന്റിറ്റിയുടെയും സ്‌കോർ ആ എന്റിറ്റി രൂപപ്പെടുത്തുന്ന വാക്കുകളുടെ സ്‌കോറുകളുടെ ശരാശരിയാണ് (അതിനാൽ "Sylvain"-ന് `"simple"` സ്‌ട്രാറ്റജിയിൽ നിന്ന് വ്യത്യാസമുണ്ടാകില്ല, എന്നാൽ "Hugging Face"-ന് "Hugging"-ന്റെ സ്‌കോറായ 0.975-ന്റെയും "Face"-ന്റെ സ്‌കോറായ 0.98879-ന്റെയും ശരാശരിയായ 0.9819 എന്ന സ്‌കോർ ലഭിക്കും)

ഇനി `pipeline()` ഫംഗ്‌ഷൻ ഉപയോഗിക്കാതെ ഈ ഫലങ്ങൾ എങ്ങനെ നേടാമെന്ന് നോക്കാം!

### ഇൻപുട്ടുകളിൽ നിന്ന് പ്രവചനങ്ങളിലേക്ക്[[from-inputs-to-predictions]]

{#if fw === 'pt'}

ആദ്യം നമ്മുടെ ഇൻപുട്ട് ടോക്കണൈസ് ചെയ്ത് മോഡലിലൂടെ കടത്തിവിടണം. [അധ്യായം 2](/course/chapter2)-ൽ ചെയ്തതുപോലെ തന്നെയാണ് ഇത് ചെയ്യുന്നത്; `AutoXxx` ക്ലാസുകൾ ഉപയോഗിച്ച് ടോക്കണൈസറും മോഡലും ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്ത ശേഷം നമ്മുടെ ഉദാഹരണത്തിൽ അവ ഉപയോഗിക്കുന്നു:

```py
from transformers import AutoTokenizer, AutoModelForTokenClassification

model_checkpoint = "dbmdz/bert-large-cased-finetuned-conll03-english"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
model = AutoModelForTokenClassification.from_pretrained(model_checkpoint)

example = "My name is Sylvain and I work at Hugging Face in Brooklyn."
inputs = tokenizer(example, return_tensors="pt")
outputs = model(**inputs)
```

ഇവിടെ നമ്മൾ `AutoModelForTokenClassification` ഉപയോഗിക്കുന്നതിനാൽ, ഇൻപുട്ട് സീക്വൻസിലെ ഓരോ ടോക്കണിനും ഒരു സെറ്റ് ലോജിറ്റുകൾ (logits) നമുക്ക് ലഭിക്കുന്നു:

```py
print(inputs["input_ids"].shape)
print(outputs.logits.shape)
```

```python out
torch.Size([1, 19, 9])
```

നമ്മൾ മുമ്പ് കണ്ടതുപോലെ, 9 ലേബലുകളുണ്ട്: ഒരു നെയിംഡ് എന്റിറ്റിയിലും ഉൾപ്പെടാത്ത ടോക്കണുകളുടെ ലേബലാണ് `O` (ഇത് "outside" എന്നതിനെ സൂചിപ്പിക്കുന്നു); പിന്നെ ഓരോ തരം എന്റിറ്റിക്കും (മിസലേനിയസ് അഥവാ മറ്റുള്ളവ, വ്യക്തി, സംഘടന, സ്ഥലം) രണ്ട് ലേബലുകൾ വീതമുണ്ട്. `B-XXX` എന്ന ലേബൽ, ടോക്കൺ ഒരു `XXX` എന്റിറ്റിയുടെ തുടക്കത്തിലാണെന്ന് സൂചിപ്പിക്കുന്നു; `I-XXX` എന്ന ലേബൽ, ടോക്കൺ `XXX` എന്റിറ്റിയുടെ ഉള്ളിലാണെന്ന് സൂചിപ്പിക്കുന്നു. ഉദാഹരണത്തിന്, ഇപ്പോഴത്തെ ഉദാഹരണത്തിൽ, നമ്മുടെ മോഡൽ `S` എന്ന ടോക്കണിനെ `B-PER` (ഒരു വ്യക്തി എന്റിറ്റിയുടെ തുടക്കം) എന്നും `##yl`, `##va`, `##in` എന്നീ ടോക്കണുകളെ `I-PER` (ഒരു വ്യക്തി എന്റിറ്റിയുടെ ഉള്ളിൽ) എന്നും വർഗ്ഗീകരിക്കുമെന്ന് നമ്മൾ പ്രതീക്ഷിക്കും.

ഈ നാല് ടോക്കണുകൾക്കും മോഡൽ `I-PER` എന്ന ലേബൽ നൽകിയതിനാൽ ഇവിടെ മോഡലിന് തെറ്റുപറ്റി എന്ന് നിങ്ങൾ ചിന്തിച്ചേക്കാം, എന്നാൽ അത് പൂർണ്ണമായും ശരിയല്ല. ആ `B-`, `I-` ലേബലുകൾക്ക് യഥാർത്ഥത്തിൽ രണ്ട് ഫോർമാറ്റുകളുണ്ട്: *IOB1*, *IOB2*. നമ്മൾ പരിചയപ്പെടുത്തിയത് IOB2 ഫോർമാറ്റാണ് (താഴെ പിങ്ക് നിറത്തിൽ); അതേസമയം IOB1 ഫോർമാറ്റിൽ (നീല നിറത്തിൽ), ഒരേ തരത്തിലുള്ള അടുത്തടുത്ത രണ്ട് എന്റിറ്റികളെ വേർതിരിക്കാൻ മാത്രമാണ് `B-` എന്ന് തുടങ്ങുന്ന ലേബലുകൾ ഉപയോഗിക്കുന്നത്. നമ്മൾ ഉപയോഗിക്കുന്ന മോഡൽ ആ ഫോർമാറ്റ് ഉപയോഗിക്കുന്ന ഒരു ഡേറ്റാസെറ്റിലാണ് ഫൈൻ-ട്യൂൻ ചെയ്തിരിക്കുന്നത്; അതുകൊണ്ടാണ് അത് `S` എന്ന ടോക്കണിന് `I-PER` എന്ന ലേബൽ നൽകുന്നത്.

### എന്റിറ്റികളെ ഗ്രൂപ്പ് ചെയ്യുന്നു[[grouping-entities]]

ഓരോ എന്റിറ്റിയുടെയും start, end കീകൾ നിർണ്ണയിക്കാൻ ഓഫ്‌സെറ്റുകൾ ഉപയോഗിക്കുന്നത് സൗകര്യപ്രദമാണ്, എന്നാൽ ആ വിവരം കർശനമായി ആവശ്യമുള്ളതല്ല. എന്നിരുന്നാലും, എന്റിറ്റികളെ ഒരുമിച്ച് ഗ്രൂപ്പ് ചെയ്യാൻ ആഗ്രഹിക്കുമ്പോൾ, കുഴഞ്ഞുമറിഞ്ഞ ഒരുപാട് കോഡ് ഓഫ്‌സെറ്റുകൾ നമുക്ക് ഒഴിവാക്കിത്തരും. ഉദാഹരണത്തിന്, `Hu`, `##gging`, `Face` എന്നീ ടോക്കണുകളെ ഒരുമിച്ച് ഗ്രൂപ്പ് ചെയ്യണമെങ്കിൽ, ആദ്യത്തെ രണ്ടെണ്ണം `##` നീക്കം ചെയ്ത് കൂട്ടിച്ചേർക്കണമെന്നും, `Face` `##`-ൽ തുടങ്ങാത്തതിനാൽ ഒരു സ്‌പേസ് സഹിതം ചേർക്കണമെന്നും പറയുന്ന പ്രത്യേക നിയമങ്ങൾ നമുക്ക് ഉണ്ടാക്കാം -- എന്നാൽ അത് ഈ പ്രത്യേക തരം ടോക്കണൈസറിന് മാത്രമേ പ്രവർത്തിക്കൂ. ഒരു SentencePiece അല്ലെങ്കിൽ Byte-Pair-Encoding ടോക്കണൈസറിന് (ഈ അധ്യായത്തിൽ പിന്നീട് ചർച്ച ചെയ്യുന്നു) മറ്റൊരു കൂട്ടം നിയമങ്ങൾ നമുക്ക് എഴുതേണ്ടിവരും.

ഓഫ്‌സെറ്റുകൾ ഉള്ളപ്പോൾ, ആ കസ്‌റ്റം കോഡെല്ലാം ഒഴിവാകുന്നു: ആദ്യ ടോക്കണിൽ തുടങ്ങി അവസാന ടോക്കണിൽ അവസാനിക്കുന്ന, യഥാർത്ഥ ടെക്‌സ്‌റ്റിലെ സ്‌പാൻ എടുത്താൽ മാത്രം മതി. അതിനാൽ, `Hu`, `##gging`, `Face` എന്നീ ടോക്കണുകളുടെ കാര്യത്തിൽ, ക്യാരക്റ്റർ 33-ൽ (`Hu`-ന്റെ തുടക്കം) തുടങ്ങി ക്യാരക്റ്റർ 45-ന് (`Face`-ന്റെ അവസാനം) മുമ്പ് അവസാനിപ്പിക്കണം:

```py
example[33:45]
```

എന്റിറ്റികളെ ഗ്രൂപ്പ് ചെയ്യുന്നതിനൊപ്പം പ്രവചനങ്ങളെ പോസ്‌റ്റ്-പ്രോസസ്സ് ചെയ്യുന്ന കോഡ് എഴുതാൻ, തുടർച്ചയായി വരുന്നതും `I-XXX` എന്ന് ലേബൽ ചെയ്തതുമായ എന്റിറ്റികളെ നമ്മൾ ഒരുമിച്ച് ഗ്രൂപ്പ് ചെയ്യും; ആദ്യത്തേത് മാത്രം ഇതിന് അപവാദമാണ്, അതിന് `B-XXX` അല്ലെങ്കിൽ `I-XXX` എന്ന ലേബൽ ആകാം (അതായത്, ഒരു `O`, ഒരു പുതിയ തരം എന്റിറ്റി, അല്ലെങ്കിൽ ഒരേ തരത്തിലുള്ള ഒരു എന്റിറ്റി തുടങ്ങുന്നു എന്ന് പറയുന്ന ഒരു `B-XXX` എന്നിവ ലഭിക്കുമ്പോൾ ഒരു എന്റിറ്റിയുടെ ഗ്രൂപ്പിംഗ് നമ്മൾ നിർത്തുന്നു):

```py
import numpy as np

results = []
inputs_with_offsets = tokenizer(example, return_offsets_mapping=True)
tokens = inputs_with_offsets.tokens()
offsets = inputs_with_offsets["offset_mapping"]

idx = 0
while idx < len(predictions):
    pred = predictions[idx]
    label = model.config.id2label[pred]
    if label != "O":
        # Remove the B- or I-
        label = label[2:]
        start, _ = offsets[idx]

        # Grab all the tokens labeled with I-label
        all_scores = []
        while (
            idx < len(predictions)
            and model.config.id2label[predictions[idx]] == f"I-{label}"
        ):
            all_scores.append(probabilities[idx][pred])
            _, end = offsets[idx]
            idx += 1

        # The score is the mean of all the scores of the tokens in that grouped entity
        score = np.mean(all_scores).item()
        word = example[start:end]
        results.append(
            {
                "entity_group": label,
                "score": score,
                "word": word,
                "start": start,
                "end": end,
            }
        )
    idx += 1

print(results)
```
