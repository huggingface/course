Unigram അൽഗോരിതം [SentencePiece](https://huggingface.co/papers/1808.06226)-നോടൊപ്പം ചേർത്താണ് ഉപയോഗിക്കുന്നത്; AlBERT, T5, mBART, Big Bird, XLNet തുടങ്ങിയ മോഡലുകൾ ഉപയോഗിക്കുന്ന ടോക്കണൈസേഷൻ അൽഗോരിതമാണ് SentencePiece.

എല്ലാ ഭാഷകളും വാക്കുകൾ വേർതിരിക്കാൻ സ്‌പേസ് ഉപയോഗിക്കുന്നില്ല എന്ന വസ്തുതയെയാണ് SentencePiece അഭിസംബോധന ചെയ്യുന്നത്. പകരം, ഉപയോഗിക്കേണ്ട ക്യാരക്‌ടറുകളുടെ കൂട്ടത്തിൽ സ്‌പേസും ഉൾപ്പെടുന്ന ഒരു അസംസ്‌കൃത ഇൻപുട്ട് സ്‌ട്രീമായി (raw input stream) SentencePiece ഇൻപുട്ടിനെ പരിഗണിക്കുന്നു. തുടർന്ന്, അനുയോജ്യമായ വൊക്കാബുലറി (vocabulary) നിർമ്മിക്കാൻ ഇതിന് Unigram അൽഗോരിതം ഉപയോഗിക്കാം.

## ട്രെയിനിംഗ് അൽഗോരിതം[[training-algorithm]]

BPE, WordPiece എന്നിവയുമായി താരതമ്യം ചെയ്യുമ്പോൾ, Unigram മറുദിശയിലാണ് പ്രവർത്തിക്കുന്നത്: ഇത് ഒരു വലിയ വൊക്കാബുലറിയിൽ നിന്ന് തുടങ്ങി, ആവശ്യമുള്ള വൊക്കാബുലറി വലുപ്പത്തിൽ എത്തുന്നതുവരെ അതിൽ നിന്ന് ടോക്കണുകൾ നീക്കം ചെയ്യുന്നു. ആ അടിസ്ഥാന വൊക്കാബുലറി നിർമ്മിക്കാൻ പല മാർഗങ്ങളുണ്ട്: ഉദാഹരണത്തിന്, പ്രീ-ടോക്കണൈസ് ചെയ്ത വാക്കുകളിലെ ഏറ്റവും സാധാരണമായ സബ്‌സ്‌ട്രിംഗുകൾ (substrings) നമുക്ക് എടുക്കാം, അല്ലെങ്കിൽ ഒരു വലിയ വൊക്കാബുലറി വലുപ്പത്തോടെ പ്രാരംഭ കോർപ്പസിൽ (corpus) BPE പ്രയോഗിക്കാം.

ട്രെയിനിംഗിന്റെ ഓരോ ഘട്ടത്തിലും, നിലവിലെ വൊക്കാബുലറി അടിസ്ഥാനമാക്കി കോർപ്പസിന് മേൽ ഒരു ലോസ് (loss) Unigram അൽഗോരിതം കണക്കാക്കുന്നു. തുടർന്ന്, വൊക്കാബുലറിയിലെ ഓരോ ചിഹ്നത്തിനും (symbol), ആ ചിഹ്നം നീക്കം ചെയ്താൽ മൊത്തത്തിലുള്ള ലോസ് എത്രമാത്രം കൂടുമെന്ന് അൽഗോരിതം കണക്കാക്കുകയും, അതിനെ ഏറ്റവും കുറച്ച് മാത്രം കൂട്ടുന്ന ചിഹ്നങ്ങൾ തിരയുകയും ചെയ്യുന്നു. കോർപ്പസിന് മേലുള്ള മൊത്തം ലോസിൽ ആ ചിഹ്നങ്ങൾക്ക് സ്വാധീനം കുറവാണ്, അതിനാൽ ഒരർത്ഥത്തിൽ അവ "അത്ര ആവശ്യമില്ലാത്തവ" ആണ്, നീക്കം ചെയ്യാനുള്ള ഏറ്റവും മികച്ച സ്ഥാനാർത്ഥികളും അവയാണ്.

ഇതെല്ലാം വളരെ ചെലവേറിയ ഒരു പ്രവർത്തനമാണ്, അതിനാൽ ഏറ്റവും കുറഞ്ഞ ലോസ് വർദ്ധനവുമായി ബന്ധപ്പെട്ട ഒരൊറ്റ ചിഹ്നം മാത്രമല്ല നമ്മൾ നീക്കം ചെയ്യുന്നത്, മറിച്ച് ഏറ്റവും കുറഞ്ഞ ലോസ് വർദ്ധനവുമായി ബന്ധപ്പെട്ട ചിഹ്നങ്ങളുടെ \\(p\\) ശതമാനമാണ് (\\(p\\) എന്നത് നിങ്ങൾക്ക് നിയന്ത്രിക്കാവുന്ന ഒരു ഹൈപ്പർപാരാമീറ്ററാണ്, സാധാരണയായി 10 അല്ലെങ്കിൽ 20). വൊക്കാബുലറി ആവശ്യമുള്ള വലുപ്പത്തിൽ എത്തുന്നതുവരെ ഈ പ്രക്രിയ ആവർത്തിക്കുന്നു.

ഏത് വാക്കും ടോക്കണൈസ് ചെയ്യാൻ കഴിയുമെന്ന് ഉറപ്പാക്കാൻ, അടിസ്ഥാന ക്യാരക്‌ടറുകൾ നമ്മൾ ഒരിക്കലും നീക്കം ചെയ്യുന്നില്ല എന്നത് ശ്രദ്ധിക്കുക.

ഇപ്പോഴും ഇത് അൽപ്പം അവ്യക്തമാണ്: കോർപ്പസിന് മേൽ ഒരു ലോസ് കണക്കാക്കുകയും, വൊക്കാബുലറിയിൽ നിന്ന് ചില ടോക്കണുകൾ നീക്കം ചെയ്യുമ്പോൾ അത് എങ്ങനെ മാറുന്നു എന്ന് നോക്കുകയും ചെയ്യുന്നതാണ് അൽഗോരിതത്തിന്റെ പ്രധാന ഭാഗം, എന്നാൽ ഇത് എങ്ങനെ ചെയ്യണമെന്ന് നമ്മൾ ഇതുവരെ വിശദീകരിച്ചിട്ടില്ല. ഈ ഘട്ടം ഒരു Unigram മോഡലിന്റെ ടോക്കണൈസേഷൻ അൽഗോരിതത്തെ ആശ്രയിച്ചിരിക്കുന്നു, അതിനാൽ അടുത്തതായി നമ്മൾ അതിലേക്ക് കടക്കും.

മുൻ ഉദാഹരണങ്ങളിലെ കോർപ്പസ് നമ്മൾ വീണ്ടും ഉപയോഗിക്കും:

```
("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)
```

കൂടാതെ, ഈ ഉദാഹരണത്തിനായി, പ്രാരംഭ വൊക്കാബുലറിക്ക് വേണ്ടി എല്ലാ സ്‌ട്രിക്‌ട് സബ്‌സ്‌ട്രിംഗുകളും (strict substrings) നമ്മൾ എടുക്കും:

```
["h", "u", "g", "hu", "ug", "p", "pu", "n", "un", "b", "bu", "s", "hug", "gs", "ugs"]
```

## ടോക്കണൈസേഷൻ അൽഗോരിതം[[tokenization-algorithm]]

ഓരോ ടോക്കണും അതിന് മുമ്പുള്ള ടോക്കണുകളിൽ നിന്ന് സ്വതന്ത്രമാണെന്ന് കരുതുന്ന ഒരു തരം ഭാഷാ മോഡലാണ് (language model) Unigram മോഡൽ. ഇത് ഏറ്റവും ലളിതമായ ഭാഷാ മോഡലാണ്; അതായത്, മുൻ സന്ദർഭം (context) നൽകിയാൽ ടോക്കൺ X-ന്റെ പ്രോബബിലിറ്റി എന്നത് ടോക്കൺ X-ന്റെ പ്രോബബിലിറ്റി തന്നെയാണ്. അതിനാൽ, ടെക്‌സ്‌റ്റ് ജനറേറ്റ് ചെയ്യാൻ ഒരു Unigram ഭാഷാ മോഡൽ ഉപയോഗിച്ചാൽ, നമ്മൾ എപ്പോഴും ഏറ്റവും സാധാരണമായ ടോക്കൺ തന്നെ പ്രവചിക്കും.

ഒരു ടോക്കണിന്റെ പ്രോബബിലിറ്റി എന്നത്, യഥാർത്ഥ കോർപ്പസിലെ അതിന്റെ ഫ്രീക്വൻസിയെ (frequency — അത് എത്ര തവണ കാണപ്പെടുന്നു എന്നത്) വൊക്കാബുലറിയിലെ എല്ലാ ടോക്കണുകളുടെയും എല്ലാ ഫ്രീക്വൻസികളുടെയും ആകെത്തുകയാൽ ഹരിച്ചതാണ് (പ്രോബബിലിറ്റികളുടെ ആകെത്തുക 1 ആണെന്ന് ഉറപ്പാക്കാൻ). ഉദാഹരണത്തിന്, `"ug"` എന്നത് `"hug"`, `"pug"`, `"hugs"` എന്നിവയിൽ ഉണ്ട്, അതിനാൽ നമ്മുടെ കോർപ്പസിൽ അതിന്റെ ഫ്രീക്വൻസി 20 ആണ്.

വൊക്കാബുലറിയിലെ സാധ്യമായ എല്ലാ സബ്‌വേഡുകളുടെയും ഫ്രീക്വൻസികൾ ഇതാ:

```
("h", 15) ("u", 36) ("g", 20) ("hu", 15) ("ug", 20) ("p", 17) ("pu", 17) ("n", 16)
("un", 16) ("b", 4) ("bu", 4) ("s", 5) ("hug", 15) ("gs", 5) ("ugs", 5)
```

അതിനാൽ, എല്ലാ ഫ്രീക്വൻസികളുടെയും ആകെത്തുക 210 ആണ്, അങ്ങനെ `"ug"` എന്ന സബ്‌വേഡിന്റെ പ്രോബബിലിറ്റി 20/210 ആണ്.

> [!TIP]
> ✏️ **ഇനി നിങ്ങളുടെ ഊഴം!** മുകളിലുള്ള ഫ്രീക്വൻസികൾ കണക്കാക്കാനുള്ള കോഡ് എഴുതുകയും, കാണിച്ചിരിക്കുന്ന ഫലങ്ങളും മൊത്തം തുകയും ശരിയാണെന്ന് ഒന്നുകൂടി ഉറപ്പുവരുത്തുകയും ചെയ്യുക.

ഇനി, ഒരു വാക്ക് ടോക്കണൈസ് ചെയ്യാൻ, അതിനെ ടോക്കണുകളായി വിഭജിക്കാവുന്ന സാധ്യമായ എല്ലാ സെഗ്‌മെന്റേഷനുകളും (segmentations) നമ്മൾ നോക്കുകയും, Unigram മോഡൽ അനുസരിച്ച് ഓരോന്നിന്റെയും പ്രോബബിലിറ്റി കണക്കാക്കുകയും ചെയ്യുന്നു. എല്ലാ ടോക്കണുകളും സ്വതന്ത്രമായി പരിഗണിക്കപ്പെടുന്നതിനാൽ, ഈ പ്രോബബിലിറ്റി ഓരോ ടോക്കണിന്റെയും പ്രോബബിലിറ്റികളുടെ ഗുണനഫലം മാത്രമാണ്. ഉദാഹരണത്തിന്, `"pug"`-ന്റെ `["p", "u", "g"]` എന്ന ടോക്കണൈസേഷന്റെ പ്രോബബിലിറ്റി ഇതാണ്:

$$P([``p", ``u", ``g"]) = P(``p") \times P(``u") \times P(``g") = \frac{5}{210} \times \frac{36}{210} \times \frac{20}{210} = 0.000389$$

താരതമ്യേന, `["pu", "g"]` എന്ന ടോക്കണൈസേഷന്റെ പ്രോബബിലിറ്റി ഇതാണ്:

$$P([``pu", ``g"]) = P(``pu") \times P(``g") = \frac{5}{210} \times \frac{20}{210} = 0.0022676$$

അതിനാൽ അതിനാണ് വളരെ കൂടുതൽ സാധ്യത. പൊതുവേ, സാധ്യമായ ഏറ്റവും കുറച്ച് ടോക്കണുകളുള്ള ടോക്കണൈസേഷനുകൾക്കായിരിക്കും ഏറ്റവും ഉയർന്ന പ്രോബബിലിറ്റി (ഓരോ ടോക്കണിനും 210 കൊണ്ടുള്ള ആ ഹരണം ആവർത്തിക്കുന്നതുകൊണ്ടാണ് ഇത്), ഇത് നമ്മൾ അവബോധപരമായി ആഗ്രഹിക്കുന്നതിനോട് യോജിക്കുന്നു: ഒരു വാക്കിനെ സാധ്യമായ ഏറ്റവും കുറഞ്ഞ എണ്ണം ടോക്കണുകളായി വിഭജിക്കുക.

അങ്ങനെ, Unigram മോഡൽ ഉപയോഗിച്ചുള്ള ഒരു വാക്കിന്റെ ടോക്കണൈസേഷൻ എന്നത് ഏറ്റവും ഉയർന്ന പ്രോബബിലിറ്റിയുള്ള ടോക്കണൈസേഷനാണ്. `"pug"`-ന്റെ ഉദാഹരണത്തിൽ, സാധ്യമായ ഓരോ സെഗ്‌മെന്റേഷനും നമുക്ക് ലഭിക്കുന്ന പ്രോബബിലിറ്റികൾ ഇതാ:

```
["p", "u", "g"] : 0.000389
["p", "ug"] : 0.0022676
["pu", "g"] : 0.0022676
```

അതിനാൽ, ആ സെഗ്‌മെന്റേഷനുകളിൽ ഏതാണ് ആദ്യം കണ്ടുമുട്ടുന്നത് എന്നതിനെ ആശ്രയിച്ച്, `"pug"` എന്നത് `["p", "ug"]` ആയോ `["pu", "g"]` ആയോ ടോക്കണൈസ് ചെയ്യപ്പെടും (ഒരു വലിയ കോർപ്പസിൽ ഇതുപോലുള്ള തുല്യതാ സാഹചര്യങ്ങൾ അപൂർവമായിരിക്കും എന്നത് ശ്രദ്ധിക്കുക).

ഈ സാഹചര്യത്തിൽ, സാധ്യമായ എല്ലാ സെഗ്‌മെന്റേഷനുകളും കണ്ടെത്തി അവയുടെ പ്രോബബിലിറ്റികൾ കണക്കാക്കുന്നത് എളുപ്പമായിരുന്നു, എന്നാൽ പൊതുവേ ഇത് കുറച്ചുകൂടി ബുദ്ധിമുട്ടുള്ളതായിരിക്കും. ഇതിനായി ഉപയോഗിക്കുന്ന ഒരു ക്ലാസിക് അൽഗോരിതമുണ്ട്, *Viterbi അൽഗോരിതം* എന്നാണ് ഇതിന്റെ പേര്. അടിസ്ഥാനപരമായി, _a_ മുതൽ _b_ വരെയുള്ള സബ്‌വേഡ് വൊക്കാബുലറിയിലുണ്ടെങ്കിൽ ക്യാരക്‌ടർ _a_-യിൽ നിന്ന് ക്യാരക്‌ടർ _b_-യിലേക്ക് ഒരു ശാഖ (branch) ഉണ്ട് എന്ന് പറഞ്ഞുകൊണ്ട്, ഒരു വാക്കിന്റെ സാധ്യമായ സെഗ്‌മെന്റേഷനുകൾ കണ്ടെത്താൻ നമുക്ക് ഒരു ഗ്രാഫ് നിർമ്മിക്കാം, ആ ശാഖയ്ക്ക് സബ്‌വേഡിന്റെ പ്രോബബിലിറ്റി നൽകുകയും ചെയ്യാം.

ആ ഗ്രാഫിൽ ഏറ്റവും മികച്ച സ്‌കോർ ലഭിക്കുന്ന പാത കണ്ടെത്താൻ, വാക്കിലെ ഓരോ സ്ഥാനത്തിനും (position), ആ സ്ഥാനത്ത് അവസാനിക്കുന്ന ഏറ്റവും മികച്ച സ്‌കോറുള്ള സെഗ്‌മെന്റേഷൻ Viterbi അൽഗോരിതം നിർണ്ണയിക്കുന്നു. നമ്മൾ തുടക്കത്തിൽ നിന്ന് അവസാനത്തിലേക്കാണ് പോകുന്നതിനാൽ, നിലവിലെ സ്ഥാനത്ത് അവസാനിക്കുന്ന എല്ലാ സബ്‌വേഡുകളിലൂടെയും ലൂപ്പ് ചെയ്ത്, ആ സബ്‌വേഡ് തുടങ്ങുന്ന സ്ഥാനത്തെ ഏറ്റവും മികച്ച ടോക്കണൈസേഷൻ സ്‌കോർ ഉപയോഗിച്ച് ആ മികച്ച സ്‌കോർ കണ്ടെത്താം. തുടർന്ന്, അവസാനത്തിൽ എത്താൻ സ്വീകരിച്ച പാത നമ്മൾ പിന്നോട്ട് നിവർത്തിയെടുത്താൽ (unroll) മാത്രം മതി.

നമ്മുടെ വൊക്കാബുലറിയും `"unhug"` എന്ന വാക്കും ഉപയോഗിച്ചുള്ള ഒരു ഉദാഹരണം നോക്കാം. ഓരോ സ്ഥാനത്തിനും, അവിടെ അവസാനിക്കുന്ന ഏറ്റവും മികച്ച സ്‌കോറുകളുള്ള സബ്‌വേഡുകൾ ഇവയാണ്:

```
Character 0 (u): "u" (score 0.171429)
Character 1 (n): "un" (score 0.076191)
Character 2 (h): "un" "h" (score 0.005442)
Character 3 (u): "un" "hu" (score 0.005442)
Character 4 (g): "un" "hug" (score 0.005442)
```

അങ്ങനെ `"unhug"` എന്നത് `["un", "hug"]` ആയി ടോക്കണൈസ് ചെയ്യപ്പെടും.

> [!TIP]
> ✏️ **ഇനി നിങ്ങളുടെ ഊഴം!** `"huggun"` എന്ന വാക്കിന്റെ ടോക്കണൈസേഷനും അതിന്റെ സ്‌കോറും നിർണ്ണയിക്കുക.

## വീണ്ടും ട്രെയിനിംഗിലേക്ക്[[back-to-training]]

ടോക്കണൈസേഷൻ എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്ന് ഇപ്പോൾ നമ്മൾ കണ്ടതിനാൽ, ട്രെയിനിംഗ് സമയത്ത് ഉപയോഗിക്കുന്ന ലോസിലേക്ക് നമുക്ക് കുറച്ചുകൂടി ആഴത്തിൽ കടക്കാം. ഏതൊരു ഘട്ടത്തിലും, നിലവിലെ വൊക്കാബുലറിയും കോർപ്പസിലെ ഓരോ ടോക്കണിന്റെയും ഫ്രീക്വൻസികൾ നിർണ്ണയിക്കുന്ന Unigram മോഡലും ഉപയോഗിച്ച് (മുമ്പ് കണ്ടതുപോലെ), കോർപ്പസിലെ ഓരോ വാക്കും ടോക്കണൈസ് ചെയ്താണ് ഈ ലോസ് കണക്കാക്കുന്നത്.

കോർപ്പസിലെ ഓരോ വാക്കിനും ഒരു സ്‌കോർ ഉണ്ട്, ആ സ്‌കോറുകളുടെ നെഗറ്റീവ് ലോഗ് ലൈക്‌ലിഹുഡ് (negative log likelihood) ആണ് ലോസ് -- അതായത്, കോർപ്പസിലെ എല്ലാ വാക്കുകളുടെയും `-log(P(word))`-കളുടെ ആകെത്തുക.

താഴെ പറയുന്ന കോർപ്പസുള്ള നമ്മുടെ ഉദാഹരണത്തിലേക്ക് തിരിച്ചുപോകാം:

```
("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)
```

ഓരോ വാക്കിന്റെയും ടോക്കണൈസേഷനും അവയുടെ സ്‌കോറുകളും ഇതാ:

```
"hug": ["hug"] (score 0.071428)
"pug": ["pu", "g"] (score 0.007710)
"pun": ["pu", "n"] (score 0.006168)
"bun": ["bu", "n"] (score 0.001451)
"hugs": ["hug", "s"] (score 0.001701)
```

അതിനാൽ ലോസ് ഇതാണ്:

```
10 * (-log(0.071428)) + 5 * (-log(0.007710)) + 12 * (-log(0.006168)) + 4 * (-log(0.001451)) + 5 * (-log(0.001701)) = 169.8
```

ഇനി, ഓരോ ടോക്കണും നീക്കം ചെയ്യുന്നത് ലോസിനെ എങ്ങനെ ബാധിക്കുന്നു എന്ന് നമ്മൾ കണക്കാക്കണം. ഇത് കുറച്ച് മടുപ്പിക്കുന്ന ജോലിയാണ്, അതിനാൽ ഇവിടെ രണ്ട് ടോക്കണുകൾക്ക് മാത്രം നമ്മൾ ഇത് ചെയ്യും; മുഴുവൻ പ്രക്രിയയും, നമ്മെ സഹായിക്കാൻ കോഡ് ഉള്ളപ്പോഴേക്ക് മാറ്റിവയ്ക്കും. ഈ (വളരെ) പ്രത്യേക സാഹചര്യത്തിൽ, എല്ലാ വാക്കുകൾക്കും തുല്യമായ രണ്ട് ടോക്കണൈസേഷനുകൾ നമുക്കുണ്ടായിരുന്നു: ഉദാഹരണത്തിന്, നേരത്തെ കണ്ടതുപോലെ, `"pug"` എന്നത് അതേ സ്‌കോറോടെ `["p", "ug"]` ആയി ടോക്കണൈസ് ചെയ്യാമായിരുന്നു. അതിനാൽ, വൊക്കാബുലറിയിൽ നിന്ന് `"pu"` ടോക്കൺ നീക്കം ചെയ്താൽ കൃത്യമായി അതേ ലോസ് തന്നെ ലഭിക്കും.

മറുവശത്ത്, `"hug"` നീക്കം ചെയ്യുന്നത് ലോസ് കൂടുതൽ മോശമാക്കും, കാരണം `"hug"`-ന്റെയും `"hugs"`-ന്റെയും ടോക്കണൈസേഷൻ ഇങ്ങനെയാകും:

```
"hug": ["hu", "g"] (score 0.006802)
"hugs": ["hu", "gs"] (score 0.001701)
```

ഈ മാറ്റങ്ങൾ ലോസ് ഇത്രയും ഉയരാൻ കാരണമാകും:

```
- 10 * (-log(0.071428)) + 10 * (-log(0.006802)) = 23.5
```

അതിനാൽ, `"pu"` എന്ന ടോക്കൺ ഒരുപക്ഷേ വൊക്കാബുലറിയിൽ നിന്ന് നീക്കം ചെയ്യപ്പെടും, എന്നാൽ `"hug"` നീക്കം ചെയ്യപ്പെടില്ല.

## Unigram ഇംപ്ലിമെന്റ് ചെയ്യുന്നു[[implementing-unigram]]

ഇനി ഇതുവരെ നമ്മൾ കണ്ടതെല്ലാം കോഡിൽ ഇംപ്ലിമെന്റ് ചെയ്യാം. BPE-യുടെയും WordPiece-ന്റെയും കാര്യത്തിലേതുപോലെ, ഇത് Unigram അൽഗോരിതത്തിന്റെ കാര്യക്ഷമമായ ഒരു ഇംപ്ലിമെന്റേഷനല്ല (നേരെ മറിച്ചാണ്), എന്നാൽ അത് കുറച്ചുകൂടി നന്നായി മനസ്സിലാക്കാൻ ഇത് നിങ്ങളെ സഹായിക്കും.

മുമ്പത്തെ അതേ കോർപ്പസ് തന്നെ നമ്മൾ ഉദാഹരണമായി ഉപയോഗിക്കും:

```python
corpus = [
    "This is the Hugging Face Course.",
    "This chapter is about tokenization.",
    "This section shows several tokenizer algorithms.",
    "Hopefully, you will be able to understand how they are trained and generate tokens.",
]
```

ഇത്തവണ, `xlnet-base-cased` ആണ് നമ്മൾ മോഡലായി ഉപയോഗിക്കുന്നത്:

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("xlnet-base-cased")
```

BPE-യുടെയും WordPiece-ന്റെയും കാര്യത്തിലേതുപോലെ, കോർപ്പസിലെ ഓരോ വാക്കും എത്ര തവണ വരുന്നു എന്ന് എണ്ണിക്കൊണ്ടാണ് നമ്മൾ തുടങ്ങുന്നത്:

```python
from collections import defaultdict

word_freqs = defaultdict(int)
for text in corpus:
    words_with_offsets = tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str(text)
    new_words = [word for word, offset in words_with_offsets]
    for word in new_words:
        word_freqs[word] += 1

word_freqs
```

തുടർന്ന്, അവസാനം നമുക്ക് വേണ്ട വൊക്കാബുലറി വലുപ്പത്തെക്കാൾ വലുതായ ഒന്നിലേക്ക് നമ്മുടെ വൊക്കാബുലറി ഇനിഷ്യലൈസ് ചെയ്യണം. എല്ലാ അടിസ്ഥാന ക്യാരക്‌ടറുകളും നമ്മൾ ഉൾപ്പെടുത്തണം (അല്ലാത്തപക്ഷം എല്ലാ വാക്കുകളും ടോക്കണൈസ് ചെയ്യാൻ നമുക്ക് കഴിയില്ല), എന്നാൽ വലിയ സബ്‌സ്‌ട്രിംഗുകളുടെ കാര്യത്തിൽ ഏറ്റവും സാധാരണമായവ മാത്രമേ നമ്മൾ നിലനിർത്തൂ, അതിനാൽ അവയെ ഫ്രീക്വൻസി അനുസരിച്ച് ക്രമീകരിക്കുന്നു:

```python
char_freqs = defaultdict(int)
subwords_freqs = defaultdict(int)
for word, freq in word_freqs.items():
    for i in range(len(word)):
        char_freqs[word[i]] += freq
        # Loop through the subwords of length at least 2
        for j in range(i + 2, len(word) + 1):
            subwords_freqs[word[i:j]] += freq

# Sort subwords by frequency
sorted_subwords = sorted(subwords_freqs.items(), key=lambda x: x[1], reverse=True)
sorted_subwords[:10]
```

300 വലുപ്പമുള്ള ഒരു പ്രാരംഭ വൊക്കാബുലറിയിൽ എത്താൻ, ക്യാരക്‌ടറുകളെ ഏറ്റവും മികച്ച സബ്‌വേഡുകളുമായി നമ്മൾ കൂട്ടിച്ചേർക്കുന്നു:

```python
token_freqs = list(char_freqs.items()) + sorted_subwords[: 300 - len(char_freqs)]
token_freqs = {token: freq for token, freq in token_freqs}
```

> [!TIP]
> 💡 പ്രാരംഭ വൊക്കാബുലറി നിർമ്മിക്കാൻ SentencePiece, Enhanced Suffix Array (ESA) എന്ന കൂടുതൽ കാര്യക്ഷമമായ ഒരു അൽഗോരിതം ഉപയോഗിക്കുന്നു.

അടുത്തതായി, ഫ്രീക്വൻസികളെ പ്രോബബിലിറ്റികളാക്കി മാറ്റാൻ, എല്ലാ ഫ്രീക്വൻസികളുടെയും ആകെത്തുക നമ്മൾ കണക്കാക്കുന്നു. നമ്മുടെ മോഡലിനായി പ്രോബബിലിറ്റികളുടെ ലോഗരിതങ്ങളാണ് (logarithms) നമ്മൾ സ്‌റ്റോർ ചെയ്യുന്നത്, കാരണം ചെറിയ സംഖ്യകൾ ഗുണിക്കുന്നതിനെക്കാൾ ലോഗരിതങ്ങൾ കൂട്ടുന്നത് സംഖ്യാപരമായി കൂടുതൽ സ്ഥിരതയുള്ളതാണ് (numerically stable), കൂടാതെ ഇത് മോഡലിന്റെ ലോസ് കണക്കാക്കുന്നത് ലളിതമാക്കുകയും ചെയ്യും:

```python
from math import log

total_sum = sum([freq for token, freq in token_freqs.items()])
model = {token: -log(freq / total_sum) for token, freq in token_freqs.items()}
```

ഇനി, Viterbi അൽഗോരിതം ഉപയോഗിച്ച് വാക്കുകൾ ടോക്കണൈസ് ചെയ്യുന്ന ഫംഗ്‌ഷനാണ് പ്രധാന ഫംഗ്‌ഷൻ. മുമ്പ് കണ്ടതുപോലെ, ആ അൽഗോരിതം വാക്കിന്റെ ഓരോ സബ്‌സ്‌ട്രിംഗിന്റെയും ഏറ്റവും മികച്ച സെഗ്‌മെന്റേഷൻ കണക്കാക്കുന്നു, അത് നമ്മൾ `best_segmentations` എന്ന വേരിയബിളിൽ സ്‌റ്റോർ ചെയ്യും. വാക്കിലെ ഓരോ സ്ഥാനത്തിനും (0 മുതൽ അതിന്റെ മൊത്തം നീളം വരെ) രണ്ട് കീകളുള്ള ഒരു ഡിക്‌ഷണറി വീതം നമ്മൾ സ്‌റ്റോർ ചെയ്യും: ഏറ്റവും മികച്ച സെഗ്‌മെന്റേഷനിലെ അവസാന ടോക്കണിന്റെ തുടക്കത്തിന്റെ ഇൻഡെക്‌സ്, ഏറ്റവും മികച്ച സെഗ്‌മെന്റേഷന്റെ സ്‌കോർ എന്നിവയാണ് ആ കീകൾ. അവസാന ടോക്കണിന്റെ തുടക്കത്തിന്റെ ഇൻഡെക്‌സ് ഉപയോഗിച്ച്, ലിസ്‌റ്റ് പൂർണ്ണമായി പൂരിപ്പിച്ചു കഴിഞ്ഞാൽ മുഴുവൻ സെഗ്‌മെന്റേഷനും നമുക്ക് വീണ്ടെടുക്കാൻ കഴിയും.

വെറും രണ്ട് ലൂപ്പുകൾ ഉപയോഗിച്ചാണ് ലിസ്‌റ്റ് പൂരിപ്പിക്കുന്നത്: പ്രധാന ലൂപ്പ് ഓരോ തുടക്ക സ്ഥാനത്തിലൂടെയും കടന്നുപോകുന്നു, രണ്ടാമത്തെ ലൂപ്പ് ആ തുടക്ക സ്ഥാനത്ത് ആരംഭിക്കുന്ന എല്ലാ സബ്‌സ്‌ട്രിംഗുകളും പരീക്ഷിക്കുന്നു. സബ്‌സ്‌ട്രിംഗ് വൊക്കാബുലറിയിലുണ്ടെങ്കിൽ, ആ അവസാന സ്ഥാനം വരെയുള്ള വാക്കിന്റെ ഒരു പുതിയ സെഗ്‌മെന്റേഷൻ നമുക്ക് ലഭിക്കുന്നു, അതിനെ `best_segmentations`-ൽ ഉള്ളതുമായി നമ്മൾ താരതമ്യം ചെയ്യുന്നു.

പ്രധാന ലൂപ്പ് പൂർത്തിയായിക്കഴിഞ്ഞാൽ, നമ്മൾ അവസാനത്തിൽ നിന്ന് തുടങ്ങി, വാക്കിന്റെ തുടക്കത്തിൽ എത്തുന്നതുവരെ ഒരു തുടക്ക സ്ഥാനത്തിൽ നിന്ന് അടുത്തതിലേക്ക് ചാടിക്കൊണ്ട്, പോകുന്ന വഴിയിൽ ടോക്കണുകൾ രേഖപ്പെടുത്തുന്നു:

```python
def encode_word(word, model):
    best_segmentations = [{"start": 0, "score": 1}] + [
        {"start": None, "score": None} for _ in range(len(word))
    ]
    for start_idx in range(len(word)):
        # This should be properly filled by the previous steps of the loop
        best_score_at_start = best_segmentations[start_idx]["score"]
        for end_idx in range(start_idx + 1, len(word) + 1):
            token = word[start_idx:end_idx]
            if token in model and best_score_at_start is not None:
                score = model[token] + best_score_at_start
                # If we have found a better segmentation ending at end_idx, we update
                if (
                    best_segmentations[end_idx]["score"] is None
                    or best_segmentations[end_idx]["score"] > score
                ):
                    best_segmentations[end_idx] = {"start": start_idx, "score": score}

    segmentation = best_segmentations[-1]
    if segmentation["score"] is None:
        # We did not find a tokenization of the word -> unknown
        return ["<unk>"], None

    score = segmentation["score"]
    start = segmentation["start"]
    end = len(word)
    tokens = []
    while start != 0:
        tokens.insert(0, word[start:end])
        next_start = best_segmentations[start]["start"]
        end = start
        start = next_start
    tokens.insert(0, word[start:end])
    return tokens, score
```

നമ്മുടെ പ്രാരംഭ മോഡൽ ചില വാക്കുകളിൽ ഇപ്പോൾ തന്നെ നമുക്ക് പരീക്ഷിക്കാം:


```python
def compute_loss(model):
    loss = 0
    for word, freq in word_freqs.items():
        _, word_loss = encode_word(word, model)
        loss += freq * word_loss
    return loss
```

ഓരോ ടോക്കണിന്റെയും സ്‌കോറുകൾ കണക്കാക്കുന്നതും അത്ര ബുദ്ധിമുട്ടുള്ള കാര്യമല്ല; ഓരോ ടോക്കണും ഒഴിവാക്കി ലഭിക്കുന്ന മോഡലുകളുടെ ലോസ് നമ്മൾ കണക്കാക്കിയാൽ മാത്രം മതി:

```python
import copy


def compute_scores(model):
    scores = {}
    model_loss = compute_loss(model)
    for token, score in model.items():
        # We always keep tokens of length 1
        if len(token) == 1:
            continue
        model_without_token = copy.deepcopy(model)
        _ = model_without_token.pop(token)
        scores[token] = compute_loss(model_without_token) - model_loss
    return scores
```

ഒരു നിശ്ചിത ടോക്കണിൽ നമുക്ക് ഇത് പരീക്ഷിക്കാം:

```python
scores = compute_scores(model)
print(scores["ll"])
print(scores["his"])
```

`"Hopefully"`-യുടെ ടോക്കണൈസേഷനിൽ `"ll"` ഉപയോഗിക്കുന്നതിനാലും, അത് നീക്കം ചെയ്താൽ പകരം `"l"` എന്ന ടോക്കൺ രണ്ട് തവണ ഉപയോഗിക്കേണ്ടി വരാൻ സാധ്യതയുള്ളതിനാലും, അതിന് ഒരു പോസിറ്റീവ് ലോസ് ഉണ്ടാകുമെന്ന് നമ്മൾ പ്രതീക്ഷിക്കുന്നു. `"his"` എന്നത് `"This"` എന്ന വാക്കിനുള്ളിൽ മാത്രമേ ഉപയോഗിക്കുന്നുള്ളൂ, ആ വാക്ക് അതേപടിയാണ് ടോക്കണൈസ് ചെയ്യപ്പെടുന്നത്, അതിനാൽ അതിന് പൂജ്യം ലോസ് ആയിരിക്കുമെന്ന് നമ്മൾ പ്രതീക്ഷിക്കുന്നു. ഫലങ്ങൾ ഇതാ:

```python out

0.0
```

> [!TIP]
> 💡 ഈ സമീപനം വളരെ കാര്യക്ഷമത കുറഞ്ഞതാണ്, അതിനാൽ ടോക്കൺ X ഇല്ലാത്ത മോഡലിന്റെ ലോസിന്റെ ഒരു ഏകദേശ കണക്ക് (approximation) SentencePiece ഉപയോഗിക്കുന്നു: തുടക്കം മുതൽ വീണ്ടും ആരംഭിക്കുന്നതിന് പകരം, ബാക്കിയുള്ള വൊക്കാബുലറിയിലെ അതിന്റെ സെഗ്‌മെന്റേഷൻ കൊണ്ട് ടോക്കൺ X-നെ അത് പകരം വയ്ക്കുന്നു. ഇങ്ങനെ, മോഡൽ ലോസിനൊപ്പം തന്നെ എല്ലാ സ്‌കോറുകളും ഒറ്റയടിക്ക് കണക്കാക്കാൻ കഴിയും.

ഇതെല്ലാം തയ്യാറായിക്കഴിഞ്ഞാൽ, മോഡൽ ഉപയോഗിക്കുന്ന സ്‌പെഷ്യൽ ടോക്കണുകൾ വൊക്കാബുലറിയിലേക്ക് ചേർക്കുകയും, തുടർന്ന് നമുക്ക് വേണ്ട വലുപ്പത്തിൽ എത്താൻ വൊക്കാബുലറിയിൽ നിന്ന് ആവശ്യത്തിന് ടോക്കണുകൾ വെട്ടിമാറ്റുന്നതുവരെ (prune) ലൂപ്പ് ചെയ്യുകയുമാണ് നമ്മൾ ചെയ്യേണ്ട അവസാന കാര്യം:

```python
percent_to_remove = 0.1
while len(model) > 100:
    scores = compute_scores(model)
    sorted_scores = sorted(scores.items(), key=lambda x: x[1])
    # Remove percent_to_remove tokens with the lowest scores.
    for i in range(int(len(model) * percent_to_remove)):
        _ = token_freqs.pop(sorted_scores[i][0])

    total_sum = sum([freq for token, freq in token_freqs.items()])
    model = {token: -log(freq / total_sum) for token, freq in token_freqs.items()}
```

തുടർന്ന്, ഏതെങ്കിലും ടെക്‌സ്‌റ്റ് ടോക്കണൈസ് ചെയ്യാൻ, പ്രീ-ടോക്കണൈസേഷൻ പ്രയോഗിച്ചതിന് ശേഷം നമ്മുടെ `encode_word()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ചാൽ മാത്രം മതി:

```python
def tokenize(text, model):
    words_with_offsets = tokenizer.backend_tokenizer.pre_tokenizer.pre_tokenize_str(text)
    pre_tokenized_text = [word for word, offset in words_with_offsets]
    encoded_words = [encode_word(word, model)[0] for word in pre_tokenized_text]
    return sum(encoded_words, [])


tokenize("This is the Hugging Face course.", model)
```


> [!TIP]
> XLNetTokenizer SentencePiece ഉപയോഗിക്കുന്നു, അതുകൊണ്ടാണ് `"_"` എന്ന ക്യാരക്‌ടർ ഉൾപ്പെട്ടിരിക്കുന്നത്. SentencePiece ഉപയോഗിച്ച് ഡീകോഡ് ചെയ്യാൻ, എല്ലാ ടോക്കണുകളും കൂട്ടിച്ചേർത്ത് (concatenate) `"_"`-നെ ഒരു സ്‌പേസ് കൊണ്ട് പകരം വയ്ക്കുക.

Unigram-നെക്കുറിച്ച് ഇത്രയേയുള്ളൂ! ടോക്കണൈസറുമായി ബന്ധപ്പെട്ട എല്ലാ കാര്യങ്ങളിലും നിങ്ങൾ ഇപ്പോൾ ഒരു എക്‌സ്‌പെർട്ട് ആയതുപോലെ തോന്നുന്നുണ്ടാകുമെന്ന് കരുതുന്നു. അടുത്ത ഭാഗത്തിൽ, 🤗 Tokenizers ലൈബ്രറിയുടെ അടിസ്ഥാന ഘടകങ്ങളിലേക്ക് (building blocks) നമ്മൾ കടക്കുകയും, നിങ്ങളുടെ സ്വന്തം ടോക്കണൈസർ നിർമ്മിക്കാൻ അവ എങ്ങനെ ഉപയോഗിക്കാമെന്ന് കാണിച്ചുതരികയും ചെയ്യും.
