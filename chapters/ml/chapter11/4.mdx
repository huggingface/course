# LoRA (Low-Rank Adaptation)

വലിയ ലാംഗ്വേജ് മോഡലുകൾ ഫൈൻ-ട്യൂൺ ചെയ്യുന്നത് വളരെയധികം വിഭവങ്ങൾ ആവശ്യമുള്ള ഒരു പ്രക്രിയയാണ്. കുറച്ച് പാരാമീറ്ററുകൾ മാത്രം ഉപയോഗിച്ച് വലിയ ലാംഗ്വേജ് മോഡലുകൾ ഫൈൻ-ട്യൂൺ ചെയ്യാൻ നമ്മെ അനുവദിക്കുന്ന ഒരു സങ്കേതമാണ് LoRA. അറ്റൻഷൻ വെയ്റ്റുകളിലേക്ക് ചെറിയ മാട്രിക്‌സുകൾ ചേർത്ത് അവ ഒപ്റ്റിമൈസ് ചെയ്യുന്ന രീതിയിലാണ് ഇത് പ്രവർത്തിക്കുന്നത്; സാധാരണയായി ഇത് ട്രെയിൻ ചെയ്യാവുന്ന പാരാമീറ്ററുകൾ ഏകദേശം 90% കുറയ്ക്കുന്നു.

## LoRA മനസ്സിലാക്കൽ

LoRA (Low-Rank Adaptation) എന്നത് പ്രീട്രെയിൻ ചെയ്ത മോഡൽ വെയ്റ്റുകൾ ഫ്രീസ് ചെയ്ത്, ട്രെയിൻ ചെയ്യാവുന്ന റാങ്ക് ഡീകമ്പോസിഷൻ മാട്രിക്‌സുകൾ (rank decomposition matrices) മോഡലിന്റെ ലെയറുകളിലേക്ക് കുത്തിവയ്ക്കുന്ന ഒരു പാരാമീറ്റർ-കാര്യക്ഷമ ഫൈൻ-ട്യൂണിംഗ് സങ്കേതമാണ്. ഫൈൻ-ട്യൂണിംഗ് സമയത്ത് മോഡലിന്റെ എല്ലാ പാരാമീറ്ററുകളും ട്രെയിൻ ചെയ്യുന്നതിനുപകരം, LoRA വെയ്റ്റ് അപ്‌ഡേറ്റുകളെ ലോ-റാങ്ക് ഡീകമ്പോസിഷൻ വഴി ചെറിയ മാട്രിക്‌സുകളായി വിഭജിക്കുന്നു; ഇത് മോഡലിന്റെ പ്രകടനം നിലനിർത്തിക്കൊണ്ട് ട്രെയിൻ ചെയ്യാവുന്ന പാരാമീറ്ററുകളുടെ എണ്ണം ഗണ്യമായി കുറയ്ക്കുന്നു. ഉദാഹരണത്തിന്, GPT-3 175B-യിൽ പ്രയോഗിച്ചപ്പോൾ, പൂർണ്ണ ഫൈൻ-ട്യൂണിംഗിനെ അപേക്ഷിച്ച് LoRA ട്രെയിൻ ചെയ്യാവുന്ന പാരാമീറ്ററുകൾ 10,000 മടങ്ങും GPU മെമ്മറി ആവശ്യകത 3 മടങ്ങും കുറച്ചു. [LoRA പേപ്പറിൽ](https://arxiv.org/pdf/2106.09685) LoRA-യെക്കുറിച്ച് കൂടുതൽ വായിക്കാം.

ട്രാൻസ്‌ഫോർമർ ലെയറുകളിലേക്ക്, സാധാരണയായി അറ്റൻഷൻ വെയ്റ്റുകളിൽ ശ്രദ്ധ കേന്ദ്രീകരിച്ച്, റാങ്ക് ഡീകമ്പോസിഷൻ മാട്രിക്‌സുകളുടെ ജോഡികൾ ചേർത്താണ് LoRA പ്രവർത്തിക്കുന്നത്. ഇൻഫറൻസ് സമയത്ത്, ഈ അഡാപ്റ്റർ വെയ്റ്റുകൾ ബേസ് മോഡലുമായി ലയിപ്പിക്കാം (merge), അതിനാൽ അധിക ലേറ്റൻസി ഉണ്ടാകുന്നില്ല. വിഭവങ്ങളുടെ ആവശ്യകത കൈകാര്യം ചെയ്യാവുന്ന നിലയിൽ നിർത്തിക്കൊണ്ട് വലിയ ലാംഗ്വേജ് മോഡലുകളെ നിർദ്ദിഷ്ട ടാസ്‌ക്കുകളിലേക്കോ ഡൊമെയ്‌നുകളിലേക്കോ പരുവപ്പെടുത്താൻ LoRA പ്രത്യേകിച്ചും ഉപയോഗപ്രദമാണ്.

## LoRA-യുടെ പ്രധാന ഗുണങ്ങൾ

1. **മെമ്മറി കാര്യക്ഷമത**: 
   - അഡാപ്റ്റർ പാരാമീറ്ററുകൾ മാത്രമേ GPU മെമ്മറിയിൽ സൂക്ഷിക്കുന്നുള്ളൂ
   - ബേസ് മോഡൽ വെയ്റ്റുകൾ ഫ്രീസ് ചെയ്ത നിലയിൽ തുടരുന്നു, അവ കുറഞ്ഞ പ്രിസിഷനിൽ ലോഡ് ചെയ്യാം
   - കൺസ്യൂമർ GPU-കളിൽ വലിയ മോഡലുകൾ ഫൈൻ-ട്യൂൺ ചെയ്യാൻ സാധ്യമാക്കുന്നു

2. **ട്രെയിനിംഗ് ഫീച്ചറുകൾ**:
   - കുറഞ്ഞ സെറ്റപ്പോടെ നേറ്റീവ് PEFT/LoRA ഇന്റഗ്രേഷൻ
   - കൂടുതൽ മികച്ച മെമ്മറി കാര്യക്ഷമതയ്ക്കായി QLoRA (Quantized LoRA) പിന്തുണ

3. **അഡാപ്റ്റർ മാനേജ്‌മെന്റ്**:
   - ചെക്ക്‌പോയിന്റുകളുടെ സമയത്ത് അഡാപ്റ്റർ വെയ്റ്റുകൾ സേവ് ചെയ്യൽ
   - അഡാപ്റ്ററുകളെ ബേസ് മോഡലിലേക്ക് തിരികെ ലയിപ്പിക്കാനുള്ള ഫീച്ചറുകൾ

## PEFT ഉപയോഗിച്ച് LoRA അഡാപ്റ്ററുകൾ ലോഡ് ചെയ്യൽ

[PEFT](https://github.com/huggingface/peft) എന്നത് LoRA ഉൾപ്പെടെയുള്ള PEFT രീതികൾ ലോഡ് ചെയ്യാനും കൈകാര്യം ചെയ്യാനും ഏകീകൃതമായ ഒരു ഇന്റർഫേസ് നൽകുന്ന ലൈബ്രറിയാണ്. വ്യത്യസ്ത PEFT രീതികൾ എളുപ്പത്തിൽ ലോഡ് ചെയ്യാനും അവയ്ക്കിടയിൽ മാറാനും ഇത് നിങ്ങളെ അനുവദിക്കുന്നു, അതുവഴി വ്യത്യസ്ത ഫൈൻ-ട്യൂണിംഗ് സങ്കേതങ്ങൾ പരീക്ഷിക്കുന്നത് എളുപ്പമാകുന്നു. 

`load_adapter()` ഉപയോഗിച്ച് പ്രീട്രെയിൻ ചെയ്ത ഒരു മോഡലിലേക്ക് അഡാപ്റ്ററുകൾ ലോഡ് ചെയ്യാം; വെയ്റ്റുകൾ ലയിപ്പിച്ചിട്ടില്ലാത്ത വ്യത്യസ്ത അഡാപ്റ്ററുകൾ പരീക്ഷിച്ചുനോക്കാൻ ഇത് ഉപയോഗപ്രദമാണ്. `set_adapter()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് ആക്റ്റീവ് അഡാപ്റ്റർ വെയ്റ്റുകൾ സെറ്റ് ചെയ്യുക. ബേസ് മോഡലിലേക്ക് തിരികെ പോകാൻ, എല്ലാ LoRA മൊഡ്യൂളുകളും അൺലോഡ് ചെയ്യാൻ unload() ഉപയോഗിക്കാം. വ്യത്യസ്ത ടാസ്‌ക്-നിർദ്ദിഷ്ട വെയ്റ്റുകൾക്കിടയിൽ മാറുന്നത് ഇത് എളുപ്പമാക്കുന്നു.  

```python
from peft import PeftModel, PeftConfig

config = PeftConfig.from_pretrained("ybelkada/opt-350m-lora")
model = AutoModelForCausalLM.from_pretrained(config.base_model_name_or_path)
lora_model = PeftModel.from_pretrained(model, "ybelkada/opt-350m-lora")
```

## `trl`-ഉം `SFTTrainer`-ഉം LoRA-യും ഉപയോഗിച്ച് LLM ഫൈൻ-ട്യൂൺ ചെയ്യൽ

`trl`-ലെ [SFTTrainer](https://huggingface.co/docs/trl/sft_trainer) [PEFT](https://huggingface.co/docs/peft/en/index) ലൈബ്രറി വഴി LoRA അഡാപ്റ്ററുകളുമായുള്ള ഇന്റഗ്രേഷൻ നൽകുന്നു. അതായത്, SFT ഉപയോഗിച്ച് ചെയ്തതുപോലെ തന്നെ നമുക്ക് ഒരു മോഡൽ ഫൈൻ-ട്യൂൺ ചെയ്യാം, എന്നാൽ ട്രെയിൻ ചെയ്യേണ്ട പാരാമീറ്ററുകളുടെ എണ്ണം കുറയ്ക്കാൻ LoRA ഉപയോഗിക്കാം.

നമ്മുടെ ഉദാഹരണത്തിൽ PEFT-ലെ `LoRAConfig` ക്ലാസ് നമ്മൾ ഉപയോഗിക്കും. സെറ്റപ്പിന് കുറച്ച് കോൺഫിഗറേഷൻ ഘട്ടങ്ങൾ മാത്രമേ ആവശ്യമുള്ളൂ:

1. LoRA കോൺഫിഗറേഷൻ നിർവചിക്കുക (rank, alpha, dropout)
2. PEFT കോൺഫിഗറേഷനോടെ SFTTrainer സൃഷ്ടിക്കുക
3. ട്രെയിൻ ചെയ്ത് അഡാപ്റ്റർ വെയ്റ്റുകൾ സേവ് ചെയ്യുക

## LoRA കോൺഫിഗറേഷൻ

LoRA കോൺഫിഗറേഷനും പ്രധാന പാരാമീറ്ററുകളും നമുക്ക് പരിശോധിക്കാം.

| പാരാമീറ്റർ | വിവരണം |
|-----------|-------------|
| `r` (rank) | വെയ്റ്റ് അപ്‌ഡേറ്റുകൾക്ക് ഉപയോഗിക്കുന്ന ലോ-റാങ്ക് മാട്രിക്‌സുകളുടെ ഡൈമെൻഷൻ. സാധാരണയായി 4-32 ഇടയിൽ. കുറഞ്ഞ മൂല്യങ്ങൾ കൂടുതൽ കംപ്രഷൻ നൽകുന്നു, എന്നാൽ ആവിഷ്‌കാരശേഷി കുറവായിരിക്കാം. |
| `lora_alpha` | LoRA ലെയറുകൾക്കുള്ള സ്കെയിലിംഗ് ഫാക്റ്റർ, സാധാരണയായി rank മൂല്യത്തിന്റെ 2 മടങ്ങായി സെറ്റ് ചെയ്യുന്നു. ഉയർന്ന മൂല്യങ്ങൾ കൂടുതൽ ശക്തമായ അഡാപ്റ്റേഷൻ ഫലങ്ങൾ നൽകുന്നു. |
| `lora_dropout` | LoRA ലെയറുകൾക്കുള്ള ഡ്രോപ്പ്ഔട്ട് പ്രോബബിലിറ്റി, സാധാരണയായി 0.05-0.1. ഉയർന്ന മൂല്യങ്ങൾ ട്രെയിനിംഗ് സമയത്ത് ഓവർഫിറ്റിംഗ് തടയാൻ സഹായിക്കുന്നു. |
| `bias` | ബയസ് ടേമുകളുടെ ട്രെയിനിംഗ് നിയന്ത്രിക്കുന്നു. ഓപ്‌ഷനുകൾ "none", "all", അല്ലെങ്കിൽ "lora_only" എന്നിവയാണ്. മെമ്മറി കാര്യക്ഷമതയ്ക്ക് "none" ആണ് ഏറ്റവും സാധാരണം. |
| `target_modules` | ഏത് മോഡൽ മൊഡ്യൂളുകളിലാണ് LoRA പ്രയോഗിക്കേണ്ടതെന്ന് നിർദ്ദേശിക്കുന്നു. "all-linear" ആകാം, അല്ലെങ്കിൽ "q_proj,v_proj" പോലുള്ള നിർദ്ദിഷ്ട മൊഡ്യൂളുകൾ ആകാം. കൂടുതൽ മൊഡ്യൂളുകൾ കൂടുതൽ അഡാപ്റ്റബിലിറ്റി നൽകുന്നു, എന്നാൽ മെമ്മറി ഉപയോഗം കൂട്ടുന്നു. |

> [!TIP]
> PEFT രീതികൾ ഇംപ്ലിമെന്റ് ചെയ്യുമ്പോൾ, LoRA-ക്ക് ചെറിയ rank മൂല്യങ്ങളിൽ (4-8) തുടങ്ങി ട്രെയിനിംഗ് ലോസ് നിരീക്ഷിക്കുക. ഓവർഫിറ്റിംഗ് തടയാൻ വാലിഡേഷൻ സെറ്റുകൾ ഉപയോഗിക്കുക, സാധ്യമാകുമ്പോൾ പൂർണ്ണ ഫൈൻ-ട്യൂണിംഗ് ബേസ്‌ലൈനുകളുമായി ഫലങ്ങൾ താരതമ്യം ചെയ്യുക. വ്യത്യസ്ത രീതികളുടെ ഫലപ്രാപ്തി ടാസ്‌ക് അനുസരിച്ച് വ്യത്യാസപ്പെടാം, അതിനാൽ പരീക്ഷണമാണ് പ്രധാനം.

## PEFT-നൊപ്പം TRL ഉപയോഗിക്കൽ

മെമ്മറി ആവശ്യകത കുറയ്ക്കാൻ ഫൈൻ-ട്യൂണിംഗിനായി PEFT രീതികളെ TRL-നൊപ്പം സംയോജിപ്പിക്കാം. മോഡൽ ലോഡ് ചെയ്യുമ്പോൾ നമുക്ക് `LoraConfig` മോഡലിലേക്ക് കൈമാറാം.  

```python
from peft import LoraConfig

# r: rank dimension for LoRA update matrices (smaller = more compression)
rank_dimension = 6
# lora_alpha: scaling factor for LoRA layers (higher = stronger adaptation)
lora_alpha = 8
# lora_dropout: dropout probability for LoRA layers (helps prevent overfitting)
lora_dropout = 0.05

peft_config = LoraConfig(
    r=rank_dimension,  # Rank dimension - typically between 4-32
    lora_alpha=lora_alpha,  # LoRA scaling factor - typically 2x rank
    lora_dropout=lora_dropout,  # Dropout probability for LoRA layers
    bias="none",  # Bias type for LoRA. the corresponding biases will be updated during training.
    target_modules="all-linear",  # Which modules to apply LoRA to
    task_type="CAUSAL_LM",  # Task type for model architecture
)
```

മുകളിൽ, മോഡലിനെ ശരിയായ ഡിവൈസിലേക്ക് സ്വയമേവ അസൈൻ ചെയ്യാൻ നമ്മൾ `device_map="auto"` ഉപയോഗിച്ചു. `device_map={"": device_index}` ഉപയോഗിച്ച് ഒരു നിർദ്ദിഷ്ട ഡിവൈസിലേക്ക് മോഡലിനെ മാനുവലായും അസൈൻ ചെയ്യാം. 

LoRA കോൺഫിഗറേഷനോടെ `SFTTrainer` നിർവചിക്കേണ്ടതും ആവശ്യമാണ്.

```python
# Create SFTTrainer with LoRA configuration
trainer = SFTTrainer(
    model=model,
    args=args,
    train_dataset=dataset["train"],
    peft_config=peft_config,  # LoRA configuration
    max_seq_length=max_seq_length,  # Maximum sequence length
    processing_class=tokenizer,
)
```

> [!TIP]
> ✏️ **പരീക്ഷിച്ചുനോക്കൂ!** മുൻ വിഭാഗത്തിൽ നിങ്ങൾ ഫൈൻ-ട്യൂൺ ചെയ്ത മോഡലിൽനിന്ന് തുടങ്ങുക, എന്നാൽ ഇത്തവണ LoRA ഉപയോഗിച്ച് ഫൈൻ-ട്യൂൺ ചെയ്യുക. മുകളിൽ നമ്മൾ നിർവചിച്ച LoRA കോൺഫിഗറേഷൻ ഉപയോഗിച്ച്, `HuggingFaceTB/smoltalk` ഡേറ്റാസെറ്റ് ഉപയോഗിച്ച് ഒരു `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` മോഡൽ ഫൈൻ-ട്യൂൺ ചെയ്യുക.

## LoRA അഡാപ്റ്ററുകൾ ലയിപ്പിക്കൽ

LoRA ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്ത ശേഷം, എളുപ്പത്തിലുള്ള ഡിപ്ലോയ്‌മെന്റിനായി അഡാപ്റ്റർ വെയ്റ്റുകൾ ബേസ് മോഡലിലേക്ക് തിരികെ ലയിപ്പിക്കാൻ നിങ്ങൾ ആഗ്രഹിച്ചേക്കാം. ഇത് സംയോജിത വെയ്റ്റുകളുള്ള ഒരൊറ്റ മോഡൽ സൃഷ്ടിക്കുന്നു, അതുവഴി ഇൻഫറൻസ് സമയത്ത് അഡാപ്റ്ററുകൾ പ്രത്യേകം ലോഡ് ചെയ്യേണ്ട ആവശ്യം ഇല്ലാതാകുന്നു.

ലയിപ്പിക്കൽ പ്രക്രിയയിൽ മെമ്മറി മാനേജ്‌മെന്റിലും പ്രിസിഷനിലും ശ്രദ്ധ വേണം. ബേസ് മോഡലും അഡാപ്റ്റർ വെയ്റ്റുകളും ഒരേസമയം ലോഡ് ചെയ്യേണ്ടതിനാൽ, മതിയായ GPU/CPU മെമ്മറി ലഭ്യമാണെന്ന് ഉറപ്പാക്കുക. `transformers`-ൽ `device_map="auto"` ഉപയോഗിച്ചാൽ നിങ്ങളുടെ ഹാർഡ്‌വെയറിനെ അടിസ്ഥാനമാക്കി മോഡലിന് ശരിയായ ഡിവൈസ് കണ്ടെത്തും. 

പ്രക്രിയയിലുടനീളം സ്ഥിരതയുള്ള പ്രിസിഷൻ (ഉദാ. float16) നിലനിർത്തുക; ട്രെയിനിംഗ് സമയത്ത് ഉപയോഗിച്ച പ്രിസിഷനുമായി പൊരുത്തപ്പെടുത്തുകയും ഡിപ്ലോയ്‌മെന്റിനായി ലയിപ്പിച്ച മോഡൽ അതേ ഫോർമാറ്റിൽ സേവ് ചെയ്യുകയും ചെയ്യുക. 

## ലയിപ്പിക്കൽ ഇംപ്ലിമെന്റേഷൻ

ഒരു LoRA അഡാപ്റ്റർ ട്രെയിൻ ചെയ്ത ശേഷം, അഡാപ്റ്റർ വെയ്റ്റുകൾ ബേസ് മോഡലിലേക്ക് തിരികെ ലയിപ്പിക്കാം. ഇത് എങ്ങനെ ചെയ്യാമെന്ന് ഇതാ:

```python
import torch
from transformers import AutoModelForCausalLM
from peft import PeftModel

# 1. Load the base model
base_model = AutoModelForCausalLM.from_pretrained(
    "base_model_name", torch_dtype=torch.float16, device_map="auto"
)

# 2. Load the PEFT model with adapter
peft_model = PeftModel.from_pretrained(
    base_model, "path/to/adapter", torch_dtype=torch.float16
)

# 3. Merge adapter weights with base model
merged_model = peft_model.merge_and_unload()
```

സേവ് ചെയ്ത മോഡലിൽ വലുപ്പ വ്യത്യാസങ്ങൾ കണ്ടാൽ, ടോക്കണൈസറും സേവ് ചെയ്യുന്നുണ്ടെന്ന് ഉറപ്പാക്കുക:

```python
# Save both model and tokenizer
tokenizer = AutoTokenizer.from_pretrained("base_model_name")
merged_model.save_pretrained("path/to/save/merged_model")
tokenizer.save_pretrained("path/to/save/merged_model")
```

> [!TIP]
> ✏️ **പരീക്ഷിച്ചുനോക്കൂ!** അഡാപ്റ്റർ വെയ്റ്റുകൾ ബേസ് മോഡലിലേക്ക് തിരികെ ലയിപ്പിക്കുക. മുകളിൽ നമ്മൾ നിർവചിച്ച LoRA കോൺഫിഗറേഷൻ ഉപയോഗിച്ച്, `HuggingFaceTB/smoltalk` ഡേറ്റാസെറ്റ് ഉപയോഗിച്ച് ഒരു `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` മോഡൽ ഫൈൻ-ട്യൂൺ ചെയ്യുക.
