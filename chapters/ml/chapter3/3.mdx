🤗 Transformers-ൽ ലഭ്യമായ ഏത് പ്രീട്രെയിൻഡ് മോഡലും, ആധുനികമായ മികച്ച രീതികൾ (best practices) പിന്തുടർന്ന്, നിങ്ങളുടെ ഡേറ്റാസെറ്റിൽ ഫൈൻ-ട്യൂൻ ചെയ്യാൻ സഹായിക്കുന്ന ഒരു `Trainer` ക്ലാസ് 🤗 Transformers നൽകുന്നു. കഴിഞ്ഞ ഭാഗത്തിലെ ഡേറ്റാ പ്രീപ്രോസസ്സിംഗ് ജോലികളെല്ലാം പൂർത്തിയാക്കിക്കഴിഞ്ഞാൽ, `Trainer` നിർവചിക്കാൻ ഇനി ഏതാനും ഘട്ടങ്ങൾ മാത്രമേ ബാക്കിയുള്ളൂ. `Trainer.train()` റൺ ചെയ്യാനുള്ള എൻവയോൺമെന്റ് തയ്യാറാക്കുന്നതായിരിക്കും ഒരുപക്ഷേ ഏറ്റവും ബുദ്ധിമുട്ടുള്ള ഭാഗം, കാരണം ഒരു CPU-വിൽ ഇത് വളരെ പതുക്കെയായിരിക്കും റൺ ചെയ്യുക. നിങ്ങൾക്ക് ഒരു GPU സെറ്റപ്പ് ചെയ്തിട്ടില്ലെങ്കിൽ, [Google Colab](https://colab.research.google.com/)-ൽ സൗജന്യ GPU-കളോ TPU-കളോ നിങ്ങൾക്ക് ഉപയോഗിക്കാം.

> [!TIP]
> 📚 **ട്രെയിനിംഗ് റിസോഴ്‌സുകൾ**: ട്രെയിനിംഗിലേക്ക് കടക്കുന്നതിന് മുമ്പ്, സമഗ്രമായ [🤗 Transformers ട്രെയിനിംഗ് ഗൈഡ്](https://huggingface.co/docs/transformers/main/en/training) പരിചയപ്പെടുകയും [ഫൈൻ-ട്യൂണിംഗ് കുക്ക്‌ബുക്കിലെ](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) പ്രായോഗിക ഉദാഹരണങ്ങൾ പരിശോധിക്കുകയും ചെയ്യുക.

മുൻ ഭാഗത്തിലെ ഉദാഹരണങ്ങൾ നിങ്ങൾ ഇതിനകം റൺ ചെയ്തിട്ടുണ്ട് എന്ന അനുമാനത്തിലാണ് താഴെയുള്ള കോഡ് ഉദാഹരണങ്ങൾ. നിങ്ങൾക്ക് ആവശ്യമുള്ളവ ഓർമ്മിപ്പിക്കുന്ന ഒരു ചെറിയ സംഗ്രഹം ഇതാ:

```py
from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)
```

### ട്രെയിനിംഗ്[[training]]

നമ്മുടെ `Trainer` നിർവചിക്കുന്നതിന് മുമ്പുള്ള ആദ്യ ഘട്ടം, ട്രെയിനിംഗിനും ഇവാല്യുവേഷനും (evaluation) `Trainer` ഉപയോഗിക്കുന്ന എല്ലാ ഹൈപ്പർപാരാമീറ്ററുകളും ഉൾക്കൊള്ളുന്ന ഒരു `TrainingArguments` ക്ലാസ് നിർവചിക്കുകയാണ്. ട്രെയിൻ ചെയ്ത മോഡലും ഇടയ്ക്കിടെയുള്ള ചെക്ക്‌പോയിന്റുകളും സേവ് ചെയ്യേണ്ട ഡയറക്ടറി മാത്രമാണ് നിങ്ങൾ നിർബന്ധമായും നൽകേണ്ട ഒരേയൊരു ആർഗ്യുമെന്റ്. ബാക്കിയെല്ലാം ഡിഫോൾട്ടുകളായി വിടാം; ഒരു അടിസ്ഥാന ഫൈൻ-ട്യൂണിംഗിന് അവ നന്നായി പ്രവർത്തിക്കേണ്ടതാണ്.

```py
from transformers import TrainingArguments

training_args = TrainingArguments("test-trainer")
```

ട്രെയിനിംഗ് സമയത്ത് നിങ്ങളുടെ മോഡൽ Hub-ലേക്ക് സ്വയമേവ അപ്‌ലോഡ് ചെയ്യണമെങ്കിൽ, `TrainingArguments`-ൽ `push_to_hub=True` നൽകുക. ഇതേക്കുറിച്ച് [അധ്യായം 4](/course/chapter4/3)-ൽ നമ്മൾ കൂടുതൽ പഠിക്കും

> [!TIP]
> 🚀 **അഡ്വാൻസ്ഡ് കോൺഫിഗറേഷൻ**: ലഭ്യമായ എല്ലാ ട്രെയിനിംഗ് ആർഗ്യുമെന്റുകളെയും ഒപ്‌റ്റിമൈസേഷൻ തന്ത്രങ്ങളെയും കുറിച്ചുള്ള വിശദമായ വിവരങ്ങൾക്ക്, [TrainingArguments ഡോക്യുമെന്റേഷനും](https://huggingface.co/docs/transformers/main/en/main_classes/trainer#transformers.TrainingArguments) [ട്രെയിനിംഗ് കോൺഫിഗറേഷൻ കുക്ക്‌ബുക്കും](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) പരിശോധിക്കുക.

രണ്ടാമത്തെ ഘട്ടം നമ്മുടെ മോഡൽ നിർവചിക്കുകയാണ്. [മുൻ അധ്യായത്തിലേതുപോലെ](/course/chapter2), രണ്ട് ലേബലുകളോടെ `AutoModelForSequenceClassification` ക്ലാസ് നമ്മൾ ഉപയോഗിക്കും:

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
```

[അധ്യായം 2](/course/chapter2)-ൽ നിന്ന് വ്യത്യസ്തമായി, ഈ പ്രീട്രെയിൻഡ് മോഡൽ ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്ത ശേഷം നിങ്ങൾക്ക് ഒരു മുന്നറിയിപ്പ് (warning) ലഭിക്കുന്നത് നിങ്ങൾ ശ്രദ്ധിക്കും. വാക്യജോഡികൾ വർഗ്ഗീകരിക്കാൻ BERT പ്രീട്രെയിൻ ചെയ്യപ്പെട്ടിട്ടില്ല എന്നതാണ് ഇതിന് കാരണം; അതിനാൽ പ്രീട്രെയിൻഡ് മോഡലിന്റെ ഹെഡ് (head) ഒഴിവാക്കി, പകരം സീക്വൻസ് ക്ലാസിഫിക്കേഷന് അനുയോജ്യമായ ഒരു പുതിയ ഹെഡ് ചേർത്തിരിക്കുന്നു. ചില വെയ്‌റ്റുകൾ ഉപയോഗിച്ചിട്ടില്ലെന്നും (ഒഴിവാക്കിയ പ്രീട്രെയിനിംഗ് ഹെഡിന്റേത്) മറ്റു ചിലത് ക്രമരഹിതമായി (randomly) ഇനിഷ്യലൈസ് ചെയ്യപ്പെട്ടിരിക്കുന്നു എന്നും (പുതിയ ഹെഡിന്റേത്) ഈ മുന്നറിയിപ്പുകൾ സൂചിപ്പിക്കുന്നു. മോഡൽ ട്രെയിൻ ചെയ്യാൻ നിങ്ങളെ പ്രോത്സാഹിപ്പിച്ചുകൊണ്ടാണ് അത് അവസാനിക്കുന്നത് — അതുതന്നെയാണ് നമ്മൾ ഇപ്പോൾ ചെയ്യാൻ പോകുന്നതും.

മോഡൽ തയ്യാറായിക്കഴിഞ്ഞാൽ, ഇതുവരെ നിർമ്മിച്ച എല്ലാ ഒബ്‌ജക്റ്റുകളും — `model`, `training_args`, ട്രെയിനിംഗ്, വാലിഡേഷൻ ഡേറ്റാസെറ്റുകൾ, നമ്മുടെ `data_collator`, നമ്മുടെ `processing_class` — നൽകിക്കൊണ്ട് ഒരു `Trainer` നിർവചിക്കാം. `processing_class` എന്ന പാരാമീറ്റർ അടുത്തകാലത്ത് ചേർത്ത ഒന്നാണ്; പ്രോസസ്സിംഗിന് ഏത് ടോക്കണൈസർ ഉപയോഗിക്കണമെന്ന് ഇത് Trainer-നോട് പറയുന്നു:

```py
from transformers import Trainer

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
)
```

`processing_class` ആയി ഒരു ടോക്കണൈസർ നൽകുമ്പോൾ, `Trainer` ഉപയോഗിക്കുന്ന ഡിഫോൾട്ട് `data_collator` ഒരു `DataCollatorWithPadding` ആയിരിക്കും. ഈ സാഹചര്യത്തിൽ `data_collator=data_collator` എന്ന വരി നിങ്ങൾക്ക് ഒഴിവാക്കാം, എന്നാൽ പ്രോസസ്സിംഗ് പൈപ്പ്‌ലൈനിന്റെ ഈ പ്രധാന ഭാഗം നിങ്ങൾക്ക് കാണിച്ചുതരാനാണ് ഞങ്ങൾ ഇവിടെ അത് ഉൾപ്പെടുത്തിയത്.

> [!TIP]
> 📖 **കൂടുതൽ അറിയാൻ**: Trainer ക്ലാസിനെയും അതിന്റെ പാരാമീറ്ററുകളെയും കുറിച്ചുള്ള സമഗ്രമായ വിവരങ്ങൾക്ക്, [Trainer API ഡോക്യുമെന്റേഷൻ](https://huggingface.co/docs/transformers/main/en/main_classes/trainer) സന്ദർശിക്കുകയും [ട്രെയിനിംഗ് കുക്ക്‌ബുക്ക് റെസിപ്പികളിലെ](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu) അഡ്വാൻസ്ഡ് ഉപയോഗരീതികൾ പരിശോധിക്കുകയും ചെയ്യുക.

നമ്മുടെ ഡേറ്റാസെറ്റിൽ മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യാൻ, നമ്മുടെ `Trainer`-ന്റെ `train()` മെത്തേഡ് വിളിച്ചാൽ മാത്രം മതി:

```py
trainer.train()
```

ഇത് ഫൈൻ-ട്യൂണിംഗ് ആരംഭിക്കുകയും (ഒരു GPU-വിൽ ഇതിന് ഏതാനും മിനിറ്റുകൾ എടുക്കും) ഓരോ 500 സ്‌റ്റെപ്പിലും ട്രെയിനിംഗ് ലോസ് റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യും. എന്നാൽ, നിങ്ങളുടെ മോഡൽ എത്ര നന്നായി (അല്ലെങ്കിൽ മോശമായി) പ്രവർത്തിക്കുന്നു എന്ന് ഇത് നിങ്ങളോട് പറയില്ല. അതിന് കാരണം:

1. `TrainingArguments`-ലെ `eval_strategy` `"steps"` (ഓരോ `eval_steps`-ലും ഇവാല്യുവേറ്റ് ചെയ്യുക) അല്ലെങ്കിൽ `"epoch"` (ഓരോ എപ്പോക്കിന്റെയും അവസാനം ഇവാല്യുവേറ്റ് ചെയ്യുക) എന്ന് സെറ്റ് ചെയ്തുകൊണ്ട്, ട്രെയിനിംഗ് സമയത്ത് ഇവാല്യുവേറ്റ് ചെയ്യാൻ നമ്മൾ `Trainer`-നോട് പറഞ്ഞില്ല.
2. ആ ഇവാല്യുവേഷൻ സമയത്ത് ഒരു മെട്രിക് കണക്കാക്കാനുള്ള `compute_metrics()` ഫംഗ്‌ഷൻ നമ്മൾ `Trainer`-ന് നൽകിയില്ല (അല്ലാത്തപക്ഷം ഇവാല്യുവേഷൻ ലോസ് മാത്രമേ പ്രിന്റ് ചെയ്യുമായിരുന്നുള്ളൂ, അത് അത്ര അവബോധജന്യമായ ഒരു സംഖ്യയല്ല).


### ഇവാല്യുവേഷൻ[[evaluation]]

ഉപകാരപ്രദമായ ഒരു `compute_metrics()` ഫംഗ്‌ഷൻ എങ്ങനെ നിർമ്മിക്കാമെന്നും അടുത്ത തവണ ട്രെയിൻ ചെയ്യുമ്പോൾ അത് എങ്ങനെ ഉപയോഗിക്കാമെന്നും നോക്കാം. ഈ ഫംഗ്‌ഷൻ ഒരു `EvalPrediction` ഒബ്‌ജക്റ്റ് സ്വീകരിക്കണം (`predictions` എന്ന ഫീൽഡും `label_ids` എന്ന ഫീൽഡും ഉള്ള ഒരു named tuple ആണിത്), കൂടാതെ സ്‌ട്രിംഗുകളെ ഫ്ലോട്ടുകളുമായി ബന്ധിപ്പിക്കുന്ന ഒരു ഡിക്‌ഷണറി റിട്ടേൺ ചെയ്യും (സ്‌ട്രിംഗുകൾ റിട്ടേൺ ചെയ്യുന്ന മെട്രിക്കുകളുടെ പേരുകളും, ഫ്ലോട്ടുകൾ അവയുടെ മൂല്യങ്ങളുമാണ്). നമ്മുടെ മോഡലിൽ നിന്ന് ചില പ്രവചനങ്ങൾ (predictions) ലഭിക്കാൻ, `Trainer.predict()` കമാൻഡ് ഉപയോഗിക്കാം:

```py
predictions = trainer.predict(tokenized_datasets["validation"])
print(predictions.predictions.shape, predictions.label_ids.shape)
```

```python out
(408, 2) (408,)
```

`predict()` മെത്തേഡിന്റെ ഔട്ട്‌പുട്ട് മൂന്ന് ഫീൽഡുകളുള്ള മറ്റൊരു named tuple ആണ്: `predictions`, `label_ids`, `metrics`. `metrics` ഫീൽഡിൽ, നൽകിയ ഡേറ്റാസെറ്റിലെ ലോസും ചില സമയ മെട്രിക്കുകളും (പ്രവചിക്കാൻ മൊത്തത്തിലും ശരാശരിയായും എത്ര സമയമെടുത്തു) മാത്രമേ ഉണ്ടാകൂ. നമ്മുടെ `compute_metrics()` ഫംഗ്‌ഷൻ പൂർത്തിയാക്കി `Trainer`-ന് നൽകിക്കഴിഞ്ഞാൽ, `compute_metrics()` റിട്ടേൺ ചെയ്യുന്ന മെട്രിക്കുകളും ആ ഫീൽഡിൽ ഉണ്ടാകും.

നിങ്ങൾക്ക് കാണാവുന്നതുപോലെ, `predictions` എന്നത് 408 x 2 ഷേപ്പുള്ള ഒരു ദ്വിമാന അറേ (two-dimensional array) ആണ് (408 എന്നത് നമ്മൾ ഉപയോഗിച്ച ഡേറ്റാസെറ്റിലെ എലമെന്റുകളുടെ എണ്ണമാണ്). `predict()`-ന് നമ്മൾ നൽകിയ ഡേറ്റാസെറ്റിലെ ഓരോ എലമെന്റിന്റെയും ലോജിറ്റുകളാണ് (logits) ഇവ ([മുൻ അധ്യായത്തിൽ](/course/chapter2) നിങ്ങൾ കണ്ടതുപോലെ, എല്ലാ Transformer മോഡലുകളും ലോജിറ്റുകളാണ് റിട്ടേൺ ചെയ്യുന്നത്). നമ്മുടെ ലേബലുകളുമായി താരതമ്യം ചെയ്യാവുന്ന പ്രവചനങ്ങളാക്കി ഇവയെ മാറ്റാൻ, രണ്ടാമത്തെ ആക്‌സിസിൽ ഏറ്റവും ഉയർന്ന മൂല്യമുള്ള ഇൻഡെക്‌സ് നമ്മൾ എടുക്കണം:

```py
import numpy as np

preds = np.argmax(predictions.predictions, axis=-1)
```

ഇപ്പോൾ ആ `preds` ലേബലുകളുമായി നമുക്ക് താരതമ്യം ചെയ്യാം. നമ്മുടെ `compute_metric()` ഫംഗ്‌ഷൻ നിർമ്മിക്കാൻ, 🤗 [Evaluate](https://github.com/huggingface/evaluate/) ലൈബ്രറിയിലെ മെട്രിക്കുകളെ നമ്മൾ ആശ്രയിക്കും. ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്തതുപോലെ അത്ര എളുപ്പത്തിൽ MRPC ഡേറ്റാസെറ്റുമായി ബന്ധപ്പെട്ട മെട്രിക്കുകളും ലോഡ് ചെയ്യാം; ഇത്തവണ `evaluate.load()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ചാണ്. റിട്ടേൺ ചെയ്യുന്ന ഒബ്‌ജക്റ്റിന്, മെട്രിക് കണക്കുകൂട്ടലിനായി ഉപയോഗിക്കാവുന്ന ഒരു `compute()` മെത്തേഡ് ഉണ്ട്:

```py
import evaluate

metric = evaluate.load("glue", "mrpc")
metric.compute(predictions=preds, references=predictions.label_ids)
```

```python out
{'accuracy': 0.8578431372549019, 'f1': 0.8996539792387542}
```

> [!TIP]
> വിവിധ ഇവാല്യുവേഷൻ മെട്രിക്കുകളെയും തന്ത്രങ്ങളെയും കുറിച്ച് [🤗 Evaluate ഡോക്യുമെന്റേഷനിൽ](https://huggingface.co/docs/evaluate/) പഠിക്കുക.

മോഡൽ ഹെഡിന്റെ ക്രമരഹിതമായ ഇനിഷ്യലൈസേഷൻ അത് നേടുന്ന മെട്രിക്കുകളെ മാറ്റിയേക്കാം എന്നതിനാൽ, നിങ്ങൾക്ക് ലഭിക്കുന്ന കൃത്യമായ ഫലങ്ങൾ വ്യത്യാസപ്പെടാം. ഇവിടെ, നമ്മുടെ മോഡലിന് വാലിഡേഷൻ സെറ്റിൽ 85.78% അക്യുറസിയും (accuracy) 89.97 F1 സ്‌കോറും ഉണ്ടെന്ന് കാണാം. GLUE ബെഞ്ച്‌മാർക്കിനായി MRPC ഡേറ്റാസെറ്റിലെ ഫലങ്ങൾ ഇവാല്യുവേറ്റ് ചെയ്യാൻ ഉപയോഗിക്കുന്ന രണ്ട് മെട്രിക്കുകളാണ് ഇവ. [BERT പ്രബന്ധത്തിലെ](https://arxiv.org/pdf/1810.04805.pdf) പട്ടിക ബേസ് മോഡലിന് 88.9 എന്ന F1 സ്‌കോർ റിപ്പോർട്ട് ചെയ്തിരുന്നു. അത് `uncased` മോഡലായിരുന്നു, നമ്മൾ ഇപ്പോൾ ഉപയോഗിക്കുന്നത് `cased` മോഡലാണ്; അതാണ് മെച്ചപ്പെട്ട ഫലത്തിന്റെ കാരണം.

എല്ലാം ഒരുമിച്ച് ചേർത്താൽ, നമ്മുടെ `compute_metrics()` ഫംഗ്‌ഷൻ ലഭിക്കും:

```py
def compute_metrics(eval_preds):
    metric = evaluate.load("glue", "mrpc")
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)
    return metric.compute(predictions=predictions, references=labels)
```

ഓരോ എപ്പോക്കിന്റെയും അവസാനം മെട്രിക്കുകൾ റിപ്പോർട്ട് ചെയ്യാൻ ഇത് പ്രവർത്തിക്കുന്നത് കാണാൻ, ഈ `compute_metrics()` ഫംഗ്‌ഷനോടെ ഒരു പുതിയ `Trainer` എങ്ങനെ നിർവചിക്കാമെന്ന് ഇതാ:

```py
training_args = TrainingArguments("test-trainer", eval_strategy="epoch")
model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)

trainer = Trainer(
    model,
    training_args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    processing_class=tokenizer,
    compute_metrics=compute_metrics,
)
```

`eval_strategy` `"epoch"` എന്ന് സെറ്റ് ചെയ്ത ഒരു പുതിയ `TrainingArguments`-ഉം ഒരു പുതിയ മോഡലും നമ്മൾ ഉണ്ടാക്കുന്നു എന്നത് ശ്രദ്ധിക്കുക — അല്ലാത്തപക്ഷം, ഇതിനകം ട്രെയിൻ ചെയ്ത മോഡലിന്റെ ട്രെയിനിംഗ് തുടരുകയാകും നമ്മൾ ചെയ്യുന്നത്. ഒരു പുതിയ ട്രെയിനിംഗ് റൺ ആരംഭിക്കാൻ, നമ്മൾ ഇത് എക്‌സിക്യൂട്ട് ചെയ്യുന്നു:

```py
trainer.train()
```

ഇത്തവണ, ട്രെയിനിംഗ് ലോസിനൊപ്പം ഓരോ എപ്പോക്കിന്റെയും അവസാനം വാലിഡേഷൻ ലോസും മെട്രിക്കുകളും ഇത് റിപ്പോർട്ട് ചെയ്യും. മോഡൽ ഹെഡിന്റെ ക്രമരഹിതമായ ഇനിഷ്യലൈസേഷൻ കാരണം, നിങ്ങൾക്ക് ലഭിക്കുന്ന കൃത്യമായ അക്യുറസി/F1 സ്‌കോർ നമ്മൾ കണ്ടതിൽ നിന്ന് അൽപ്പം വ്യത്യസ്തമായിരിക്കാം, എന്നാൽ അത് ഏറെക്കുറെ അതേ പരിധിയിലായിരിക്കണം.

### അഡ്വാൻസ്ഡ് ട്രെയിനിംഗ് സവിശേഷതകൾ[[advanced-training-features]]

ആധുനിക ഡീപ് ലേണിംഗിലെ മികച്ച രീതികൾ എളുപ്പത്തിൽ ലഭ്യമാക്കുന്ന ധാരാളം ബിൽറ്റ്-ഇൻ സവിശേഷതകളോടെയാണ് `Trainer` വരുന്നത്:

**മിക്‌സഡ് പ്രിസിഷൻ ട്രെയിനിംഗ് (Mixed Precision Training)**: വേഗതയേറിയ ട്രെയിനിംഗിനും കുറഞ്ഞ മെമ്മറി ഉപയോഗത്തിനും നിങ്ങളുടെ ട്രെയിനിംഗ് ആർഗ്യുമെന്റുകളിൽ `fp16=True` ഉപയോഗിക്കുക:

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    fp16=True,  # Enable mixed precision
)
```

**ഗ്രേഡിയന്റ് അക്യുമുലേഷൻ (Gradient Accumulation)**: GPU മെമ്മറി പരിമിതമായിരിക്കുമ്പോൾ ഫലത്തിൽ വലിയ ബാച്ച് സൈസുകൾ ലഭിക്കാൻ:

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # Effective batch size = 4 * 4 = 16
)
```

**ലേണിംഗ് റേറ്റ് ഷെഡ്യൂളിംഗ് (Learning Rate Scheduling)**: Trainer ഡിഫോൾട്ടായി ലീനിയർ ഡികേ (linear decay) ഉപയോഗിക്കുന്നു, എന്നാൽ ഇത് നിങ്ങൾക്ക് ഇഷ്ടാനുസൃതമാക്കാം:

```py
training_args = TrainingArguments(
    "test-trainer",
    eval_strategy="epoch",
    learning_rate=2e-5,
    lr_scheduler_type="cosine",  # Try different schedulers
)
```

> [!TIP]
> 🎯 **പെർഫോമൻസ് ഒപ്‌റ്റിമൈസേഷൻ**: ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗ്, മെമ്മറി ഒപ്‌റ്റിമൈസേഷൻ, ഹാർഡ്‌വെയർ-നിർദ്ദിഷ്ട ഒപ്‌റ്റിമൈസേഷനുകൾ എന്നിവയുൾപ്പെടെയുള്ള കൂടുതൽ അഡ്വാൻസ്ഡ് ട്രെയിനിംഗ് ടെക്‌നിക്കുകൾക്കായി, [🤗 Transformers പെർഫോമൻസ് ഗൈഡ്](https://huggingface.co/docs/transformers/main/en/performance) പരിശോധിക്കുക.

`Trainer` ഒന്നിലധികം GPU-കളിലോ TPU-കളിലോ യാതൊരു അധിക സജ്ജീകരണവുമില്ലാതെ പ്രവർത്തിക്കും, കൂടാതെ ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗിനായി ധാരാളം ഓപ്‌ഷനുകളും നൽകുന്നു. ഇത് പിന്തുണയ്ക്കുന്ന എല്ലാ കാര്യങ്ങളും അധ്യായം 10-ൽ നമ്മൾ പരിശോധിക്കും.

`Trainer` API ഉപയോഗിച്ചുള്ള ഫൈൻ-ട്യൂണിംഗിന്റെ ആമുഖം ഇവിടെ അവസാനിക്കുന്നു. ഏറ്റവും സാധാരണമായ NLP ടാസ്‌ക്കുകൾക്ക് ഇത് എങ്ങനെ ചെയ്യാമെന്നതിന്റെ ഒരു ഉദാഹരണം [അധ്യായം 7](/course/chapter7)-ൽ നൽകും, എന്നാൽ ഇപ്പോൾ ഇതേ കാര്യം ശുദ്ധമായ PyTorch ട്രെയിനിംഗ് ലൂപ്പ് ഉപയോഗിച്ച് എങ്ങനെ ചെയ്യാമെന്ന് നോക്കാം.

> [!TIP]
> 📝 **കൂടുതൽ ഉദാഹരണങ്ങൾ**: [🤗 Transformers നോട്ട്‌ബുക്കുകളുടെ](https://huggingface.co/docs/transformers/main/en/notebooks) സമഗ്രമായ ശേഖരം പരിശോധിക്കുക.

> [!TIP]
> 💡 **പ്രധാന പാഠങ്ങൾ:**
> - `Trainer` API ട്രെയിനിംഗിന്റെ സങ്കീർണ്ണതകളിൽ മിക്കതും കൈകാര്യം ചെയ്യുന്ന ഒരു ഉയർന്ന തലത്തിലുള്ള (high-level) ഇന്റർഫേസ് നൽകുന്നു
> - ശരിയായ ഡേറ്റാ കൈകാര്യത്തിനായി നിങ്ങളുടെ ടോക്കണൈസർ വ്യക്തമാക്കാൻ `processing_class` ഉപയോഗിക്കുക
> - `TrainingArguments` ട്രെയിനിംഗിന്റെ എല്ലാ വശങ്ങളും നിയന്ത്രിക്കുന്നു: ലേണിംഗ് റേറ്റ്, ബാച്ച് സൈസ്, ഇവാല്യുവേഷൻ സ്‌ട്രാറ്റജി, ഒപ്‌റ്റിമൈസേഷനുകൾ
> - ട്രെയിനിംഗ് ലോസിനപ്പുറം ഇഷ്ടാനുസൃത ഇവാല്യുവേഷൻ മെട്രിക്കുകൾ `compute_metrics` സാധ്യമാക്കുന്നു
> - മിക്‌സഡ് പ്രിസിഷൻ (`fp16=True`), ഗ്രേഡിയന്റ് അക്യുമുലേഷൻ പോലുള്ള ആധുനിക സവിശേഷതകൾ ട്രെയിനിംഗ് കാര്യക്ഷമത ഗണ്യമായി മെച്ചപ്പെടുത്തും
