`Trainer` ക്ലാസ് ഉപയോഗിക്കാതെ, ആധുനിക PyTorch മികച്ച രീതികൾ (best practices) പിന്തുടർന്ന് തുടക്കം മുതൽ ഒരു ട്രെയിനിംഗ് ലൂപ്പ് ഇംപ്ലിമെന്റ് ചെയ്തുകൊണ്ട്, കഴിഞ്ഞ വിഭാഗത്തിൽ നേടിയ അതേ ഫലങ്ങൾ എങ്ങനെ നേടാം എന്ന് ഇനി നമ്മൾ നോക്കും. വിഭാഗം 2-ലെ ഡേറ്റ പ്രോസസ്സിംഗ് നിങ്ങൾ ചെയ്തിട്ടുണ്ടെന്ന് ഇവിടെയും നമ്മൾ അനുമാനിക്കുന്നു. നിങ്ങൾക്ക് ആവശ്യമായതെല്ലാം ഉൾക്കൊള്ളുന്ന ഒരു ചെറിയ സംഗ്രഹം ഇതാ:

> [!TIP]
> 🏗️ **തുടക്കം മുതൽ ട്രെയിൻ ചെയ്യുന്നു**: ഈ വിഭാഗം മുൻ ഉള്ളടക്കത്തിന്മേൽ കെട്ടിപ്പടുത്തിരിക്കുന്നതാണ്. PyTorch ട്രെയിനിംഗ് ലൂപ്പുകളെയും മികച്ച രീതികളെയും കുറിച്ചുള്ള സമഗ്രമായ മാർഗ്ഗനിർദ്ദേശങ്ങൾക്ക്, [🤗 Transformers ട്രെയിനിംഗ് ഡോക്യുമെന്റേഷനും](https://huggingface.co/docs/transformers/main/en/training#train-in-native-pytorch) [കസ്‌റ്റം ട്രെയിനിംഗ് കുക്ക്‌ബുക്കും](https://huggingface.co/learn/cookbook/en/fine_tuning_code_llm_on_single_gpu#model) നോക്കുക.

```py
from datasets import load_dataset
from transformers import AutoTokenizer, DataCollatorWithPadding

raw_datasets = load_dataset("glue", "mrpc")
checkpoint = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)


def tokenize_function(example):
    return tokenizer(example["sentence1"], example["sentence2"], truncation=True)


tokenized_datasets = raw_datasets.map(tokenize_function, batched=True)
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)
```

### ട്രെയിനിംഗിനായി തയ്യാറെടുക്കുന്നു[[prepare-for-training]]

നമ്മുടെ ട്രെയിനിംഗ് ലൂപ്പ് യഥാർത്ഥത്തിൽ എഴുതുന്നതിന് മുമ്പ്, ഏതാനും ഒബ്‌ജക്റ്റുകൾ നമുക്ക് നിർവചിക്കേണ്ടതുണ്ട്. ബാച്ചുകളിലൂടെ ആവർത്തിച്ച് കടന്നുപോകാൻ (iterate) നമ്മൾ ഉപയോഗിക്കുന്ന ഡേറ്റാലോഡറുകളാണ് (dataloaders) ആദ്യത്തേത്. എന്നാൽ ആ ഡേറ്റാലോഡറുകൾ നിർവചിക്കുന്നതിന് മുമ്പ്, `Trainer` നമുക്കായി സ്വയമേവ ചെയ്തുതന്ന ചില കാര്യങ്ങൾ കൈകാര്യം ചെയ്യാൻ, നമ്മുടെ `tokenized_datasets`-ൽ കുറച്ച് പോസ്‌റ്റ്‌പ്രോസസ്സിംഗ് നമുക്ക് ചെയ്യേണ്ടതുണ്ട്. കൃത്യമായി പറഞ്ഞാൽ, നമ്മൾ ചെയ്യേണ്ടത്:

- മോഡൽ പ്രതീക്ഷിക്കാത്ത മൂല്യങ്ങളുമായി ബന്ധപ്പെട്ട കോളങ്ങൾ (`sentence1`, `sentence2` കോളങ്ങൾ പോലുള്ളവ) നീക്കം ചെയ്യുക.
- `label` എന്ന കോളത്തിന്റെ പേര് `labels` എന്നാക്കി മാറ്റുക (കാരണം ആർഗ്യുമെന്റിന്റെ പേര് `labels` ആയിരിക്കണമെന്നാണ് മോഡൽ പ്രതീക്ഷിക്കുന്നത്).
- ലിസ്‌റ്റുകൾക്ക് പകരം PyTorch ടെൻസറുകൾ റിട്ടേൺ ചെയ്യുന്ന വിധത്തിൽ ഡേറ്റാസെറ്റുകളുടെ ഫോർമാറ്റ് സെറ്റ് ചെയ്യുക.

ഈ ഓരോ ഘട്ടത്തിനും നമ്മുടെ `tokenized_datasets`-ൽ ഒരു മെത്തേഡ് വീതമുണ്ട്:

```py
tokenized_datasets = tokenized_datasets.remove_columns(["sentence1", "sentence2", "idx"])
tokenized_datasets = tokenized_datasets.rename_column("label", "labels")
tokenized_datasets.set_format("torch")
tokenized_datasets["train"].column_names
```

നമ്മുടെ മോഡൽ സ്വീകരിക്കുന്ന കോളങ്ങൾ മാത്രമേ ഫലത്തിൽ ഉള്ളൂ എന്ന് പിന്നീട് നമുക്ക് പരിശോധിക്കാം:

```python
["attention_mask", "input_ids", "labels", "token_type_ids"]
```

ഇത് പൂർത്തിയായ സ്ഥിതിക്ക്, നമ്മുടെ ഡേറ്റാലോഡറുകൾ എളുപ്പത്തിൽ നിർവചിക്കാം:

```py
from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"], shuffle=True, batch_size=8, collate_fn=data_collator
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], batch_size=8, collate_fn=data_collator
)
```

ഡേറ്റ പ്രോസസ്സിംഗിൽ തെറ്റുകളൊന്നുമില്ലെന്ന് വേഗത്തിൽ ഉറപ്പുവരുത്താൻ, ഒരു ബാച്ച് ഇങ്ങനെ പരിശോധിക്കാം:

```py
for batch in train_dataloader:
    break
{k: v.shape for k, v in batch.items()}
```

```python out
{'attention_mask': torch.Size([8, 65]),
 'input_ids': torch.Size([8, 65]),
 'labels': torch.Size([8]),
 'token_type_ids': torch.Size([8, 65])}
```

ട്രെയിനിംഗ് ഡേറ്റാലോഡറിന് `shuffle=True` എന്ന് സെറ്റ് ചെയ്തിരിക്കുന്നതിനാലും ബാച്ചിനുള്ളിലെ പരമാവധി നീളത്തിലേക്ക് നമ്മൾ പാഡിംഗ് ചെയ്യുന്നതിനാലും, യഥാർത്ഥ ഷേപ്പുകൾ (shapes) നിങ്ങൾക്ക് ഒരുപക്ഷേ ചെറുതായി വ്യത്യസ്തമായിരിക്കും എന്നത് ശ്രദ്ധിക്കുക.

ഡേറ്റ പ്രീപ്രോസസ്സിംഗ് പൂർണ്ണമായി തീർന്ന സ്ഥിതിക്ക് (ഏതൊരു ML പ്രാക്റ്റീഷണർക്കും സംതൃപ്തി നൽകുന്ന, എന്നാൽ അപൂർവ്വമായി മാത്രം കൈവരുന്ന ഒരു ലക്ഷ്യം), ഇനി മോഡലിലേക്ക് തിരിയാം. മുൻ വിഭാഗത്തിൽ ചെയ്തതുപോലെ തന്നെ നമ്മൾ അത് ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്നു:

```py
from transformers import AutoModelForSequenceClassification

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
```

ട്രെയിനിംഗ് സമയത്ത് എല്ലാം സുഗമമായി നടക്കുമെന്ന് ഉറപ്പാക്കാൻ, നമ്മുടെ ബാച്ച് ഈ മോഡലിലേക്ക് നൽകുന്നു:

```py
outputs = model(**batch)
print(outputs.loss, outputs.logits.shape)
```

```python out
tensor(0.5441, grad_fn=<NllLossBackward>) torch.Size([8, 2])
```

`labels` നൽകുമ്പോൾ എല്ലാ 🤗 Transformers മോഡലുകളും ലോസ് (loss) റിട്ടേൺ ചെയ്യും; കൂടാതെ ലോജിറ്റുകളും (logits) നമുക്ക് ലഭിക്കും (നമ്മുടെ ബാച്ചിലെ ഓരോ ഇൻപുട്ടിനും രണ്ട് വീതം, അതിനാൽ 8 x 2 വലിപ്പമുള്ള ഒരു ടെൻസർ).

നമ്മുടെ ട്രെയിനിംഗ് ലൂപ്പ് എഴുതാൻ നമ്മൾ ഏകദേശം തയ്യാറായി! രണ്ട് കാര്യങ്ങൾ മാത്രമാണ് ഇനി വേണ്ടത്: ഒരു ഒപ്‌റ്റിമൈസറും (optimizer) ഒരു ലേണിംഗ് റേറ്റ് ഷെഡ്യൂളറും (learning rate scheduler). `Trainer` ചെയ്തിരുന്നത് സ്വന്തമായി പുനഃസൃഷ്ടിക്കാനാണ് നമ്മൾ ശ്രമിക്കുന്നത് എന്നതിനാൽ, അതേ ഡിഫോൾട്ടുകൾ തന്നെ ഉപയോഗിക്കും. `Trainer` ഉപയോഗിക്കുന്ന ഒപ്‌റ്റിമൈസർ `AdamW` ആണ്; ഇത് Adam-ന് തുല്യമാണ്, എന്നാൽ വെയ്‌റ്റ് ഡികേ റെഗുലറൈസേഷനിൽ (weight decay regularization) ഒരു ചെറിയ മാറ്റമുണ്ട് (Ilya Loshchilov, Frank Hutter എന്നിവരുടെ ["Decoupled Weight Decay Regularization"](https://arxiv.org/abs/1711.05101) കാണുക):

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=5e-5)
```

> [!TIP]
> 💡 **ആധുനിക ഒപ്‌റ്റിമൈസേഷൻ നുറുങ്ങുകൾ**: കൂടുതൽ മികച്ച പ്രകടനത്തിനായി, ഇവ പരീക്ഷിക്കാം:
> - **വെയ്‌റ്റ് ഡികേയോടുകൂടിയ AdamW**: `AdamW(model.parameters(), lr=5e-5, weight_decay=0.01)`
> - **8-bit Adam**: മെമ്മറി-കാര്യക്ഷമമായ ഒപ്‌റ്റിമൈസേഷനായി `bitsandbytes` ഉപയോഗിക്കുക
> - **വ്യത്യസ്ത ലേണിംഗ് റേറ്റുകൾ**: വലിയ മോഡലുകൾക്ക് കുറഞ്ഞ ലേണിംഗ് റേറ്റുകൾ (1e-5 മുതൽ 3e-5 വരെ) പലപ്പോഴും കൂടുതൽ നന്നായി പ്രവർത്തിക്കും
>
> 🚀 **ഒപ്‌റ്റിമൈസേഷൻ വിഭവങ്ങൾ**: ഒപ്‌റ്റിമൈസറുകളെയും ട്രെയിനിംഗ് തന്ത്രങ്ങളെയും കുറിച്ച് കൂടുതൽ അറിയാൻ [🤗 Transformers ഒപ്‌റ്റിമൈസേഷൻ ഗൈഡ്](https://huggingface.co/docs/transformers/main/en/performance#optimizer) കാണുക.

അവസാനമായി, ഡിഫോൾട്ടായി ഉപയോഗിക്കുന്ന ലേണിംഗ് റേറ്റ് ഷെഡ്യൂളർ പരമാവധി മൂല്യത്തിൽ (5e-5) നിന്ന് 0-ലേക്കുള്ള ഒരു ലീനിയർ ഡികേ (linear decay) മാത്രമാണ്. ഇത് ശരിയായി നിർവചിക്കാൻ, നമ്മൾ എടുക്കുന്ന ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണം അറിയേണ്ടതുണ്ട്; അത് നമുക്ക് റൺ ചെയ്യേണ്ട എപ്പോക്കുകളുടെ (epochs) എണ്ണത്തെ ട്രെയിനിംഗ് ബാച്ചുകളുടെ എണ്ണം (അതായത് നമ്മുടെ ട്രെയിനിംഗ് ഡേറ്റാലോഡറിന്റെ നീളം) കൊണ്ട് ഗുണിച്ചതാണ്. `Trainer` ഡിഫോൾട്ടായി മൂന്ന് എപ്പോക്കുകൾ ഉപയോഗിക്കുന്നു, അതിനാൽ നമ്മളും അത് പിന്തുടരും:

```py
from transformers import get_scheduler

num_epochs = 3
num_training_steps = num_epochs * len(train_dataloader)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
print(num_training_steps)
```

```python out
1377
```

### ട്രെയിനിംഗ് ലൂപ്പ്[[the-training-loop]]

അവസാനത്തെ ഒരു കാര്യം: ഒരു GPU ലഭ്യമാണെങ്കിൽ അത് ഉപയോഗിക്കാൻ നമ്മൾ ആഗ്രഹിക്കും (ഒരു CPU-വിൽ, ട്രെയിനിംഗിന് ഏതാനും മിനിറ്റുകൾക്ക് പകരം മണിക്കൂറുകൾ എടുത്തേക്കാം). ഇതിനായി, നമ്മുടെ മോഡലും ബാച്ചുകളും വയ്ക്കാനുള്ള ഒരു `device` നമ്മൾ നിർവചിക്കുന്നു:

```py
import torch

device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
model.to(device)
device
```

```python out
device(type='cuda')
```

ഇനി നമ്മൾ ട്രെയിൻ ചെയ്യാൻ തയ്യാറാണ്! ട്രെയിനിംഗ് എപ്പോൾ പൂർത്തിയാകും എന്നതിനെക്കുറിച്ച് ഒരു ധാരണ ലഭിക്കാൻ, `tqdm` ലൈബ്രറി ഉപയോഗിച്ച് നമ്മുടെ ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണത്തിന് മേൽ ഒരു പ്രോഗ്രസ് ബാർ ചേർക്കുന്നു:

```py
from tqdm.auto import tqdm

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dataloader:
        batch = {k: v.to(device) for k, v in batch.items()}
        outputs = model(**batch)
        loss = outputs.loss
        loss.backward()

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)
```

> [!TIP]
> 💡 **ആധുനിക ട്രെയിനിംഗ് ഒപ്‌റ്റിമൈസേഷനുകൾ**: നിങ്ങളുടെ ട്രെയിനിംഗ് ലൂപ്പ് കൂടുതൽ കാര്യക്ഷമമാക്കാൻ, ഇവ പരിഗണിക്കുക:
>
> - **ഗ്രേഡിയന്റ് ക്ലിപ്പിംഗ് (Gradient Clipping)**: `optimizer.step()`-ന് മുമ്പ് `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)` ചേർക്കുക
> - **മിക്‌സഡ് പ്രിസിഷൻ (Mixed Precision)**: വേഗത്തിലുള്ള ട്രെയിനിംഗിനായി `torch.cuda.amp.autocast()`, `GradScaler` എന്നിവ ഉപയോഗിക്കുക
> - **ഗ്രേഡിയന്റ് അക്യുമുലേഷൻ (Gradient Accumulation)**: വലിയ ബാച്ച് സൈസുകൾ അനുകരിക്കാൻ ഒന്നിലധികം ബാച്ചുകളിലായി ഗ്രേഡിയന്റുകൾ സംഭരിക്കുക
> - **ചെക്ക്‌പോയിന്റിംഗ് (Checkpointing)**: ട്രെയിനിംഗ് തടസ്സപ്പെട്ടാൽ പുനരാരംഭിക്കാൻ കഴിയുന്ന വിധത്തിൽ മോഡൽ ചെക്ക്‌പോയിന്റുകൾ ഇടയ്ക്കിടെ സേവ് ചെയ്യുക
>
> 🔧 **ഇംപ്ലിമെന്റേഷൻ ഗൈഡ്**: ഈ ഒപ്‌റ്റിമൈസേഷനുകളുടെ വിശദമായ ഉദാഹരണങ്ങൾക്ക്, [🤗 Transformers കാര്യക്ഷമ ട്രെയിനിംഗ് ഗൈഡും](https://huggingface.co/docs/transformers/main/en/perf_train_gpu_one) [ലഭ്യമായ ഒപ്‌റ്റിമൈസറുകളുടെ പട്ടികയും](https://huggingface.co/docs/transformers/main/en/optimizers) കാണുക.

ട്രെയിനിംഗ് ലൂപ്പിന്റെ കാതലായ ഭാഗം ആമുഖത്തിൽ കണ്ടതിനോട് ഏറെ സാമ്യമുള്ളതാണെന്ന് നിങ്ങൾക്ക് കാണാം. നമ്മൾ ഒരു റിപ്പോർട്ടിംഗും ആവശ്യപ്പെട്ടിട്ടില്ല, അതിനാൽ മോഡൽ എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്നതിനെക്കുറിച്ച് ഈ ട്രെയിനിംഗ് ലൂപ്പ് നമ്മോട് ഒന്നും പറയില്ല. അതിനായി ഒരു ഇവാലുവേഷൻ ലൂപ്പ് (evaluation loop) നമുക്ക് ചേർക്കേണ്ടതുണ്ട്.


### ഇവാലുവേഷൻ ലൂപ്പ്[[the-evaluation-loop]]

മുമ്പ് ചെയ്തതുപോലെ, 🤗 Evaluate ലൈബ്രറി നൽകുന്ന ഒരു മെട്രിക് നമ്മൾ ഉപയോഗിക്കും. `metric.compute()` മെത്തേഡ് നമ്മൾ ഇതിനകം കണ്ടിട്ടുണ്ട്, എന്നാൽ പ്രെഡിക്‌ഷൻ ലൂപ്പിലൂടെ കടന്നുപോകുമ്പോൾ `add_batch()` മെത്തേഡ് ഉപയോഗിച്ച് മെട്രിക്കുകൾക്ക് നമുക്കായി ബാച്ചുകൾ സംഭരിച്ചുവയ്ക്കാനും കഴിയും. എല്ലാ ബാച്ചുകളും സംഭരിച്ചുകഴിഞ്ഞാൽ, `metric.compute()` ഉപയോഗിച്ച് അന്തിമ ഫലം നമുക്ക് ലഭിക്കും. ഇതെല്ലാം ഒരു ഇവാലുവേഷൻ ലൂപ്പിൽ എങ്ങനെ ഇംപ്ലിമെന്റ് ചെയ്യാം എന്ന് ഇതാ:

> [!TIP]
> 📊 **ഇവാലുവേഷനിലെ മികച്ച രീതികൾ**: കൂടുതൽ സങ്കീർണ്ണമായ ഇവാലുവേഷൻ തന്ത്രങ്ങൾക്കും മെട്രിക്കുകൾക്കും, [🤗 Evaluate ഡോക്യുമെന്റേഷനും](https://huggingface.co/docs/evaluate/) [സമഗ്രമായ ഇവാലുവേഷൻ കുക്ക്‌ബുക്കും](https://github.com/huggingface/evaluation-guidebook) പരിശോധിക്കുക.

```py
import evaluate

metric = evaluate.load("glue", "mrpc")
model.eval()
for batch in eval_dataloader:
    batch = {k: v.to(device) for k, v in batch.items()}
    with torch.no_grad():
        outputs = model(**batch)

    logits = outputs.logits
    predictions = torch.argmax(logits, dim=-1)
    metric.add_batch(predictions=predictions, references=batch["labels"])

metric.compute()
```

```python out
{'accuracy': 0.8431372549019608, 'f1': 0.8907849829351535}
```

മോഡൽ ഹെഡിന്റെ ഇനിഷ്യലൈസേഷനിലെയും ഡേറ്റ ഷഫ്‌ളിംഗിലെയും റാൻഡംനെസ് കാരണം നിങ്ങളുടെ ഫലങ്ങൾ ഇവിടെയും ചെറുതായി വ്യത്യസ്തമായിരിക്കും, എന്നാൽ അവ ഏകദേശം ഇതേ പരിധിയിൽ തന്നെ വരണം.

> [!TIP]
> ✏️ **സ്വയം പരീക്ഷിക്കുക!** SST-2 ഡേറ്റാസെറ്റിൽ നിങ്ങളുടെ മോഡൽ ഫൈൻ-ട്യൂൺ ചെയ്യാൻ മുമ്പത്തെ ട്രെയിനിംഗ് ലൂപ്പ് പരിഷ്‌കരിക്കുക.

### 🤗 Accelerate ഉപയോഗിച്ച് നിങ്ങളുടെ ട്രെയിനിംഗ് ലൂപ്പിന് കൂടുതൽ കരുത്ത് പകരുക[[supercharge-your-training-loop-with-accelerate]]

<Youtube id="s7dy8QRgjJ0" />

നമ്മൾ മുമ്പ് നിർവചിച്ച ട്രെയിനിംഗ് ലൂപ്പ് ഒരൊറ്റ CPU-വിലോ GPU-വിലോ നന്നായി പ്രവർത്തിക്കും. എന്നാൽ [🤗 Accelerate](https://github.com/huggingface/accelerate) ലൈബ്രറി ഉപയോഗിച്ച്, ഏതാനും ചെറിയ മാറ്റങ്ങൾ മാത്രം വരുത്തി, ഒന്നിലധികം GPU-കളിലോ TPU-കളിലോ ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗ് (distributed training) നമുക്ക് സാധ്യമാക്കാം. ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗ്, മിക്‌സഡ് പ്രിസിഷൻ, ഡിവൈസ് പ്ലേസ്‌മെന്റ് എന്നിവയുടെ സങ്കീർണ്ണതകൾ 🤗 Accelerate സ്വയമേവ കൈകാര്യം ചെയ്യുന്നു. ട്രെയിനിംഗ്, വാലിഡേഷൻ ഡേറ്റാലോഡറുകൾ സൃഷ്ടിക്കുന്നിടത്തു നിന്ന് തുടങ്ങിയാൽ, നമ്മുടെ മാനുവൽ ട്രെയിനിംഗ് ലൂപ്പ് ഇങ്ങനെയാണ് കാണപ്പെടുന്നത്:

> [!TIP]
> ⚡ **Accelerate-ലേക്ക് ആഴത്തിൽ**: ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗ്, മിക്‌സഡ് പ്രിസിഷൻ, ഹാർഡ്‌വെയർ ഒപ്‌റ്റിമൈസേഷൻ എന്നിവയെക്കുറിച്ച് എല്ലാം [🤗 Accelerate ഡോക്യുമെന്റേഷനിൽ](https://huggingface.co/docs/accelerate/) പഠിക്കുക, [transformers ഡോക്യുമെന്റേഷനിലെ](https://huggingface.co/docs/transformers/main/en/accelerate) പ്രായോഗിക ഉദാഹരണങ്ങൾ പരിശോധിക്കുക.

```py
from accelerate import Accelerator
from torch.optim import AdamW
from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

train_dl, eval_dl, model, optimizer = accelerator.prepare(
    train_dataloader, eval_dataloader, model, optimizer
)

num_epochs = 3
num_training_steps = num_epochs * len(train_dl)
lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)

progress_bar = tqdm(range(num_training_steps))

model.train()
for epoch in range(num_epochs):
    for batch in train_dl:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)
```

ചേർക്കേണ്ട ആദ്യ വരി ഇംപോർട്ട് വരിയാണ്. രണ്ടാമത്തെ വരി ഒരു `Accelerator` ഒബ്‌ജക്റ്റ് ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്നു; അത് പരിസ്ഥിതി (environment) പരിശോധിച്ച് ശരിയായ ഡിസ്‌ട്രിബ്യൂട്ടഡ് സെറ്റപ്പ് ഇനിഷ്യലൈസ് ചെയ്യും. ഡിവൈസ് പ്ലേസ്‌മെന്റ് 🤗 Accelerate നിങ്ങൾക്കായി കൈകാര്യം ചെയ്യുന്നു, അതിനാൽ മോഡലിനെ ഡിവൈസിൽ വയ്ക്കുന്ന വരികൾ നിങ്ങൾക്ക് നീക്കം ചെയ്യാം (അല്ലെങ്കിൽ, വേണമെങ്കിൽ, `device`-ന് പകരം `accelerator.device` ഉപയോഗിക്കുന്ന വിധത്തിൽ അവ മാറ്റാം).

പിന്നീട്, ഡേറ്റാലോഡറുകളും മോഡലും ഒപ്‌റ്റിമൈസറും `accelerator.prepare()`-ലേക്ക് അയയ്ക്കുന്ന വരിയിലാണ് പ്രധാന ജോലിയുടെ സിംഹഭാഗവും നടക്കുന്നത്. നിങ്ങളുടെ ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗ് ഉദ്ദേശിച്ചതുപോലെ പ്രവർത്തിക്കുമെന്ന് ഉറപ്പാക്കാൻ ഇത് ആ ഒബ്‌ജക്റ്റുകളെ ശരിയായ കണ്ടെയ്‌നറിൽ പൊതിയും (wrap). ബാക്കി വരുത്തേണ്ട മാറ്റങ്ങൾ ഇവയാണ്: ബാച്ചിനെ `device`-ൽ വയ്ക്കുന്ന വരി നീക്കം ചെയ്യുക (ഇത് നിലനിർത്തണമെങ്കിൽ, `accelerator.device` ഉപയോഗിക്കുന്ന വിധത്തിൽ മാറ്റിയാൽ മതി), `loss.backward()`-ന് പകരം `accelerator.backward(loss)` ഉപയോഗിക്കുക.

> [!TIP]
> ⚠️ Cloud TPU-കൾ നൽകുന്ന വേഗതാവർദ്ധനവ് പ്രയോജനപ്പെടുത്താൻ, ടോക്കണൈസറിന്റെ `padding="max_length"`, `max_length` എന്നീ ആർഗ്യുമെന്റുകൾ ഉപയോഗിച്ച് നിങ്ങളുടെ സാമ്പിളുകൾ ഒരു നിശ്ചിത നീളത്തിലേക്ക് പാഡ് ചെയ്യാൻ ഞങ്ങൾ ശുപാർശ ചെയ്യുന്നു.

കോപ്പി-പേസ്‌റ്റ് ചെയ്ത് പരീക്ഷിച്ചുനോക്കാൻ നിങ്ങൾക്ക് താൽപ്പര്യമുണ്ടെങ്കിൽ, 🤗 Accelerate ഉപയോഗിച്ചുള്ള പൂർണ്ണമായ ട്രെയിനിംഗ് ലൂപ്പ് ഇങ്ങനെയാണ്:

```py
from accelerate import Accelerator

from transformers import AutoModelForSequenceClassification, get_scheduler

accelerator = Accelerator()

model = AutoModelForSequenceClassification.from_pretrained(checkpoint, num_labels=2)
optimizer = AdamW(model.parameters(), lr=3e-5)

    train_dataloader, eval_dataloader, model, optimizer

num_epochs = 3

    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,

for epoch in range(num_epochs):
```

ഇത് ഒരു നോട്ട്‌ബുക്കിൽ പരീക്ഷിക്കണമെങ്കിൽ (ഉദാഹരണത്തിന്, Colab-ൽ TPU-കൾ ഉപയോഗിച്ച് ടെസ്‌റ്റ് ചെയ്യാൻ), കോഡ് ഒരു `training_function()`-ൽ പേസ്‌റ്റ് ചെയ്ത്, അവസാന സെൽ ഇങ്ങനെ റൺ ചെയ്താൽ മതി:

### അടുത്ത ഘട്ടങ്ങളും മികച്ച രീതികളും[[next-steps-and-best-practices]]

തുടക്കം മുതൽ ട്രെയിനിംഗ് എങ്ങനെ ഇംപ്ലിമെന്റ് ചെയ്യാമെന്ന് നിങ്ങൾ പഠിച്ച സ്ഥിതിക്ക്, പ്രൊഡക്‌ഷൻ ഉപയോഗത്തിനായി പരിഗണിക്കേണ്ട ചില അധിക കാര്യങ്ങൾ ഇതാ:

**മോഡൽ ഇവാലുവേഷൻ**: നിങ്ങളുടെ മോഡൽ എപ്പോഴും ഒന്നിലധികം മെട്രിക്കുകളിൽ വിലയിരുത്തുക, അക്യുറസി (accuracy) മാത്രം നോക്കരുത്. സമഗ്രമായ ഇവാലുവേഷനായി 🤗 Evaluate ലൈബ്രറി ഉപയോഗിക്കുക.

**ഹൈപ്പർപാരാമീറ്റർ ട്യൂണിംഗ്**: വ്യവസ്ഥാപിതമായ ഹൈപ്പർപാരാമീറ്റർ ഒപ്‌റ്റിമൈസേഷനായി Optuna, Ray Tune പോലുള്ള ലൈബ്രറികൾ ഉപയോഗിക്കുന്നത് പരിഗണിക്കുക.

**മോഡൽ മോണിറ്ററിംഗ്**: ട്രെയിനിംഗിലുടനീളം ട്രെയിനിംഗ് മെട്രിക്കുകൾ, ലേണിംഗ് കർവുകൾ, വാലിഡേഷൻ പ്രകടനം എന്നിവ നിരീക്ഷിക്കുക.

**മോഡൽ പങ്കുവയ്ക്കൽ**: ട്രെയിൻ ചെയ്തുകഴിഞ്ഞാൽ, കമ്മ്യൂണിറ്റിക്ക് ലഭ്യമാക്കാൻ നിങ്ങളുടെ മോഡൽ Hugging Face Hub-ൽ പങ്കുവയ്ക്കുക.

**കാര്യക്ഷമത**: വലിയ മോഡലുകൾക്ക്, ഗ്രേഡിയന്റ് ചെക്ക്‌പോയിന്റിംഗ്, പാരാമീറ്റർ-കാര്യക്ഷമമായ ഫൈൻ-ട്യൂണിംഗ് (LoRA, AdaLoRA), ക്വാണ്ടൈസേഷൻ (quantization) രീതികൾ തുടങ്ങിയ സങ്കേതങ്ങൾ പരിഗണിക്കുക.

കസ്‌റ്റം ട്രെയിനിംഗ് ലൂപ്പുകൾ ഉപയോഗിച്ചുള്ള ഫൈൻ-ട്യൂണിംഗിലേക്കുള്ള നമ്മുടെ ആഴത്തിലുള്ള അന്വേഷണം ഇവിടെ അവസാനിക്കുന്നു. ട്രെയിനിംഗ് പ്രക്രിയയിൽ പൂർണ്ണ നിയന്ത്രണം ആവശ്യമായി വരുമ്പോഴോ, `Trainer` API നൽകുന്നതിനപ്പുറമുള്ള കസ്‌റ്റം ട്രെയിനിംഗ് ലോജിക് ഇംപ്ലിമെന്റ് ചെയ്യാൻ ആഗ്രഹിക്കുമ്പോഴോ, ഇവിടെ നിങ്ങൾ പഠിച്ച കഴിവുകൾ നിങ്ങൾക്ക് ഏറെ ഉപകാരപ്പെടും.
