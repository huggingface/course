താഴെയുള്ള ഘട്ടങ്ങളിൽ, പ്രീട്രെയിൻഡ് മോഡലുകൾ 🤗 Hub-ലേക്ക് പങ്കുവെക്കാനുള്ള ഏറ്റവും എളുപ്പമുള്ള വഴികൾ നമ്മൾ നോക്കും. Hub-ൽ നേരിട്ട് മോഡലുകൾ പങ്കുവെക്കാനും അപ്‌ഡേറ്റ് ചെയ്യാനും ലളിതമാക്കുന്ന ടൂളുകളും യൂട്ടിലിറ്റികളും ലഭ്യമാണ്; അവ നമ്മൾ താഴെ പരിശോധിക്കും.

<Youtube id="9yY3RB_GSPM"/>

മോഡലുകൾ ട്രെയിൻ ചെയ്യുന്ന എല്ലാ ഉപയോക്താക്കളെയും അവ കമ്മ്യൂണിറ്റിയുമായി പങ്കുവെച്ച് സംഭാവന ചെയ്യാൻ ഞങ്ങൾ പ്രോത്സാഹിപ്പിക്കുന്നു — വളരെ പ്രത്യേകമായ ഡേറ്റാസെറ്റുകളിൽ ട്രെയിൻ ചെയ്തവയാണെങ്കിൽ പോലും, മോഡലുകൾ പങ്കുവെക്കുന്നത് മറ്റുള്ളവർക്ക് സഹായകമാകും; അത് അവരുടെ സമയവും കമ്പ്യൂട്ട് വിഭവങ്ങളും ലാഭിക്കുകയും, ഉപകാരപ്രദമായ ട്രെയിൻഡ് ആർട്ടിഫാക്റ്റുകളിലേക്ക് പ്രവേശനം നൽകുകയും ചെയ്യുന്നു. അതുപോലെ, മറ്റുള്ളവർ ചെയ്ത ജോലിയിൽ നിന്ന് നിങ്ങൾക്കും പ്രയോജനം നേടാം!

പുതിയ മോഡൽ റിപ്പോസിറ്ററികൾ ഉണ്ടാക്കാൻ മൂന്ന് വഴികളുണ്ട്:

- `push_to_hub` API ഉപയോഗിച്ച്
- `huggingface_hub` Python ലൈബ്രറി ഉപയോഗിച്ച്
- വെബ് ഇന്റർഫേസ് ഉപയോഗിച്ച്

ഒരു റിപ്പോസിറ്ററി ഉണ്ടാക്കിക്കഴിഞ്ഞാൽ, git-ഉം git-lfs-ഉം വഴി അതിലേക്ക് ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യാം. തുടർന്നുള്ള വിഭാഗങ്ങളിൽ മോഡൽ റിപ്പോസിറ്ററികൾ ഉണ്ടാക്കുന്നതും അവയിലേക്ക് ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യുന്നതും ഞങ്ങൾ ഘട്ടം ഘട്ടമായി കാണിച്ചുതരാം.


## `push_to_hub` API ഉപയോഗിക്കുന്നു[[using-the-pushtohub-api]]

Hub-ലേക്ക് ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യാനുള്ള ഏറ്റവും ലളിതമായ വഴി `push_to_hub` API പ്രയോജനപ്പെടുത്തുന്നതാണ്.

മുന്നോട്ട് പോകുന്നതിന് മുമ്പ്, നിങ്ങൾ ആരാണെന്നും ഏതൊക്കെ നെയിംസ്‌പേസുകളിൽ നിങ്ങൾക്ക് എഴുതാനുള്ള അനുമതി (write access) ഉണ്ടെന്നും `huggingface_hub` API-ക്ക് അറിയാൻ ഒരു ഓതന്റിക്കേഷൻ ടോക്കൺ നിങ്ങൾ ജനറേറ്റ് ചെയ്യേണ്ടതുണ്ട്. `transformers` ഇൻസ്‌റ്റാൾ ചെയ്തിട്ടുള്ള ഒരു എൻവയോൺമെന്റിലാണ് നിങ്ങൾ എന്ന് ഉറപ്പാക്കുക ([സെറ്റപ്പ്](/course/chapter0) കാണുക). നിങ്ങൾ ഒരു നോട്ട്‌ബുക്കിലാണെങ്കിൽ, ലോഗിൻ ചെയ്യാൻ താഴെയുള്ള ഫംഗ്‌ഷൻ ഉപയോഗിക്കാം:

```python
from huggingface_hub import notebook_login

notebook_login()
```

ഒരു ടെർമിനലിൽ, നിങ്ങൾക്ക് ഇത് റൺ ചെയ്യാം:

```bash
huggingface-cli login
```

രണ്ട് സാഹചര്യങ്ങളിലും, നിങ്ങളുടെ യൂസർനെയിമും പാസ്‌വേഡും ചോദിക്കും; Hub-ൽ ലോഗിൻ ചെയ്യാൻ നിങ്ങൾ ഉപയോഗിക്കുന്ന അതേ വിവരങ്ങളാണ് ഇവ. നിങ്ങൾക്ക് ഇതുവരെ ഒരു Hub പ്രൊഫൈൽ ഇല്ലെങ്കിൽ, [ഇവിടെ](https://huggingface.co/join) ഒന്ന് ഉണ്ടാക്കുക.

കൊള്ളാം! നിങ്ങളുടെ ഓതന്റിക്കേഷൻ ടോക്കൺ ഇപ്പോൾ നിങ്ങളുടെ കാഷ് ഫോൾഡറിൽ സംഭരിച്ചിരിക്കുന്നു. ഇനി കുറച്ച് റിപ്പോസിറ്ററികൾ ഉണ്ടാക്കാം!

{#if fw === 'pt'}

ഒരു മോഡൽ ട്രെയിൻ ചെയ്യാൻ `Trainer` API നിങ്ങൾ പരീക്ഷിച്ചിട്ടുണ്ടെങ്കിൽ, അത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാനുള്ള ഏറ്റവും എളുപ്പമുള്ള വഴി നിങ്ങളുടെ `TrainingArguments` നിർവചിക്കുമ്പോൾ `push_to_hub=True` എന്ന് സെറ്റ് ചെയ്യുന്നതാണ്:

```py
from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)
```

നിങ്ങൾ `trainer.train()` വിളിക്കുമ്പോൾ, മോഡൽ സേവ് ചെയ്യപ്പെടുന്ന ഓരോ തവണയും (ഇവിടെ ഓരോ എപ്പോക്കിലും) `Trainer` അത് നിങ്ങളുടെ നെയിംസ്‌പേസിലെ ഒരു റിപ്പോസിറ്ററിയിലേക്ക് Hub-ൽ അപ്‌ലോഡ് ചെയ്യും. നിങ്ങൾ തിരഞ്ഞെടുത്ത ഔട്ട്‌പുട്ട് ഡയറക്ടറിയുടെ പേരായിരിക്കും (ഇവിടെ `bert-finetuned-mrpc`) ആ റിപ്പോസിറ്ററിക്ക്, എന്നാൽ `hub_model_id = "a_different_name"` ഉപയോഗിച്ച് നിങ്ങൾക്ക് മറ്റൊരു പേര് തിരഞ്ഞെടുക്കാം.

നിങ്ങൾ അംഗമായ ഒരു ഓർഗനൈസേഷനിലേക്ക് നിങ്ങളുടെ മോഡൽ അപ്‌ലോഡ് ചെയ്യാൻ, `hub_model_id = "my_organization/my_repo_name"` എന്ന് നൽകിയാൽ മതി.

ട്രെയിനിംഗ് പൂർത്തിയായിക്കഴിഞ്ഞാൽ, നിങ്ങളുടെ മോഡലിന്റെ അവസാന പതിപ്പ് അപ്‌ലോഡ് ചെയ്യാൻ അവസാനമായി ഒരു `trainer.push_to_hub()` ചെയ്യണം. ഉപയോഗിച്ച ഹൈപ്പർപാരാമീറ്ററുകളും ഇവാല്യുവേഷൻ ഫലങ്ങളും റിപ്പോർട്ട് ചെയ്യുന്ന, പ്രസക്തമായ എല്ലാ മെറ്റാഡേറ്റയും അടങ്ങിയ ഒരു മോഡൽ കാർഡും ഇത് ജനറേറ്റ് ചെയ്യും! അങ്ങനെയുള്ള ഒരു മോഡൽ കാർഡിൽ നിങ്ങൾ കണ്ടേക്കാവുന്ന ഉള്ളടക്കത്തിന്റെ ഒരു ഉദാഹരണം ഇതാ:

</div>

{:else}

നിങ്ങളുടെ മോഡൽ ട്രെയിൻ ചെയ്യാൻ Keras ആണ് ഉപയോഗിക്കുന്നതെങ്കിൽ, അത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാനുള്ള ഏറ്റവും എളുപ്പമുള്ള വഴി `model.fit()` വിളിക്കുമ്പോൾ ഒരു `PushToHubCallback` കൈമാറുന്നതാണ്:

```py
from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)
```

തുടർന്ന് നിങ്ങളുടെ `model.fit()` കോളിൽ `callbacks=[callback]` ചേർക്കണം. മോഡൽ സേവ് ചെയ്യപ്പെടുന്ന ഓരോ തവണയും (ഇവിടെ ഓരോ എപ്പോക്കിലും) കോൾബാക്ക് അത് നിങ്ങളുടെ നെയിംസ്‌പേസിലെ ഒരു റിപ്പോസിറ്ററിയിലേക്ക് Hub-ൽ അപ്‌ലോഡ് ചെയ്യും. നിങ്ങൾ തിരഞ്ഞെടുത്ത ഔട്ട്‌പുട്ട് ഡയറക്ടറിയുടെ പേരായിരിക്കും (ഇവിടെ `bert-finetuned-mrpc`) ആ റിപ്പോസിറ്ററിക്ക്, എന്നാൽ `hub_model_id = "a_different_name"` ഉപയോഗിച്ച് നിങ്ങൾക്ക് മറ്റൊരു പേര് തിരഞ്ഞെടുക്കാം.

നിങ്ങൾ അംഗമായ ഒരു ഓർഗനൈസേഷനിലേക്ക് നിങ്ങളുടെ മോഡൽ അപ്‌ലോഡ് ചെയ്യാൻ, `hub_model_id = "my_organization/my_repo_name"` എന്ന് നൽകിയാൽ മതി.

{/if}

കുറച്ചുകൂടി താഴ്ന്ന തലത്തിൽ, മോഡലുകൾ, ടോക്കണൈസറുകൾ, കോൺഫിഗറേഷൻ ഒബ്‌ജക്റ്റുകൾ എന്നിവയുടെ `push_to_hub()` മെത്തേഡ് വഴി അവയിൽ നേരിട്ട് Model Hub ആക്‌സസ് ചെയ്യാം. റിപ്പോസിറ്ററി ഉണ്ടാക്കുന്നതും മോഡൽ, ടോക്കണൈസർ ഫയലുകൾ നേരിട്ട് റിപ്പോസിറ്ററിയിലേക്ക് പുഷ് ചെയ്യുന്നതും ഈ മെത്തേഡ് തന്നെ കൈകാര്യം ചെയ്യുന്നു. താഴെ നമ്മൾ കാണുന്ന API-യിൽ നിന്ന് വ്യത്യസ്തമായി, ഇവിടെ മാനുവലായി ഒന്നും ചെയ്യേണ്ടതില്ല.

ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്ന് മനസ്സിലാക്കാൻ, ആദ്യം ഒരു മോഡലും ഒരു ടോക്കണൈസറും ഇനിഷ്യലൈസ് ചെയ്യാം:

{#if fw === 'pt'}
```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{:else}
```py
from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{/if}

ഇവ ഉപയോഗിച്ച് നിങ്ങൾക്ക് ഇഷ്ടമുള്ളതെന്തും ചെയ്യാം — ടോക്കണൈസറിലേക്ക് ടോക്കണുകൾ ചേർക്കുക, മോഡൽ ട്രെയിൻ ചെയ്യുക, ഫൈൻ-ട്യൂൺ ചെയ്യുക. ലഭിച്ച മോഡൽ, വെയ്‌റ്റുകൾ, ടോക്കണൈസർ എന്നിവയിൽ നിങ്ങൾ തൃപ്തരായിക്കഴിഞ്ഞാൽ, `model` ഒബ്‌ജക്റ്റിൽ നേരിട്ട് ലഭ്യമായ `push_to_hub()` മെത്തേഡ് നിങ്ങൾക്ക് പ്രയോജനപ്പെടുത്താം:

```py
model.push_to_hub("dummy-model")
```

ഇത് നിങ്ങളുടെ പ്രൊഫൈലിൽ `dummy-model` എന്ന പുതിയ റിപ്പോസിറ്ററി ഉണ്ടാക്കി, നിങ്ങളുടെ മോഡൽ ഫയലുകൾ അതിൽ നിറയ്ക്കും.
ടോക്കണൈസറിനും ഇതേ കാര്യം ചെയ്യുക, അങ്ങനെ എല്ലാ ഫയലുകളും ഇപ്പോൾ ഈ റിപ്പോസിറ്ററിയിൽ ലഭ്യമാകും:

```py
tokenizer.push_to_hub("dummy-model")
```

നിങ്ങൾ ഒരു ഓർഗനൈസേഷനിൽ അംഗമാണെങ്കിൽ, ആ ഓർഗനൈസേഷന്റെ നെയിംസ്‌പേസിലേക്ക് അപ്‌ലോഡ് ചെയ്യാൻ `organization` ആർഗ്യുമെന്റ് വ്യക്തമാക്കിയാൽ മതി:

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface")
```

ഒരു പ്രത്യേക Hugging Face ടോക്കൺ ഉപയോഗിക്കാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ, അതും `push_to_hub()` മെത്തേഡിന് നൽകാൻ നിങ്ങൾക്ക് സ്വാതന്ത്ര്യമുണ്ട്:

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")
```

ഇനി Model Hub-ലേക്ക് പോയി നിങ്ങൾ പുതുതായി അപ്‌ലോഡ് ചെയ്ത മോഡൽ കണ്ടെത്തുക: *https://huggingface.co/user-or-organization/dummy-model*.

> ✏️ **സ്വയം പരീക്ഷിക്കുക!** `bert-base-cased` ചെക്ക്‌പോയിന്റുമായി ബന്ധപ്പെട്ട മോഡലും ടോക്കണൈസറും എടുത്ത്, `push_to_hub()` മെത്തേഡ് ഉപയോഗിച്ച് നിങ്ങളുടെ നെയിംസ്‌പേസിലെ ഒരു റിപ്പോയിലേക്ക് അപ്‌ലോഡ് ചെയ്യുക. റിപ്പോ ഡിലീറ്റ് ചെയ്യുന്നതിന് മുമ്പ് അത് നിങ്ങളുടെ പേജിൽ ശരിയായി കാണുന്നുണ്ടെന്ന് ഒന്നുകൂടി ഉറപ്പുവരുത്തുക.

നിങ്ങൾ കണ്ടതുപോലെ, `push_to_hub()` മെത്തേഡ് പല ആർഗ്യുമെന്റുകൾ സ്വീകരിക്കുന്നു; അതുവഴി ഒരു പ്രത്യേക റിപ്പോസിറ്ററിയിലേക്കോ ഓർഗനൈസേഷൻ നെയിംസ്‌പേസിലേക്കോ അപ്‌ലോഡ് ചെയ്യാനും, മറ്റൊരു API ടോക്കൺ ഉപയോഗിക്കാനും സാധിക്കും. എന്തൊക്കെ സാധ്യമാണ് എന്ന് മനസ്സിലാക്കാൻ [🤗 Transformers ഡോക്യുമെന്റേഷനിൽ](https://huggingface.co/transformers/model_sharing) നേരിട്ട് ലഭ്യമായ മെത്തേഡ് സ്‌പെസിഫിക്കേഷൻ ഒന്ന് നോക്കാൻ ഞങ്ങൾ ശുപാർശ ചെയ്യുന്നു.

`push_to_hub()` മെത്തേഡിന് പിന്നിൽ പ്രവർത്തിക്കുന്നത് [`huggingface_hub`](https://github.com/huggingface/huggingface_hub) Python പാക്കേജാണ്; ഇത് Hugging Face Hub-ലേക്ക് ഒരു നേരിട്ടുള്ള API നൽകുന്നു. 🤗 Transformers-ലും, [`allenlp`](https://github.com/allenai/allennlp) പോലുള്ള മറ്റ് പല മെഷീൻ ലേണിംഗ് ലൈബ്രറികളിലും ഇത് ഇന്റഗ്രേറ്റ് ചെയ്തിട്ടുണ്ട്. ഈ അധ്യായത്തിൽ നമ്മൾ 🤗 Transformers ഇന്റഗ്രേഷനിലാണ് ശ്രദ്ധ കേന്ദ്രീകരിക്കുന്നതെങ്കിലും, നിങ്ങളുടെ സ്വന്തം കോഡിലോ ലൈബ്രറിയിലോ ഇത് ഇന്റഗ്രേറ്റ് ചെയ്യുന്നത് ലളിതമാണ്.

നിങ്ങൾ പുതുതായി ഉണ്ടാക്കിയ റിപ്പോസിറ്ററിയിലേക്ക് ഫയലുകൾ എങ്ങനെ അപ്‌ലോഡ് ചെയ്യാമെന്ന് കാണാൻ അവസാന വിഭാഗത്തിലേക്ക് പോകുക!

## `huggingface_hub` Python ലൈബ്രറി ഉപയോഗിക്കുന്നു[[using-the-huggingfacehub-python-library]]

`huggingface_hub` Python ലൈബ്രറി, മോഡൽ, ഡേറ്റാസെറ്റ് ഹബ്ബുകൾക്കായുള്ള ഒരു കൂട്ടം ടൂളുകൾ നൽകുന്ന ഒരു പാക്കേജാണ്. Hub-ലെ റിപ്പോസിറ്ററികളെക്കുറിച്ചുള്ള വിവരങ്ങൾ നേടുക, അവ കൈകാര്യം ചെയ്യുക തുടങ്ങിയ 
സാധാരണ ടാസ്‌ക്കുകൾക്കായി ലളിതമായ മെത്തേഡുകളും ക്ലാസുകളും ഇത് നൽകുന്നു. ആ റിപ്പോസിറ്ററികളുടെ ഉള്ളടക്കം കൈകാര്യം ചെയ്യാനും നിങ്ങളുടെ പ്രോജക്റ്റുകളിലും ലൈബ്രറികളിലും Hub-നെ
സംയോജിപ്പിക്കാനും git-ന് മുകളിൽ പ്രവർത്തിക്കുന്ന ലളിതമായ API-കളും ഇത് നൽകുന്നു.

`push_to_hub` API ഉപയോഗിക്കുന്നതുപോലെ, ഇതിനും നിങ്ങളുടെ API ടോക്കൺ കാഷിൽ സേവ് ചെയ്തിരിക്കണം. അതിനായി, മുൻ വിഭാഗത്തിൽ പറഞ്ഞതുപോലെ CLI-യിലെ `login` കമാൻഡ് നിങ്ങൾ ഉപയോഗിക്കേണ്ടതുണ്ട് (Google Colab-ൽ റൺ ചെയ്യുന്നെങ്കിൽ ഈ കമാൻഡുകൾക്ക് മുന്നിൽ `!` എന്ന ചിഹ്നം ചേർക്കാൻ വീണ്ടും ഓർക്കുക):

```bash
huggingface-cli login
```

നമ്മുടെ ആവശ്യത്തിന് ഉപകാരപ്രദമായ പല മെത്തേഡുകളും ക്ലാസുകളും `huggingface_hub` പാക്കേജ് നൽകുന്നു. ആദ്യമായി, റിപ്പോസിറ്ററി ഉണ്ടാക്കൽ, ഡിലീറ്റ് ചെയ്യൽ തുടങ്ങിയവ കൈകാര്യം ചെയ്യാൻ ഏതാനും മെത്തേഡുകളുണ്ട്:

```python no-format
from huggingface_hub import (
    # User management
    login,
    logout,
    whoami,

    # Repository creation and management
    create_repo,
    delete_repo,
    update_repo_visibility,

    # And some methods to retrieve/change information about the content
    list_models,
    list_datasets,
    list_metrics,
    list_repo_files,
    upload_file,
    delete_file,
)
```


കൂടാതെ, ഒരു ലോക്കൽ റിപ്പോസിറ്ററി കൈകാര്യം ചെയ്യാൻ വളരെ ശക്തമായ `Repository` ക്ലാസും ഇത് നൽകുന്നു. ഇവ എങ്ങനെ പ്രയോജനപ്പെടുത്താം എന്ന് മനസ്സിലാക്കാൻ അടുത്ത ഏതാനും വിഭാഗങ്ങളിൽ ഈ മെത്തേഡുകളും ആ ക്ലാസും നമ്മൾ പരിശോധിക്കും.

Hub-ൽ ഒരു പുതിയ റിപ്പോസിറ്ററി ഉണ്ടാക്കാൻ `create_repo` മെത്തേഡ് ഉപയോഗിക്കാം:

```py
from huggingface_hub import create_repo

create_repo("dummy-model")
```

ഇത് നിങ്ങളുടെ നെയിംസ്‌പേസിൽ `dummy-model` എന്ന റിപ്പോസിറ്ററി ഉണ്ടാക്കും. വേണമെങ്കിൽ, `organization` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് റിപ്പോസിറ്ററി ഏത് ഓർഗനൈസേഷന്റേതായിരിക്കണം എന്ന് നിങ്ങൾക്ക് വ്യക്തമാക്കാം:

```py
from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")
```

നിങ്ങൾ ആ ഓർഗനൈസേഷനിൽ അംഗമാണെങ്കിൽ, ഇത് `huggingface` നെയിംസ്‌പേസിൽ `dummy-model` റിപ്പോസിറ്ററി ഉണ്ടാക്കും.
ഉപകാരപ്രദമാകാവുന്ന മറ്റ് ആർഗ്യുമെന്റുകൾ:

- `private`, റിപ്പോസിറ്ററി മറ്റുള്ളവർക്ക് കാണാവുന്നതായിരിക്കണോ വേണ്ടയോ എന്ന് വ്യക്തമാക്കാൻ.
- `token`, നിങ്ങളുടെ കാഷിൽ സംഭരിച്ചിരിക്കുന്ന ടോക്കണിന് പകരം ഒരു നിശ്ചിത ടോക്കൺ ഉപയോഗിക്കാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ.
- `repo_type`, ഒരു മോഡലിന് പകരം ഒരു `dataset` അല്ലെങ്കിൽ ഒരു `space` ഉണ്ടാക്കാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ. സ്വീകരിക്കുന്ന മൂല്യങ്ങൾ `"dataset"`, `"space"` എന്നിവയാണ്.

റിപ്പോസിറ്ററി ഉണ്ടാക്കിക്കഴിഞ്ഞാൽ, അതിലേക്ക് ഫയലുകൾ ചേർക്കണം! ഇത് ചെയ്യാവുന്ന മൂന്ന് വഴികൾ കാണാൻ അടുത്ത വിഭാഗത്തിലേക്ക് പോകുക.


## വെബ് ഇന്റർഫേസ് ഉപയോഗിക്കുന്നു[[using-the-web-interface]]

Hub-ൽ നേരിട്ട് റിപ്പോസിറ്ററികൾ കൈകാര്യം ചെയ്യാനുള്ള ടൂളുകൾ വെബ് ഇന്റർഫേസ് നൽകുന്നു. ഇന്റർഫേസ് ഉപയോഗിച്ച്, റിപ്പോസിറ്ററികൾ ഉണ്ടാക്കാനും, ഫയലുകൾ (വലുതായവ പോലും!) ചേർക്കാനും, മോഡലുകൾ പരിശോധിക്കാനും, ഡിഫുകൾ (diffs) കാണാനും, മറ്റ് പലതും എളുപ്പത്തിൽ ചെയ്യാം.

ഒരു പുതിയ റിപ്പോസിറ്ററി ഉണ്ടാക്കാൻ, [huggingface.co/new](https://huggingface.co/new) സന്ദർശിക്കുക:

<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/new_model.png" alt="ഒരു പുതിയ മോഡൽ റിപ്പോസിറ്ററി ഉണ്ടാക്കാൻ ഉപയോഗിക്കുന്ന പേജ്." width="80%"/>

ആദ്യം, റിപ്പോസിറ്ററിയുടെ ഉടമ ആരാണെന്ന് വ്യക്തമാക്കുക: ഇത് നിങ്ങളോ, നിങ്ങൾ ഭാഗമായ ഏതെങ്കിലും ഓർഗനൈസേഷനോ ആകാം. ഒരു ഓർഗനൈസേഷൻ തിരഞ്ഞെടുത്താൽ, മോഡൽ ആ ഓർഗനൈസേഷന്റെ പേജിൽ പ്രദർശിപ്പിക്കപ്പെടും, കൂടാതെ ഓർഗനൈസേഷനിലെ ഓരോ അംഗത്തിനും റിപ്പോസിറ്ററിയിലേക്ക് സംഭാവന ചെയ്യാൻ കഴിയും.

അടുത്തതായി, നിങ്ങളുടെ മോഡലിന്റെ പേര് നൽകുക. ഇത് തന്നെയായിരിക്കും റിപ്പോസിറ്ററിയുടെ പേരും. അവസാനമായി, നിങ്ങളുടെ മോഡൽ പബ്ലിക് ആയിരിക്കണോ പ്രൈവറ്റ് ആയിരിക്കണോ എന്ന് വ്യക്തമാക്കാം. പ്രൈവറ്റ് മോഡലുകൾ പൊതുജനങ്ങൾക്ക് കാണാൻ കഴിയില്ല.

നിങ്ങളുടെ മോഡൽ റിപ്പോസിറ്ററി ഉണ്ടാക്കിയ ശേഷം, ഇതുപോലൊരു പേജ് നിങ്ങൾക്ക് കാണാൻ കഴിയണം:

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/empty_model.png" alt="ഒരു പുതിയ റിപ്പോസിറ്ററി ഉണ്ടാക്കിയ ശേഷമുള്ള ഒഴിഞ്ഞ മോഡൽ പേജ്." width="80%"/>
</div>

ഇവിടെയാണ് നിങ്ങളുടെ മോഡൽ ഹോസ്‌റ്റ് ചെയ്യപ്പെടുന്നത്. ഇതിൽ ഉള്ളടക്കം ചേർക്കാൻ തുടങ്ങാൻ, വെബ് ഇന്റർഫേസിൽ നിന്ന് നേരിട്ട് ഒരു README ഫയൽ ചേർക്കാം.

README ഫയൽ Markdown-ലാണ് — അതിൽ നിങ്ങൾക്ക് ഇഷ്ടമുള്ളതുപോലെ പരീക്ഷിക്കാം! ഈ അധ്യായത്തിന്റെ മൂന്നാം ഭാഗം ഒരു മോഡൽ കാർഡ് നിർമ്മിക്കുന്നതിനായി മാറ്റിവെച്ചിരിക്കുന്നു. നിങ്ങളുടെ മോഡലിന് മൂല്യം നൽകുന്നതിൽ ഇവയ്ക്ക് വളരെ പ്രധാന പങ്കുണ്ട്, കാരണം മോഡലിന് എന്തൊക്കെ ചെയ്യാൻ കഴിയുമെന്ന് മറ്റുള്ളവരോട് പറയുന്നത് ഇവിടെയാണ്.

"Files and versions" ടാബ് നോക്കിയാൽ, അവിടെ ഇതുവരെ അധികം ഫയലുകൾ ഇല്ലെന്ന് കാണാം — നിങ്ങൾ ഇപ്പോൾ ഉണ്ടാക്കിയ *README.md*-ഉം, വലിയ ഫയലുകളുടെ ട്രാക്ക് സൂക്ഷിക്കുന്ന *.gitattributes* ഫയലും മാത്രം.

അടുത്തതായി, കുറച്ച് പുതിയ ഫയലുകൾ എങ്ങനെ ചേർക്കാം എന്ന് നോക്കാം.

## മോഡൽ ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യുന്നു[[uploading-the-model-files]]

Hugging Face Hub-ൽ ഫയലുകൾ കൈകാര്യം ചെയ്യുന്ന സിസ്‌റ്റം, സാധാരണ ഫയലുകൾക്ക് git-ഉം, വലിയ ഫയലുകൾക്ക് git-lfs-ഉം ([Git Large File Storage](https://git-lfs.github.com/) എന്നതിന്റെ ചുരുക്കം) അടിസ്ഥാനമാക്കിയുള്ളതാണ്. 

അടുത്ത വിഭാഗത്തിൽ, Hub-ലേക്ക് ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യാനുള്ള മൂന്ന് വ്യത്യസ്ത വഴികൾ നമ്മൾ പരിശോധിക്കും: `huggingface_hub` വഴിയും git കമാൻഡുകൾ വഴിയും.

### `upload_file` രീതി[[the-uploadfile-approach]]

`upload_file` ഉപയോഗിക്കാൻ നിങ്ങളുടെ സിസ്‌റ്റത്തിൽ git-ഉം git-lfs-ഉം ഇൻസ്‌റ്റാൾ ചെയ്തിരിക്കണമെന്നില്ല. HTTP POST റിക്വസ്‌റ്റുകൾ ഉപയോഗിച്ച് ഇത് ഫയലുകൾ നേരിട്ട് 🤗 Hub-ലേക്ക് പുഷ് ചെയ്യുന്നു. 5GB-യിൽ കൂടുതൽ വലുപ്പമുള്ള ഫയലുകൾ ഇത് കൈകാര്യം ചെയ്യില്ല എന്നതാണ് ഈ രീതിയുടെ ഒരു പരിമിതി.
നിങ്ങളുടെ ഫയലുകൾ 5GB-യിൽ കൂടുതലാണെങ്കിൽ, താഴെ വിശദീകരിക്കുന്ന മറ്റ് രണ്ട് രീതികൾ പിന്തുടരുക.

API ഇങ്ങനെ ഉപയോഗിക്കാം:

```py
from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)
```

ഇത് `<path_to_file>`-ൽ ലഭ്യമായ `config.json` ഫയലിനെ `config.json` എന്ന പേരിൽ `dummy-model` റിപ്പോസിറ്ററിയുടെ റൂട്ടിലേക്ക് അപ്‌ലോഡ് ചെയ്യും.
ഉപകാരപ്രദമാകാവുന്ന മറ്റ് ആർഗ്യുമെന്റുകൾ:

- `token`, നിങ്ങളുടെ കാഷിൽ സംഭരിച്ചിരിക്കുന്ന ടോക്കണിന് പകരം ഒരു നിശ്ചിത ടോക്കൺ ഉപയോഗിക്കാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ.
- `repo_type`, ഒരു മോഡലിന് പകരം ഒരു `dataset`-ലേക്കോ `space`-ലേക്കോ അപ്‌ലോഡ് ചെയ്യാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ. സ്വീകരിക്കുന്ന മൂല്യങ്ങൾ `"dataset"`, `"space"` എന്നിവയാണ്.


### `Repository` ക്ലാസ്[[the-repository-class]]

`Repository` ക്ലാസ് ഒരു ലോക്കൽ റിപ്പോസിറ്ററിയെ git-ന് സമാനമായ രീതിയിൽ കൈകാര്യം ചെയ്യുന്നു. git ഉപയോഗിക്കുമ്പോൾ ഉണ്ടാകാവുന്ന മിക്ക ബുദ്ധിമുട്ടുകളും മറച്ചുവെച്ച് (abstract), നമുക്ക് ആവശ്യമായ എല്ലാ ഫീച്ചറുകളും ഇത് നൽകുന്നു. 

ഈ ക്ലാസ് ഉപയോഗിക്കാൻ git-ഉം git-lfs-ഉം ഇൻസ്‌റ്റാൾ ചെയ്തിരിക്കണം; അതിനാൽ തുടങ്ങുന്നതിന് മുമ്പ് git-lfs ഇൻസ്‌റ്റാൾ ചെയ്ത് (ഇൻസ്‌റ്റാളേഷൻ നിർദ്ദേശങ്ങൾക്ക് [ഇവിടെ](https://git-lfs.github.com/) കാണുക) സെറ്റപ്പ് ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക. 

നമ്മൾ ഇപ്പോൾ ഉണ്ടാക്കിയ റിപ്പോസിറ്ററിയുമായി പ്രവർത്തിക്കാൻ തുടങ്ങാൻ, റിമോട്ട് റിപ്പോസിറ്ററി ക്ലോൺ ചെയ്ത് അതിനെ ഒരു ലോക്കൽ ഫോൾഡറിലേക്ക് ഇനിഷ്യലൈസ് ചെയ്യുന്നതിലൂടെ തുടങ്ങാം:

```py
from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")
```

ഇത് നമ്മുടെ വർക്കിംഗ് ഡയറക്ടറിയിൽ `<path_to_dummy_folder>` എന്ന ഫോൾഡർ ഉണ്ടാക്കി. `create_repo` വഴി റിപ്പോസിറ്ററി ഉണ്ടാക്കുമ്പോൾ സൃഷ്ടിക്കപ്പെടുന്ന ഒരേയൊരു ഫയൽ `.gitattributes` ആയതിനാൽ, ഈ ഫോൾഡറിൽ ആ ഫയൽ മാത്രമേ ഉണ്ടാകൂ.

ഇവിടെ നിന്ന്, പരമ്പരാഗത git മെത്തേഡുകളിൽ പലതും നമുക്ക് പ്രയോജനപ്പെടുത്താം:

```py
repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()
```

ഇനിയും പലതും! ലഭ്യമായ എല്ലാ മെത്തേഡുകളുടെയും ഒരു അവലോകനത്തിനായി [ഇവിടെ](https://github.com/huggingface/huggingface_hub/tree/main/src/huggingface_hub#advanced-programmatic-repository-management) ലഭ്യമായ `Repository` ഡോക്യുമെന്റേഷൻ ഒന്ന് നോക്കാൻ ഞങ്ങൾ ശുപാർശ ചെയ്യുന്നു.

ഇപ്പോൾ, Hub-ലേക്ക് പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന ഒരു മോഡലും ഒരു ടോക്കണൈസറും നമ്മുടെ പക്കലുണ്ട്. റിപ്പോസിറ്ററി നമ്മൾ വിജയകരമായി ക്ലോൺ ചെയ്തിട്ടുണ്ട്, അതിനാൽ ആ റിപ്പോസിറ്ററിക്കുള്ളിൽ നമുക്ക് ഫയലുകൾ സേവ് ചെയ്യാം.

ഏറ്റവും പുതിയ മാറ്റങ്ങൾ പുൾ ചെയ്ത് നമ്മുടെ ലോക്കൽ ക്ലോൺ കാലികമാണെന്ന് ആദ്യം ഉറപ്പാക്കാം:

```py
repo.git_pull()
```

അത് കഴിഞ്ഞാൽ, മോഡൽ, ടോക്കണൈസർ ഫയലുകൾ സേവ് ചെയ്യാം:

```py
model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

`<path_to_dummy_folder>`-ൽ ഇപ്പോൾ എല്ലാ മോഡൽ, ടോക്കണൈസർ ഫയലുകളും ഉണ്ട്. ഫയലുകൾ സ്‌റ്റേജിംഗ് ഏരിയയിലേക്ക് ചേർത്ത്, കമ്മിറ്റ് ചെയ്ത്, Hub-ലേക്ക് പുഷ് ചെയ്യുന്ന സാധാരണ git വർക്ക്‌ഫ്ലോ നമ്മൾ പിന്തുടരുന്നു:

```py
repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()
```

അഭിനന്ദനങ്ങൾ! നിങ്ങൾ ആദ്യമായി Hub-ലേക്ക് ഫയലുകൾ പുഷ് ചെയ്തിരിക്കുന്നു.

### git അടിസ്ഥാനമാക്കിയ രീതി[[the-git-based-approach]]

ഫയലുകൾ അപ്‌ലോഡ് ചെയ്യാനുള്ള ഏറ്റവും അടിസ്ഥാനപരമായ രീതിയാണിത്: git-ഉം git-lfs-ഉം നേരിട്ട് ഉപയോഗിച്ചാണ് നമ്മൾ ഇത് ചെയ്യുന്നത്. മുമ്പത്തെ രീതികൾ ബുദ്ധിമുട്ടുകളിൽ ഭൂരിഭാഗവും മറച്ചുവെക്കുന്നു, എന്നാൽ താഴെയുള്ള രീതിയിൽ ചില മുന്നറിയിപ്പുകൾ (caveats) ഉള്ളതിനാൽ കുറച്ചുകൂടി സങ്കീർണ്ണമായ ഒരു ഉപയോഗസന്ദർഭം നമ്മൾ പിന്തുടരും.

ഈ ക്ലാസ് ഉപയോഗിക്കാൻ git-ഉം git-lfs-ഉം ഇൻസ്‌റ്റാൾ ചെയ്തിരിക്കണം; അതിനാൽ തുടങ്ങുന്നതിന് മുമ്പ് [git-lfs](https://git-lfs.github.com/) ഇൻസ്‌റ്റാൾ ചെയ്ത് (ഇൻസ്‌റ്റാളേഷൻ നിർദ്ദേശങ്ങൾക്ക് ഇവിടെ കാണുക) സെറ്റപ്പ് ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക. 

ആദ്യം git-lfs ഇനിഷ്യലൈസ് ചെയ്ത് തുടങ്ങാം:

```bash
git lfs install
```

```bash
Updated git hooks.
Git LFS initialized.
```

അത് കഴിഞ്ഞാൽ, ആദ്യ ഘട്ടം നിങ്ങളുടെ മോഡൽ റിപ്പോസിറ്ററി ക്ലോൺ ചെയ്യുകയാണ്:

```bash
git clone https://huggingface.co/<namespace>/<your-model-id>
```

Hugging Face Hub-ന്റെ `create_repo` മെത്തേഡ് ഉപയോഗിച്ചാണ് നിങ്ങൾ റിപ്പോസിറ്ററി ഉണ്ടാക്കിയതെങ്കിൽ, ഈ ഫോൾഡറിൽ മറഞ്ഞിരിക്കുന്ന (hidden) ഒരു `.gitattributes` ഫയൽ മാത്രമേ ഉണ്ടാകൂ. മുൻ വിഭാഗത്തിലെ നിർദ്ദേശങ്ങൾ പിന്തുടർന്ന് വെബ് ഇന്റർഫേസ് ഉപയോഗിച്ചാണ് റിപ്പോസിറ്ററി ഉണ്ടാക്കിയതെങ്കിൽ, ഇവിടെ കാണിച്ചിരിക്കുന്നതുപോലെ, മറഞ്ഞിരിക്കുന്ന `.gitattributes` ഫയലിനൊപ്പം ഒരു *README.md* ഫയലും ഫോൾഡറിൽ ഉണ്ടാകും.

ഒരു കോൺഫിഗറേഷൻ ഫയൽ, ഒരു വൊക്കാബുലറി ഫയൽ, അല്ലെങ്കിൽ ഏതാനും മെഗാബൈറ്റിൽ താഴെയുള്ള ഏത് ഫയലും പോലുള്ള സാധാരണ വലുപ്പമുള്ള ഒരു ഫയൽ ചേർക്കുന്നത്, git അടിസ്ഥാനമാക്കിയ ഏത് സിസ്‌റ്റത്തിലും ചെയ്യുന്നതുപോലെ തന്നെയാണ്. എന്നാൽ, വലിയ ഫയലുകൾ *huggingface.co*-യിലേക്ക് പുഷ് ചെയ്യാൻ അവ git-lfs വഴി രജിസ്‌റ്റർ ചെയ്യണം.
