ചില സമയങ്ങളിൽ ഒരു NLP ആപ്ലിക്കേഷൻ നിർമ്മിക്കാൻ നിങ്ങൾക്ക് ആവശ്യമായ ഡേറ്റാസെറ്റ് നിലവിലുണ്ടാകില്ല; അപ്പോൾ അത് നിങ്ങൾ സ്വയം ഉണ്ടാക്കേണ്ടിവരും. GitHub റെപ്പോസിറ്ററികളിലെ ബഗ്ഗുകളോ ഫീച്ചറുകളോ ട്രാക്ക് ചെയ്യാൻ സാധാരണയായി ഉപയോഗിക്കുന്ന [GitHub ഇഷ്യൂകളുടെ](https://github.com/features/issues/) ഒരു കോർപ്പസ് (corpus) എങ്ങനെ ഉണ്ടാക്കാമെന്ന് ഈ ഭാഗത്തിൽ ഞങ്ങൾ നിങ്ങൾക്ക് കാണിച്ചുതരും. ഈ കോർപ്പസ് താഴെപ്പറയുന്നവ ഉൾപ്പെടെ വിവിധ ആവശ്യങ്ങൾക്ക് ഉപയോഗിക്കാം:

* തുറന്നിരിക്കുന്ന ഇഷ്യൂകളോ പുൾ റിക്വസ്റ്റുകളോ ക്ലോസ് ചെയ്യാൻ എത്ര സമയമെടുക്കുന്നു എന്ന് പരിശോധിക്കുക
* ഇഷ്യൂവിന്റെ വിവരണത്തെ അടിസ്ഥാനമാക്കി ഇഷ്യൂകൾക്ക് മെറ്റാഡേറ്റ ടാഗുകൾ (ഉദാ., "bug", "enhancement", അല്ലെങ്കിൽ "question") നൽകാൻ കഴിയുന്ന ഒരു _മൾട്ടിലേബൽ ക്ലാസിഫയർ_ (multilabel classifier) ട്രെയിൻ ചെയ്യുക
* ഒരു ഉപയോക്താവിന്റെ ക്വറിയുമായി (query) ഏതെല്ലാം ഇഷ്യൂകൾ പൊരുത്തപ്പെടുന്നു എന്ന് കണ്ടെത്താൻ ഒരു സെമാന്റിക് സെർച്ച് എഞ്ചിൻ നിർമ്മിക്കുക

ഇവിടെ നമ്മൾ കോർപ്പസ് ഉണ്ടാക്കുന്നതിൽ ശ്രദ്ധ കേന്ദ്രീകരിക്കും; അടുത്ത ഭാഗത്തിൽ സെമാന്റിക് സെർച്ച് ആപ്ലിക്കേഷൻ നമ്മൾ കൈകാര്യം ചെയ്യും. കാര്യങ്ങൾ ഒന്ന് "മെറ്റാ" (meta) ആക്കാൻ, ജനപ്രിയമായ ഒരു ഓപ്പൺ സോഴ്‌സ് പ്രോജക്റ്റുമായി ബന്ധപ്പെട്ട GitHub ഇഷ്യൂകൾ നമ്മൾ ഉപയോഗിക്കും: 🤗 Datasets! ഡേറ്റ എങ്ങനെ നേടാമെന്നും ഈ ഇഷ്യൂകളിൽ അടങ്ങിയിരിക്കുന്ന വിവരങ്ങൾ എങ്ങനെ പരിശോധിക്കാമെന്നും നോക്കാം.

## ഡേറ്റ ശേഖരിക്കുന്നു[[getting-the-data]]

റെപ്പോസിറ്ററിയുടെ [Issues ടാബിലേക്ക്](https://github.com/huggingface/datasets/issues) പോയാൽ 🤗 Datasets-ലെ എല്ലാ ഇഷ്യൂകളും നിങ്ങൾക്ക് കാണാം. താഴെയുള്ള സ്‌ക്രീൻഷോട്ടിൽ കാണിച്ചിരിക്കുന്നതുപോലെ, ഇത് എഴുതുന്ന സമയത്ത് 331 തുറന്ന ഇഷ്യൂകളും 668 ക്ലോസ് ചെയ്തവയും ഉണ്ടായിരുന്നു.

ഈ ഇഷ്യൂകളിലൊന്നിൽ ക്ലിക്ക് ചെയ്താൽ, അതിൽ ഒരു തലക്കെട്ടും (title), ഒരു വിവരണവും (description), ഇഷ്യൂവിന്റെ സ്വഭാവം വ്യക്തമാക്കുന്ന ഒരു കൂട്ടം ലേബലുകളും അടങ്ങിയിരിക്കുന്നതായി നിങ്ങൾ കാണും. താഴെയുള്ള സ്‌ക്രീൻഷോട്ടിൽ ഒരു ഉദാഹരണം കാണിച്ചിരിക്കുന്നു.

</div>

റെപ്പോസിറ്ററിയിലെ എല്ലാ ഇഷ്യൂകളും ഡൗൺലോഡ് ചെയ്യാൻ, നമ്മൾ [GitHub REST API](https://docs.github.com/en/rest) ഉപയോഗിച്ച് [`Issues` എൻഡ്‌പോയിന്റിനെ](https://docs.github.com/en/rest/reference/issues#list-repository-issues) പോൾ ചെയ്യും (poll). ഈ എൻഡ്‌പോയിന്റ് JSON ഒബ്‌ജക്റ്റുകളുടെ ഒരു ലിസ്‌റ്റ് റിട്ടേൺ ചെയ്യുന്നു; ഓരോ ഒബ്‌ജക്റ്റിലും തലക്കെട്ടും വിവരണവും ഉൾപ്പെടെ, ഇഷ്യൂവിന്റെ സ്ഥിതിയെക്കുറിച്ചുള്ള മെറ്റാഡേറ്റ തുടങ്ങിയ ധാരാളം ഫീൽഡുകൾ അടങ്ങിയിരിക്കുന്നു.

ഇഷ്യൂകൾ ഡൗൺലോഡ് ചെയ്യാനുള്ള സൗകര്യപ്രദമായ ഒരു മാർഗം `requests` ലൈബ്രറി ഉപയോഗിക്കുകയാണ്; Python-ൽ HTTP റിക്വസ്റ്റുകൾ അയയ്ക്കാനുള്ള സ്‌റ്റാൻഡേർഡ് രീതിയാണിത്. താഴെയുള്ള കമാൻഡ് റൺ ചെയ്ത് നിങ്ങൾക്ക് ഈ ലൈബ്രറി ഇൻസ്‌റ്റാൾ ചെയ്യാം:

```python
!pip install requests
```

ലൈബ്രറി ഇൻസ്‌റ്റാൾ ചെയ്തുകഴിഞ്ഞാൽ, `requests.get()` ഫംഗ്‌ഷൻ വിളിച്ച് `Issues` എൻഡ്‌പോയിന്റിലേക്ക് നിങ്ങൾക്ക് GET റിക്വസ്റ്റുകൾ അയയ്ക്കാം. ഉദാഹരണത്തിന്, ആദ്യ പേജിലെ ആദ്യത്തെ ഇഷ്യൂ എടുക്കാൻ താഴെയുള്ള കമാൻഡ് നിങ്ങൾക്ക് റൺ ചെയ്യാം:

```py
import requests

url = "https://api.github.com/repos/huggingface/datasets/issues?page=1&per_page=1"
response = requests.get(url)
```

`response` ഒബ്‌ജക്റ്റിൽ HTTP സ്‌റ്റാറ്റസ് കോഡ് ഉൾപ്പെടെ, റിക്വസ്റ്റിനെക്കുറിച്ചുള്ള ധാരാളം ഉപകാരപ്രദമായ വിവരങ്ങൾ അടങ്ങിയിരിക്കുന്നു:

```py
response.status_code
```

```python out
200
```

ഇവിടെ `200` എന്ന സ്‌റ്റാറ്റസ്, റിക്വസ്റ്റ് വിജയകരമായിരുന്നു എന്നാണ് അർത്ഥമാക്കുന്നത് (സാധ്യമായ HTTP സ്‌റ്റാറ്റസ് കോഡുകളുടെ ഒരു ലിസ്‌റ്റ് [ഇവിടെ](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) കാണാം). എന്നാൽ, നമുക്ക് ശരിക്കും താൽപ്പര്യമുള്ളത് _പേലോഡിലാണ്_ (payload); ബൈറ്റുകൾ, സ്‌ട്രിംഗുകൾ, JSON എന്നിങ്ങനെ വിവിധ ഫോർമാറ്റുകളിൽ ഇത് ആക്‌സസ് ചെയ്യാം. നമ്മുടെ ഇഷ്യൂകൾ JSON ഫോർമാറ്റിലാണെന്ന് നമുക്ക് അറിയാവുന്നതിനാൽ, പേലോഡ് താഴെ കാണിച്ചിരിക്കുന്നതുപോലെ പരിശോധിക്കാം:

```py
response.json()
```

ഹോ, അതൊരുപാട് വിവരങ്ങളാണ്! ഇഷ്യൂവിനെ വിവരിക്കുന്ന `title`, `body`, `number` എന്നിവ പോലുള്ള ഉപകാരപ്രദമായ ഫീൽഡുകളും, ഇഷ്യൂ തുറന്ന GitHub ഉപയോക്താവിനെക്കുറിച്ചുള്ള വിവരങ്ങളും നമുക്ക് കാണാം.

> [!TIP]
> ✏️ **സ്വയം പരീക്ഷിക്കുക!** ഓരോ GitHub ഇഷ്യൂവും ഏതുതരം വിവരങ്ങളുമായി ബന്ധപ്പെട്ടിരിക്കുന്നു എന്ന് ഒരു ധാരണ കിട്ടാൻ, മുകളിലെ JSON പേലോഡിലെ ഏതാനും URL-കളിൽ ക്ലിക്ക് ചെയ്യുക.

GitHub [ഡോക്യുമെന്റേഷനിൽ](https://docs.github.com/en/rest/overview/resources-in-the-rest-api#rate-limiting) വിവരിച്ചിരിക്കുന്നതുപോലെ, ഓതന്റിക്കേറ്റ് ചെയ്യാത്ത റിക്വസ്റ്റുകൾ മണിക്കൂറിൽ 60 എണ്ണമായി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. നിങ്ങൾ അയയ്ക്കുന്ന റിക്വസ്റ്റുകളുടെ എണ്ണം കുറയ്ക്കാൻ `per_page` ക്വറി പാരാമീറ്റർ കൂട്ടാമെങ്കിലും, ഏതാനും ആയിരത്തിലധികം ഇഷ്യൂകളുള്ള ഏതൊരു റെപ്പോസിറ്ററിയിലും നിങ്ങൾ ഈ റേറ്റ് ലിമിറ്റിൽ (rate limit) തട്ടും. അതിനാൽ പകരം, റേറ്റ് ലിമിറ്റ് മണിക്കൂറിൽ 5,000 റിക്വസ്റ്റുകളായി ഉയർത്താൻ കഴിയുന്ന വിധത്തിൽ, ഒരു _പേഴ്‌സണൽ ആക്‌സസ് ടോക്കൺ_ (personal access token) ഉണ്ടാക്കുന്നതിനുള്ള GitHub-ന്റെ [നിർദ്ദേശങ്ങൾ](https://docs.github.com/en/github/authenticating-to-github/creating-a-personal-access-token) നിങ്ങൾ പിന്തുടരണം. ടോക്കൺ കിട്ടിക്കഴിഞ്ഞാൽ, റിക്വസ്റ്റ് ഹെഡറിന്റെ ഭാഗമായി അത് നിങ്ങൾക്ക് ഉൾപ്പെടുത്താം:

```py
GITHUB_TOKEN = xxx  # Copy your GitHub token here
headers = {"Authorization": f"token {GITHUB_TOKEN}"}
```

ഇപ്പോൾ നമുക്ക് ആക്‌സസ് ടോക്കൺ ഉള്ളതിനാൽ, ഒരു GitHub റെപ്പോസിറ്ററിയിൽ നിന്ന് എല്ലാ ഇഷ്യൂകളും ഡൗൺലോഡ് ചെയ്യാൻ കഴിയുന്ന ഒരു ഫംഗ്‌ഷൻ ഉണ്ടാക്കാം:

```py
import time
import math
from pathlib import Path
import pandas as pd
from tqdm.notebook import tqdm


def fetch_issues(
    owner="huggingface",
    repo="datasets",
    num_issues=10_000,
    rate_limit=5_000,
    issues_path=Path("."),
):
    if not issues_path.is_dir():
        issues_path.mkdir(exist_ok=True)

    batch = []
    all_issues = []
    per_page = 100  # Number of issues to return per page
    num_pages = math.ceil(num_issues / per_page)
    base_url = "https://api.github.com/repos"

    for page in tqdm(range(num_pages)):
        # Query with state=all to get both open and closed issues
        query = f"issues?page={page}&per_page={per_page}&state=all"
        issues = requests.get(f"{base_url}/{owner}/{repo}/{query}", headers=headers)
        batch.extend(issues.json())

        if len(batch) > rate_limit and len(all_issues) < num_issues:
            all_issues.extend(batch)
            batch = []  # Flush batch for next time period
            print(f"Reached GitHub rate limit. Sleeping for one hour ...")
            time.sleep(60 * 60 + 1)

    all_issues.extend(batch)
    df = pd.DataFrame.from_records(all_issues)
    df.to_json(f"{issues_path}/{repo}-issues.jsonl", orient="records", lines=True)
    print(
        f"Downloaded all the issues for {repo}! Dataset stored at {issues_path}/{repo}-issues.jsonl"
    )
```

ഇപ്പോൾ നമ്മൾ `fetch_issues()` വിളിക്കുമ്പോൾ, മണിക്കൂറിലെ റിക്വസ്റ്റുകളുടെ എണ്ണത്തിൽ GitHub വെച്ചിരിക്കുന്ന പരിധി കവിയാതിരിക്കാൻ അത് എല്ലാ ഇഷ്യൂകളും ബാച്ചുകളായി ഡൗൺലോഡ് ചെയ്യും; ഫലം ഒരു _repository_name-issues.jsonl_ ഫയലിൽ സൂക്ഷിക്കപ്പെടും, അതിലെ ഓരോ വരിയും ഒരു ഇഷ്യൂവിനെ പ്രതിനിധീകരിക്കുന്ന ഒരു JSON ഒബ്‌ജക്റ്റാണ്. 🤗 Datasets-ലെ എല്ലാ ഇഷ്യൂകളും എടുക്കാൻ ഈ ഫംഗ്‌ഷൻ ഉപയോഗിക്കാം:

## ഡേറ്റ വൃത്തിയാക്കുന്നു[[cleaning-up-the-data]]

ഇഷ്യൂകളും പുൾ റിക്വസ്റ്റുകളും തമ്മിൽ വേർതിരിക്കാൻ `pull_request` കോളം ഉപയോഗിക്കാമെന്ന് GitHub ഡോക്യുമെന്റേഷനിൽ നിന്നുള്ള മുകളിലെ ഭാഗം നമ്മോട് പറയുന്നു. എന്താണ് വ്യത്യാസമെന്ന് കാണാൻ ഒരു റാൻഡം സാമ്പിൾ നോക്കാം. [ഭാഗം 3](/course/chapter5/3)-ൽ ചെയ്തതുപോലെ, ഒരു റാൻഡം സാമ്പിൾ ഉണ്ടാക്കാൻ `Dataset.shuffle()`-ഉം `Dataset.select()`-ഉം ചെയിൻ ചെയ്യുകയും, തുടർന്ന് വിവിധ URL-കൾ താരതമ്യം ചെയ്യാൻ കഴിയുന്ന വിധത്തിൽ `html_url`, `pull_request` കോളങ്ങൾ zip ചെയ്യുകയും ചെയ്യും:

## ഡേറ്റാസെറ്റ് Hugging Face Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യുന്നു[[uploading-the-dataset-to-the-hugging-face-hub]]

<Youtube id="HaN6qCr_Afc"/>

ഇപ്പോൾ നമ്മുടെ വിപുലീകരിച്ച ഡേറ്റാസെറ്റ് തയ്യാറായതിനാൽ, കമ്മ്യൂണിറ്റിയുമായി പങ്കിടാൻ അത് Hub-ലേക്ക് പുഷ് ചെയ്യാനുള്ള സമയമായി! ഒരു ഡേറ്റാസെറ്റ് അപ്‌ലോഡ് ചെയ്യുന്നത് വളരെ ലളിതമാണ്: 🤗 Transformers-ലെ മോഡലുകളും ടോക്കണൈസറുകളും പോലെ തന്നെ, ഒരു ഡേറ്റാസെറ്റ് പുഷ് ചെയ്യാൻ `push_to_hub()` മെത്തേഡ് നമുക്ക് ഉപയോഗിക്കാം. അതിനായി നമുക്ക് ഒരു ഓതന്റിക്കേഷൻ ടോക്കൺ ആവശ്യമാണ്; `notebook_login()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് ആദ്യം Hugging Face Hub-ൽ ലോഗിൻ ചെയ്താൽ അത് ലഭിക്കും:

```py
from huggingface_hub import notebook_login

```

നിങ്ങളുടെ യൂസർനെയിമും പാസ്‌വേഡും നൽകാൻ കഴിയുന്ന ഒരു വിഡ്‌ജറ്റ് ഇത് ഉണ്ടാക്കും, ഒരു API ടോക്കൺ *~/.huggingface/token*-ൽ സേവ് ചെയ്യപ്പെടും. നിങ്ങൾ കോഡ് ഒരു ടെർമിനലിലാണ് റൺ ചെയ്യുന്നതെങ്കിൽ, പകരം CLI വഴി ലോഗിൻ ചെയ്യാം:


## ഒരു ഡേറ്റാസെറ്റ് കാർഡ് ഉണ്ടാക്കുന്നു[[creating-a-dataset-card]]

നന്നായി ഡോക്യുമെന്റ് ചെയ്ത ഡേറ്റാസെറ്റുകൾ മറ്റുള്ളവർക്ക് (ഭാവിയിലെ നിങ്ങൾക്കും ഉൾപ്പെടെ!) ഉപകാരപ്രദമാകാൻ കൂടുതൽ സാധ്യതയുണ്ട്; കാരണം, ഡേറ്റാസെറ്റ് തങ്ങളുടെ ടാസ്‌ക്കിന് പ്രസക്തമാണോ എന്ന് തീരുമാനിക്കാനും, ഡേറ്റാസെറ്റിലെ സാധ്യമായ പക്ഷപാതങ്ങളോ (biases) അത് ഉപയോഗിക്കുന്നതുമായി ബന്ധപ്പെട്ട അപകടസാധ്യതകളോ വിലയിരുത്താനും ഉപയോക്താക്കളെ പ്രാപ്തരാക്കുന്ന സന്ദർഭം (context) അവ നൽകുന്നു.

Hugging Face Hub-ൽ, ഈ വിവരങ്ങൾ ഓരോ ഡേറ്റാസെറ്റ് റെപ്പോസിറ്ററിയുടെയും *README.md* ഫയലിലാണ് സൂക്ഷിക്കുന്നത്. ഈ ഫയൽ ഉണ്ടാക്കുന്നതിന് മുമ്പ് നിങ്ങൾ ചെയ്യേണ്ട രണ്ട് പ്രധാന ഘട്ടങ്ങളുണ്ട്:

1. YAML ഫോർമാറ്റിൽ മെറ്റാഡേറ്റ ടാഗുകൾ ഉണ്ടാക്കാൻ [`datasets-tagging` ആപ്ലിക്കേഷൻ](https://huggingface.co/datasets/tagging/) ഉപയോഗിക്കുക. Hugging Face Hub-ലെ വിവിധ സെർച്ച് ഫീച്ചറുകൾക്കായി ഈ ടാഗുകൾ ഉപയോഗിക്കുന്നു; കമ്മ്യൂണിറ്റിയിലെ അംഗങ്ങൾക്ക് നിങ്ങളുടെ ഡേറ്റാസെറ്റ് എളുപ്പത്തിൽ കണ്ടെത്താൻ കഴിയുമെന്ന് അവ ഉറപ്പാക്കുന്നു. ഇവിടെ നമ്മൾ ഒരു കസ്‌റ്റം ഡേറ്റാസെറ്റ് ഉണ്ടാക്കിയതിനാൽ, `datasets-tagging` റെപ്പോസിറ്ററി ക്ലോൺ ചെയ്ത് ആപ്ലിക്കേഷൻ ലോക്കലായി റൺ ചെയ്യേണ്ടിവരും. ഇന്റർഫേസ് കാണുന്നത് ഇങ്ങനെയാണ്:

2. വിവരസമ്പന്നമായ ഡേറ്റാസെറ്റ് കാർഡുകൾ ഉണ്ടാക്കുന്നതിനെക്കുറിച്ചുള്ള [🤗 Datasets ഗൈഡ്](https://github.com/huggingface/datasets/blob/master/templates/README_guide.md) വായിക്കുകയും അത് ഒരു ടെംപ്ലേറ്റായി ഉപയോഗിക്കുകയും ചെയ്യുക.
