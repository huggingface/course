ഇക്കാലത്ത് പല ഗിഗാബൈറ്റ് വലുപ്പമുള്ള ഡേറ്റാസെറ്റുകളുമായി പ്രവർത്തിക്കേണ്ടി വരുന്നത് അസാധാരണമല്ല; പ്രത്യേകിച്ചും BERT അല്ലെങ്കിൽ GPT-2 പോലുള്ള ഒരു ട്രാൻസ്‌ഫോർമർ ആദ്യം മുതൽ (from scratch) പ്രീട്രെയിൻ ചെയ്യാൻ നിങ്ങൾ ഉദ്ദേശിക്കുന്നുണ്ടെങ്കിൽ. ഇത്തരം സന്ദർഭങ്ങളിൽ, ഡേറ്റ _ലോഡ് ചെയ്യുന്നത്_ പോലും ഒരു വെല്ലുവിളിയാകാം. ഉദാഹരണത്തിന്, GPT-2 പ്രീട്രെയിൻ ചെയ്യാൻ ഉപയോഗിച്ച WebText കോർപ്പസിൽ 8 ദശലക്ഷത്തിലധികം ഡോക്യുമെന്റുകളും 40 GB ടെക്‌സ്‌റ്റും അടങ്ങിയിരിക്കുന്നു -- ഇത് നിങ്ങളുടെ ലാപ്‌ടോപ്പിന്റെ RAM-ലേക്ക് ലോഡ് ചെയ്താൽ അതിന് ഒരു ഹൃദയാഘാതം വരാൻ സാധ്യതയുണ്ട്!

ഭാഗ്യവശാൽ, ഈ പരിമിതികളെ മറികടക്കാൻ വേണ്ടിയാണ് 🤗 Datasets രൂപകൽപ്പന ചെയ്തിരിക്കുന്നത്. ഡേറ്റാസെറ്റുകളെ _മെമ്മറി-മാപ്പ്ഡ്_ (memory-mapped) ഫയലുകളായി കൈകാര്യം ചെയ്തുകൊണ്ട് മെമ്മറി മാനേജ്‌മെന്റ് പ്രശ്‌നങ്ങളിൽ നിന്നും, ഒരു കോർപ്പസിലെ എൻട്രികൾ _സ്‌ട്രീം_ (streaming) ചെയ്തുകൊണ്ട് ഹാർഡ് ഡ്രൈവിന്റെ പരിധികളിൽ നിന്നും ഇത് നിങ്ങളെ മോചിപ്പിക്കുന്നു.

ഈ ഭാഗത്തിൽ, [the Pile](https://pile.eleuther.ai) എന്നറിയപ്പെടുന്ന 825 GB വലുപ്പമുള്ള ഒരു ഭീമൻ കോർപ്പസ് ഉപയോഗിച്ച് 🤗 Datasets-ന്റെ ഈ ഫീച്ചറുകൾ നമ്മൾ പരിശോധിക്കും. നമുക്ക് തുടങ്ങാം!

## എന്താണ് Pile?[[what-is-the-pile]]

വലിയ തോതിലുള്ള ലാംഗ്വേജ് മോഡലുകൾ ട്രെയിൻ ചെയ്യുന്നതിനായി [EleutherAI](https://www.eleuther.ai) സൃഷ്ടിച്ച ഒരു ഇംഗ്ലീഷ് ടെക്‌സ്‌റ്റ് കോർപ്പസാണ് Pile. ശാസ്ത്രീയ ലേഖനങ്ങൾ, GitHub കോഡ് റിപ്പോസിറ്ററികൾ, ഫിൽട്ടർ ചെയ്ത വെബ് ടെക്‌സ്‌റ്റ് എന്നിങ്ങനെ വൈവിധ്യമാർന്ന ഡേറ്റാസെറ്റുകൾ ഇതിൽ ഉൾപ്പെടുന്നു. ട്രെയിനിംഗ് കോർപ്പസ് [14 GB വീതമുള്ള ഭാഗങ്ങളായി](https://the-eye.eu/public/AI/pile/) ലഭ്യമാണ്; കൂടാതെ [വ്യക്തിഗത ഘടകങ്ങളിൽ](https://the-eye.eu/public/AI/pile_preliminary_components/) പലതും നിങ്ങൾക്ക് ഡൗൺലോഡ് ചെയ്യാനും കഴിയും. [PubMed](https://pubmed.ncbi.nlm.nih.gov/)-ലെ 15 ദശലക്ഷം ബയോമെഡിക്കൽ പ്രസിദ്ധീകരണങ്ങളുടെ സംഗ്രഹങ്ങൾ (abstracts) അടങ്ങിയ ഒരു കോർപ്പസായ PubMed Abstracts ഡേറ്റാസെറ്റ് പരിശോധിച്ചുകൊണ്ട് നമുക്ക് തുടങ്ങാം. ഈ ഡേറ്റാസെറ്റ് [JSON Lines ഫോർമാറ്റിലാണ്](https://jsonlines.org); `zstandard` ലൈബ്രറി ഉപയോഗിച്ച് കംപ്രസ് ചെയ്തിരിക്കുന്നതിനാൽ, ആദ്യം നമുക്ക് അത് ഇൻസ്‌റ്റാൾ ചെയ്യണം:

```py
!pip install zstandard
```

അടുത്തതായി, [ഭാഗം 2](/course/chapter5/2)-ൽ നമ്മൾ പഠിച്ച റിമോട്ട് ഫയലുകൾക്കുള്ള രീതി ഉപയോഗിച്ച് ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്യാം:

ശരി, ഇത് ഒരു മെഡിക്കൽ ലേഖനത്തിന്റെ സംഗ്രഹം (abstract) പോലെ തോന്നുന്നു. ഇനി, ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്യാൻ നമ്മൾ എത്ര RAM ഉപയോഗിച്ചു എന്ന് നോക്കാം!

## മെമ്മറി മാപ്പിംഗിന്റെ മാജിക്[[the-magic-of-memory-mapping]]

Python-ൽ മെമ്മറി ഉപയോഗം അളക്കാനുള്ള ഒരു ലളിതമായ മാർഗ്ഗം [`psutil`](https://psutil.readthedocs.io/en/latest/) ലൈബ്രറി ഉപയോഗിക്കുന്നതാണ്; താഴെ കാണിച്ചിരിക്കുന്നതുപോലെ `pip` ഉപയോഗിച്ച് ഇത് ഇൻസ്‌റ്റാൾ ചെയ്യാം:

```python
!pip install psutil
```

നിലവിലെ പ്രോസസ്സിന്റെ മെമ്മറി ഉപയോഗം താഴെ കാണിച്ചിരിക്കുന്നതുപോലെ പരിശോധിക്കാൻ നമ്മെ അനുവദിക്കുന്ന ഒരു `Process` ക്ലാസ് ഇത് നൽകുന്നു:

```py
import psutil

# Process.memory_info is expressed in bytes, so convert to megabytes
print(f"RAM used: {psutil.Process().memory_info().rss / (1024 * 1024):.2f} MB")
```

```python out
RAM used: 5678.33 MB
```

ഇവിടെ `rss` ആട്രിബ്യൂട്ട് _റെസിഡന്റ് സെറ്റ് സൈസ്_ (resident set size) എന്നതിനെ സൂചിപ്പിക്കുന്നു; ഒരു പ്രോസസ്സ് RAM-ൽ കൈവശം വയ്ക്കുന്ന മെമ്മറിയുടെ അംശമാണിത്. Python ഇന്റർപ്രെറ്ററും നമ്മൾ ലോഡ് ചെയ്ത ലൈബ്രറികളും ഉപയോഗിക്കുന്ന മെമ്മറിയും ഈ അളവിൽ ഉൾപ്പെടുന്നു; അതിനാൽ ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്യാൻ യഥാർത്ഥത്തിൽ ഉപയോഗിച്ച മെമ്മറിയുടെ അളവ് ഇതിലും കുറച്ച് ചെറുതാണ്. താരതമ്യത്തിനായി, `dataset_size` ആട്രിബ്യൂട്ട് ഉപയോഗിച്ച് ഡേറ്റാസെറ്റിന് ഡിസ്‌കിൽ എത്ര വലുപ്പമുണ്ടെന്ന് നോക്കാം. മുമ്പത്തേതുപോലെ ഫലം ബൈറ്റുകളിലാണ് പ്രകടിപ്പിക്കുന്നത് എന്നതിനാൽ, നമുക്ക് അത് സ്വയം ഗിഗാബൈറ്റുകളിലേക്ക് മാറ്റേണ്ടതുണ്ട്:

```py
print(f"Dataset size in bytes: {pubmed_dataset.dataset_size}")
size_gb = pubmed_dataset.dataset_size / (1024**3)
print(f"Dataset size (cache file) : {size_gb:.2f} GB")
```

```python out
Dataset size in bytes : 20979437051
Dataset size (cache file) : 19.54 GB
```

കൊള്ളാം -- ഏകദേശം 20 GB വലുപ്പമുണ്ടെങ്കിലും, അതിലും വളരെ കുറഞ്ഞ RAM ഉപയോഗിച്ച് ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്യാനും ആക്‌സസ് ചെയ്യാനും നമുക്ക് കഴിയുന്നു!

> [!TIP]
> ✏️ **സ്വയം പരീക്ഷിക്കുക!** നിങ്ങളുടെ ലാപ്‌ടോപ്പിന്റെയോ ഡെസ്‌ക്‌ടോപ്പിന്റെയോ RAM-നേക്കാൾ വലുപ്പമുള്ള, Pile-ലെ [സബ്‌സെറ്റുകളിൽ](https://the-eye.eu/public/AI/pile_preliminary_components/) ഒന്ന് തിരഞ്ഞെടുത്ത്, 🤗 Datasets ഉപയോഗിച്ച് അത് ലോഡ് ചെയ്ത്, ഉപയോഗിച്ച RAM-ന്റെ അളവ് അളക്കുക. കൃത്യമായ ഒരു അളവ് ലഭിക്കാൻ ഇത് ഒരു പുതിയ പ്രോസസ്സിൽ ചെയ്യേണ്ടതുണ്ട് എന്നത് ശ്രദ്ധിക്കുക. ഓരോ സബ്‌സെറ്റിന്റെയും ഡീകംപ്രസ് ചെയ്ത വലുപ്പങ്ങൾ [Pile പേപ്പറിലെ](https://arxiv.org/abs/2101.00027) ടേബിൾ 1-ൽ നിങ്ങൾക്ക് കാണാം.

നിങ്ങൾക്ക് Pandas പരിചയമുണ്ടെങ്കിൽ, ഈ ഫലം ഒരു അത്ഭുതമായി തോന്നാം; കാരണം, നിങ്ങളുടെ ഡേറ്റാസെറ്റിന്റെ വലുപ്പത്തിന്റെ 5 മുതൽ 10 മടങ്ങ് വരെ RAM സാധാരണയായി ആവശ്യമാണെന്ന Wes Kinney-യുടെ പ്രശസ്തമായ ഒരു [പൊതുനിയമം (rule of thumb)](https://wesmckinney.com/blog/apache-arrow-pandas-internals/) ഉണ്ട്. അപ്പോൾ 🤗 Datasets ഈ മെമ്മറി മാനേജ്‌മെന്റ് പ്രശ്‌നം എങ്ങനെ പരിഹരിക്കുന്നു? 🤗 Datasets ഓരോ ഡേറ്റാസെറ്റിനെയും ഒരു [മെമ്മറി-മാപ്പ്ഡ് ഫയലായി](https://en.wikipedia.org/wiki/Memory-mapped_file) കൈകാര്യം ചെയ്യുന്നു; RAM-നും ഫയൽസിസ്‌റ്റം സ്‌റ്റോറേജിനും ഇടയിൽ ഒരു മാപ്പിംഗ് ഇത് നൽകുന്നു, അതുവഴി ഡേറ്റാസെറ്റ് പൂർണ്ണമായി മെമ്മറിയിലേക്ക് ലോഡ് ചെയ്യാതെ തന്നെ അതിലെ എലമെന്റുകൾ ആക്‌സസ് ചെയ്യാനും അവയിൽ പ്രവർത്തിക്കാനും ലൈബ്രറിക്ക് കഴിയുന്നു.

മെമ്മറി-മാപ്പ്ഡ് ഫയലുകൾ ഒന്നിലധികം പ്രോസസ്സുകൾക്കിടയിൽ പങ്കുവയ്ക്കാനും കഴിയും; ഡേറ്റാസെറ്റ് നീക്കുകയോ പകർത്തുകയോ ചെയ്യാതെ തന്നെ `Dataset.map()` പോലുള്ള മെത്തേഡുകൾ പാരലലൈസ് ചെയ്യാൻ ഇത് സാധ്യമാക്കുന്നു. ഉള്ളിൽ, ഈ കഴിവുകളെല്ലാം സാക്ഷാത്കരിക്കുന്നത് [Apache Arrow](https://arrow.apache.org) മെമ്മറി ഫോർമാറ്റും [`pyarrow`](https://arrow.apache.org/docs/python/index.html) ലൈബ്രറിയുമാണ്; ഇവയാണ് ഡേറ്റാ ലോഡിംഗും പ്രോസസ്സിംഗും മിന്നൽ വേഗത്തിലാക്കുന്നത്. (Apache Arrow-യെക്കുറിച്ചുള്ള കൂടുതൽ വിവരങ്ങൾക്കും Pandas-മായുള്ള താരതമ്യങ്ങൾക്കും, [Dejan Simic-ന്റെ ബ്ലോഗ് പോസ്‌റ്റ്](https://towardsdatascience.com/apache-arrow-read-dataframe-with-zero-memory-69634092b1a) പരിശോധിക്കുക.) ഇത് പ്രവർത്തനത്തിൽ കാണാൻ, PubMed Abstracts ഡേറ്റാസെറ്റിലെ എല്ലാ എലമെന്റുകളിലൂടെയും ഇറ്ററേറ്റ് ചെയ്തുകൊണ്ട് ഒരു ചെറിയ വേഗതാ പരീക്ഷണം നടത്താം:

```py
import timeit

code_snippet = """batch_size = 1000

for idx in range(0, len(pubmed_dataset), batch_size):
    _ = pubmed_dataset[idx:idx + batch_size]
"""

time = timeit.timeit(stmt=code_snippet, number=1, globals=globals())
print(
    f"Iterated over {len(pubmed_dataset)} examples (about {size_gb:.1f} GB) in "
    f"{time:.1f}s, i.e. {size_gb/time:.3f} GB/s"
)
```

```python out
'Iterated over 15518009 examples (about 19.5 GB) in 64.2s, i.e. 0.304 GB/s'
```

`code_snippet` എക്‌സിക്യൂട്ട് ചെയ്യാൻ എടുത്ത സമയം അളക്കാൻ ഇവിടെ നമ്മൾ Python-ന്റെ `timeit` മൊഡ്യൂൾ ഉപയോഗിച്ചു. സാധാരണയായി, ഒരു GB/s-ന്റെ ഏതാനും പത്തിലൊന്ന് മുതൽ നിരവധി GB/s വരെ വേഗതയിൽ ഒരു ഡേറ്റാസെറ്റിലൂടെ ഇറ്ററേറ്റ് ചെയ്യാൻ നിങ്ങൾക്ക് കഴിയും. ബഹുഭൂരിപക്ഷം ആപ്ലിക്കേഷനുകൾക്കും ഇത് നന്നായി പ്രവർത്തിക്കും, എന്നാൽ ചിലപ്പോൾ നിങ്ങളുടെ ലാപ്‌ടോപ്പിന്റെ ഹാർഡ് ഡ്രൈവിൽ സൂക്ഷിക്കാൻ പോലും കഴിയാത്തത്ര വലിയ ഒരു ഡേറ്റാസെറ്റുമായി നിങ്ങൾക്ക് പ്രവർത്തിക്കേണ്ടി വരും. ഉദാഹരണത്തിന്, Pile പൂർണ്ണമായി ഡൗൺലോഡ് ചെയ്യാൻ ശ്രമിച്ചാൽ, നമുക്ക് 825 GB ഒഴിഞ്ഞ ഡിസ്‌ക് സ്ഥലം വേണ്ടിവരും! ഇത്തരം സന്ദർഭങ്ങൾ കൈകാര്യം ചെയ്യാൻ, മുഴുവൻ ഡേറ്റാസെറ്റും ഡൗൺലോഡ് ചെയ്യാതെ തന്നെ എലമെന്റുകൾ തത്സമയം (on the fly) ഡൗൺലോഡ് ചെയ്യാനും ആക്‌സസ് ചെയ്യാനും അനുവദിക്കുന്ന ഒരു സ്‌ട്രീമിംഗ് ഫീച്ചർ 🤗 Datasets നൽകുന്നു. ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്ന് നോക്കാം.

> [!TIP]
> 💡 Jupyter നോട്ട്‌ബുക്കുകളിൽ [`%%timeit` മാജിക് ഫംഗ്‌ഷൻ](https://ipython.readthedocs.io/en/stable/interactive/magics.html#magic-timeit) ഉപയോഗിച്ചും സെല്ലുകളുടെ സമയം അളക്കാം.

## ഡേറ്റാസെറ്റുകൾ സ്‌ട്രീം ചെയ്യുന്നു[[streaming-datasets]]

ഡേറ്റാസെറ്റ് സ്‌ട്രീമിംഗ് പ്രവർത്തനക്ഷമമാക്കാൻ `load_dataset()` ഫംഗ്‌ഷനിലേക്ക് `streaming=True` എന്ന ആർഗ്യുമെന്റ് നൽകിയാൽ മാത്രം മതി. ഉദാഹരണത്തിന്, PubMed Abstracts ഡേറ്റാസെറ്റ് ഒരിക്കൽക്കൂടി ലോഡ് ചെയ്യാം, പക്ഷേ ഇത്തവണ സ്‌ട്രീമിംഗ് മോഡിൽ:

```py
pubmed_dataset_streamed = load_dataset(
    "json", data_files=data_files, split="train", streaming=True
)
```

ഈ അധ്യായത്തിൽ മറ്റിടങ്ങളിൽ നമ്മൾ കണ്ടുപരിചയിച്ച `Dataset`-ന് പകരം, `streaming=True` ഉപയോഗിക്കുമ്പോൾ റിട്ടേൺ ചെയ്യുന്ന ഒബ്‌ജക്റ്റ് ഒരു `IterableDataset` ആണ്. പേര് സൂചിപ്പിക്കുന്നതുപോലെ, ഒരു `IterableDataset`-ലെ എലമെന്റുകൾ ആക്‌സസ് ചെയ്യാൻ നമുക്ക് അതിലൂടെ ഇറ്ററേറ്റ് ചെയ്യേണ്ടതുണ്ട്. നമ്മുടെ സ്‌ട്രീം ചെയ്ത ഡേറ്റാസെറ്റിലെ ആദ്യത്തെ എലമെന്റ് താഴെ കാണിച്ചിരിക്കുന്നതുപോലെ ആക്‌സസ് ചെയ്യാം:


```py
next(iter(pubmed_dataset_streamed))
```

```python out

 'text': 'Epidemiology of hypoxaemia in children with acute lower respiratory infection.\nTo determine the prevalence of hypoxaemia in children aged under 5 years suffering acute lower respiratory infections (ALRI), the risk factors for hypoxaemia in children under 5 years of age with ALRI, and the association of hypoxaemia with an increased risk of dying in children of the same age ...'}
```

സ്‌ട്രീം ചെയ്ത ഒരു ഡേറ്റാസെറ്റിലെ എലമെന്റുകൾ `IterableDataset.map()` ഉപയോഗിച്ച് തത്സമയം പ്രോസസ്സ് ചെയ്യാം; ട്രെയിനിംഗ് സമയത്ത് ഇൻപുട്ടുകൾ ടോക്കണൈസ് ചെയ്യേണ്ടതുണ്ടെങ്കിൽ ഇത് ഉപകാരപ്രദമാണ്. [അധ്യായം 3](/course/chapter3)-ൽ നമ്മുടെ ഡേറ്റാസെറ്റ് ടോക്കണൈസ് ചെയ്യാൻ നമ്മൾ ഉപയോഗിച്ച അതേ പ്രക്രിയ തന്നെയാണിത്; ഔട്ട്‌പുട്ടുകൾ ഒന്നൊന്നായി റിട്ടേൺ ചെയ്യപ്പെടുന്നു എന്നതാണ് ഒരേയൊരു വ്യത്യാസം:

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("distilbert-base-uncased")
tokenized_dataset = pubmed_dataset_streamed.map(lambda x: tokenizer(x["text"]))
next(iter(tokenized_dataset))
```

```python out

```

> [!TIP]
> 💡 സ്‌ട്രീമിംഗിനൊപ്പം ടോക്കണൈസേഷൻ വേഗത്തിലാക്കാൻ, കഴിഞ്ഞ ഭാഗത്തിൽ നമ്മൾ കണ്ടതുപോലെ `batched=True` നൽകാം. ഇത് ഉദാഹരണങ്ങളെ ബാച്ച് ബാച്ചായി പ്രോസസ്സ് ചെയ്യും; ഡിഫോൾട്ട് ബാച്ച് സൈസ് 1,000 ആണ്, ഇത് `batch_size` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് വ്യക്തമാക്കാം.

`IterableDataset.shuffle()` ഉപയോഗിച്ച് സ്‌ട്രീം ചെയ്ത ഒരു ഡേറ്റാസെറ്റ് ഷഫിൾ ചെയ്യാനും കഴിയും, എന്നാൽ `Dataset.shuffle()`-ൽ നിന്ന് വ്യത്യസ്തമായി, മുൻകൂട്ടി നിശ്ചയിച്ച ഒരു `buffer_size`-ലെ എലമെന്റുകൾ മാത്രമേ ഇത് ഷഫിൾ ചെയ്യുന്നുള്ളൂ:

```py
shuffled_dataset = pubmed_dataset_streamed.shuffle(buffer_size=10_000, seed=42)
next(iter(shuffled_dataset))
```


ഈ ഉദാഹരണത്തിൽ, ബഫറിലെ ആദ്യത്തെ 10,000 ഉദാഹരണങ്ങളിൽ നിന്ന് ക്രമരഹിതമായ (random) ഒരു ഉദാഹരണം നമ്മൾ തിരഞ്ഞെടുത്തു. ഒരു ഉദാഹരണം ആക്‌സസ് ചെയ്തുകഴിഞ്ഞാൽ, ബഫറിലെ അതിന്റെ സ്ഥാനം കോർപ്പസിലെ അടുത്ത ഉദാഹരണം കൊണ്ട് നിറയ്ക്കപ്പെടുന്നു (അതായത്, മുകളിലെ സന്ദർഭത്തിൽ 10,001-ാമത്തെ ഉദാഹരണം). `Dataset.select()`-ന് സമാനമായ രീതിയിൽ പ്രവർത്തിക്കുന്ന `IterableDataset.take()`, `IterableDataset.skip()` ഫംഗ്‌ഷനുകൾ ഉപയോഗിച്ച് സ്‌ട്രീം ചെയ്ത ഒരു ഡേറ്റാസെറ്റിൽ നിന്ന് എലമെന്റുകൾ തിരഞ്ഞെടുക്കാനും കഴിയും. ഉദാഹരണത്തിന്, PubMed Abstracts ഡേറ്റാസെറ്റിലെ ആദ്യത്തെ 5 ഉദാഹരണങ്ങൾ തിരഞ്ഞെടുക്കാൻ നമുക്ക് ഇങ്ങനെ ചെയ്യാം:

```py
dataset_head = pubmed_dataset_streamed.take(5)
list(dataset_head)
```

അതുപോലെ, ഷഫിൾ ചെയ്ത ഒരു ഡേറ്റാസെറ്റിൽ നിന്ന് ട്രെയിനിംഗ്, വാലിഡേഷൻ സ്‌പ്ലിറ്റുകൾ ഉണ്ടാക്കാൻ `IterableDataset.skip()` ഫംഗ്‌ഷൻ താഴെ കാണിച്ചിരിക്കുന്നതുപോലെ ഉപയോഗിക്കാം:

```py
# Skip the first 1,000 examples and include the rest in the training set
train_dataset = shuffled_dataset.skip(1000)
# Take the first 1,000 examples for the validation set
validation_dataset = shuffled_dataset.take(1000)
```

ഡേറ്റാസെറ്റ് സ്‌ട്രീമിംഗിനെക്കുറിച്ചുള്ള നമ്മുടെ അന്വേഷണം ഒരു സാധാരണ ഉപയോഗത്തോടെ പൂർത്തിയാക്കാം: ഒന്നിലധികം ഡേറ്റാസെറ്റുകൾ കൂട്ടിച്ചേർത്ത് ഒരൊറ്റ കോർപ്പസ് ഉണ്ടാക്കുന്നത്. `IterableDataset` ഒബ്‌ജക്റ്റുകളുടെ ഒരു ലിസ്‌റ്റിനെ ഒരൊറ്റ `IterableDataset`-ലേക്ക് മാറ്റുന്ന `interleave_datasets()` എന്ന ഫംഗ്‌ഷൻ 🤗 Datasets നൽകുന്നു; ഇവിടെ പുതിയ ഡേറ്റാസെറ്റിലെ എലമെന്റുകൾ ലഭിക്കുന്നത് ഉറവിട ഉദാഹരണങ്ങൾക്കിടയിൽ മാറിമാറി എടുത്തുകൊണ്ടാണ്. വലിയ ഡേറ്റാസെറ്റുകൾ കൂട്ടിച്ചേർക്കാൻ ശ്രമിക്കുമ്പോൾ ഈ ഫംഗ്‌ഷൻ പ്രത്യേകിച്ചും ഉപകാരപ്രദമാണ്; അതിനാൽ ഒരു ഉദാഹരണമായി, Pile-ലെ FreeLaw സബ്‌സെറ്റ് നമുക്ക് സ്‌ട്രീം ചെയ്യാം — US കോടതികളിൽ നിന്നുള്ള നിയമപരമായ വിധിന്യായങ്ങളുടെ (legal opinions) 51 GB വലുപ്പമുള്ള ഒരു ഡേറ്റാസെറ്റാണിത്:
