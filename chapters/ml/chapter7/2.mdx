നമ്മൾ ആദ്യം പരിശോധിക്കുന്ന ആപ്ലിക്കേഷൻ ടോക്കൺ ക്ലാസിഫിക്കേഷൻ (token classification) ആണ്. "ഒരു വാക്യത്തിലെ ഓരോ ടോക്കണിനും ഒരു ലേബൽ നൽകുക" എന്ന രീതിയിൽ രൂപപ്പെടുത്താവുന്ന ഏത് പ്രശ്നവും ഈ പൊതുവായ ടാസ്‌കിൽ ഉൾപ്പെടുന്നു, ഉദാഹരണത്തിന്:

- **നെയിംഡ് എന്റിറ്റി റെക്കഗ്നിഷൻ (Named entity recognition, NER)**: ഒരു വാക്യത്തിലെ എന്റിറ്റികൾ (വ്യക്തികൾ, സ്ഥലങ്ങൾ, സംഘടനകൾ എന്നിവ പോലുള്ളവ) കണ്ടെത്തുക. ഓരോ എന്റിറ്റിക്കും ഒരു ക്ലാസ്സും "എന്റിറ്റി ഇല്ല" എന്നതിന് ഒരു ക്ലാസ്സും വച്ച്, ഓരോ ടോക്കണിനും ഒരു ലേബൽ നൽകുന്ന രീതിയിൽ ഇത് രൂപപ്പെടുത്താം.
- **പാർട്ട്-ഓഫ്-സ്പീച്ച് ടാഗിംഗ് (Part-of-speech tagging, POS)**: ഒരു വാക്യത്തിലെ ഓരോ വാക്കും ഒരു പ്രത്യേക പദവിഭാഗത്തിൽ (നാമം, ക്രിയ, വിശേഷണം എന്നിങ്ങനെ) പെടുന്നതായി അടയാളപ്പെടുത്തുക.
- **ചങ്കിംഗ് (Chunking)**: ഒരേ എന്റിറ്റിയിൽ പെടുന്ന ടോക്കണുകൾ കണ്ടെത്തുക. ഈ ടാസ്‌ക് (POS-മായോ NER-മായോ ഇത് സംയോജിപ്പിക്കാം) ഇങ്ങനെ രൂപപ്പെടുത്താം: ഒരു ചങ്കിന്റെ തുടക്കത്തിലുള്ള ടോക്കണുകൾക്ക് ഒരു ലേബൽ (സാധാരണയായി `B-`), ഒരു ചങ്കിന്റെ ഉള്ളിലുള്ള ടോക്കണുകൾക്ക് മറ്റൊരു ലേബൽ (സാധാരണയായി `I-`), ഒരു ചങ്കിലും പെടാത്ത ടോക്കണുകൾക്ക് മൂന്നാമതൊരു ലേബൽ (സാധാരണയായി `O`) എന്നിങ്ങനെ നൽകുക.

## ഡേറ്റ തയ്യാറാക്കുന്നു[[preparing-the-data]]

ആദ്യം വേണ്ടത്, ടോക്കൺ ക്ലാസിഫിക്കേഷന് അനുയോജ്യമായ ഒരു ഡേറ്റാസെറ്റാണ്. ഈ ഭാഗത്തിൽ, Reuters-ൽ നിന്നുള്ള വാർത്തകൾ ഉൾക്കൊള്ളുന്ന [CoNLL-2003 ഡേറ്റാസെറ്റ്](https://huggingface.co/datasets/conll2003) നമ്മൾ ഉപയോഗിക്കും.

> [!TIP]
> 💡 നിങ്ങളുടെ ഡേറ്റാസെറ്റിൽ വാക്കുകളായി വിഭജിച്ച ടെക്‌സ്‌റ്റുകളും അവയോട് ബന്ധപ്പെട്ട ലേബലുകളും ഉള്ളിടത്തോളം, ഇവിടെ വിവരിക്കുന്ന ഡേറ്റാ പ്രോസസ്സിംഗ് രീതികൾ നിങ്ങളുടെ സ്വന്തം ഡേറ്റാസെറ്റിന് അനുയോജ്യമായി മാറ്റാൻ നിങ്ങൾക്ക് കഴിയും. നിങ്ങളുടെ സ്വന്തം കസ്‌റ്റം ഡേറ്റ ഒരു `Dataset`-ൽ എങ്ങനെ ലോഡ് ചെയ്യാമെന്ന് ഓർമ്മ പുതുക്കണമെങ്കിൽ [അധ്യായം 5](/course/chapter5) വീണ്ടും നോക്കുക.

### CoNLL-2003 ഡേറ്റാസെറ്റ്[[the-conll-2003-dataset]]

CoNLL-2003 ഡേറ്റാസെറ്റ് ലോഡ് ചെയ്യാൻ, 🤗 Datasets ലൈബ്രറിയിലെ `load_dataset()` മെത്തേഡ് നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
from datasets import load_dataset

raw_datasets = load_dataset("conll2003")
```

[അധ്യായം 3](/course/chapter3)-ൽ GLUE MRPC ഡേറ്റാസെറ്റിന്റെ കാര്യത്തിൽ കണ്ടതുപോലെ, ഇത് ഡേറ്റാസെറ്റ് ഡൗൺലോഡ് ചെയ്ത് കാഷ് ചെയ്യും. ഈ ഒബ്‌ജക്റ്റ് പരിശോധിച്ചാൽ, അതിലുള്ള കോളങ്ങളും ട്രെയിനിംഗ്, വാലിഡേഷൻ, ടെസ്‌റ്റ് സെറ്റുകൾ തമ്മിലുള്ള വിഭജനവും നമുക്ക് കാണാം:

```py
raw_datasets
```

```python out
DatasetDict({
    train: Dataset({
        features: ['chunk_tags', 'id', 'ner_tags', 'pos_tags', 'tokens'],
        num_rows: 14041

    validation: Dataset({

    test: Dataset({
```

പ്രത്യേകിച്ച്, നമ്മൾ മുമ്പ് പറഞ്ഞ മൂന്ന് ടാസ്‌കുകൾക്കുമുള്ള — NER, POS, ചങ്കിംഗ് — ലേബലുകൾ ഈ ഡേറ്റാസെറ്റിൽ ഉണ്ടെന്ന് കാണാം. മറ്റ് ഡേറ്റാസെറ്റുകളിൽ നിന്നുള്ള ഒരു വലിയ വ്യത്യാസം, ഇൻപുട്ട് ടെക്‌സ്‌റ്റുകൾ വാക്യങ്ങളായോ ഡോക്യുമെന്റുകളായോ അല്ല, വാക്കുകളുടെ ലിസ്‌റ്റുകളായാണ് നൽകിയിരിക്കുന്നത് എന്നതാണ് (അവസാനത്തെ കോളത്തിന്റെ പേര് `tokens` എന്നാണെങ്കിലും, അതിൽ ഉള്ളത് വാക്കുകളാണ് — അതായത്, സബ്‌വേഡ് ടോക്കണൈസേഷനായി ഇനിയും ടോക്കണൈസറിലൂടെ കടന്നുപോകേണ്ട, മുൻകൂട്ടി ടോക്കണൈസ് ചെയ്ത (pre-tokenized) ഇൻപുട്ടുകളാണ് ഇവ).

ട്രെയിനിംഗ് സെറ്റിലെ ആദ്യത്തെ എലമെന്റ് നോക്കാം:

```py
raw_datasets["train"][0]["tokens"]
```

```python out
['EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'lamb', '.']
```

നമുക്ക് നെയിംഡ് എന്റിറ്റി റെക്കഗ്നിഷൻ ചെയ്യണം എന്നതിനാൽ, NER ടാഗുകൾ നമ്മൾ നോക്കും:

```py
raw_datasets["train"][0]["ner_tags"]
```

```python out
[3, 0, 7, 0, 0, 0, 7, 0, 0]
```

ട്രെയിനിംഗിന് തയ്യാറായ, ഇന്റിജറുകളായുള്ള (integers) ലേബലുകളാണ് ഇവ; എന്നാൽ ഡേറ്റ പരിശോധിക്കാൻ ആഗ്രഹിക്കുമ്പോൾ ഇവ അത്ര ഉപകാരപ്രദമാകണമെന്നില്ല. ടെക്‌സ്‌റ്റ് ക്ലാസിഫിക്കേഷന്റെ കാര്യത്തിലേതുപോലെ, നമ്മുടെ ഡേറ്റാസെറ്റിന്റെ `features` ആട്രിബ്യൂട്ട് നോക്കിയാൽ ഈ ഇന്റിജറുകളും ലേബൽ പേരുകളും തമ്മിലുള്ള ബന്ധം നമുക്ക് കാണാം:

```py
ner_feature = raw_datasets["train"].features["ner_tags"]
ner_feature
```

```python out
Sequence(feature=ClassLabel(num_classes=9, names=['O', 'B-PER', 'I-PER', 'B-ORG', 'I-ORG', 'B-LOC', 'I-LOC', 'B-MISC', 'I-MISC'], names_file=None, id=None), length=-1, id=None)
```

അതായത്, ഈ കോളത്തിലെ എലമെന്റുകൾ `ClassLabel`-ന്റെ സീക്വൻസുകളാണ്. സീക്വൻസിലെ എലമെന്റുകളുടെ ടൈപ്പ് ഈ `ner_feature`-ന്റെ `feature` ആട്രിബ്യൂട്ടിലാണ് ഉള്ളത്; ആ `feature`-ന്റെ `names` ആട്രിബ്യൂട്ട് നോക്കിയാൽ പേരുകളുടെ ലിസ്‌റ്റ് നമുക്ക് ലഭിക്കും:

```py
label_names = ner_feature.feature.names
label_names
```

```python out
['O', 'B-PER', 'I-PER', 'B-ORG', 'I-ORG', 'B-LOC', 'I-LOC', 'B-MISC', 'I-MISC']
```

[അധ്യായം 6](/course/chapter6/3)-ൽ `token-classification` പൈപ്പ്‌ലൈനിലേക്ക് ആഴത്തിൽ ഇറങ്ങിയപ്പോൾ ഈ ലേബലുകൾ നമ്മൾ ഇതിനകം കണ്ടിട്ടുണ്ട്, എങ്കിലും പെട്ടെന്ന് ഒന്ന് ഓർമ്മ പുതുക്കാൻ:

- `O` എന്നാൽ ആ വാക്ക് ഒരു എന്റിറ്റിയുമായും ബന്ധപ്പെട്ടതല്ല എന്നാണ്.
- `B-PER`/`I-PER` എന്നാൽ ആ വാക്ക് ഒരു *വ്യക്തി* (person) എന്റിറ്റിയുടെ തുടക്കമാണ്/ഉള്ളിലാണ് എന്നാണ്.
- `B-ORG`/`I-ORG` എന്നാൽ ആ വാക്ക് ഒരു *സംഘടന* (organization) എന്റിറ്റിയുടെ തുടക്കമാണ്/ഉള്ളിലാണ് എന്നാണ്.
- `B-LOC`/`I-LOC` എന്നാൽ ആ വാക്ക് ഒരു *സ്ഥലം* (location) എന്റിറ്റിയുടെ തുടക്കമാണ്/ഉള്ളിലാണ് എന്നാണ്.
- `B-MISC`/`I-MISC` എന്നാൽ ആ വാക്ക് ഒരു *മറ്റ് വിഭാഗത്തിലുള്ള* (miscellaneous) എന്റിറ്റിയുടെ തുടക്കമാണ്/ഉള്ളിലാണ് എന്നാണ്.

ഇപ്പോൾ, നമ്മൾ മുമ്പ് കണ്ട ലേബലുകൾ ഡീകോഡ് ചെയ്താൽ ഇതാണ് ലഭിക്കുന്നത്:

```python
words = raw_datasets["train"][0]["tokens"]
labels = raw_datasets["train"][0]["ner_tags"]
line1 = ""
line2 = ""
for word, label in zip(words, labels):
    full_label = label_names[label]
    max_length = max(len(word), len(full_label))
    line1 += word + " " * (max_length - len(word) + 1)
    line2 += full_label + " " * (max_length - len(full_label) + 1)

print(line1)
print(line2)
```

```python out
'EU    rejects German call to boycott British lamb .'
'B-ORG O       B-MISC O    O  O       B-MISC  O    O'
```

`B-`, `I-` ലേബലുകൾ ഇടകലർന്നു വരുന്ന ഒരു ഉദാഹരണത്തിനായി, ട്രെയിനിംഗ് സെറ്റിലെ ഇൻഡെക്‌സ് 4-ലുള്ള എലമെന്റിൽ അതേ കോഡ് നൽകുന്ന ഫലം ഇതാ:

```python out
'Germany \'s representative to the European Union \'s veterinary committee Werner Zwingmann said on Wednesday consumers should buy sheepmeat from countries other than Britain until the scientific advice was clearer .'
'B-LOC   O  O              O  O   B-ORG    I-ORG O  O          O         B-PER  I-PER     O    O  O         O         O      O   O         O    O         O     O    B-LOC   O     O   O          O      O   O       O'
```

നമുക്ക് കാണാവുന്നതുപോലെ, "European Union", "Werner Zwingmann" എന്നിവ പോലെ രണ്ട് വാക്കുകളിലായി വ്യാപിക്കുന്ന എന്റിറ്റികൾക്ക്, ആദ്യത്തെ വാക്കിന് ഒരു `B-` ലേബലും രണ്ടാമത്തേതിന് ഒരു `I-` ലേബലുമാണ് നൽകിയിരിക്കുന്നത്.

പതിവുപോലെ, മോഡലിന് മനസ്സിലാക്കാൻ കഴിയുന്നതിന് മുമ്പ് നമ്മുടെ ടെക്‌സ്‌റ്റുകൾ ടോക്കൺ ID-കളാക്കി മാറ്റേണ്ടതുണ്ട്. [അധ്യായം 6](/course/chapter6/)-ൽ കണ്ടതുപോലെ, ടോക്കൺ ക്ലാസിഫിക്കേഷൻ ടാസ്‌കുകളുടെ കാര്യത്തിലെ ഒരു വലിയ വ്യത്യാസം, നമ്മുടെ ഇൻപുട്ടുകൾ മുൻകൂട്ടി ടോക്കണൈസ് ചെയ്തവയാണ് എന്നതാണ്. ഭാഗ്യവശാൽ, ടോക്കണൈസർ API-ക്ക് ഇത് വളരെ എളുപ്പത്തിൽ കൈകാര്യം ചെയ്യാൻ കഴിയും; ഒരു പ്രത്യേക ഫ്ലാഗ് ഉപയോഗിച്ച് `tokenizer`-നെ അറിയിച്ചാൽ മാത്രം മതി.

തുടങ്ങാൻ, നമ്മുടെ `tokenizer` ഒബ്‌ജക്റ്റ് ഉണ്ടാക്കാം. മുമ്പ് പറഞ്ഞതുപോലെ, ഒരു BERT പ്രീട്രെയിൻഡ് മോഡലാണ് നമ്മൾ ഉപയോഗിക്കുന്നത്; അതിനാൽ അതിനോട് ബന്ധപ്പെട്ട ടോക്കണൈസർ ഡൗൺലോഡ് ചെയ്ത് കാഷ് ചെയ്യുന്നതിലൂടെ നമ്മൾ ആരംഭിക്കും:

```python
from transformers import AutoTokenizer

model_checkpoint = "bert-base-cased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

`model_checkpoint`-ന് പകരം [Hub](https://huggingface.co/models)-ൽ നിന്ന് നിങ്ങൾക്ക് ഇഷ്ടമുള്ള മറ്റേതെങ്കിലും മോഡലോ, ഒരു പ്രീട്രെയിൻഡ് മോഡലും ടോക്കണൈസറും നിങ്ങൾ സേവ് ചെയ്തിട്ടുള്ള ഒരു ലോക്കൽ ഫോൾഡറോ നിങ്ങൾക്ക് ഉപയോഗിക്കാം. ഒരേയൊരു നിബന്ധന, ടോക്കണൈസർ 🤗 Tokenizers ലൈബ്രറിയെ അടിസ്ഥാനമാക്കിയുള്ളതായിരിക്കണം, അതായത് അതിന്റെ ഒരു "ഫാസ്‌റ്റ്" (fast) പതിപ്പ് ലഭ്യമായിരിക്കണം എന്നതാണ്. ഫാസ്‌റ്റ് പതിപ്പുള്ള എല്ലാ ആർക്കിടെക്‌ചറുകളും [ഈ വലിയ പട്ടികയിൽ](https://huggingface.co/transformers/#supported-frameworks) നിങ്ങൾക്ക് കാണാം; നിങ്ങൾ ഉപയോഗിക്കുന്ന `tokenizer` ഒബ്‌ജക്റ്റ് ശരിക്കും 🤗 Tokenizers-നെ അടിസ്ഥാനമാക്കിയുള്ളതാണോ എന്ന് പരിശോധിക്കാൻ അതിന്റെ `is_fast` ആട്രിബ്യൂട്ട് നോക്കാം:

```py
tokenizer.is_fast
```

```python out
True
```

മുൻകൂട്ടി ടോക്കണൈസ് ചെയ്ത ഒരു ഇൻപുട്ട് ടോക്കണൈസ് ചെയ്യാൻ, നമ്മുടെ `tokenizer` പതിവുപോലെ ഉപയോഗിച്ച്, `is_split_into_words=True` എന്നത് കൂടി ചേർത്താൽ മതി:

```py
inputs = tokenizer(raw_datasets["train"][0]["tokens"], is_split_into_words=True)
inputs.tokens()
```

```python out
['[CLS]', 'EU', 'rejects', 'German', 'call', 'to', 'boycott', 'British', 'la', '##mb', '.', '[SEP]']
```

നമുക്ക് കാണാവുന്നതുപോലെ, മോഡൽ ഉപയോഗിക്കുന്ന സ്‌പെഷ്യൽ ടോക്കണുകൾ (തുടക്കത്തിൽ `[CLS]`, അവസാനം `[SEP]`) ടോക്കണൈസർ ചേർത്തു, മിക്ക വാക്കുകളെയും അതേപടി വിട്ടു. എന്നാൽ `lamb` എന്ന വാക്ക് `la`, `##mb` എന്നീ രണ്ട് സബ്‌വേഡുകളായി ടോക്കണൈസ് ചെയ്യപ്പെട്ടു. ഇത് നമ്മുടെ ഇൻപുട്ടുകളും ലേബലുകളും തമ്മിൽ ഒരു പൊരുത്തക്കേട് ഉണ്ടാക്കുന്നു: ലേബലുകളുടെ ലിസ്‌റ്റിൽ 9 എലമെന്റുകൾ മാത്രമേയുള്ളൂ, എന്നാൽ നമ്മുടെ ഇൻപുട്ടിൽ ഇപ്പോൾ 12 ടോക്കണുകളുണ്ട്. സ്‌പെഷ്യൽ ടോക്കണുകളുടെ കാര്യം കണക്കിലെടുക്കുന്നത് എളുപ്പമാണ് (അവ തുടക്കത്തിലും അവസാനത്തിലുമാണെന്ന് നമുക്കറിയാം), എന്നാൽ എല്ലാ ലേബലുകളും ശരിയായ വാക്കുകളുമായി വിന്യസിക്കുന്നു (align) എന്ന് ഉറപ്പാക്കുകയും വേണം.

ഭാഗ്യവശാൽ, നമ്മൾ ഒരു ഫാസ്‌റ്റ് ടോക്കണൈസർ ഉപയോഗിക്കുന്നതിനാൽ 🤗 Tokenizers-ന്റെ അസാമാന്യ ശേഷികൾ നമുക്ക് ലഭ്യമാണ്; അതായത്, ഓരോ ടോക്കണും അതിനോട് ബന്ധപ്പെട്ട വാക്കുമായി എളുപ്പത്തിൽ മാപ്പ് ചെയ്യാൻ നമുക്ക് കഴിയും ([അധ്യായം 6](/course/chapter6/3)-ൽ കണ്ടതുപോലെ):

```py
inputs.word_ids()
```

```python out
[None, 0, 1, 2, 3, 4, 5, 6, 7, 7, 8, None]
```

ചെറിയൊരു പണിയിലൂടെ, ടോക്കണുകളുമായി പൊരുത്തപ്പെടുന്ന തരത്തിൽ നമ്മുടെ ലേബൽ ലിസ്‌റ്റ് വികസിപ്പിക്കാം. നമ്മൾ പ്രയോഗിക്കുന്ന ആദ്യത്തെ നിയമം, സ്‌പെഷ്യൽ ടോക്കണുകൾക്ക് `-100` എന്ന ലേബൽ ലഭിക്കും എന്നതാണ്. കാരണം, നമ്മൾ ഉപയോഗിക്കാൻ പോകുന്ന ലോസ് ഫംഗ്‌ഷനിൽ (ക്രോസ് എൻട്രോപ്പി) ഡിഫോൾട്ടായി അവഗണിക്കപ്പെടുന്ന ഒരു ഇൻഡെക്‌സാണ് `-100`. പിന്നീട്, ഓരോ ടോക്കണിനും അത് ഉള്ളിലുള്ള വാക്ക് ആരംഭിച്ച ടോക്കണിന്റെ അതേ ലേബൽ ലഭിക്കും, കാരണം അവ ഒരേ എന്റിറ്റിയുടെ ഭാഗമാണ്. ഒരു വാക്കിന്റെ ഉള്ളിലുള്ള, എന്നാൽ തുടക്കത്തിലല്ലാത്ത ടോക്കണുകൾക്ക്, `B-` എന്നത് `I-` എന്നാക്കി മാറ്റുന്നു (ആ ടോക്കൺ എന്റിറ്റി ആരംഭിക്കുന്നില്ല എന്നതിനാൽ):

```python
def align_labels_with_tokens(labels, word_ids):
    new_labels = []
    current_word = None
    for word_id in word_ids:
        if word_id != current_word:
            # Start of a new word!
            current_word = word_id
            label = -100 if word_id is None else labels[word_id]
            new_labels.append(label)
        elif word_id is None:
            # Special token
            new_labels.append(-100)
        else:
            # Same word as previous token
            label = labels[word_id]
            # If the label is B-XXX we change it to I-XXX
            if label % 2 == 1:
                label += 1
            new_labels.append(label)

    return new_labels
```

നമ്മുടെ ആദ്യത്തെ വാക്യത്തിൽ ഇത് പരീക്ഷിച്ചുനോക്കാം:

```py
labels = raw_datasets["train"][0]["ner_tags"]
word_ids = inputs.word_ids()
print(labels)
print(align_labels_with_tokens(labels, word_ids))
```

```python out
[3, 0, 7, 0, 0, 0, 7, 0, 0]
[-100, 3, 0, 7, 0, 0, 0, 7, 0, 0, 0, -100]
```

നമുക്ക് കാണാവുന്നതുപോലെ, തുടക്കത്തിലെയും അവസാനത്തെയും രണ്ട് സ്‌പെഷ്യൽ ടോക്കണുകൾക്ക് `-100`-ഉം, രണ്ട് ടോക്കണുകളായി വിഭജിക്കപ്പെട്ട നമ്മുടെ വാക്കിന് ഒരു പുതിയ `0`-ഉം നമ്മുടെ ഫംഗ്‌ഷൻ ചേർത്തു.

> [!TIP]
> ✏️ **നിങ്ങളുടെ ഊഴം!** ചില ഗവേഷകർ ഒരു വാക്കിന് ഒരു ലേബൽ മാത്രം നൽകാനും, ആ വാക്കിലെ മറ്റ് സബ്‌ടോക്കണുകൾക്ക് `-100` നൽകാനുമാണ് ഇഷ്ടപ്പെടുന്നത്. ധാരാളം സബ്‌ടോക്കണുകളായി വിഭജിക്കപ്പെടുന്ന നീണ്ട വാക്കുകൾ ലോസിൽ വലിയ സ്വാധീനം ചെലുത്തുന്നത് ഒഴിവാക്കാനാണ് ഇത്. ഈ നിയമം പിന്തുടർന്ന് ലേബലുകളെ ഇൻപുട്ട് ID-കളുമായി വിന്യസിക്കാൻ മുമ്പത്തെ ഫംഗ്‌ഷൻ മാറ്റുക.

നമ്മുടെ മുഴുവൻ ഡേറ്റാസെറ്റും പ്രീപ്രോസസ്സ് ചെയ്യാൻ, എല്ലാ ഇൻപുട്ടുകളും ടോക്കണൈസ് ചെയ്യുകയും എല്ലാ ലേബലുകളിലും `align_labels_with_tokens()` പ്രയോഗിക്കുകയും വേണം. നമ്മുടെ ഫാസ്‌റ്റ് ടോക്കണൈസറിന്റെ വേഗത പ്രയോജനപ്പെടുത്താൻ, ധാരാളം ടെക്‌സ്‌റ്റുകൾ ഒരേസമയം ടോക്കണൈസ് ചെയ്യുന്നതാണ് ഏറ്റവും നല്ലത്; അതിനാൽ ഉദാഹരണങ്ങളുടെ ഒരു ലിസ്‌റ്റ് പ്രോസസ്സ് ചെയ്യുന്ന ഒരു ഫംഗ്‌ഷൻ എഴുതി, `batched=True` എന്ന ഓപ്‌ഷനോടെ `Dataset.map()` മെത്തേഡ് നമ്മൾ ഉപയോഗിക്കും. നമ്മുടെ മുൻ ഉദാഹരണത്തിൽ നിന്നുള്ള ഒരേയൊരു വ്യത്യാസം, ടോക്കണൈസറിലേക്കുള്ള ഇൻപുട്ടുകൾ ടെക്‌സ്‌റ്റുകളുടെ ലിസ്‌റ്റുകളായിരിക്കുമ്പോൾ (അല്ലെങ്കിൽ നമ്മുടെ കാര്യത്തിൽ, വാക്കുകളുടെ ലിസ്‌റ്റുകളുടെ ലിസ്‌റ്റ്), ഏത് ഉദാഹരണത്തിന്റെ വേഡ് ID-കളാണ് വേണ്ടത് എന്നതിന്റെ ഇൻഡെക്‌സ് `word_ids()` ഫംഗ്‌ഷന് നൽകേണ്ടതുണ്ട് എന്നതാണ്; അതിനാൽ അതും നമ്മൾ ചേർക്കുന്നു:

```py
def tokenize_and_align_labels(examples):
    tokenized_inputs = tokenizer(
        examples["tokens"], truncation=True, is_split_into_words=True
    )
    all_labels = examples["ner_tags"]
    new_labels = []
    for i, labels in enumerate(all_labels):
        word_ids = tokenized_inputs.word_ids(i)
        new_labels.append(align_labels_with_tokens(labels, word_ids))

    tokenized_inputs["labels"] = new_labels
    return tokenized_inputs
```

നമ്മുടെ ഇൻപുട്ടുകൾ ഇതുവരെ പാഡ് ചെയ്തിട്ടില്ല എന്നത് ശ്രദ്ധിക്കുക; ഒരു ഡേറ്റാ കൊളേറ്റർ (data collator) ഉപയോഗിച്ച് ബാച്ചുകൾ ഉണ്ടാക്കുമ്പോൾ, പിന്നീട് നമ്മൾ അത് ചെയ്യും.

ഇപ്പോൾ ആ പ്രീപ്രോസസ്സിംഗ് മുഴുവൻ ഒറ്റയടിക്ക് നമ്മുടെ ഡേറ്റാസെറ്റിന്റെ മറ്റ് സ്‌പ്ലിറ്റുകളിലും പ്രയോഗിക്കാം:

```py
tokenized_datasets = raw_datasets.map(
    tokenize_and_align_labels,
    batched=True,
    remove_columns=raw_datasets["train"].column_names,
)
```

ഏറ്റവും ബുദ്ധിമുട്ടുള്ള ഭാഗം നമ്മൾ പൂർത്തിയാക്കി! ഡേറ്റ പ്രീപ്രോസസ്സ് ചെയ്തുകഴിഞ്ഞ സ്ഥിതിക്ക്, യഥാർത്ഥ ട്രെയിനിംഗ് [അധ്യായം 3](/course/chapter3)-ൽ നമ്മൾ ചെയ്തതിനോട് വളരെ സാമ്യമുള്ളതായിരിക്കും.

`Trainer` ഉപയോഗിക്കുന്ന യഥാർത്ഥ കോഡ് മുമ്പത്തേതുപോലെ തന്നെയായിരിക്കും; ഡേറ്റ ഒരു ബാച്ചായി കൊളേറ്റ് ചെയ്യുന്ന രീതിയും മെട്രിക് കണക്കുകൂട്ടൽ ഫംഗ്‌ഷനും മാത്രമാണ് മാറ്റങ്ങൾ.

### ഡേറ്റാ കൊളേഷൻ[[data-collation]]

[അധ്യായം 3](/course/chapter3)-ലേതുപോലെ ഒരു `DataCollatorWithPadding` അതേപടി ഉപയോഗിക്കാൻ നമുക്ക് കഴിയില്ല, കാരണം അത് ഇൻപുട്ടുകൾ (ഇൻപുട്ട് ID-കൾ, അറ്റൻഷൻ മാസ്‌ക്, ടോക്കൺ ടൈപ്പ് ID-കൾ) മാത്രമേ പാഡ് ചെയ്യുന്നുള്ളൂ. ഇവിടെ നമ്മുടെ ലേബലുകളും ഇൻപുട്ടുകളുടെ അതേ രീതിയിൽ തന്നെ പാഡ് ചെയ്യണം, അങ്ങനെ അവ ഒരേ വലിപ്പത്തിൽ തുടരും; ലോസ് കണക്കുകൂട്ടലിൽ അതിനോട് ബന്ധപ്പെട്ട പ്രവചനങ്ങൾ അവഗണിക്കപ്പെടാൻ വേണ്ടി `-100` ആണ് മൂല്യമായി ഉപയോഗിക്കുന്നത്.

ഇതെല്ലാം ഒരു [`DataCollatorForTokenClassification`](https://huggingface.co/transformers/main_classes/data_collator.html#datacollatorfortokenclassification) ചെയ്യുന്നു. `DataCollatorWithPadding` പോലെ, ഇൻപുട്ടുകൾ പ്രീപ്രോസസ്സ് ചെയ്യാൻ ഉപയോഗിച്ച `tokenizer` ഇത് സ്വീകരിക്കുന്നു:

{#if fw === 'pt'}

```py
from transformers import DataCollatorForTokenClassification

data_collator = DataCollatorForTokenClassification(tokenizer=tokenizer)
```

{:else}

```py
from transformers import DataCollatorForTokenClassification

data_collator = DataCollatorForTokenClassification(
    tokenizer=tokenizer, return_tensors="tf"
)
```

{/if}

```py
batch = data_collator([tokenized_datasets["train"][i] for i in range(2)])
```

```py
for i in range(2):
```

നമ്മുടെ ഡേറ്റാ കൊളേറ്റർ തയ്യാറായി! ഇപ്പോൾ `to_tf_dataset()` മെത്തേഡ് ഉപയോഗിച്ച് ഒരു `tf.data.Dataset` ഉണ്ടാക്കാൻ ഇത് ഉപയോഗിക്കാം. കുറച്ചുകൂടി കുറഞ്ഞ ബോയിലർപ്ലേറ്റ് കോഡിൽ ഇത് ചെയ്യാൻ `model.prepare_tf_dataset()` ഉപയോഗിക്കുകയും ചെയ്യാം — ഈ അധ്യായത്തിലെ മറ്റ് ചില ഭാഗങ്ങളിൽ ഇത് നിങ്ങൾ കാണും.

```py
tf_train_dataset = tokenized_datasets["train"].to_tf_dataset(

    shuffle=True,
    batch_size=16,
)

tf_eval_dataset = tokenized_datasets["validation"].to_tf_dataset(
    columns=["attention_mask", "input_ids", "labels", "token_type_ids"],
    collate_fn=data_collator,
    shuffle=False,
    batch_size=16,
)
```

### മോഡൽ നിർവചിക്കുന്നു[[defining-the-model]]

നമ്മൾ ഒരു ടോക്കൺ ക്ലാസിഫിക്കേഷൻ പ്രശ്നത്തിലാണ് പ്രവർത്തിക്കുന്നത് എന്നതിനാൽ, `TFAutoModelForTokenClassification` ക്ലാസ് നമ്മൾ ഉപയോഗിക്കും. ഈ മോഡൽ നിർവചിക്കുമ്പോൾ ഓർമ്മിക്കേണ്ട പ്രധാന കാര്യം, നമുക്കുള്ള ലേബലുകളുടെ എണ്ണത്തെക്കുറിച്ചുള്ള വിവരം കൈമാറുക എന്നതാണ്. ഇത് ചെയ്യാനുള്ള ഏറ്റവും എളുപ്പ വഴി `num_labels` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് ആ എണ്ണം നൽകുകയാണ്; എന്നാൽ ഈ ഭാഗത്തിന്റെ തുടക്കത്തിൽ കണ്ടതുപോലെ നന്നായി പ്രവർത്തിക്കുന്ന ഒരു ഇൻഫറൻസ് വിഡ്‌ജറ്റ് വേണമെങ്കിൽ, പകരം ശരിയായ ലേബൽ ബന്ധങ്ങൾ (label correspondences) സെറ്റ് ചെയ്യുന്നതാണ് നല്ലത്.

ID-യിൽ നിന്ന് ലേബലിലേക്കും തിരിച്ചുമുള്ള മാപ്പിംഗ് ഉൾക്കൊള്ളുന്ന `id2label`, `label2id` എന്നീ രണ്ട് ഡിക്‌ഷണറികൾ ഉപയോഗിച്ചാണ് അവ സെറ്റ് ചെയ്യേണ്ടത്:

```py
id2label = {i: label for i, label in enumerate(label_names)}
label2id = {v: k for k, v in id2label.items()}
```

ഇപ്പോൾ അവ `TFAutoModelForTokenClassification.from_pretrained()` മെത്തേഡിന് നൽകിയാൽ മതി; അവ മോഡലിന്റെ കോൺഫിഗറേഷനിൽ സെറ്റ് ചെയ്യപ്പെടുകയും, പിന്നീട് ശരിയായി സേവ് ചെയ്ത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെടുകയും ചെയ്യും:

```py
from transformers import TFAutoModelForTokenClassification

model = TFAutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

[അധ്യായം 3](/course/chapter3)-ൽ നമ്മുടെ `TFAutoModelForSequenceClassification` നിർവചിച്ചപ്പോഴത്തേതുപോലെ, മോഡൽ ഉണ്ടാക്കുമ്പോൾ ചില വെയ്‌റ്റുകൾ ഉപയോഗിച്ചിട്ടില്ലെന്നും (പ്രീട്രെയിനിംഗ് ഹെഡിന്റേത്) മറ്റു ചില വെയ്‌റ്റുകൾ ക്രമരഹിതമായി ഇനിഷ്യലൈസ് ചെയ്യപ്പെട്ടിരിക്കുന്നു എന്നും (പുതിയ ടോക്കൺ ക്ലാസിഫിക്കേഷൻ ഹെഡിന്റേത്), ഈ മോഡൽ ട്രെയിൻ ചെയ്യണം എന്നും ഒരു മുന്നറിയിപ്പ് ലഭിക്കും. അത് നമ്മൾ ഉടൻ ചെയ്യും, എന്നാൽ ആദ്യം നമ്മുടെ മോഡലിന് ശരിയായ എണ്ണം ലേബലുകൾ ഉണ്ടെന്ന് ഒന്നുകൂടി ഉറപ്പാക്കാം:

```python
model.config.num_labels
```

```python out
9
```

> [!WARNING]
> ⚠️ തെറ്റായ എണ്ണം ലേബലുകളുള്ള ഒരു മോഡലാണ് നിങ്ങളുടേതെങ്കിൽ, പിന്നീട് `model.fit()` വിളിക്കുമ്പോൾ അവ്യക്തമായ ഒരു എറർ നിങ്ങൾക്ക് ലഭിക്കും. ഇത് ഡീബഗ് ചെയ്യാൻ ബുദ്ധിമുട്ടായിരിക്കാം; അതിനാൽ പ്രതീക്ഷിക്കുന്ന എണ്ണം ലേബലുകൾ ഉണ്ടെന്ന് സ്ഥിരീകരിക്കാൻ ഈ പരിശോധന നിങ്ങൾ തീർച്ചയായും ചെയ്യുക.

### മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നു[[fine-tuning-the-model]]

ഇപ്പോൾ നമ്മുടെ മോഡൽ ട്രെയിൻ ചെയ്യാൻ നമ്മൾ തയ്യാറാണ്! എന്നാൽ ആദ്യം ചെറിയ ചില ഒരുക്കങ്ങൾ കൂടി ബാക്കിയുണ്ട്: Hugging Face-ൽ ലോഗിൻ ചെയ്യുകയും നമ്മുടെ ട്രെയിനിംഗ് ഹൈപ്പർപാരാമീറ്ററുകൾ നിർവചിക്കുകയും വേണം. നിങ്ങൾ ഒരു നോട്ട്‌ബുക്കിലാണ് പ്രവർത്തിക്കുന്നതെങ്കിൽ, ഇതിന് നിങ്ങളെ സഹായിക്കുന്ന സൗകര്യപ്രദമായ ഒരു ഫംഗ്‌ഷൻ ഉണ്ട്:

```python
from huggingface_hub import notebook_login

notebook_login()
```

നിങ്ങളുടെ Hugging Face ലോഗിൻ വിവരങ്ങൾ (credentials) നൽകാവുന്ന ഒരു വിഡ്‌ജറ്റ് ഇത് കാണിക്കും.

നിങ്ങൾ ഒരു നോട്ട്‌ബുക്കിലല്ല പ്രവർത്തിക്കുന്നതെങ്കിൽ, നിങ്ങളുടെ ടെർമിനലിൽ താഴെയുള്ള വരി ടൈപ്പ് ചെയ്താൽ മതി:

```bash
huggingface-cli login
```

ലോഗിൻ ചെയ്ത ശേഷം, നമ്മുടെ മോഡൽ കംപൈൽ ചെയ്യാൻ ആവശ്യമായതെല്ലാം തയ്യാറാക്കാം. വെയ്‌റ്റ് ഡികേയ്‌ക്കും (weight decay) ലേണിംഗ് റേറ്റ് ഡികേയ്‌ക്കും അനുയോജ്യമായ സെറ്റിംഗുകളോടെ ഒരു `AdamW` ഒപ്‌റ്റിമൈസർ നിങ്ങൾക്ക് നൽകുന്ന സൗകര്യപ്രദമായ ഒരു `create_optimizer()` ഫംഗ്‌ഷൻ 🤗 Transformers നൽകുന്നു; ബിൽറ്റ്-ഇൻ `Adam` ഒപ്‌റ്റിമൈസറിനെ അപേക്ഷിച്ച് ഇവ രണ്ടും നിങ്ങളുടെ മോഡലിന്റെ പ്രകടനം മെച്ചപ്പെടുത്തും:

```python
from transformers import create_optimizer
import tensorflow as tf

# Train in mixed-precision float16
# Comment this line out if you're using a GPU that will not benefit from this
tf.keras.mixed_precision.set_global_policy("mixed_float16")

# The number of training steps is the number of samples in the dataset, divided by the batch size then multiplied
# by the total number of epochs. Note that the tf_train_dataset here is a batched tf.data.Dataset,
# not the original Hugging Face Dataset, so its len() is already num_samples // batch_size.
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=2e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)
```

`compile()`-ന് ഒരു `loss` ആർഗ്യുമെന്റ് നമ്മൾ നൽകുന്നില്ല എന്നതും ശ്രദ്ധിക്കുക. കാരണം, മോഡലുകൾക്ക് ആന്തരികമായി ലോസ് കണക്കാക്കാൻ കഴിയും — ലോസ് ഇല്ലാതെ കംപൈൽ ചെയ്യുകയും നിങ്ങളുടെ ലേബലുകൾ ഇൻപുട്ട് ഡിക്‌ഷണറിയിൽ നൽകുകയും ചെയ്താൽ (നമ്മുടെ ഡേറ്റാസെറ്റുകളിൽ നമ്മൾ ചെയ്യുന്നതുപോലെ), മോഡൽ ആ ആന്തരിക ലോസ് ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്യും; നിങ്ങൾ തിരഞ്ഞെടുത്ത ടാസ്‌കിനും മോഡൽ ടൈപ്പിനും അനുയോജ്യമായതായിരിക്കും അത്.

അടുത്തതായി, ട്രെയിനിംഗ് സമയത്ത് നമ്മുടെ മോഡൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാൻ ഒരു `PushToHubCallback` നിർവചിച്ച്, ആ കോൾബാക്കോടെ മോഡൽ ഫിറ്റ് ചെയ്യുന്നു:

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(output_dir="bert-finetuned-ner", tokenizer=tokenizer)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ പൂർണ്ണമായ പേര് `hub_model_id` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് നിങ്ങൾക്ക് വ്യക്തമാക്കാം (പ്രത്യേകിച്ച്, ഒരു ഓർഗനൈസേഷനിലേക്ക് പുഷ് ചെയ്യാൻ ഈ ആർഗ്യുമെന്റ് നിങ്ങൾ ഉപയോഗിക്കേണ്ടിവരും). ഉദാഹരണത്തിന്, [`huggingface-course` ഓർഗനൈസേഷനിലേക്ക്](https://huggingface.co/huggingface-course) മോഡൽ പുഷ് ചെയ്തപ്പോൾ, ഞങ്ങൾ `hub_model_id="huggingface-course/bert-finetuned-ner"` ചേർത്തു. ഡിഫോൾട്ടായി, ഉപയോഗിക്കുന്ന റിപ്പോസിറ്ററി നിങ്ങളുടെ നെയിംസ്‌പേസിലായിരിക്കും, നിങ്ങൾ സെറ്റ് ചെയ്ത ഔട്ട്‌പുട്ട് ഡയറക്ടറിയുടെ പേരിലായിരിക്കും അത്; ഉദാഹരണത്തിന് `"cool_huggingface_user/bert-finetuned-ner"`.

> [!TIP]
> 💡 നിങ്ങൾ ഉപയോഗിക്കുന്ന ഔട്ട്‌പുട്ട് ഡയറക്ടറി ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, അത് നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ലോക്കൽ ക്ലോൺ ആയിരിക്കണം. അല്ലെങ്കിൽ, `model.fit()` വിളിക്കുമ്പോൾ ഒരു എറർ ലഭിക്കും, പുതിയ ഒരു പേര് സെറ്റ് ചെയ്യേണ്ടിവരും.

ട്രെയിനിംഗ് നടക്കുമ്പോൾ, ഓരോ തവണ മോഡൽ സേവ് ചെയ്യപ്പെടുമ്പോഴും (ഇവിടെ, ഓരോ എപ്പോക്കിലും) അത് പശ്ചാത്തലത്തിൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെടുന്നു എന്നത് ശ്രദ്ധിക്കുക. ഇങ്ങനെ, ആവശ്യമെങ്കിൽ മറ്റൊരു മെഷീനിൽ നിങ്ങളുടെ ട്രെയിനിംഗ് പുനരാരംഭിക്കാൻ നിങ്ങൾക്ക് കഴിയും.

ഈ ഘട്ടത്തിൽ, Model Hub-ലെ ഇൻഫറൻസ് വിഡ്‌ജറ്റ് ഉപയോഗിച്ച് നിങ്ങളുടെ മോഡൽ പരീക്ഷിക്കാനും സുഹൃത്തുക്കളുമായി പങ്കുവയ്ക്കാനും കഴിയും. ഒരു ടോക്കൺ ക്ലാസിഫിക്കേഷൻ ടാസ്‌കിൽ നിങ്ങൾ വിജയകരമായി ഒരു മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്തു — അഭിനന്ദനങ്ങൾ! എന്നാൽ നമ്മുടെ മോഡൽ ശരിക്കും എത്ര മികച്ചതാണ്? അത് അറിയാൻ ചില മെട്രിക്കുകൾ നമ്മൾ ഇവാല്യുവേറ്റ് ചെയ്യണം.

{/if}


### മെട്രിക്കുകൾ[[metrics]]

ഓരോ എപ്പോക്കിലും `Trainer` ഒരു മെട്രിക് കണക്കാക്കണമെങ്കിൽ, പ്രവചനങ്ങളുടെയും ലേബലുകളുടെയും അറേകൾ സ്വീകരിച്ച്, മെട്രിക്കുകളുടെ പേരുകളും മൂല്യങ്ങളുമുള്ള ഒരു ഡിക്‌ഷണറി റിട്ടേൺ ചെയ്യുന്ന ഒരു `compute_metrics()` ഫംഗ്‌ഷൻ നമ്മൾ നിർവചിക്കേണ്ടതുണ്ട്.

ഇത് ധാരാളം വിവരങ്ങൾ തിരികെ നൽകുന്നു! ഓരോ എന്റിറ്റിക്കും വെവ്വേറെയും, മൊത്തത്തിലുമുള്ള പ്രിസിഷൻ (precision), റീകോൾ (recall), F1 സ്‌കോർ എന്നിവ നമുക്ക് ലഭിക്കുന്നു. നമ്മുടെ മെട്രിക് കണക്കുകൂട്ടലിനായി മൊത്തത്തിലുള്ള സ്‌കോർ മാത്രമേ നമ്മൾ നിലനിർത്തുകയുള്ളൂ; എന്നാൽ നിങ്ങൾക്ക് റിപ്പോർട്ട് ചെയ്യണമെന്നുള്ള എല്ലാ മെട്രിക്കുകളും റിട്ടേൺ ചെയ്യുന്ന തരത്തിൽ `compute_metrics()` ഫംഗ്‌ഷൻ മാറ്റാൻ മടിക്കേണ്ടതില്ല.

ഈ `compute_metrics()` ഫംഗ്‌ഷൻ ആദ്യം ലോജിറ്റുകളുടെ argmax എടുത്ത് അവയെ പ്രവചനങ്ങളാക്കി മാറ്റുന്നു (പതിവുപോലെ, ലോജിറ്റുകളും പ്രോബബിലിറ്റികളും ഒരേ ക്രമത്തിലാണ്, അതിനാൽ softmax പ്രയോഗിക്കേണ്ട ആവശ്യമില്ല). പിന്നീട് ലേബലുകളെയും പ്രവചനങ്ങളെയും ഇന്റിജറുകളിൽ നിന്ന് സ്‌ട്രിംഗുകളാക്കി മാറ്റണം. ലേബൽ `-100` ആയിട്ടുള്ള എല്ലാ മൂല്യങ്ങളും നമ്മൾ നീക്കം ചെയ്യുന്നു, പിന്നീട് ഫലങ്ങൾ `metric.compute()` മെത്തേഡിന് നൽകുന്നു:

```py
import numpy as np


def compute_metrics(eval_preds):
    logits, labels = eval_preds
    predictions = np.argmax(logits, axis=-1)

    # Remove ignored index (special tokens) and convert to labels
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    all_metrics = metric.compute(predictions=true_predictions, references=true_labels)
    return {
        "precision": all_metrics["overall_precision"],
        "recall": all_metrics["overall_recall"],
        "f1": all_metrics["overall_f1"],
        "accuracy": all_metrics["overall_accuracy"],
    }
```

{:else}

ഇത് ധാരാളം വിവരങ്ങൾ തിരികെ നൽകുന്നു! ഓരോ എന്റിറ്റിക്കും വെവ്വേറെയും, മൊത്തത്തിലുമുള്ള പ്രിസിഷൻ (precision), റീകോൾ (recall), F1 സ്‌കോർ എന്നിവ നമുക്ക് ലഭിക്കുന്നു. ഇപ്പോൾ, നമ്മുടെ യഥാർത്ഥ മോഡൽ പ്രവചനങ്ങൾ ഉപയോഗിച്ച് ചില യഥാർത്ഥ സ്‌കോറുകൾ കണക്കാക്കാൻ ശ്രമിച്ചാൽ എന്ത് സംഭവിക്കുമെന്ന് നോക്കാം.

നമ്മുടെ പ്രവചനങ്ങൾക്ക് വ്യത്യസ്ത സീക്വൻസ് നീളങ്ങൾ ഉള്ളതിനാൽ, അവയെ ഒന്നിച്ച് കൂട്ടിച്ചേർക്കുന്നത് (concatenate) TensorFlow-ന് ഇഷ്ടമല്ല. അതായത്, `model.predict()` അതേപടി ഉപയോഗിക്കാൻ നമുക്ക് കഴിയില്ല — എന്നാൽ അത് നമ്മളെ തടയാൻ പോകുന്നില്ല. ഓരോ തവണയും ഒരു ബാച്ച് വീതം പ്രവചനങ്ങൾ എടുത്ത്, മാസ്‌കിംഗ്/പാഡിംഗ് സൂചിപ്പിക്കുന്ന `-100` ടോക്കണുകൾ ഒഴിവാക്കിക്കൊണ്ട്, അവയെ ഒരു വലിയ നീണ്ട ലിസ്‌റ്റായി കൂട്ടിച്ചേർത്തുകൊണ്ടുപോകും; അവസാനം ആ ലിസ്‌റ്റിൽ മെട്രിക്കുകൾ കണക്കാക്കും:

```py
import numpy as np

all_predictions = []
all_labels = []
for batch in tf_eval_dataset:
    logits = model.predict_on_batch(batch)["logits"]
    labels = batch["labels"]
    predictions = np.argmax(logits, axis=-1)
    for prediction, label in zip(predictions, labels):
        for predicted_idx, label_idx in zip(prediction, label):
            if label_idx == -100:
                continue
            all_predictions.append(label_names[predicted_idx])
            all_labels.append(label_names[label_idx])
metric.compute(predictions=[all_predictions], references=[all_labels])
```

### മോഡൽ നിർവചിക്കുന്നു[[defining-the-model]]

നമ്മൾ ഒരു ടോക്കൺ ക്ലാസിഫിക്കേഷൻ പ്രശ്നത്തിലാണ് പ്രവർത്തിക്കുന്നത് എന്നതിനാൽ, `AutoModelForTokenClassification` ക്ലാസ് നമ്മൾ ഉപയോഗിക്കും. ഈ മോഡൽ നിർവചിക്കുമ്പോൾ ഓർമ്മിക്കേണ്ട പ്രധാന കാര്യം, നമുക്കുള്ള ലേബലുകളുടെ എണ്ണത്തെക്കുറിച്ചുള്ള വിവരം കൈമാറുക എന്നതാണ്. ഇത് ചെയ്യാനുള്ള ഏറ്റവും എളുപ്പ വഴി `num_labels` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് ആ എണ്ണം നൽകുകയാണ്; എന്നാൽ ഈ ഭാഗത്തിന്റെ തുടക്കത്തിൽ കണ്ടതുപോലെ നന്നായി പ്രവർത്തിക്കുന്ന ഒരു ഇൻഫറൻസ് വിഡ്‌ജറ്റ് വേണമെങ്കിൽ, പകരം ശരിയായ ലേബൽ ബന്ധങ്ങൾ (label correspondences) സെറ്റ് ചെയ്യുന്നതാണ് നല്ലത്.

ID-യിൽ നിന്ന് ലേബലിലേക്കും തിരിച്ചുമുള്ള മാപ്പിംഗുകൾ ഉൾക്കൊള്ളുന്ന `id2label`, `label2id` എന്നീ രണ്ട് ഡിക്‌ഷണറികൾ ഉപയോഗിച്ചാണ് അവ സെറ്റ് ചെയ്യേണ്ടത്:

```py
id2label = {i: label for i, label in enumerate(label_names)}
label2id = {v: k for k, v in id2label.items()}
```

ഇപ്പോൾ അവ `AutoModelForTokenClassification.from_pretrained()` മെത്തേഡിന് നൽകിയാൽ മതി; അവ മോഡലിന്റെ കോൺഫിഗറേഷനിൽ സെറ്റ് ചെയ്യപ്പെടുകയും, പിന്നീട് ശരിയായി സേവ് ചെയ്ത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെടുകയും ചെയ്യും:

```py
from transformers import AutoModelForTokenClassification

model = AutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

[അധ്യായം 3](/course/chapter3)-ൽ നമ്മുടെ `AutoModelForSequenceClassification` നിർവചിച്ചപ്പോഴത്തേതുപോലെ, മോഡൽ ഉണ്ടാക്കുമ്പോൾ ചില വെയ്‌റ്റുകൾ ഉപയോഗിച്ചിട്ടില്ലെന്നും (പ്രീട്രെയിനിംഗ് ഹെഡിന്റേത്) മറ്റു ചില വെയ്‌റ്റുകൾ ക്രമരഹിതമായി ഇനിഷ്യലൈസ് ചെയ്യപ്പെട്ടിരിക്കുന്നു എന്നും (പുതിയ ടോക്കൺ ക്ലാസിഫിക്കേഷൻ ഹെഡിന്റേത്), ഈ മോഡൽ ട്രെയിൻ ചെയ്യണം എന്നും ഒരു മുന്നറിയിപ്പ് ലഭിക്കും. അത് നമ്മൾ ഉടൻ ചെയ്യും, എന്നാൽ ആദ്യം നമ്മുടെ മോഡലിന് ശരിയായ എണ്ണം ലേബലുകൾ ഉണ്ടെന്ന് ഒന്നുകൂടി ഉറപ്പാക്കാം:

```python
model.config.num_labels
```

```python out
9
```

> [!WARNING]
> ⚠️ തെറ്റായ എണ്ണം ലേബലുകളുള്ള ഒരു മോഡലാണ് നിങ്ങളുടേതെങ്കിൽ, പിന്നീട് `Trainer.train()` മെത്തേഡ് വിളിക്കുമ്പോൾ അവ്യക്തമായ ഒരു എറർ നിങ്ങൾക്ക് ലഭിക്കും ("CUDA error: device-side assert triggered" എന്നതുപോലെ എന്തെങ്കിലും). ഇത്തരം എററുകൾക്ക് ഉപയോക്താക്കൾ റിപ്പോർട്ട് ചെയ്യുന്ന ബഗുകളുടെ ഒന്നാമത്തെ കാരണം ഇതാണ്; അതിനാൽ പ്രതീക്ഷിക്കുന്ന എണ്ണം ലേബലുകൾ ഉണ്ടെന്ന് സ്ഥിരീകരിക്കാൻ ഈ പരിശോധന നിങ്ങൾ തീർച്ചയായും ചെയ്യുക.

### മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നു[[fine-tuning-the-model]]

ഇപ്പോൾ നമ്മുടെ മോഡൽ ട്രെയിൻ ചെയ്യാൻ നമ്മൾ തയ്യാറാണ്! നമ്മുടെ `Trainer` നിർവചിക്കുന്നതിന് മുമ്പ് അവസാനത്തെ രണ്ട് കാര്യങ്ങൾ മാത്രം ചെയ്യാനുണ്ട്: Hugging Face-ൽ ലോഗിൻ ചെയ്യുക, നമ്മുടെ ട്രെയിനിംഗ് ആർഗ്യുമെന്റുകൾ നിർവചിക്കുക. നിങ്ങൾ ഒരു നോട്ട്‌ബുക്കിലാണ് പ്രവർത്തിക്കുന്നതെങ്കിൽ, ഇതിന് നിങ്ങളെ സഹായിക്കുന്ന സൗകര്യപ്രദമായ ഒരു ഫംഗ്‌ഷൻ ഉണ്ട്:

```python
from huggingface_hub import notebook_login

notebook_login()
```

നിങ്ങളുടെ Hugging Face ലോഗിൻ വിവരങ്ങൾ (credentials) നൽകാവുന്ന ഒരു വിഡ്‌ജറ്റ് ഇത് കാണിക്കും.

നിങ്ങൾ ഒരു നോട്ട്‌ബുക്കിലല്ല പ്രവർത്തിക്കുന്നതെങ്കിൽ, നിങ്ങളുടെ ടെർമിനലിൽ താഴെയുള്ള വരി ടൈപ്പ് ചെയ്താൽ മതി:

```bash
huggingface-cli login
```

ഇത് പൂർത്തിയായാൽ, നമ്മുടെ `TrainingArguments` നിർവചിക്കാം:

```python
from transformers import TrainingArguments

args = TrainingArguments(
    "bert-finetuned-ner",
    evaluation_strategy="epoch",
    save_strategy="epoch",
    learning_rate=2e-5,
    num_train_epochs=3,
    weight_decay=0.01,
    push_to_hub=True,
)
```

ഇവയിൽ മിക്കതും നിങ്ങൾ മുമ്പ് കണ്ടിട്ടുണ്ട്: ചില ഹൈപ്പർപാരാമീറ്ററുകൾ (ലേണിംഗ് റേറ്റ്, ട്രെയിൻ ചെയ്യേണ്ട എപ്പോക്കുകളുടെ എണ്ണം, വെയ്‌റ്റ് ഡികേ എന്നിവ പോലുള്ളവ) നമ്മൾ സെറ്റ് ചെയ്യുന്നു; കൂടാതെ ഓരോ എപ്പോക്കിന്റെയും അവസാനം മോഡൽ സേവ് ചെയ്ത് ഇവാല്യുവേറ്റ് ചെയ്യണമെന്നും നമ്മുടെ ഫലങ്ങൾ Model Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യണമെന്നും സൂചിപ്പിക്കാൻ `push_to_hub=True` എന്ന് വ്യക്തമാക്കുന്നു. നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ പേര് `hub_model_id` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് വ്യക്തമാക്കാം എന്നത് ശ്രദ്ധിക്കുക (പ്രത്യേകിച്ച്, ഒരു ഓർഗനൈസേഷനിലേക്ക് പുഷ് ചെയ്യാൻ ഈ ആർഗ്യുമെന്റ് നിങ്ങൾ ഉപയോഗിക്കേണ്ടിവരും). ഉദാഹരണത്തിന്, [`huggingface-course` ഓർഗനൈസേഷനിലേക്ക്](https://huggingface.co/huggingface-course) മോഡൽ പുഷ് ചെയ്തപ്പോൾ, ഞങ്ങൾ `TrainingArguments`-ൽ `hub_model_id="huggingface-course/bert-finetuned-ner"` ചേർത്തു. ഡിഫോൾട്ടായി, ഉപയോഗിക്കുന്ന റിപ്പോസിറ്ററി നിങ്ങളുടെ നെയിംസ്‌പേസിലായിരിക്കും, നിങ്ങൾ സെറ്റ് ചെയ്ത ഔട്ട്‌പുട്ട് ഡയറക്ടറിയുടെ പേരിലായിരിക്കും അത്; അതിനാൽ നമ്മുടെ കാര്യത്തിൽ അത് `"sgugger/bert-finetuned-ner"` ആയിരിക്കും.

> [!TIP]
> 💡 നിങ്ങൾ ഉപയോഗിക്കുന്ന ഔട്ട്‌പുട്ട് ഡയറക്ടറി ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, അത് നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ലോക്കൽ ക്ലോൺ ആയിരിക്കണം. അല്ലെങ്കിൽ, നിങ്ങളുടെ `Trainer` നിർവചിക്കുമ്പോൾ ഒരു എറർ ലഭിക്കും, പുതിയ ഒരു പേര് സെറ്റ് ചെയ്യേണ്ടിവരും.

അവസാനമായി, എല്ലാം `Trainer`-ന് നൽകി ട്രെയിനിംഗ് ആരംഭിക്കുന്നു:

```python
from transformers import Trainer

trainer = Trainer(
    model=model,
    args=args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    compute_metrics=compute_metrics,
    processing_class=tokenizer,
)
trainer.train()
```

ട്രെയിനിംഗ് നടക്കുമ്പോൾ, ഓരോ തവണ മോഡൽ സേവ് ചെയ്യപ്പെടുമ്പോഴും (ഇവിടെ, ഓരോ എപ്പോക്കിലും) അത് പശ്ചാത്തലത്തിൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെടുന്നു എന്നത് ശ്രദ്ധിക്കുക. ഇങ്ങനെ, ആവശ്യമെങ്കിൽ മറ്റൊരു മെഷീനിൽ നിങ്ങളുടെ ട്രെയിനിംഗ് പുനരാരംഭിക്കാൻ നിങ്ങൾക്ക് കഴിയും.

ട്രെയിനിംഗ് പൂർത്തിയായിക്കഴിഞ്ഞാൽ, മോഡലിന്റെ ഏറ്റവും പുതിയ പതിപ്പ് അപ്‌ലോഡ് ചെയ്യുന്നു എന്ന് ഉറപ്പാക്കാൻ `push_to_hub()` മെത്തേഡ് നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
trainer.push_to_hub(commit_message="Training complete")
```

ഈ കമാൻഡ് അത് ഇപ്പോൾ ചെയ്ത കമ്മിറ്റിന്റെ URL റിട്ടേൺ ചെയ്യുന്നു; നിങ്ങൾക്ക് അത് പരിശോധിക്കണമെങ്കിൽ ഉപയോഗിക്കാം:

```python out
'https://huggingface.co/sgugger/bert-finetuned-ner/commit/26ab21e5b1568f9afeccdaed2d8715f571d786ed'
```

എല്ലാ ഇവാല്യുവേഷൻ ഫലങ്ങളോടും കൂടിയ ഒരു മോഡൽ കാർഡ് `Trainer` തയ്യാറാക്കി അപ്‌ലോഡ് ചെയ്യുകയും ചെയ്യുന്നു. ഈ ഘട്ടത്തിൽ, Model Hub-ലെ ഇൻഫറൻസ് വിഡ്‌ജറ്റ് ഉപയോഗിച്ച് നിങ്ങളുടെ മോഡൽ പരീക്ഷിക്കാനും സുഹൃത്തുക്കളുമായി പങ്കുവയ്ക്കാനും കഴിയും. ഒരു ടോക്കൺ ക്ലാസിഫിക്കേഷൻ ടാസ്‌കിൽ നിങ്ങൾ വിജയകരമായി ഒരു മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്തു — അഭിനന്ദനങ്ങൾ!

ട്രെയിനിംഗ് ലൂപ്പിലേക്ക് കുറച്ചുകൂടി ആഴത്തിൽ ഇറങ്ങണമെങ്കിൽ, 🤗 Accelerate ഉപയോഗിച്ച് ഇതേ കാര്യം എങ്ങനെ ചെയ്യാമെന്ന് ഇപ്പോൾ ഞങ്ങൾ കാണിച്ചുതരാം.

## ഒരു കസ്‌റ്റം ട്രെയിനിംഗ് ലൂപ്പ്[[a-custom-training-loop]]

ഇപ്പോൾ പൂർണ്ണമായ ട്രെയിനിംഗ് ലൂപ്പ് നോക്കാം, അങ്ങനെ നിങ്ങൾക്ക് ആവശ്യമുള്ള ഭാഗങ്ങൾ എളുപ്പത്തിൽ ഇഷ്ടാനുസൃതമാക്കാം. ഇവാല്യുവേഷനുള്ള ഏതാനും മാറ്റങ്ങളൊഴിച്ചാൽ, [അധ്യായം 3](/course/chapter3/4)-ൽ നമ്മൾ ചെയ്തതിനോട് ഇത് വളരെ സാമ്യമുള്ളതായിരിക്കും.

### ട്രെയിനിംഗിനായി എല്ലാം തയ്യാറാക്കുന്നു[[preparing-everything-for-training]]

ആദ്യം നമ്മുടെ ഡേറ്റാസെറ്റുകളിൽ നിന്ന് `DataLoader`-കൾ നിർമ്മിക്കണം. നമ്മുടെ `data_collator` ഒരു `collate_fn` ആയി വീണ്ടും ഉപയോഗിക്കുകയും ട്രെയിനിംഗ് സെറ്റ് ഷഫിൾ ചെയ്യുകയും ചെയ്യും, എന്നാൽ വാലിഡേഷൻ സെറ്റ് ഷഫിൾ ചെയ്യില്ല:

```py
from torch.utils.data import DataLoader

train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

അടുത്തതായി, മുമ്പത്തെ ഫൈൻ-ട്യൂണിംഗ് തുടരുകയല്ല, BERT പ്രീട്രെയിൻഡ് മോഡലിൽ നിന്ന് വീണ്ടും ആരംഭിക്കുകയാണ് എന്ന് ഉറപ്പാക്കാൻ, നമ്മുടെ മോഡൽ വീണ്ടും ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്നു:

```py
model = AutoModelForTokenClassification.from_pretrained(
    model_checkpoint,
    id2label=id2label,
    label2id=label2id,
)
```

പിന്നീട് നമുക്ക് ഒരു ഒപ്‌റ്റിമൈസർ വേണം. ക്ലാസിക് `AdamW` നമ്മൾ ഉപയോഗിക്കും; ഇത് `Adam` പോലെയാണ്, എന്നാൽ വെയ്‌റ്റ് ഡികേ പ്രയോഗിക്കുന്ന രീതിയിൽ ഒരു തിരുത്തലുണ്ട്:

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

ആ ഒബ്‌ജക്റ്റുകളെല്ലാം ലഭിച്ചുകഴിഞ്ഞാൽ, അവയെ `accelerator.prepare()` മെത്തേഡിലേക്ക് അയയ്ക്കാം:

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

> [!TIP]
> 🚨 നിങ്ങൾ ഒരു TPU-വിലാണ് ട്രെയിൻ ചെയ്യുന്നതെങ്കിൽ, മുകളിലെ സെല്ലിൽ നിന്ന് തുടങ്ങുന്ന എല്ലാ കോഡും ഒരു പ്രത്യേക ട്രെയിനിംഗ് ഫംഗ്‌ഷനിലേക്ക് മാറ്റേണ്ടിവരും. കൂടുതൽ വിവരങ്ങൾക്ക് [അധ്യായം 3](/course/chapter3) കാണുക.

നമ്മുടെ `train_dataloader` `accelerator.prepare()`-ലേക്ക് അയച്ചുകഴിഞ്ഞ സ്ഥിതിക്ക്, ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണം കണക്കാക്കാൻ അതിന്റെ നീളം ഉപയോഗിക്കാം. ഡേറ്റാലോഡർ പ്രിപ്പയർ ചെയ്ത ശേഷം മാത്രമേ ഇത് എപ്പോഴും ചെയ്യാവൂ എന്ന് ഓർക്കുക, കാരണം ആ മെത്തേഡ് അതിന്റെ നീളം മാറ്റും. ലേണിംഗ് റേറ്റിൽ നിന്ന് 0-ലേക്കുള്ള ക്ലാസിക് ലീനിയർ ഷെഡ്യൂൾ നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

അവസാനമായി, നമ്മുടെ മോഡൽ Hub-ലേക്ക് പുഷ് ചെയ്യാൻ, ഒരു വർക്കിംഗ് ഫോൾഡറിൽ ഒരു `Repository` ഒബ്‌ജക്റ്റ് ഉണ്ടാക്കേണ്ടതുണ്ട്. ഇതിനകം ലോഗിൻ ചെയ്തിട്ടില്ലെങ്കിൽ, ആദ്യം Hugging Face-ൽ ലോഗിൻ ചെയ്യുക. നമ്മുടെ മോഡലിന് നൽകാൻ ആഗ്രഹിക്കുന്ന മോഡൽ ID-യിൽ നിന്ന് റിപ്പോസിറ്ററിയുടെ പേര് നമ്മൾ നിർണ്ണയിക്കും (`repo_name` നിങ്ങളുടെ ഇഷ്ടപ്രകാരം മാറ്റാൻ മടിക്കേണ്ടതില്ല; അതിൽ നിങ്ങളുടെ യൂസർനെയിം ഉണ്ടായിരിക്കണം എന്ന് മാത്രം, `get_full_repo_name()` എന്ന ഫംഗ്‌ഷൻ ചെയ്യുന്നത് അതാണ്):

```py
from huggingface_hub import Repository, get_full_repo_name

model_name = "bert-finetuned-ner-accelerate"
repo_name = get_full_repo_name(model_name)
repo_name
```

```python out
'sgugger/bert-finetuned-ner-accelerate'
```

പിന്നീട് ആ റിപ്പോസിറ്ററി ഒരു ലോക്കൽ ഫോൾഡറിലേക്ക് ക്ലോൺ ചെയ്യാം. അത് ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, ഈ ലോക്കൽ ഫോൾഡർ നമ്മൾ പ്രവർത്തിക്കുന്ന റിപ്പോസിറ്ററിയുടെ നിലവിലുള്ള ഒരു ക്ലോൺ ആയിരിക്കണം:

```py
output_dir = "bert-finetuned-ner-accelerate"
repo = Repository(output_dir, clone_from=repo_name)
```

`repo.push_to_hub()` മെത്തേഡ് വിളിച്ചുകൊണ്ട്, `output_dir`-ൽ നമ്മൾ സേവ് ചെയ്യുന്ന എന്തും ഇപ്പോൾ അപ്‌ലോഡ് ചെയ്യാം. ഓരോ എപ്പോക്കിന്റെയും അവസാനം ഇടക്കാല മോഡലുകൾ അപ്‌ലോഡ് ചെയ്യാൻ ഇത് നമ്മളെ സഹായിക്കും.

### ട്രെയിനിംഗ് ലൂപ്പ്[[training-loop]]

ഇപ്പോൾ പൂർണ്ണമായ ട്രെയിനിംഗ് ലൂപ്പ് എഴുതാൻ നമ്മൾ തയ്യാറാണ്. അതിന്റെ ഇവാല്യുവേഷൻ ഭാഗം ലളിതമാക്കാൻ, പ്രവചനങ്ങളും ലേബലുകളും സ്വീകരിച്ച്, നമ്മുടെ `metric` ഒബ്‌ജക്റ്റ് പ്രതീക്ഷിക്കുന്നതുപോലെ അവയെ സ്‌ട്രിംഗുകളുടെ ലിസ്‌റ്റുകളാക്കി മാറ്റുന്ന ഈ `postprocess()` ഫംഗ്‌ഷൻ നമ്മൾ നിർവചിക്കുന്നു:

```py
def postprocess(predictions, labels):
    predictions = predictions.detach().cpu().clone().numpy()
    labels = labels.detach().cpu().clone().numpy()

    # Remove ignored index (special tokens) and convert to labels
    true_labels = [[label_names[l] for l in label if l != -100] for label in labels]
    true_predictions = [
        [label_names[p] for (p, l) in zip(prediction, label) if l != -100]
        for prediction, label in zip(predictions, labels)
    ]
    return true_labels, true_predictions
```

പിന്നീട് ട്രെയിനിംഗ് ലൂപ്പ് എഴുതാം. ട്രെയിനിംഗ് എങ്ങനെ പുരോഗമിക്കുന്നു എന്ന് പിന്തുടരാൻ ഒരു പ്രോഗ്രസ് ബാർ നിർവചിച്ച ശേഷം, ലൂപ്പിന് മൂന്ന് ഭാഗങ്ങളുണ്ട്:

- ട്രെയിനിംഗ് തന്നെ; ഇത് `train_dataloader`-ലൂടെയുള്ള ക്ലാസിക് ഇറ്ററേഷനാണ്: മോഡലിലൂടെയുള്ള ഫോർവേഡ് പാസ്, പിന്നീട് ബാക്ക്‌വേഡ് പാസും ഒപ്‌റ്റിമൈസർ സ്‌റ്റെപ്പും.
- ഇവാല്യുവേഷൻ; ഇതിൽ ഒരു ബാച്ചിലെ നമ്മുടെ മോഡലിന്റെ ഔട്ട്‌പുട്ടുകൾ ലഭിച്ച ശേഷം ഒരു പുതുമയുണ്ട്: രണ്ട് പ്രോസസ്സുകൾ ഇൻപുട്ടുകളും ലേബലുകളും വ്യത്യസ്ത ഷേപ്പുകളിലേക്ക് പാഡ് ചെയ്തിരിക്കാം എന്നതിനാൽ, `gather()` മെത്തേഡ് വിളിക്കുന്നതിന് മുമ്പ് പ്രവചനങ്ങളെയും ലേബലുകളെയും ഒരേ ഷേപ്പിലാക്കാൻ `accelerator.pad_across_processes()` നമ്മൾ ഉപയോഗിക്കണം. ഇത് ചെയ്തില്ലെങ്കിൽ, ഇവാല്യുവേഷൻ ഒന്നുകിൽ എറർ നൽകും, അല്ലെങ്കിൽ എന്നെന്നേക്കുമായി തടഞ്ഞുനിൽക്കും (hang). പിന്നീട് ഫലങ്ങൾ `metric.add_batch()`-ലേക്ക് അയയ്ക്കുകയും, ഇവാല്യുവേഷൻ ലൂപ്പ് കഴിഞ്ഞാൽ `metric.compute()` വിളിക്കുകയും ചെയ്യുന്നു.
- സേവ് ചെയ്യലും അപ്‌ലോഡ് ചെയ്യലും; ഇവിടെ ആദ്യം മോഡലും ടോക്കണൈസറും സേവ് ചെയ്ത്, പിന്നീട് `repo.push_to_hub()` വിളിക്കുന്നു. ഒരു അസിൻക്രണസ് (asynchronous) പ്രോസസ്സിൽ പുഷ് ചെയ്യാൻ 🤗 Hub ലൈബ്രറിയോട് പറയാൻ `blocking=False` എന്ന ആർഗ്യുമെന്റ് നമ്മൾ ഉപയോഗിക്കുന്നത് ശ്രദ്ധിക്കുക. ഇങ്ങനെ, ട്രെയിനിംഗ് സാധാരണപോലെ തുടരുകയും ഈ (ദൈർഘ്യമേറിയ) നിർദ്ദേശം പശ്ചാത്തലത്തിൽ എക്‌സിക്യൂട്ട് ചെയ്യപ്പെടുകയും ചെയ്യുന്നു.

ട്രെയിനിംഗ് ലൂപ്പിന്റെ പൂർണ്ണമായ കോഡ് ഇതാ:

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # Training
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # Evaluation
    model.eval()
    for batch in eval_dataloader:
        with torch.no_grad():
            outputs = model(**batch)

        predictions = outputs.logits.argmax(dim=-1)
        labels = batch["labels"]

        # Necessary to pad predictions and labels for being gathered
        predictions = accelerator.pad_across_processes(predictions, dim=1, pad_index=-100)
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(predictions)
        labels_gathered = accelerator.gather(labels)

        true_predictions, true_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=true_predictions, references=true_labels)

    results = metric.compute()
    print(
        f"epoch {epoch}:",
        {
            key: results[f"overall_{key}"]
            for key in ["precision", "recall", "f1", "accuracy"]
        },
    )

    # Save and upload
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

🤗 Accelerate ഉപയോഗിച്ച് സേവ് ചെയ്ത ഒരു മോഡൽ നിങ്ങൾ ആദ്യമായി കാണുന്നതാണെങ്കിൽ, അതിനോടൊപ്പമുള്ള മൂന്ന് വരി കോഡ് ഒരു നിമിഷം പരിശോധിക്കാം:

```py
accelerator.wait_for_everyone()
unwrapped_model = accelerator.unwrap_model(model)
unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
```

ആദ്യത്തെ വരി സ്വയം വ്യക്തമാണ്: തുടരുന്നതിന് മുമ്പ് എല്ലാവരും ആ ഘട്ടത്തിൽ എത്തുന്നതുവരെ കാത്തിരിക്കാൻ ഇത് എല്ലാ പ്രോസസ്സുകളോടും പറയുന്നു. സേവ് ചെയ്യുന്നതിന് മുമ്പ് എല്ലാ പ്രോസസ്സിലും ഒരേ മോഡൽ ഉണ്ടെന്ന് ഉറപ്പാക്കാനാണ് ഇത്. പിന്നീട് നമ്മൾ നിർവചിച്ച ബേസ് മോഡലായ `unwrapped_model` നമ്മൾ എടുക്കുന്നു. `accelerator.prepare()` മെത്തേഡ് ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗിൽ പ്രവർത്തിക്കാൻ മോഡലിനെ മാറ്റുന്നു, അതിനാൽ അതിന് ഇനി `save_pretrained()` മെത്തേഡ് ഉണ്ടാകില്ല; `accelerator.unwrap_model()` മെത്തേഡ് ആ ഘട്ടം പഴയപടിയാക്കുന്നു. അവസാനമായി, നമ്മൾ `save_pretrained()` വിളിക്കുന്നു, എന്നാൽ `torch.save()`-ന് പകരം `accelerator.save()` ഉപയോഗിക്കാൻ ആ മെത്തേഡിനോട് പറയുന്നു.

ഇത് പൂർത്തിയായാൽ, `Trainer` ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്തതിനോട് ഏറെക്കുറെ സമാനമായ ഫലങ്ങൾ നൽകുന്ന ഒരു മോഡൽ നിങ്ങൾക്ക് ഉണ്ടായിരിക്കണം. ഈ കോഡ് ഉപയോഗിച്ച് ഞങ്ങൾ ട്രെയിൻ ചെയ്ത മോഡൽ [*huggingface-course/bert-finetuned-ner-accelerate*](https://huggingface.co/huggingface-course/bert-finetuned-ner-accelerate)-ൽ നിങ്ങൾക്ക് പരിശോധിക്കാം. ട്രെയിനിംഗ് ലൂപ്പിൽ എന്തെങ്കിലും മാറ്റങ്ങൾ പരീക്ഷിക്കണമെങ്കിൽ, മുകളിൽ കാണിച്ച കോഡ് എഡിറ്റ് ചെയ്ത് നേരിട്ട് അവ നടപ്പിലാക്കാം!

## ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ ഉപയോഗിക്കുന്നു[[using-the-fine-tuned-model]]

നമ്മൾ ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ Model Hub-ലെ ഇൻഫറൻസ് വിഡ്‌ജറ്റ് ഉപയോഗിച്ച് എങ്ങനെ ഉപയോഗിക്കാമെന്ന് ഞങ്ങൾ ഇതിനകം കാണിച്ചുതന്നിട്ടുണ്ട്. ഒരു `pipeline`-ൽ ഇത് ലോക്കലായി ഉപയോഗിക്കാൻ, ശരിയായ മോഡൽ ഐഡന്റിഫയർ വ്യക്തമാക്കിയാൽ മാത്രം മതി:

```py
from transformers import pipeline

# Replace this with your own checkpoint
model_checkpoint = "huggingface-course/bert-finetuned-ner"
token_classifier = pipeline(
    "token-classification", model=model_checkpoint, aggregation_strategy="simple"
)
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```
