ഇനി ചോദ്യോത്തരത്തിലേക്ക് (question answering) കടക്കാം! ഈ ടാസ്‌ക്ക് പല രൂപങ്ങളിൽ വരുന്നുണ്ട്, എന്നാൽ ഈ ഭാഗത്തിൽ നമ്മൾ ശ്രദ്ധ കേന്ദ്രീകരിക്കുന്നത് *എക്‌സ്‌ട്രാക്റ്റീവ്* (extractive) ചോദ്യോത്തരം എന്ന് വിളിക്കുന്ന തരത്തിലാണ്. ഒരു ഡോക്യുമെന്റിനെക്കുറിച്ച് ചോദ്യങ്ങൾ ചോദിക്കുകയും, ആ ഡോക്യുമെന്റിനുള്ളിലെ _ടെക്‌സ്‌റ്റ് സ്‌പാനുകളായി_ (spans of text) ഉത്തരങ്ങൾ കണ്ടെത്തുകയും ചെയ്യുന്നതാണ് ഇതിൽ ഉൾപ്പെടുന്നത്.

ഈ ഭാഗത്തിൽ കാണിച്ചിരിക്കുന്ന കോഡ് ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്ത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്ത മോഡലാണ് ഇവിടെ യഥാർത്ഥത്തിൽ പ്രദർശിപ്പിക്കുന്നത്. അത് [ഇവിടെ](https://huggingface.co/huggingface-course/bert-finetuned-squad?context=%F0%9F%A4%97+Transformers+is+backed+by+the+three+most+popular+deep+learning+libraries+%E2%80%94+Jax%2C+PyTorch+and+TensorFlow+%E2%80%94+with+a+seamless+integration+between+them.+It%27s+straightforward+to+train+your+models+with+one+before+loading+them+for+inference+with+the+other.&question=Which+deep+learning+libraries+back+%F0%9F%A4%97+Transformers%3F) കണ്ടെത്താനും പ്രവചനങ്ങൾ ഒന്നുകൂടി പരിശോധിക്കാനും നിങ്ങൾക്ക് കഴിയും.

> [!TIP]
> 💡 BERT പോലുള്ള എൻകോഡർ-ഒൺലി (encoder-only) മോഡലുകൾ "Who invented the Transformer architecture?" പോലുള്ള വസ്തുതാപരമായ (factoid) ചോദ്യങ്ങൾക്ക് ഉത്തരങ്ങൾ എക്‌സ്‌ട്രാക്റ്റ് ചെയ്യുന്നതിൽ മികച്ചതായിരിക്കും, എന്നാൽ "Why is the sky blue?" പോലുള്ള തുറന്ന (open-ended) ചോദ്യങ്ങൾ നൽകുമ്പോൾ മോശമായി പ്രവർത്തിക്കും. കൂടുതൽ വെല്ലുവിളി നിറഞ്ഞ ഇത്തരം സന്ദർഭങ്ങളിൽ, [ടെക്‌സ്‌റ്റ് സമ്മറൈസേഷനോട്](/course/chapter7/5) ഏറെ സാമ്യമുള്ള രീതിയിൽ വിവരങ്ങൾ സംയോജിപ്പിക്കാൻ (synthesize) T5, BART പോലുള്ള എൻകോഡർ-ഡീകോഡർ മോഡലുകളാണ് സാധാരണയായി ഉപയോഗിക്കുന്നത്. ഇത്തരം *ജനറേറ്റീവ്* (generative) ചോദ്യോത്തരത്തിൽ നിങ്ങൾക്ക് താൽപ്പര്യമുണ്ടെങ്കിൽ, ഞങ്ങളുടെ [ഡെമോ](https://yjernite.github.io/lfqa.html) പരിശോധിക്കാൻ ഞങ്ങൾ ശുപാർശ ചെയ്യുന്നു; അത് [ELI5 ഡേറ്റാസെറ്റ്](https://huggingface.co/datasets/eli5) അടിസ്ഥാനമാക്കിയുള്ളതാണ്.

## ഡേറ്റ തയ്യാറാക്കുന്നു[[preparing-the-data]]

എക്‌സ്‌ട്രാക്റ്റീവ് ചോദ്യോത്തരത്തിനുള്ള അക്കാദമിക് ബെഞ്ച്‌മാർക്കായി ഏറ്റവുമധികം ഉപയോഗിക്കുന്ന ഡേറ്റാസെറ്റ് [SQuAD](https://rajpurkar.github.io/SQuAD-explorer/) ആണ്, അതിനാൽ അതാണ് നമ്മൾ ഇവിടെ ഉപയോഗിക്കുന്നത്. ഉത്തരമില്ലാത്ത ചോദ്യങ്ങളും ഉൾപ്പെടുന്ന, കൂടുതൽ കഠിനമായ ഒരു [SQuAD v2](https://huggingface.co/datasets/squad_v2) ബെഞ്ച്‌മാർക്കും ഉണ്ട്. നിങ്ങളുടെ സ്വന്തം ഡേറ്റാസെറ്റിൽ കോൺടെക്‌സ്‌റ്റുകൾക്ക് (contexts) ഒരു കോളവും, ചോദ്യങ്ങൾക്ക് ഒരു കോളവും, ഉത്തരങ്ങൾക്ക് ഒരു കോളവും ഉണ്ടെങ്കിൽ, താഴെയുള്ള ഘട്ടങ്ങൾ നിങ്ങൾക്ക് അതിനനുസരിച്ച് മാറ്റിയെടുക്കാൻ കഴിയേണ്ടതാണ്.

### SQuAD ഡേറ്റാസെറ്റ്[[the-squad-dataset]]

പതിവുപോലെ, `load_dataset()`-ന്റെ സഹായത്തോടെ ഒരൊറ്റ ഘട്ടത്തിൽ ഡേറ്റാസെറ്റ് ഡൗൺലോഡ് ചെയ്ത് കാഷ് (cache) ചെയ്യാം:

```py
from datasets import load_dataset

raw_datasets = load_dataset("squad")
```

SQuAD ഡേറ്റാസെറ്റിനെക്കുറിച്ച് കൂടുതൽ അറിയാൻ ഈ ഒബ്‌ജക്റ്റ് നമുക്ക് ഒന്ന് നോക്കാം:

```py
raw_datasets
```

```python out
DatasetDict({
    train: Dataset({
        features: ['id', 'title', 'context', 'question', 'answers'],
        num_rows: 87599
    })
    validation: Dataset({
        features: ['id', 'title', 'context', 'question', 'answers'],
        num_rows: 10570
    })
})
```

`context`, `question`, `answers` എന്നീ ഫീൽഡുകളോടെ നമുക്ക് ആവശ്യമുള്ളതെല്ലാം ഉണ്ടെന്ന് തോന്നുന്നു, അതിനാൽ നമ്മുടെ ട്രെയിനിംഗ് സെറ്റിലെ ആദ്യ എലമെന്റിന്റെ ആ ഫീൽഡുകൾ പ്രിന്റ് ചെയ്ത് നോക്കാം:

```py
print("Context: ", raw_datasets["train"][0]["context"])
print("Question: ", raw_datasets["train"][0]["question"])
print("Answer: ", raw_datasets["train"][0]["answers"])
```

`context`, `question` എന്നീ ഫീൽഡുകൾ ഉപയോഗിക്കാൻ വളരെ എളുപ്പമാണ്. `answers` ഫീൽഡ് അൽപ്പം കൂടുതൽ സങ്കീർണ്ണമാണ്, കാരണം അതിൽ രണ്ട് ഫീൽഡുകളുള്ള ഒരു ഡിക്‌ഷണറിയാണ് ഉള്ളത്, രണ്ടും ലിസ്‌റ്റുകളാണ്. ഇവാല്യുവേഷൻ സമയത്ത് `squad` മെട്രിക് പ്രതീക്ഷിക്കുന്ന ഫോർമാറ്റാണിത്; നിങ്ങളുടെ സ്വന്തം ഡേറ്റയാണ് ഉപയോഗിക്കുന്നതെങ്കിൽ, ഉത്തരങ്ങൾ ഇതേ ഫോർമാറ്റിൽ ആക്കുന്നതിനെക്കുറിച്ച് നിങ്ങൾ വിഷമിക്കേണ്ട ആവശ്യമില്ല. `text` ഫീൽഡ് വളരെ വ്യക്തമാണ്, `answer_start` ഫീൽഡിൽ കോൺടെക്‌സ്‌റ്റിലെ ഓരോ ഉത്തരത്തിന്റെയും ആരംഭ ക്യാരക്റ്റർ ഇൻഡെക്‌സ് (starting character index) അടങ്ങിയിരിക്കുന്നു.

ട്രെയിനിംഗ് സമയത്ത്, സാധ്യമായ ഒരേയൊരു ഉത്തരം മാത്രമേയുള്ളൂ. `Dataset.filter()` മെത്തേഡ് ഉപയോഗിച്ച് ഇത് നമുക്ക് ഒന്നുകൂടി ഉറപ്പാക്കാം:

```py
raw_datasets["train"].filter(lambda x: len(x["answers"]["text"]) != 1)
```

```python out
Dataset({
    features: ['id', 'title', 'context', 'question', 'answers'],
    num_rows: 0
})
```

```py
print(raw_datasets["validation"][0]["answers"])
```

```py
print(raw_datasets["validation"][2]["context"])
```

### ട്രെയിനിംഗ് ഡേറ്റ പ്രോസസ്സ് ചെയ്യുന്നു[[processing-the-training-data]]

<Youtube id="qgaM0weJHpA"/>

ട്രെയിനിംഗ് ഡേറ്റ പ്രീപ്രോസസ്സ് ചെയ്യുന്നതിൽ നിന്ന് തുടങ്ങാം. ചോദ്യത്തിന്റെ ഉത്തരത്തിനുള്ള ലേബലുകൾ ഉണ്ടാക്കുന്നതായിരിക്കും ബുദ്ധിമുട്ടുള്ള ഭാഗം; കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ ഉത്തരത്തിന് അനുയോജ്യമായ ടോക്കണുകളുടെ ആരംഭ, അവസാന സ്ഥാനങ്ങളായിരിക്കും (start and end positions) ഈ ലേബലുകൾ.

എന്നാൽ നമുക്ക് അധികം മുന്നോട്ട് ചാടേണ്ട. ആദ്യം, ഒരു ടോക്കണൈസർ ഉപയോഗിച്ച് ഇൻപുട്ടിലെ ടെക്‌സ്‌റ്റിനെ മോഡലിന് മനസ്സിലാക്കാൻ കഴിയുന്ന ID-കളാക്കി മാറ്റണം:

```py
from transformers import AutoTokenizer

model_checkpoint = "bert-base-cased"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

ഇപ്പോഴത്തെ ഉദാഹരണം ഉപയോഗിച്ച് ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്ന് കാണാൻ, ദൈർഘ്യം 100-ലേക്ക് പരിമിതപ്പെടുത്തി 50 ടോക്കണുകളുടെ ഒരു സ്ലൈഡിംഗ് വിൻഡോ ഉപയോഗിക്കാം. ഓർമ്മപ്പെടുത്തലായി, നമ്മൾ ഉപയോഗിക്കുന്നത്:

- പരമാവധി ദൈർഘ്യം സെറ്റ് ചെയ്യാൻ `max_length` (ഇവിടെ 100)
- ചോദ്യവും അതിന്റെ കോൺടെക്‌സ്‌റ്റും ചേർന്ന് വളരെ നീണ്ടതാകുമ്പോൾ കോൺടെക്‌സ്‌റ്റ് (രണ്ടാം സ്ഥാനത്തുള്ളത്) ട്രങ്കേറ്റ് ചെയ്യാൻ `truncation="only_second"`
- തുടർച്ചയായ രണ്ട് ചങ്കുകൾക്കിടയിൽ (chunks) ഓവർലാപ്പ് ചെയ്യുന്ന ടോക്കണുകളുടെ എണ്ണം സെറ്റ് ചെയ്യാൻ `stride` (ഇവിടെ 50)
- ഓവർഫ്ലോ ചെയ്യുന്ന ടോക്കണുകൾ നമുക്ക് വേണമെന്ന് ടോക്കണൈസറിനെ അറിയിക്കാൻ `return_overflowing_tokens=True`

```py
inputs = tokenizer(
    question,
    context,
    max_length=100,

    stride=50,
    return_overflowing_tokens=True,

for ids in inputs["input_ids"]:
```

നമുക്ക് കാണാവുന്നതുപോലെ, ആദ്യത്തെ മൂന്ന് ഉദാഹരണങ്ങൾ (ട്രെയിനിംഗ് സെറ്റിലെ ഇൻഡെക്‌സ് 2, 3, 4 എന്നിവയിലുള്ളവ) ഓരോന്നും നാല് ഫീച്ചറുകൾ വീതം നൽകി, അവസാനത്തെ ഉദാഹരണം (ട്രെയിനിംഗ് സെറ്റിലെ ഇൻഡെക്‌സ് 5-ലുള്ളത്) 7 ഫീച്ചറുകൾ നൽകി.

നമുക്ക് ലഭിക്കുന്ന ഓരോ ഫീച്ചറിനെയും അതിന്റെ ലേബലുമായി ബന്ധിപ്പിക്കാൻ ഈ വിവരം ഉപകാരപ്പെടും. മുമ്പ് സൂചിപ്പിച്ചതുപോലെ, ആ ലേബലുകൾ ഇവയാണ്:

- കോൺടെക്‌സ്‌റ്റിന്റെ അനുബന്ധ സ്‌പാനിൽ ഉത്തരം ഇല്ലെങ്കിൽ `(0, 0)`
- കോൺടെക്‌സ്‌റ്റിന്റെ അനുബന്ധ സ്‌പാനിൽ ഉത്തരം ഉണ്ടെങ്കിൽ `(start_position, end_position)`; ഇവിടെ `start_position` എന്നത് ഉത്തരത്തിന്റെ ആരംഭത്തിലുള്ള ടോക്കണിന്റെ (ഇൻപുട്ട് ID-കളിലെ) ഇൻഡെക്‌സും `end_position` എന്നത് ഉത്തരം അവസാനിക്കുന്ന ടോക്കണിന്റെ (ഇൻപുട്ട് ID-കളിലെ) ഇൻഡെക്‌സുമാണ്

ഇവയിൽ ഏതാണ് ബാധകമെന്നും, ബാധകമെങ്കിൽ ടോക്കണുകളുടെ സ്ഥാനങ്ങളും നിർണ്ണയിക്കാൻ, ഇൻപുട്ട് ID-കളിൽ കോൺടെക്‌സ്‌റ്റ് ആരംഭിക്കുന്നതും അവസാനിക്കുന്നതുമായ ഇൻഡെക്‌സുകൾ നമ്മൾ ആദ്യം കണ്ടെത്തുന്നു. ഇതിനായി ടോക്കൺ ടൈപ്പ് ID-കൾ ഉപയോഗിക്കാമായിരുന്നു, എന്നാൽ അവ എല്ലാ മോഡലുകൾക്കും ഉണ്ടാകണമെന്നില്ല എന്നതിനാൽ (ഉദാഹരണത്തിന്, DistilBERT-ന് അവ ആവശ്യമില്ല), പകരം നമ്മുടെ ടോക്കണൈസർ റിട്ടേൺ ചെയ്യുന്ന `BatchEncoding`-ന്റെ `sequence_ids()` മെത്തേഡ് നമ്മൾ ഉപയോഗിക്കും.

ആ ടോക്കൺ ഇൻഡെക്‌സുകൾ ലഭിച്ചുകഴിഞ്ഞാൽ, അവയ്ക്ക് അനുബന്ധമായ ഓഫ്‌സെറ്റുകൾ നമ്മൾ നോക്കുന്നു; യഥാർത്ഥ കോൺടെക്‌സ്‌റ്റിനുള്ളിലെ ക്യാരക്റ്ററുകളുടെ സ്‌പാൻ സൂചിപ്പിക്കുന്ന രണ്ട് ഇന്റിജറുകളുടെ ട്യൂപ്പിളുകളാണ് ഇവ. അങ്ങനെ, ഈ ഫീച്ചറിലെ കോൺടെക്‌സ്‌റ്റിന്റെ ചങ്ക് ഉത്തരത്തിന് ശേഷമാണോ ആരംഭിക്കുന്നത്, അല്ലെങ്കിൽ ഉത്തരം തുടങ്ങുന്നതിന് മുമ്പാണോ അവസാനിക്കുന്നത് എന്ന് നമുക്ക് കണ്ടെത്താം (അങ്ങനെയാണെങ്കിൽ ലേബൽ `(0, 0)` ആണ്). അങ്ങനെയല്ലെങ്കിൽ, ഉത്തരത്തിന്റെ ആദ്യത്തെയും അവസാനത്തെയും ടോക്കൺ കണ്ടെത്താൻ നമ്മൾ ലൂപ്പ് ചെയ്യുന്നു:

```py
answers = raw_datasets["train"][2:6]["answers"]
start_positions = []
end_positions = []

for i, offset in enumerate(inputs["offset_mapping"]):
    sample_idx = inputs["overflow_to_sample_mapping"][i]
    answer = answers[sample_idx]
    start_char = answer["answer_start"][0]
    end_char = answer["answer_start"][0] + len(answer["text"][0])
    sequence_ids = inputs.sequence_ids(i)

    # Find the start and end of the context
    idx = 0
    while sequence_ids[idx] != 1:
        idx += 1
    context_start = idx
    while sequence_ids[idx] == 1:
        idx += 1
    context_end = idx - 1

    # If the answer is not fully inside the context, label is (0, 0)
    if offset[context_start][0] > start_char or offset[context_end][1] < end_char:
        start_positions.append(0)
        end_positions.append(0)
    else:
        # Otherwise it's the start and end token positions
        idx = context_start
        while idx <= context_end and offset[idx][0] <= start_char:
            idx += 1
        start_positions.append(idx - 1)

        idx = context_end
        while idx >= context_start and offset[idx][1] >= end_char:
            idx -= 1
        end_positions.append(idx + 1)

start_positions, end_positions
```

തീർച്ചയായും, കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ ഉത്തരം നമ്മൾ കാണുന്നില്ല.

> [!TIP]
> ✏️ **നിങ്ങളുടെ ഊഴം!** XLNet ആർക്കിടെക്ചർ ഉപയോഗിക്കുമ്പോൾ, പാഡിംഗ് ഇടതുവശത്താണ് പ്രയോഗിക്കുന്നത്, കൂടാതെ ചോദ്യവും കോൺടെക്‌സ്‌റ്റും പരസ്പരം സ്ഥാനം മാറുന്നു. നമ്മൾ ഇപ്പോൾ കണ്ട എല്ലാ കോഡും XLNet ആർക്കിടെക്ചറിന് അനുയോജ്യമായി മാറ്റുക (`padding=True` കൂടി ചേർക്കുക). പാഡിംഗ് പ്രയോഗിക്കുമ്പോൾ `[CLS]` ടോക്കൺ 0 എന്ന സ്ഥാനത്തായിരിക്കണമെന്നില്ല എന്നത് ഓർമ്മിക്കുക.

നമ്മുടെ ട്രെയിനിംഗ് ഡേറ്റ എങ്ങനെ പ്രീപ്രോസസ്സ് ചെയ്യാമെന്ന് ഘട്ടം ഘട്ടമായി കണ്ടുകഴിഞ്ഞതിനാൽ, മുഴുവൻ ട്രെയിനിംഗ് ഡേറ്റാസെറ്റിലും പ്രയോഗിക്കാവുന്ന ഒരു ഫംഗ്‌ഷനിൽ ഇത് ഒരുമിച്ച് ചേർക്കാം. ഓരോ ഫീച്ചറും നമ്മൾ സെറ്റ് ചെയ്ത പരമാവധി ദൈർഘ്യത്തിലേക്ക് പാഡ് ചെയ്യും, കാരണം മിക്ക കോൺടെക്‌സ്‌റ്റുകളും നീണ്ടതായിരിക്കും (അവയ്ക്ക് അനുബന്ധമായ സാമ്പിളുകൾ ഒന്നിലധികം ഫീച്ചറുകളായി വിഭജിക്കപ്പെടും), അതിനാൽ ഇവിടെ ഡൈനാമിക് പാഡിംഗ് പ്രയോഗിക്കുന്നതിൽ യഥാർത്ഥ പ്രയോജനമൊന്നുമില്ല:

```py
max_length = 384
stride = 128


def preprocess_training_examples(examples):
    questions = [q.strip() for q in examples["question"]]
    inputs = tokenizer(
        questions,
        examples["context"],
        max_length=max_length,
        truncation="only_second",
        stride=stride,
        return_overflowing_tokens=True,
        return_offsets_mapping=True,
        padding="max_length",
    )

    offset_mapping = inputs.pop("offset_mapping")
    sample_map = inputs.pop("overflow_to_sample_mapping")
    answers = examples["answers"]
    start_positions = []
    end_positions = []

    for i, offset in enumerate(offset_mapping):
        sample_idx = sample_map[i]
        answer = answers[sample_idx]
        start_char = answer["answer_start"][0]
        end_char = answer["answer_start"][0] + len(answer["text"][0])
        sequence_ids = inputs.sequence_ids(i)

        # Find the start and end of the context
        idx = 0
        while sequence_ids[idx] != 1:
            idx += 1
        context_start = idx
        while sequence_ids[idx] == 1:
            idx += 1
        context_end = idx - 1

        # If the answer is not fully inside the context, label is (0, 0)
        if offset[context_start][0] > start_char or offset[context_end][1] < end_char:
            start_positions.append(0)
            end_positions.append(0)
        else:
            # Otherwise it's the start and end token positions
            idx = context_start
            while idx <= context_end and offset[idx][0] <= start_char:
                idx += 1
            start_positions.append(idx - 1)

            idx = context_end
            while idx >= context_start and offset[idx][1] >= end_char:
                idx -= 1
            end_positions.append(idx + 1)

    inputs["start_positions"] = start_positions
    inputs["end_positions"] = end_positions
    return inputs
```

ഉപയോഗിക്കുന്ന പരമാവധി ദൈർഘ്യവും സ്ലൈഡിംഗ് വിൻഡോയുടെ ദൈർഘ്യവും നിർണ്ണയിക്കാൻ നമ്മൾ രണ്ട് കോൺസ്‌റ്റന്റുകൾ നിർവചിച്ചെന്നും, ടോക്കണൈസ് ചെയ്യുന്നതിന് മുമ്പ് ഒരു ചെറിയ ക്ലീനപ്പ് ചേർത്തെന്നും ശ്രദ്ധിക്കുക: SQuAD ഡേറ്റാസെറ്റിലെ ചില ചോദ്യങ്ങളുടെ തുടക്കത്തിലും അവസാനത്തിലും ഒന്നും കൂട്ടിച്ചേർക്കാത്ത അധിക സ്‌പേസുകളുണ്ട് (RoBERTa പോലുള്ള ഒരു മോഡൽ ഉപയോഗിക്കുകയാണെങ്കിൽ ടോക്കണൈസ് ചെയ്യുമ്പോൾ അവ സ്ഥലം അപഹരിക്കുകയും ചെയ്യും), അതിനാൽ ആ അധിക സ്‌പേസുകൾ നമ്മൾ നീക്കം ചെയ്തു.

ഈ ഫംഗ്‌ഷൻ മുഴുവൻ ട്രെയിനിംഗ് സെറ്റിലും പ്രയോഗിക്കാൻ, `batched=True` ഫ്ലാഗോടെ `Dataset.map()` മെത്തേഡ് നമ്മൾ ഉപയോഗിക്കുന്നു. ഡേറ്റാസെറ്റിന്റെ ദൈർഘ്യം നമ്മൾ മാറ്റുന്നതിനാൽ (ഒരു ഉദാഹരണത്തിൽ നിന്ന് ഒന്നിലധികം ട്രെയിനിംഗ് ഫീച്ചറുകൾ ലഭിക്കാം എന്നതിനാൽ) ഇത് ഇവിടെ അത്യാവശ്യമാണ്:

```py
train_dataset = raw_datasets["train"].map(
    preprocess_training_examples,
    batched=True,
    remove_columns=raw_datasets["train"].column_names,
)
len(raw_datasets["train"]), len(train_dataset)
```

നമുക്ക് കാണാവുന്നതുപോലെ, പ്രീപ്രോസസ്സിംഗ് ഏകദേശം 1,000 ഫീച്ചറുകൾ കൂട്ടിച്ചേർത്തു. നമ്മുടെ ട്രെയിനിംഗ് സെറ്റ് ഇപ്പോൾ ഉപയോഗിക്കാൻ തയ്യാറാണ് -- ഇനി വാലിഡേഷൻ സെറ്റിന്റെ പ്രീപ്രോസസ്സിംഗിലേക്ക് കടക്കാം!

### വാലിഡേഷൻ ഡേറ്റ പ്രോസസ്സ് ചെയ്യുന്നു[[processing-the-validation-data]]

വാലിഡേഷൻ ഡേറ്റ പ്രീപ്രോസസ്സ് ചെയ്യുന്നത് അൽപ്പം കൂടുതൽ എളുപ്പമായിരിക്കും, കാരണം നമുക്ക് ലേബലുകൾ ഉണ്ടാക്കേണ്ട ആവശ്യമില്ല (ഒരു വാലിഡേഷൻ ലോസ് കണക്കാക്കണമെങ്കിൽ ഒഴികെ, എന്നാൽ മോഡൽ എത്ര നല്ലതാണെന്ന് മനസ്സിലാക്കാൻ ആ സംഖ്യ നമ്മെ കാര്യമായി സഹായിക്കില്ല). മോഡലിന്റെ പ്രവചനങ്ങളെ യഥാർത്ഥ കോൺടെക്‌സ്‌റ്റിന്റെ സ്‌പാനുകളായി വ്യാഖ്യാനിക്കുന്നതായിരിക്കും യഥാർത്ഥ രസം. ഇതിനായി, ഓഫ്‌സെറ്റ് മാപ്പിംഗുകളും, ഉണ്ടാക്കിയ ഓരോ ഫീച്ചറിനെയും അത് ഉത്ഭവിച്ച യഥാർത്ഥ ഉദാഹരണവുമായി ബന്ധിപ്പിക്കാനുള്ള ഏതെങ്കിലും ഒരു മാർഗ്ഗവും നമ്മൾ സ്‌റ്റോർ ചെയ്താൽ മതി. യഥാർത്ഥ ഡേറ്റാസെറ്റിൽ ഒരു ID കോളം ഉള്ളതിനാൽ, ആ ID നമ്മൾ ഉപയോഗിക്കും.

ഇവിടെ നമ്മൾ കൂട്ടിച്ചേർക്കുന്ന ഒരേയൊരു കാര്യം ഓഫ്‌സെറ്റ് മാപ്പിംഗുകളുടെ ഒരു ചെറിയ ക്ലീനപ്പാണ്. അവയിൽ ചോദ്യത്തിന്റെയും കോൺടെക്‌സ്‌റ്റിന്റെയും ഓഫ്‌സെറ്റുകൾ അടങ്ങിയിരിക്കും, എന്നാൽ പോസ്‌റ്റ്-പ്രോസസ്സിംഗ് ഘട്ടത്തിൽ എത്തിക്കഴിഞ്ഞാൽ ഇൻപുട്ട് ID-കളുടെ ഏത് ഭാഗമാണ് കോൺടെക്‌സ്‌റ്റിനോട് ബന്ധപ്പെട്ടത്, ഏത് ഭാഗമാണ് ചോദ്യം എന്ന് അറിയാൻ നമുക്ക് ഒരു മാർഗ്ഗവുമുണ്ടാകില്ല (നമ്മൾ ഉപയോഗിച്ച `sequence_ids()` മെത്തേഡ് ടോക്കണൈസറിന്റെ ഔട്ട്‌പുട്ടിന് മാത്രമേ ലഭ്യമാകൂ). അതിനാൽ, ചോദ്യത്തിന് അനുബന്ധമായ ഓഫ്‌സെറ്റുകൾ നമ്മൾ `None` എന്ന് സെറ്റ് ചെയ്യും:

```py
def preprocess_validation_examples(examples):
    questions = [q.strip() for q in examples["question"]]
    inputs = tokenizer(
        questions,
        examples["context"],
        max_length=max_length,
        truncation="only_second",
        stride=stride,
        return_overflowing_tokens=True,
        return_offsets_mapping=True,
        padding="max_length",
    )

    sample_map = inputs.pop("overflow_to_sample_mapping")
    example_ids = []

    for i in range(len(inputs["input_ids"])):
        sample_idx = sample_map[i]
        example_ids.append(examples["id"][sample_idx])

        sequence_ids = inputs.sequence_ids(i)
        offset = inputs["offset_mapping"][i]
        inputs["offset_mapping"][i] = [
            o if sequence_ids[k] == 1 else None for k, o in enumerate(offset)
        ]

    inputs["example_id"] = example_ids
    return inputs
```

[`question-answering` പൈപ്പ്‌ലൈൻ](/course/chapter6/3b) പരിശോധിച്ചപ്പോൾ നമ്മൾ കണ്ടതുപോലെ, ഇൻപുട്ട് ID-കളിലെ ഉത്തരത്തിന്റെ ആരംഭ, അവസാന സ്ഥാനങ്ങൾക്കുള്ള ലോജിറ്റുകൾ മോഡൽ ഔട്ട്‌പുട്ട് ചെയ്യും. പോസ്‌റ്റ്-പ്രോസസ്സിംഗ് ഘട്ടം അവിടെ നമ്മൾ ചെയ്തതിന് സമാനമായിരിക്കും, അതിനാൽ നമ്മൾ സ്വീകരിച്ച നടപടികളുടെ ഒരു ചെറിയ ഓർമ്മപ്പെടുത്തൽ ഇതാ:

- കോൺടെക്‌സ്‌റ്റിന് പുറത്തുള്ള ടോക്കണുകൾക്ക് അനുബന്ധമായ ആരംഭ, അവസാന ലോജിറ്റുകൾ നമ്മൾ മാസ്‌ക് ചെയ്തു.
- തുടർന്ന് ഒരു സോഫ്‌റ്റ്‌മാക്‌സ് ഉപയോഗിച്ച് ആരംഭ, അവസാന ലോജിറ്റുകളെ പ്രോബബിലിറ്റികളാക്കി മാറ്റി.
- അനുബന്ധമായ രണ്ട് പ്രോബബിലിറ്റികളുടെ ഗുണനഫലം എടുത്ത് ഓരോ `(start_token, end_token)` ജോഡിക്കും ഒരു സ്‌കോർ നൽകി.
- സാധുവായ ഒരു ഉത്തരം നൽകുന്ന (ഉദാഹരണത്തിന്, `end_token`-നേക്കാൾ ചെറിയ ഒരു `start_token`) പരമാവധി സ്‌കോറുള്ള ജോഡി നമ്മൾ തിരഞ്ഞു.

ഇവിടെ ഈ പ്രക്രിയ നമ്മൾ അൽപ്പം മാറ്റും, കാരണം യഥാർത്ഥ സ്‌കോറുകൾ കണക്കാക്കേണ്ട ആവശ്യമില്ല (പ്രവചിച്ച ഉത്തരം മാത്രം മതി). അതിനർത്ഥം സോഫ്‌റ്റ്‌മാക്‌സ് ഘട്ടം നമുക്ക് ഒഴിവാക്കാം എന്നാണ്. വേഗത കൂട്ടാൻ, സാധ്യമായ എല്ലാ `(start_token, end_token)` ജോഡികൾക്കും നമ്മൾ സ്‌കോർ നൽകില്ല, പകരം ഏറ്റവും ഉയർന്ന `n_best` ലോജിറ്റുകൾക്ക് അനുബന്ധമായവയ്ക്ക് മാത്രം (`n_best=20` ഉപയോഗിച്ച്). സോഫ്‌റ്റ്‌മാക്‌സ് ഒഴിവാക്കുന്നതിനാൽ, ആ സ്‌കോറുകൾ ലോജിറ്റ് സ്‌കോറുകളായിരിക്കും, ആരംഭ, അവസാന ലോജിറ്റുകളുടെ തുക എടുത്താണ് അവ ലഭിക്കുന്നത് (ഗുണനഫലത്തിന് പകരം, \\(\log(ab) = \log(a) + \log(b)\\) എന്ന നിയമം കാരണം).

ഇതെല്ലാം കാണിച്ചുതരാൻ, ഏതെങ്കിലും തരത്തിലുള്ള പ്രവചനങ്ങൾ നമുക്ക് ആവശ്യമാണ്. നമ്മുടെ മോഡൽ ഇതുവരെ ട്രെയിൻ ചെയ്തിട്ടില്ലാത്തതിനാൽ, വാലിഡേഷൻ സെറ്റിന്റെ ഒരു ചെറിയ ഭാഗത്തിൽ ചില പ്രവചനങ്ങൾ ഉണ്ടാക്കാൻ QA പൈപ്പ്‌ലൈനിന്റെ ഡിഫോൾട്ട് മോഡൽ നമ്മൾ ഉപയോഗിക്കാൻ പോകുന്നു. മുമ്പത്തെ അതേ പ്രോസസ്സിംഗ് ഫംഗ്‌ഷൻ നമുക്ക് ഉപയോഗിക്കാം; അത് `tokenizer` എന്ന ഗ്ലോബൽ കോൺസ്‌റ്റന്റിനെ ആശ്രയിക്കുന്നതിനാൽ, ആ ഒബ്‌ജക്റ്റിനെ താൽക്കാലികമായി ഉപയോഗിക്കാൻ ആഗ്രഹിക്കുന്ന മോഡലിന്റെ ടോക്കണൈസറാക്കി മാറ്റിയാൽ മാത്രം മതി:

```python
small_eval_set = raw_datasets["validation"].select(range(100))
trained_checkpoint = "distilbert-base-cased-distilled-squad"

tokenizer = AutoTokenizer.from_pretrained(trained_checkpoint)
eval_set = small_eval_set.map(
    preprocess_validation_examples,
    batched=True,
    remove_columns=raw_datasets["validation"].column_names,
```

- കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ അല്ലാത്ത ഒരു ഉത്തരം
- നെഗറ്റീവ് ദൈർഘ്യമുള്ള ഒരു ഉത്തരം
- വളരെ നീണ്ട ഒരു ഉത്തരം (സാധ്യതകളെ നമ്മൾ `max_answer_length=30`-ൽ പരിമിതപ്പെടുത്തുന്നു)

ഒരു ഉദാഹരണത്തിന് സ്‌കോർ നൽകിയ സാധ്യമായ എല്ലാ ഉത്തരങ്ങളും ലഭിച്ചുകഴിഞ്ഞാൽ, ഏറ്റവും മികച്ച ലോജിറ്റ് സ്‌കോറുള്ളത് നമ്മൾ തിരഞ്ഞെടുക്കുന്നു:

```python
import numpy as np

n_best = 20
max_answer_length = 30
predicted_answers = []

for example in small_eval_set:
    example_id = example["id"]
    context = example["context"]
    answers = []

    for feature_index in example_to_features[example_id]:
        start_logit = start_logits[feature_index]
        end_logit = end_logits[feature_index]
        offsets = eval_set["offset_mapping"][feature_index]

        start_indexes = np.argsort(start_logit)[-1 : -n_best - 1 : -1].tolist()
        end_indexes = np.argsort(end_logit)[-1 : -n_best - 1 : -1].tolist()
        for start_index in start_indexes:
            for end_index in end_indexes:
                # Skip answers that are not fully in the context
                if offsets[start_index] is None or offsets[end_index] is None:
                    continue
                # Skip answers with a length that is either < 0 or > max_answer_length.
                if (
                    end_index < start_index
                    or end_index - start_index + 1 > max_answer_length
                ):
                    continue

                answers.append(
                    {
                        "text": context[offsets[start_index][0] : offsets[end_index][1]],
                        "logit_score": start_logit[start_index] + end_logit[end_index],
                    }
                )

    best_answer = max(answers, key=lambda x: x["logit_score"])
    predicted_answers.append({"id": example_id, "prediction_text": best_answer["text"]})
```

ഇനി നമ്മൾ ഇപ്പോൾ ചെയ്തതെല്ലാം `Trainer`-ൽ ഉപയോഗിക്കാനുള്ള ഒരു `compute_metrics()` ഫംഗ്‌ഷനിൽ ഒരുമിച്ച് ചേർക്കാം. സാധാരണയായി, ആ `compute_metrics()` ഫംഗ്‌ഷന് ലോജിറ്റുകളും ലേബലുകളുമുള്ള `eval_preds` എന്ന ഒരു ട്യൂപ്പിൾ മാത്രമേ ലഭിക്കൂ. ഇവിടെ നമുക്ക് അൽപ്പം കൂടുതൽ ആവശ്യമാണ്, കാരണം ഓഫ്‌സെറ്റിനായി ഫീച്ചറുകളുടെ ഡേറ്റാസെറ്റിലും യഥാർത്ഥ കോൺടെക്‌സ്‌റ്റുകൾക്കായി ഉദാഹരണങ്ങളുടെ ഡേറ്റാസെറ്റിലും നമ്മൾ നോക്കേണ്ടതുണ്ട്; അതിനാൽ ട്രെയിനിംഗ് സമയത്ത് പതിവായ ഇവാല്യുവേഷൻ ഫലങ്ങൾ ലഭിക്കാൻ ഈ ഫംഗ്‌ഷൻ നമുക്ക് ഉപയോഗിക്കാൻ കഴിയില്ല. ഫലങ്ങൾ പരിശോധിക്കാൻ ട്രെയിനിംഗിന്റെ അവസാനം മാത്രമേ നമ്മൾ ഇത് ഉപയോഗിക്കൂ.

`compute_metrics()` ഫംഗ്‌ഷൻ മുമ്പത്തെ അതേ ഘട്ടങ്ങളാണ് ഒരുമിച്ച് ചേർക്കുന്നത്; സാധുവായ ഉത്തരങ്ങളൊന്നും ലഭിക്കാത്ത സാഹചര്യത്തിനായി (അപ്പോൾ നമ്മൾ ഒരു ശൂന്യ സ്‌ട്രിംഗ് പ്രവചിക്കുന്നു) ഒരു ചെറിയ പരിശോധന മാത്രം കൂട്ടിച്ചേർക്കുന്നു.

{:else}

ഇനി നമ്മൾ ഇപ്പോൾ ചെയ്തതെല്ലാം, മോഡൽ ട്രെയിൻ ചെയ്ത ശേഷം ഉപയോഗിക്കാനുള്ള ഒരു `compute_metrics()` ഫംഗ്‌ഷനിൽ ഒരുമിച്ച് ചേർക്കാം. ഔട്ട്‌പുട്ട് ലോജിറ്റുകൾ മാത്രമല്ല, അൽപ്പം കൂടുതൽ കാര്യങ്ങൾ നമുക്ക് നൽകേണ്ടിവരും, കാരണം ഓഫ്‌സെറ്റിനായി ഫീച്ചറുകളുടെ ഡേറ്റാസെറ്റിലും യഥാർത്ഥ കോൺടെക്‌സ്‌റ്റുകൾക്കായി ഉദാഹരണങ്ങളുടെ ഡേറ്റാസെറ്റിലും നമ്മൾ നോക്കേണ്ടതുണ്ട്:

```python
from tqdm.auto import tqdm


def compute_metrics(start_logits, end_logits, features, examples):
    example_to_features = collections.defaultdict(list)
    for idx, feature in enumerate(features):
        example_to_features[feature["example_id"]].append(idx)

    predicted_answers = []
    for example in tqdm(examples):
        example_id = example["id"]
        context = example["context"]
        answers = []

        # Loop through all features associated with that example
        for feature_index in example_to_features[example_id]:
            start_logit = start_logits[feature_index]
            end_logit = end_logits[feature_index]
            offsets = features[feature_index]["offset_mapping"]

            start_indexes = np.argsort(start_logit)[-1 : -n_best - 1 : -1].tolist()
            end_indexes = np.argsort(end_logit)[-1 : -n_best - 1 : -1].tolist()
            for start_index in start_indexes:
                for end_index in end_indexes:
                    # Skip answers that are not fully in the context
                    if offsets[start_index] is None or offsets[end_index] is None:
                        continue
                    # Skip answers with a length that is either < 0 or > max_answer_length
                    if (
                        end_index < start_index
                        or end_index - start_index + 1 > max_answer_length
                    ):
                        continue

                    answer = {
                        "text": context[offsets[start_index][0] : offsets[end_index][1]],
                        "logit_score": start_logit[start_index] + end_logit[end_index],
                    }
                    answers.append(answer)

        # Select the answer with the best score
        if len(answers) > 0:
            best_answer = max(answers, key=lambda x: x["logit_score"])
            predicted_answers.append(
                {"id": example_id, "prediction_text": best_answer["text"]}
            )
        else:
            predicted_answers.append({"id": example_id, "prediction_text": ""})

    theoretical_answers = [{"id": ex["id"], "answers": ex["answers"]} for ex in examples]
    return metric.compute(predictions=predicted_answers, references=theoretical_answers)
```

പതിവുപോലെ, ചില വെയ്‌റ്റുകൾ ഉപയോഗിച്ചിട്ടില്ലെന്നും (പ്രീട്രെയിനിംഗ് ഹെഡിന്റേത്) മറ്റു ചിലത് ക്രമരഹിതമായി ഇനിഷ്യലൈസ് ചെയ്യപ്പെട്ടിരിക്കുന്നു എന്നും (ചോദ്യോത്തര ഹെഡിന്റേത്) ഒരു മുന്നറിയിപ്പ് നമുക്ക് ലഭിക്കുന്നു. ഇപ്പോൾ നിങ്ങൾക്ക് ഇത് പരിചിതമായിരിക്കണം, എന്നാൽ ഈ മോഡൽ ഇപ്പോൾത്തന്നെ ഉപയോഗിക്കാൻ തയ്യാറല്ലെന്നും ഫൈൻ-ട്യൂണിംഗ് ആവശ്യമാണെന്നുമാണ് അതിനർത്ഥം -- നമ്മൾ അത് ചെയ്യാൻ പോകുന്നു എന്നത് നല്ല കാര്യം!

നമ്മുടെ മോഡൽ Hub-ലേക്ക് പുഷ് ചെയ്യാൻ കഴിയണമെങ്കിൽ, Hugging Face-ൽ ലോഗിൻ ചെയ്യേണ്ടതുണ്ട്. ഈ കോഡ് ഒരു നോട്ട്‌ബുക്കിലാണ് നിങ്ങൾ റൺ ചെയ്യുന്നതെങ്കിൽ, താഴെയുള്ള യൂട്ടിലിറ്റി ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് അത് ചെയ്യാം; നിങ്ങളുടെ ലോഗിൻ വിവരങ്ങൾ നൽകാവുന്ന ഒരു വിഡ്‌ജെറ്റ് ഇത് കാണിക്കും:

```python

notebook_login()
```

ഇത് ചെയ്തുകഴിഞ്ഞാൽ, നമ്മുടെ `TrainingArguments` നിർവചിക്കാം. മെട്രിക് കണക്കാക്കാനുള്ള ഫംഗ്‌ഷൻ നിർവചിച്ചപ്പോൾ പറഞ്ഞതുപോലെ, `compute_metrics()` ഫംഗ്‌ഷന്റെ സിഗ്നേച്ചർ കാരണം ഒരു പതിവായ ഇവാല്യുവേഷൻ ലൂപ്പ് നമുക്ക് സാധ്യമാകില്ല. ഇത് ചെയ്യാൻ `Trainer`-ന്റെ നമ്മുടെ സ്വന്തം സബ്‌ക്ലാസ് എഴുതാമായിരുന്നു ([ചോദ്യോത്തര ഉദാഹരണ സ്‌ക്രിപ്‌റ്റിൽ](https://github.com/huggingface/transformers/blob/master/examples/pytorch/question-answering/trainer_qa.py) നിങ്ങൾക്ക് കാണാവുന്ന ഒരു സമീപനം), എന്നാൽ ഈ ഭാഗത്തിന് അത് അൽപ്പം ദൈർഘ്യമേറിയതാണ്. പകരം, ഇവിടെ ട്രെയിനിംഗിന്റെ അവസാനം മാത്രം മോഡൽ ഇവാല്യുവേറ്റ് ചെയ്യുകയും, താഴെ "ഒരു ഇഷ്ടാനുസൃത ട്രെയിനിംഗ് ലൂപ്പ്" എന്ന ഭാഗത്തിൽ പതിവായ ഇവാല്യുവേഷൻ എങ്ങനെ ചെയ്യാമെന്ന് കാണിച്ചുതരികയും ചെയ്യും.

`Trainer` API-യുടെ പരിമിതികൾ വെളിപ്പെടുന്നതും 🤗 Accelerate ലൈബ്രറി തിളങ്ങുന്നതും ശരിക്കും ഇവിടെയാണ്: ഒരു പ്രത്യേക ഉപയോഗ സാഹചര്യത്തിനായി ക്ലാസ് ഇഷ്ടാനുസൃതമാക്കുന്നത് ബുദ്ധിമുട്ടേറിയതാകാം, എന്നാൽ പൂർണ്ണമായി തുറന്നുകിടക്കുന്ന ഒരു ട്രെയിനിംഗ് ലൂപ്പിൽ മാറ്റങ്ങൾ വരുത്തുന്നത് എളുപ്പമാണ്.

നമ്മുടെ `TrainingArguments` ഒന്ന് നോക്കാം:

```python
from transformers import TrainingArguments

args = TrainingArguments(
    "bert-finetuned-squad",
    evaluation_strategy="no",
    save_strategy="epoch",
    learning_rate=2e-5,
    num_train_epochs=3,
    weight_decay=0.01,
    fp16=True,
    push_to_hub=True,
)
```

ഇവയിൽ മിക്കതും നമ്മൾ മുമ്പ് കണ്ടിട്ടുണ്ട്: ചില ഹൈപ്പർപാരാമീറ്ററുകൾ (ലേണിംഗ് റേറ്റ്, നമ്മൾ ട്രെയിൻ ചെയ്യുന്ന എപ്പോക്കുകളുടെ എണ്ണം, കുറച്ച് വെയ്‌റ്റ് ഡികേ എന്നിവ പോലെ) നമ്മൾ സെറ്റ് ചെയ്യുന്നു, കൂടാതെ ഓരോ എപ്പോക്കിന്റെയും അവസാനം മോഡൽ സേവ് ചെയ്യണമെന്നും, ഇവാല്യുവേഷൻ ഒഴിവാക്കണമെന്നും, നമ്മുടെ ഫലങ്ങൾ Model Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യണമെന്നും സൂചിപ്പിക്കുന്നു. `fp16=True` ഉപയോഗിച്ച് മിക്‌സഡ്-പ്രിസിഷൻ ട്രെയിനിംഗും നമ്മൾ പ്രവർത്തനക്ഷമമാക്കുന്നു, കാരണം ഒരു പുതിയ GPU-വിൽ അത് ട്രെയിനിംഗിന്റെ വേഗത നന്നായി കൂട്ടും.

{:else}

അത് ചെയ്തുകഴിഞ്ഞതിനാൽ, നമ്മുടെ TF Datasets ഉണ്ടാക്കാം. ഇത്തവണ ലളിതമായ ഡിഫോൾട്ട് ഡേറ്റാ കൊളേറ്റർ നമുക്ക് ഉപയോഗിക്കാം:

```python
from transformers import DefaultDataCollator

data_collator = DefaultDataCollator(return_tensors="tf")
```

ഇപ്പോൾ പതിവുപോലെ ഡേറ്റാസെറ്റുകൾ ഉണ്ടാക്കുന്നു.

```python
tf_train_dataset = model.prepare_tf_dataset(
    train_dataset,
    collate_fn=data_collator,
    shuffle=True,
    batch_size=16,
)
tf_eval_dataset = model.prepare_tf_dataset(
    validation_dataset,
    collate_fn=data_collator,
    shuffle=False,
    batch_size=16,
)
```

അടുത്തതായി, നമ്മുടെ ട്രെയിനിംഗ് ഹൈപ്പർപാരാമീറ്ററുകൾ സെറ്റപ്പ് ചെയ്ത് മോഡൽ കംപൈൽ ചെയ്യുന്നു:

```python
from transformers import create_optimizer
from transformers.keras_callbacks import PushToHubCallback
import tensorflow as tf

# The number of training steps is the number of samples in the dataset, divided by the batch size then multiplied
# by the total number of epochs. Note that the tf_train_dataset here is a batched tf.data.Dataset,
# not the original Hugging Face Dataset, so its len() is already num_samples // batch_size.
num_train_epochs = 3
num_train_steps = len(tf_train_dataset) * num_train_epochs
optimizer, schedule = create_optimizer(
    init_lr=2e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)

# Train in mixed-precision float16
tf.keras.mixed_precision.set_global_policy("mixed_float16")
```

അവസാനമായി, `model.fit()` ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്യാൻ നമ്മൾ തയ്യാറാണ്. ഓരോ എപ്പോക്കിന് ശേഷവും മോഡൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാൻ ഒരു `PushToHubCallback` നമ്മൾ ഉപയോഗിക്കുന്നു.

{/if}

ഡിഫോൾട്ടായി, ഉപയോഗിക്കുന്ന റിപ്പോസിറ്ററി നിങ്ങളുടെ നെയിംസ്‌പേസിൽ ആയിരിക്കും, നിങ്ങൾ സെറ്റ് ചെയ്ത ഔട്ട്‌പുട്ട് ഡയറക്ടറിയുടെ പേരിലായിരിക്കും അത്; അതിനാൽ നമ്മുടെ കാര്യത്തിൽ അത് `"sgugger/bert-finetuned-squad"`-ൽ ആയിരിക്കും. ഒരു `hub_model_id` നൽകിക്കൊണ്ട് ഇത് നമുക്ക് മാറ്റാം; ഉദാഹരണത്തിന്, `huggingface_course` ഓർഗനൈസേഷനിലേക്ക് മോഡൽ പുഷ് ചെയ്യാൻ നമ്മൾ `hub_model_id="huggingface_course/bert-finetuned-squad"` ഉപയോഗിച്ചു (ഈ ഭാഗത്തിന്റെ തുടക്കത്തിൽ നമ്മൾ ലിങ്ക് ചെയ്ത മോഡലാണിത്).

> [!TIP]
> 💡 നിങ്ങൾ ഉപയോഗിക്കുന്ന ഔട്ട്‌പുട്ട് ഡയറക്ടറി നിലവിലുണ്ടെങ്കിൽ, അത് നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ലോക്കൽ ക്ലോൺ ആയിരിക്കണം (അതിനാൽ നിങ്ങളുടെ `Trainer` നിർവചിക്കുമ്പോൾ ഒരു എറർ ലഭിച്ചാൽ ഒരു പുതിയ പേര് സെറ്റ് ചെയ്യുക).

അവസാനമായി, എല്ലാം `Trainer` ക്ലാസിന് നൽകി ട്രെയിനിംഗ് ആരംഭിക്കുന്നു:

```python
from transformers import Trainer

trainer = Trainer(

    args=args,
    train_dataset=train_dataset,
    eval_dataset=validation_dataset,
    tokenizer=tokenizer,
)
trainer.train()
```

ട്രെയിനിംഗ് നടക്കുമ്പോൾ, മോഡൽ സേവ് ചെയ്യപ്പെടുന്ന ഓരോ തവണയും (ഇവിടെ, ഓരോ എപ്പോക്കിലും) അത് പശ്ചാത്തലത്തിൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെടുന്നു എന്നത് ശ്രദ്ധിക്കുക. ഇങ്ങനെ, ആവശ്യമെങ്കിൽ മറ്റൊരു മെഷീനിൽ നിങ്ങളുടെ ട്രെയിനിംഗ് പുനരാരംഭിക്കാൻ നിങ്ങൾക്ക് കഴിയും. മുഴുവൻ ട്രെയിനിംഗിനും കുറച്ച് സമയമെടുക്കും (ഒരു Titan RTX-ൽ ഒരു മണിക്കൂറിൽ കുറച്ചധികം), അതിനാൽ അത് പുരോഗമിക്കുമ്പോൾ നിങ്ങൾക്ക് ഒരു കാപ്പി കുടിക്കാം, അല്ലെങ്കിൽ കോഴ്‌സിൽ കൂടുതൽ വെല്ലുവിളിയായി തോന്നിയ ഭാഗങ്ങൾ വീണ്ടും വായിക്കാം. ആദ്യത്തെ എപ്പോക്ക് പൂർത്തിയായ ഉടൻ, ചില വെയ്‌റ്റുകൾ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യപ്പെട്ടതായി നിങ്ങൾ കാണും, അതിന്റെ പേജിൽ നിങ്ങളുടെ മോഡലുമായി കളിച്ചുതുടങ്ങാം എന്നതും ശ്രദ്ധിക്കുക.

{#if fw === 'pt'}

ട്രെയിനിംഗ് പൂർത്തിയായിക്കഴിഞ്ഞാൽ, ഒടുവിൽ നമ്മുടെ മോഡൽ ഇവാല്യുവേറ്റ് ചെയ്യാം (ആ കമ്പ്യൂട്ട് സമയമെല്ലാം വെറുതെയായില്ലെന്ന് പ്രാർത്ഥിക്കുകയും ചെയ്യാം). `Trainer`-ന്റെ `predict()` മെത്തേഡ് ഒരു ട്യൂപ്പിൾ റിട്ടേൺ ചെയ്യും; അതിലെ ആദ്യ എലമെന്റുകൾ മോഡലിന്റെ പ്രവചനങ്ങളായിരിക്കും (ഇവിടെ ആരംഭ, അവസാന ലോജിറ്റുകളുള്ള ഒരു ജോഡി). ഇത് നമ്മുടെ `compute_metrics()` ഫംഗ്‌ഷന് നൽകുന്നു:

```python
predictions, _, _ = trainer.predict(validation_dataset)
start_logits, end_logits = predictions
compute_metrics(start_logits, end_logits, validation_dataset, raw_datasets["validation"])
```

```python
predictions = model.predict(tf_eval_dataset)
```

## ഒരു ഇഷ്ടാനുസൃത ട്രെയിനിംഗ് ലൂപ്പ്[[a-custom-training-loop]]

ഇനി മുഴുവൻ ട്രെയിനിംഗ് ലൂപ്പും ഒന്ന് നോക്കാം, അങ്ങനെ നിങ്ങൾക്ക് ആവശ്യമുള്ള ഭാഗങ്ങൾ എളുപ്പത്തിൽ ഇഷ്ടാനുസൃതമാക്കാം. ഇവാല്യുവേഷൻ ലൂപ്പ് ഒഴികെ, [അധ്യായം 3](/course/chapter3/4)-ലെ ട്രെയിനിംഗ് ലൂപ്പിനോട് ഇത് ഏറെ സാമ്യമുള്ളതായിരിക്കും. `Trainer` ക്ലാസിന്റെ പരിമിതികൾ ഇനി നമുക്കില്ലാത്തതിനാൽ, മോഡൽ പതിവായി ഇവാല്യുവേറ്റ് ചെയ്യാൻ നമുക്ക് കഴിയും.

### ട്രെയിനിംഗിനായി എല്ലാം തയ്യാറാക്കുന്നു[[preparing-everything-for-training]]

ആദ്യം നമ്മുടെ ഡേറ്റാസെറ്റുകളിൽ നിന്ന് `DataLoader`-കൾ നിർമ്മിക്കണം. ആ ഡേറ്റാസെറ്റുകളുടെ ഫോർമാറ്റ് `"torch"` എന്ന് സെറ്റ് ചെയ്യുകയും, വാലിഡേഷൻ സെറ്റിലെ, മോഡൽ ഉപയോഗിക്കാത്ത കോളങ്ങൾ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു. തുടർന്ന്, Transformers നൽകുന്ന `default_data_collator` ഒരു `collate_fn` ആയി ഉപയോഗിക്കാം, കൂടാതെ ട്രെയിനിംഗ് സെറ്റ് ഷഫിൾ ചെയ്യാം, എന്നാൽ വാലിഡേഷൻ സെറ്റ് ഷഫിൾ ചെയ്യരുത്:

```py
from torch.utils.data import DataLoader
from transformers import default_data_collator

train_dataset.set_format("torch")
validation_set = validation_dataset.remove_columns(["example_id", "offset_mapping"])
validation_set.set_format("torch")

train_dataloader = DataLoader(
    train_dataset,
    shuffle=True,
    collate_fn=default_data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    validation_set, collate_fn=default_data_collator, batch_size=8
)
```

അടുത്തതായി നമ്മുടെ മോഡൽ വീണ്ടും ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്നു; മുമ്പത്തെ ഫൈൻ-ട്യൂണിംഗ് തുടരുകയല്ല, മറിച്ച് BERT പ്രീട്രെയിൻഡ് മോഡലിൽ നിന്ന് വീണ്ടും ആരംഭിക്കുകയാണ് എന്ന് ഉറപ്പാക്കാനാണിത്:

```py
model = AutoModelForQuestionAnswering.from_pretrained(model_checkpoint)
```

പിന്നീട് നമുക്ക് ഒരു ഒപ്‌റ്റിമൈസർ ആവശ്യമാണ്. പതിവുപോലെ ക്ലാസിക് `AdamW` നമ്മൾ ഉപയോഗിക്കുന്നു; ഇത് Adam പോലെയാണ്, എന്നാൽ വെയ്‌റ്റ് ഡികേ പ്രയോഗിക്കുന്ന രീതിയിൽ ഒരു തിരുത്തലോടെ:

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

ആ ഒബ്‌ജക്റ്റുകളെല്ലാം ലഭിച്ചുകഴിഞ്ഞാൽ, അവ `accelerator.prepare()` മെത്തേഡിന് നൽകാം. ഒരു Colab നോട്ട്‌ബുക്കിൽ TPU-കളിൽ ട്രെയിൻ ചെയ്യാൻ ആഗ്രഹിക്കുന്നെങ്കിൽ, ഈ കോഡ് മുഴുവനും ഒരു ട്രെയിനിംഗ് ഫംഗ്‌ഷനിലേക്ക് മാറ്റേണ്ടിവരും എന്നും, ഒരു `Accelerator` ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്ന ഒരു സെല്ലും അത് എക്‌സിക്യൂട്ട് ചെയ്യരുത് എന്നും ഓർമ്മിക്കുക. `Accelerator`-ന് `fp16=True` നൽകിക്കൊണ്ട് മിക്‌സഡ്-പ്രിസിഷൻ ട്രെയിനിംഗ് നമുക്ക് നിർബന്ധിതമാക്കാം (അല്ലെങ്കിൽ, കോഡ് ഒരു സ്‌ക്രിപ്‌റ്റായി എക്‌സിക്യൂട്ട് ചെയ്യുകയാണെങ്കിൽ, 🤗 Accelerate `config` ഉചിതമായി പൂരിപ്പിക്കാൻ മറക്കരുത്).

```py
from accelerate import Accelerator

accelerator = Accelerator(fp16=True)
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

മുൻ ഭാഗങ്ങളിൽ നിന്ന് നിങ്ങൾക്ക് അറിയാവുന്നതുപോലെ, `train_dataloader` എന്നത് `accelerator.prepare()` മെത്തേഡിലൂടെ കടന്നുപോയതിന് ശേഷം മാത്രമേ ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണം കണക്കാക്കാൻ അതിന്റെ ദൈർഘ്യം നമുക്ക് ഉപയോഗിക്കാൻ കഴിയൂ. മുൻ ഭാഗങ്ങളിലെ അതേ ലീനിയർ ഷെഡ്യൂൾ നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

നമ്മുടെ മോഡൽ Hub-ലേക്ക് പുഷ് ചെയ്യാൻ, ഒരു വർക്കിംഗ് ഫോൾഡറിൽ ഒരു `Repository` ഒബ്‌ജക്റ്റ് ഉണ്ടാക്കേണ്ടിവരും. ഇതിനകം ലോഗിൻ ചെയ്തിട്ടില്ലെങ്കിൽ, ആദ്യം Hugging Face Hub-ൽ ലോഗിൻ ചെയ്യുക. നമ്മുടെ മോഡലിന് നൽകാൻ ആഗ്രഹിക്കുന്ന മോഡൽ ID-യിൽ നിന്ന് റിപ്പോസിറ്ററിയുടെ പേര് നമ്മൾ നിർണ്ണയിക്കും (`repo_name` നിങ്ങളുടെ ഇഷ്ടപ്രകാരം മാറ്റാൻ മടിക്കേണ്ട; അതിൽ നിങ്ങളുടെ യൂസർനെയിം അടങ്ങിയിരിക്കണം എന്ന് മാത്രം, അതാണ് `get_full_repo_name()` ഫംഗ്‌ഷൻ ചെയ്യുന്നത്):

```py
from huggingface_hub import Repository, get_full_repo_name

model_name = "bert-finetuned-squad-accelerate"
repo_name = get_full_repo_name(model_name)
repo_name
```


തുടർന്ന് ആ റിപ്പോസിറ്ററി ഒരു ലോക്കൽ ഫോൾഡറിൽ ക്ലോൺ ചെയ്യാം. അത് ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, ഈ ലോക്കൽ ഫോൾഡർ നമ്മൾ പ്രവർത്തിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ക്ലോൺ ആയിരിക്കണം:

```py
output_dir = "bert-finetuned-squad-accelerate"
repo = Repository(output_dir, clone_from=repo_name)
```

`repo.push_to_hub()` മെത്തേഡ് വിളിച്ചുകൊണ്ട് `output_dir`-ൽ നമ്മൾ സേവ് ചെയ്യുന്ന എന്തും ഇപ്പോൾ അപ്‌ലോഡ് ചെയ്യാം. ഓരോ എപ്പോക്കിന്റെയും അവസാനം ഇടക്കാല മോഡലുകൾ അപ്‌ലോഡ് ചെയ്യാൻ ഇത് നമ്മെ സഹായിക്കും.

## ട്രെയിനിംഗ് ലൂപ്പ്[[training-loop]]

ഇപ്പോൾ മുഴുവൻ ട്രെയിനിംഗ് ലൂപ്പും എഴുതാൻ നമ്മൾ തയ്യാറാണ്. ട്രെയിനിംഗ് എങ്ങനെ പുരോഗമിക്കുന്നു എന്ന് പിന്തുടരാൻ ഒരു പ്രോഗ്രസ് ബാർ നിർവചിച്ച ശേഷം, ലൂപ്പിന് മൂന്ന് ഭാഗങ്ങളുണ്ട്:

- ട്രെയിനിംഗ് തന്നെ; `train_dataloader`-ലൂടെയുള്ള ക്ലാസിക് ഇറ്ററേഷൻ, മോഡലിലൂടെയുള്ള ഫോർവേഡ് പാസ്, പിന്നെ ബാക്ക്‌വേഡ് പാസും ഒപ്‌റ്റിമൈസർ സ്‌റ്റെപ്പും ആണിത്.
- ഇവാല്യുവേഷൻ; ഇതിൽ `start_logits`-ന്റെയും `end_logits`-ന്റെയും എല്ലാ മൂല്യങ്ങളും NumPy അറേകളാക്കി മാറ്റുന്നതിന് മുമ്പ് നമ്മൾ ശേഖരിക്കുന്നു (gather). ഇവാല്യുവേഷൻ ലൂപ്പ് പൂർത്തിയായിക്കഴിഞ്ഞാൽ, എല്ലാ ഫലങ്ങളും നമ്മൾ കൂട്ടിച്ചേർക്കുന്നു (concatenate). ഓരോ പ്രോസസ്സിലും ഒരേ എണ്ണം ഉദാഹരണങ്ങൾ ഉണ്ടെന്ന് ഉറപ്പാക്കാൻ `Accelerator` അവസാനം ഏതാനും സാമ്പിളുകൾ കൂട്ടിച്ചേർത്തിരിക്കാം എന്നതിനാൽ നമ്മൾ ട്രങ്കേറ്റ് ചെയ്യേണ്ടതുണ്ട് എന്നത് ശ്രദ്ധിക്കുക.
- സേവ് ചെയ്യലും അപ്‌ലോഡ് ചെയ്യലും; ഇവിടെ ആദ്യം മോഡലും ടോക്കണൈസറും സേവ് ചെയ്യുന്നു, പിന്നീട് `repo.push_to_hub()` വിളിക്കുന്നു. മുമ്പ് ചെയ്തതുപോലെ, ഒരു അസിൻക്രണസ് പ്രോസസ്സിൽ പുഷ് ചെയ്യാൻ 🤗 Hub ലൈബ്രറിയോട് പറയാൻ `blocking=False` എന്ന ആർഗ്യുമെന്റ് നമ്മൾ ഉപയോഗിക്കുന്നു. ഇങ്ങനെ, ട്രെയിനിംഗ് സാധാരണപോലെ തുടരുകയും ഈ (ദൈർഘ്യമേറിയ) നിർദ്ദേശം പശ്ചാത്തലത്തിൽ എക്‌സിക്യൂട്ട് ചെയ്യപ്പെടുകയും ചെയ്യുന്നു.

ട്രെയിനിംഗ് ലൂപ്പിന്റെ പൂർണ്ണമായ കോഡ് ഇതാ:

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # Training
    model.train()
    for step, batch in enumerate(train_dataloader):
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # Evaluation
    model.eval()
    start_logits = []
    end_logits = []
    accelerator.print("Evaluation!")
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            outputs = model(**batch)

        start_logits.append(accelerator.gather(outputs.start_logits).cpu().numpy())
        end_logits.append(accelerator.gather(outputs.end_logits).cpu().numpy())

    start_logits = np.concatenate(start_logits)
    end_logits = np.concatenate(end_logits)
    start_logits = start_logits[: len(validation_dataset)]
    end_logits = end_logits[: len(validation_dataset)]

    metrics = compute_metrics(
        start_logits, end_logits, validation_dataset, raw_datasets["validation"]
    )
    print(f"epoch {epoch}:", metrics)

    # Save and upload
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

🤗 Accelerate ഉപയോഗിച്ച് ഒരു മോഡൽ സേവ് ചെയ്യുന്നത് നിങ്ങൾ ആദ്യമായി കാണുന്നതാണെങ്കിൽ, അതിനോടൊപ്പമുള്ള മൂന്ന് വരി കോഡ് പരിശോധിക്കാൻ ഒരു നിമിഷം എടുക്കാം:

```py
accelerator.wait_for_everyone()
unwrapped_model = accelerator.unwrap_model(model)
unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
```

ആദ്യത്തെ വരി സ്വയം വ്യക്തമാണ്: തുടരുന്നതിന് മുമ്പ് എല്ലാവരും ആ ഘട്ടത്തിൽ എത്തുന്നതുവരെ കാത്തിരിക്കാൻ ഇത് എല്ലാ പ്രോസസ്സുകളോടും പറയുന്നു. സേവ് ചെയ്യുന്നതിന് മുമ്പ് എല്ലാ പ്രോസസ്സിലും ഒരേ മോഡൽ ഉണ്ടെന്ന് ഉറപ്പാക്കാനാണിത്. തുടർന്ന് നമ്മൾ നിർവചിച്ച അടിസ്ഥാന മോഡലായ `unwrapped_model` എടുക്കുന്നു. `accelerator.prepare()` മെത്തേഡ് ഡിസ്‌ട്രിബ്യൂട്ടഡ് ട്രെയിനിംഗിൽ പ്രവർത്തിക്കാനായി മോഡലിനെ മാറ്റുന്നു, അതിനാൽ അതിന് ഇനി `save_pretrained()` മെത്തേഡ് ഉണ്ടാകില്ല; `accelerator.unwrap_model()` മെത്തേഡ് ആ ഘട്ടം പഴയപടിയാക്കുന്നു. അവസാനമായി, നമ്മൾ `save_pretrained()` വിളിക്കുന്നു, എന്നാൽ `torch.save()`-ന് പകരം `accelerator.save()` ഉപയോഗിക്കാൻ ആ മെത്തേഡിനോട് പറയുന്നു.

ഇത് ചെയ്തുകഴിഞ്ഞാൽ, `Trainer` ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്തതിനോട് ഏറെ സാമ്യമുള്ള ഫലങ്ങൾ നൽകുന്ന ഒരു മോഡൽ നിങ്ങൾക്ക് ഉണ്ടായിരിക്കണം. ഈ കോഡ് ഉപയോഗിച്ച് ഞങ്ങൾ ട്രെയിൻ ചെയ്ത മോഡൽ [*huggingface-course/bert-finetuned-squad-accelerate*](https://huggingface.co/huggingface-course/bert-finetuned-squad-accelerate)-ൽ നിങ്ങൾക്ക് പരിശോധിക്കാം. ട്രെയിനിംഗ് ലൂപ്പിൽ എന്തെങ്കിലും മാറ്റങ്ങൾ പരീക്ഷിക്കാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്നെങ്കിൽ, മുകളിൽ കാണിച്ച കോഡ് എഡിറ്റ് ചെയ്തുകൊണ്ട് അവ നേരിട്ട് ഇംപ്ലിമെന്റ് ചെയ്യാം!

## ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ ഉപയോഗിക്കുന്നു[[using-the-fine-tuned-model]]

നമ്മൾ ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ Model Hub-ൽ ഇൻഫറൻസ് വിഡ്‌ജെറ്റ് ഉപയോഗിച്ച് എങ്ങനെ ഉപയോഗിക്കാമെന്ന് ഞങ്ങൾ ഇതിനകം കാണിച്ചുതന്നിട്ടുണ്ട്. ഒരു `pipeline`-ൽ ഇത് ലോക്കലായി ഉപയോഗിക്കാൻ, മോഡൽ ഐഡന്റിഫയർ വ്യക്തമാക്കിയാൽ മാത്രം മതി:

```py
from transformers import pipeline

# Replace this with your own checkpoint
model_checkpoint = "huggingface-course/bert-finetuned-squad"
question_answerer = pipeline("question-answering", model=model_checkpoint)

context = """
🤗 Transformers is backed by the three most popular deep learning libraries — Jax, PyTorch and TensorFlow — with a seamless integration
between them. It's straightforward to train your models with one before loading them for inference with the other.
"""
question = "Which deep learning libraries back 🤗 Transformers?"
question_answerer(question=question, context=context)
```
