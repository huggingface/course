ഇനി നമുക്ക് വിവർത്തനത്തിലേക്ക് (translation) കടക്കാം. ഇത് മറ്റൊരു [സീക്വൻസ്-ടു-സീക്വൻസ് ടാസ്‌ക്](/course/chapter1/7) ആണ്; അതായത്, ഒരു സീക്വൻസിൽ നിന്ന് മറ്റൊരു സീക്വൻസിലേക്ക് പോകുന്നതായി രൂപപ്പെടുത്താവുന്ന ഒരു പ്രശ്‌നമാണിത്. ആ അർത്ഥത്തിൽ ഈ പ്രശ്‌നം [സംഗ്രഹത്തോട് (summarization)](/course/chapter7/6) ഏറെ അടുത്തുനിൽക്കുന്നു, കൂടാതെ ഇവിടെ നമ്മൾ കാണുന്ന കാര്യങ്ങൾ താഴെപ്പറയുന്നതുപോലുള്ള മറ്റ് സീക്വൻസ്-ടു-സീക്വൻസ് പ്രശ്‌നങ്ങൾക്കും നിങ്ങൾക്ക് അനുയോജ്യമാക്കി ഉപയോഗിക്കാം:

- **സ്‌റ്റൈൽ ട്രാൻസ്‌ഫർ (Style transfer)**: ഒരു പ്രത്യേക ശൈലിയിൽ എഴുതിയ ടെക്‌സ്‌റ്റുകളെ മറ്റൊരു ശൈലിയിലേക്ക് *വിവർത്തനം ചെയ്യുന്ന* ഒരു മോഡൽ നിർമ്മിക്കുക (ഉദാ., ഔപചാരികമായതിൽ നിന്ന് അനൗപചാരികമായതിലേക്ക്, അല്ലെങ്കിൽ ഷേക്‌സ്‌പിയർ കാലത്തെ ഇംഗ്ലീഷിൽ നിന്ന് ആധുനിക ഇംഗ്ലീഷിലേക്ക്)
- **ജനറേറ്റീവ് ക്വസ്‌റ്റ്യൻ ആൻസറിംഗ് (Generative question answering)**: ഒരു കോൺടെക്‌സ്‌റ്റ് നൽകിയാൽ ചോദ്യങ്ങൾക്ക് ഉത്തരങ്ങൾ ജനറേറ്റ് ചെയ്യുന്ന ഒരു മോഡൽ നിർമ്മിക്കുക

രണ്ടോ (അതിലധികമോ) ഭാഷകളിലുള്ള ടെക്‌സ്‌റ്റുകളുടെ മതിയായ വലിപ്പമുള്ള ഒരു കോർപ്പസ് (corpus) നിങ്ങളുടെ കൈവശമുണ്ടെങ്കിൽ, [കോസൽ ലാംഗ്വേജ് മോഡലിംഗ്](/course/chapter7/6)-നെക്കുറിച്ചുള്ള ഭാഗത്തിൽ നമ്മൾ ചെയ്യുന്നതുപോലെ ഒരു പുതിയ വിവർത്തന മോഡൽ പൂജ്യത്തിൽ നിന്ന് ട്രെയിൻ ചെയ്യാം. എന്നാൽ, നിലവിലുള്ള ഒരു വിവർത്തന മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നതായിരിക്കും കൂടുതൽ വേഗത്തിലുള്ളത് — അത് ഒരു പ്രത്യേക ഭാഷാജോഡിയിലേക്ക് ഫൈൻ-ട്യൂൻ ചെയ്യാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്ന mT5 അല്ലെങ്കിൽ mBART പോലുള്ള ഒരു ബഹുഭാഷാ (multilingual) മോഡലായാലും, അല്ലെങ്കിൽ നിങ്ങളുടെ പ്രത്യേക കോർപ്പസിലേക്ക് ഫൈൻ-ട്യൂൻ ചെയ്യാൻ ആഗ്രഹിക്കുന്ന, ഒരു ഭാഷയിൽ നിന്ന് മറ്റൊന്നിലേക്കുള്ള വിവർത്തനത്തിനായി പ്രത്യേകം തയ്യാറാക്കിയ ഒരു മോഡലായാലും.

ഈ ഭാഗത്തിൽ, ഇംഗ്ലീഷിൽ നിന്ന് ഫ്രഞ്ചിലേക്ക് വിവർത്തനം ചെയ്യാൻ പ്രീട്രെയിൻ ചെയ്ത ഒരു Marian മോഡൽ (Hugging Face-ലെ ധാരാളം ജീവനക്കാർ ഈ രണ്ട് ഭാഷകളും സംസാരിക്കുന്നവരാണ് എന്നതിനാൽ) [KDE4 ഡേറ്റാസെറ്റിൽ](https://huggingface.co/datasets/kde4) നമ്മൾ ഫൈൻ-ട്യൂൻ ചെയ്യും; [KDE ആപ്പുകൾക്കായുള്ള](https://apps.kde.org/) ലോക്കലൈസ് ചെയ്ത ഫയലുകളുടെ ഒരു ഡേറ്റാസെറ്റാണിത്. നമ്മൾ ഉപയോഗിക്കുന്ന മോഡൽ, [Opus ഡേറ്റാസെറ്റിൽ](https://opus.nlpl.eu/) നിന്നെടുത്ത ഫ്രഞ്ച്, ഇംഗ്ലീഷ് ടെക്‌സ്‌റ്റുകളുടെ ഒരു വലിയ കോർപ്പസിലാണ് പ്രീട്രെയിൻ ചെയ്തിരിക്കുന്നത്; അതിൽ യഥാർത്ഥത്തിൽ KDE4 ഡേറ്റാസെറ്റും ഉൾപ്പെടുന്നു. എന്നാൽ നമ്മൾ ഉപയോഗിക്കുന്ന പ്രീട്രെയിൻഡ് മോഡൽ പ്രീട്രെയിനിംഗ് സമയത്ത് ആ ഡേറ്റ കണ്ടിട്ടുണ്ടെങ്കിലും, ഫൈൻ-ട്യൂണിംഗിന് ശേഷം അതിന്റെ കൂടുതൽ മെച്ചപ്പെട്ട ഒരു പതിപ്പ് നമുക്ക് ലഭിക്കുമെന്ന് നമ്മൾ കാണും.

പൂർത്തിയാകുമ്പോൾ, ഇതുപോലുള്ള പ്രവചനങ്ങൾ (predictions) നടത്താൻ കഴിവുള്ള ഒരു മോഡൽ നമുക്കുണ്ടാകും:

മുൻ ഭാഗങ്ങളിലേതുപോലെ, താഴെയുള്ള കോഡ് ഉപയോഗിച്ച് നമ്മൾ ട്രെയിൻ ചെയ്ത് Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യുന്ന യഥാർത്ഥ മോഡൽ [ഇവിടെ](https://huggingface.co/huggingface-course/marian-finetuned-kde4-en-to-fr?text=This+plugin+allows+you+to+automatically+translate+web+pages+between+several+languages.) കണ്ടെത്താനും അതിന്റെ പ്രവചനങ്ങൾ ഒന്നുകൂടി പരിശോധിക്കാനും നിങ്ങൾക്ക് കഴിയും.

## ഡേറ്റ തയ്യാറാക്കുന്നു[[preparing-the-data]]

ഒരു വിവർത്തന മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യാനോ പൂജ്യത്തിൽ നിന്ന് ട്രെയിൻ ചെയ്യാനോ, ആ ടാസ്‌ക്കിന് അനുയോജ്യമായ ഒരു ഡേറ്റാസെറ്റ് നമുക്ക് ആവശ്യമാണ്. മുമ്പ് സൂചിപ്പിച്ചതുപോലെ, ഈ ഭാഗത്തിൽ നമ്മൾ [KDE4 ഡേറ്റാസെറ്റ്](https://huggingface.co/datasets/kde4) ഉപയോഗിക്കും, എന്നാൽ നിങ്ങൾ ഏതൊക്കെ ഭാഷകളിൽ നിന്നും ഏതിലേക്കും വിവർത്തനം ചെയ്യാൻ ആഗ്രഹിക്കുന്നുവോ ആ രണ്ട് ഭാഷകളിലെയും വാക്യജോഡികൾ നിങ്ങളുടെ കൈവശമുണ്ടെങ്കിൽ, നിങ്ങളുടെ സ്വന്തം ഡേറ്റ ഉപയോഗിക്കാൻ ഈ കോഡ് വളരെ എളുപ്പത്തിൽ അനുയോജ്യമാക്കാം. നിങ്ങളുടെ ഇഷ്ടാനുസൃത ഡേറ്റ ഒരു `Dataset`-ൽ എങ്ങനെ ലോഡ് ചെയ്യാമെന്ന് ഓർമ്മിക്കേണ്ടതുണ്ടെങ്കിൽ [അധ്യായം 5](/course/chapter5) വീണ്ടും പരിശോധിക്കുക.

### KDE4 ഡേറ്റാസെറ്റ്[[the-kde4-dataset]]

പതിവുപോലെ, `load_dataset()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് നമ്മുടെ ഡേറ്റാസെറ്റ് ഡൗൺലോഡ് ചെയ്യുന്നു:

```py
from datasets import load_dataset

raw_datasets = load_dataset("kde4", lang1="en", lang2="fr")
```

മറ്റൊരു ഭാഷാജോഡിയുമായി പ്രവർത്തിക്കണമെങ്കിൽ, അവയുടെ കോഡുകൾ ഉപയോഗിച്ച് നിങ്ങൾക്ക് അവ വ്യക്തമാക്കാം. ഈ ഡേറ്റാസെറ്റിനായി മൊത്തം 92 ഭാഷകൾ ലഭ്യമാണ്; അതിന്റെ [ഡേറ്റാസെറ്റ് കാർഡിലെ](https://huggingface.co/datasets/kde4) ലാംഗ്വേജ് ടാഗുകൾ വികസിപ്പിച്ചാൽ അവയെല്ലാം നിങ്ങൾക്ക് കാണാം.

<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter7/language_tags.png" alt="KDE4 ഡേറ്റാസെറ്റിനായി ലഭ്യമായ ഭാഷകൾ." width="100%">

ഡേറ്റാസെറ്റ് ഒന്ന് നോക്കാം:

```py
raw_datasets
```

```python out
DatasetDict({
    train: Dataset({
        features: ['id', 'translation'],
        num_rows: 210173
    })
})
```

നമുക്ക് 210,173 വാക്യജോഡികളുണ്ട്, എന്നാൽ അവ ഒരൊറ്റ സ്‌പ്ലിറ്റിലാണ്; അതിനാൽ നമ്മുടെ സ്വന്തം വാലിഡേഷൻ സെറ്റ് നമ്മൾ ഉണ്ടാക്കേണ്ടിവരും. [അധ്യായം 5](/course/chapter5)-ൽ കണ്ടതുപോലെ, ഒരു `Dataset`-ന് ഇതിന് നമ്മെ സഹായിക്കുന്ന `train_test_split()` എന്ന മെത്തേഡ് ഉണ്ട്. ഫലങ്ങൾ പുനഃസൃഷ്ടിക്കാൻ (reproducibility) കഴിയുന്നതിനായി നമ്മൾ ഒരു സീഡ് നൽകും:

```py
split_datasets = raw_datasets["train"].train_test_split(train_size=0.9, seed=20)
split_datasets
```

```python out
DatasetDict({
    train: Dataset({
        features: ['id', 'translation'],
        num_rows: 189155
    })
    test: Dataset({
        features: ['id', 'translation'],
        num_rows: 21018
    })
})
```

`"test"` എന്ന കീ ഇങ്ങനെ `"validation"` എന്ന് പുനർനാമകരണം ചെയ്യാം:

```py
split_datasets["validation"] = split_datasets.pop("test")
```

ഇനി ഡേറ്റാസെറ്റിലെ ഒരു എലമെന്റ് നോക്കാം:

```py
split_datasets["train"][1]["translation"]
```

```python out
{'en': 'Default to expanded threads',
 'fr': 'Par défaut, développer les fils de discussion'}
```

നമ്മൾ ആവശ്യപ്പെട്ട ഭാഷാജോഡിയിലെ രണ്ട് വാക്യങ്ങളുള്ള ഒരു ഡിക്‌ഷണറി നമുക്ക് ലഭിക്കുന്നു. സാങ്കേതിക കമ്പ്യൂട്ടർ സയൻസ് പദങ്ങൾ നിറഞ്ഞ ഈ ഡേറ്റാസെറ്റിന്റെ ഒരു പ്രത്യേകത, അവയെല്ലാം പൂർണ്ണമായും ഫ്രഞ്ചിലേക്ക് വിവർത്തനം ചെയ്തിരിക്കുന്നു എന്നതാണ്. എന്നാൽ, ഫ്രഞ്ച് എൻജിനീയർമാർ സംസാരിക്കുമ്പോൾ കമ്പ്യൂട്ടർ സയൻസുമായി ബന്ധപ്പെട്ട മിക്ക വാക്കുകളും ഇംഗ്ലീഷിൽ തന്നെ വിടുകയാണ് പതിവ്. ഉദാഹരണത്തിന്, ഇവിടെ "threads" എന്ന വാക്ക് ഒരു ഫ്രഞ്ച് വാക്യത്തിൽ, വിശേഷിച്ചും ഒരു സാങ്കേതിക സംഭാഷണത്തിൽ, അതേപടി വരാൻ നല്ല സാധ്യതയുണ്ട്; എന്നാൽ ഈ ഡേറ്റാസെറ്റിൽ അത് കൂടുതൽ ശരിയായ "fils de discussion" എന്നതിലേക്ക് വിവർത്തനം ചെയ്തിരിക്കുന്നു. ഫ്രഞ്ച്, ഇംഗ്ലീഷ് വാക്യങ്ങളുടെ കൂടുതൽ വലിയ ഒരു കോർപ്പസിൽ പ്രീട്രെയിൻ ചെയ്ത, നമ്മൾ ഉപയോഗിക്കുന്ന പ്രീട്രെയിൻഡ് മോഡൽ, ആ വാക്ക് അതേപടി വിടുക എന്ന എളുപ്പവഴിയാണ് സ്വീകരിക്കുന്നത്:

```py
from transformers import pipeline

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
translator = pipeline("translation", model=model_checkpoint)
translator("Default to expanded threads")
```

```python out
[{'translation_text': 'Par défaut pour les threads élargis'}]
```

ഈ സ്വഭാവത്തിന്റെ മറ്റൊരു ഉദാഹരണം "plugin" എന്ന വാക്കിൽ കാണാം; ഇത് ഔദ്യോഗികമായി ഒരു ഫ്രഞ്ച് വാക്കല്ല, എന്നാൽ മിക്ക മാതൃഭാഷക്കാർക്കും അത് മനസ്സിലാകും, അവർ അത് വിവർത്തനം ചെയ്യാൻ മിനക്കെടാറുമില്ല.
KDE4 ഡേറ്റാസെറ്റിൽ ഈ വാക്ക് ഫ്രഞ്ചിൽ കൂടുതൽ ഔദ്യോഗികമായ "module d'extension" എന്നതിലേക്ക് വിവർത്തനം ചെയ്തിരിക്കുന്നു:

```py
split_datasets["train"][172]["translation"]
```

```python out
 'fr': "Impossible d'importer %1 en utilisant le module d'extension d'importation OFX. Ce fichier n'a pas un format correct."}
```

എന്നാൽ, നമ്മുടെ പ്രീട്രെയിൻഡ് മോഡൽ ഹ്രസ്വവും പരിചിതവുമായ ഇംഗ്ലീഷ് വാക്കിൽ തന്നെ ഉറച്ചുനിൽക്കുന്നു:

```py
translator(

)
```


> ✏️ **നിങ്ങളുടെ ഊഴം!** ഫ്രഞ്ചിൽ പതിവായി ഉപയോഗിക്കുന്ന മറ്റൊരു ഇംഗ്ലീഷ് വാക്കാണ് "email." ഈ വാക്ക് ഉപയോഗിക്കുന്ന ആദ്യത്തെ സാമ്പിൾ ട്രെയിനിംഗ് ഡേറ്റാസെറ്റിൽ കണ്ടെത്തുക. അത് എങ്ങനെയാണ് വിവർത്തനം ചെയ്തിരിക്കുന്നത്? അതേ ഇംഗ്ലീഷ് വാക്യം പ്രീട്രെയിൻഡ് മോഡൽ എങ്ങനെ വിവർത്തനം ചെയ്യുന്നു?

### ഡേറ്റ പ്രോസസ്സ് ചെയ്യുന്നു[[processing-the-data]]

<Youtube id="XAR8jnZZuUs"/>

ഇപ്പോൾ നിങ്ങൾക്ക് ഈ രീതി പരിചിതമായിരിക്കണം: മോഡലിന് മനസ്സിലാക്കാൻ കഴിയുന്നതിനായി ടെക്‌സ്‌റ്റുകളെല്ലാം ടോക്കൺ ID-കളുടെ സെറ്റുകളായി മാറ്റേണ്ടതുണ്ട്. ഈ ടാസ്‌ക്കിനായി, ഇൻപുട്ടുകളും ടാർഗെറ്റുകളും രണ്ടും നമ്മൾ ടോക്കണൈസ് ചെയ്യേണ്ടതുണ്ട്. നമ്മുടെ ആദ്യ ജോലി നമ്മുടെ `tokenizer` ഒബ്‌ജക്റ്റ് ഉണ്ടാക്കുകയാണ്. മുമ്പ് സൂചിപ്പിച്ചതുപോലെ, ഇംഗ്ലീഷിൽ നിന്ന് ഫ്രഞ്ചിലേക്കുള്ള ഒരു Marian പ്രീട്രെയിൻഡ് മോഡലാണ് നമ്മൾ ഉപയോഗിക്കുന്നത്. മറ്റൊരു ഭാഷാജോഡിയുമായി ഈ കോഡ് പരീക്ഷിക്കുകയാണെങ്കിൽ, മോഡൽ ചെക്ക്‌പോയിന്റ് അതിനനുസരിച്ച് മാറ്റാൻ മറക്കരുത്. [Helsinki-NLP](https://huggingface.co/Helsinki-NLP) ഓർഗനൈസേഷൻ ഒന്നിലധികം ഭാഷകളിലായി ആയിരത്തിലേറെ മോഡലുകൾ നൽകുന്നു.

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")
```

[Hub](https://huggingface.co/models)-ൽ നിന്ന് നിങ്ങൾക്ക് ഇഷ്ടമുള്ള മറ്റേതെങ്കിലും മോഡൽ ഉപയോഗിച്ചോ, അല്ലെങ്കിൽ ഒരു പ്രീട്രെയിൻഡ് മോഡലും ടോക്കണൈസറും നിങ്ങൾ സേവ് ചെയ്തിട്ടുള്ള ഒരു ലോക്കൽ ഫോൾഡർ ഉപയോഗിച്ചോ `model_checkpoint` മാറ്റാനും നിങ്ങൾക്ക് കഴിയും.

> [!TIP]
> 💡 mBART, mBART-50, അല്ലെങ്കിൽ M2M100 പോലുള്ള ഒരു ബഹുഭാഷാ ടോക്കണൈസർ നിങ്ങൾ ഉപയോഗിക്കുന്നുണ്ടെങ്കിൽ, `tokenizer.src_lang`, `tokenizer.tgt_lang` എന്നിവ ശരിയായ മൂല്യങ്ങളിലേക്ക് സെറ്റ് ചെയ്തുകൊണ്ട് നിങ്ങളുടെ ഇൻപുട്ടുകളുടെയും ടാർഗെറ്റുകളുടെയും ഭാഷാ കോഡുകൾ ടോക്കണൈസറിൽ നിങ്ങൾ സെറ്റ് ചെയ്യേണ്ടതുണ്ട്.

നമ്മുടെ ഡേറ്റ തയ്യാറാക്കുന്നത് വളരെ ലളിതമാണ്. ഓർമ്മിക്കേണ്ട ഒരേയൊരു കാര്യം ഇതാണ്: ടോക്കണൈസർ ടാർഗെറ്റുകളെ ഔട്ട്‌പുട്ട് ഭാഷയിൽ (ഇവിടെ, ഫ്രഞ്ച്) പ്രോസസ്സ് ചെയ്യുന്നുണ്ടെന്ന് നിങ്ങൾ ഉറപ്പാക്കണം. ടോക്കണൈസറിന്റെ `__call__` മെത്തേഡിന്റെ `text_targets` ആർഗ്യുമെന്റിലേക്ക് ടാർഗെറ്റുകൾ നൽകിക്കൊണ്ട് നിങ്ങൾക്ക് ഇത് ചെയ്യാം.

ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു എന്ന് കാണാൻ, ട്രെയിനിംഗ് സെറ്റിലെ ഓരോ ഭാഷയുടെയും ഒരു സാമ്പിൾ വീതം പ്രോസസ്സ് ചെയ്യാം:

```python
en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs
```

```python out
{'input_ids': [47591, 12, 9842, 19634, 9, 0], 'attention_mask': [1, 1, 1, 1, 1, 1], 'labels': [577, 5891, 2, 3184, 16, 2542, 5, 1710, 0]}
```

നമുക്ക് കാണാവുന്നതുപോലെ, ഇംഗ്ലീഷ് വാക്യവുമായി ബന്ധപ്പെട്ട ഇൻപുട്ട് ID-കൾ ഔട്ട്‌പുട്ടിൽ ഉണ്ട്, അതേസമയം ഫ്രഞ്ച് വാക്യവുമായി ബന്ധപ്പെട്ട ID-കൾ `labels` ഫീൽഡിലാണ് സൂക്ഷിച്ചിരിക്കുന്നത്. ലേബലുകളാണ് ടോക്കണൈസ് ചെയ്യുന്നത് എന്ന് സൂചിപ്പിക്കാൻ നിങ്ങൾ മറന്നാൽ, അവ ഇൻപുട്ട് ടോക്കണൈസർ ഉപയോഗിച്ചാകും ടോക്കണൈസ് ചെയ്യപ്പെടുക; ഒരു Marian മോഡലിന്റെ കാര്യത്തിൽ അത് ഒട്ടും നന്നായി വരില്ല:

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))
print(tokenizer.convert_ids_to_tokens(inputs["labels"]))
```

```python out
['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', '</s>']
['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '</s>']
```

നമുക്ക് കാണാവുന്നതുപോലെ, ഒരു ഫ്രഞ്ച് വാക്യം പ്രീപ്രോസസ്സ് ചെയ്യാൻ ഇംഗ്ലീഷ് ടോക്കണൈസർ ഉപയോഗിക്കുമ്പോൾ വളരെയധികം ടോക്കണുകൾ ഉണ്ടാകുന്നു, കാരണം ടോക്കണൈസറിന് ഫ്രഞ്ച് വാക്കുകളൊന്നും അറിയില്ല ("discussion" പോലെ ഇംഗ്ലീഷ് ഭാഷയിലും വരുന്നവ ഒഴികെ).

`inputs` നമ്മുടെ പതിവ് കീകളുള്ള (ഇൻപുട്ട് ID-കൾ, അറ്റൻഷൻ മാസ്‌ക് മുതലായവ) ഒരു ഡിക്‌ഷണറിയാണെന്നതിനാൽ, ഡേറ്റാസെറ്റുകളിൽ നമ്മൾ പ്രയോഗിക്കുന്ന പ്രീപ്രോസസ്സിംഗ് ഫംഗ്‌ഷൻ നിർവചിക്കുകയാണ് അവസാന ഘട്ടം:

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs
```

നമ്മുടെ ഇൻപുട്ടുകൾക്കും ഔട്ട്‌പുട്ടുകൾക്കും ഒരേ പരമാവധി ദൈർഘ്യമാണ് നമ്മൾ സെറ്റ് ചെയ്യുന്നത് എന്ന് ശ്രദ്ധിക്കുക. നമ്മൾ കൈകാര്യം ചെയ്യുന്ന ടെക്‌സ്‌റ്റുകൾ വളരെ ചെറുതായി തോന്നുന്നതിനാൽ, നമ്മൾ 128 ഉപയോഗിക്കുന്നു.

> [!TIP]
> 💡 നിങ്ങൾ ഒരു T5 മോഡൽ ഉപയോഗിക്കുന്നുണ്ടെങ്കിൽ (കൂടുതൽ കൃത്യമായി പറഞ്ഞാൽ, `t5-xxx` ചെക്ക്‌പോയിന്റുകളിൽ ഒന്ന്), ടെക്‌സ്‌റ്റ് ഇൻപുട്ടുകൾക്ക് `translate: English to French:` പോലെ, ചെയ്യേണ്ട ടാസ്‌ക് സൂചിപ്പിക്കുന്ന ഒരു പ്രിഫിക്‌സ് ഉണ്ടാകണമെന്ന് മോഡൽ പ്രതീക്ഷിക്കും.

> ⚠️ ടാർഗെറ്റുകളുടെ അറ്റൻഷൻ മാസ്‌കിനെ നമ്മൾ ശ്രദ്ധിക്കുന്നില്ല, കാരണം മോഡൽ അത് പ്രതീക്ഷിക്കുന്നില്ല. പകരം, ഒരു പാഡിംഗ് ടോക്കണിന് അനുയോജ്യമായ ലേബലുകൾ `-100` എന്ന് സെറ്റ് ചെയ്യണം, അങ്ങനെ ലോസ് കണക്കുകൂട്ടലിൽ അവ അവഗണിക്കപ്പെടും. നമ്മൾ ഡൈനാമിക് പാഡിംഗ് പ്രയോഗിക്കുന്നതിനാൽ ഇത് പിന്നീട് നമ്മുടെ ഡേറ്റാ കൊളേറ്റർ (data collator) ചെയ്യും, എന്നാൽ നിങ്ങൾ ഇവിടെ പാഡിംഗ് ഉപയോഗിക്കുന്നുണ്ടെങ്കിൽ, പാഡിംഗ് ടോക്കണിന് അനുയോജ്യമായ എല്ലാ ലേബലുകളും `-100` എന്ന് സെറ്റ് ചെയ്യുന്ന തരത്തിൽ പ്രീപ്രോസസ്സിംഗ് ഫംഗ്‌ഷൻ നിങ്ങൾ മാറ്റണം.

ഇപ്പോൾ ആ പ്രീപ്രോസസ്സിംഗ് നമ്മുടെ ഡേറ്റാസെറ്റിന്റെ എല്ലാ സ്‌പ്ലിറ്റുകളിലും ഒറ്റയടിക്ക് പ്രയോഗിക്കാം:

```py
tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)
```

## `Trainer` API ഉപയോഗിച്ച് മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നു[[fine-tuning-the-model-with-the-trainer-api]]

`Trainer` ഉപയോഗിക്കുന്ന യഥാർത്ഥ കോഡ് മുമ്പത്തേതുപോലെ തന്നെയായിരിക്കും, ഒരു ചെറിയ മാറ്റം മാത്രം: ഇവിടെ നമ്മൾ ഒരു [`Seq2SeqTrainer`](https://huggingface.co/transformers/main_classes/trainer.html#seq2seqtrainer) ഉപയോഗിക്കുന്നു; `Trainer`-ന്റെ ഒരു സബ്‌ക്ലാസായ ഇത്, ഇൻപുട്ടുകളിൽ നിന്ന് ഔട്ട്‌പുട്ടുകൾ പ്രവചിക്കാൻ `generate()` മെത്തേഡ് ഉപയോഗിച്ചുകൊണ്ട് ഇവാല്യുവേഷൻ ശരിയായി കൈകാര്യം ചെയ്യാൻ നമ്മെ അനുവദിക്കും. മെട്രിക് കണക്കുകൂട്ടലിനെക്കുറിച്ച് സംസാരിക്കുമ്പോൾ അതിലേക്ക് നമ്മൾ കൂടുതൽ വിശദമായി കടക്കും.

ആദ്യം ആദ്യത്തെ കാര്യം: ഫൈൻ-ട്യൂൻ ചെയ്യാൻ നമുക്ക് ഒരു യഥാർത്ഥ മോഡൽ ആവശ്യമാണ്. പതിവ് `AutoModel` API നമ്മൾ ഉപയോഗിക്കും:

```py
from transformers import AutoModelForSeq2SeqLM

model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

### ഡേറ്റാ കൊളേഷൻ[[data-collation]]

ഡൈനാമിക് ബാച്ചിംഗിനുള്ള പാഡിംഗ് കൈകാര്യം ചെയ്യാൻ നമുക്ക് ഒരു ഡേറ്റാ കൊളേറ്റർ ആവശ്യമാണ്. ഈ സാഹചര്യത്തിൽ [അധ്യായം 3](/course/chapter3)-ലേതുപോലെ ഒരു `DataCollatorWithPadding` അതേപടി ഉപയോഗിക്കാൻ കഴിയില്ല, കാരണം അത് ഇൻപുട്ടുകൾ (ഇൻപുട്ട് ID-കൾ, അറ്റൻഷൻ മാസ്‌ക്, ടോക്കൺ ടൈപ്പ് ID-കൾ) മാത്രമേ പാഡ് ചെയ്യുന്നുള്ളൂ. നമ്മുടെ ലേബലുകളും ലേബലുകളിൽ കാണുന്ന പരമാവധി ദൈർഘ്യത്തിലേക്ക് പാഡ് ചെയ്യണം. കൂടാതെ, മുമ്പ് സൂചിപ്പിച്ചതുപോലെ, ലേബലുകൾ പാഡ് ചെയ്യാൻ ഉപയോഗിക്കുന്ന പാഡിംഗ് മൂല്യം ടോക്കണൈസറിന്റെ പാഡിംഗ് ടോക്കണല്ല, `-100` ആയിരിക്കണം; അങ്ങനെ പാഡ് ചെയ്ത ആ മൂല്യങ്ങൾ ലോസ് കണക്കുകൂട്ടലിൽ അവഗണിക്കപ്പെടുമെന്ന് ഉറപ്പാക്കാം.

ഇതെല്ലാം ഒരു [`DataCollatorForSeq2Seq`](https://huggingface.co/transformers/main_classes/data_collator.html#datacollatorforseq2seq) ചെയ്യുന്നു. `DataCollatorWithPadding` പോലെ, ഇൻപുട്ടുകൾ പ്രീപ്രോസസ്സ് ചെയ്യാൻ ഉപയോഗിച്ച `tokenizer` ഇത് സ്വീകരിക്കുന്നു, എന്നാൽ `model`-ഉം ഇത് സ്വീകരിക്കുന്നു. ഡീകോഡർ ഇൻപുട്ട് ID-കൾ തയ്യാറാക്കാനുള്ള ഉത്തരവാദിത്തവും ഈ ഡേറ്റാ കൊളേറ്ററിനായിരിക്കും എന്നതാണ് ഇതിന് കാരണം; തുടക്കത്തിൽ ഒരു സ്‌പെഷ്യൽ ടോക്കണോടെ ലേബലുകളെ ഷിഫ്‌റ്റ് ചെയ്ത പതിപ്പുകളാണ് ഇവ. ഈ ഷിഫ്‌റ്റ് വ്യത്യസ്ത ആർക്കിടെക്ചറുകൾക്ക് അൽപ്പം വ്യത്യസ്തമായാണ് ചെയ്യുന്നത് എന്നതിനാൽ, `DataCollatorForSeq2Seq`-ന് `model` ഒബ്‌ജക്റ്റ് അറിയേണ്ടതുണ്ട്:

{#if fw === 'pt'}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model)
```

{:else}

```py
from transformers import DataCollatorForSeq2Seq

data_collator = DataCollatorForSeq2Seq(tokenizer, model=model, return_tensors="tf")
```

{/if}

### മെട്രിക്കുകൾ[[metrics]]

<Youtube id="M05L1DhFqcw"/>

`Seq2SeqTrainer` അതിന്റെ സൂപ്പർക്ലാസായ `Trainer`-ലേക്ക് ചേർക്കുന്ന സവിശേഷത, ഇവാല്യുവേഷൻ അല്ലെങ്കിൽ പ്രവചന സമയത്ത് `generate()` മെത്തേഡ് ഉപയോഗിക്കാനുള്ള കഴിവാണ്. ട്രെയിനിംഗ് സമയത്ത്, ട്രെയിനിംഗ് വേഗത്തിലാക്കാൻ, പ്രവചിക്കാൻ ശ്രമിക്കുന്ന ടോക്കണിന് ശേഷമുള്ള ടോക്കണുകൾ ഉപയോഗിക്കുന്നില്ലെന്ന് ഉറപ്പാക്കുന്ന ഒരു അറ്റൻഷൻ മാസ്‌കോടൊപ്പം മോഡൽ `decoder_input_ids` ഉപയോഗിക്കും. ഇൻഫറൻസ് സമയത്ത് നമുക്ക് ലേബലുകൾ ഉണ്ടാകില്ല എന്നതിനാൽ അവ ഉപയോഗിക്കാൻ കഴിയില്ല; അതിനാൽ അതേ സജ്ജീകരണത്തോടെ നമ്മുടെ മോഡൽ ഇവാല്യുവേറ്റ് ചെയ്യുന്നതാണ് നല്ലത്.

[അധ്യായം 1](/course/chapter1/6)-ൽ കണ്ടതുപോലെ, ഡീകോഡർ ടോക്കണുകൾ ഒന്നൊന്നായി പ്രവചിച്ചുകൊണ്ടാണ് ഇൻഫറൻസ് നടത്തുന്നത് — 🤗 Transformers-ൽ `generate()` മെത്തേഡ് വഴി തിരശ്ശീലയ്ക്ക് പിന്നിൽ നടപ്പിലാക്കിയിരിക്കുന്ന ഒരു കാര്യമാണിത്. `predict_with_generate=True` എന്ന് സെറ്റ് ചെയ്താൽ ഇവാല്യുവേഷനായി ആ മെത്തേഡ് ഉപയോഗിക്കാൻ `Seq2SeqTrainer` നമ്മെ അനുവദിക്കും.

{/if}

വിവർത്തനത്തിനായി പരമ്പരാഗതമായി ഉപയോഗിക്കുന്ന മെട്രിക് [BLEU സ്‌കോർ](https://en.wikipedia.org/wiki/BLEU) ആണ്; Kishore Papineni et al. [2002-ലെ ഒരു പ്രബന്ധത്തിൽ](https://aclanthology.org/P02-1040.pdf) അവതരിപ്പിച്ചതാണ് ഇത്. വിവർത്തനങ്ങൾ അവയുടെ ലേബലുകളോട് എത്ര അടുത്തുനിൽക്കുന്നു എന്ന് BLEU സ്‌കോർ വിലയിരുത്തുന്നു. മോഡൽ ജനറേറ്റ് ചെയ്ത ഔട്ട്‌പുട്ടുകളുടെ വ്യക്തതയോ വ്യാകരണശുദ്ധിയോ ഇത് അളക്കുന്നില്ല, പകരം ജനറേറ്റ് ചെയ്ത ഔട്ട്‌പുട്ടുകളിലെ എല്ലാ വാക്കുകളും ടാർഗെറ്റുകളിലും വരുന്നുണ്ടെന്ന് ഉറപ്പാക്കാൻ സ്ഥിതിവിവര നിയമങ്ങൾ (statistical rules) ഉപയോഗിക്കുന്നു. കൂടാതെ, ടാർഗെറ്റുകളിൽ ആവർത്തിക്കാത്ത അതേ വാക്കുകളുടെ ആവർത്തനങ്ങൾക്ക് (`"the the the the the"` പോലുള്ള വാക്യങ്ങൾ മോഡൽ ഔട്ട്‌പുട്ട് ചെയ്യുന്നത് ഒഴിവാക്കാൻ) പിഴ ചുമത്തുന്ന നിയമങ്ങളും, ടാർഗെറ്റുകളിലുള്ളതിനേക്കാൾ ചെറിയ ഔട്ട്‌പുട്ട് വാക്യങ്ങൾക്ക് (`"the"` പോലുള്ള വാക്യങ്ങൾ മോഡൽ ഔട്ട്‌പുട്ട് ചെയ്യുന്നത് ഒഴിവാക്കാൻ) പിഴ ചുമത്തുന്ന നിയമങ്ങളും ഉണ്ട്.

BLEU-വിന്റെ ഒരു ദൗർബല്യം, ടെക്‌സ്‌റ്റ് ഇതിനകം ടോക്കണൈസ് ചെയ്തിരിക്കണമെന്ന് ഇത് പ്രതീക്ഷിക്കുന്നു എന്നതാണ്; ഇത് വ്യത്യസ്ത ടോക്കണൈസറുകൾ ഉപയോഗിക്കുന്ന മോഡലുകൾക്കിടയിൽ സ്‌കോറുകൾ താരതമ്യം ചെയ്യുന്നത് ബുദ്ധിമുട്ടാക്കുന്നു. അതിനാൽ പകരം, ഇന്ന് വിവർത്തന മോഡലുകൾ ബെഞ്ച്‌മാർക്ക് ചെയ്യാൻ ഏറ്റവും സാധാരണയായി ഉപയോഗിക്കുന്ന മെട്രിക് [SacreBLEU](https://github.com/mjpost/sacrebleu) ആണ്; ടോക്കണൈസേഷൻ ഘട്ടം സ്‌റ്റാൻഡേർഡൈസ് ചെയ്തുകൊണ്ട് ഇത് ഈ ദൗർബല്യം (മറ്റുള്ളവയും) പരിഹരിക്കുന്നു. ഈ മെട്രിക് ഉപയോഗിക്കാൻ, ആദ്യം നമ്മൾ SacreBLEU ലൈബ്രറി ഇൻസ്‌റ്റാൾ ചെയ്യേണ്ടതുണ്ട്:

ഈ മെട്രിക് ടെക്‌സ്‌റ്റുകളെ ഇൻപുട്ടുകളായും ടാർഗെറ്റുകളായും സ്വീകരിക്കും. ഒരേ വാക്യത്തിന് പലപ്പോഴും സ്വീകാര്യമായ ഒന്നിലധികം വിവർത്തനങ്ങൾ ഉണ്ടാകാറുള്ളതിനാൽ, സ്വീകാര്യമായ പല ടാർഗെറ്റുകളും സ്വീകരിക്കാൻ കഴിയുന്ന തരത്തിലാണ് ഇത് രൂപകൽപ്പന ചെയ്തിരിക്കുന്നത് — നമ്മൾ ഉപയോഗിക്കുന്ന ഡേറ്റാസെറ്റ് ഒന്ന് മാത്രമേ നൽകുന്നുള്ളൂ, എന്നാൽ ലേബലുകളായി പല വാക്യങ്ങൾ നൽകുന്ന ഡേറ്റാസെറ്റുകൾ NLP-യിൽ കണ്ടെത്തുന്നത് അസാധാരണമല്ല. അതിനാൽ, പ്രവചനങ്ങൾ വാക്യങ്ങളുടെ ഒരു ലിസ്‌റ്റ് ആയിരിക്കണം, എന്നാൽ റഫറൻസുകൾ വാക്യങ്ങളുടെ ലിസ്‌റ്റുകളുടെ ഒരു ലിസ്‌റ്റ് ആയിരിക്കണം.

മോഡൽ ഔട്ട്‌പുട്ടുകളിൽ നിന്ന് മെട്രിക്കിന് ഉപയോഗിക്കാൻ കഴിയുന്ന ടെക്‌സ്‌റ്റുകളിലേക്ക് എത്താൻ, നമ്മൾ `tokenizer.batch_decode()` മെത്തേഡ് ഉപയോഗിക്കും. ലേബലുകളിലെ എല്ലാ `-100`-കളും വൃത്തിയാക്കിയാൽ മാത്രം മതി; പാഡിംഗ് ടോക്കണിനായി ടോക്കണൈസർ അതേ കാര്യം സ്വയമേവ ചെയ്യും. നമ്മുടെ മോഡലും ഒരു ഡേറ്റാസെറ്റും സ്വീകരിച്ച് അതിൽ മെട്രിക്കുകൾ കണക്കുകൂട്ടുന്ന ഒരു ഫംഗ്‌ഷൻ നിർവചിക്കാം. പ്രകടനം ഗണ്യമായി വർദ്ധിപ്പിക്കുന്ന ഒരു തന്ത്രവും നമ്മൾ ഉപയോഗിക്കാൻ പോകുന്നു - TensorFlow-യുടെ ആക്‌സിലറേറ്റഡ് ലീനിയർ ആൾജിബ്ര കംപൈലറായ [XLA](https://www.tensorflow.org/xla) ഉപയോഗിച്ച് നമ്മുടെ ജനറേഷൻ കോഡ് കംപൈൽ ചെയ്യുക. മോഡലിന്റെ കമ്പ്യൂട്ടേഷൻ ഗ്രാഫിൽ XLA വിവിധ ഒപ്‌റ്റിമൈസേഷനുകൾ പ്രയോഗിക്കുന്നു, അതിന്റെ ഫലമായി വേഗതയിലും മെമ്മറി ഉപയോഗത്തിലും ഗണ്യമായ മെച്ചപ്പെടുത്തലുകൾ ഉണ്ടാകുന്നു. Hugging Face [ബ്ലോഗിൽ](https://huggingface.co/blog/tf-xla-generate) വിവരിച്ചിരിക്കുന്നതുപോലെ, നമ്മുടെ ഇൻപുട്ട് ഷേപ്പുകൾ വളരെയധികം മാറാതിരിക്കുമ്പോഴാണ് XLA ഏറ്റവും നന്നായി പ്രവർത്തിക്കുന്നത്. ഇത് കൈകാര്യം ചെയ്യാൻ, നമ്മുടെ ഇൻപുട്ടുകൾ 128-ന്റെ ഗുണിതങ്ങളിലേക്ക് പാഡ് ചെയ്യുകയും പാഡിംഗ് കൊളേറ്റർ ഉപയോഗിച്ച് ഒരു പുതിയ ഡേറ്റാസെറ്റ് ഉണ്ടാക്കുകയും ചെയ്യും, തുടർന്ന് നമ്മുടെ ജനറേഷൻ ഫംഗ്‌ഷനിൽ `@tf.function(jit_compile=True)` ഡെക്കറേറ്റർ പ്രയോഗിക്കും; ഇത് മുഴുവൻ ഫംഗ്‌ഷനെയും XLA ഉപയോഗിച്ചുള്ള കംപൈലേഷനായി അടയാളപ്പെടുത്തുന്നു.

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}
```

മോഡൽ ഔട്ട്‌പുട്ടുകളിൽ നിന്ന് മെട്രിക്കിന് ഉപയോഗിക്കാൻ കഴിയുന്ന ടെക്‌സ്‌റ്റുകളിലേക്ക് എത്താൻ, നമ്മൾ `tokenizer.batch_decode()` മെത്തേഡ് ഉപയോഗിക്കും. ലേബലുകളിലെ എല്ലാ `-100`-കളും വൃത്തിയാക്കിയാൽ മാത്രം മതി (പാഡിംഗ് ടോക്കണിനായി ടോക്കണൈസർ അതേ കാര്യം സ്വയമേവ ചെയ്യും):

```py
import numpy as np


def compute_metrics(eval_preds):
    preds, labels = eval_preds
    # In case the model returns more than the prediction logits
    if isinstance(preds, tuple):
        preds = preds[0]

    decoded_preds = tokenizer.batch_decode(preds, skip_special_tokens=True)

    # Replace -100s in the labels as we can't decode them
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # Some simple post-processing
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]

    result = metric.compute(predictions=decoded_preds, references=decoded_labels)
    return {"bleu": result["score"]}
```

### മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നു[[fine-tuning-the-model]]

ഇത് പൂർത്തിയായാൽ, നമ്മുടെ മോഡൽ കംപൈൽ ചെയ്യാനും ട്രെയിൻ ചെയ്യാനും ആവശ്യമായതെല്ലാം നമുക്ക് തയ്യാറാക്കാം. `tf.keras.mixed_precision.set_global_policy("mixed_float16")`-ന്റെ ഉപയോഗം ശ്രദ്ധിക്കുക — float16 ഉപയോഗിച്ച് ട്രെയിൻ ചെയ്യാൻ ഇത് Keras-നോട് പറയും; ഇതിനെ പിന്തുണയ്ക്കുന്ന GPU-കളിൽ (Nvidia 20xx/V100 അല്ലെങ്കിൽ അതിലും പുതിയവ) ഇത് ഗണ്യമായ വേഗവർദ്ധന നൽകും.

```python
from transformers import create_optimizer
from transformers.keras_callbacks import PushToHubCallback
import tensorflow as tf

# The number of training steps is the number of samples in the dataset, divided by the batch size then multiplied
# by the total number of epochs. Note that the tf_train_dataset here is a batched tf.data.Dataset,
# not the original Hugging Face Dataset, so its len() is already num_samples // batch_size.
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=5e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)

# Train in mixed-precision float16
tf.keras.mixed_precision.set_global_policy("mixed_float16")
```

അടുത്തതായി, [ഭാഗം 2]((/course/chapter7/2))-ൽ കണ്ടതുപോലെ, ട്രെയിനിംഗ് സമയത്ത് നമ്മുടെ മോഡൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാൻ ഒരു `PushToHubCallback` നമ്മൾ നിർവചിക്കുന്നു, തുടർന്ന് ആ കോൾബാക്ക് ഉപയോഗിച്ച് മോഡൽ ഫിറ്റ് ചെയ്യുകയേ വേണ്ടൂ:

```python
from transformers.keras_callbacks import PushToHubCallback

callback = PushToHubCallback(
    output_dir="marian-finetuned-kde4-en-to-fr", tokenizer=tokenizer
)

model.fit(
    tf_train_dataset,
    validation_data=tf_eval_dataset,
    callbacks=[callback],
    epochs=num_epochs,
)
```

നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ പേര് `hub_model_id` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് നിങ്ങൾക്ക് വ്യക്തമാക്കാം എന്ന് ശ്രദ്ധിക്കുക (വിശേഷിച്ചും, ഒരു ഓർഗനൈസേഷനിലേക്ക് പുഷ് ചെയ്യാൻ നിങ്ങൾ ഈ ആർഗ്യുമെന്റ് ഉപയോഗിക്കേണ്ടിവരും). ഉദാഹരണത്തിന്, [`huggingface-course` ഓർഗനൈസേഷനിലേക്ക്](https://huggingface.co/huggingface-course) നമ്മൾ മോഡൽ പുഷ് ചെയ്തപ്പോൾ, `Seq2SeqTrainingArguments`-ലേക്ക് `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` നമ്മൾ ചേർത്തു. ഡിഫോൾട്ടായി, ഉപയോഗിക്കുന്ന റിപ്പോസിറ്ററി നിങ്ങളുടെ നെയിംസ്‌പേസിൽ ആയിരിക്കും, നിങ്ങൾ സെറ്റ് ചെയ്ത ഔട്ട്‌പുട്ട് ഡയറക്‌ടറിയുടെ പേരിലായിരിക്കും അത്; അതിനാൽ ഇവിടെ അത് `"sgugger/marian-finetuned-kde4-en-to-fr"` ആയിരിക്കും (ഈ ഭാഗത്തിന്റെ തുടക്കത്തിൽ നമ്മൾ ലിങ്ക് ചെയ്ത മോഡലാണിത്).

> [!TIP]
> 💡 നിങ്ങൾ ഉപയോഗിക്കുന്ന ഔട്ട്‌പുട്ട് ഡയറക്‌ടറി ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, അത് നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ലോക്കൽ ക്ലോൺ ആയിരിക്കണം. അല്ലെങ്കിൽ, `model.fit()` വിളിക്കുമ്പോൾ നിങ്ങൾക്ക് ഒരു എറർ ലഭിക്കും, ഒരു പുതിയ പേര് സെറ്റ് ചെയ്യേണ്ടിവരും.

അവസാനമായി, ട്രെയിനിംഗ് പൂർത്തിയായ സ്ഥിതിക്ക് നമ്മുടെ മെട്രിക്കുകൾ ഇപ്പോൾ എങ്ങനെയുണ്ടെന്ന് നോക്കാം:

ഇത് പൂർത്തിയായാൽ, നമ്മുടെ `Seq2SeqTrainingArguments` നമുക്ക് നിർവചിക്കാം. `Trainer`-ന്റെ കാര്യത്തിലേതുപോലെ, ഏതാനും ഫീൽഡുകൾ കൂടുതലായി അടങ്ങിയ `TrainingArguments`-ന്റെ ഒരു സബ്‌ക്ലാസാണ് നമ്മൾ ഉപയോഗിക്കുന്നത്:

```python
from transformers import Seq2SeqTrainingArguments

args = Seq2SeqTrainingArguments(
    f"marian-finetuned-kde4-en-to-fr",
    evaluation_strategy="no",
    save_strategy="epoch",
    learning_rate=2e-5,
    per_device_train_batch_size=32,
    per_device_eval_batch_size=64,
    weight_decay=0.01,
    save_total_limit=3,
    num_train_epochs=3,
    predict_with_generate=True,
    fp16=True,
    push_to_hub=True,
)
```

പതിവ് ഹൈപ്പർപാരാമീറ്ററുകൾ (ലേണിംഗ് റേറ്റ്, എപ്പോക്കുകളുടെ എണ്ണം, ബാച്ച് സൈസ്, കുറച്ച് വെയ്‌റ്റ് ഡികേ പോലുള്ളവ) ഒഴികെ, മുൻ ഭാഗങ്ങളിൽ കണ്ടതുമായി താരതമ്യം ചെയ്യുമ്പോൾ ഇവിടെയുള്ള ഏതാനും മാറ്റങ്ങൾ ഇതാ:

- ഇവാല്യുവേഷന് കുറച്ച് സമയമെടുക്കും എന്നതിനാൽ, പതിവായുള്ള ഇവാല്യുവേഷനൊന്നും നമ്മൾ സെറ്റ് ചെയ്യുന്നില്ല; ട്രെയിനിംഗിന് മുമ്പും ശേഷവും ഒരു തവണ മാത്രം നമ്മുടെ മോഡൽ ഇവാല്യുവേറ്റ് ചെയ്യും.
- `fp16=True` എന്ന് നമ്മൾ സെറ്റ് ചെയ്യുന്നു, ഇത് ആധുനിക GPU-കളിൽ ട്രെയിനിംഗ് വേഗത്തിലാക്കുന്നു.
- മുകളിൽ ചർച്ച ചെയ്തതുപോലെ, `predict_with_generate=True` എന്ന് നമ്മൾ സെറ്റ് ചെയ്യുന്നു.
- ഓരോ എപ്പോക്കിന്റെയും അവസാനം മോഡൽ Hub-ലേക്ക് അപ്‌ലോഡ് ചെയ്യാൻ `push_to_hub=True` നമ്മൾ ഉപയോഗിക്കുന്നു.

നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ പൂർണ്ണമായ പേര് `hub_model_id` ആർഗ്യുമെന്റ് ഉപയോഗിച്ച് നിങ്ങൾക്ക് വ്യക്തമാക്കാം എന്ന് ശ്രദ്ധിക്കുക (വിശേഷിച്ചും, ഒരു ഓർഗനൈസേഷനിലേക്ക് പുഷ് ചെയ്യാൻ നിങ്ങൾ ഈ ആർഗ്യുമെന്റ് ഉപയോഗിക്കേണ്ടിവരും). ഉദാഹരണത്തിന്, [`huggingface-course` ഓർഗനൈസേഷനിലേക്ക്](https://huggingface.co/huggingface-course) നമ്മൾ മോഡൽ പുഷ് ചെയ്തപ്പോൾ, `Seq2SeqTrainingArguments`-ലേക്ക് `hub_model_id="huggingface-course/marian-finetuned-kde4-en-to-fr"` നമ്മൾ ചേർത്തു. ഡിഫോൾട്ടായി, ഉപയോഗിക്കുന്ന റിപ്പോസിറ്ററി നിങ്ങളുടെ നെയിംസ്‌പേസിൽ ആയിരിക്കും, നിങ്ങൾ സെറ്റ് ചെയ്ത ഔട്ട്‌പുട്ട് ഡയറക്‌ടറിയുടെ പേരിലായിരിക്കും അത്; അതിനാൽ നമ്മുടെ കാര്യത്തിൽ അത് `"sgugger/marian-finetuned-kde4-en-to-fr"` ആയിരിക്കും (ഈ ഭാഗത്തിന്റെ തുടക്കത്തിൽ നമ്മൾ ലിങ്ക് ചെയ്ത മോഡലാണിത്).

> [!TIP]
> 💡 നിങ്ങൾ ഉപയോഗിക്കുന്ന ഔട്ട്‌പുട്ട് ഡയറക്‌ടറി ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, അത് നിങ്ങൾ പുഷ് ചെയ്യാൻ ആഗ്രഹിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ലോക്കൽ ക്ലോൺ ആയിരിക്കണം. അല്ലെങ്കിൽ, നിങ്ങളുടെ `Seq2SeqTrainer` നിർവചിക്കുമ്പോൾ നിങ്ങൾക്ക് ഒരു എറർ ലഭിക്കും, ഒരു പുതിയ പേര് സെറ്റ് ചെയ്യേണ്ടിവരും.


അവസാനമായി, എല്ലാം `Seq2SeqTrainer`-ന് കൈമാറുകയേ വേണ്ടൂ:

```python
from transformers import Seq2SeqTrainer

trainer = Seq2SeqTrainer(
    model,
    args,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["validation"],
    data_collator=data_collator,
    tokenizer=tokenizer,
    compute_metrics=compute_metrics,
)
```

## ഒരു ഇഷ്ടാനുസൃത ട്രെയിനിംഗ് ലൂപ്പ്[[a-custom-training-loop]]

ഇനി പൂർണ്ണമായ ട്രെയിനിംഗ് ലൂപ്പ് ഒന്ന് നോക്കാം, അങ്ങനെ നിങ്ങൾക്ക് ആവശ്യമുള്ള ഭാഗങ്ങൾ എളുപ്പത്തിൽ ഇഷ്ടാനുസൃതമാക്കാം. [ഭാഗം 2](/course/chapter7/2)-ലും [അധ്യായം 3](/course/chapter3/4)-ലും നമ്മൾ ചെയ്തതിനോട് ഇത് ഏറെ സാമ്യമുള്ളതായിരിക്കും.

### ട്രെയിനിംഗിനായി എല്ലാം തയ്യാറാക്കുന്നു[[preparing-everything-for-training]]

ഇതെല്ലാം നിങ്ങൾ ഇപ്പോൾ ഏതാനും തവണ കണ്ടിട്ടുള്ളതിനാൽ, കോഡിലൂടെ നമ്മൾ വളരെ വേഗത്തിൽ കടന്നുപോകും. ആദ്യം, PyTorch ടെൻസറുകൾ ലഭിക്കുന്നതിനായി ഡേറ്റാസെറ്റുകൾ `"torch"` ഫോർമാറ്റിലേക്ക് സെറ്റ് ചെയ്തതിന് ശേഷം, നമ്മുടെ ഡേറ്റാസെറ്റുകളിൽ നിന്ന് `DataLoader`-കൾ നമ്മൾ നിർമ്മിക്കും:

```py
from torch.utils.data import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

അടുത്തതായി, മുമ്പത്തെ ഫൈൻ-ട്യൂണിംഗ് തുടരുകയല്ല, മറിച്ച് പ്രീട്രെയിൻഡ് മോഡലിൽ നിന്ന് വീണ്ടും തുടങ്ങുകയാണ് എന്ന് ഉറപ്പാക്കാൻ, നമ്മുടെ മോഡൽ നമ്മൾ വീണ്ടും ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്നു:

```py
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

തുടർന്ന് നമുക്ക് ഒരു ഒപ്‌റ്റിമൈസർ ആവശ്യമായി വരും:

```py
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

ആ ഒബ്‌ജക്റ്റുകളെല്ലാം കൈവശമായാൽ, അവ `accelerator.prepare()` മെത്തേഡിലേക്ക് നമുക്ക് അയയ്ക്കാം. ഒരു Colab നോട്ട്‌ബുക്കിൽ TPU-കളിൽ ട്രെയിൻ ചെയ്യാൻ നിങ്ങൾ ആഗ്രഹിക്കുന്നുവെങ്കിൽ, ഈ കോഡ് മുഴുവൻ ഒരു ട്രെയിനിംഗ് ഫംഗ്‌ഷനിലേക്ക് മാറ്റേണ്ടിവരും, കൂടാതെ ഒരു `Accelerator` ഇൻസ്‌റ്റാൻഷിയേറ്റ് ചെയ്യുന്ന ഒരു സെല്ലും അത് എക്‌സിക്യൂട്ട് ചെയ്യരുത് എന്ന് ഓർമ്മിക്കുക.

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

നമ്മുടെ `train_dataloader` `accelerator.prepare()`-ലേക്ക് അയച്ചുകഴിഞ്ഞതിനാൽ, ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണം കണക്കുകൂട്ടാൻ അതിന്റെ ദൈർഘ്യം നമുക്ക് ഉപയോഗിക്കാം. ആ മെത്തേഡ് `DataLoader`-ന്റെ ദൈർഘ്യം മാറ്റും എന്നതിനാൽ, ഡേറ്റാലോഡർ തയ്യാറാക്കിയതിന് ശേഷം മാത്രമേ ഇത് എപ്പോഴും ചെയ്യാവൂ എന്ന് ഓർമ്മിക്കുക. ലേണിംഗ് റേറ്റിൽ നിന്ന് 0-ലേക്കുള്ള ഒരു ക്ലാസിക് ലീനിയർ ഷെഡ്യൂൾ നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

അവസാനമായി, നമ്മുടെ മോഡൽ Hub-ലേക്ക് പുഷ് ചെയ്യാൻ, ഒരു വർക്കിംഗ് ഫോൾഡറിൽ ഒരു `Repository` ഒബ്‌ജക്റ്റ് നമ്മൾ ഉണ്ടാക്കേണ്ടിവരും. നിങ്ങൾ ഇതിനകം ലോഗിൻ ചെയ്തിട്ടില്ലെങ്കിൽ, ആദ്യം Hugging Face Hub-ൽ ലോഗിൻ ചെയ്യുക. നമ്മുടെ മോഡലിന് നൽകാൻ ആഗ്രഹിക്കുന്ന മോഡൽ ID-യിൽ നിന്ന് റിപ്പോസിറ്ററിയുടെ പേര് നമ്മൾ നിർണ്ണയിക്കും (`repo_name` നിങ്ങളുടെ സ്വന്തം ഇഷ്ടപ്രകാരം മാറ്റാൻ മടിക്കേണ്ട; അതിൽ നിങ്ങളുടെ യൂസർനെയിം അടങ്ങിയിരിക്കണം എന്ന് മാത്രം, `get_full_repo_name()` ഫംഗ്‌ഷൻ ചെയ്യുന്നത് അതാണ്):

```py
from huggingface_hub import Repository, get_full_repo_name

model_name = "marian-finetuned-kde4-en-to-fr-accelerate"
repo_name = get_full_repo_name(model_name)
repo_name
```

```python out
'sgugger/marian-finetuned-kde4-en-to-fr-accelerate'
```

തുടർന്ന് ആ റിപ്പോസിറ്ററി ഒരു ലോക്കൽ ഫോൾഡറിലേക്ക് നമുക്ക് ക്ലോൺ ചെയ്യാം. അത് ഇതിനകം നിലവിലുണ്ടെങ്കിൽ, ഈ ലോക്കൽ ഫോൾഡർ നമ്മൾ പ്രവർത്തിക്കുന്ന റിപ്പോസിറ്ററിയുടെ ഒരു ക്ലോൺ ആയിരിക്കണം:

```py
output_dir = "marian-finetuned-kde4-en-to-fr-accelerate"
repo = Repository(output_dir, clone_from=repo_name)
```

`repo.push_to_hub()` മെത്തേഡ് വിളിച്ചുകൊണ്ട് `output_dir`-ൽ നമ്മൾ സേവ് ചെയ്യുന്ന എന്തും ഇപ്പോൾ നമുക്ക് അപ്‌ലോഡ് ചെയ്യാം. ഓരോ എപ്പോക്കിന്റെയും അവസാനം ഇടക്കാല മോഡലുകൾ അപ്‌ലോഡ് ചെയ്യാൻ ഇത് നമ്മെ സഹായിക്കും.

### ട്രെയിനിംഗ് ലൂപ്പ്[[training-loop]]

പൂർണ്ണമായ ട്രെയിനിംഗ് ലൂപ്പ് എഴുതാൻ നമ്മൾ ഇപ്പോൾ തയ്യാറാണ്. അതിന്റെ ഇവാല്യുവേഷൻ ഭാഗം ലളിതമാക്കാൻ, പ്രവചനങ്ങളും ലേബലുകളും സ്വീകരിച്ച് അവയെ നമ്മുടെ `metric` ഒബ്‌ജക്റ്റ് പ്രതീക്ഷിക്കുന്ന സ്‌ട്രിംഗുകളുടെ ലിസ്‌റ്റുകളിലേക്ക് മാറ്റുന്ന ഈ `postprocess()` ഫംഗ്‌ഷൻ നമ്മൾ നിർവചിക്കുന്നു:

```py
def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # Replace -100 in the labels as we can't decode them.
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # Some simple post-processing
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels
```

ട്രെയിനിംഗ് ലൂപ്പ് [ഭാഗം 2](/course/chapter7/2)-ലെയും [അധ്യായം 3](/course/chapter3)-ലെയും ലൂപ്പുകളോട് ഏറെ സാമ്യമുള്ളതാണ്, ഇവാല്യുവേഷൻ ഭാഗത്തിൽ ഏതാനും വ്യത്യാസങ്ങളോടെ — അതിനാൽ അതിൽ നമുക്ക് ശ്രദ്ധ കേന്ദ്രീകരിക്കാം!

ആദ്യം ശ്രദ്ധിക്കേണ്ട കാര്യം, പ്രവചനങ്ങൾ കണക്കുകൂട്ടാൻ നമ്മൾ `generate()` മെത്തേഡ് ഉപയോഗിക്കുന്നു എന്നതാണ്; എന്നാൽ ഇത് നമ്മുടെ ബേസ് മോഡലിലെ ഒരു മെത്തേഡാണ്, `prepare()` മെത്തേഡിൽ 🤗 Accelerate ഉണ്ടാക്കിയ റാപ്പ് ചെയ്ത മോഡലിലേതല്ല. അതുകൊണ്ടാണ് നമ്മൾ ആദ്യം മോഡൽ അൻറാപ്പ് (unwrap) ചെയ്ത്, പിന്നീട് ഈ മെത്തേഡ് വിളിക്കുന്നത്.

രണ്ടാമത്തെ കാര്യം, [ടോക്കൺ ക്ലാസിഫിക്കേഷനിലേതുപോലെ](/course/chapter7/2), രണ്ട് പ്രോസസ്സുകൾ ഇൻപുട്ടുകളും ലേബലുകളും വ്യത്യസ്ത ഷേപ്പുകളിലേക്ക് പാഡ് ചെയ്തിരിക്കാം എന്നതാണ്; അതിനാൽ `gather()` മെത്തേഡ് വിളിക്കുന്നതിന് മുമ്പ് പ്രവചനങ്ങളെയും ലേബലുകളെയും ഒരേ ഷേപ്പിലാക്കാൻ `accelerator.pad_across_processes()` നമ്മൾ ഉപയോഗിക്കുന്നു. ഇത് ചെയ്തില്ലെങ്കിൽ, ഇവാല്യുവേഷൻ ഒന്നുകിൽ എറർ നൽകി നിലയ്ക്കും, അല്ലെങ്കിൽ എന്നെന്നേക്കുമായി തൂങ്ങിക്കിടക്കും (hang).

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # Training
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # Evaluation
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # Necessary to pad predictions and labels for being gathered
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"epoch {epoch}, BLEU score: {results['score']:.2f}")

    # Save and upload
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```

## ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ ഉപയോഗിക്കുന്നു[[using-the-fine-tuned-model]]

നമ്മൾ ഫൈൻ-ട്യൂൻ ചെയ്ത മോഡൽ Model Hub-ൽ ഇൻഫറൻസ് വിജറ്റ് ഉപയോഗിച്ച് എങ്ങനെ ഉപയോഗിക്കാമെന്ന് നമ്മൾ ഇതിനകം നിങ്ങൾക്ക് കാണിച്ചുതന്നിട്ടുണ്ട്. ഒരു `pipeline`-ൽ അത് ലോക്കലായി ഉപയോഗിക്കാൻ, ശരിയായ മോഡൽ ഐഡന്റിഫയർ വ്യക്തമാക്കിയാൽ മാത്രം മതി:

```py
from transformers import pipeline

# Replace this with your own checkpoint
model_checkpoint = "huggingface-course/marian-finetuned-kde4-en-to-fr"
translator = pipeline("translation", model=model_checkpoint)
translator("Default to expanded threads")
```

```python out
[{'translation_text': 'Par défaut, développer les fils de discussion'}]
```

പ്രതീക്ഷിച്ചതുപോലെ, നമ്മുടെ പ്രീട്രെയിൻഡ് മോഡൽ അതിന്റെ അറിവ് നമ്മൾ ഫൈൻ-ട്യൂൻ ചെയ്ത കോർപ്പസിലേക്ക് അനുയോജ്യമാക്കി; "threads" എന്ന ഇംഗ്ലീഷ് വാക്ക് അതേപടി വിടുന്നതിന് പകരം, ഇപ്പോൾ അത് അതിന്റെ ഔദ്യോഗിക ഫ്രഞ്ച് പതിപ്പിലേക്ക് വിവർത്തനം ചെയ്യുന്നു. "plugin"-ന്റെ കാര്യത്തിലും ഇതുതന്നെയാണ് സ്ഥിതി:

```py
translator(
```
