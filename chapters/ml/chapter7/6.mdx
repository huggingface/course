ഇതുവരെ, നമ്മൾ പ്രധാനമായും പ്രീട്രെയിൻഡ് മോഡലുകൾ ഉപയോഗിക്കുകയും, പ്രീട്രെയിനിംഗിൽ നിന്നുള്ള വെയ്‌റ്റുകൾ പുനരുപയോഗിച്ച് പുതിയ ഉപയോഗ സാഹചര്യങ്ങൾക്കായി (use cases) അവയെ ഫൈൻ-ട്യൂൻ ചെയ്യുകയുമായിരുന്നു. [അധ്യായം 1](/course/chapter1)-ൽ നമ്മൾ കണ്ടതുപോലെ, ഇതിനെ സാധാരണയായി _ട്രാൻസ്ഫർ ലേണിംഗ്_ (transfer learning) എന്ന് വിളിക്കുന്നു; ലേബൽ ചെയ്ത ഡേറ്റ കുറവായ യഥാർത്ഥ ലോക ഉപയോഗ സാഹചര്യങ്ങളിൽ Transformer മോഡലുകൾ പ്രയോഗിക്കാൻ ഇത് വളരെ വിജയകരമായ ഒരു തന്ത്രമാണ്. ഈ അധ്യായത്തിൽ, നമ്മൾ വ്യത്യസ്തമായ ഒരു സമീപനം സ്വീകരിച്ച്, തീർത്തും പുതിയ ഒരു മോഡൽ പൂജ്യത്തിൽ നിന്ന് (from scratch) ട്രെയിൻ ചെയ്യും. നിങ്ങളുടെ കൈവശം ധാരാളം ഡേറ്റ ഉണ്ടെങ്കിൽ, അത് ലഭ്യമായ മോഡലുകൾക്കായി ഉപയോഗിച്ച പ്രീട്രെയിനിംഗ് ഡേറ്റയിൽ നിന്ന് വളരെ വ്യത്യസ്തവുമാണെങ്കിൽ, ഇത് സ്വീകരിക്കാൻ നല്ലൊരു സമീപനമാണ്. എന്നിരുന്നാലും, നിലവിലുള്ള ഒരു മോഡൽ ഫൈൻ-ട്യൂൻ ചെയ്യുന്നതിനെക്കാൾ വളരെയധികം കമ്പ്യൂട്ട് റിസോഴ്‌സുകൾ ഒരു ലാംഗ്വേജ് മോഡൽ പ്രീട്രെയിൻ ചെയ്യാൻ ആവശ്യമാണ്. സംഗീത സ്വരങ്ങൾ (musical notes), DNA പോലുള്ള മോളിക്യുലാർ സീക്വൻസുകൾ, അല്ലെങ്കിൽ പ്രോഗ്രാമിംഗ് ഭാഷകൾ അടങ്ങിയ ഡേറ്റാസെറ്റുകൾ, ഒരു പുതിയ മോഡൽ ട്രെയിൻ ചെയ്യുന്നത് അർത്ഥവത്താകുന്ന ഉദാഹരണങ്ങളാണ്. TabNine, OpenAI-യുടെ Codex മോഡലിന്റെ പിൻബലത്തോടെ പ്രവർത്തിക്കുന്ന GitHub-ന്റെ Copilot തുടങ്ങിയ, നീണ്ട കോഡ് സീക്വൻസുകൾ ജനറേറ്റ് ചെയ്യാൻ കഴിയുന്ന ടൂളുകൾക്ക് നന്ദി, അവസാനം പറഞ്ഞവയ്ക്ക് (പ്രോഗ്രാമിംഗ് ഭാഷകൾക്ക്) അടുത്തകാലത്ത് ഏറെ ശ്രദ്ധ ലഭിച്ചിട്ടുണ്ട്. ഈ ടെക്‌സ്‌റ്റ് ജനറേഷൻ ടാസ്‌ക് ഏറ്റവും നന്നായി കൈകാര്യം ചെയ്യുന്നത് GPT-2 പോലുള്ള ഓട്ടോ-റിഗ്രസ്സീവ് (auto-regressive) അഥവാ കോസൽ ലാംഗ്വേജ് മോഡലുകളാണ്.

ഈ ഭാഗത്തിൽ നമ്മൾ ഒരു കോഡ് ജനറേഷൻ മോഡലിന്റെ ചെറുതാക്കിയ (scaled-down) ഒരു പതിപ്പ് നിർമ്മിക്കും: Python കോഡിന്റെ ഒരു ഉപവിഭാഗം (subset) ഉപയോഗിച്ച്, പൂർണ്ണമായ ഫംഗ്‌ഷനുകൾക്കോ ക്ലാസുകൾക്കോ പകരം ഒറ്റവരി കംപ്ലീഷനുകളിലായിരിക്കും നമ്മൾ ശ്രദ്ധ കേന്ദ്രീകരിക്കുക. Python-ൽ ഡേറ്റയുമായി പ്രവർത്തിക്കുമ്പോൾ, `matplotlib`, `seaborn`, `pandas`, `scikit-learn` എന്നീ ലൈബ്രറികൾ അടങ്ങുന്ന Python ഡേറ്റാ സയൻസ് സ്‌റ്റാക്കുമായി നിങ്ങൾ നിരന്തരം ഇടപെടേണ്ടിവരും. ആ ഫ്രെയിംവർക്കുകൾ ഉപയോഗിക്കുമ്പോൾ പ്രത്യേക കമാൻഡുകൾ തിരഞ്ഞുനോക്കേണ്ടിവരുന്നത് സാധാരണമാണ്; അതിനാൽ ഈ കോളുകൾ നമുക്കായി പൂർത്തിയാക്കിത്തരാൻ ഒരു മോഡൽ ഉപയോഗിക്കാൻ കഴിഞ്ഞാൽ അത് നന്നായിരിക്കും.

## ഡേറ്റ ശേഖരിക്കുന്നു[[gathering-the-data]]

GitHub പോലുള്ള കോഡ് റിപ്പോസിറ്ററികളിൽ നിന്ന് Python കോഡ് സമൃദ്ധമായി ലഭ്യമാണ്; എല്ലാ Python റിപ്പോസിറ്ററികളും സ്‌ക്രേപ്പ് ചെയ്ത് (scraping) ഒരു ഡേറ്റാസെറ്റ് നിർമ്മിക്കാൻ ഇത് നമുക്ക് ഉപയോഗിക്കാം. ഒരു വലിയ GPT-2 മോഡൽ പ്രീട്രെയിൻ ചെയ്യാൻ [Transformers പാഠപുസ്തകത്തിൽ](https://learning.oreilly.com/library/view/natural-language-processing/9781098136789/) സ്വീകരിച്ച സമീപനം ഇതായിരുന്നു. ഏകദേശം 20 ദശലക്ഷം Python ഫയലുകൾ അടങ്ങിയ, `codeparrot` എന്ന് വിളിക്കുന്ന, ഏകദേശം 180 GB വലിപ്പമുള്ള ഒരു GitHub ഡംപ് ഉപയോഗിച്ച് രചയിതാക്കൾ ഒരു ഡേറ്റാസെറ്റ് നിർമ്മിക്കുകയും, പിന്നീട് അത് [Hugging Face Hub](https://huggingface.co/datasets/transformersbook/codeparrot)-ൽ പങ്കുവയ്ക്കുകയും ചെയ്തു.

എന്നിരുന്നാലും, മുഴുവൻ കോർപ്പസിലും ട്രെയിൻ ചെയ്യുന്നത് സമയവും കമ്പ്യൂട്ടും ഏറെ ചെലവാക്കുന്ന കാര്യമാണ്; Python ഡേറ്റാ സയൻസ് സ്‌റ്റാക്കുമായി ബന്ധപ്പെട്ട ഡേറ്റാസെറ്റിന്റെ ഉപവിഭാഗം മാത്രമേ നമുക്ക് ആവശ്യമുള്ളൂ. അതിനാൽ, ഈ സ്‌റ്റാക്കിലെ ഏതെങ്കിലും ലൈബ്രറി ഉൾപ്പെടുന്ന എല്ലാ ഫയലുകൾക്കുമായി `codeparrot` ഡേറ്റാസെറ്റ് ഫിൽറ്റർ ചെയ്തുകൊണ്ട് നമുക്ക് തുടങ്ങാം. ഡേറ്റാസെറ്റിന്റെ വലിപ്പം കാരണം, അത് ഡൗൺലോഡ് ചെയ്യുന്നത് ഒഴിവാക്കാൻ നമ്മൾ ആഗ്രഹിക്കുന്നു; പകരം, സ്‌ട്രീമിംഗ് (streaming) സവിശേഷത ഉപയോഗിച്ച് അത് തത്സമയം (on the fly) ഫിൽറ്റർ ചെയ്യും. നേരത്തെ പറഞ്ഞ ലൈബ്രറികൾ ഉപയോഗിച്ച് കോഡ് സാമ്പിളുകൾ ഫിൽറ്റർ ചെയ്യാൻ സഹായിക്കുന്നതിന്, താഴെയുള്ള ഫംഗ്‌ഷൻ നമ്മൾ ഉപയോഗിക്കും:

```py
def any_keyword_in_string(string, keywords):
    for keyword in keywords:
        if keyword in string:
            return True
    return False
```

രണ്ട് ഉദാഹരണങ്ങളിൽ ഇത് പരീക്ഷിച്ചുനോക്കാം:

```py
filters = ["pandas", "sklearn", "matplotlib", "seaborn"]
example_1 = "import numpy as np"
example_2 = "import pandas as pd"

print(
    any_keyword_in_string(example_1, filters), any_keyword_in_string(example_2, filters)
)
```

```python out
False True
```

ഡേറ്റാസെറ്റ് സ്‌ട്രീം ചെയ്ത് നമുക്ക് ആവശ്യമുള്ള എലമെന്റുകൾ ഫിൽറ്റർ ചെയ്യുന്ന ഒരു ഫംഗ്‌ഷൻ നിർമ്മിക്കാൻ ഇത് നമുക്ക് ഉപയോഗിക്കാം:

```py
from collections import defaultdict
from tqdm import tqdm
from datasets import Dataset


def filter_streaming_dataset(dataset, filters):
    filtered_dict = defaultdict(list)
    total = 0
    for sample in tqdm(iter(dataset)):
        total += 1
        if any_keyword_in_string(sample["content"], filters):
            for k, v in sample.items():
                filtered_dict[k].append(v)
    print(f"{len(filtered_dict['content'])/total:.2%} of data after filtering.")
    return Dataset.from_dict(filtered_dict)
```

തുടർന്ന് ഈ ഫംഗ്‌ഷൻ സ്‌ട്രീമിംഗ് ഡേറ്റാസെറ്റിൽ പ്രയോഗിച്ചാൽ മാത്രം മതി:

```py
# This cell will take a very long time to execute, so you should skip it and go to
# the next one!
from datasets import load_dataset

split = "train"  # "valid"
filters = ["pandas", "sklearn", "matplotlib", "seaborn"]

data = load_dataset(f"transformersbook/codeparrot-{split}", split=split, streaming=True)
filtered_data = filter_streaming_dataset(data, filters)
```

```python out
3.26% of data after filtering.
```

## ഡേറ്റാസെറ്റ് തയ്യാറാക്കുന്നു[[preparing-the-dataset]]

<Youtube id="ma1TrR7gE7I"/>

ട്രെയിനിംഗിന് ഉപയോഗിക്കാൻ കഴിയുന്ന വിധത്തിൽ ഡേറ്റ ടോക്കണൈസ് ചെയ്യുകയാണ് ആദ്യ ഘട്ടം. ചെറിയ ഫംഗ്‌ഷൻ കോളുകൾ ഓട്ടോകംപ്ലീറ്റ് ചെയ്യുകയാണ് നമ്മുടെ പ്രധാന ലക്ഷ്യം എന്നതിനാൽ, കോൺടെക്‌സ്‌റ്റ് സൈസ് (context size) താരതമ്യേന ചെറുതായി നിലനിർത്താം. മോഡൽ വളരെ വേഗത്തിൽ ട്രെയിൻ ചെയ്യാമെന്നും ഗണ്യമായി കുറഞ്ഞ മെമ്മറി മതിയെന്നുമുള്ള ഗുണം ഇതിനുണ്ട്. നിങ്ങളുടെ ആപ്ലിക്കേഷന് കൂടുതൽ കോൺടെക്‌സ്‌റ്റ് ഉണ്ടായിരിക്കുന്നത് പ്രധാനമാണെങ്കിൽ (ഉദാഹരണത്തിന്, ഫംഗ്‌ഷൻ ഡെഫനിഷൻ അടങ്ങിയ ഒരു ഫയലിനെ അടിസ്ഥാനമാക്കി യൂണിറ്റ് ടെസ്‌റ്റുകൾ എഴുതാൻ മോഡൽ വേണമെങ്കിൽ), ആ സംഖ്യ കൂട്ടാൻ മറക്കരുത്; എന്നാൽ ഇതോടൊപ്പം GPU മെമ്മറി ഉപയോഗവും കൂടുമെന്നത് ഓർമ്മയിൽ വയ്ക്കുക. തൽക്കാലം, GPT-2-ലും GPT-3-ലും ഉപയോഗിക്കുന്ന യഥാക്രമം 1,024, 2,048 എന്നിവയ്ക്ക് പകരം, കോൺടെക്‌സ്‌റ്റ് സൈസ് 128 ടോക്കണുകളായി നമുക്ക് നിശ്ചയിക്കാം.

മിക്ക ഡോക്യുമെന്റുകളിലും 128-ൽ വളരെ കൂടുതൽ ടോക്കണുകൾ ഉണ്ടാകും, അതിനാൽ ഇൻപുട്ടുകളെ പരമാവധി ദൈർഘ്യത്തിലേക്ക് വെറുതെ ട്രങ്കേറ്റ് ചെയ്യുന്നത് (truncate) നമ്മുടെ ഡേറ്റാസെറ്റിന്റെ വലിയൊരു ഭാഗം ഇല്ലാതാക്കും. പകരം, [അധ്യായം 6](/course/chapter6/4)-ൽ ചെയ്തതുപോലെ, മുഴുവൻ ഇൻപുട്ടും ടോക്കണൈസ് ചെയ്ത് അതിനെ പല ചങ്കുകളായി (chunks) വിഭജിക്കാൻ `return_overflowing_tokens` ഓപ്‌ഷൻ നമ്മൾ ഉപയോഗിക്കും. സൃഷ്ടിക്കപ്പെട്ട ഓരോ ചങ്കിന്റെയും ദൈർഘ്യം സ്വയമേവ റിട്ടേൺ ചെയ്യാൻ `return_length` ഓപ്‌ഷനും നമ്മൾ ഉപയോഗിക്കും. പലപ്പോഴും അവസാനത്തെ ചങ്ക് കോൺടെക്‌സ്‌റ്റ് സൈസിനെക്കാൾ ചെറുതായിരിക്കും; പാഡിംഗ് പ്രശ്നങ്ങൾ ഒഴിവാക്കാൻ ഈ കഷണങ്ങൾ നമ്മൾ ഒഴിവാക്കും. എന്തായാലും നമുക്ക് ധാരാളം ഡേറ്റ ഉള്ളതിനാൽ അവ യഥാർത്ഥത്തിൽ നമുക്ക് ആവശ്യമില്ല.

ആ രണ്ട് ഉദാഹരണങ്ങളിൽ നിന്ന് മൊത്തം 34 സെഗ്‌മെന്റുകൾ നമുക്ക് ലഭിക്കുന്നതായി കാണാം. ചങ്കുകളുടെ ദൈർഘ്യം നോക്കിയാൽ, രണ്ട് ഡോക്യുമെന്റുകളുടെയും അവസാനത്തെ ചങ്കുകളിൽ 128-ൽ കുറവ് ടോക്കണുകളാണ് ഉള്ളതെന്ന് കാണാം (യഥാക്രമം 117-ഉം 41-ഉം). നമ്മുടെ മൊത്തം ചങ്കുകളുടെ ഒരു ചെറിയ അംശം മാത്രമാണ് ഇവ, അതിനാൽ ഇവ സുരക്ഷിതമായി ഒഴിവാക്കാം. `overflow_to_sample_mapping` ഫീൽഡ് ഉപയോഗിച്ച്, ഏത് ചങ്കുകൾ ഏത് ഇൻപുട്ട് സാമ്പിളുകളുടേതായിരുന്നു എന്നും നമുക്ക് പുനർനിർമ്മിക്കാം.

ഈ ഓപ്പറേഷനിലൂടെ 🤗 Datasets-ലെ `Dataset.map()` ഫംഗ്‌ഷന്റെ ഉപകാരപ്രദമായ ഒരു സവിശേഷത നമ്മൾ ഉപയോഗിക്കുന്നു: അതിന് ഒന്നിനൊന്ന് (one-to-one) മാപ്പുകൾ ആവശ്യമില്ല; [ഭാഗം 3](/course/chapter7/3)-ൽ നമ്മൾ കണ്ടതുപോലെ, ഇൻപുട്ട് ബാച്ചിനെക്കാൾ കൂടുതലോ കുറവോ എലമെന്റുകളുള്ള ബാച്ചുകൾ നമുക്ക് സൃഷ്ടിക്കാം. എലമെന്റുകളുടെ എണ്ണം മാറ്റുന്ന ഡേറ്റാ ഓഗ്മെന്റേഷൻ (data augmentation) അല്ലെങ്കിൽ ഡേറ്റാ ഫിൽറ്ററിംഗ് പോലുള്ള ഓപ്പറേഷനുകൾ ചെയ്യുമ്പോൾ ഇത് ഉപകാരപ്രദമാണ്. നമ്മുടെ കാര്യത്തിൽ, ഓരോ എലമെന്റും നിശ്ചിത കോൺടെക്‌സ്‌റ്റ് സൈസുള്ള ചങ്കുകളായി ടോക്കണൈസ് ചെയ്യുമ്പോൾ, ഓരോ ഡോക്യുമെന്റിൽ നിന്നും നമ്മൾ ധാരാളം സാമ്പിളുകൾ സൃഷ്ടിക്കുന്നു. നിലവിലുള്ള കോളങ്ങൾ ഡിലീറ്റ് ചെയ്യാൻ മാത്രം നമ്മൾ ഉറപ്പാക്കണം, കാരണം അവയുടെ വലിപ്പം പൊരുത്തപ്പെടുന്നില്ല. അവ നിലനിർത്തണമെങ്കിൽ, `Dataset.map()` കോളിനുള്ളിൽ അവയെ ഉചിതമായി ആവർത്തിച്ച് റിട്ടേൺ ചെയ്യാം:

```py
def tokenize(element):
    outputs = tokenizer(
        element["content"],
        truncation=True,
        max_length=context_length,
        return_overflowing_tokens=True,
        return_length=True,
    )
    input_batch = []
    for length, input_ids in zip(outputs["length"], outputs["input_ids"]):
        if length == context_length:
            input_batch.append(input_ids)
    return {"input_ids": input_batch}


tokenized_datasets = raw_datasets.map(
    tokenize, batched=True, remove_columns=raw_datasets["train"].column_names
)
tokenized_datasets
```

ഇപ്പോൾ നമുക്ക് 128 ടോക്കണുകൾ വീതമുള്ള 16.7 ദശലക്ഷം ഉദാഹരണങ്ങളുണ്ട്, അത് മൊത്തം ഏകദേശം 2.1 ബില്യൺ ടോക്കണുകൾക്ക് തുല്യമാണ്. താരതമ്യത്തിന്, OpenAI-യുടെ GPT-3, Codex മോഡലുകൾ യഥാക്രമം 300, 100 ബില്യൺ ടോക്കണുകളിലാണ് ട്രെയിൻ ചെയ്തിരിക്കുന്നത്; അതിൽ Codex മോഡലുകൾ GPT-3 ചെക്ക്‌പോയിന്റുകളിൽ നിന്നാണ് ഇനിഷ്യലൈസ് ചെയ്യപ്പെട്ടിരിക്കുന്നത്. നീണ്ടതും യോജിപ്പുള്ളതുമായ ടെക്‌സ്‌റ്റുകൾ ജനറേറ്റ് ചെയ്യാൻ കഴിയുന്ന ഈ മോഡലുകളോട് മത്സരിക്കുകയല്ല ഈ ഭാഗത്തിലെ നമ്മുടെ ലക്ഷ്യം, മറിച്ച് ഡേറ്റാ സയന്റിസ്‌റ്റുകൾക്ക് വേഗത്തിലുള്ള ഒരു ഓട്ടോകംപ്ലീറ്റ് സൗകര്യം നൽകുന്ന ചെറുതാക്കിയ ഒരു പതിപ്പ് നിർമ്മിക്കുകയാണ്.

ഇപ്പോൾ ഡേറ്റാസെറ്റ് തയ്യാറായതിനാൽ, മോഡൽ സെറ്റപ്പ് ചെയ്യാം!

> [!TIP]
> ✏️ **പരീക്ഷിച്ചുനോക്കൂ!** ചെറിയ കോൺടെക്‌സ്‌റ്റ് വിൻഡോകളാണ് നമ്മൾ ഉപയോഗിക്കുന്നത് എന്നതിനാൽ, കോൺടെക്‌സ്‌റ്റ് സൈസിനെക്കാൾ ചെറിയ എല്ലാ ചങ്കുകളും ഒഴിവാക്കുന്നത് ഇവിടെ വലിയൊരു പ്രശ്നമായിരുന്നില്ല. കോൺടെക്‌സ്‌റ്റ് സൈസ് കൂട്ടുമ്പോൾ (അല്ലെങ്കിൽ ചെറിയ ഡോക്യുമെന്റുകളുടെ ഒരു കോർപ്പസ് നിങ്ങളുടെ കൈവശമുണ്ടെങ്കിൽ), ഒഴിവാക്കപ്പെടുന്ന ചങ്കുകളുടെ അംശവും വർദ്ധിക്കും. ഡേറ്റ തയ്യാറാക്കാനുള്ള കൂടുതൽ കാര്യക്ഷമമായ ഒരു മാർഗ്ഗം, ഒരു ബാച്ചിലെ ടോക്കണൈസ് ചെയ്ത എല്ലാ സാമ്പിളുകളും ഇടയിൽ ഒരു `eos_token_id` ടോക്കൺ ചേർത്ത് കൂട്ടിച്ചേർക്കുകയും, തുടർന്ന് കൂട്ടിച്ചേർത്ത സീക്വൻസുകളിൽ ചങ്കിംഗ് നടത്തുകയും ചെയ്യുന്നതാണ്. ഒരു അഭ്യാസമായി, ആ സമീപനം ഉപയോഗപ്പെടുത്തുന്ന വിധത്തിൽ `tokenize()` ഫംഗ്‌ഷൻ പരിഷ്‌കരിക്കുക. ടോക്കൺ ID-കളുടെ പൂർണ്ണമായ സീക്വൻസ് ലഭിക്കാൻ `truncation=False` എന്ന് സെറ്റ് ചെയ്യുകയും ടോക്കണൈസറിൽ നിന്ന് മറ്റ് ആർഗ്യുമെന്റുകൾ നീക്കം ചെയ്യുകയും വേണമെന്നത് ശ്രദ്ധിക്കുക.


## ഒരു പുതിയ മോഡൽ ഇനിഷ്യലൈസ് ചെയ്യുന്നു[[initializing-a-new-model]]

ഒരു GPT-2 മോഡൽ പുതുതായി ഇനിഷ്യലൈസ് ചെയ്യുകയാണ് നമ്മുടെ ആദ്യ ഘട്ടം. ചെറിയ GPT-2 മോഡലിന്റെ അതേ കോൺഫിഗറേഷൻ തന്നെ നമ്മുടെ മോഡലിനും നമ്മൾ ഉപയോഗിക്കും; അതിനാൽ പ്രീട്രെയിൻഡ് കോൺഫിഗറേഷൻ ലോഡ് ചെയ്ത്, ടോക്കണൈസറിന്റെ വലിപ്പം മോഡലിന്റെ വൊക്കാബുലറി വലിപ്പവുമായി പൊരുത്തപ്പെടുന്നുവെന്ന് ഉറപ്പാക്കി, `bos`, `eos` (സീക്വൻസിന്റെ ആരംഭവും അവസാനവും) ടോക്കൺ ID-കൾ നൽകുന്നു:

{#if fw === 'pt'}

```py
from transformers import AutoTokenizer, GPT2LMHeadModel, AutoConfig

config = AutoConfig.from_pretrained(
    "gpt2",
    vocab_size=len(tokenizer),
    n_ctx=context_length,
    bos_token_id=tokenizer.bos_token_id,
    eos_token_id=tokenizer.eos_token_id,
)
```

ആ കോൺഫിഗറേഷൻ ഉപയോഗിച്ച്, ഒരു പുതിയ മോഡൽ നമുക്ക് ലോഡ് ചെയ്യാം. `from_pretrained()` ഫംഗ്‌ഷൻ നമ്മൾ ഉപയോഗിക്കാത്ത ആദ്യ തവണയാണിത് എന്നത് ശ്രദ്ധിക്കുക, കാരണം യഥാർത്ഥത്തിൽ നമ്മൾ സ്വയം ഒരു മോഡൽ ഇനിഷ്യലൈസ് ചെയ്യുകയാണ്:

```py
model = GPT2LMHeadModel(config)
model_size = sum(t.numel() for t in model.parameters())
print(f"GPT-2 size: {model_size/1000**2:.1f}M parameters")
```

നമ്മുടെ മോഡലിന് നമ്മൾ ട്യൂൻ ചെയ്യേണ്ട 124M പാരാമീറ്ററുകളുണ്ട്. ട്രെയിനിംഗ് ആരംഭിക്കുന്നതിന് മുമ്പ്, ബാച്ചുകൾ സൃഷ്ടിക്കുന്ന കാര്യം ഏറ്റെടുക്കുന്ന ഒരു ഡേറ്റാ കൊളേറ്റർ (data collator) നമ്മൾ സെറ്റപ്പ് ചെയ്യേണ്ടതുണ്ട്. ലാംഗ്വേജ് മോഡലിംഗിനായി പ്രത്യേകം രൂപകൽപ്പന ചെയ്ത `DataCollatorForLanguageModeling` കൊളേറ്റർ നമുക്ക് ഉപയോഗിക്കാം (പേര് സൂക്ഷ്മമായി സൂചിപ്പിക്കുന്നതുപോലെ). ബാച്ചുകൾ സ്‌റ്റാക്ക് ചെയ്യുകയും പാഡ് ചെയ്യുകയും ചെയ്യുന്നതിനു പുറമേ, ലാംഗ്വേജ് മോഡൽ ലേബലുകൾ സൃഷ്ടിക്കുന്ന കാര്യവും ഇത് ഏറ്റെടുക്കുന്നു -- കോസൽ ലാംഗ്വേജ് മോഡലിംഗിൽ ഇൻപുട്ടുകൾ തന്നെയാണ് ലേബലുകളായും പ്രവർത്തിക്കുന്നത് (ഒരു എലമെന്റ് മാറ്റി), ട്രെയിനിംഗ് സമയത്ത് ഈ ഡേറ്റാ കൊളേറ്റർ അവ തത്സമയം സൃഷ്ടിക്കുന്നതിനാൽ `input_ids` നമ്മൾ ഡ്യൂപ്ലിക്കേറ്റ് ചെയ്യേണ്ടതില്ല.

`DataCollatorForLanguageModeling` മാസ്‌ക്‌ഡ് ലാംഗ്വേജ് മോഡലിംഗും (MLM) കോസൽ ലാംഗ്വേജ് മോഡലിംഗും (CLM) പിന്തുണയ്ക്കുന്നു എന്നത് ശ്രദ്ധിക്കുക. ഡിഫോൾട്ടായി ഇത് MLM-നായി ഡേറ്റ തയ്യാറാക്കുന്നു, എന്നാൽ `mlm=False` എന്ന ആർഗ്യുമെന്റ് സെറ്റ് ചെയ്തുകൊണ്ട് CLM-ലേക്ക് നമുക്ക് മാറാം:

{#if fw === 'pt'}

```py
from transformers import DataCollatorForLanguageModeling

tokenizer.pad_token = tokenizer.eos_token
data_collator = DataCollatorForLanguageModeling(tokenizer, mlm=False)
```

{:else}

```py
from transformers import DataCollatorForLanguageModeling

tokenizer.pad_token = tokenizer.eos_token
data_collator = DataCollatorForLanguageModeling(tokenizer, mlm=False, return_tensors="tf")
```

{/if}

ഇനി ബാക്കിയുള്ളത് ട്രെയിനിംഗ് ആർഗ്യുമെന്റുകൾ കോൺഫിഗർ ചെയ്ത് `Trainer` സ്‌റ്റാർട്ട് ചെയ്യുക മാത്രമാണ്. കുറച്ച് വാംഅപ്പോടു (warmup) കൂടിയ ഒരു കോസൈൻ ലേണിംഗ് റേറ്റ് ഷെഡ്യൂളും 256-ന്റെ ഒരു എഫക്റ്റീവ് ബാച്ച് സൈസും (`per_device_train_batch_size` * `gradient_accumulation_steps`) നമ്മൾ ഉപയോഗിക്കും. ഒരു ബാച്ച് മെമ്മറിയിൽ ഒതുങ്ങാത്തപ്പോഴാണ് ഗ്രേഡിയന്റ് അക്യുമുലേഷൻ (gradient accumulation) ഉപയോഗിക്കുന്നത്; പല ഫോർവേഡ്/ബാക്ക്‌വേഡ് പാസ്സുകളിലൂടെ ഇത് ഗ്രേഡിയന്റ് പടിപടിയായി കൂട്ടിച്ചേർക്കുന്നു. 🤗 Accelerate ഉപയോഗിച്ച് ട്രെയിനിംഗ് ലൂപ്പ് നിർമ്മിക്കുമ്പോൾ ഇത് പ്രവർത്തിക്കുന്നത് നമ്മൾ കാണും.

```py
from transformers import Trainer, TrainingArguments

args = TrainingArguments(
    output_dir="codeparrot-ds",
    per_device_train_batch_size=32,
    per_device_eval_batch_size=32,
    evaluation_strategy="steps",
    eval_steps=5_000,
    logging_steps=5_000,
    gradient_accumulation_steps=8,
    num_train_epochs=1,
    weight_decay=0.1,
    warmup_steps=1_000,
    lr_scheduler_type="cosine",
    learning_rate=5e-4,
    save_steps=5_000,
    fp16=True,
    push_to_hub=True,
)

trainer = Trainer(
    model=model,
    tokenizer=tokenizer,
    args=args,
    data_collator=data_collator,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["valid"],
)
```

ഇപ്പോൾ `Trainer` സ്‌റ്റാർട്ട് ചെയ്ത് ട്രെയിനിംഗ് പൂർത്തിയാകാൻ കാത്തിരുന്നാൽ മതി. മുഴുവൻ ട്രെയിനിംഗ് സെറ്റിലാണോ അതോ അതിന്റെ ഒരു ഉപവിഭാഗത്തിലാണോ റൺ ചെയ്യുന്നത് എന്നതിനെ ആശ്രയിച്ച്, ഇതിന് യഥാക്രമം 20 അല്ലെങ്കിൽ 2 മണിക്കൂർ എടുക്കും; അതിനാൽ കുറച്ച് കാപ്പിയും വായിക്കാൻ ഒരു നല്ല പുസ്തകവും കരുതിക്കോളൂ!

കുറച്ച് കസ്‌റ്റമൈസേഷൻ അനുവദിക്കുന്ന `Trainer` ഉപയോഗിച്ച് ഒരു മോഡൽ എങ്ങനെ ട്രെയിൻ ചെയ്യാമെന്ന് നമ്മൾ കണ്ടു. എന്നിരുന്നാലും, ചിലപ്പോൾ ട്രെയിനിംഗ് ലൂപ്പിന്മേൽ പൂർണ്ണ നിയന്ത്രണം നമുക്ക് വേണ്ടിവരും, അല്ലെങ്കിൽ അസാധാരണമായ ചില മാറ്റങ്ങൾ വരുത്താൻ നമ്മൾ ആഗ്രഹിക്കും. ഈ സാഹചര്യത്തിൽ 🤗 Accelerate ഒരു മികച്ച തിരഞ്ഞെടുപ്പാണ്; നമ്മുടെ മോഡൽ ട്രെയിൻ ചെയ്യാൻ അത് ഉപയോഗിക്കുന്നതിനുള്ള ഘട്ടങ്ങളിലൂടെ ഈ ഭാഗത്തിൽ നമ്മൾ കടന്നുപോകും. കാര്യങ്ങൾ കൂടുതൽ രസകരമാക്കാൻ, ട്രെയിനിംഗ് ലൂപ്പിൽ ഒരു ട്വിസ്‌റ്റും നമ്മൾ ചേർക്കും.

കൊള്ളാം, അത് നന്നായി പ്രവർത്തിക്കുന്നതായി തോന്നുന്നു! ഇൻപുട്ട് സീക്വൻസ്, ലോജിറ്റുകൾ (logits), നമ്മൾ ഇപ്പോൾ തിരഞ്ഞെടുത്ത കീ ടോക്കണുകൾ എന്നിവ ഇൻപുട്ടുകളായി സ്വീകരിക്കുന്ന ഒരു കസ്‌റ്റം ലോസ് ഫംഗ്‌ഷൻ ഇപ്പോൾ നമുക്ക് എഴുതാം. ആദ്യം ലോജിറ്റുകളും ഇൻപുട്ടുകളും നമ്മൾ വിന്യസിക്കണം (align): ഇൻപുട്ട് സീക്വൻസ് ഒന്ന് വലത്തോട്ട് ഷിഫ്‌റ്റ് ചെയ്തതാണ് ലേബലുകൾ, കാരണം അടുത്ത ടോക്കണാണ് നിലവിലെ ടോക്കണിന്റെ ലേബൽ. ഇൻപുട്ട് സീക്വൻസിന്റെ രണ്ടാമത്തെ ടോക്കണിൽ നിന്ന് ലേബലുകൾ ആരംഭിച്ചുകൊണ്ട് ഇത് നമുക്ക് സാധിക്കാം, കാരണം ആദ്യത്തെ ടോക്കണിനായി മോഡൽ എന്തായാലും ഒരു പ്രവചനം നടത്തുന്നില്ല. തുടർന്ന് അവസാനത്തെ ലോജിറ്റ് നമ്മൾ മുറിച്ചുമാറ്റുന്നു, കാരണം മുഴുവൻ ഇൻപുട്ട് സീക്വൻസിനും ശേഷം വരുന്ന ടോക്കണിന് നമുക്ക് ലേബൽ ഇല്ല. അതോടെ ഓരോ സാമ്പിളിനുമുള്ള ലോസ് കണക്കാക്കാനും ഓരോ സാമ്പിളിലും എല്ലാ കീവേഡുകളും എത്ര തവണ വരുന്നു എന്ന് എണ്ണാനും നമുക്ക് കഴിയും. അവസാനമായി, ആ എണ്ണങ്ങളെ വെയ്‌റ്റുകളായി ഉപയോഗിച്ച് എല്ലാ സാമ്പിളുകളുടെയും വെയ്‌റ്റഡ് ആവറേജ് (weighted average) നമ്മൾ കണക്കാക്കുന്നു. കീവേഡുകളൊന്നുമില്ലാത്ത എല്ലാ സാമ്പിളുകളും ഒഴിവാക്കാൻ നമ്മൾ ആഗ്രഹിക്കാത്തതിനാൽ, വെയ്‌റ്റുകളിലേക്ക് 1 കൂട്ടിച്ചേർക്കുന്നു:

```py
from torch.nn import CrossEntropyLoss
import torch


def keytoken_weighted_loss(inputs, logits, keytoken_ids, alpha=1.0):
    # Shift so that tokens < n predict n
    shift_labels = inputs[..., 1:].contiguous()
    shift_logits = logits[..., :-1, :].contiguous()
    # Calculate per-token loss
    loss_fct = CrossEntropyLoss(reduce=False)
    loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
    # Resize and average loss per sample
    loss_per_sample = loss.view(shift_logits.size(0), shift_logits.size(1)).mean(axis=1)
    # Calculate and scale weighting
    weights = torch.stack([(inputs == kt).float() for kt in keytoken_ids]).sum(
        axis=[0, 2]
    )
    weights = alpha * (1.0 + weights)
    # Calculate weighted average
    weighted_loss = (loss_per_sample * weights).mean()
    return weighted_loss
```

ഈ മികച്ച പുതിയ ലോസ് ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് ട്രെയിനിംഗ് ആരംഭിക്കുന്നതിന് മുമ്പ്, ചില കാര്യങ്ങൾ നമ്മൾ തയ്യാറാക്കേണ്ടതുണ്ട്:

- ഡേറ്റ ബാച്ചുകളായി ലോഡ് ചെയ്യാൻ നമുക്ക് ഡേറ്റാലോഡറുകൾ ആവശ്യമാണ്.
- വെയ്‌റ്റ് ഡികേ (weight decay) പാരാമീറ്ററുകൾ നമ്മൾ സെറ്റപ്പ് ചെയ്യേണ്ടതുണ്ട്.
- ഇടയ്ക്കിടെ ഇവാല്യുവേറ്റ് ചെയ്യാൻ നമ്മൾ ആഗ്രഹിക്കുന്നു, അതിനാൽ ഇവാല്യുവേഷൻ കോഡ് ഒരു ഫംഗ്‌ഷനിൽ പൊതിയുന്നത് അർത്ഥവത്താണ്.

ഡേറ്റാലോഡറുകളിൽ നിന്ന് തുടങ്ങാം. ഡേറ്റാസെറ്റിന്റെ ഫോർമാറ്റ് `"torch"` എന്ന് സെറ്റ് ചെയ്യുക മാത്രമേ നമ്മൾ ചെയ്യേണ്ടതുള്ളൂ, തുടർന്ന് ഉചിതമായ ബാച്ച് സൈസോടെ അത് ഒരു PyTorch `DataLoader`-ലേക്ക് നൽകാം:

```py
from torch.utils.data.dataloader import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(tokenized_datasets["train"], batch_size=32, shuffle=True)
eval_dataloader = DataLoader(tokenized_datasets["valid"], batch_size=32)
```

അടുത്തതായി, ഏതൊക്കെ പാരാമീറ്ററുകൾക്കാണ് അധിക വെയ്‌റ്റ് ഡികേ ലഭിക്കുക എന്ന് ഒപ്‌റ്റിമൈസറിന് അറിയാൻ വേണ്ടി നമ്മൾ പാരാമീറ്ററുകളെ ഗ്രൂപ്പ് ചെയ്യുന്നു. സാധാരണയായി, എല്ലാ bias, LayerNorm വെയ്‌റ്റ് ടേമുകളും ഇതിൽ നിന്ന് ഒഴിവാക്കപ്പെടുന്നു; ഇത് എങ്ങനെ ചെയ്യാമെന്ന് ഇതാ:

```py
weight_decay = 0.1


def get_grouped_params(model, no_decay=["bias", "LayerNorm.weight"]):
    params_with_wd, params_without_wd = [], []
    for n, p in model.named_parameters():
        if any(nd in n for nd in no_decay):
            params_without_wd.append(p)
        else:
            params_with_wd.append(p)
    return [
        {"params": params_with_wd, "weight_decay": weight_decay},
        {"params": params_without_wd, "weight_decay": 0.0},
    ]
```

ട്രെയിനിംഗ് സമയത്ത് വാലിഡേഷൻ സെറ്റിൽ മോഡലിനെ ക്രമമായി ഇവാല്യുവേറ്റ് ചെയ്യാൻ നമ്മൾ ആഗ്രഹിക്കുന്നതിനാൽ, അതിനായി ഒരു ഫംഗ്‌ഷനും എഴുതാം. ഇത് ഇവാല്യുവേഷൻ ഡേറ്റാലോഡറിലൂടെ കടന്നുപോയി എല്ലാ പ്രോസസ്സുകളിലുമുള്ള ലോസുകൾ ശേഖരിക്കുക മാത്രമേ ചെയ്യുന്നുള്ളൂ:

```py
def evaluate():
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(batch["input_ids"], labels=batch["input_ids"])

        losses.append(accelerator.gather(outputs.loss))
    loss = torch.mean(torch.cat(losses))
    try:
        perplexity = torch.exp(loss)
    except OverflowError:
        perplexity = float("inf")
    return loss.item(), perplexity.item()
```

`evaluate()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് കൃത്യമായ ഇടവേളകളിൽ ലോസും [പെർപ്ലെക്‌സിറ്റിയും](/course/chapter7/3) നമുക്ക് റിപ്പോർട്ട് ചെയ്യാം. അടുത്തതായി, വീണ്ടും പൂജ്യത്തിൽ നിന്ന് ട്രെയിൻ ചെയ്യുന്നു എന്ന് ഉറപ്പാക്കാൻ നമ്മുടെ മോഡൽ വീണ്ടും നിർവചിക്കുന്നു:

```py
model = GPT2LMHeadModel(config)
```

തുടർന്ന്, വെയ്‌റ്റ് ഡികേയ്ക്കായി പാരാമീറ്ററുകളെ വിഭജിക്കാൻ മുമ്പത്തെ ഫംഗ്‌ഷൻ ഉപയോഗിച്ച്, നമ്മുടെ ഒപ്‌റ്റിമൈസർ നിർവചിക്കാം:

```py
from torch.optim import AdamW

optimizer = AdamW(get_grouped_params(model), lr=5e-4)
```

ഇപ്പോൾ ട്രെയിനിംഗ് ആരംഭിക്കാൻ കഴിയുന്ന വിധത്തിൽ മോഡൽ, ഒപ്‌റ്റിമൈസർ, ഡേറ്റാലോഡറുകൾ എന്നിവ തയ്യാറാക്കാം:

```py
from accelerate import Accelerator

accelerator = Accelerator(fp16=True)

model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

> [!TIP]
> 🚨 നിങ്ങൾ ഒരു TPU-വിലാണ് ട്രെയിൻ ചെയ്യുന്നതെങ്കിൽ, മുകളിലുള്ള സെല്ലിൽ നിന്ന് ആരംഭിക്കുന്ന എല്ലാ കോഡും ഒരു പ്രത്യേക ട്രെയിനിംഗ് ഫംഗ്‌ഷനിലേക്ക് മാറ്റേണ്ടതുണ്ട്. കൂടുതൽ വിവരങ്ങൾക്ക് [അധ്യായം 3](/course/chapter3) കാണുക.

നമ്മുടെ `train_dataloader` ഇപ്പോൾ `accelerator.prepare()`-ലേക്ക് അയച്ചതിനാൽ, ട്രെയിനിംഗ് സ്‌റ്റെപ്പുകളുടെ എണ്ണം കണക്കാക്കാൻ അതിന്റെ ദൈർഘ്യം നമുക്ക് ഉപയോഗിക്കാം. ഡേറ്റാലോഡർ തയ്യാറാക്കിയ ശേഷം മാത്രമേ എപ്പോഴും ഇത് ചെയ്യാവൂ എന്ന് ഓർക്കുക, കാരണം ആ മെത്തേഡ് അതിന്റെ ദൈർഘ്യം മാറ്റും. ലേണിംഗ് റേറ്റിൽ നിന്ന് 0-ലേക്കുള്ള ക്ലാസിക് ലീനിയർ ഷെഡ്യൂൾ നമ്മൾ ഉപയോഗിക്കുന്നു:

```py
from transformers import get_scheduler

num_train_epochs = 1
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    name="linear",
    optimizer=optimizer,
    num_warmup_steps=1_000,
    num_training_steps=num_training_steps,
)
```

അവസാനമായി, നമ്മുടെ മോഡൽ Hub-ലേക്ക് പുഷ് ചെയ്യാൻ, ഒരു വർക്കിംഗ് ഫോൾഡറിൽ ഒരു `Repository` ഒബ്‌ജക്റ്റ് സൃഷ്ടിക്കേണ്ടതുണ്ട്. നിങ്ങൾ ഇതുവരെ ലോഗിൻ ചെയ്തിട്ടില്ലെങ്കിൽ, ആദ്യം Hugging Face Hub-ൽ ലോഗിൻ ചെയ്യുക. നമ്മുടെ മോഡലിന് നൽകാൻ ആഗ്രഹിക്കുന്ന മോഡൽ ID-യിൽ നിന്ന് റിപ്പോസിറ്ററിയുടെ പേര് നമ്മൾ നിർണ്ണയിക്കും (`repo_name` നിങ്ങളുടെ ഇഷ്ടപ്രകാരം മാറ്റാൻ മടിക്കേണ്ടതില്ല; അതിൽ നിങ്ങളുടെ യൂസർനെയിം അടങ്ങിയിരിക്കണം എന്നേയുള്ളൂ, അതാണ് `get_full_repo_name()` ഫംഗ്‌ഷൻ ചെയ്യുന്നത്):

ട്രെയിൻ ചെയ്യുന്നതിന് മുമ്പ്, ഇവാല്യുവേഷൻ ഫംഗ്‌ഷൻ ശരിയായി പ്രവർത്തിക്കുന്നുണ്ടോ എന്നറിയാൻ ഒരു ചെറിയ ടെസ്‌റ്റ് റൺ ചെയ്യാം:

ലോസിനും പെർപ്ലെക്‌സിറ്റിക്കും ഇവ വളരെ ഉയർന്ന മൂല്യങ്ങളാണ്, എന്നാൽ നമ്മൾ ഇതുവരെ മോഡൽ ട്രെയിൻ ചെയ്തിട്ടില്ലാത്തതിനാൽ അതിൽ അതിശയിക്കാനില്ല. അതോടെ, ട്രെയിനിംഗ് സ്‌ക്രിപ്‌റ്റിന്റെ പ്രധാന ഭാഗമായ ട്രെയിനിംഗ് ലൂപ്പ് എഴുതാൻ ആവശ്യമായതെല്ലാം നമ്മൾ തയ്യാറാക്കിക്കഴിഞ്ഞു. ട്രെയിനിംഗ് ലൂപ്പിൽ നമ്മൾ ഡേറ്റാലോഡറിലൂടെ ഇറ്ററേറ്റ് ചെയ്ത് ബാച്ചുകൾ മോഡലിലേക്ക് നൽകുന്നു. ലോജിറ്റുകൾ ഉപയോഗിച്ച്, നമ്മുടെ കസ്‌റ്റം ലോസ് ഫംഗ്‌ഷൻ തുടർന്ന് നമുക്ക് കണക്കാക്കാം. കൂടുതൽ സ്‌റ്റെപ്പുകൾ കൂട്ടിച്ചേർക്കുമ്പോൾ വലിയ ലോസുകൾ ഉണ്ടാകാതിരിക്കാൻ, ഗ്രേഡിയന്റ് അക്യുമുലേഷൻ സ്‌റ്റെപ്പുകളുടെ എണ്ണം കൊണ്ട് ലോസ് നമ്മൾ സ്‌കെയിൽ ചെയ്യുന്നു. ഒപ്‌റ്റിമൈസ് ചെയ്യുന്നതിന് മുമ്പ്, മികച്ച കൺവെർജൻസിനായി (convergence) ഗ്രേഡിയന്റുകൾ ക്ലിപ്പ് ചെയ്യുകയും ചെയ്യുന്നു. അവസാനമായി, ഓരോ കുറച്ച് സ്‌റ്റെപ്പുകൾ കഴിയുമ്പോഴും നമ്മുടെ പുതിയ `evaluate()` ഫംഗ്‌ഷൻ ഉപയോഗിച്ച് ഇവാല്യുവേഷൻ സെറ്റിൽ മോഡലിനെ ഇവാല്യുവേറ്റ് ചെയ്യുന്നു:

```py
from tqdm.notebook import tqdm

gradient_accumulation_steps = 8
eval_steps = 5_000

model.train()
completed_steps = 0
for epoch in range(num_train_epochs):
    for step, batch in tqdm(
        enumerate(train_dataloader, start=1), total=num_training_steps
    ):
        logits = model(batch["input_ids"]).logits
        loss = keytoken_weighted_loss(batch["input_ids"], logits, keytoken_ids)
        if step % 100 == 0:
            accelerator.print(
                {
                    "samples": step * samples_per_step,
                    "steps": completed_steps,
                    "loss/train": loss.item() * gradient_accumulation_steps,
                }
            )
        loss = loss / gradient_accumulation_steps
        accelerator.backward(loss)
        if step % gradient_accumulation_steps == 0:
            accelerator.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            lr_scheduler.step()
            optimizer.zero_grad()
            completed_steps += 1
        if (step % (eval_steps * gradient_accumulation_steps)) == 0:
            eval_loss, perplexity = evaluate()
            accelerator.print({"loss/eval": eval_loss, "perplexity": perplexity})
            model.train()
            accelerator.wait_for_everyone()
            unwrapped_model = accelerator.unwrap_model(model)
            unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
            if accelerator.is_main_process:
                tokenizer.save_pretrained(output_dir)
                repo.push_to_hub(
                    commit_message=f"Training in progress step {step}", blocking=False
                )
```
