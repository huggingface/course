മുൻ ഭാഗങ്ങളിൽ `Interface` ക്ലാസ് ഉപയോഗിച്ച് ഡെമോകൾ പരിശോധിക്കുകയും ഉണ്ടാക്കുകയും ചെയ്തു. ഈ ഭാഗത്തിൽ, `gradio.Blocks` എന്ന, **പുതുതായി വികസിപ്പിച്ച** നമ്മുടെ ലോ-ലെവൽ API പരിചയപ്പെടുത്തും.

ഇനി, `Interface`-ഉം `Blocks`-ഉം തമ്മിലുള്ള വ്യത്യാസം എന്താണ്?

- ⚡ `Interface`: ഇൻപുട്ടുകളുടെയും ഔട്ട്‌പുട്ടുകളുടെയും ഒരു ലിസ്‌റ്റ് നൽകുന്നതിലൂടെ മാത്രം ഒരു പൂർണ്ണ മെഷീൻ ലേണിംഗ് ഡെമോ ഉണ്ടാക്കാൻ അനുവദിക്കുന്ന ഒരു ഹൈ-ലെവൽ API.

- 🧱 `Blocks`: നിങ്ങളുടെ ആപ്ലിക്കേഷന്റെ ഡേറ്റാ ഫ്ലോകളുടെയും ലേഔട്ടിന്റെയും മേൽ പൂർണ്ണ നിയന്ത്രണം നൽകുന്ന ഒരു ലോ-ലെവൽ API. `Blocks` ("building blocks" എന്നതിലെപ്പോലെ) ഉപയോഗിച്ച് വളരെ സങ്കീർണ്ണമായ, പല ഘട്ടങ്ങളുള്ള ആപ്ലിക്കേഷനുകൾ നിങ്ങൾക്ക് നിർമ്മിക്കാം.


### എന്തിന് Blocks 🧱?[[why-blocks-]]

മുൻ ഭാഗങ്ങളിൽ കണ്ടതുപോലെ, വെറും കുറച്ച് വരി കോഡുകൊണ്ട് പൂർണ്ണ സജ്ജമായ മെഷീൻ ലേണിംഗ് ഡെമോകൾ എളുപ്പത്തിൽ ഉണ്ടാക്കാൻ `Interface` ക്ലാസ് നിങ്ങളെ അനുവദിക്കുന്നു. `Interface` API ഉപയോഗിക്കാൻ അത്യധികം എളുപ്പമാണ്, പക്ഷേ `Blocks` API നൽകുന്ന വഴക്കം (flexibility) അതിനില്ല. ഉദാഹരണത്തിന്, നിങ്ങൾക്ക് ഇവ വേണ്ടിവന്നേക്കാം:

- പരസ്പരബന്ധമുള്ള ഡെമോകൾ ഒരു വെബ് ആപ്ലിക്കേഷനിൽ ഒന്നിലധികം ടാബുകളായി ഒരുമിച്ചു ചേർക്കുക
- നിങ്ങളുടെ ഡെമോയുടെ ലേഔട്ട് മാറ്റുക, ഉദാ. ഇൻപുട്ടുകളും ഔട്ട്‌പുട്ടുകളും എവിടെ വരണം എന്ന് നിശ്ചയിക്കുക
- ഒരു മോഡലിന്റെ ഔട്ട്‌പുട്ട് അടുത്ത മോഡലിന്റെ ഇൻപുട്ടാകുന്ന, പല ഘട്ടങ്ങളുള്ള ഇന്റർഫേസുകൾ ഉണ്ടാക്കുക, അല്ലെങ്കിൽ പൊതുവേ കൂടുതൽ വഴക്കമുള്ള ഡേറ്റാ ഫ്ലോകൾ ഉണ്ടാക്കുക
- ഉപയോക്താവിന്റെ ഇൻപുട്ടിനെ അടിസ്ഥാനമാക്കി ഒരു കോംപോണന്റിന്റെ പ്രോപ്പർട്ടികൾ (ഉദാഹരണത്തിന്, ഒരു ഡ്രോപ്‌ഡൗണിലെ ചോയ്‌സുകൾ) അല്ലെങ്കിൽ അതിന്റെ ദൃശ്യത (visibility) മാറ്റുക

ഈ ആശയങ്ങളെല്ലാം താഴെ നമ്മൾ പരിശോധിക്കും.

### Blocks ഉപയോഗിച്ച് ഒരു ലളിതമായ ഡെമോ ഉണ്ടാക്കുന്നു[[creating-a-simple-demo-using-blocks]]

Gradio ഇൻസ്റ്റാൾ ചെയ്ത ശേഷം, താഴെയുള്ള കോഡ് ഒരു Python സ്‌ക്രിപ്‌റ്റായോ, ഒരു Jupyter നോട്ട്‌ബുക്കായോ, അല്ലെങ്കിൽ ഒരു Colab നോട്ട്‌ബുക്കായോ റൺ ചെയ്യുക.

```py
import gradio as gr


def flip_text(x):
    return x[::-1]


demo = gr.Blocks()

with demo:
    gr.Markdown(
        """
    # Flip Text!
    Start typing below to see the output.
    """
    )
    input = gr.Textbox(placeholder="Flip this text")
    output = gr.Textbox()

    input.change(fn=flip_text, inputs=input, outputs=output)

demo.launch()
```

മുകളിലുള്ള ഈ ലളിതമായ ഉദാഹരണം Blocks-ന്റെ അടിസ്ഥാനമായ 4 ആശയങ്ങൾ പരിചയപ്പെടുത്തുന്നു:

1. ഒരു `with gradio.Blocks` കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ Python-ൽ ഒബ്‌ജക്റ്റുകൾ ഇൻസ്റ്റാൻഷിയേറ്റ് ചെയ്യുന്നതിലൂടെ മാത്രം, markdown, HTML, ബട്ടണുകൾ, ഇന്ററാക്റ്റീവ് കോംപോണന്റുകൾ എന്നിവ സംയോജിപ്പിക്കുന്ന വെബ് ആപ്ലിക്കേഷനുകൾ നിർമ്മിക്കാൻ Blocks നിങ്ങളെ അനുവദിക്കുന്നു.
> [!TIP]
> 🙋Python-ലെ `with` സ്‌റ്റേറ്റ്‌മെന്റ് നിങ്ങൾക്ക് പരിചിതമല്ലെങ്കിൽ, Real Python-ന്റെ മികച്ച [ട്യൂട്ടോറിയൽ](https://realpython.com/python-with-statement/) പരിശോധിക്കാൻ ഞങ്ങൾ ശുപാർശ ചെയ്യുന്നു. അത് വായിച്ച ശേഷം ഇവിടെ തിരികെ വരൂ 🤗
കോംപോണന്റുകൾ ഇൻസ്റ്റാൻഷിയേറ്റ് ചെയ്യുന്ന ക്രമം പ്രധാനമാണ്, കാരണം ഓരോ എലമെന്റും ഉണ്ടാക്കിയ ക്രമത്തിലാണ് വെബ് ആപ്പിൽ റെൻഡർ ചെയ്യപ്പെടുന്നത്. (കൂടുതൽ സങ്കീർണ്ണമായ ലേഔട്ടുകൾ താഴെ ചർച്ച ചെയ്യുന്നു)

2. നിങ്ങളുടെ കോഡിൽ എവിടെയും സാധാരണ Python ഫംഗ്‌ഷനുകൾ നിർവചിക്കാനും, `Blocks` ഉപയോഗിച്ച് ഉപയോക്താവിന്റെ ഇൻപുട്ടുമായി അവ റൺ ചെയ്യാനും കഴിയും. നമ്മുടെ ഉദാഹരണത്തിൽ, ഇൻപുട്ട് ടെക്‌സ്‌റ്റ് "തിരിച്ചിടുന്ന" ഒരു ലളിതമായ ഫംഗ്‌ഷനാണുള്ളത്, പക്ഷേ ഒരു ലളിതമായ കണക്കുകൂട്ടൽ മുതൽ ഒരു മെഷീൻ ലേണിംഗ് മോഡലിന്റെ പ്രവചനങ്ങൾ പ്രോസസ്സ് ചെയ്യുന്നതു വരെ, ഏത് Python ഫംഗ്‌ഷനും നിങ്ങൾക്ക് എഴുതാം.

3. ഏത് `Blocks` കോംപോണന്റിനും ഇവന്റുകൾ അസൈൻ ചെയ്യാം. കോംപോണന്റ് ക്ലിക്ക് ചെയ്യുമ്പോഴോ, മാറുമ്പോഴോ, മറ്റും നിങ്ങളുടെ ഫംഗ്‌ഷൻ ഇത് റൺ ചെയ്യും. ഒരു ഇവന്റ് അസൈൻ ചെയ്യുമ്പോൾ, മൂന്ന് പാരാമീറ്ററുകൾ നിങ്ങൾ കൈമാറുന്നു: `fn`: വിളിക്കേണ്ട ഫംഗ്‌ഷൻ, `inputs`: ഇൻപുട്ട് കോംപോണന്റുകളുടെ (ലിസ്‌റ്റ്), `outputs`: വിളിക്കേണ്ട ഔട്ട്‌പുട്ട് കോംപോണന്റുകളുടെ (ലിസ്‌റ്റ്).

   മുകളിലുള്ള ഉദാഹരണത്തിൽ, `input` എന്ന പേരുള്ള `Textbox`-ലെ മൂല്യം മാറുമ്പോൾ നമ്മൾ `flip_text()` ഫംഗ്‌ഷൻ റൺ ചെയ്യുന്നു. ഇവന്റ് `input`-ലെ മൂല്യം വായിച്ച്, അത് name പാരാമീറ്ററായി `flip_text()`-ലേക്ക് കൈമാറുന്നു; അത് തിരികെ നൽകുന്ന മൂല്യം `output` എന്ന പേരുള്ള നമ്മുടെ രണ്ടാമത്തെ `Textbox`-ലേക്ക് അസൈൻ ചെയ്യപ്പെടുന്നു.

   ഓരോ കോംപോണന്റും പിന്തുണയ്ക്കുന്ന ഇവന്റുകളുടെ പട്ടിക കാണാൻ, Gradio [ഡോക്യുമെന്റേഷൻ](https://www.gradio.app/docs/) കാണുക.

4. നിങ്ങൾ നിർവചിക്കുന്ന ഇവന്റ് ട്രിഗറുകളെ അടിസ്ഥാനമാക്കി, ഒരു കോംപോണന്റ് ഇന്ററാക്റ്റീവ് (ഉപയോക്താവിന്റെ ഇൻപുട്ട് സ്വീകരിക്കുന്നത്) ആയിരിക്കണോ വേണ്ടയോ എന്ന് Blocks സ്വയമേവ കണ്ടെത്തുന്നു. നമ്മുടെ ഉദാഹരണത്തിൽ, ആദ്യത്തെ ടെക്‌സ്‌റ്റ്‌ബോക്‌സ് ഇന്ററാക്റ്റീവ് ആണ്, കാരണം അതിന്റെ മൂല്യം `flip_text()` ഫംഗ്‌ഷൻ ഉപയോഗിക്കുന്നു. രണ്ടാമത്തെ ടെക്‌സ്‌റ്റ്‌ബോക്‌സ് ഇന്ററാക്റ്റീവ് അല്ല, കാരണം അതിന്റെ മൂല്യം ഒരിക്കലും ഒരു ഇൻപുട്ടായി ഉപയോഗിക്കുന്നില്ല. ചില സന്ദർഭങ്ങളിൽ, ഇത് ഓവർറൈഡ് ചെയ്യാൻ നിങ്ങൾ ആഗ്രഹിച്ചേക്കാം; കോംപോണന്റിന്റെ `interactive` പാരാമീറ്ററിലേക്ക് ഒരു boolean കൈമാറിക്കൊണ്ട് അത് ചെയ്യാം (ഉദാ. `gr.Textbox(placeholder="Flip this text", interactive=True)`).

### നിങ്ങളുടെ ഡെമോയുടെ ലേഔട്ട് ഇഷ്ടാനുസൃതമാക്കുന്നു[[customizing-the-layout-of-your-demo]]

നമ്മുടെ ഡെമോയുടെ ലേഔട്ട് ഇഷ്ടാനുസൃതമാക്കാൻ `Blocks` എങ്ങനെ ഉപയോഗിക്കാം? ഡിഫോൾട്ടായി, നിങ്ങൾ ഉണ്ടാക്കുന്ന കോംപോണന്റുകൾ `Blocks` ഒരു കോളത്തിൽ ലംബമായി റെൻഡർ ചെയ്യുന്നു. `with gradio.Column():` ഉപയോഗിച്ച് അധിക കോളങ്ങളോ `with gradio.Row():` ഉപയോഗിച്ച് വരികളോ (rows) ഉണ്ടാക്കി, ആ കോൺടെക്‌സ്‌റ്റുകൾക്കുള്ളിൽ കോംപോണന്റുകൾ ഉണ്ടാക്കിക്കൊണ്ട് അത് മാറ്റാം.

ഓർത്തിരിക്കേണ്ട കാര്യം ഇതാണ്: ഒരു `Column`-നു കീഴിൽ ഉണ്ടാക്കുന്ന ഏത് കോംപോണന്റും (ഇതാണ് ഡിഫോൾട്ടും) ലംബമായി ക്രമീകരിക്കപ്പെടും. ഒരു `Row`-നു കീഴിൽ ഉണ്ടാക്കുന്ന ഏത് കോംപോണന്റും, [വെബ് ഡെവലപ്‌മെന്റിലെ flexbox മോഡലിനു](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Flexible_Box_Layout/Basic_Concepts_of_Flexbox) സമാനമായി, തിരശ്ചീനമായി ക്രമീകരിക്കപ്പെടും.

അവസാനമായി, `with gradio.Tabs()` കോൺടെക്‌സ്‌റ്റ് മാനേജർ ഉപയോഗിച്ച് നിങ്ങളുടെ ഡെമോയ്ക്ക് ടാബുകളും ഉണ്ടാക്കാം. ഈ കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ, `with gradio.TabItem(name_of_tab):` എന്ന ചൈൽഡുകൾ വ്യക്തമാക്കിക്കൊണ്ട് ഒന്നിലധികം ടാബുകൾ ഉണ്ടാക്കാം. ഒരു `with gradio.TabItem(name_of_tab):` കോൺടെക്‌സ്‌റ്റിനുള്ളിൽ ഉണ്ടാക്കുന്ന ഏത് കോംപോണന്റും ആ ടാബിൽ പ്രത്യക്ഷപ്പെടും.

ഇനി നമ്മുടെ ഡെമോയിലേക്ക് ഒരു `flip_image()` ഫംഗ്‌ഷൻ ചേർക്കുകയും, ചിത്രങ്ങൾ തിരിച്ചിടുന്ന ഒരു പുതിയ ടാബ് ചേർക്കുകയും ചെയ്യാം. താഴെ 2 ടാബുകളുള്ള, ഒരു Row-യും ഉപയോഗിക്കുന്ന ഒരു ഉദാഹരണം:

```py
import numpy as np
import gradio as gr

demo = gr.Blocks()


def flip_text(x):
    return x[::-1]


def flip_image(x):
    return np.fliplr(x)


with demo:
    gr.Markdown("Flip text or image files using this demo.")
    with gr.Tabs():
        with gr.TabItem("Flip Text"):
            with gr.Row():
                text_input = gr.Textbox()
                text_output = gr.Textbox()
            text_button = gr.Button("Flip")
        with gr.TabItem("Flip Image"):
            with gr.Row():
                image_input = gr.Image()
                image_output = gr.Image()
            image_button = gr.Button("Flip")

    text_button.click(flip_text, inputs=text_input, outputs=text_output)
    image_button.click(flip_image, inputs=image_input, outputs=image_output)

demo.launch()
```

ഈ ഉദാഹരണത്തിൽ, ഓരോ ടാബിലും ഒരു `Button` കോംപോണന്റും നമ്മൾ ഉണ്ടാക്കിയിട്ടുണ്ടെന്നും, ഓരോ ബട്ടണിനും ഒരു click ഇവന്റ് അസൈൻ ചെയ്തിട്ടുണ്ടെന്നും നിങ്ങൾ ശ്രദ്ധിക്കും; അതാണ് യഥാർത്ഥത്തിൽ ഫംഗ്‌ഷൻ റൺ ചെയ്യുന്നത്.

### ഇവന്റുകളും state-ഉം പരിശോധിക്കുന്നു[[exploring-events-and-state]]

ലേഔട്ട് നിയന്ത്രിക്കാൻ കഴിയുന്നതുപോലെ തന്നെ, ഏതെല്ലാം ഇവന്റുകൾ ഫംഗ്‌ഷൻ കോളുകൾ ട്രിഗർ ചെയ്യുന്നു എന്നതിന്മേൽ സൂക്ഷ്മമായ നിയന്ത്രണം `Blocks` നിങ്ങൾക്ക് നൽകുന്നു. ഓരോ കോംപോണന്റിനും പല ലേഔട്ടുകൾക്കും അവ പിന്തുണയ്ക്കുന്ന നിശ്ചിത ഇവന്റുകളുണ്ട്.

ഉദാഹരണത്തിന്, `Textbox` കോംപോണന്റിന് 2 ഇവന്റുകളുണ്ട്: `change()` (ടെക്‌സ്‌റ്റ്‌ബോക്‌സിനുള്ളിലെ മൂല്യം മാറുമ്പോൾ), `submit()` (ടെക്‌സ്‌റ്റ്‌ബോക്‌സിൽ ഫോക്കസ് ചെയ്തിരിക്കുമ്പോൾ ഉപയോക്താവ് enter കീ അമർത്തുമ്പോൾ). കൂടുതൽ സങ്കീർണ്ണമായ കോംപോണന്റുകൾക്ക് അതിലും കൂടുതൽ ഇവന്റുകൾ ഉണ്ടാകാം: ഉദാഹരണത്തിന്, `Audio` കോംപോണന്റിന് ഓഡിയോ ഫയൽ പ്ലേ ചെയ്യുമ്പോൾ, ക്ലിയർ ചെയ്യുമ്പോൾ, പോസ് ചെയ്യുമ്പോൾ എന്നിങ്ങനെയുള്ളവയ്ക്ക് പ്രത്യേക ഇവന്റുകളും ഉണ്ട്. ഓരോ കോംപോണന്റും പിന്തുണയ്ക്കുന്ന ഇവന്റുകൾക്കായി ഡോക്യുമെന്റേഷൻ കാണുക.

ഈ ഇവന്റുകളിൽ ഒന്നിനും അല്ലെങ്കിൽ ഒന്നോ അതിലധികമോ എണ്ണത്തിന് ഇവന്റ് ട്രിഗർ ഘടിപ്പിക്കാം. കോംപോണന്റ് ഇൻസ്‌റ്റൻസിൽ ഇവന്റിന്റെ പേര് ഒരു ഫംഗ്‌ഷനായി വിളിച്ചുകൊണ്ടാണ് ഒരു ഇവന്റ് ട്രിഗർ ഉണ്ടാക്കുന്നത് -- ഉദാ. `textbox.change(...)` അല്ലെങ്കിൽ `btn.click(...)`. മുകളിൽ ചർച്ച ചെയ്തതുപോലെ, ഈ ഫംഗ്‌ഷൻ മൂന്ന് പാരാമീറ്ററുകൾ എടുക്കുന്നു:

- `fn`: റൺ ചെയ്യേണ്ട ഫംഗ്‌ഷൻ
- `inputs`: ഫംഗ്‌ഷന്റെ ഇൻപുട്ട് പാരാമീറ്ററുകളായി മൂല്യങ്ങൾ നൽകേണ്ട കോംപോണന്റുകൾ (അവയുടെ ലിസ്‌റ്റ്). ഓരോ കോംപോണന്റിന്റെയും മൂല്യം, ക്രമത്തിൽ, അതിനോട് ചേരുന്ന ഫംഗ്‌ഷൻ പാരാമീറ്ററിലേക്ക് മാപ്പ് ചെയ്യപ്പെടുന്നു. ഫംഗ്‌ഷൻ പാരാമീറ്ററുകളൊന്നും എടുക്കുന്നില്ലെങ്കിൽ ഈ പാരാമീറ്റർ None ആകാം.
- `outputs`: ഫംഗ്‌ഷൻ തിരികെ നൽകുന്ന മൂല്യങ്ങളെ അടിസ്ഥാനമാക്കി മൂല്യങ്ങൾ പുതുക്കേണ്ട കോംപോണന്റുകൾ (അവയുടെ ലിസ്‌റ്റ്). ഓരോ റിട്ടേൺ മൂല്യവും, ക്രമത്തിൽ, അതിനോട് ചേരുന്ന കോംപോണന്റിന്റെ മൂല്യം സെറ്റ് ചെയ്യുന്നു. ഫംഗ്‌ഷൻ ഒന്നും തിരികെ നൽകുന്നില്ലെങ്കിൽ ഈ പാരാമീറ്റർ None ആകാം.

ഇൻപുട്ട്, ഔട്ട്‌പുട്ട് കോംപോണന്റ് ഒരേ കോംപോണന്റ് തന്നെയാക്കാനും കഴിയും; ടെക്‌സ്‌റ്റ് പൂർത്തീകരണത്തിനായി ഒരു GPT മോഡൽ ഉപയോഗിക്കുന്ന ഈ ഉദാഹരണത്തിൽ നമ്മൾ അങ്ങനെ ചെയ്യുന്നു:

```py
import gradio as gr

api = gr.Interface.load("huggingface/EleutherAI/gpt-j-6B")


def complete_with_gpt(text):
    # Use the last 50 characters of the text as context
    return text[:-50] + api(text[-50:])


with gr.Blocks() as demo:
    textbox = gr.Textbox(placeholder="Type here and press enter...", lines=4)
    btn = gr.Button("Generate")

    btn.click(complete_with_gpt, textbox, textbox)

demo.launch()
```

### പല ഘട്ടങ്ങളുള്ള ഡെമോകൾ ഉണ്ടാക്കുന്നു[[creating-multi-step-demos]]

ചില സന്ദർഭങ്ങളിൽ, ഒരു ഫംഗ്‌ഷന്റെ ഔട്ട്‌പുട്ട് അടുത്തതിന്റെ ഇൻപുട്ടായി പുനരുപയോഗിക്കുന്ന ഒരു _പല ഘട്ടങ്ങളുള്ള ഡെമോ_ (multi-step demo) നിങ്ങൾക്ക് വേണ്ടിവന്നേക്കാം. `Blocks` ഉപയോഗിച്ച് ഇത് വളരെ എളുപ്പമാണ്, കാരണം ഒരു കോംപോണന്റ് ഒരു ഇവന്റ് ട്രിഗറിന്റെ ഇൻപുട്ടായും മറ്റൊന്നിന്റെ ഔട്ട്‌പുട്ടായും ഉപയോഗിക്കാം. താഴെയുള്ള ഉദാഹരണത്തിലെ text കോംപോണന്റ് നോക്കുക; അതിന്റെ മൂല്യം ഒരു സ്‌പീച്ച്-ടു-ടെക്‌സ്‌റ്റ് മോഡലിന്റെ ഫലമാണ്, പക്ഷേ അത് ഒരു സെന്റിമെന്റ് അനാലിസിസ് മോഡലിലേക്കും കൈമാറപ്പെടുന്നു:

```py
from transformers import pipeline

import gradio as gr

asr = pipeline("automatic-speech-recognition", "facebook/wav2vec2-base-960h")
classifier = pipeline("text-classification")


def speech_to_text(speech):
    text = asr(speech)["text"]
    return text


def text_to_sentiment(text):
    return classifier(text)[0]["label"]


demo = gr.Blocks()

with demo:
    audio_file = gr.Audio(type="filepath")
    text = gr.Textbox()
    label = gr.Label()

    b1 = gr.Button("Recognize Speech")
    b2 = gr.Button("Classify Sentiment")

    b1.click(speech_to_text, inputs=audio_file, outputs=text)
    b2.click(text_to_sentiment, inputs=text, outputs=label)

demo.launch()
```

### കോംപോണന്റ് പ്രോപ്പർട്ടികൾ അപ്‌ഡേറ്റ് ചെയ്യുന്നു[[updating-component-properties]]

ഇതുവരെ, മറ്റൊരു കോംപോണന്റിന്റെ മൂല്യം അപ്‌ഡേറ്റ് ചെയ്യാൻ ഇവന്റുകൾ എങ്ങനെ ഉണ്ടാക്കാമെന്ന് നമ്മൾ കണ്ടു. പക്ഷേ ഒരു ടെക്‌സ്‌റ്റ്‌ബോക്‌സിന്റെ ദൃശ്യതയോ ഒരു റേഡിയോ ബട്ടൺ ഗ്രൂപ്പിലെ ചോയ്‌സുകളോ പോലെ, ഒരു കോംപോണന്റിന്റെ മറ്റു പ്രോപ്പർട്ടികൾ മാറ്റണമെങ്കിൽ എന്തു സംഭവിക്കും? നിങ്ങളുടെ ഫംഗ്‌ഷനിൽ നിന്ന് ഒരു സാധാരണ റിട്ടേൺ മൂല്യത്തിനു പകരം ഒരു കോംപോണന്റ് ക്ലാസിന്റെ `update()` മെത്തേഡ് തിരികെ നൽകിക്കൊണ്ട് നിങ്ങൾക്ക് ഇത് ചെയ്യാം.

ഒരു ഉദാഹരണത്തിലൂടെ ഇത് ഏറ്റവും എളുപ്പത്തിൽ വ്യക്തമാക്കാം:

```py
import gradio as gr


def change_textbox(choice):
    if choice == "short":
        return gr.Textbox.update(lines=2, visible=True)
    elif choice == "long":
        return gr.Textbox.update(lines=8, visible=True)
    else:
        return gr.Textbox.update(visible=False)


with gr.Blocks() as block:
    radio = gr.Radio(
        ["short", "long", "none"], label="What kind of essay would you like to write?"
    )
    text = gr.Textbox(lines=2, interactive=True)

    radio.change(fn=change_textbox, inputs=radio, outputs=text)
    block.launch()
```
