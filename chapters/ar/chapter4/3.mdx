في الخطوات التالية، سنلقي نظرة على أسهل الطرق لمشاركة النماذج المُدرَّبة مسبقًا (pretrained models) على الـ 🤗 Hub. تتوفر أدوات ووسائل مساعدة تُسهِّل مشاركة النماذج وتحديثها مباشرةً على الـ Hub، وسنستكشفها فيما يلي.

</div>

<Youtube id="9yY3RB_GSPM"/>

<div dir="rtl" style="direction:rtl;text-align:right;">

نشجّع جميع المستخدمين الذين يدرّبون النماذج على المساهمة بمشاركتها مع المجتمع (community)؛ فمشاركة النماذج، حتى تلك المُدرَّبة على مجموعات بيانات (datasets) شديدة التخصص، ستساعد الآخرين، إذ توفّر عليهم الوقت وموارد الحوسبة، وتتيح لهم الوصول إلى مخرجات تدريب مفيدة. وفي المقابل، يمكنك أنت أيضًا الاستفادة من العمل الذي أنجزه الآخرون!

هناك ثلاث طرق لإنشاء مستودعات نماذج (model repositories) جديدة:

- باستخدام واجهة `push_to_hub` البرمجية (API)
- باستخدام مكتبة `huggingface_hub` في Python
- باستخدام واجهة الويب

بعد إنشاء المستودع، يمكنك رفع الملفات إليه عبر git و git-lfs. سنرشدك في الأقسام التالية خلال خطوات إنشاء مستودعات النماذج ورفع الملفات إليها.


## استخدام واجهة `push_to_hub` البرمجية[[using-the-pushtohub-api]]

</div>

{#if fw === 'pt'}

<Youtube id="Zh0FfmVrKX0"/>

<div dir="rtl" style="direction:rtl;text-align:right;">

أبسط طريقة لرفع الملفات إلى الـ Hub هي الاستفادة من واجهة `push_to_hub` البرمجية.

قبل المتابعة، ستحتاج إلى إنشاء رمز وصول (access token) للمصادقة، حتى تتعرّف واجهة `huggingface_hub` البرمجية على هويتك وعلى فضاءات الأسماء (namespaces) التي تملك صلاحية الكتابة فيها. تأكّد من أنك تعمل في بيئة مثبَّتة فيها مكتبة `transformers` (راجع [الإعداد](/course/chapter0)). إذا كنت تعمل في دفتر (notebook)، فيمكنك استخدام الدالة التالية لتسجيل الدخول:

</div>

```python
from huggingface_hub import notebook_login

notebook_login()
```

<div dir="rtl" style="direction:rtl;text-align:right;">

أما في سطر الأوامر (terminal)، فيمكنك تشغيل:

</div>

```bash
huggingface-cli login
```

<div dir="rtl" style="direction:rtl;text-align:right;">

في كلتا الحالتين، سيُطلب منك إدخال اسم المستخدم وكلمة المرور، وهما نفسهما اللذان تستخدمهما لتسجيل الدخول إلى الـ Hub. إذا لم يكن لديك ملف شخصي على الـ Hub بعد، فعليك إنشاء واحد [من هنا](https://huggingface.co/join).

رائع! أصبح رمز الوصول الخاص بك مخزَّنًا الآن في مجلد ذاكرة التخزين المؤقت (cache). لننشئ بعض المستودعات!

</div>

{#if fw === 'pt'}

<div dir="rtl" style="direction:rtl;text-align:right;">

إذا كنت قد جرّبت واجهة `Trainer` البرمجية لتدريب نموذج، فإن أسهل طريقة لرفعه إلى الـ Hub هي ضبط `push_to_hub=True` عند تعريف `TrainingArguments`:

</div>

```py
from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)
```

<div dir="rtl" style="direction:rtl;text-align:right;">

عند استدعاء `trainer.train()`، سيرفع `Trainer` نموذجك إلى الـ Hub في كل مرة يُحفَظ فيها (هنا في نهاية كل حقبة، أي epoch) داخل مستودع في فضاء الأسماء الخاص بك. سيحمل هذا المستودع اسم مجلد المخرجات الذي اخترته (هنا `bert-finetuned-mrpc`)، لكن يمكنك اختيار اسم مختلف باستخدام `hub_model_id = "a_different_name"`.

لرفع نموذجك إلى منظمة (organization) أنت عضو فيها، يكفي تمرير اسمها عبر `hub_model_id = "my_organization/my_repo_name"`.

بعد انتهاء التدريب، عليك تنفيذ `trainer.push_to_hub()` مرة أخيرة لرفع آخر إصدار من نموذجك. سيُنشئ ذلك أيضًا بطاقة نموذج (model card) تتضمن جميع البيانات الوصفية ذات الصلة، وتعرض المعاملات الفائقة (hyperparameters) المستخدمة ونتائج التقييم! إليك مثالًا على المحتوى الذي قد تجده في بطاقة نموذج كهذه:

<div class="flex justify-center">
  <img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/model_card.png" alt="مثال على بطاقة نموذج مُنشأة تلقائيًا." width="100%"/>
</div>

</div>

{:else}

<div dir="rtl" style="direction:rtl;text-align:right;">

إذا كنت تستخدم Keras لتدريب نموذجك، فإن أسهل طريقة لرفعه إلى الـ Hub هي تمرير `PushToHubCallback` عند استدعاء `model.fit()`:

</div>

```py
from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)
```

<div dir="rtl" style="direction:rtl;text-align:right;">

بعد ذلك، عليك إضافة `callbacks=[callback]` في استدعائك لـ `model.fit()`. ستتولّى دالة الاستدعاء (callback) حينها رفع نموذجك إلى الـ Hub في كل مرة يُحفَظ فيها (هنا في نهاية كل حقبة، أي epoch) داخل مستودع في فضاء الأسماء الخاص بك. سيحمل هذا المستودع اسم مجلد المخرجات الذي اخترته (هنا `bert-finetuned-mrpc`)، لكن يمكنك اختيار اسم مختلف باستخدام `hub_model_id = "a_different_name"`.

لرفع نموذجك إلى منظمة (organization) أنت عضو فيها، يكفي تمرير اسمها عبر `hub_model_id = "my_organization/my_repo_name"`.

</div>

{/if}

<div dir="rtl" style="direction:rtl;text-align:right;">

على مستوى أدنى، يمكن الوصول إلى منصة النماذج (Model Hub) مباشرةً من كائنات النماذج والمُرمِّزات (tokenizers) والإعدادات (configuration) عبر تابعها (method) المسمّى `push_to_hub()`. يتولّى هذا التابع إنشاء المستودع ورفع ملفات النموذج والمُرمِّز مباشرةً إليه، دون الحاجة إلى أي معالجة يدوية، على عكس الواجهة البرمجية التي سنراها لاحقًا.

لتكوين فكرة عن طريقة عمله، لنبدأ أولًا بإنشاء نموذج ومُرمِّز:

</div>

{#if fw === 'pt'}
```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{:else}
```py
from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{/if}

<div dir="rtl" style="direction:rtl;text-align:right;">

لك مطلق الحرية في فعل ما تشاء بهما: إضافة رموز (tokens) إلى المُرمِّز، أو تدريب النموذج، أو ضبطه ضبطًا دقيقًا (fine-tuning). وحين تصبح راضيًا عن النموذج الناتج وأوزانه (weights) والمُرمِّز، يمكنك الاستفادة من التابع `push_to_hub()` المتاح مباشرةً على الكائن `model`:

</div>

```py
model.push_to_hub("dummy-model")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

سيؤدي ذلك إلى إنشاء المستودع الجديد `dummy-model` في ملفك الشخصي، وملئه بملفات نموذجك.
افعل الشيء نفسه مع المُرمِّز، لتصبح جميع الملفات متاحة الآن في هذا المستودع:

</div>

```py
tokenizer.push_to_hub("dummy-model")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

إذا كنت تنتمي إلى منظمة، فما عليك سوى تحديد الوسيط (argument) المسمّى `organization` للرفع إلى فضاء أسماء تلك المنظمة:

</div>

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

وإذا أردت استخدام رمز وصول معيّن من Hugging Face، فيمكنك أيضًا تمريره إلى التابع `push_to_hub()`:

</div>

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

> [!TIP]
> ✏️ **جرّبها بنفسك!** خذ النموذج والمُرمِّز المرتبطين بنقطة الحفظ (checkpoint) المسمّاة `bert-base-cased` وارفعهما إلى مستودع في فضاء الأسماء الخاص بك باستخدام التابع `push_to_hub()`. تحقّق جيدًا من ظهور المستودع بشكل صحيح في صفحتك قبل حذفه.

كما رأيت، يقبل التابع `push_to_hub()` عدة وسائط، ما يتيح الرفع إلى مستودع محدد أو إلى فضاء أسماء منظمة، أو استخدام رمز وصول مختلف للواجهة البرمجية. نوصيك بالاطلاع على توصيف هذا التابع المتاح مباشرةً في [توثيق 🤗 Transformers](https://huggingface.co/transformers/model_sharing) لتكوين فكرة عمّا هو ممكن.

يعتمد التابع `push_to_hub()` على حزمة Python المسماة [`huggingface_hub`](https://github.com/huggingface/huggingface_hub)، التي توفر واجهة برمجية مباشرة للتعامل مع Hugging Face Hub. وهي مدمجة في 🤗 Transformers وفي عدد من مكتبات تعلّم الآلة (machine learning) الأخرى، مثل [`allenlp`](https://github.com/allenai/allennlp). ومع أننا نركّز في هذا الفصل على تكاملها مع 🤗 Transformers، فإن دمجها في الكود أو المكتبة الخاصة بك أمر بسيط.

انتقل إلى القسم الأخير لترى كيفية رفع الملفات إلى مستودعك الذي أنشأته حديثًا!

## استخدام مكتبة `huggingface_hub` في Python[[using-the-huggingfacehub-python-library]]

مكتبة `huggingface_hub` في Python هي حزمة توفر مجموعة من الأدوات لمنصتَي النماذج ومجموعات البيانات. وهي تقدّم توابع وأصنافًا (classes) بسيطة للمهام الشائعة، مثل الحصول على معلومات حول المستودعات على الـ Hub وإدارتها. كما توفر واجهات برمجية بسيطة تعمل فوق git لإدارة محتوى تلك المستودعات ولدمج الـ Hub في مشاريعك ومكتباتك.

على غرار استخدام واجهة `push_to_hub` البرمجية، يتطلب هذا أن يكون رمز الوصول الخاص بك محفوظًا في ذاكرة التخزين المؤقت. ولتحقيق ذلك، ستحتاج إلى استخدام الأمر `login` من واجهة سطر الأوامر (CLI)، كما ذكرنا في القسم السابق (ومرة أخرى، تأكد من إضافة الحرف `!` قبل هذه الأوامر إذا كنت تعمل في Google Colab):

</div>

```bash
huggingface-cli login
```

<div dir="rtl" style="direction:rtl;text-align:right;">

توفر حزمة `huggingface_hub` عدة توابع وأصناف مفيدة لغرضنا. أولًا، هناك بعض التوابع لإدارة إنشاء المستودعات وحذفها وغير ذلك:

</div>

```python no-format
from huggingface_hub import (
    # User management
    login,
    logout,
    whoami,

    # Repository creation and management
    create_repo,
    delete_repo,
    update_repo_visibility,

    # And some methods to retrieve/change information about the content
    list_models,
    list_datasets,
    list_metrics,
    list_repo_files,
    upload_file,
    delete_file,
)
```

<div dir="rtl" style="direction:rtl;text-align:right;">


بالإضافة إلى ذلك، توفر الحزمة الصنف `Repository` القوي جدًا لإدارة مستودع محلي. سنستكشف هذه التوابع وهذا الصنف في الأقسام القليلة التالية لفهم كيفية الاستفادة منها.

يمكن استخدام التابع `create_repo` لإنشاء مستودع جديد على الـ Hub:

</div>

```py
from huggingface_hub import create_repo

create_repo("dummy-model")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

سيؤدي ذلك إلى إنشاء المستودع `dummy-model` في فضاء الأسماء الخاص بك. ويمكنك، إن أردت، تحديد المنظمة التي سينتمي إليها المستودع باستخدام الوسيط `organization`:

</div>

```py
from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

سيؤدي ذلك إلى إنشاء المستودع `dummy-model` في فضاء الأسماء `huggingface`، على افتراض أنك تنتمي إلى تلك المنظمة.
ومن الوسائط الأخرى التي قد تكون مفيدة:

- `private`: لتحديد ما إذا كان المستودع مرئيًا للآخرين أم لا.
- `token`: إذا أردت استبدال رمز الوصول المخزَّن في ذاكرة التخزين المؤقت برمز آخر تحدده.
- `repo_type`: إذا أردت إنشاء `dataset` (مجموعة بيانات) أو `space` (مساحة) بدلًا من نموذج. القيم المقبولة هي `"dataset"` و `"space"`.

بعد إنشاء المستودع، علينا إضافة الملفات إليه! انتقل إلى القسم التالي لترى الطرق الثلاث للقيام بذلك.


## استخدام واجهة الويب[[using-the-web-interface]]

توفر واجهة الويب أدوات لإدارة المستودعات مباشرةً على الـ Hub. وباستخدامها، يمكنك بسهولة إنشاء المستودعات، وإضافة الملفات (حتى الكبيرة منها!)، واستكشاف النماذج، وعرض الفروقات (diffs)، وغير ذلك الكثير.

لإنشاء مستودع جديد، تفضّل بزيارة [huggingface.co/new](https://huggingface.co/new):

</div>

أولًا، حدّد مالك المستودع: يمكن أن يكون أنت أو أيًّا من المنظمات التي تنتمي إليها. إذا اخترت منظمة، فسيُعرَض النموذج على صفحة المنظمة، وسيكون بمقدور كل عضو فيها المساهمة في المستودع.

بعد ذلك، أدخل اسم نموذجك، وسيكون هذا أيضًا اسم المستودع. وأخيرًا، يمكنك تحديد ما إذا كنت تريد أن يكون نموذجك عامًّا أو خاصًّا. النماذج الخاصة تكون مخفية عن العامة.

هنا سيُستضاف نموذجك. ولتبدأ في ملئه، يمكنك إضافة ملف README مباشرةً من واجهة الويب.

<div class="flex justify-center">

ملف README مكتوب بلغة Markdown، فلا تتردد في إطلاق العنان لإبداعك فيه! الجزء الثالث من هذا الفصل مخصص لإنشاء بطاقة النموذج (model card). تحظى هذه البطاقات بأهمية بالغة في إبراز قيمة نموذجك، فهي المكان الذي تخبر فيه الآخرين بما يستطيع فعله.

إذا نظرت إلى تبويب "Files and versions"، فسترى أنه لا يحتوي على ملفات كثيرة بعد: فقط ملف *README.md* الذي أنشأته للتو، وملف *.gitattributes* الذي يتتبّع الملفات الكبيرة.

## رفع ملفات النموذج[[uploading-the-model-files]]

يعتمد نظام إدارة الملفات على Hugging Face Hub على git للملفات العادية، وعلى git-lfs (اختصار لـ [Git Large File Storage](https://git-lfs.github.com/)، أي نظام Git لتخزين الملفات الكبيرة) للملفات الأكبر حجمًا.

في القسم التالي، نستعرض ثلاث طرق مختلفة لرفع الملفات إلى الـ Hub: عبر `huggingface_hub` وعبر أوامر git.

### طريقة `upload_file`[[the-uploadfile-approach]]

لا يتطلب استخدام `upload_file` تثبيت git و git-lfs على نظامك، إذ يرفع الملفات مباشرةً إلى الـ 🤗 Hub باستخدام طلبات HTTP POST. ومن قيود هذه الطريقة أنها لا تتعامل مع الملفات التي يتجاوز حجمها 5GB.
إذا كانت ملفاتك أكبر من 5GB، فيُرجى اتباع إحدى الطريقتين الأخريين الموضحتين أدناه.

يمكن استخدام هذه الواجهة البرمجية على النحو التالي:

</div>

```py
from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)
```

<div dir="rtl" style="direction:rtl;text-align:right;">

سيؤدي ذلك إلى رفع الملف `config.json` الموجود في `<path_to_file>` إلى جذر المستودع `dummy-model` باسم `config.json`.
ومن الوسائط الأخرى التي قد تكون مفيدة:

- `token`: إذا أردت استبدال رمز الوصول المخزَّن في ذاكرة التخزين المؤقت برمز آخر تحدده.
- `repo_type`: إذا أردت الرفع إلى `dataset` (مجموعة بيانات) أو `space` (مساحة) بدلًا من نموذج. القيم المقبولة هي `"dataset"` و `"space"`.


### الصنف `Repository`[[the-repository-class]]

يدير الصنف `Repository` مستودعًا محليًا بأسلوب مشابه لـ git. فهو يُخفي معظم الصعوبات التي قد يواجهها المرء مع git، ويوفّر جميع الميزات التي نحتاج إليها.

يتطلب استخدام هذا الصنف تثبيت git و git-lfs، لذا تأكد من تثبيت git-lfs (راجع [هنا](https://git-lfs.github.com/) للاطلاع على تعليمات التثبيت) وإعداده قبل أن تبدأ.

للبدء في التعامل مع المستودع الذي أنشأناه للتو، يمكننا أولًا تهيئته في مجلد محلي عن طريق استنساخ (clone) المستودع البعيد:

</div>

```py
from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

أدى ذلك إلى إنشاء المجلد `<path_to_dummy_folder>` في مجلد العمل لدينا. لا يحتوي هذا المجلد إلا على الملف `.gitattributes`، لأنه الملف الوحيد الذي يُولَّد عند إنشاء المستودع عبر `create_repo`.

ومن الآن فصاعدًا، يمكننا الاستفادة من عدد من توابع git التقليدية:

</div>

```py
repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()
```

<div dir="rtl" style="direction:rtl;text-align:right;">

وغيرها! نوصيك بالاطلاع على توثيق `Repository` المتاح [هنا](https://github.com/huggingface/huggingface_hub/tree/main/src/huggingface_hub#advanced-programmatic-repository-management) للحصول على نظرة عامة على جميع التوابع المتاحة.

لدينا حاليًا نموذج ومُرمِّز نرغب في رفعهما إلى الـ Hub. وبما أننا استنسخنا المستودع بنجاح، يمكننا الآن حفظ الملفات داخله.

نتأكد أولًا من أن نسختنا المحلية محدَّثة عن طريق سحب (pull) آخر التغييرات:

</div>

```py
repo.git_pull()
```

<div dir="rtl" style="direction:rtl;text-align:right;">

بعد ذلك، نحفظ ملفات النموذج والمُرمِّز:

</div>

```py
model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

<div dir="rtl" style="direction:rtl;text-align:right;">

يحتوي المجلد `<path_to_dummy_folder>` الآن على جميع ملفات النموذج والمُرمِّز. نتّبع سير عمل git المعتاد: نضيف الملفات إلى منطقة التجهيز (staging area)، ثم نُجري إيداعًا (commit) لها، ثم ندفعها (push) إلى الـ Hub:

</div>

```py
repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()
```

<div dir="rtl" style="direction:rtl;text-align:right;">

تهانينا! لقد دفعت للتو أول ملفاتك إلى الـ Hub.

### الطريقة القائمة على git[[the-git-based-approach]]

هذه هي الطريقة الأدنى مستوى والأقل تجريدًا لرفع الملفات: سنستخدم git و git-lfs مباشرةً. تُخفي الطرق السابقة معظم الصعوبات، لكن هناك بعض المحاذير في الطريقة التالية، لذا سنتّبع حالة استخدام أكثر تعقيدًا.

يتطلب استخدام هذا الصنف تثبيت git و git-lfs، لذا تأكد من تثبيت [git-lfs](https://git-lfs.github.com/) (راجع هنا للاطلاع على تعليمات التثبيت) وإعداده قبل أن تبدأ.

ابدأ أولًا بتهيئة git-lfs:

</div>

```bash
git lfs install
```

```bash

Git LFS initialized.
```

<div dir="rtl" style="direction:rtl;text-align:right;">

بعد ذلك، تكون الخطوة الأولى استنساخ مستودع نموذجك:

</div>

```bash
git clone https://huggingface.co/<namespace>/<your-model-id>
```

<div dir="rtl" style="direction:rtl;text-align:right;">

يُضاف الملف ذو الحجم العادي، مثل ملف إعدادات أو ملف مفردات (vocabulary) أو أي ملف لا يتجاوز حجمه بضعة ميغابايتات، تمامًا كما يُضاف في أي نظام قائم على git. أما الملفات الأكبر حجمًا، فيجب تسجيلها عبر git-lfs حتى يمكن دفعها إلى *huggingface.co*.

لنعد إلى Python قليلًا لإنشاء نموذج ومُرمِّز نرغب في إيداعهما في مستودعنا التجريبي:

```py
checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

# Do whatever with the model, train it, fine-tune it...

model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```
