# ऑप्टिमाइज्ड इन्फरन्स डिप्लॉयमेंट

या विभागात, आपण LLM डिप्लॉयमेंट्सना ऑप्टिमाइझ करण्यासाठी प्रगत फ्रेमवर्क्सचा शोध घेणार आहोत: Text Generation Inference (TGI), vLLM, आणि llama.cpp. या अ‍ॅप्लिकेशन्सचा वापर प्रामुख्याने प्रोडक्शन एन्व्हायर्नमेंट्समध्ये वापरकर्त्यांना LLMs सर्व्ह करण्यासाठी केला जातो. हा विभाग या फ्रेमवर्क्सना एकाच मशीनवर इन्फरन्ससाठी कसे वापरायचे यापेक्षा प्रोडक्शनमध्ये कसे डिप्लॉय करायचे यावर लक्ष केंद्रित करतो.

आपण या टूल्सद्वारे इन्फरन्स कार्यक्षमता कशी वाढवली जाते आणि लार्ज लँग्वेज मॉडेल्सचे प्रोडक्शन डिप्लॉयमेंट्स कसे सुलभ केले जातात याबद्दल जाणून घेऊ.

## फ्रेमवर्क निवड मार्गदर्शक

TGI, vLLM, आणि llama.cpp हे समान उद्देश पूर्ण करतात परंतु त्यांची वेगळी वैशिष्ट्ये आहेत जी त्यांना वेगवेगळ्या वापर प्रकरणांसाठी अधिक योग्य बनवतात. चला त्यांच्यातील मुख्य फरक पाहूया, कामगिरी आणि इंटिग्रेशनवर लक्ष केंद्रित करून.

### मेमरी व्यवस्थापन आणि कामगिरी

**TGI** प्रोडक्शनमध्ये स्थिर आणि अंदाज करण्यायोग्य असण्यासाठी डिझाइन केलेले आहे, मेमरी वापर सुसंगत ठेवण्यासाठी निश्चित सिक्वेन्स लांबी वापरते. TGI Flash Attention 2 आणि सतत बॅचिंग (continuous batching) तंत्रांचा वापर करून मेमरी व्यवस्थापित करते. याचा अर्थ ते अटेंशन गणना खूप कार्यक्षमतेने प्रक्रिया करू शकते आणि GPU ला सतत काम पुरवून व्यस्त ठेवू शकते. आवश्यकतेनुसार प्रणाली मॉडेलचे भाग CPU आणि GPU दरम्यान हलवू शकते, ज्यामुळे मोठ्या मॉडेल्सना हाताळण्यास मदत होते.

<img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/tgi/flash-attn.png" alt="Flash Attention" />

<Tip title="Flash Attention कसे कार्य करते">

Flash Attention हे एक तंत्र आहे जे मेमरी बँडविड्थ अडथळ्यांचे निराकरण करून ट्रान्सफॉर्मर मॉडेल्समधील अटेंशन यंत्रणा ऑप्टिमाइझ करते. आधी [प्रकरण 1.8](/course/chapter1/8) मध्ये चर्चा केल्याप्रमाणे, अटेंशन यंत्रणेची क्वाड्रॅटिक कॉम्प्लेक्सिटी आणि मेमरी वापर असतो, ज्यामुळे लांब सिक्वेन्सेससाठी ती अकार्यक्षम ठरते.

मुख्य नावीन्य म्हणजे ते High Bandwidth Memory (HBM) आणि जलद SRAM कॅश दरम्यान मेमरी ट्रान्सफर्स कसे व्यवस्थापित करते यात आहे. पारंपरिक अटेंशन HBM आणि SRAM दरम्यान वारंवार डेटा ट्रान्सफर करते, ज्यामुळे GPU निष्क्रिय राहून अडथळे निर्माण होतात. Flash Attention डेटा एकदाच SRAM मध्ये लोड करते आणि सर्व गणना तिथेच करते, ज्यामुळे महागडे मेमरी ट्रान्सफर्स कमीत कमी होतात.

प्रशिक्षणादरम्यान फायदे सर्वात लक्षणीय असले तरी, Flash Attention चा कमी झालेला VRAM वापर आणि सुधारित कार्यक्षमता इन्फरन्ससाठी देखील मौल्यवान ठरते, ज्यामुळे जलद आणि अधिक स्केलेबल LLM सर्व्हिंग शक्य होते.

</Tip>

**vLLM** PagedAttention वापरून वेगळा दृष्टिकोन घेते. ज्याप्रमाणे संगणक त्याची मेमरी पेजेसमध्ये व्यवस्थापित करतो, त्याचप्रमाणे vLLM मॉडेलच्या मेमरीला लहान ब्लॉक्समध्ये विभागते. या हुशार प्रणालीमुळे ते वेगवेगळ्या आकाराच्या रिक्वेस्ट्सना अधिक लवचिकपणे हाताळू शकते आणि मेमरी स्पेस वाया घालवत नाही. वेगवेगळ्या रिक्वेस्ट्समध्ये मेमरी शेअर करण्यात हे विशेषतः चांगले आहे आणि मेमरी फ्रॅगमेंटेशन कमी करते, ज्यामुळे संपूर्ण प्रणाली अधिक कार्यक्षम बनते.

<Tip title="PagedAttention कसे कार्य करते">

PagedAttention हे एक तंत्र आहे जे LLM इन्फरन्समधील आणखी एका महत्त्वाच्या अडथळ्याचे निराकरण करते: KV कॅश मेमरी व्यवस्थापन. [प्रकरण 1.8](/course/chapter1/8) मध्ये चर्चा केल्याप्रमाणे, मजकूर निर्मितीदरम्यान, मॉडेल पुनरावृत्ती होणाऱ्या गणना कमी करण्यासाठी प्रत्येक तयार झालेल्या टोकनसाठी अटेंशन कीज आणि व्हॅल्यूज (KV कॅश) साठवते. विशेषतः लांब सिक्वेन्सेस किंवा अनेक समवर्ती रिक्वेस्ट्ससह KV कॅश प्रचंड मोठे होऊ शकते.

vLLM चे मुख्य नावीन्य ते हा कॅश कसे व्यवस्थापित करते यात आहे:

1. **मेमरी पेजिंग**: KV कॅशला एक मोठा ब्लॉक मानण्याऐवजी, त्याचे निश्चित आकाराच्या "पेजेस" मध्ये विभाजन केले जाते (ऑपरेटिंग सिस्टम्समधील व्हर्च्युअल मेमरीसारखे).
2. **नॉन-कॉन्टिग्युअस स्टोरेज**: पेजेसना GPU मेमरीमध्ये सलग साठवण्याची गरज नसते, ज्यामुळे अधिक लवचिक मेमरी वाटप शक्य होते.
3. **पेज टेबल व्यवस्थापन**: एक पेज टेबल कोणती पेजेस कोणत्या सिक्वेन्सशी संबंधित आहेत याचा मागोवा ठेवते, ज्यामुळे कार्यक्षम शोध आणि प्रवेश शक्य होतो.
4. **मेमरी शेअरिंग**: पॅरलल सॅम्पलिंगसारख्या ऑपरेशन्ससाठी, प्रॉम्प्टचे KV कॅश साठवणारी पेजेस अनेक सिक्वेन्सेसमध्ये शेअर केली जाऊ शकतात.

PagedAttention दृष्टिकोन पारंपरिक पद्धतींच्या तुलनेत 24 पट जास्त थ्रूपुटपर्यंत नेऊ शकतो, ज्यामुळे तो प्रोडक्शन LLM डिप्लॉयमेंट्ससाठी गेम-चेंजर ठरतो. PagedAttention कसे कार्य करते याबद्दल अधिक सखोलपणे जाणून घ्यायचे असल्यास, तुम्ही [vLLM डॉक्युमेंटेशनमधील मार्गदर्शक](https://docs.vllm.ai/en/latest/design/kernel/paged_attention.html) वाचू शकता.

</Tip>

**llama.cpp** हे मूळतः कन्झ्युमर हार्डवेअरवर LLaMA मॉडेल्स चालवण्यासाठी डिझाइन केलेले अत्यंत ऑप्टिमाइझ केलेले C/C++ इम्प्लिमेंटेशन आहे. ते पर्यायी GPU प्रवेगासह CPU कार्यक्षमतेवर लक्ष केंद्रित करते आणि संसाधन-मर्यादित वातावरणांसाठी आदर्श आहे. llama.cpp चांगली कामगिरी राखत मॉडेलचा आकार आणि मेमरी आवश्यकता कमी करण्यासाठी क्वांटायझेशन तंत्रांचा वापर करते. ते वेगवेगळ्या CPU आर्किटेक्चर्ससाठी ऑप्टिमाइझ केलेले कर्नल्स इम्प्लिमेंट करते आणि कार्यक्षम टोकन जनरेशनसाठी मूलभूत KV कॅश व्यवस्थापन सपोर्ट करते.

<Tip title="llama.cpp क्वांटायझेशन कसे कार्य करते">

llama.cpp मधील क्वांटायझेशन मॉडेल वेट्सची अचूकता 32-बिट किंवा 16-बिट फ्लोटिंग पॉइंटवरून 8-बिट इंटिजर्स (INT8), 4-बिट, किंवा त्याहूनही कमी अचूकतेच्या फॉरमॅट्सपर्यंत कमी करते. यामुळे किमान गुणवत्ता हानीसह मेमरी वापर लक्षणीयरीत्या कमी होतो आणि इन्फरन्स गती सुधारते.

llama.cpp मधील मुख्य क्वांटायझेशन वैशिष्ट्यांमध्ये समाविष्ट आहे:
1. **अनेक क्वांटायझेशन लेव्हल्स**: 8-बिट, 4-बिट, 3-बिट, आणि अगदी 2-बिट क्वांटायझेशन सपोर्ट करते
2. **GGML/GGUF फॉरमॅट**: क्वांटाइज्ड इन्फरन्ससाठी ऑप्टिमाइझ केलेले कस्टम टेन्सर फॉरमॅट्स वापरते
3. **मिश्र अचूकता**: मॉडेलच्या वेगवेगळ्या भागांना वेगवेगळे क्वांटायझेशन लेव्हल्स लागू करू शकते
4. **हार्डवेअर-विशिष्ट ऑप्टिमायझेशन्स**: वेगवेगळ्या CPU आर्किटेक्चर्ससाठी (AVX2, AVX-512, NEON) ऑप्टिमाइझ केलेले कोड पाथ्स समाविष्ट करते

हा दृष्टिकोन मर्यादित मेमरी असलेल्या कन्झ्युमर हार्डवेअरवर अब्जावधी-पॅरामीटर मॉडेल्स चालवणे शक्य करतो, ज्यामुळे तो स्थानिक डिप्लॉयमेंट्स आणि एज डिव्हाइसेससाठी परिपूर्ण ठरतो.

</Tip>

### डिप्लॉयमेंट आणि इंटिग्रेशन

चला फ्रेमवर्क्समधील डिप्लॉयमेंट आणि इंटिग्रेशन फरकांकडे वळूया.

**TGI** त्याच्या प्रोडक्शन-रेडी वैशिष्ट्यांसह एंटरप्राइझ-स्तरीय डिप्लॉयमेंटमध्ये उत्कृष्ट आहे. ते Kubernetes साठी अंगभूत सपोर्टसह येते आणि प्रोडक्शनमध्ये चालवण्यासाठी आवश्यक असलेले सर्वकाही समाविष्ट करते, जसे की Prometheus आणि Grafana द्वारे मॉनिटरिंग, स्वयंचलित स्केलिंग, आणि सर्वसमावेशक सुरक्षा वैशिष्ट्ये. प्रणालीमध्ये एंटरप्राइझ-दर्जाचे लॉगिंग आणि तुमचे डिप्लॉयमेंट सुरक्षित आणि स्थिर ठेवण्यासाठी कंटेंट फिल्टरिंग आणि रेट लिमिटिंग सारखे विविध संरक्षणात्मक उपाय देखील समाविष्ट आहेत.

**vLLM** डिप्लॉयमेंटसाठी अधिक लवचिक, डेव्हलपर-अनुकूल दृष्टिकोन घेते. ते Python च्या गाभ्यासह तयार केले गेले आहे आणि तुमच्या विद्यमान अ‍ॅप्लिकेशन्समध्ये OpenAI च्या API ला सहजपणे बदलू शकते. फ्रेमवर्क कच्च्या कामगिरीवर लक्ष केंद्रित करते आणि तुमच्या विशिष्ट गरजांनुसार कस्टमाइझ केले जाऊ शकते. क्लस्टर व्यवस्थापित करण्यासाठी हे Ray सोबत विशेषतः चांगले काम करते, ज्यामुळे तुम्हाला उच्च कामगिरी आणि अनुकूलतेची गरज असताना हा एक उत्तम पर्याय ठरतो.

**llama.cpp** साधेपणा आणि पोर्टेबिलिटीला प्राधान्य देते. त्याची सर्व्हर इम्प्लिमेंटेशन हलकी आहे आणि शक्तिशाली सर्व्हर्सपासून ते कन्झ्युमर लॅपटॉप्स आणि काही उच्च-दर्जाच्या मोबाइल डिव्हाइसेसपर्यंत विविध हार्डवेअरवर चालू शकते. किमान अवलंबित्व आणि साधा C/C++ कोर असल्यामुळे, Python फ्रेमवर्क्स इन्स्टॉल करणे आव्हानात्मक असलेल्या वातावरणांमध्ये देखील ते सहजपणे डिप्लॉय करता येते. सर्व्हर इतर सोल्युशन्सपेक्षा खूपच लहान रिसोर्स फूटप्रिंट राखत OpenAI-सुसंगत API पुरवते.

## सुरुवात करणे

चला LLMs डिप्लॉय करण्यासाठी हे फ्रेमवर्क्स कसे वापरायचे ते पाहूया, इन्स्टॉलेशन आणि मूलभूत सेटअपपासून सुरुवात करून.

### इन्स्टॉलेशन आणि मूलभूत सेटअप

<hfoptions id="inference-frameworks" >

<hfoption value="tgi" label="TGI">

TGI इन्स्टॉल करणे आणि वापरणे सोपे आहे, Hugging Face इकोसिस्टमसह सखोल इंटिग्रेशनसह.

प्रथम, Docker वापरून TGI सर्व्हर लाँच करा:

```sh
docker run --gpus all \
    --shm-size 1g \
    -p 8080:80 \
    -v ~/.cache/huggingface:/data \
    ghcr.io/huggingface/text-generation-inference:latest \
    --model-id HuggingFaceTB/SmolLM2-360M-Instruct
```

नंतर Hugging Face च्या InferenceClient चा वापर करून त्याच्याशी संवाद साधा:

```python
from huggingface_hub import InferenceClient

# Initialize client pointing to TGI endpoint
client = InferenceClient(
    model="http://localhost:8080",  # URL to the TGI server
)

# Text generation
response = client.text_generation(
    "Tell me a story",
    max_new_tokens=100,
    temperature=0.7,
    top_p=0.95,
    details=True,
    stop_sequences=[],
)
print(response.generated_text)

# For chat format
response = client.chat_completion(
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Tell me a story"},
    ],
    max_tokens=100,
    temperature=0.7,
    top_p=0.95,
)
print(response.choices[0].message.content)
```

पर्यायाने, तुम्ही OpenAI क्लायंट वापरू शकता:

```python
from openai import OpenAI

# Initialize client pointing to TGI endpoint
client = OpenAI(
    base_url="http://localhost:8080/v1",  # Make sure to include /v1
    api_key="not-needed",  # TGI doesn't require an API key by default
)

# Chat completion
response = client.chat.completions.create(
    model="HuggingFaceTB/SmolLM2-360M-Instruct",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Tell me a story"},
    ],
    max_tokens=100,
    temperature=0.7,
    top_p=0.95,
)
print(response.choices[0].message.content)
```

    stop=["\n\n", "###"],  # Stop sequences

## प्रगत जनरेशन नियंत्रण

### टोकन निवड आणि सॅम्पलिंग

मजकूर निर्मितीच्या प्रक्रियेत प्रत्येक टप्प्यावर पुढील टोकन निवडणे समाविष्ट असते. या निवड प्रक्रियेला विविध पॅरामीटर्सद्वारे नियंत्रित केले जाऊ शकते:

1. **कच्चे लॉजिट्स (Raw Logits)**: प्रत्येक टोकनसाठी प्रारंभिक आउटपुट संभाव्यता
2. **तापमान (Temperature)**: निवडीतील यादृच्छिकता नियंत्रित करते (जास्त = अधिक सर्जनशील)
3. **टॉप-p (Nucleus) सॅम्पलिंग**: संभाव्यतेच्या X% भाग बनवणाऱ्या टॉप टोकन्सपर्यंत फिल्टर करते
4. **टॉप-k फिल्टरिंग**: निवड सर्वात संभाव्य k टोकन्सपुरती मर्यादित करते

हे पॅरामीटर्स कसे कॉन्फिगर करायचे ते इथे आहे:
