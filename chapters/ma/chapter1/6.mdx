# Transformer Architectures[[transformer-architectures]]

मागील sections मध्ये आपण सामान्य Transformer architecture ची ओळख करून घेतली आणि हे models विविध tasks कसे सोडवू शकतात हे पाहिले. आता Transformer models च्या तीन मुख्य architectural variants कडे अधिक बारकाईने पाहू आणि प्रत्येकाचा वापर कधी करायचा हे समजून घेऊ. त्यानंतर या architectures वेगवेगळ्या language tasks साठी कशा वापरल्या जातात ते पाहू.

या section मध्ये आपण Transformer models च्या तीन मुख्य architectural variants चा सखोल अभ्यास करू आणि प्रत्येकाचा वापर कधी करायचा हे समजून घेऊ.

> [!TIP]
> लक्षात ठेवा की बहुतेक Transformer models पैकी एका architecture चा वापर करतात: encoder-only, decoder-only किंवा encoder-decoder (sequence-to-sequence). हे differences समजून घेतल्यास तुमच्या specific task साठी योग्य model निवडणे सोपे जाईल.

## Encoder models[[encoder-models]]

<Youtube id="MUqNwgPjJvQ" />

Encoder models Transformer model मधील फक्त encoder चा वापर करतात. प्रत्येक stage मध्ये attention layers सुरुवातीच्या sentence मधील सर्व words access करू शकतात. या models मध्ये "bi-directional" attention हे वैशिष्ट्य आढळते आणि त्यांना अनेकदा *auto-encoding models* असे म्हटले जाते.

या models चे pretraining सहसा एखाद्या sentence मध्ये काही प्रकारे बदल करून (उदाहरणार्थ, त्यातील काही random words mask करून) केले जाते आणि model ला मूळ sentence शोधण्याचे किंवा पुन्हा तयार करण्याचे task दिले जाते.

Encoder models हे संपूर्ण sentence समजून घेण्याची आवश्यकता असलेल्या tasks साठी सर्वात योग्य आहेत. उदाहरणार्थ, sentence classification, named entity recognition (आणि सर्वसाधारणपणे word classification) आणि extractive question answering.

> [!TIP]
> आपण [How 🤗 Transformers solve tasks](https://huggingface.co/learn/llm-course/chapter1/5) मध्ये पाहिल्याप्रमाणे, BERT सारखे encoder models text समजून घेण्यात उत्कृष्ट असतात कारण ते दोन्ही दिशांनी संपूर्ण context पाहू शकतात. त्यामुळे संपूर्ण input समजून घेणे महत्त्वाचे असलेल्या tasks साठी ते योग्य आहेत.

या model family मधील काही प्रमुख models:

* [BERT](https://huggingface.co/docs/transformers/model_doc/bert)
* [DistilBERT](https://huggingface.co/docs/transformers/model_doc/distilbert)
* [ModernBERT](https://huggingface.co/docs/transformers/en/model_doc/modernbert)

## Decoder models[[decoder-models]]

<Youtube id="d_ixlCubqQw" />

Decoder models Transformer मधील फक्त decoder चा वापर करतात. प्रत्येक stage मध्ये, एखाद्या word साठी attention layers त्या word च्या आधी sentence मध्ये असलेल्या words ना फक्त access करू शकतात. या models ना अनेकदा *auto-regressive models* असे म्हटले जाते.

Decoder models चे pretraining सहसा sentence मधील पुढील word चा अंदाज लावण्यावर आधारित असते.

हे models text generation शी संबंधित tasks साठी सर्वात योग्य आहेत.

> [!TIP]
> GPT सारखे decoder models एका वेळी एक token predict करून text generate करण्यासाठी तयार केलेले आहेत. [How 🤗 Transformers solve tasks](https://huggingface.co/learn/llm-course/chapter1/5) मध्ये आपण पाहिल्याप्रमाणे, ते फक्त previous tokens पाहू शकतात. त्यामुळे creative text generation साठी ते उत्कृष्ट आहेत, परंतु bidirectional understanding आवश्यक असलेल्या tasks साठी ते कमी योग्य आहेत.

या model family मधील काही प्रमुख models:

* [Hugging Face SmolLM Series](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B-Instruct)
* [Meta's Llama Series](https://huggingface.co/docs/transformers/en/model_doc/llama4)
* [Google's Gemma Series](https://huggingface.co/docs/transformers/main/en/model_doc/gemma3)
* [DeepSeek's V3](https://huggingface.co/deepseek-ai/DeepSeek-V3)

### Modern Large Language Models (LLMs)

अलीकडील बहुतेक Large Language Models (LLMs) decoder-only architecture वापरतात. गेल्या काही वर्षांत या models चा आकार आणि capabilities मोठ्या प्रमाणात वाढल्या आहेत. काही सर्वात मोठ्या models मध्ये शेकडो billions parameters असतात.

Modern LLMs चे training सामान्यतः दोन phases मध्ये केले जाते:

1. **Pretraining**: model मोठ्या प्रमाणातील text data वर पुढील token predict करायला शिकतो
2. **Instruction tuning**: model ला instructions follow करण्यासाठी आणि helpful responses generate करण्यासाठी fine-tune केले जाते

या approach मुळे models विविध प्रकारच्या topics आणि tasks वर human-like text समजून घेऊ आणि generate करू शकतात.

#### Key capabilities of modern LLMs

Modern decoder-based LLMs ने प्रभावी capabilities दाखवल्या आहेत:

| Capability         | Description                                                  | Example                                           |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------- |
| Text generation    | सुसंगत आणि context शी संबंधित text तयार करणे                 | Essays, stories किंवा emails लिहिणे               |
| Summarization      | मोठ्या documents चे छोटे versions तयार करणे                  | Reports चे executive summaries तयार करणे          |
| Translation        | एका language मधील text दुसऱ्या language मध्ये रूपांतरित करणे | English चे Spanish मध्ये translation              |
| Question answering | factual questions ची उत्तरे देणे                             | "What is the capital of France?"                  |
| Code generation    | Code snippets लिहिणे किंवा पूर्ण करणे                        | Description वरून function तयार करणे               |
| Reasoning          | Problems step by step सोडवणे                                 | Math problems किंवा logical puzzles सोडवणे        |
| Few-shot learning  | Prompt मधील काही examples वरून शिकणे                         | फक्त 2-3 examples पाहिल्यानंतर text classify करणे |

## Sequence-to-sequence models[[sequence-to-sequence-models]]

<Youtube id="0_4KEb08xrE" />

Encoder-decoder models (ज्यांना *sequence-to-sequence models* असेही म्हटले जाते) Transformer architecture मधील दोन्ही parts वापरतात. प्रत्येक stage मध्ये encoder च्या attention layers ना सुरुवातीच्या sentence मधील सर्व words access करता येतात, तर decoder च्या attention layers ना दिलेल्या word च्या आधीचे words फक्त access करता येतात.

या models चे pretraining वेगवेगळ्या प्रकारे केले जाऊ शकते, परंतु त्यामध्ये अनेकदा एखाद्या sentence चा input काही प्रकारे corrupt करून (उदाहरणार्थ, random words mask करून) ते sentence पुन्हा तयार करण्याचा समावेश असतो. T5 model च्या pretraining मध्ये random text spans (ज्यामध्ये अनेक words असू शकतात) एका single mask special token ने replace केले जातात आणि त्यानंतर त्या mask token ने replace केलेला text predict करण्याचे task model ला दिले जाते.

Sequence-to-sequence models हे दिलेल्या input वर आधारित नवीन sentences generate करण्याशी संबंधित tasks साठी सर्वात योग्य आहेत, जसे की summarization, translation किंवा generative question answering.

> [!TIP]
> [How 🤗 Transformers solve tasks](https://huggingface.co/learn/llm-course/chapter1/5) मध्ये आपण पाहिल्याप्रमाणे, BART आणि T5 सारखे encoder-decoder models दोन्ही architectures ची strengths एकत्र करतात. Encoder input चे deep bidirectional understanding देतो, तर decoder योग्य output text generate करतो. त्यामुळे translation किंवा summarization सारख्या एका sequence चे दुसऱ्या sequence मध्ये transformation करणाऱ्या tasks साठी ते योग्य आहेत.

### Practical applications

Sequence-to-sequence models असे tasks सोडवण्यात उत्कृष्ट आहेत ज्यामध्ये meaning टिकवून text च्या एका form चे दुसऱ्या form मध्ये transformation करणे आवश्यक असते. काही practical applications:

| Application             | Description                                                  | Example Model |
| ----------------------- | ------------------------------------------------------------ | ------------- |
| Machine translation     | एका language मधील text दुसऱ्या language मध्ये रूपांतरित करणे | Marian, T5    |
| Text summarization      | मोठ्या text चे concise summaries तयार करणे                   | BART, T5      |
| Data-to-text generation | Structured data चे natural language मध्ये रूपांतर करणे       | T5            |
| Grammar correction      | Text मधील grammatical errors दुरुस्त करणे                    | T5            |
| Question answering      | Context वर आधारित answers generate करणे                      | BART, T5      |

## Choosing the right architecture[[choosing-the-right-architecture]]

एखाद्या specific NLP task वर काम करताना कोणते architecture वापरायचे हे कसे ठरवायचे? येथे एक quick guide आहे:

| Task                                   | Suggested Architecture     | Examples      |
| -------------------------------------- | -------------------------- | ------------- |
| Text classification (sentiment, topic) | Encoder                    | BERT, RoBERTa |
| Text generation (creative writing)     | Decoder                    | GPT, LLaMA    |
| Translation                            | Encoder-Decoder            | T5, BART      |
| Summarization                          | Encoder-Decoder            | BART, T5      |
| Named entity recognition               | Encoder                    | BERT, RoBERTa |
| Question answering (extractive)        | Encoder                    | BERT, RoBERTa |
| Question answering (generative)        | Encoder-Decoder or Decoder | T5, GPT       |
| Conversational AI                      | Decoder                    | GPT, LLaMA    |

> [!TIP]
> कोणते model वापरायचे याबद्दल शंका असल्यास पुढील गोष्टी विचारात घ्या:
>
> 1. तुमच्या task ला कोणत्या प्रकारचे understanding आवश्यक आहे? (Bidirectional किंवा unidirectional)
> 2. तुम्ही नवीन text generate करत आहात की existing text चे analysis करत आहात?
> 3. तुम्हाला एका sequence चे दुसऱ्या sequence मध्ये transformation करायचे आहे का?
>
> या questions ची उत्तरे तुम्हाला योग्य architecture निवडण्यास मदत करतील.

## The evolution of LLMs

Large Language Models गेल्या काही वर्षांत वेगाने विकसित झाले आहेत आणि प्रत्येक generation मध्ये त्यांच्या capabilities मध्ये मोठ्या प्रमाणात सुधारणा झाली आहे.

## Attention mechanisms[[attention-mechanisms]]

बहुतेक transformer models full attention वापरतात, म्हणजे attention matrix square असतो. Long texts असताना हे computational bottleneck ठरू शकते. Longformer आणि Reformer हे models अधिक efficient होण्याचा प्रयत्न करतात आणि training speed वाढवण्यासाठी attention matrix ची sparse version वापरतात.

> [!TIP]
> Standard attention mechanisms ची computational complexity O(n²) असते, जिथे n म्हणजे sequence length. खूप मोठ्या sequences साठी हे problematic ठरते. खाली दिलेले specialized attention mechanisms ही limitation कमी करण्यास मदत करतात.

### LSH attention

[Reformer](https://huggingface.co/docs/transformers/model_doc/reformer) LSH attention वापरतो. `softmax(QK^t)` मध्ये matrix `QK^t` मधील softmax dimension मधील फक्त सर्वात मोठे elements उपयुक्त contribution देतात. त्यामुळे Q मधील प्रत्येक query q साठी आपण K मधील q च्या जवळ असलेल्या keys k चा विचार करू शकतो.

q आणि k एकमेकांच्या जवळ आहेत की नाही हे ठरवण्यासाठी hash function वापरले जाते. Attention mask मध्ये current token ला mask करण्यासाठी बदल केला जातो (पहिल्या position वगळता), कारण त्यामुळे query आणि key समान (आणि त्यामुळे एकमेकांसारखे) होतील.

Hash थोडा random असू शकत असल्यामुळे practice मध्ये अनेक hash functions वापरले जातात (हे `n_rounds` parameter द्वारे ठरवले जाते) आणि त्यानंतर त्यांची average घेतली जाते.

### Local attention

[Longformer](https://huggingface.co/docs/transformers/model_doc/longformer) local attention वापरतो. अनेकदा local context (उदाहरणार्थ, "दिलेल्या token च्या डावीकडे आणि उजवीकडे असलेले दोन tokens कोणते आहेत?") एखाद्या token साठी action घेण्यासाठी पुरेसा असतो.

तसेच, small window असलेल्या attention layers एकावर एक stack केल्यामुळे शेवटच्या layer कडे फक्त त्या window मधील tokens पेक्षा मोठे receptive field असते. त्यामुळे model संपूर्ण sentence चे representation तयार करू शकतो.

काही preselected input tokens ना global attention देखील दिले जाते. या काही tokens साठी attention matrix सर्व tokens access करू शकतो आणि ही प्रक्रिया symmetric असते: इतर सर्व tokens ना त्यांच्या local window मधील tokens व्यतिरिक्त त्या specific tokens चा access असतो. हे paper च्या Figure 2d मध्ये दाखवले आहे. खाली sample attention mask दिला आहे:

### Axial positional encodings

[Reformer](https://huggingface.co/docs/transformers/model_doc/reformer) axial positional encodings वापरतो. Traditional transformer models मध्ये positional encoding E हा \(l\) by \(d\) आकाराचा matrix असतो, जिथे \(l\) म्हणजे sequence length आणि \(d\) म्हणजे hidden state ची dimension.

जर texts खूप मोठे असतील, तर हा matrix खूप मोठा होऊ शकतो आणि GPU वर खूप जास्त space घेऊ शकतो. ही समस्या कमी करण्यासाठी axial positional encodings मध्ये मोठ्या matrix E चे दोन छोट्या matrices E1 आणि E2 मध्ये factorization केले जाते.

या matrices चे dimensions अनुक्रमे \(l_{1} \times d_{1}\) आणि \(l_{2} \times d_{2}\) असतात, ज्यामध्ये \(l_{1} \times l_{2} = l\) आणि \(d_{1} + d_{2} = d\) (lengths चा product घेतल्यामुळे हा matrix खूपच लहान होतो).

E मधील timestep \(j\) साठी embedding हे E1 मधील timestep \(j % l1\) आणि E2 मधील timestep \(j // l1\) यांचे embeddings concatenate करून मिळवले जाते.
