> [!TIP]
> विशिष्ट architectural variants मध्ये जाण्यापूर्वी, हे समजून घेणे उपयुक्त आहे की बहुतेक tasks एकाच प्रकारच्या pattern चे अनुसरण करतात: input data वर model द्वारे processing केली जाते आणि output चा एखाद्या specific task साठी अर्थ लावला जातो. यामधील फरक data कसा तयार केला जातो, कोणता model architecture variant वापरला जातो आणि output वर कशा प्रकारे processing केली जाते यामध्ये असतो.

Tasks कशा सोडवल्या जातात हे समजावून सांगण्यासाठी, useful predictions मिळवण्यासाठी model च्या आत काय घडते ते आपण पाहू. आपण खालील models आणि त्यांच्याशी संबंधित tasks समजून घेणार आहोत:

* [Wav2Vec2](https://huggingface.co/docs/transformers/model_doc/wav2vec2) — audio classification आणि automatic speech recognition (ASR) साठी
* [Vision Transformer (ViT)](https://huggingface.co/docs/transformers/model_doc/vit) आणि [ConvNeXT](https://huggingface.co/docs/transformers/model_doc/convnext) — image classification साठी
* [DETR](https://huggingface.co/docs/transformers/model_doc/detr) — object detection साठी
* [Mask2Former](https://huggingface.co/docs/transformers/model_doc/mask2former) — image segmentation साठी
* [GLPN](https://huggingface.co/docs/transformers/model_doc/glpn) — depth estimation साठी
* [BERT](https://huggingface.co/docs/transformers/model_doc/bert) — encoder वापरणाऱ्या NLP tasks जसे text classification, token classification आणि question answering साठी
* [GPT2](https://huggingface.co/docs/transformers/model_doc/gpt2) — decoder वापरणाऱ्या NLP tasks जसे text generation साठी
* [BART](https://huggingface.co/docs/transformers/model_doc/bart) — encoder-decoder वापरणाऱ्या NLP tasks जसे summarization आणि translation साठी

> [!TIP]

Encoder, decoder आणि attention कसे काम करतात हे माहीत असल्यास वेगवेगळे Transformer models कसे काम करतात हे समजणे सोपे जाईल. अधिक माहितीसाठी [the previous section](https://huggingface.co/course/chapter1/4?fw=pt) नक्की पहा!

## Language साठी Transformer models

Language models हे modern NLP च्या केंद्रस्थानी आहेत. Text मधील words किंवा tokens यांच्यातील statistical patterns आणि relationships शिकून human language समजून घेणे आणि generate करणे यासाठी त्यांची रचना केलेली असते.

Transformer सुरुवातीला machine translation साठी design करण्यात आला होता आणि त्यानंतर सर्व AI tasks सोडवण्यासाठी तो default architecture बनला आहे. काही tasks साठी Transformer ची encoder structure अधिक योग्य असते, तर काही tasks decoder साठी अधिक योग्य असतात. काही इतर tasks मध्ये Transformer ची encoder-decoder structure वापरली जाते.

### Language models कसे काम करतात

Language models ला surrounding words च्या context वरून एखादा word येण्याची probability predict करण्यासाठी train केले जाते. यामुळे त्यांना language ची एक foundational understanding मिळते जी इतर tasks साठी generalize होऊ शकते.

Transformer model train करण्यासाठी दोन मुख्य approaches आहेत:

1. **Masked language modeling (MLM)**: BERT सारख्या encoder models मध्ये वापरले जाणारे हे approach input मधील काही tokens randomly mask करते आणि surrounding context च्या आधारे original tokens predict करण्यासाठी model ला train करते. यामुळे model ला bidirectional context शिकता येतो, म्हणजे masked word च्या आधी आणि नंतरचे दोन्ही words पाहता येतात.

2. **Causal language modeling (CLM)**: GPT सारख्या decoder models मध्ये वापरले जाणारे हे approach sequence मधील सर्व previous tokens च्या आधारे next token predict करते. Next token predict करण्यासाठी model फक्त डावीकडील म्हणजे previous tokens चा context वापरू शकते.

### Language models चे प्रकार

Transformers library मध्ये language models साधारणपणे तीन architectural categories मध्ये येतात:

1. **Encoder-only models** (जसे BERT): हे models दोन्ही दिशांकडून context समजून घेण्यासाठी bidirectional approach वापरतात. Classification, named entity recognition आणि question answering यांसारख्या text ची सखोल understanding आवश्यक असलेल्या tasks साठी हे सर्वात योग्य असतात.

2. **Decoder-only models** (जसे GPT, Llama): हे models text डावीकडून उजवीकडे process करतात आणि विशेषतः text generation tasks साठी चांगले असतात. ते sentences पूर्ण करू शकतात, essays लिहू शकतात किंवा prompt च्या आधारे code देखील generate करू शकतात.

3. **Encoder-decoder models** (जसे T5, BART): हे models दोन्ही approaches एकत्र करतात. Encoder चा वापर input समजून घेण्यासाठी आणि decoder चा वापर output generate करण्यासाठी केला जातो. Translation, summarization आणि question answering यांसारख्या sequence-to-sequence tasks मध्ये हे models उत्कृष्ट काम करतात.

![transformer-models-for-language](https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter1/transformers_architecture.png)

मागील section मध्ये पाहिल्याप्रमाणे, language models सामान्यतः मोठ्या प्रमाणातील text data वर self-supervised पद्धतीने (human annotations शिवाय) pretrained केले जातात आणि त्यानंतर specific tasks साठी fine-tuned केले जातात. या approach ला transfer learning असे म्हणतात. यामुळे तुलनेने कमी task-specific data वापरून हे models अनेक वेगवेगळ्या NLP tasks साठी adapt करता येतात.

पुढील sections मध्ये आपण specific model architectures आणि speech, vision आणि text domains मधील विविध tasks साठी त्यांचा कसा वापर केला जातो हे पाहणार आहोत.

> [!TIP]
> एखाद्या विशिष्ट NLP task साठी Transformer architecture मधील कोणता भाग (encoder, decoder किंवा दोन्ही) योग्य आहे हे समजणे योग्य model निवडण्यासाठी महत्त्वाचे आहे. सामान्यतः bidirectional context आवश्यक असलेल्या tasks साठी encoders, text generate करणाऱ्या tasks साठी decoders आणि एका sequence ला दुसऱ्या sequence मध्ये convert करणाऱ्या tasks साठी encoder-decoders वापरले जातात.

### Text generation

Text generation म्हणजे prompt किंवा input च्या आधारे coherent आणि contextually relevant text तयार करणे.

[GPT-2](https://huggingface.co/docs/transformers/model_doc/gpt2) हे decoder-only model आहे जे मोठ्या प्रमाणातील text वर pretrained केलेले आहे. Prompt दिल्यावर ते convincing (जरी नेहमीच सत्य असेल असे नाही!) text generate करू शकते आणि question answering सारखी इतर NLP tasks देखील करू शकते, जरी त्यासाठी त्याला explicitly train केलेले नसले तरी.

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gpt2_architecture.png"/>
</div>

1. GPT-2 words चे tokenization करण्यासाठी [byte pair encoding (BPE)](https://huggingface.co/docs/transformers/tokenizer_summary#bytepair-encoding-bpe) वापरते आणि token embedding तयार करते. Sequence मधील प्रत्येक token ची position दर्शवण्यासाठी token embeddings मध्ये positional encodings जोडले जातात. Input embeddings अनेक decoder blocks मधून pass केले जातात आणि त्यातून final hidden state मिळते. प्रत्येक decoder block मध्ये GPT-2 एक *masked self-attention* layer वापरते, याचा अर्थ GPT-2 future tokens कडे attend करू शकत नाही. त्याला फक्त डावीकडील tokens कडे attend करण्याची परवानगी असते. हे BERT मधील [`mask`] token पेक्षा वेगळे आहे कारण masked self-attention मध्ये future tokens साठी score `0` करण्यासाठी attention mask वापरला जातो.

2. Decoder मधून मिळालेला output language modeling head कडे पाठवला जातो. हा hidden states ला logits मध्ये convert करण्यासाठी linear transformation करतो. Label हा sequence मधील next token असतो आणि logits एक स्थान उजवीकडे shift करून तो तयार केला जातो. Next most likely token मिळवण्यासाठी shifted logits आणि labels यांच्यामध्ये cross-entropy loss calculate केला जातो.

GPT-2 चे pretraining objective पूर्णपणे [causal language modeling](https://huggingface.co/docs/transformers/glossary#causal-language-modeling) वर आधारित आहे, म्हणजे sequence मधील next word predict करणे. त्यामुळे text generate करण्याशी संबंधित tasks साठी GPT-2 विशेषतः उपयुक्त आहे.

Text generation स्वतः करून पाहण्यास तयार आहात? DistilGPT-2 fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [causal language modeling guide](https://huggingface.co/docs/transformers/tasks/language_modeling#causal-language-modeling) पहा!

> Text generation बद्दल अधिक माहितीसाठी [text generation strategies](https://huggingface.co/docs/transformers/generation_strategies#generation-strategies) guide पहा!

### Text classification

Text classification म्हणजे text documents ना predefined categories assign करणे, जसे sentiment analysis, topic classification किंवा spam detection.

[BERT](https://huggingface.co/docs/transformers/model_doc/bert) हे encoder-only model आहे आणि text च्या दोन्ही बाजूंवरील words कडे attend करून richer representations शिकण्यासाठी deep bidirectionality प्रभावीपणे implement करणारे पहिले models पैकी एक आहे.

1. BERT text चे token embedding तयार करण्यासाठी [WordPiece](https://huggingface.co/docs/transformers/tokenizer_summary#wordpiece) tokenization वापरते. Single sentence आणि sentences ची pair यांच्यात फरक करण्यासाठी special `[SEP]` token जोडला जातो. प्रत्येक text sequence च्या सुरुवातीला special `[CLS]` token जोडला जातो. Classification tasks साठी `[CLS]` token असलेला final output classification head साठी input म्हणून वापरला जातो. Pair of sentences मध्ये एखादा token पहिल्या किंवा दुसऱ्या sentence शी संबंधित आहे हे दर्शवण्यासाठी BERT segment embedding देखील जोडते.

2. BERT ला दोन objectives सह pretrained केले जाते: masked language modeling आणि next-sentence prediction. Masked language modeling मध्ये input tokens मधील काही percentage tokens randomly mask केले जातात आणि model ला ते predict करावे लागतात. यामुळे bidirectionality ची समस्या सोडवली जाते, जिथे model सर्व words पाहून next word "predict" करून cheat करू शकते. Predicted mask tokens चे final hidden states vocabulary वर softmax असलेल्या feedforward network कडे पाठवले जातात, ज्यामुळे masked word predict करता येतो.

   दुसरे pretraining objective म्हणजे next-sentence prediction. Sentence B हे sentence A नंतर येते की नाही हे model ला predict करावे लागते. अर्ध्या वेळेस sentence B हे next sentence असते आणि उर्वरित अर्ध्या वेळेस sentence B हे random sentence असते. Sentence B next sentence आहे की नाही याबद्दलची prediction दोन classes (`IsNext` आणि `NotNext`) वर softmax असलेल्या feedforward network कडे पाठवली जाते.

3. Input embeddings अनेक encoder layers मधून pass केले जातात आणि त्यातून final hidden states मिळतात.

Pretrained model चा text classification साठी वापर करण्यासाठी base BERT model च्या वर sequence classification head जोडला जातो. Sequence classification head हा एक linear layer आहे जो final hidden states स्वीकारतो आणि त्यांना logits मध्ये convert करण्यासाठी linear transformation करतो. सर्वात संभाव्य label शोधण्यासाठी logits आणि target यांच्यामध्ये cross-entropy loss calculate केला जातो.

### Token classification

Token classification म्हणजे sequence मधील प्रत्येक token ला एक label assign करणे, जसे named entity recognition किंवा part-of-speech tagging.

Named entity recognition (NER) सारख्या token classification tasks साठी BERT वापरण्यासाठी base BERT model च्या वर token classification head जोडला जातो. Token classification head हा एक linear layer आहे जो final hidden states स्वीकारतो आणि त्यांना logits मध्ये convert करण्यासाठी linear transformation करतो. प्रत्येक token साठी सर्वात संभाव्य label शोधण्यासाठी logits आणि प्रत्येक token यांच्यामध्ये cross-entropy loss calculate केला जातो.

Token classification स्वतः करून पाहण्यास तयार आहात? DistilBERT fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [token classification guide](https://huggingface.co/docs/transformers/tasks/token_classification) पहा!

### Question answering

Question answering म्हणजे दिलेल्या context किंवा passage मधून एखाद्या question चे answer शोधणे.

Question answering साठी BERT वापरण्यासाठी base BERT model च्या वर span classification head जोडला जातो. हा linear layer final hidden states स्वीकारतो आणि answer शी संबंधित `span` च्या start आणि end logits calculate करण्यासाठी linear transformation करतो. Answer शी संबंधित सर्वात संभाव्य text span शोधण्यासाठी logits आणि label position यांच्यामध्ये cross-entropy loss calculate केला जातो.

Question answering स्वतः करून पाहण्यास तयार आहात? DistilBERT fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [question answering guide](https://huggingface.co/docs/transformers/tasks/question_answering) पहा!

> [!TIP]
> 💡 BERT pretrained झाल्यानंतर वेगवेगळ्या tasks साठी त्याचा वापर करणे किती सोपे आहे हे लक्षात घ्या. Hidden states ला तुमच्या इच्छित output मध्ये बदलण्यासाठी pretrained model च्या वर फक्त एक specific head जोडण्याची गरज असते!

### Summarization

Summarization म्हणजे मोठ्या text ला त्यातील मुख्य माहिती आणि meaning कायम ठेवून छोट्या स्वरूपात आणणे.

[BART](https://huggingface.co/docs/transformers/model_doc/bart) आणि [T5](model_doc/t5) सारखी encoder-decoder models summarization task च्या sequence-to-sequence pattern साठी design केलेली आहेत. या section मध्ये आपण BART कसे काम करते हे समजावून घेऊ आणि शेवटी T5 चे fine-tuning करून पाहू शकता.

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/bart_architecture.png"/>
</div>

1. BART ची encoder architecture BERT सारखीच आहे आणि ती text चे token आणि positional embedding स्वीकारते. Input ला corrupt करून आणि त्यानंतर decoder च्या मदतीने तो reconstruct करून BART ला pretrained केले जाते. Specific corruption strategies असलेल्या इतर encoders पेक्षा वेगळे, BART कोणत्याही प्रकारची corruption लागू करू शकते. मात्र *text infilling* corruption strategy सर्वात चांगले काम करते. Text infilling मध्ये अनेक text spans एका **single** [`mask`] token ने replace केले जातात. हे महत्त्वाचे आहे कारण model ला masked tokens predict करावे लागतात आणि त्यामुळे किती tokens missing आहेत हे predict करायला model शिकते. Input embeddings आणि masked spans encoder मधून pass केले जातात आणि त्यातून final hidden states मिळतात. मात्र BERT पेक्षा वेगळे, BART शब्द predict करण्यासाठी शेवटी final feedforward network जोडत नाही.

2. Encoder चा output decoder कडे पाठवला जातो. Encoder च्या output मधून masked tokens आणि uncorrupted tokens predict करणे decoder चे काम असते. यामुळे decoder ला additional context मिळतो आणि तो original text restore करू शकतो. Decoder मधील output language modeling head कडे पाठवला जातो, जो hidden states ला logits मध्ये convert करण्यासाठी linear transformation करतो. Logits आणि label यांच्यामध्ये cross-entropy loss calculate केला जातो. Label म्हणजे उजवीकडे shift केलेला token असतो.

Summarization स्वतः करून पाहण्यास तयार आहात? T5 fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [summarization guide](https://huggingface.co/docs/transformers/tasks/summarization) पहा!

> [!TIP]
> Text generation बद्दल अधिक माहितीसाठी [text generation strategies](https://huggingface.co/docs/transformers/generation_strategies) guide पहा!

### Translation

Translation म्हणजे text चा meaning कायम ठेवून एका language मधून दुसऱ्या language मध्ये convert करणे. Translation हे sequence-to-sequence task चे आणखी एक उदाहरण आहे. त्यामुळे ते करण्यासाठी [BART](https://huggingface.co/docs/transformers/model_doc/bart) किंवा [T5](model_doc/t5) सारखे encoder-decoder model वापरता येते. या section मध्ये आपण BART कसे काम करते हे समजावून घेऊ आणि त्यानंतर तुम्ही T5 चे fine-tuning करून पाहू शकता.

Translation साठी BART मध्ये एक स्वतंत्र randomly initialized encoder जोडला जातो, जो source language ला अशा input मध्ये map करतो ज्याला target language मध्ये decode करता येते. या नवीन encoder चे embeddings original word embeddings ऐवजी pretrained encoder कडे पाठवले जातात. Model output मधून मिळणाऱ्या cross-entropy loss च्या आधारे source encoder, positional embeddings आणि input embeddings update करून source encoder ला train केले जाते. या पहिल्या step मध्ये model parameters frozen ठेवले जातात आणि दुसऱ्या step मध्ये सर्व model parameters एकत्र train केले जातात.

यानंतर BART चे multilingual version, mBART, विकसित करण्यात आले. mBART हे translation साठी तयार करण्यात आले असून अनेक वेगवेगळ्या languages वर pretrained केलेले आहे.

Translation स्वतः करून पाहण्यास तयार आहात? T5 fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [translation guide](https://huggingface.co/docs/transformers/tasks/translation) पहा!

> [!TIP]
> या guide मध्ये तुम्ही पाहिल्याप्रमाणे, वेगवेगळ्या tasks साठी वापरले जात असूनही अनेक models समान patterns follow करतात. हे common patterns समजून घेतल्यास नवीन models कसे काम करतात हे पटकन समजून घेता येते आणि existing models तुमच्या specific needs नुसार adapt करता येतात.

## Text पलीकडील Modalities

Transformers केवळ text पुरते मर्यादित नाहीत. ते speech आणि audio, images आणि video यांसारख्या इतर modalities वर देखील लागू करता येतात. अर्थात, या course मध्ये आपण text वर focus करणार आहोत, पण इतर modalities चा थोडक्यात परिचय करून घेऊ शकतो.

### Speech आणि audio

Transformer models speech आणि audio data कसे handle करतात हे पाहण्यापासून सुरुवात करूया. Text किंवा images च्या तुलनेत speech आणि audio मध्ये काही वेगळी आव्हाने असतात.

[Whisper](https://huggingface.co/docs/transformers/main/en/model_doc/whisper) हे encoder-decoder (sequence-to-sequence) Transformer आहे जे 680,000 तासांच्या labeled audio data वर pretrained केलेले आहे. एवढ्या मोठ्या प्रमाणातील pretraining data मुळे English आणि इतर अनेक languages मधील audio tasks वर zero-shot performance मिळते. Decoder मुळे Whisper encoder ने शिकलेल्या speech representations ला text सारख्या useful outputs मध्ये map करू शकते, आणि त्यासाठी additional fine-tuning ची आवश्यकता नसते. Whisper थेट काम करते.

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter1/whisper_architecture.png"/>
</div>

Diagram हे [Whisper paper](https://huggingface.co/papers/2212.04356) मधून घेतले आहे.

या model चे दोन मुख्य components आहेत:

1. एक **encoder** input audio process करतो. Raw audio प्रथम log-Mel spectrogram मध्ये convert केले जाते. त्यानंतर हा spectrogram Transformer encoder network मधून pass केला जातो.

2. एक **decoder** encoded audio representation घेतो आणि त्याच्याशी संबंधित text tokens autoregressively predict करतो. हा एक standard Transformer decoder आहे, जो previous tokens आणि encoder output दिल्यावर next text token predict करण्यासाठी train केला जातो. Decoder input च्या सुरुवातीला special tokens वापरले जातात, ज्यामुळे transcription, translation किंवा language identification यांसारख्या specific tasks कडे model ला steer करता येते.

Whisper ला web वरून collected केलेल्या 680,000 तासांच्या labeled audio data च्या massive आणि diverse dataset वर pretrained केले गेले आहे. हे large-scale, weakly supervised pretraining अनेक languages आणि tasks वर त्याच्या strong zero-shot performance चे मुख्य कारण आहे.

आता Whisper pretrained झाले असल्यामुळे, zero-shot inference साठी तुम्ही ते थेट वापरू शकता किंवा automatic speech recognition किंवा speech translation सारख्या specific tasks वर performance सुधारण्यासाठी तुमच्या data वर fine-tune करू शकता!

> [!TIP]
> Whisper मधील key innovation म्हणजे internet वरून मिळालेल्या मोठ्या प्रमाणातील diverse आणि weakly supervised audio data वर त्याचे training. यामुळे task-specific fine-tuning शिवाय वेगवेगळ्या languages, accents आणि tasks साठी ते remarkably चांगल्या प्रकारे generalize करू शकते.

### Automatic speech recognition

Automatic speech recognition साठी pretrained model वापरण्यासाठी त्याची पूर्ण encoder-decoder structure वापरली जाते. Encoder audio input process करतो आणि decoder autoregressively transcript token by token generate करतो. Fine-tuning करताना, audio input च्या आधारे योग्य text tokens predict करण्यासाठी model ला सामान्यतः standard sequence-to-sequence loss (जसे cross-entropy) वापरून train केले जाते.

Inference साठी fine-tuned model वापरण्याचा सर्वात सोपा मार्ग म्हणजे `pipeline` वापरणे.

```python
from transformers import pipeline

transcriber = pipeline(
    task="automatic-speech-recognition", model="openai/whisper-base.en"
)
transcriber("https://huggingface.co/datasets/Narsil/asr_dummy/resolve/main/mlk.flac")
# Output: {'text': ' I have a dream that one day this nation will rise up and live out the true meaning of its creed.'}
```

Automatic speech recognition स्वतः करून पाहण्यास तयार आहात? Whisper fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [automatic speech recognition guide](https://huggingface.co/docs/transformers/tasks/asr) पहा!

### Computer vision

आता computer vision tasks कडे वळूया. या tasks मध्ये images किंवा videos मधील visual information समजून घेणे आणि त्याचा अर्थ लावणे यांचा समावेश होतो.

Computer vision tasks कडे पाहण्याचे दोन मार्ग आहेत:

1. Image ला patches च्या sequence मध्ये split करणे आणि त्यांना Transformer वापरून parallel process करणे.
2. [ConvNeXT](https://huggingface.co/docs/transformers/model_doc/convnext) सारखा modern CNN वापरणे, जो convolutional layers वर आधारित आहे परंतु modern network designs स्वीकारतो.

> [!TIP]
> तिसरा approach Transformers आणि convolutions यांचे मिश्रण करतो (उदाहरणार्थ, [Convolutional Vision Transformer](https://huggingface.co/docs/transformers/model_doc/cvt) किंवा [LeViT](https://huggingface.co/docs/transformers/model_doc/levit)). आपण यांची चर्चा करणार नाही कारण आपण येथे पाहत असलेल्या दोन approaches चेच ते combination आहेत.

ViT आणि ConvNeXT सामान्यतः image classification साठी वापरले जातात. मात्र object detection, segmentation आणि depth estimation यांसारख्या इतर vision tasks साठी आपण अनुक्रमे DETR, Mask2Former आणि GLPN पाहणार आहोत. ही models त्या tasks साठी अधिक योग्य आहेत.

### Image classification

Image classification हे computer vision मधील एक fundamental task आहे. वेगवेगळ्या model architectures या problem कडे कशा प्रकारे पाहतात ते पाहूया.

ViT आणि ConvNeXT दोन्ही image classification साठी वापरता येतात. मुख्य फरक असा आहे की ViT attention mechanism वापरते, तर ConvNeXT convolutions वापरते.

[ViT](https://huggingface.co/docs/transformers/model_doc/vit) convolutions पूर्णपणे replace करून pure Transformer architecture वापरते. जर तुम्हाला original Transformer ची माहिती असेल, तर ViT समजून घेण्यासाठी तुम्ही आधीच बराच भाग शिकलेला आहे.

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/transformers/model_doc/vit_architecture.jpg"/>
</div>

ViT ने केलेला मुख्य बदल म्हणजे images Transformer ला कशा प्रकारे दिल्या जातात:

1. Image ला square non-overlapping patches मध्ये split केले जाते आणि प्रत्येक patch ला vector किंवा *patch embedding* मध्ये convert केले जाते. Patch embeddings हे convolutional 2D layer मधून तयार केले जातात, जे योग्य input dimensions तयार करते (base Transformer साठी प्रत्येक patch embedding मध्ये 768 values असतात). जर तुमच्याकडे 224x224 pixel image असेल, तर तुम्ही ती 196 16x16 image patches मध्ये split करू शकता. Text ज्या प्रकारे words मध्ये tokenize केला जातो, त्याच प्रकारे image ला patches च्या sequence मध्ये "tokenize" केले जाते.

2. BERT प्रमाणेच patch embeddings च्या सुरुवातीला एक *learnable embedding* — special `[CLS]` token — जोडला जातो. `[CLS]` token ची final hidden state ही attached classification head साठी input म्हणून वापरली जाते; इतर outputs दुर्लक्षित केले जातात. हा token model ला image चे representation कसे encode करायचे हे शिकण्यास मदत करतो.

3. Patch आणि learnable embeddings मध्ये आणखी एक गोष्ट जोडणे आवश्यक आहे — *position embeddings* — कारण image patches कोणत्या क्रमाने आहेत हे model ला माहीत नसते. Position embeddings देखील learnable असतात आणि त्यांचा आकार patch embeddings इतकाच असतो. शेवटी, सर्व embeddings Transformer encoder कडे पाठवले जातात.

4. Output, विशेषतः `[CLS]` token असलेला output, multilayer perceptron head (MLP) कडे पाठवला जातो. ViT चे pretraining objective हे simply classification आहे. इतर classification heads प्रमाणे, MLP head output ला class labels वरील logits मध्ये convert करते आणि सर्वात संभाव्य class शोधण्यासाठी cross-entropy loss calculate करते.

Image classification स्वतः करून पाहण्यास तयार आहात? ViT fine-tune करून inference मध्ये वापरण्यासाठी आमचे complete [image classification guide](https://huggingface.co/docs/transformers/tasks/image_classification) पहा!

> [!TIP]
> ViT आणि BERT यांच्यातील similarity लक्षात घ्या: दोन्ही overall representation capture करण्यासाठी एक special token (<code>[CLS]</code>) वापरतात, दोन्ही त्यांच्या embeddings मध्ये position information जोडतात आणि दोन्ही tokens/patches च्या sequence वर process करण्यासाठी Transformer encoder वापरतात.
