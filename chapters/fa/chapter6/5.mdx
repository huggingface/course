## الگوریتم تعلیم[[training-algorithm]]

تعلیم BPE با محاسبه‌ی مجموعه‌ی یکتای کلمه‌های استفاده‌شده در پیکره آغاز می‌شود (پس از تکمیل مراحل نرمال‌سازی و پیش‌توکِن‌سازی) و سپس با برداشتن همه‌ی علامت‌هایی که برای نوشتن این کلمه‌ها به کار رفته‌اند، واژگان را می‌سازد. برای نمونه‌ای بسیار ساده، فرض کنید پیکره‌ی ما از این پنج کلمه استفاده می‌کند:

<div dir="ltr">

```
"hug", "pug", "pun", "bun", "hugs"
```

</div>

واژگان پایه در این حالت `["b", "g", "h", "n", "p", "s", "u"]` خواهد بود. در نمونه‌های واقعی، این واژگان دست‌کم همه‌ی نویسه‌های ASCII و احتمالاً تعدادی نویسه‌ی Unicode را نیز دربرمی‌گیرد. اگر متنی که توکِن‌سازی می‌کنید نویسه‌ای داشته باشد که در پیکره‌ی تعلیم وجود نداشته است، آن نویسه به توکِن ناشناخته تبدیل می‌شود. به همین دلیل، برای مثال، بسیاری از مدل‌های NLP در تحلیل محتواهای دارای ایموجی عملکرد بسیار ضعیفی دارند.

> [!TIP]
> توکِنایزرهای GPT-2 و RoBERTa (که شباهت زیادی به هم دارند) راه هوشمندانه‌ای برای حل این مسئله دارند: آن‌ها کلمه‌ها را به‌صورت رشته‌ای از نویسه‌های Unicode در نظر نمی‌گیرند، بلکه آن‌ها را با بایت‌ها نمایش می‌دهند. در نتیجه، اندازه‌ی واژگان پایه کوچک (۲۵۶) می‌ماند، اما هر نویسه‌ای که بتوانید تصور کنید همچنان در آن جای می‌گیرد و به توکِن ناشناخته تبدیل نمی‌شود. این روش *BPE در سطح بایت* نام دارد.

پس از به‌دست‌آوردن این واژگان پایه، با یادگیری *ادغام‌ها*، توکِن‌های جدیدی اضافه می‌کنیم تا به اندازه‌ی مطلوب واژگان برسیم. ادغام‌ها قواعدی هستند که دو عنصر از واژگان موجود را در یک عنصر جدید ادغام می‌کنند. بنابراین، این ادغام‌ها در ابتدا توکِن‌های دوحرفی و با پیشرفت تعلیم، زیرکلمه‌های طولانی‌تری می‌سازند.

الگوریتم BPE در هر گام تعلیم توکِنایزر، پرتکرارترین جفت توکِن‌های موجود را پیدا می‌کند (منظور از «جفت» در اینجا دو توکِن پشت‌سرهم در یک کلمه است). همان جفت پرتکرار ادغام می‌شود و این کار در گام بعدی تکرار می‌شود.

به نمونه‌ی قبلی برگردیم و فرض کنیم کلمه‌ها بسامدهای زیر را داشته باشند:

<div dir="ltr">

```
("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)
```

</div>

یعنی کلمه‌ی `"hug"` ده بار، `"pug"` پنج بار، `"pun"` دوازده بار، `"bun"` چهار بار و `"hugs"` پنج بار در پیکره ظاهر شده‌اند. تعلیم را با تقسیم هر کلمه به نویسه‌ها (نویسه‌هایی که واژگان اولیه‌ی ما را تشکیل می‌دهند) شروع می‌کنیم تا بتوانیم هر کلمه را به‌صورت فهرستی از توکِن‌ها ببینیم:

<div dir="ltr">

```
("h" "u" "g", 10), ("p" "u" "g", 5), ("p" "u" "n", 12), ("b" "u" "n", 4), ("h" "u" "g" "s", 5)
```

</div>

سپس جفت‌ها را بررسی می‌کنیم. جفت `("h", "u")` در کلمه‌های `"hug"` و `"hugs"` وجود دارد، بنابراین در مجموع ۱۵ بار در پیکره دیده می‌شود. بااین‌حال، این جفت پرتکرارترین جفت نیست؛ این عنوان به `("u", "g")` تعلق دارد که در `"hug"`، `"pug"` و `"hugs"` وجود دارد و در مجموع ۲۰ بار در واژگان دیده می‌شود.

بنابراین، نخستین قاعده‌ی ادغامِ یادگرفته‌شده توسط توکِنایزر `("u", "g") -> "ug"` است؛ یعنی `"ug"` به واژگان اضافه می‌شود و این جفت باید در همه‌ی کلمه‌های پیکره ادغام شود. در پایان این مرحله، واژگان و پیکره به شکل زیر درمی‌آیند:

<div dir="ltr">

```
Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug"]
Corpus: ("h" "ug", 10), ("p" "ug", 5), ("p" "u" "n", 12), ("b" "u" "n", 4), ("h" "ug" "s", 5)
```

</div>

اکنون جفت‌هایی داریم که به توکِنی طولانی‌تر از دو نویسه منجر می‌شوند؛ برای نمونه جفت `("h", "ug")` (که ۱۵ بار در پیکره وجود دارد). بااین‌حال، پرتکرارترین جفت در این مرحله `("u", "n")` است که ۱۶ بار در پیکره دیده می‌شود؛ بنابراین دومین قاعده‌ی ادغامِ یادگرفته‌شده `("u", "n") -> "un"` است. با افزودن این قاعده به واژگان و ادغام همه‌ی نمونه‌های موجود، به نتیجه‌ی زیر می‌رسیم:

<div dir="ltr">

```
Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug", "un"]
Corpus: ("h" "ug", 10), ("p" "ug", 5), ("p" "un", 12), ("b" "un", 4), ("h" "ug" "s", 5)
```

</div>

اکنون پرتکرارترین جفت `("h", "ug")` است؛ پس قاعده‌ی ادغام `("h", "ug") -> "hug"` را یاد می‌گیریم که نخستین توکِن سه‌حرفی ما را ایجاد می‌کند. پس از این ادغام، پیکره به شکل زیر درمی‌آید:

<div dir="ltr">

```
Vocabulary: ["b", "g", "h", "n", "p", "s", "u", "ug", "un", "hug"]
Corpus: ("hug", 10), ("p" "ug", 5), ("p" "un", 12), ("b" "un", 4), ("hug" "s", 5)
```

</div>

این روند را تا رسیدن به اندازه‌ی مطلوب واژگان ادامه می‌دهیم.

> [!TIP]
> ✏️ **حالا نوبت شماست!** به نظر شما قاعده‌ی ادغام بعدی چه خواهد بود؟

## الگوریتم توکِن‌سازی[[tokenization-algorithm]]

توکِن‌سازی با فرایند تعلیم ارتباط نزدیکی دارد؛ به این معنا که ورودی‌های جدید با اجرای گام‌های زیر توکِن‌سازی می‌شوند:

<div dir="rtl">

1. نرمال‌سازی
2. پیش‌توکِن‌سازی
3. تقسیم کلمه‌ها به نویسه‌های منفرد
4. اجرای قواعد ادغامی که به‌ترتیب روی این تقسیم‌ها یاد گرفته شده‌اند

</div>

نمونه‌ای را که هنگام تعلیم استفاده کردیم، با همان سه قاعده‌ی ادغامِ یادگرفته‌شده در نظر بگیرید:

<div dir="ltr">

```
("u", "g") -> "ug"
("u", "n") -> "un"
("h", "ug") -> "hug"
```

</div>

کلمه‌ی `"bug"` به‌صورت `["b", "ug"]` توکِن‌سازی می‌شود. اما `"mug"` به `["[UNK]", "ug"]` توکِن‌سازی خواهد شد، چون حرف `"m"` در واژگان پایه وجود نداشت. به همین ترتیب، کلمه‌ی `"thug"` به `["[UNK]", "hug"]` تبدیل می‌شود: حرف `"t"` در واژگان پایه نیست و اجرای قواعد ادغام ابتدا باعث ادغام `"u"` و `"g"` و سپس ادغام `"h"` و `"ug"` می‌شود.

> [!TIP]
> ✏️ **حالا نوبت شماست!** به نظر شما کلمه‌ی `"unhug"` چگونه توکِن‌سازی خواهد شد؟

## پیاده‌سازی BPE[[implementing-bpe]]

حالا نگاهی به پیاده‌سازی الگوریتم BPE بیندازیم. این نسخه بهینه‌شده‌ای نیست که بتوانید واقعاً روی پیکره‌ای بزرگ به کار ببرید؛ هدف ما فقط این است که کد را نشان دهیم تا الگوریتم را کمی بهتر درک کنید.

ابتدا به یک پیکره نیاز داریم، پس پیکره‌ای ساده با چند جمله ایجاد می‌کنیم:


حالا که برای تعلیم آماده‌ایم، تابعی می‌نویسیم که بسامد هر جفت را محاسبه کند. در هر گام تعلیم به این تابع نیاز خواهیم داشت:

<div dir="ltr">

```python
def compute_pair_freqs(splits):
    pair_freqs = defaultdict(int)
    for word, freq in word_freqs.items():
        split = splits[word]
        if len(split) == 1:
            continue
        for i in range(len(split) - 1):
            pair = (split[i], split[i + 1])
            pair_freqs[pair] += freq
    return pair_freqs
```

</div>


برای ادامه، باید این ادغام را در دیکشنری `splits` اعمال کنیم. بیایید تابع دیگری برای این کار بنویسیم:

<div dir="ltr">

```python
def merge_pair(a, b, splits):
    for word in word_freqs:
        split = splits[word]
        if len(split) == 1:
            continue

        i = 0
        while i < len(split) - 1:
            if split[i] == a and split[i + 1] == b:
                split = split[:i] + [a + b] + split[i + 2 :]
            else:
                i += 1
        splits[word] = split
    return splits
```

</div>

و می‌توانیم نتیجه‌ی نخستین ادغام را بررسی کنیم:

<div dir="ltr">

```py

print(splits["Ġtrained"])
```

```python
vocab_size = 50
```

> [!TIP]
> 💡 اجرای `train_new_from_iterator()` روی همان پیکره دقیقاً به همین واژگان منجر نمی‌شود. دلیلش این است که هنگام وجود چند گزینه برای پرتکرارترین جفت، ما نخستین جفتی را که دیده‌ایم انتخاب کردیم؛ درحالی‌که کتابخانه‌ی 🤗 Tokenizers نخستین جفت را بر اساس شناسه‌های داخلی آن انتخاب می‌کند.

برای توکِن‌سازی یک متن جدید، ابتدا آن را پیش‌توکِن‌سازی و تقسیم می‌کنیم و سپس همه‌ی قواعد ادغامِ یادگرفته‌شده را اعمال می‌کنیم:

<div dir="ltr">

```python
def tokenize(text):
    pre_tokenize_result = tokenizer._tokenizer.pre_tokenizer.pre_tokenize_str(text)
    pre_tokenized_text = [word for word, offset in pre_tokenize_result]
    splits = [[l for l in word] for word in pre_tokenized_text]
    for pair, merge in merges.items():
        for idx, split in enumerate(splits):
            i = 0
            while i < len(split) - 1:
                if split[i] == pair[0] and split[i + 1] == pair[1]:
                    split = split[:i] + [merge] + split[i + 2 :]
                else:
                    i += 1
            splits[idx] = split

    return sum(splits, [])
```
