## استفاده از خط تولید `question-answering`[[using-the-question-answering-pipeline]]

همان‌طور که در [فصل ۱](/course/chapter1) دیدیم، می‌توانیم از خط تولید `question-answering` به شکل زیر برای پیدا کردن پاسخ یک پرسش استفاده کنیم:

<div dir="ltr">

```py
from transformers import pipeline

question_answerer = pipeline("question-answering")
context = """
🤗 Transformers is backed by the three most popular deep learning libraries — Jax, PyTorch, and TensorFlow — with a seamless integration
between them. It's straightforward to train your models with one before loading them for inference with the other.
"""
question = "Which deep learning libraries back 🤗 Transformers?"
question_answerer(question=question, context=context)
```

## استفاده از یک مدل برای پاسخ‌گویی به پرسش[[using-a-model-for-question-answering]]

مانند هر خط تولید دیگری، کار را با توکِن‌سازی ورودی شروع می‌کنیم و سپس آن را از مدل عبور می‌دهیم. نقطه‌ی تعلیم پیش‌فرض خط تولید `question-answering`، [`distilbert-base-cased-distilled-squad`](https://huggingface.co/distilbert-base-cased-distilled-squad) است (واژه‌ی «squad» در نام مدل از دیتاستی می‌آید که مدل روی آن کوک شده است؛ در [فصل ۷](/course/chapter7/7) بیشتر درباره‌ی دیتاست SQuAD صحبت می‌کنیم):

{#if fw === 'pt'}

<div dir="ltr">

```py
from transformers import AutoTokenizer, AutoModelForQuestionAnswering

model_checkpoint = "distilbert-base-cased-distilled-squad"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
model = AutoModelForQuestionAnswering.from_pretrained(model_checkpoint)

inputs = tokenizer(question, context, return_tensors="pt")
outputs = model(**inputs)
```

</div>

{:else}

<div dir="ltr">

```py
from transformers import AutoTokenizer, TFAutoModelForQuestionAnswering

model_checkpoint = "distilbert-base-cased-distilled-squad"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
model = TFAutoModelForQuestionAnswering.from_pretrained(model_checkpoint)

inputs = tokenizer(question, context, return_tensors="tf")
outputs = model(**inputs)
```

</div>

{/if}

مدل‌های پاسخ‌گویی به پرسش کمی متفاوت از مدل‌هایی هستند که تا اینجا دیده‌ایم. با استفاده از تصویر بالا به‌عنوان مثال، مدل تعلیم دیده است تا اندیس توکِنی را که پاسخ از آن شروع می‌شود (در اینجا ۲۱) و اندیس توکِنی را که پاسخ در آن تمام می‌شود (در اینجا ۲۴) پیش‌بینی کند. به همین دلیل این مدل‌ها به‌جای یک تِنسور logit، دو تِنسور برمی‌گردانند: یکی برای logitهای متناظر با توکِن آغاز پاسخ و دیگری برای logitهای متناظر با توکِن پایان پاسخ. از آنجا که در اینجا فقط یک ورودی شامل ۶۶ توکِن داریم، نتیجه‌ی زیر را می‌گیریم:

<div dir="ltr">

```py
start_logits = outputs.start_logits
end_logits = outputs.end_logits
print(start_logits.shape, end_logits.shape)
```

</div>

{#if fw === 'pt'}

<div dir="ltr">

```python out
torch.Size([1, 66]) torch.Size([1, 66])
```

</div>

{:else}

<div dir="ltr">

```python out
(1, 66) (1, 66)
```

</div>

{/if}

برای تبدیل این logitها به احتمال، تابع softmax را اعمال می‌کنیم — اما پیش از آن باید مطمئن شویم اندیس‌هایی را که بخشی از متن زمینه نیستند ماسک می‌کنیم. ورودی ما به شکل `[CLS] question [SEP] context [SEP]` است، پس باید توکِن‌های پرسش و همچنین توکِن `[SEP]` را ماسک کنیم. بااین‌حال توکِن `[CLS]` را نگه می‌داریم، چون برخی مدل‌ها از آن برای نشان دادن نبودن پاسخ در متن زمینه استفاده می‌کنند.

از آنجا که بعداً softmax را اعمال می‌کنیم، کافی است logitهایی را که می‌خواهیم ماسک کنیم با عددی منفی و بزرگ جایگزین کنیم. در اینجا از `-10000` استفاده می‌کنیم:

{#if fw === 'pt'}

<div dir="ltr">

```py
import torch

sequence_ids = inputs.sequence_ids()
# Mask everything apart from the tokens of the context
mask = [i != 1 for i in sequence_ids]
# Unmask the [CLS] token
mask[0] = False
mask = torch.tensor(mask)[None]

start_logits[mask] = -10000
end_logits[mask] = -10000
```

</div>

{:else}

<div dir="ltr">

```py
import tensorflow as tf

sequence_ids = inputs.sequence_ids()
# Mask everything apart from the tokens of the context
mask = [i != 1 for i in sequence_ids]
# Unmask the [CLS] token
mask[0] = False
mask = tf.constant(mask)[None]

start_logits = tf.where(mask, -10000, start_logits)
end_logits = tf.where(mask, -10000, end_logits)
```

</div>

{/if}

حالا که logitهای متناظر با موقعیت‌هایی را که نمی‌خواهیم پیش‌بینی شوند به‌درستی ماسک کرده‌ایم، می‌توانیم softmax را اعمال کنیم:

{#if fw === 'pt'}

<div dir="ltr">

```py
start_probabilities = torch.nn.functional.softmax(start_logits, dim=-1)[0]
end_probabilities = torch.nn.functional.softmax(end_logits, dim=-1)[0]
```

</div>

{:else}

<div dir="ltr">

```py
start_probabilities = tf.math.softmax(start_logits, axis=-1)[0].numpy()
end_probabilities = tf.math.softmax(end_logits, axis=-1)[0].numpy()
```

</div>

{/if}

در این مرحله می‌توانستیم روی احتمال‌های آغاز و پایان argmax بگیریم — اما ممکن بود به اندیس آغازی برسیم که از اندیس پایان بزرگ‌تر باشد، پس باید چند احتیاط دیگر انجام دهیم. احتمال هر `start_index` و `end_index` ممکن را که در آن `start_index <= end_index` است محاسبه می‌کنیم، سپس تاپل `(start_index, end_index)` با بیشترین احتمال را برمی‌گزینیم.

با فرض مستقل بودن رویدادهای «پاسخ از `start_index` شروع می‌شود» و «پاسخ در `end_index` تمام می‌شود»، احتمال اینکه پاسخ از `start_index` شروع شود و در `end_index` پایان یابد برابر است با:

$$\mathrm{start\_probabilities}[\mathrm{start\_index}] \times \mathrm{end\_probabilities}[\mathrm{end\_index}]$$

بنابراین برای محاسبه‌ی همه‌ی امتیازها، کافی است همه‌ی حاصل‌ضرب‌های \(\mathrm{start\_probabilities}[\mathrm{start\_index}] \times \mathrm{end\_probabilities}[\mathrm{end\_index}]\) را که در آن‌ها `start_index <= end_index` است محاسبه کنیم.

ابتدا همه‌ی حاصل‌ضرب‌های ممکن را محاسبه می‌کنیم:

<div dir="ltr">

```py
scores = start_probabilities[:, None] * end_probabilities[None, :]
```

</div>

{#if fw === 'pt'}

سپس مقدارهایی را که در آن‌ها `start_index > end_index` است با قرار دادن مقدارشان روی `0` ماسک می‌کنیم (همه‌ی احتمال‌های دیگر عددهایی مثبت‌اند). تابع `torch.triu()` بخش مثلث بالایی تِنسور دوبعدیِ داده‌شده به‌عنوان آرگومان را برمی‌گرداند، پس این ماسک‌گذاری را برای ما انجام می‌دهد:

<div dir="ltr">

```py
scores = torch.triu(scores)
```

</div>

{:else}

سپس مقدارهایی را که در آن‌ها `start_index > end_index` است با قرار دادن مقدارشان روی `0` ماسک می‌کنیم (همه‌ی احتمال‌های دیگر عددهایی مثبت‌اند). تابع `np.triu()` بخش مثلث بالایی تِنسور دوبعدیِ داده‌شده به‌عنوان آرگومان را برمی‌گرداند، پس این ماسک‌گذاری را برای ما انجام می‌دهد:

<div dir="ltr">

```py
import numpy as np

scores = np.triu(scores)
```

</div>

{/if}

حالا فقط باید اندیس بیشینه را به دست آوریم. چون PyTorch اندیس را در تِنسور تخت‌شده برمی‌گرداند، باید از عملگرهای تقسیم صحیح `//` و باقیمانده `%` برای به دست آوردن `start_index` و `end_index` استفاده کنیم:

<div dir="ltr">

```py
max_index = scores.argmax().item()
start_index = max_index // scores.shape[1]
end_index = max_index % scores.shape[1]
print(scores[start_index, end_index])
```

</div>

هنوز کاملاً تمام نشده‌ایم، اما دست‌کم امتیاز درست پاسخ را داریم (می‌توانید با مقایسه‌ی آن با نخستین نتیجه‌ی بخش قبلی این موضوع را بررسی کنید):

<div dir="ltr">

```python out
0.97773
```

</div>

> [!TIP]
> ✏️ **امتحان کنید!** اندیس‌های آغاز و پایان پنج پاسخ محتمل‌تر را محاسبه کنید.

حالا `start_index` و `end_index` پاسخ را برحسب توکِن داریم، پس فقط باید آن‌ها را به اندیس‌های نویسه‌ای در متن زمینه تبدیل کنیم. اینجاست که offsetها بسیار مفید خواهند بود. می‌توانیم آن‌ها را بگیریم و درست مانند وظیفه‌ی دسته‌بندی توکِن از آن‌ها استفاده کنیم:

<div dir="ltr">

```py
inputs_with_offsets = tokenizer(question, context, return_offsets_mapping=True)
offsets = inputs_with_offsets["offset_mapping"]

start_char, _ = offsets[start_index]
_, end_char = offsets[end_index]
answer = context[start_char:end_char]
```

</div>

حالا فقط باید همه‌چیز را قالب‌بندی کنیم تا نتیجه‌مان به دست آید:

<div dir="ltr">

```py
result = {
    "answer": answer,
    "start": start_char,
    "end": end_char,
    "score": scores[start_index, end_index],
}
print(result)
```

</div>

<div dir="ltr">

```python out
{'answer': 'Jax, PyTorch and TensorFlow',
 'start': 78,
 'end': 105,
 'score': 0.97773}
```

</div>

عالی است! این همان نتیجه‌ای است که در مثال اول گرفتیم!

> [!TIP]
> ✏️ **امتحان کنید!** از بهترین امتیازهایی که پیش‌تر محاسبه کردید استفاده کنید تا پنج پاسخ محتمل‌تر را نشان دهید. برای بررسی نتایج، به خط تولید اول برگردید و هنگام فراخوانی آن، `top_k=5` را به آن بدهید.

## کار با متن‌های زمینه‌ی طولانی[[handling-long-contexts]]

اگر بخواهیم پرسش و متن زمینه‌ی طولانی‌ای را که پیش‌تر به‌عنوان مثال استفاده کردیم توکِن‌سازی کنیم، تعداد توکِن‌ها از حداکثر طول مورد استفاده در خط تولید `question-answering` (که ۳۸۴ است) بیشتر خواهد شد:

<div dir="ltr">

```py
inputs = tokenizer(question, long_context)
print(len(inputs["input_ids"]))
```

</div>

<div dir="ltr">

```python out
461
```

</div>

این یعنی مدل برای پیدا کردن پاسخ درست کار دشواری خواهد داشت. برای حل این مشکل، خط تولید `question-answering` به ما اجازه می‌دهد متن زمینه را به قطعه‌های کوچک‌تر تقسیم کنیم و حداکثر طول را مشخص کنیم. برای اینکه متن زمینه را دقیقاً در نقطه‌ای نامناسب تقسیم نکنیم و امکان پیدا کردن پاسخ از بین نرود، بین قطعه‌ها مقداری هم‌پوشانی نیز قرار می‌دهد.

می‌توانیم از توکِنایزر (سریع یا کند) بخواهیم این کار را برای ما انجام دهد؛ کافی است `return_overflowing_tokens=True` را اضافه کنیم و با آرگومان `stride` میزان هم‌پوشانی را مشخص کنیم. در ادامه مثالی با جمله‌ای کوتاه‌تر می‌بینید:

<div dir="ltr">

```py
sentence = "This sentence is not too long but we are going to split it anyway."
inputs = tokenizer(
    sentence, truncation=True, return_overflowing_tokens=True, max_length=6, stride=2
)

for ids in inputs["input_ids"]:
```
