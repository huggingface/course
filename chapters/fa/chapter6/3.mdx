## رمزگذاری بتچ[[batch-encoding]]

<Youtube id="3umI3tm27Vw"/>

خروجی یک توکِنایزر، یک دیکشنری ساده‌ی پایتون نیست؛ چیزی که در واقع دریافت می‌کنیم یک شیء ویژه‌ی `BatchEncoding` است. این شیء زیرکلاسی از یک دیکشنری است (به همین دلیل پیش‌تر توانستیم بدون مشکل در نتیجه اندیس‌گذاری کنیم)، اما متدهای اضافی‌ای دارد که بیشتر برای توکِنایزرهای سریع استفاده می‌شوند.

جدا از قابلیت‌های موازی‌سازی، عملکرد اصلی توکِنایزرهای سریع این است که همیشه بازه‌ی اصلی متنی را که توکِن‌های نهایی از آن آمده‌اند دنبال می‌کنند — قابلیتی که آن را *نگاشت offset* می‌نامیم. این قابلیت به نوبه‌ی خود امکاناتی مانند نگاشت هر کلمه به توکِن‌هایی که تولید کرده یا نگاشت هر نویسه از متن اصلی به توکِنی که آن را دربر دارد و برعکس را ممکن می‌کند.

بیایید یک مثال را بررسی کنیم:

<div dir="ltr">

```py
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-cased")
example = "My name is Sylvain and I work at Hugging Face in Brooklyn."
encoding = tokenizer(example)
print(type(encoding))
```

</div>

همان‌طور که پیش‌تر گفتیم، در خروجی توکِنایزر یک شیء `BatchEncoding` دریافت می‌کنیم:

<div dir="ltr">

```python out
<class 'transformers.tokenization_utils_base.BatchEncoding'>
```

</div>

از آنجا که کلاس `AutoTokenizer` به‌صورت پیش‌فرض یک توکِنایزر سریع انتخاب می‌کند، می‌توانیم از متدهای اضافی‌ای که این شیء `BatchEncoding` ارائه می‌دهد استفاده کنیم. برای بررسی سریع یا کند بودن توکِنایزرمان دو راه داریم. می‌توانیم ویژگی `is_fast` مربوط به `tokenizer` را بررسی کنیم:

<div dir="ltr">

```python
tokenizer.is_fast
```

</div>

<div dir="ltr">

```python out
True
```

</div>

یا همین ویژگی را در `encoding` بررسی کنیم:

<div dir="ltr">

```python
encoding.is_fast
```

</div>

<div dir="ltr">

```python out
True
```

</div>

بیایید ببینیم توکِنایزر سریع چه امکاناتی در اختیار ما می‌گذارد. نخست، می‌توانیم بدون تبدیل شناسه‌ها به توکِن، مستقیماً به توکِن‌ها دسترسی پیدا کنیم:

<div dir="ltr">

```py
encoding.tokens()
```

</div>

<div dir="ltr">

```python out
['[CLS]', 'My', 'name', 'is', 'S', '##yl', '##va', '##in', 'and', 'I', 'work', 'at', 'Hu', '##gging', 'Face', 'in',
 'Brooklyn', '.', '[SEP]']
```

</div>

در اینجا توکِنِ اندیس ۵ یعنی `##yl` بخشی از کلمه‌ی «Sylvain» در جمله‌ی اصلی است. همچنین می‌توانیم از متد `word_ids()` استفاده کنیم تا اندیس کلمه‌ای را که هر توکِن از آن آمده به دست آوریم:

<div dir="ltr">

```py
encoding.word_ids()
```

</div>

<div dir="ltr">

```python out
[None, 0, 1, 2, 3, 3, 3, 3, 4, 5, 6, 7, 8, 8, 9, 10, 11, 12, None]
```

</div>

می‌بینیم که توکِن‌های ویژه‌ی توکِنایزر یعنی `[CLS]` و `[SEP]` به `None` نگاشت شده‌اند و سپس هر توکِن به کلمه‌ای که از آن منشأ گرفته نگاشت می‌شود. این قابلیت به‌ویژه برای تشخیص اینکه یک توکِن در ابتدای کلمه قرار دارد یا اینکه دو توکِن متعلق به یک کلمه هستند مفید است. می‌توانستیم برای این کار به پیشوند `##` تکیه کنیم، اما این روش فقط برای توکِنایزرهای شبیه BERT کار می‌کند؛ روش حاضر برای هر نوع توکِنایزر، به شرط سریع بودن آن، کار می‌کند. در فصل بعد می‌بینیم چگونه می‌توانیم از این قابلیت برای اعمال درست برچسب‌های هر کلمه روی توکِن‌ها در وظایفی مانند تشخیص موجودیت نامدار (NER) و برچسب‌گذاری نقش دستوری (POS) استفاده کنیم. همچنین می‌توانیم از آن برای ماسک کردن همه‌ی توکِن‌های متعلق به یک کلمه در مدل‌سازی زبان ماسک‌شده (تکنیکی به نام _ماسک‌گذاری کل کلمه_) استفاده کنیم.

> [!TIP]
> مفهوم «کلمه» پیچیده است. برای مثال، آیا «I'll» (شکل کوتاه‌شده‌ی «I will») یک کلمه محسوب می‌شود یا دو کلمه؟ پاسخ در واقع به توکِنایزر و عملیاتی که برای پیش‌توکِن‌سازی انجام می‌دهد بستگی دارد. برخی توکِنایزرها فقط بر اساس فاصله‌ها جدا می‌کنند، پس این مورد را یک کلمه در نظر می‌گیرند. برخی دیگر علاوه بر فاصله‌ها از علائم نگارشی نیز استفاده می‌کنند و آن را دو کلمه در نظر می‌گیرند.
>
> ✏️ **امتحان کنید!** با استفاده از نقاط تعلیم `bert-base-cased` و `roberta-base` یک توکِنایزر بسازید و با آن‌ها «81s» را توکِن‌سازی کنید. چه چیزی مشاهده می‌کنید؟ شناسه‌های کلمه چه هستند؟

به‌طور مشابه، متد `sentence_ids()` را داریم که می‌توانیم از آن برای نگاشت یک توکِن به جمله‌ای که از آن آمده استفاده کنیم (البته در این مورد، `token_type_ids` برگشتی از توکِنایزر می‌تواند همین اطلاعات را به ما بدهد).

در نهایت، می‌توانیم هر کلمه یا توکِن را با استفاده از متدهای `word_to_chars()` یا `token_to_chars()` و `char_to_word()` یا `char_to_token()` به نویسه‌های متن اصلی نگاشت کنیم و برعکس. برای مثال، متد `word_ids()` به ما گفت که `##yl` بخشی از کلمه‌ی اندیس ۳ است، اما این کلمه در جمله کدام است؟ می‌توانیم این‌طور متوجه شویم:

<div dir="ltr">

```py
start, end = encoding.word_to_chars(3)
example[start:end]
```

</div>

<div dir="ltr">

```python out
Sylvain
```

</div>

همان‌طور که پیش‌تر گفتیم، همه‌ی این قابلیت‌ها به این دلیل ممکن‌اند که توکِنایزر سریع بازه‌ی متنی مربوط به هر توکِن را در فهرستی از *offsetها* دنبال می‌کند. برای نشان دادن کاربرد آن‌ها، در ادامه نحوه‌ی بازتولید دستی نتایج خط تولید `token-classification` را نشان می‌دهیم.

> [!TIP]
> ✏️ **امتحان کنید!** یک متن نمونه‌ی خودتان بسازید و ببینید آیا می‌توانید بفهمید کدام توکِن‌ها به یک شناسه‌ی کلمه مربوط‌اند و چگونه بازه‌های نویسه‌ای یک کلمه‌ی واحد را استخراج کنید. برای امتیاز بیشتر، دو جمله را به‌عنوان ورودی استفاده کنید و ببینید شناسه‌های جمله برایتان منطقی هستند یا نه.

## درون خط تولید `token-classification`[[inside-the-token-classification-pipeline]]

در [فصل ۱](/course/chapter1)، نخستین تجربه‌ی خود را از به‌کارگیری NER داشتیم — وظیفه‌ای که در آن باید مشخص کنیم کدام بخش‌های متن به موجودیت‌هایی مانند افراد، مکان‌ها یا سازمان‌ها مربوط‌اند — و برای این کار از تابع `pipeline()` در 🤗 Transformers استفاده کردیم. سپس در [فصل ۲](/course/chapter2) دیدیم که خط تولید چگونه سه مرحله‌ی لازم برای گرفتن پیش‌بینی از یک متن خام را کنار هم قرار می‌دهد: توکِن‌سازی، عبور دادن ورودی‌ها از مدل و پس‌پردازش. دو مرحله‌ی اول خط تولید `token-classification` مانند هر خط تولید دیگری هستند، اما پس‌پردازش کمی پیچیده‌تر است — بیایید ببینیم چگونه!

### به‌دست‌آوردن نتایج پایه با خط تولید[[getting-the-base-results-with-the-pipeline]]

ابتدا یک خط تولید دسته‌بندی توکِن می‌گیریم تا بتوانیم نتایجی برای مقایسه‌ی دستی به دست آوریم. مدل پیش‌فرض [`dbmdz/bert-large-cased-finetuned-conll03-english`](https://huggingface.co/dbmdz/bert-large-cased-finetuned-conll03-english) است؛ این مدل روی جمله‌ها NER انجام می‌دهد:

<div dir="ltr">

```py
from transformers import pipeline

token_classifier = pipeline("token-classification")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

</div>

<div dir="ltr">

```python out

 {'entity': 'I-PER', 'score': 0.99590725, 'index': 6, 'word': '##va', 'start': 14, 'end': 16},
```

مدل هر توکِنی را که از «Sylvain» تولید شده به‌درستی به‌عنوان یک شخص، هر توکِنی را که از «Hugging Face» تولید شده به‌عنوان یک سازمان و توکِن «Brooklyn» را به‌عنوان یک مکان شناسایی کرد. همچنین می‌توانیم از خط تولید بخواهیم توکِن‌های مربوط به یک موجودیت یکسان را در کنار هم گروه‌بندی کند:

<div dir="ltr">

```py
from transformers import pipeline

token_classifier = pipeline("token-classification", aggregation_strategy="simple")
token_classifier("My name is Sylvain and I work at Hugging Face in Brooklyn.")
```

</div>

<div dir="ltr">

```python out
[{'entity_group': 'PER', 'score': 0.9981694, 'word': 'Sylvain', 'start': 11, 'end': 18},
 {'entity_group': 'ORG', 'score': 0.97960204, 'word': 'Hugging Face', 'start': 33, 'end': 45},
 {'entity_group': 'LOC', 'score': 0.99321055, 'word': 'Brooklyn', 'start': 49, 'end': 57}]
```

</div>

استراتژی `aggregation_strategy` انتخاب‌شده، امتیازهای محاسبه‌شده برای هر موجودیت گروه‌بندی‌شده را تغییر می‌دهد. در حالت `"simple"`، امتیاز فقط میانگین امتیازهای هر توکِن در موجودیت داده‌شده است: برای مثال، امتیاز «Sylvain» میانگین امتیازهایی است که در نمونه‌ی قبلی برای توکِن‌های `S`، `##yl`، `##va` و `##in` دیدیم. استراتژی‌های دیگری نیز وجود دارند:

- `"first"`، که در آن امتیاز هر موجودیت امتیاز نخستین توکِن آن موجودیت است (پس برای «Sylvain» برابر 0.993828، یعنی امتیاز توکِن `S`، خواهد بود)
- `"max"`، که در آن امتیاز هر موجودیت بیشینه‌ی امتیاز توکِن‌های آن موجودیت است (پس برای «Hugging Face» برابر 0.98879766، یعنی امتیاز «Face»، خواهد بود)
- `"average"`، که در آن امتیاز هر موجودیت میانگین امتیاز کلمه‌هایی است که آن موجودیت را تشکیل می‌دهند (پس برای «Sylvain» تفاوتی با استراتژی `"simple"` ندارد، اما امتیاز «Hugging Face» برابر 0.9819، میانگین امتیازهای «Hugging» یعنی 0.975 و «Face» یعنی 0.98879، خواهد بود)

حالا ببینیم چگونه می‌توانیم این نتایج را بدون استفاده از تابع `pipeline()` به دست آوریم!

### از ورودی‌ها تا پیش‌بینی‌ها[[from-inputs-to-predictions]]

{#if fw === 'pt'}

ابتدا باید ورودی خود را توکِن‌سازی کنیم و آن را از مدل عبور دهیم. این کار دقیقاً مانند [فصل ۲](/course/chapter2) انجام می‌شود؛ با استفاده از کلاس‌های `AutoXxx`، توکِنایزر و مدل را نمونه‌سازی می‌کنیم و سپس آن‌ها را روی مثال خود به کار می‌بریم:

<div dir="ltr">

```py
from transformers import AutoTokenizer, AutoModelForTokenClassification

model_checkpoint = "dbmdz/bert-large-cased-finetuned-conll03-english"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
model = AutoModelForTokenClassification.from_pretrained(model_checkpoint)

example = "My name is Sylvain and I work at Hugging Face in Brooklyn."
inputs = tokenizer(example, return_tensors="pt")
outputs = model(**inputs)
```

</div>

از آنجا که در اینجا از `AutoModelForTokenClassification` استفاده می‌کنیم، برای هر توکِن در دنباله‌ی ورودی یک مجموعه logit دریافت می‌کنیم:

<div dir="ltr">

```py
print(inputs["input_ids"].shape)
print(outputs.logits.shape)
```

</div>

<div dir="ltr">


</div>

همان‌طور که پیش‌تر دیدیم، ۹ برچسب داریم: `O` برچسب توکِن‌هایی است که در هیچ موجودیت نام‌داری نیستند (مخفف «outside» به معنای «بیرون» است) و سپس برای هر نوع موجودیت دو برچسب داریم (متفرقه، شخص، سازمان و مکان). برچسب `B-XXX` نشان می‌دهد توکِن در ابتدای موجودیت `XXX` قرار دارد و برچسب `I-XXX` نشان می‌دهد توکِن درون موجودیت `XXX` است. برای مثال، در نمونه‌ی فعلی انتظار داریم مدل توکِن `S` را با `B-PER` (آغاز موجودیت شخص) و توکِن‌های `##yl`، `##va` و `##in` را با `I-PER` (درون موجودیت شخص) دسته‌بندی کند.

ممکن است فکر کنید مدل در این مورد اشتباه کرده است، چون به هر چهار توکِن برچسب `I-PER` داده، اما این کاملاً درست نیست. در واقع دو قالب برای برچسب‌های `B-` و `I-` وجود دارد: *IOB1* و *IOB2*. قالب IOB2 (که در تصویر زیر به رنگ صورتی نشان داده شده) همان قالبی است که معرفی کردیم، درحالی‌که در قالب IOB1 (به رنگ آبی)، برچسب‌هایی که با `B-` شروع می‌شوند فقط برای جدا کردن دو موجودیت مجاور از یک نوع استفاده می‌شوند. مدل مورد استفاده‌ی ما روی دیتاستی با همین قالب کوک شده است و به همین دلیل برچسب `I-PER` را به توکِن `S` اختصاص می‌دهد.

### گروه‌بندی موجودیت‌ها[[grouping-entities]]

استفاده از offsetها برای تعیین کلیدهای شروع و پایان هر موجودیت مفید است، اما این اطلاعات ضرورتاً لازم نیستند. بااین‌حال، هنگام گروه‌بندی موجودیت‌ها offsetها مقدار زیادی از کدنویسی پیچیده را حذف می‌کنند. برای مثال، اگر بخواهیم توکِن‌های `Hu`، `##gging` و `Face` را با هم گروه‌بندی کنیم، می‌توانیم قواعد ویژه‌ای بنویسیم که بر اساس آن دو توکِن اول به هم متصل شوند و `##` از آن‌ها حذف شود و `Face` نیز چون با `##` شروع نمی‌شود با یک فاصله اضافه شود — اما این قواعد فقط برای همین نوع توکِنایزر کار می‌کنند. برای توکِنایزر SentencePiece یا Byte-Pair-Encoding (که بعداً در این فصل درباره‌شان صحبت می‌کنیم) باید مجموعه‌ی قواعد دیگری بنویسیم.

با offsetها، همه‌ی آن کدهای سفارشی از بین می‌روند: کافی است بازه‌ای از متن اصلی را برداریم که از اولین توکِن شروع می‌شود و به آخرین توکِن ختم می‌شود. بنابراین، در مورد توکِن‌های `Hu`، `##gging` و `Face`، باید از نویسه‌ی ۳۳ (ابتدای `Hu`) شروع کنیم و پیش از نویسه‌ی ۴۵ (انتهای `Face`) پایان دهیم:

<div dir="ltr">

```py
example[33:45]
```

</div>

<div dir="ltr">

```python out
Hugging Face
```

</div>

برای نوشتن کدی که هنگام گروه‌بندی موجودیت‌ها پیش‌بینی‌ها را پس‌پردازش می‌کند، موجودیت‌هایی را که پشت سر هم آمده‌اند و با `I-XXX` برچسب خورده‌اند در یک گروه قرار می‌دهیم؛ به‌جز نخستین موجودیت که می‌تواند `B-XXX` یا `I-XXX` باشد (پس هرگاه به `O`، نوع جدیدی از موجودیت یا `B-XXX`ای برسیم که آغاز موجودیتی از همان نوع را نشان می‌دهد، گروه‌بندی آن موجودیت را متوقف می‌کنیم):

<div dir="ltr">

```py
import numpy as np

results = []
inputs_with_offsets = tokenizer(example, return_offsets_mapping=True)
tokens = inputs_with_offsets.tokens()
offsets = inputs_with_offsets["offset_mapping"]

idx = 0
while idx < len(predictions):
    pred = predictions[idx]
    label = model.config.id2label[pred]
    if label != "O":
        # Remove the B- or I-
        label = label[2:]
        start, _ = offsets[idx]

        # Grab all the tokens labeled with I-label
        all_scores = []
        while (
            idx < len(predictions)
            and model.config.id2label[predictions[idx]] == f"I-{label}"
        ):
            all_scores.append(probabilities[idx][pred])
            _, end = offsets[idx]
            idx += 1

        # The score is the mean of all the scores of the tokens in that grouped entity
        score = np.mean(all_scores).item()
        word = example[start:end]
        results.append(
            {
                "entity_group": label,
                "score": score,
                "word": word,
                "start": start,
                "end": end,
            }
        )
    idx += 1

print(results)
```
