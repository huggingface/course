# استقرار بهینه‌ی استنتاج

در این بخش، چارچوب‌های پیشرفته‌ی بهینه‌سازی استقرار مدل‌های زبانی بزرگ را بررسی می‌کنیم: Text Generation Inference (TGI)، vLLM و llama.cpp. این برنامه‌ها عمدتاً در محیط‌های تولید برای ارائه‌ی مدل‌های زبانی بزرگ به کاربران استفاده می‌شوند. تمرکز این بخش بر نحوه‌ی استقرار این چارچوب‌ها در محیط تولید است، نه نحوه‌ی استفاده از آن‌ها برای استنتاج روی یک ماشین منفرد.

بررسی خواهیم کرد که این ابزارها چگونه کارایی استنتاج را به حداکثر می‌رسانند و استقرار مدل‌های زبانی بزرگ را در محیط تولید ساده‌تر می‌کنند.

## راهنمای انتخاب چارچوب

TGI، vLLM و llama.cpp هدف‌های مشابهی دارند، اما ویژگی‌های متمایزی دارند که باعث می‌شود هرکدام برای موارد استفاده‌ی متفاوتی مناسب‌تر باشند. بیایید تفاوت‌های کلیدی آن‌ها را با تمرکز بر عملکرد و یکپارچه‌سازی بررسی کنیم.

### مدیریت حافظه و عملکرد

**TGI** برای پایدار و قابل‌پیش‌بینی بودن در محیط تولید طراحی شده و از طول‌های ثابت رشته استفاده می‌کند تا مصرف حافظه را ثابت نگه دارد. TGI حافظه را با استفاده از Flash Attention 2 و تکنیک‌های بتچ‌سازی پیوسته مدیریت می‌کند. این یعنی می‌تواند محاسبات توجه را بسیار کارآمد انجام دهد و با تغذیه‌ی پیوسته‌ی کار، GPU را مشغول نگه دارد. سیستم می‌تواند در صورت نیاز بخش‌هایی از مدل را بین CPU و GPU جابه‌جا کند و به این ترتیب از مدل‌های بزرگ‌تر پشتیبانی کند.

<img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/tgi/flash-attn.png" alt="Flash Attention" />

<Tip title="Flash Attention چگونه کار می‌کند؟">

Flash Attention تکنیکی است که با برطرف کردن گلوگاه‌های پهنای باند حافظه، مکانیزم توجه را در مدل‌های ترنسفورمر بهینه می‌کند. همان‌طور که پیش‌تر در [بخش ۱.۸](/course/chapter1/8) گفتیم، مکانیزم توجه پیچیدگی و مصرف حافظه‌ی درجه‌دوم دارد و همین موضوع آن را برای رشته‌های طولانی ناکارآمد می‌کند.

نوآوری اصلی در نحوه‌ی مدیریت انتقال حافظه است. توجه سنتی داده‌ها را بارها بین حافظه‌ی با پهنای باند بالا (HBM) و کش سریع SRAM جابه‌جا می‌کند و با بیکار گذاشتن GPU گلوگاه ایجاد می‌کند. Flash Attention داده‌ها را یک‌بار در SRAM بارگذاری می‌کند و همه‌ی محاسبات را همان‌جا انجام می‌دهد؛ در نتیجه انتقال‌های پرهزینه‌ی حافظه به حداقل می‌رسند.

اگرچه مزایای آن در زمان تعلیم بیشترین مقدار را دارند، مصرف کمتر VRAM و کارایی بهتر Flash Attention باعث می‌شود برای استنتاج نیز ارزشمند باشد و ارائه‌ی سریع‌تر و مقیاس‌پذیرتر مدل‌های زبانی بزرگ را ممکن کند.

</Tip>

**vLLM** با استفاده از PagedAttention رویکرد متفاوتی دارد. همان‌طور که رایانه حافظه‌ی خود را به صفحه‌ها تقسیم می‌کند، vLLM حافظه‌ی مدل را به بلوک‌های کوچک‌تر تقسیم می‌کند. این سیستم هوشمندانه باعث می‌شود بتواند درخواست‌هایی با اندازه‌های مختلف را انعطاف‌پذیرتر مدیریت کند و فضای حافظه را هدر ندهد. این چارچوب در اشتراک‌گذاری حافظه بین درخواست‌های مختلف بسیار خوب عمل می‌کند و تکه‌تکه‌شدن حافظه را کاهش می‌دهد؛ بنابراین کل سیستم کارآمدتر می‌شود.

<Tip title="PagedAttention چگونه کار می‌کند؟">

PagedAttention تکنیکی است که به یکی دیگر از گلوگاه‌های مهم استنتاج مدل‌های زبانی بزرگ، یعنی مدیریت حافظه‌ی کش KV، می‌پردازد. همان‌طور که در [بخش ۱.۸](/course/chapter1/8) گفتیم، مدل هنگام تولید متن، کلیدها و مقادیر توجه (کش KV) را برای هر توکِن تولیدشده ذخیره می‌کند تا محاسبات تکراری کاهش یابند. کش KV، به‌خصوص برای رشته‌های طولانی یا چندین درخواست هم‌زمان، می‌تواند بسیار بزرگ شود.

نوآوری اصلی vLLM در نحوه‌ی مدیریت این کش است:

1. **صفحه‌بندی حافظه**: به‌جای اینکه کش KV به‌صورت یک بلوک بزرگ در نظر گرفته شود، به «صفحه‌های» با اندازه‌ی ثابت تقسیم می‌شود (مشابه حافظه‌ی مجازی در سیستم‌عامل‌ها).
2. **ذخیره‌سازی غیرپیوسته**: لازم نیست صفحه‌ها به‌صورت پیوسته در حافظه‌ی GPU ذخیره شوند؛ بنابراین تخصیص حافظه انعطاف‌پذیرتر است.
3. **مدیریت جدول صفحه**: یک جدول صفحه مشخص می‌کند کدام صفحه‌ها به کدام رشته تعلق دارند و جست‌وجو و دسترسی کارآمد را ممکن می‌کند.
4. **اشتراک‌گذاری حافظه**: در عملیاتی مانند نمونه‌برداری موازی، صفحه‌هایی که کش KV مربوط به پیام ورودی را ذخیره می‌کنند می‌توانند بین چندین رشته به اشتراک گذاشته شوند.

رویکرد PagedAttention در مقایسه با روش‌های سنتی می‌تواند توان عملیاتی را تا ۲۴ برابر افزایش دهد و برای استقرار مدل‌های زبانی بزرگ در محیط تولید تحولی اساسی ایجاد کند. اگر می‌خواهید درباره‌ی نحوه‌ی کار PagedAttention عمیق‌تر مطالعه کنید، می‌توانید [راهنمای مستندات vLLM](https://docs.vllm.ai/en/latest/design/kernel/paged_attention.html) را بخوانید.

</Tip>

**llama.cpp** یک پیاده‌سازی بسیار بهینه از C/C++ است که در ابتدا برای اجرای مدل‌های LLaMA روی سخت‌افزارهای مصرفی طراحی شد. این پروژه بر کارایی CPU تمرکز دارد، با امکان شتاب‌دهی GPU، و برای محیط‌های دارای منابع محدود ایدئال است. llama.cpp از تکنیک‌های کوانتیزه‌سازی برای کاهش اندازه و نیازمندی‌های حافظه‌ی مدل استفاده می‌کند و در عین حفظ عملکرد خوب، کرنل‌های بهینه‌شده‌ای برای معماری‌های مختلف CPU ارائه می‌دهد و از مدیریت پایه‌ی کش KV برای تولید کارآمد توکِن پشتیبانی می‌کند.

<Tip title="کوانتیزه‌سازی llama.cpp چگونه کار می‌کند؟">

کوانتیزه‌سازی در llama.cpp دقت وزن‌های مدل را از ممیز شناور ۳۲بیتی یا ۱۶بیتی به قالب‌های کم‌دقت‌تری مانند اعداد صحیح ۸بیتی (INT8)، ۴بیتی یا حتی پایین‌تر کاهش می‌دهد. این کار مصرف حافظه را به‌طور چشمگیری کاهش می‌دهد و سرعت استنتاج را با افت کیفیتی اندک افزایش می‌دهد.

ویژگی‌های کلیدی کوانتیزه‌سازی در llama.cpp عبارت‌اند از:
1. **سطوح متعدد کوانتیزه‌سازی**: از کوانتیزه‌سازی ۸بیتی، ۴بیتی، ۳بیتی و حتی ۲بیتی پشتیبانی می‌کند
2. **قالب GGML/GGUF**: از قالب‌های سفارشی تِنسور استفاده می‌کند که برای استنتاج کوانتیزه‌شده بهینه شده‌اند
3. **دقت ترکیبی**: می‌تواند سطوح مختلف کوانتیزه‌سازی را روی بخش‌های مختلف مدل اعمال کند
4. **بهینه‌سازی‌های ویژه‌ی سخت‌افزار**: مسیرهای کد بهینه‌شده برای معماری‌های مختلف CPU (AVX2، AVX-512، NEON) دارد

این رویکرد اجرای مدل‌های دارای میلیاردها پارامتر را روی سخت‌افزارهای مصرفی با حافظه‌ی محدود ممکن می‌کند و برای استقرارهای محلی و دستگاه‌های لبه‌ای عالی است.

</Tip>

### استقرار و یکپارچه‌سازی

حالا به سراغ تفاوت‌های استقرار و یکپارچه‌سازی میان این چارچوب‌ها برویم.

**TGI** در استقرارهای سازمانی و در مقیاس بزرگ، با قابلیت‌های آماده‌ی تولید خود، عملکردی عالی دارد. این چارچوب پشتیبانی داخلی از Kubernetes دارد و هر چیزی را که برای اجرای محیط تولید نیاز دارید، از جمله پایش با Prometheus و Grafana، مقیاس‌بندی خودکار و قابلیت‌های جامع ایمنی، در اختیار می‌گذارد. سیستم همچنین شامل ثبت گزارش در سطح سازمانی و اقدامات حفاظتی مختلفی مانند فیلتر کردن محتوا و محدودسازی نرخ است تا استقرار شما امن و پایدار بماند.

**vLLM** رویکردی انعطاف‌پذیرتر و سازگارتر با توسعه‌دهندگان برای استقرار دارد. هسته‌ی آن با پایتون ساخته شده و می‌تواند به‌سادگی جایگزین API شرکت OpenAI در برنامه‌های موجود شما شود. این چارچوب بر ارائه‌ی عملکرد خام تمرکز دارد و می‌توان آن را مطابق نیازهای خاص شما سفارشی کرد. vLLM برای مدیریت کلاسترها به‌خوبی با Ray کار می‌کند و وقتی به عملکرد بالا و سازگاری نیاز دارید، انتخابی عالی است.

**llama.cpp** سادگی و قابلیت حمل را در اولویت قرار می‌دهد. پیاده‌سازی سرور آن سبک است و می‌تواند روی طیف گسترده‌ای از سخت‌افزارها، از سرورهای قدرتمند تا لپ‌تاپ‌های مصرفی و حتی برخی دستگاه‌های همراه رده‌بالا اجرا شود. با وابستگی‌های حداقلی و هسته‌ی ساده‌ی C/C++، استقرار آن در محیط‌هایی که نصب چارچوب‌های پایتونی دشوار است آسان است. سرور، ضمن حفظ ردپای بسیار کوچک‌تر منابع نسبت به راهکارهای دیگر، یک API سازگار با OpenAI ارائه می‌دهد.

نصب و استفاده از TGI آسان است و یکپارچه‌سازی عمیقی با اکوسیستم هاگینگ‌فِیس دارد.

ابتدا سرور TGI را با Docker اجرا کنید:

<div dir="ltr">

```sh
docker run --gpus all \
    --shm-size 1g \
    -p 8080:80 \
    -v ~/.cache/huggingface:/data \
    ghcr.io/huggingface/text-generation-inference:latest \
    --model-id HuggingFaceTB/SmolLM2-360M-Instruct
```

</div>

سپس با استفاده از InferenceClient هاگینگ‌فِیس با آن تعامل کنید:

<div dir="ltr">

```python
from huggingface_hub import InferenceClient

# Initialize client pointing to TGI endpoint
client = InferenceClient(
    model="http://localhost:8080",  # URL to the TGI server
)

# Text generation
response = client.text_generation(
    "Tell me a story",
    max_new_tokens=100,
    temperature=0.7,
    top_p=0.95,
    details=True,
    stop_sequences=[],
)
print(response.generated_text)

# For chat format
response = client.chat_completion(
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Tell me a story"},
    ],
    max_tokens=100,
    temperature=0.7,
    top_p=0.95,
)
print(response.choices[0].message.content)
```

</div>

یا می‌توانید از کلاینت OpenAI استفاده کنید:

<div dir="ltr">

```python
from openai import OpenAI

# Initialize client pointing to TGI endpoint
client = OpenAI(
    base_url="http://localhost:8080/v1",  # Make sure to include /v1
    api_key="not-needed",  # TGI doesn't require an API key by default
)

# Chat completion
response = client.chat.completions.create(
    model="HuggingFaceTB/SmolLM2-360M-Instruct",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Tell me a story"},
    ],
    max_tokens=100,
    temperature=0.7,
    top_p=0.95,
)
print(response.choices[0].message.content)
```

```sh
git clone https://github.com/ggerganov/llama.cpp

curl -L -O https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B-Instruct-GGUF/resolve/main/smollm2-1.7b-instruct.Q4_K_M.gguf
```

سپس سرور را اجرا کنید (با سازگاری با API شرکت OpenAI):

<div dir="ltr">

```sh
# Start the server
./server \
    -m smollm2-1.7b-instruct.Q4_K_M.gguf \
    --host 0.0.0.0 \
    --port 8080 \
    -c 4096 \
    --n-gpu-layers 0  # Set to a higher number to use GPU
```

```python
)
```

### تولید پایه‌ی متن

بیایید نمونه‌هایی از تولید متن با این چارچوب‌ها را بررسی کنیم:

<hfoptions id="inference-frameworks" >

<hfoption value="tgi" label="TGI">

ابتدا TGI را با پارامترهای پیشرفته مستقر کنید:

<div dir="ltr">

```sh
docker run --gpus all \
    --shm-size 1g \
    -p 8080:80 \
    -v ~/.cache/huggingface:/data \
    ghcr.io/huggingface/text-generation-inference:latest \
    --model-id HuggingFaceTB/SmolLM2-360M-Instruct \
    --max-total-tokens 4096 \
    --max-input-length 3072 \
    --max-batch-total-tokens 8192 \
    --waiting-served-ratio 1.2
```

برای تولید انعطاف‌پذیر متن از InferenceClient استفاده کنید:

## کنترل پیشرفته‌ی تولید

### انتخاب توکِن و نمونه‌برداری

فرایند تولید متن شامل انتخاب توکِن بعدی در هر مرحله است. این فرایند انتخاب را می‌توان با پارامترهای مختلف کنترل کرد:

1. **لوجیت‌های خام**: احتمال‌های اولیه‌ی خروجی برای هر توکِن
2. **دما**: میزان تصادفی بودن انتخاب را کنترل می‌کند (مقدار بیشتر = خلاقیت بیشتر)
3. **نمونه‌برداری Top-p (هسته‌ای)**: توکِن‌های برتر تشکیل‌دهنده‌ی X٪ از جرم احتمال را فیلتر می‌کند
4. **فیلتر Top-k**: انتخاب را به k توکِن محتمل‌تر محدود می‌کند

در اینجا نحوه‌ی پیکربندی این پارامترها را می‌بینید:
