## آماده‌سازی یک پیکره چندزبانه[[preparing-a-multilingual-corpus]]

ما از [Multilingual Amazon Reviews Corpus](https://huggingface.co/datasets/amazon_reviews_multi) برای ایجاد خلاصه‌ساز دوزبانه خود استفاده خواهیم کرد. این مجموعه شامل نقد و بررسی محصولات آمازون به شش زبان است و معمولاً برای ارزیابی طبقه‌بندی‌کننده‌های چندزبانه استفاده می‌شود. با این حال، از آنجایی که هر نقد با یک عنوان کوتاه همراه است، می‌توانیم از عناوین به عنوان خلاصه‌های هدف برای یادگیری مدل خود استفاده کنیم! برای شروع، بیایید زیرمجموعه‌های انگلیسی و اسپانیایی را از هاگینگ‌فِیس هاب دانلود کنیم:

محبوب‌ترین محصولات در دیتاسِت انگلیسی مربوط به لوازم خانه، پوشاک و تجهیزات بی‌سیم هستند. برای ماندن در فضای آمازون، روی خلاصه‌سازی مرور کتاب‌ها تمرکز می‌کنیم؛ بالاخره شرکت با همین کار آغاز شد! دو دسته‌ی مناسب، `book` و `digital_ebook_purchase`، را می‌بینیم؛ پس دیتاسِت‌های هر دو زبان را فقط برای همین محصولات فیلتر می‌کنیم. همان‌طور که در [فصل ۵](/course/chapter5) دیدیم، متد `Dataset.filter()` امکان برش کارآمد دیتاسِت را می‌دهد و می‌توانیم تابع ساده‌ای برای این کار تعریف کنیم:

```python
def filter_books(example):
    return (
        example["product_category"] == "book"
        or example["product_category"] == "digital_ebook_purchase"
    )
```

حالا وقتی این تابع را روی `english_dataset` و `spanish_dataset` اعمال کنیم، نتیجه فقط شامل ردیف‌هایی خواهد بود که شامل دسته‌های کتاب هستند. قبل از اعمال فیلتر، بیایید قالب `english_dataset` را از `"pandas"` به `"arrow"` تغییر دهیم:

```python
english_dataset.reset_format()
```

سپس می‌توانیم تابع فیلتر را اعمال کنیم و به عنوان یک بررسی سلامت، نمونه‌ای از نقدها را بررسی کنیم تا ببینیم آیا واقعاً درباره کتاب‌ها هستند یا خیر:

```python
spanish_books = spanish_dataset.filter(filter_books)
english_books = english_dataset.filter(filter_books)
```

خب، می‌بینیم که نقدها صرفاً مربوط به کتاب‌ها نیستند و ممکن است به چیزهایی مانند تقویم‌ها و برنامه‌های الکترونیکی مانند OneNote اشاره داشته باشند. با این وجود، به نظر می‌رسد این دامنه برای آموزش یک مدل خلاصه‌سازی مناسب باشد. قبل از اینکه به مدل‌های مختلف مناسب برای این کار نگاه کنیم، یک مرحله آماده‌سازی داده‌ها داریم: ترکیب نقدهای انگلیسی و اسپانیایی به عنوان یک شیء واحد `DatasetDict`. 🤗 دیتاسِت‌ها یک تابع مفید `concatenate_datasets()` ارائه می‌دهد که (همانطور که از نامش پیداست) دو شیء `Dataset` را روی هم قرار می‌دهد. بنابراین، برای ایجاد دیتاسِت دوزبانه خود، روی هر تقسیم‌بندی حلقه می‌زنیم، دیتاسِت‌های مربوط به آن تقسیم‌بندی را به هم متصل می‌کنیم و نتیجه را تغییر می‌دهیم تا مطمئن شویم مدل ما به یک زبان واحد بیش‌برازش (overfit) نمی‌شود:

```python
from datasets import concatenate_datasets, DatasetDict

books_dataset = DatasetDict()

for split in english_books.keys():
    books_dataset[split] = concatenate_datasets(
        [english_books[split], spanish_books[split]]
    )
    books_dataset[split] = books_dataset[split].shuffle(seed=42)

# Peek at a few examples
show_samples(books_dataset)
```

## مدل‌های خلاصه‌سازی متن[[models-for-text-summarization]]

اگر در مورد آن فکر کنید، خلاصه‌سازی متن نوعی کار مشابه ترجمه ماشینی است: ما مجموعه‌ای از متن مانند یک نقد و بررسی داریم که می‌خواهیم آن را به نسخه‌ای کوتاه‌تر که ویژگی‌های برجسته ورودی را در بر می‌گیرد، "ترجمه" کنیم. بر این اساس، اکثر مدل‌های ترنسفورمر برای خلاصه‌سازی، معماری رمزگذار-رمزگشا را که برای اولین بار در [فصل 1](/course/chapter1) با آن مواجه شدیم، اتخاذ می‌کنند، اگرچه استثنائاتی مانند ... نیز وجود دارد. خانواده مدل‌های GPT که می‌توانند برای خلاصه‌سازی در تنظیمات چند مرحله‌ای نیز استفاده شوند. جدول زیر برخی از مدل‌های از پیش تعلیم‌دیده محبوب را که می‌توانند برای خلاصه‌سازی کوک کردن شوند، فهرست می‌کند.

| [BART](https://huggingface.co/facebook/bart-base) | یک معماری ترنسفورمر جدید با پشته رمزگذار و رمزگشا که برای بازسازی ورودی خراب آموزش دیده است و طرح‌های پیش‌تعلیم BERT و GPT-2 را ترکیب می‌کند. | ❌ |
| [mBART-50](https://huggingface.co/facebook/mbart-large-50) | یک نسخه چند زبانه از BART، از پیش آموزش دیده بر روی 50 زبان. | ✅ |

همانطور که از این جدول مشاهده می‌کنید، اکثر مدل‌های ترنسفورمر برای خلاصه‌سازی (و در واقع اکثر وظایف NLP) تک‌زبانه هستند. اگر وظیفه شما به زبانی با «منابع بالا» مانند انگلیسی یا آلمانی باشد، این عالی است، اما برای هزاران زبان دیگر که در سراسر جهان استفاده می‌شوند، این‌طور نیست. خوشبختانه، دسته‌ای از مدل‌های ترنسفورمر چندزبانه، مانند mT5 و mBART، وجود دارند که به کمک می‌آیند. این مدل‌ها از قبل آموزش دیده‌اند با استفاده از مدل‌سازی زبان، اما با یک تغییر: به جای آموزش روی مجموعه‌ای از یک زبان، آنها به طور مشترک روی متون بیش از ۵۰ زبان به طور همزمان آموزش می‌بینند!

ما بر روی mT5 تمرکز خواهیم کرد، یک معماری جالب مبتنی بر T5 که در یک چارچوب متن به متن از پیش تعلیم داده شده است. در T5، هر وظیفه NLP بر اساس یک پیشوند اعلان مانند `summarize:` فرموله می‌شود که مدل را برای تطبیق متن تولید شده با اعلان شرطی می‌کند. همانطور که در شکل زیر نشان داده شده است، این امر T5 را بسیار متنوع می‌کند، زیرا می‌توانید بسیاری از وظایف را با یک مدل واحد حل کنید!

## پیش‌پردازش داده‌ها[[preprocessing-the-data]]

<Youtube id="1m7BerpSq8A"/>

کار بعدی توکِن‌سازی و کدگذاری مرورها و عنوان‌های آن‌هاست. طبق معمول، ابتدا توکِن‌ساز مربوط به نقطه‌ی بررسی مدل از پیش تعلیم‌دیده را بارگذاری می‌کنیم. از `mt5-small` استفاده می‌کنیم تا بتوانیم مدل را در زمانی معقول کوک کنیم:

```python
from transformers import AutoTokenizer

model_checkpoint = "google/mt5-small"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
```

> نکته
> 💡 در مراحل اولیه پروژه‌های NLP خود، یک روش خوب این است که یک کلاس از مدل‌های "کوچک" را روی یک نمونه کوچک از داده‌ها آموزش دهید. این به شما امکان می‌دهد تا سریع‌تر اشکال‌زدایی کنید و به سمت یک گردش کار سرتاسری تکرار کنید. هنگامی که از نتایج مطمئن شدید، همیشه می‌توانید مدل را با تغییر ساده نقطه بررسی مدل، مقیاس‌بندی کنید!

بیایید توکن‌ساز mT5 را روی یک مثال کوچک آزمایش کنیم:

```python
inputs = tokenizer("I loved reading the Hunger Games!")
inputs
```

```python out
{'input_ids': [336, 259, 28387, 11807, 287, 62893, 295, 12507, 1], 'attention_mask': [1, 1, 1, 1, 1, 1, 1, 1, 1]}
```

در اینجا می‌توانیم `input_ids` و `attention_mask` آشنا را که در اولین آزمایش‌های کوک کردن خود در [فصل 3](/course/chapter3) با آنها مواجه شدیم، ببینیم. بیایید این شناسه‌های ورودی را با تابع `convert_ids_to_tokens()` توکن‌ساز رمزگشایی کنیم تا ببینیم با چه نوع توکن‌سازی سروکار داریم:

```python
tokenizer.convert_ids_to_tokens(inputs.input_ids)
```

```python out
['▁I', '▁', 'loved', '▁reading', '▁the', '▁Hung', 'er', '▁Games', '</s>']
```

کاراکتر یونیکد ویژه `▁` و توکن پایان توالی `</s>` نشان می‌دهند که ما با توکن‌ساز SentencePiece سروکار داریم که مبتنی بر الگوریتم قطعه‌بندی Unigram است که در [فصل 6](/course/chapter6) مورد بحث قرار گرفته است. Unigram به ویژه برای پیکره‌های چندزبانه مفید است زیرا به SentencePiece اجازه می‌دهد تا نسبت به لهجه‌ها، علائم نگارشی و این واقعیت که بسیاری از زبان‌ها، مانند ژاپنی، کاراکترهای فاصله ندارند، بی‌تفاوت باشد.

برای توکنیزه کردن دیتاسِت‌هایمان، باید با یک نکتهٔ ظریف مرتبط با خلاصه‌سازی سر و کار داشته باشیم: از آنجا که برچسب‌های ما نیز متن هستند، ممکن است از حداکثر اندازهٔ متن مدل فراتر روند. این بدان معناست که باید هم بر روی نظرات و هم بر روی عناوین آن‌ها کوتاه‌سازی اعمال کنیم تا مطمئن شویم ورودی‌های بیش از حد طولانی به مدل خود ارسال نمی‌کنیم. توکنایزرها در ترنسفورمرهای 🤗 یک آرگومان `text_target` ارائه می‌دهند که به شما امکان می‌دهد برچسب‌ها را هم‌زمان با ورودی‌ها توکنیزه کنید. در اینجا مثالی از نحوهٔ پردازش ورودی‌ها و اهداف برای mT5 آورده شده است:

```python
max_input_length = 512
max_target_length = 30


def preprocess_function(examples):
    model_inputs = tokenizer(
        examples["review_body"],
        max_length=max_input_length,
        truncation=True,
    )
    labels = tokenizer(
        examples["review_title"], max_length=max_target_length, truncation=True
    )
    model_inputs["labels"] = labels["input_ids"]
    return model_inputs
```

بیایید این کد را بررسی کنیم تا بفهمیم چه اتفاقی می‌افتد. اولین کاری که انجام داده‌ایم، تعریف مقادیری برای `max_input_length` و `max_target_length` است که حداکثر طول نقدها و عناوین ما را تعیین می‌کنند. از آنجایی که متن نقد معمولاً بسیار بزرگتر از عنوان است، این مقادیر را بر این اساس مقیاس‌بندی کرده‌ایم.

با `preprocess_function()`، توکِن‌سازی کل پیکره با تابع کاربردی `Dataset.map()` که در این دوره بسیار استفاده کرده‌ایم ساده است:

```python
tokenized_datasets = books_dataset.map(preprocess_function, batched=True)
```

اکنون که متن پیش‌پردازش شده است، بیایید نگاهی به برخی از معیارهایی که معمولاً برای خلاصه‌سازی استفاده می‌شوند، بیندازیم. همانطور که خواهیم دید، هیچ راه حل قطعی برای اندازه‌گیری کیفیت متن تولید شده توسط ماشین وجود ندارد.

> نکته
> 💡 شاید متوجه شده باشید که ما در تابع `Dataset.map()` بالا از `batched=True` استفاده کردیم. این تابع مثال‌ها را در دسته‌های ۱۰۰۰تایی (به‌صورت پیش‌فرض) کدگذاری می‌کند و به شما امکان می‌دهد از قابلیت‌های چندنخی توکنایزرهای سریع در ترنسفورمرهای 🤗 استفاده کنید. در صورت امکان، سعی کنید از `batched=True` استفاده کنید تا از پیش‌پردازش خود نهایت استفاده را ببرید!


## معیارهای خلاصه‌سازی متن[[metrics-for-text-summarization]]

<Youtube id="TMshhnrEXlg"/>

در مقایسه با اکثر وظایف دیگری که در این دوره پوشش داده‌ایم، اندازه‌گیری عملکرد وظایف تولید متن مانند خلاصه‌سازی یا ترجمه به این سادگی نیست. برای مثال، با توجه به نقدی مانند «من عاشق خواندن بازی‌های گرسنگی بودم»، چندین خلاصه معتبر وجود دارد، مانند «من عاشق بازی‌های گرسنگی بودم» یا «بازی‌های گرسنگی یک اثر عالی برای خواندن است». واضح است که اعمال نوعی تطابق دقیق بین خلاصه تولید شده و این برچسب راه حل خوبی نیست -- حتی انسان‌ها هم تحت چنین معیاری عملکرد ضعیفی خواهند داشت، زیرا همه ما سبک نوشتاری خودمان را داریم.

برای خلاصه‌سازی، یکی از معیارهای رایج [امتیاز ROUGE](https://en.wikipedia.org/wiki/ROUGE_(metric)) است. ایده‌ی اصلی مقایسه‌ی خلاصه‌ی تولیدشده با مجموعه‌ای از خلاصه‌های مرجع است که معمولاً انسان‌ها می‌نویسند. برای دقیق‌تر شدن، فرض کنید می‌خواهیم دو خلاصه‌ی زیر را مقایسه کنیم:

```python
generated_summary = "I absolutely loved reading the Hunger Games"
reference_summary = "I loved reading the Hunger Games"
```

یک راه برای مقایسه آنها می‌تواند شمارش تعداد کلمات همپوشانی باشد که در این مورد ۶ خواهد بود. با این حال، این کمی خام است، بنابراین در عوض ROUGE مبتنی بر محاسبه نمرات _precision_ و _recall_ برای همپوشانی است.

> نکته
> 🙋 اگر این اولین باری است که در مورد دقت و فراخوانی می‌شنوید، نگران نباشید -- ما با هم چند مثال واضح را بررسی خواهیم کرد تا همه چیز روشن شود. این معیارها معمولاً در وظایف طبقه‌بندی با هم مواجه می‌شوند، بنابراین اگر می‌خواهید بفهمید که دقت و فراخوانی در آن زمینه چگونه تعریف می‌شوند، توصیه می‌کنیم [راهنماهای `scikit-learn`](https://scikit-learn.org/stable/auto_examples/model_selection/plot_precision_recall.html) را بررسی کنید.

برای ROUGE، معیار فراخوانی، میزان خلاصه مرجعی را که توسط خلاصه تولید شده در بر گرفته شده است، اندازه‌گیری می‌کند. اگر فقط کلمات را مقایسه کنیم، فراخوانی را می‌توان طبق فرمول زیر محاسبه کرد:

$$ \mathrm{Recall} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, reference\, summary}} $$

برای مثال ساده‌ی بالا، این فرمول میزان یادآوری کاملی برابر با ۶/۶ = ۱ ارائه می‌دهد؛ یعنی تمام کلمات موجود در خلاصه‌ی مرجع توسط مدل تولید شده‌اند. این ممکن است عالی به نظر برسد، اما تصور کنید اگر خلاصه‌ی تولید شده‌ی ما این بود: «من واقعاً واقعاً عاشق خواندن بازی‌های گرسنگی در تمام طول شب بودم». این نیز میزان یادآوری کاملی داشت، اما مسلماً خلاصه‌ی بدتری است زیرا طولانی است. برای مقابله با این سناریوها، ما همچنین محاسبه می‌کنیم دقت، که در زمینه ROUGE میزان مرتبط بودن خلاصه تولید شده را اندازه‌گیری می‌کند:

$$ \mathrm{Precision} = \frac{\mathrm{Number\,of\,overlapping\, words}}{\mathrm{Total\, number\, of\, words\, in\, generated\, summary}} $$

اعمال این مورد بر خلاصه‌ی طولانی ما، دقتی برابر با ۶/۱۰ = ۰.۶ را ارائه می‌دهد که به طور قابل توجهی بدتر از دقت ۶/۷ = ۰.۸۶ است که توسط خلاصه‌ی کوتاه‌تر ما به دست آمده است. در عمل، معمولاً هم دقت و هم فراخوانی محاسبه می‌شوند و سپس امتیاز F1 (میانگین هارمونیک دقت و فراخوانی) گزارش می‌شود. ما می‌توانیم این کار را به راحتی در دیتاسِت‌های 🤗 با نصب اولیه‌ی بسته‌ی `rouge_score` انجام دهیم:

```py
!pip install rouge_score
```

و سپس بارگذاری متریک ROUGE به شرح زیر:

```python

```

سپس می‌توانیم از تابع `rouge_score.compute()` برای محاسبه‌ی همزمان تمام معیارها استفاده کنیم:

"جمع" در `rougeLsum` به این واقعیت اشاره دارد که این معیار بر روی کل خلاصه محاسبه می‌شود، در حالی که `rougeL` به عنوان میانگین روی تک تک جملات محاسبه می‌شود.

> [!TIP]
> ✏️ **امتحانش کنید!** مثال خودتان را از یک خلاصه تولید شده و مرجع ایجاد کنید و ببینید آیا نمرات ROUGE حاصل با محاسبه دستی بر اساس فرمول‌های دقت و فراخوانی مطابقت دارد یا خیر. برای امتیاز بیشتر، متن را به دو قسمت تقسیم کنید و دقت و فراخوانی را برای معیار `rouge2` مقایسه کنید.

ما از این نمرات ROUGE برای ردیابی عملکرد مدل خود استفاده خواهیم کرد، اما قبل از انجام این کار، بیایید کاری را انجام دهیم که هر متخصص خوب NLP باید انجام دهد: ایجاد یک خط پایه قوی و در عین حال ساده!

### ایجاد یک خط مبنای قوی[[creating-a-strong-baseline]]

یک خط پایه‌ی رایج برای خلاصه‌سازی متن، گرفتن سه جمله‌ی نخست مقاله است که معمولاً خط پایه‌ی _lead-3_ نامیده می‌شود. می‌توانیم با نقطه پایان جمله‌ها را پیدا کنیم، اما این روش برای سرواژه‌هایی مانند «U.S.» یا «U.N.» شکست می‌خورد؛ بنابراین از کتابخانه‌ی `nltk` استفاده می‌کنیم که الگوریتم بهتری برای این موارد دارد. بسته را با `pip` نصب کنید:

```python
!pip install nltk
```

در اینجا، آرگومان `predict_with_generate` طوری تنظیم شده است که نشان دهد ما باید در طول ارزیابی خلاصه‌هایی تولید کنیم تا بتوانیم نمرات ROUGE را برای هر دوره محاسبه کنیم. همانطور که در [فصل 1](/course/chapter1) بحث شد، رمزگشا با پیش‌بینی توکن‌ها به صورت یک به یک، استنتاج را انجام می‌دهد و این توسط روش `generate()` مدل پیاده‌سازی می‌شود. تنظیم `predict_with_generate=True` به `Seq2SeqTrainer` می‌گوید که از آن روش برای ارزیابی استفاده کند. همچنین ابرپارامترهای پیش‌فرضی مانند نرخ یادگیری، تعداد دوره‌ها و کاهش وزن را تنظیم کرده‌ایم و گزینه‌ی `save_total_limit` را طوری تنظیم کرده‌ایم که حداکثر ۳ نقطه‌ی بررسی را در طول تعلیم ذخیره کند؛ زیرا حتی نسخه‌ی «کوچک» mT5 حدود یک گیگابایت از فضای دیسک را مصرف می‌کند و با محدود کردن تعداد نسخه‌های ذخیره‌شده، کمی فضا آزاد می‌کنیم.

آرگومان `push_to_hub=True` به ما این امکان را می‌دهد که مدل را پس از آموزش به هاب ارسال کنیم؛ مخزن را در زیر پروفایل کاربری خود، در مکانی که توسط `output_dir` تعریف شده است، خواهید یافت. توجه داشته باشید که می‌توانید نام مخزنی را که می‌خواهید به آن ارسال کنید، با آرگومان `hub_model_id` مشخص کنید (به طور خاص، برای ارسال به یک سازمان باید از این آرگومان استفاده کنید). به عنوان مثال، وقتی مدل را به سازمان [`huggingface-course`](https://huggingface.co/huggingface-course) ارسال کردیم، ما `hub_model_id="huggingface-course/mt5-finetuned-amazon-en-es"` به `Seq2SeqTrainingArguments` اضافه شد.

کار بعدی که باید انجام دهیم این است که یک تابع `compute_metrics()` به مربی ارائه دهیم تا بتوانیم مدل خود را در طول آموزش ارزیابی کنیم. به طور خلاصه، این کار کمی پیچیده‌تر از فراخوانی ساده `rouge_score.compute()` روی پیش‌بینی‌های مدل است، زیرا قبل از محاسبه امتیازات ROUGE، باید خروجی‌ها و برچسب‌ها را به متن _رمزگشایی_ کنیم. تابع زیر دقیقاً همین کار را انجام می‌دهد و همچنین از تابع `sent_tokenize()` از `nltk` برای جدا کردن جمله‌های خلاصه با خط‌های جدید استفاده می‌کند:

```python
import numpy as np


def compute_metrics(eval_pred):
    predictions, labels = eval_pred
    # Decode generated summaries into text
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    # Replace -100 in the labels as we can't decode them
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    # Decode reference summaries into text
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    # ROUGE expects a newline after each sentence
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    # Compute ROUGE scores
    result = rouge_score.compute(
        predictions=decoded_preds, references=decoded_labels, use_stemmer=True
    )
    # Extract the median scores
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    return {k: round(v, 4) for k, v in result.items()}
```

```python
)
```

در طول تعلیم چند مقدار هزینه گرفتیم، اما می‌خواهیم معیارهای ROUGE قبلی را ببینیم. برای این کار باید خروجی‌های مدل را تولید و به رشته تبدیل کنیم و فهرست‌هایی از برچسب‌ها و پیش‌بینی‌ها برای مقایسه بسازیم؛ اگر در این بخش خطای import گرفتید، شاید به `!pip install tqdm` نیاز داشته باشید. برای افزایش چشمگیر عملکرد، کد تولید را با [XLA](https://www.tensorflow.org/xla)، کامپایلر جبر خطی شتاب‌یافته‌ی TensorFlow، کامپایل می‌کنیم. XLA نمودار محاسباتی مدل را بهینه می‌کند و سرعت و مصرف حافظه را بهتر می‌کند. طبق توضیح [وبلاگ](https://huggingface.co/blog/tf-xla-generate)، چون XLA با شکل‌های ورودی مشابه بهتر کار می‌کند، ورودی‌ها را به مضرب‌های ۱۲۸ هم‌طول می‌کنیم و جمع‌کننده‌ی padding تازه‌ای می‌سازیم و دکوراتور `@tf.function(jit_compile=True)` را روی تابع تولید می‌گذاریم.

```python
from tqdm import tqdm
import numpy as np

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=320
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
    drop_remainder=True,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=32,
    )


all_preds = []
all_labels = []
for batch, labels in tqdm(tf_generate_dataset):
    predictions = generate_with_xla(batch)
    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
    labels = labels.numpy()
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
    decoded_preds = ["\n".join(sent_tokenize(pred.strip())) for pred in decoded_preds]
    decoded_labels = ["\n".join(sent_tokenize(label.strip())) for label in decoded_labels]
    all_preds.extend(decoded_preds)
    all_labels.extend(decoded_labels)
```

زمانی که لیست‌های برچسب و رشته‌های پیش‌بینی خود را داشته باشیم، محاسبه امتیاز ROUGE آسان است:

```python
result = rouge_score.compute(
    predictions=decoded_preds, references=decoded_labels, use_stemmer=True
)
result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
{k: round(v, 4) for k, v in result.items()}
```

## کوک کردن mT5 با 🤗 شتاب‌دهی[[fine-tuning-mt5-with-accelerate]]

کوک کردن مدل با 🤗 Accelerate بسیار شبیه به مثال طبقه‌بندی متن است که در [فصل ۳](/course/chapter3) با آن مواجه شدیم. تفاوت‌های اصلی، نیاز به تولید صریح خلاصه‌های ما در طول آموزش و تعریف نحوه محاسبه امتیازات ROUGE خواهد بود (به یاد داشته باشید که `Seq2SeqTrainer` تولید را برای ما انجام داد). بیایید نگاهی به نحوه پیاده‌سازی این دو الزام در 🤗 Accelerate بیندازیم!

### آماده‌سازی همه‌چیز برای آموزش[[preparing-everything-for-training]]

اولین کاری که باید انجام دهیم این است که برای هر یک از تقسیم‌بندی‌هایمان یک `DataLoader` ایجاد کنیم. از آنجایی که بارگذارهای داده PyTorch انتظار دسته‌هایی از تانسورها را دارند، باید قالب را در دیتاسِت‌های خود روی `"torch"` تنظیم کنیم:

```python
tokenized_datasets.set_format("torch")
```

حالا که دیتاسِت‌هایی داریم که فقط از تانسورها تشکیل شده‌اند، کار بعدی که باید انجام دهیم، نمونه‌سازی مجدد `DataCollatorForSeq2Seq` است. برای این کار باید نسخه جدیدی از مدل را ارائه دهیم، بنابراین بیایید دوباره آن را از حافظه پنهان خود بارگذاری کنیم:

```python
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

سپس می‌توانیم از گردآورنده‌ی داده‌ها نمونه‌سازی کنیم و از آن برای تعریف بارگذارهای داده‌ی خود استفاده کنیم:

```python
from torch.utils.data import DataLoader

batch_size = 8
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=batch_size,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=batch_size
)
```

کار بعدی که باید انجام دهیم، تعریف بهینه‌ساز مورد نظرمان است. همانند مثال‌های دیگرمان، از `AdamW` استفاده خواهیم کرد که برای اکثر مسائل به خوبی کار می‌کند:

```python
from torch.optim import AdamW

optimizer = AdamW(model.parameters(), lr=2e-5)
```

در نهایت، مدل، بهینه‌ساز و بارگذارهای داده خود را به متد `accelerator.prepare()` می‌دهیم:

```python
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

> نکته
> 🚨 اگر روی یک TPU آموزش می‌بینید، باید تمام کد بالا را به یک تابع آموزش اختصاصی منتقل کنید. برای جزئیات بیشتر به [فصل ۳](/course/chapter3) مراجعه کنید.

حالا که اشیاء خود را آماده کرده‌ایم، سه کار دیگر باقی مانده است:

* جدول نرخ یادگیری را تعریف کنید.
* تابعی را برای پس‌پردازش خلاصه‌ها جهت ارزیابی پیاده‌سازی کنید.
* مخزنی در هاب ایجاد کنید تا بتوانیم مدل خود را در آن بارگذاری کنیم.

برای زمانبندی نرخ یادگیری، از زمانبندی خطی استاندارد بخش‌های قبلی استفاده خواهیم کرد:

```python
from transformers import get_scheduler

num_train_epochs = 10
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

برای پس‌پردازش، به تابعی نیاز داریم که خلاصه‌های تولید شده را به جملاتی تقسیم کند که با خط جدید از هم جدا شده‌اند. این فرمتی است که معیار ROUGE انتظار دارد و می‌توانیم با قطعه کد زیر به آن دست یابیم:

```python
def postprocess_text(preds, labels):
    preds = [pred.strip() for pred in preds]
    labels = [label.strip() for label in labels]

    # ROUGE expects a newline after each sentence
    preds = ["\n".join(nltk.sent_tokenize(pred)) for pred in preds]
    labels = ["\n".join(nltk.sent_tokenize(label)) for label in labels]

    return preds, labels
```

اگر به یاد داشته باشید که چگونه تابع `compute_metrics()` مربوط به `Seq2SeqTrainer` را تعریف کردیم، این باید برای شما آشنا به نظر برسد.

در نهایت، باید یک مخزن مدل در هاگینگ‌فِیس هاب ایجاد کنیم. برای این کار، می‌توانیم از کتابخانه هاب با عنوان مناسب 🤗 استفاده کنیم. فقط باید یک نام برای مخزن خود تعریف کنیم و کتابخانه یک تابع کاربردی برای ترکیب شناسه مخزن با پروفایل کاربر دارد:

### حلقه آموزشی[[training-loop]]

حلقه آموزشی برای خلاصه‌سازی کاملاً شبیه به سایر مثال‌های Accelerate 🤗 است که با آنها مواجه شده‌ایم و تقریباً به چهار مرحله اصلی تقسیم می‌شود:

۱. مدل را با تکرار روی تمام مثال‌های موجود در `train_dataloader` برای هر دوره، آموزش دهید.
۲. در پایان هر دوره خلاصه‌های مدل را تولید کنید؛ ابتدا توکن‌ها و سپس آن‌ها (و خلاصه‌های مرجع) را به متن تبدیل کنید.
۳. امتیازهای ROUGE را با همان روش‌هایی که پیش‌تر دیدیم محاسبه کنید.
۴. چک‌پوینت‌ها را ذخیره کنید و همه چیز را به هاب ارسال کنید. در اینجا ما به آرگومان `blocking=False` از شیء `Repository` تکیه می‌کنیم تا بتوانیم چک‌پوینت‌ها را در هر دوره _به صورت ناهمگام_ ارسال کنیم. این به ما امکان می‌دهد بدون نیاز به انتظار برای آپلود نسبتاً کند مربوط به یک مدل با اندازه GB، به آموزش ادامه دهیم!

این مراحل را می‌توانید در بلوک کد زیر مشاهده کنید:

```python
from tqdm.auto import tqdm
import torch
import numpy as np

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # Training
    model.train()
    for step, batch in enumerate(train_dataloader):
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # Evaluation
    model.eval()
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
            )

            generated_tokens = accelerator.pad_across_processes(
                generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
            )
            labels = batch["labels"]

            # If we did not pad to max length, we need to pad the labels too
            labels = accelerator.pad_across_processes(
                batch["labels"], dim=1, pad_index=tokenizer.pad_token_id
            )

            generated_tokens = accelerator.gather(generated_tokens).cpu().numpy()
            labels = accelerator.gather(labels).cpu().numpy()

            # Replace -100 in the labels as we can't decode them
            labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
            if isinstance(generated_tokens, tuple):
                generated_tokens = generated_tokens[0]
            decoded_preds = tokenizer.batch_decode(
                generated_tokens, skip_special_tokens=True
            )
            decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

            decoded_preds, decoded_labels = postprocess_text(
                decoded_preds, decoded_labels
            )

            rouge_score.add_batch(predictions=decoded_preds, references=decoded_labels)

    # Compute metrics
    result = rouge_score.compute()
    # Extract the median ROUGE scores
    result = {key: value.mid.fmeasure * 100 for key, value in result.items()}
    result = {k: round(v, 4) for k, v in result.items()}
    print(f"Epoch {epoch}:", result)

    # Save and upload
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```
