## گردآوری داده‌ها[[gathering-the-data]]

کد پایتون در مخزن‌هایی مانند گیت‌هاب فراوان است و می‌توانیم با خزش در مخزن‌های پایتون دیتاسِت بسازیم. نویسندگان [کتاب ترنسفورمرها](https://learning.oreilly.com/library/view/natural-language-processing/9781098136789/) با همین روش یک GPT-2 بزرگ را پیش‌تعلیم دادند. آن‌ها با dump گیت‌هاب به‌اندازه‌ی حدود ۱۸۰ گیگابایت، شامل نزدیک به ۲۰ میلیون فایل پایتون، دیتاسِتی به نام `codeparrot` ساختند و آن را در [هاب هاگینگ‌فِیس](https://huggingface.co/datasets/transformersbook/codeparrot) به اشتراک گذاشتند.

با این حال، آموزش روی کل دیتاسِت‌ها زمان‌بر و محاسباتی است و ما فقط به زیرمجموعه‌ای از دیتاسِت‌های مربوط به پشته علوم داده پایتون نیاز داریم. بنابراین، بیایید با فیلتر کردن دیتاسِت‌های `codeparrot` برای تمام فایل‌هایی که شامل هر یک از کتابخانه‌های موجود در این پشته هستند، شروع کنیم. به دلیل اندازه دیتاسِت‌ها، می‌خواهیم از دانلود آن خودداری کنیم. در عوض، از ویژگی استریمینگ برای فیلتر کردن آن درجا استفاده خواهیم کرد. برای کمک به فیلتر کردن کد برای نمونه با استفاده از کتابخانه‌هایی که قبلاً به آنها اشاره کردیم، از تابع زیر استفاده خواهیم کرد:

```py
def any_keyword_in_string(string, keywords):
    for keyword in keywords:
        if keyword in string:
            return True
    return False
```

بیایید آن را روی دو مثال آزمایش کنیم:

```py
filters = ["pandas", "sklearn", "matplotlib", "seaborn"]
example_1 = "import numpy as np"
example_2 = "import pandas as pd"

print(
    any_keyword_in_string(example_1, filters), any_keyword_in_string(example_2, filters)
)
```

می‌توانیم از این برای ایجاد تابعی استفاده کنیم که دیتاسِت‌ها را پخش کرده و عناصر مورد نظر ما را فیلتر می‌کند:

```py
from collections import defaultdict
from tqdm import tqdm
from datasets import Dataset


def filter_streaming_dataset(dataset, filters):
    filtered_dict = defaultdict(list)
    total = 0
    for sample in tqdm(iter(dataset)):
        total += 1
        if any_keyword_in_string(sample["content"], filters):
            for k, v in sample.items():
                filtered_dict[k].append(v)
    print(f"{len(filtered_dict['content'])/total:.2%} of data after filtering.")
    return Dataset.from_dict(filtered_dict)
```

سپس می‌توانیم به سادگی این تابع را روی دیتاسِت‌های استریمینگ اعمال کنیم:

## آماده‌سازی دیتاسِت[[preparing-the-dataset]]

<Youtube id="ma1TrR7gE7I"/>

گام اول توکِن‌سازی داده‌هاست تا بتوانیم از آن‌ها برای تعلیم استفاده کنیم. چون هدف ما تکمیل فراخوانی‌های کوتاه تابع است، اندازه‌ی زمینه را نسبتاً کوچک می‌گیریم؛ در نتیجه مدل سریع‌تر تعلیم می‌بیند و حافظه‌ی کم‌تری مصرف می‌کند. اگر کاربرد شما به زمینه‌ی بیشتری نیاز دارد، مثلاً برای نوشتن آزمون واحد بر اساس فایل تعریف تابع، این عدد را افزایش دهید و در نظر داشته باشید که مصرف حافظه‌ی GPU بیشتر می‌شود. فعلاً اندازه‌ی زمینه را ۱۲۸ توکِن تعیین می‌کنیم، در برابر ۱۰۲۴ یا ۲۰۴۸ توکِنی که GPT-2 و GPT-3 به‌ترتیب استفاده می‌کنند.

بیشتر اسناد حاوی بیش از ۱۲۸ توکن هستند، بنابراین کوتاه کردن ورودی‌ها به حداکثر طول، بخش بزرگی از دیتاسِت‌های ما را حذف می‌کند. در عوض، ما از گزینه `return_overflowing_tokens` برای توکنیزه کردن کل ورودی و تقسیم آن به چندین تکه استفاده خواهیم کرد، همانطور که در [فصل ۶](/course/chapter6/4) انجام دادیم. ما همچنین از گزینه `return_length` برای بازگرداندن خودکار طول هر تکه ایجاد شده استفاده خواهیم کرد. اغلب آخرین تکه کوچکتر خواهد بود. از اندازه متن بیشتر است، و ما از شر این قطعات خلاص خواهیم شد تا از مشکلات padding جلوگیری کنیم؛ ما واقعاً به آنها نیازی نداریم زیرا به هر حال داده‌های زیادی داریم.

می‌توانیم ببینیم که در مجموع ۳۴ بخش از این دو مثال به دست آمده است. با نگاهی به طول تکه‌ها، می‌توانیم ببینیم که تکه‌های انتهای هر دو سند کمتر از ۱۲۸ توکن دارند (به ترتیب ۱۱۷ و ۴۱). اینها تنها بخش کوچکی از کل تکه‌هایی هستند که داریم، بنابراین می‌توانیم با خیال راحت آنها را دور بیندازیم. با فیلد `overflow_to_sample_mapping`، می‌توانیم بازسازی کنیم که کدام تکه‌ها متعلق به کدام نمونه‌های ورودی بوده‌اند.

با این عملیات، ما از یک ویژگی مفید تابع `Dataset.map()` در دیتاسِت‌ها استفاده می‌کنیم، به این معنی که نیازی به نگاشت‌های یک به یک ندارد؛ همان‌طور که در [بخش ۳](/course/chapter7/3) دیدیم، می‌توانیم دسته‌هایی با عناصر بیشتر یا کمتر از دستهٔ ورودی ایجاد کنیم. این هنگام انجام عملیاتی مانند افزایش داده یا فیلتر کردن داده که تعداد عناصر را تغییر می‌دهد، مفید است. در مورد ما، هنگام توکِن‌سازی هر عنصر به تکه‌هایی با اندازهٔ زمینهٔ مشخص‌شده، از هر سند نمونه‌های زیادی ایجاد می‌کنیم. فقط باید ستون‌های موجود را حذف کنیم، چون اندازهٔ آن‌ها با خروجی سازگار نیست. اگر بخواهیم آن‌ها را نگه داریم، می‌توانیم به‌طور مناسب تکرارشان کنیم و آن‌ها را در فراخوانی `Dataset.map()` برگردانیم:

```py
def tokenize(element):
    outputs = tokenizer(
        element["content"],
        truncation=True,
        max_length=context_length,
        return_overflowing_tokens=True,
        return_length=True,
    )
    input_batch = []
    for length, input_ids in zip(outputs["length"], outputs["input_ids"]):
        if length == context_length:
            input_batch.append(input_ids)
    return {"input_ids": input_batch}


tokenized_datasets = raw_datasets.map(
    tokenize, batched=True, remove_columns=raw_datasets["train"].column_names
)
tokenized_datasets
```

> ✏️ **امتحانش کنید!** خلاص شدن از شر تمام تکه‌هایی که کوچکتر از اندازه متن هستند، در اینجا مسئله بزرگی نبود زیرا ما از پنجره‌های متن کوچک استفاده می‌کنیم. با افزایش اندازه متن (یا اگر مجموعه‌ای از اسناد کوتاه دارید)، کسری از تکه‌هایی که دور انداخته می‌شوند نیز افزایش می‌یابد. یک روش کارآمدتر برای آماده‌سازی داده‌ها، اتصال تمام نمونه‌های توکن‌شده در یک دسته با یک توکن `eos_token_id` در بین آنها است و سپس تکه‌بندی را روی توالی‌های به‌هم‌پیوسته انجام می‌دهیم. به‌عنوان تمرین، تابع `tokenize()` را طوری تغییر دهید که از این روش استفاده کند. توجه کنید که باید `truncation=False` را تنظیم کنید و آرگومان‌های دیگر را از `tokenizer` حذف کنید تا توالی کامل شناسه‌های `token` را به دست آورید.


## مقداردهی اولیه یک مدل جدید[[initializing-a-new-model]]

گام اول مقداردهی اولیه‌ی تازه‌ی یک مدل GPT-2 است. همان تنظیمات مدل GPT-2 کوچک را به کار می‌بریم؛ پس تنظیمات از پیش تعلیم‌دیده را بارگذاری می‌کنیم، مطمئن می‌شویم اندازه‌ی توکِن‌ساز با اندازه‌ی واژگان مدل برابر است و شناسه‌های توکِن `bos` و `eos` (آغاز و پایان توالی) را می‌فرستیم:

from transformers import AutoTokenizer, GPT2LMHeadModel, AutoConfig

فقط تنظیم آرگومان‌های تعلیم و اجرای `Trainer` باقی مانده است. از زمان‌بندی کسینوسی نرخ یادگیری با مقداری warmup و اندازه‌ی مؤثر بتچ ۲۵۶ (`per_device_train_batch_size` * `gradient_accumulation_steps`) استفاده می‌کنیم. انباشت گرادیان زمانی به کار می‌رود که یک بتچ در حافظه جا نشود و گرادیان را در چند گذر رو به جلو و پس‌رو به‌تدریج می‌سازد. هنگام ساخت حلقه‌ی تعلیم با 🤗 Accelerate این کار را می‌بینیم.

```py
from transformers import Trainer, TrainingArguments

args = TrainingArguments(
    output_dir="codeparrot-ds",
    per_device_train_batch_size=32,
    per_device_eval_batch_size=32,
    evaluation_strategy="steps",
    eval_steps=5_000,
    logging_steps=5_000,
    gradient_accumulation_steps=8,
    num_train_epochs=1,
    weight_decay=0.1,
    warmup_steps=1_000,
    lr_scheduler_type="cosine",
    learning_rate=5e-4,
    save_steps=5_000,
    fp16=True,
    push_to_hub=True,
)

trainer = Trainer(
    model=model,
    tokenizer=tokenizer,
    args=args,
    data_collator=data_collator,
    train_dataset=tokenized_datasets["train"],
    eval_dataset=tokenized_datasets["valid"],
)
```

حالا می‌توانیم `Trainer` را اجرا کنیم و منتظر بمانیم تا آموزش تمام شود. بسته به اینکه آن را روی کل مجموعه آموزش یا زیرمجموعه‌ای از آن اجرا کنید، این کار به ترتیب ۲۰ یا ۲ ساعت طول خواهد کشید، پس چند قهوه و یک کتاب خوب برای خواندن بردارید!

```py
trainer.train()
```

پس از اتمام آموزش، می‌توانیم مدل و توکن‌ساز را به هاب ارسال کنیم:

```py
trainer.push_to_hub()
```

حالا زمان آزمون واقعی است: ببینیم مدل تعلیم‌دیده چقدر خوب کار می‌کند! در گزارش‌ها می‌بینیم هزینه پیوسته کم شده است؛ برای آزمایش مدل، عملکرد آن را روی چند پرامپت بررسی می‌کنیم. مدل را در یک `pipeline` تولید متن قرار می‌دهیم و اگر GPU موجود باشد برای تولید سریع روی آن می‌گذاریم:

import torch

## آموزش با 🤗 Accelerate[[training-with-accelerate]]

عالی است، درست کار می‌کند! حالا تابع هزینه‌ی سفارشی‌ای می‌نویسیم که توالی ورودی، لوجیت‌ها و توکِن‌های کلیدی انتخاب‌شده را می‌گیرد. ابتدا باید لوجیت‌ها و ورودی‌ها را هم‌تراز کنیم: توالی ورودی که یک خانه به راست منتقل شده برچسب‌ها را می‌سازد، چون توکِن بعدی برچسب توکِن فعلی است. برچسب‌ها را از توکِن دوم ورودی آغاز می‌کنیم، چون مدل برای نخستین توکِن پیش‌بینی نمی‌کند. سپس آخرین لوجیت را حذف می‌کنیم، چون برای توکِنی که پس از پایان توالی ورودی قرار دارد برچسبی نداریم. با این کار هزینه‌ی هر نمونه و تعداد تکرار کلمات کلیدی در هر نمونه را به دست می‌آوریم و در پایان میانگین وزنی همه‌ی نمونه‌ها را محاسبه می‌کنیم؛ برای نمونه‌هایی که کلیدواژه ندارند وزن ۱ در نظر می‌گیریم:

```py
from torch.nn import CrossEntropyLoss
import torch


def keytoken_weighted_loss(inputs, logits, keytoken_ids, alpha=1.0):
    # Shift so that tokens < n predict n
    shift_labels = inputs[..., 1:].contiguous()
    shift_logits = logits[..., :-1, :].contiguous()
    # Calculate per-token loss
    loss_fct = CrossEntropyLoss(reduce=False)
    loss = loss_fct(shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1))
    # Resize and average loss per sample
    loss_per_sample = loss.view(shift_logits.size(0), shift_logits.size(1)).mean(axis=1)
    # Calculate and scale weighting
    weights = torch.stack([(inputs == kt).float() for kt in keytoken_ids]).sum(
        axis=[0, 2]
    )
    weights = alpha * (1.0 + weights)
    # Calculate weighted average
    weighted_loss = (loss_per_sample * weights).mean()
    return weighted_loss
```

قبل از اینکه بتوانیم آموزش با این تابع زیان جدید و فوق‌العاده را شروع کنیم، باید چند نکته را آماده کنیم:

- ما به dataloader ها نیاز داریم تا داده‌ها را به صورت دسته‌ای بارگذاری کنند.
- ما باید پارامترهای کاهش وزن را تنظیم کنیم.
- هر از گاهی می‌خواهیم ارزیابی کنیم، بنابراین منطقی است که کد ارزیابی را در یک تابع قرار دهیم.

با دیتالودرها شروع کنیم. فقط باید قالب دیتاسِت را روی `"torch"` بگذاریم و سپس آن را با اندازه‌ی بتچ مناسب به `DataLoader` پایتورچ بدهیم:

```py
from torch.utils.data.dataloader import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(tokenized_datasets["train"], batch_size=32, shuffle=True)

```

در مرحله بعد، پارامترها را گروه‌بندی می‌کنیم تا بهینه‌ساز بداند کدام یک از آنها کاهش وزن اضافی دریافت خواهند کرد. معمولاً همه عبارات وزنی بایاس و LayerNorm از این امر مستثنی هستند؛ در اینجا نحوه انجام این کار آمده است:

```py
weight_decay = 0.1


def get_grouped_params(model, no_decay=["bias", "LayerNorm.weight"]):
    params_with_wd, params_without_wd = [], []
    for n, p in model.named_parameters():
        if any(nd in n for nd in no_decay):
            params_without_wd.append(p)
        else:
            params_with_wd.append(p)
    return [
        {"params": params_with_wd, "weight_decay": weight_decay},
        {"params": params_without_wd, "weight_decay": 0.0},
    ]
```

چون می‌خواهیم هنگام تعلیم مدل را مرتب روی مجموعه‌ی اعتبارسنجی ارزیابی کنیم، تابعی برای آن می‌نویسیم. این تابع فقط دیتالودر ارزیابی را پیمایش و همه‌ی هزینه‌ها را میان فرایندها جمع می‌کند:

```py
def evaluate():
    model.eval()
    losses = []
    for step, batch in enumerate(eval_dataloader):
        with torch.no_grad():
            outputs = model(batch["input_ids"], labels=batch["input_ids"])

        losses.append(accelerator.gather(outputs.loss))
    loss = torch.mean(torch.cat(losses))
    try:
        perplexity = torch.exp(loss)
    except OverflowError:
        perplexity = float("inf")
    return loss.item(), perplexity.item()
```

model.train()

for epoch in range(num_train_epochs):

    ):
        logits = model(batch["input_ids"]).logits
        loss = keytoken_weighted_loss(batch["input_ids"], logits, keytoken_ids)
        if step % 100 == 0:
            accelerator.print(
                {
                    "samples": step * samples_per_step,
                    "steps": completed_steps,

        loss = loss / gradient_accumulation_steps
        accelerator.backward(loss)
        if step % gradient_accumulation_steps == 0:

            optimizer.step()
            lr_scheduler.step()
            optimizer.zero_grad()
            completed_steps += 1
        if (step % (eval_steps * gradient_accumulation_steps)) == 0:

            accelerator.print({"loss/eval": eval_loss, "perplexity": perplexity})
            model.train()
            accelerator.wait_for_everyone()
            unwrapped_model = accelerator.unwrap_model(model)
            unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)

                )
