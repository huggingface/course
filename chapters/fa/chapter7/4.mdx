## آماده‌سازی داده‌ها[[preparing-the-data]]

برای کوک کردن یا آموزش یک مدل ترجمه از ابتدا، به یک دیتاسِت مناسب برای این کار نیاز داریم. همانطور که قبلاً ذکر شد، ما در این بخش از دیتاسِت [KDE4](https://huggingface.co/datasets/kde4) استفاده خواهیم کرد، اما شما می‌توانید کد را به راحتی با استفاده از داده‌های خود تطبیق دهید، البته تا زمانی که جفت جملاتی به دو زبانی که می‌خواهید از و به آنها ترجمه کنید، داشته باشید. اگر به یادآوری نحوه بارگذاری کد خود نیاز دارید، به [فصل 5](/course/chapter5) مراجعه کنید. داده‌های سفارشی در یک `Dataset`.

### دیتاسِت KDE4[[the-kde4-dataset]]

طبق معمول، دیتاسِت خود را با استفاده از تابع `load_dataset()` دانلود می‌کنیم:

```py
from datasets import load_dataset

raw_datasets = load_dataset("kde4", lang1="en", lang2="fr")
```

اگر می‌خواهید با یک جفت زبان متفاوت کار کنید، می‌توانید آنها را با کدهایشان مشخص کنید. در مجموع ۹۲ زبان برای این دیتاسِت موجود است؛ می‌توانید با باز کردن برچسب‌های زبان در [کارت دیتاسِت](https://huggingface.co/datasets/kde4) آن، همه آنها را مشاهده کنید.

<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter7/language_tags.png" alt="Language available for the KDE4 dataset." width="100%">

بیایید نگاهی به دیتاسِت‌ها بیندازیم:

```py
raw_datasets
```

```python out
DatasetDict({
    train: Dataset({
        features: ['id', 'translation'],
        num_rows: 210173
    })
})
```

ما ۲۱۰٬۱۷۳ جفت جمله داریم، اما همه در یک بخش قرار دارند؛ بنابراین باید مجموعه‌ی اعتبارسنجی خودمان را بسازیم. همان‌طور که در [فصل ۵](/course/chapter5) دیدیم، یک `Dataset` متد `train_test_split()` دارد که به ما کمک می‌کند. برای تکرارپذیری یک seed هم می‌دهیم:

```py
split_datasets = raw_datasets["train"].train_test_split(train_size=0.9, seed=20)
split_datasets
```

```python out
DatasetDict({

```

می‌توانیم کلید `"test"` را به `"validation"` به این صورت تغییر نام دهیم:

```py
split_datasets["validation"] = split_datasets.pop("test")
```

حالا بیایید نگاهی به یکی از عناصر دیتاسِت‌ها بیندازیم:

```py
split_datasets["train"][1]["translation"]
```

```python out
{'en': 'Default to expanded threads',
 'fr': 'Par défaut, développer les fils de discussion'}
```

ما یک فرهنگ لغت با دو جمله در دو زبانی که درخواست کردیم دریافت می‌کنیم. یکی از ویژگی‌های این دیتاسِت پر از اصطلاحات فنی علوم کامپیوتر این است که همه آنها به طور کامل به زبان فرانسوی ترجمه شده‌اند. با این حال، مهندسان فرانسوی هنگام صحبت کردن، بیشتر کلمات خاص علوم کامپیوتر را به انگلیسی باقی می‌گذارند. برای مثال، در اینجا، کلمه "threads" ممکن است در یک جمله فرانسوی، به خصوص در یک مکالمه فنی، ظاهر شود. اما در این دیتاسِت‌ای که به عبارت صحیح‌تر «fils de discussion» ترجمه شده است. مدل از پیش تعلیم‌دیده‌ای که ما استفاده می‌کنیم، که بر روی مجموعه‌ای بزرگتر از جملات فرانسوی و انگلیسی تعلیم‌دیده است، گزینه آسان‌ترِ باقی گذاشتن کلمه به همان شکل فعلی را انتخاب می‌کند:

```py
from transformers import pipeline

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
translator = pipeline("translation", model=model_checkpoint)
translator("Default to expanded threads")
```

```python out
[{'translation_text': 'Par défaut pour les threads élargis'}]
```

نمونه دیگری از این رفتار را می‌توان با کلمه "plugin" مشاهده کرد که رسماً یک کلمه فرانسوی نیست اما اکثر گویشوران بومی آن را می‌فهمند و زحمت ترجمه آن را به خود نمی‌دهند.
در دیتاسِت KDE4 این کلمه در زبان فرانسوی به صورت رسمی‌تر «module d'extension» ترجمه شده است:

```py
split_datasets["train"][172]["translation"]
```

```python out
{'en': 'Unable to import %1 using the OFX importer plugin. This file is not the correct format.',
 'fr': "Impossible d'importer %1 en utilisant le module d'extension d'importation OFX. Ce fichier n'a pas un format correct."}
```

با این حال، مدل از پیش تعلیم‌دیده‌ی ما به کلمه‌ی انگلیسی فشرده و آشنا پایبند است:

```py
translator(
    "Unable to import %1 using the OFX importer plugin. This file is not the correct format."
)
```

```python out
[{'translation_text': "Impossible d'importer %1 en utilisant le plugin d'importateur OFX. Ce fichier n'est pas le bon format."}]
```

### پردازش داده‌ها[[processing-the-data]]

<Youtube id="XAR8jnZZuUs"/>

شما باید تا الان با مراحل کار آشنا شده باشید: همه متن‌ها باید به مجموعه‌ای از شناسه‌های توکن تبدیل شوند تا مدل بتواند آنها را درک کند. برای این کار، باید ورودی‌ها و اهداف را توکن‌سازی کنیم. اولین کار ما ایجاد شیء `tokenizer` است. همانطور که قبلاً اشاره شد، ما از یک مدل از پیش تعلیم‌دیده انگلیسی به فرانسوی استفاده خواهیم کرد. اگر این کد را با دو زبان دیگر امتحان می‌کنید، حتماً چک‌پوینت مدل را تطبیق دهید. سازمان [Helsinki-NLP](https://huggingface.co/Helsinki-NLP) بیش از هزار مدل را به زبان‌های مختلف ارائه می‌دهد.

```python
from transformers import AutoTokenizer

model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")
```

همچنین می‌توانید `model_checkpoint` را با هر مدل دیگری که از [هاب](https://huggingface.co/models) ترجیح می‌دهید، یا یک پوشه محلی که در آن یک مدل از پیش آموزش دیده و یک توکنایزر ذخیره کرده‌اید، جایگزین کنید.

> نکته
> 💡 اگر از یک توکن‌ساز چندزبانه مانند mBART، mBART-50 یا M2M100 استفاده می‌کنید، باید کدهای زبان ورودی‌ها و اهداف خود را در توکن‌ساز با تنظیم `tokenizer.src_lang` و `tokenizer.tgt_lang` روی مقادیر صحیح تنظیم کنید.

آماده‌سازی داده‌های ما بسیار ساده است. فقط یک نکته وجود دارد که باید به خاطر داشته باشید؛ باید مطمئن شوید که توکن‌ساز، اهداف را به زبان خروجی (در اینجا، فرانسوی) پردازش می‌کند. می‌توانید این کار را با ارسال اهداف به آرگومان `text_targets` از متد `__call__` توکن‌ساز انجام دهید.

برای دیدن نحوه‌ی عملکرد این روش، بیایید یک نمونه از هر زبان در مجموعه‌ی آموزشی را پردازش کنیم:

```python
en_sentence = split_datasets["train"][1]["translation"]["en"]
fr_sentence = split_datasets["train"][1]["translation"]["fr"]

inputs = tokenizer(en_sentence, text_target=fr_sentence)
inputs
```

```python out
{'input_ids': [47591, 12, 9842, 19634, 9, 0], 'attention_mask': [1, 1, 1, 1, 1, 1], 'labels': [577, 5891, 2, 3184, 16, 2542, 5, 1710, 0]}
```

همانطور که می‌بینیم، خروجی شامل شناسه‌های ورودی مرتبط با جمله انگلیسی است، در حالی که شناسه‌های مرتبط با جمله فرانسوی در فیلد `labels` ذخیره شده‌اند. اگر فراموش کنید که مشخص کنید در حال توکن‌سازی برچسب‌ها هستید، آنها توسط توکن‌ساز ورودی توکن‌سازی می‌شوند، که در مورد مدل Marian به هیچ وجه خوب پیش نخواهد رفت:

```python
wrong_targets = tokenizer(fr_sentence)
print(tokenizer.convert_ids_to_tokens(wrong_targets["input_ids"]))
print(tokenizer.convert_ids_to_tokens(inputs["labels"]))
```

```python out
['▁Par', '▁dé', 'f', 'aut', ',', '▁dé', 've', 'lop', 'per', '▁les', '▁fil', 's', '▁de', '▁discussion', '</s>']
['▁Par', '▁défaut', ',', '▁développer', '▁les', '▁fils', '▁de', '▁discussion', '</s>']
```

همانطور که می‌بینیم، استفاده از توکن‌ساز انگلیسی برای پیش‌پردازش یک جمله فرانسوی منجر به توکن‌های بسیار بیشتری می‌شود، زیرا توکن‌ساز هیچ کلمه فرانسوی نمی‌شناسد (به جز کلماتی که در زبان انگلیسی نیز وجود دارند، مانند "discussion").

از آنجایی که `inputs` یک دیکشنری با کلیدهای معمول ما (شناسه‌های ورودی، ماسک توجه و غیره) است، آخرین مرحله تعریف تابع پیش‌پردازشی است که روی دیتاسِت‌ها اعمال خواهیم کرد:

```python
max_length = 128


def preprocess_function(examples):
    inputs = [ex["en"] for ex in examples["translation"]]
    targets = [ex["fr"] for ex in examples["translation"]]
    model_inputs = tokenizer(
        inputs, text_target=targets, max_length=max_length, truncation=True
    )
    return model_inputs
```

توجه داشته باشید که ما حداکثر طول یکسانی را برای ورودی‌ها و خروجی‌های خود تعیین می‌کنیم. از آنجایی که متن‌هایی که با آنها سروکار داریم بسیار کوتاه به نظر می‌رسند، از ۱۲۸ استفاده می‌کنیم.

> نکته
> 💡 اگر از مدل T5 استفاده می‌کنید (به طور خاص، یکی از نقاط بررسی `t5-xxx`)، مدل انتظار دارد ورودی‌های متنی پیشوندی داشته باشند که نشان دهنده وظیفه مورد نظر باشد، مانند `translate: English to French:`.

> WARNING
> ⚠️ ما به ماسک توجه اهداف توجه نمی‌کنیم، زیرا مدل انتظار آن را ندارد. در عوض، برچسب‌های مربوط به یک نشانه‌ی بالشتک باید روی `-100` تنظیم شوند تا در محاسبه‌ی زیان نادیده گرفته شوند. این کار بعداً توسط گردآورنده‌ی داده‌های ما انجام خواهد شد زیرا ما در حال اعمال بالشتک پویا هستیم، اما اگر در اینجا از بالشتک استفاده می‌کنید، باید تابع پیش‌پردازش را طوری تنظیم کنید که تمام برچسب‌های مربوط به نشانه‌ی بالشتک را روی `-100` تنظیم کند.

اکنون می‌توانیم آن پیش‌پردازش را به‌طور یکجا روی تمام بخش‌های دیتاسِت خود اعمال کنیم:

```py
tokenized_datasets = split_datasets.map(
    preprocess_function,
    batched=True,
    remove_columns=split_datasets["train"].column_names,
)
```

اکنون که داده‌ها پیش‌پردازش شده‌اند، آماده‌ایم تا مدل از پیش تعلیم‌دیده خود را تنظیم کنیم!

## کوک کردن مدل با رابط برنامه‌نویسی کاربردی `Trainer`[[fine-tuning-the-model-with-the-trainer-api]]

### گردآوری داده‌ها[[data-collation]]

برای هم‌طول‌سازی بتچ‌های پویا به یک جمع‌کننده‌ی داده نیاز داریم. اینجا نمی‌توانیم مانند [فصل ۳](/course/chapter3) فقط از `DataCollatorWithPadding` استفاده کنیم، چون آن فقط ورودی‌ها (شناسه‌های ورودی، ماسک توجه و شناسه‌های نوع توکِن) را هم‌طول می‌کند. برچسب‌ها نیز باید تا بیشترین طول موجود در برچسب‌ها هم‌طول شوند. همان‌طور که پیش‌تر گفتیم، مقدار padding برای برچسب‌ها باید `-100` باشد، نه توکِن padding توکِن‌ساز، تا مقادیر padding در محاسبه‌ی هزینه نادیده گرفته شوند.

همه این کارها توسط یک [`DataCollatorForSeq2Seq`](https://huggingface.co/transformers/main_classes/data_collator.html#datacollatorforseq2seq) انجام می‌شود. مانند `DataCollatorWithPadding`، این واحد از `tokenizer` برای پیش‌پردازش ورودی‌ها استفاده می‌کند، اما `model` را نیز دریافت می‌کند. دلیل این امر آن است که این گردآورنده داده‌ها مسئول آماده‌سازی شناسه‌های ورودی رمزگشا نیز خواهد بود که نسخه‌های تغییر یافته برچسب‌ها با یک توکن ویژه در ابتدا هستند. از آنجایی که این تغییر برای معماری‌های مختلف کمی متفاوت انجام می‌شود، `DataCollatorForSeq2Seq` باید شیء `model` را بشناسد:

{#if fw === 'pt'}

```py

```

### معیارها[[metrics]]

<Youtube id="M05L1DhFqcw"/>

{#if fw === 'pt'}

ویژگی‌ای که `Seq2SeqTrainer` به سوپرکلاس خود `Trainer` اضافه می‌کند، قابلیت استفاده از روش `generate()` در طول ارزیابی یا پیش‌بینی است. در طول آموزش، مدل از `decoder_input_ids` با یک ماسک توجه استفاده می‌کند تا اطمینان حاصل شود که از توکن‌های پس از توکنی که سعی در پیش‌بینی آن دارد استفاده نمی‌کند تا آموزش را سرعت بخشد. در طول استنتاج، ما نمی‌توانیم از آنها استفاده کنیم زیرا برچسب نخواهیم داشت، بنابراین ایده خوبی است که مدل خود را با همان تنظیمات ارزیابی کنیم.

همانطور که در [فصل ۱](/course/chapter1/6) دیدیم، رمزگشا با پیش‌بینی توکن‌ها به صورت یک به یک، استنتاج را انجام می‌دهد -- چیزی که در پشت صحنه در ترنسفورمرهای 🤗 با روش `generate()` پیاده‌سازی شده است. `Seq2SeqTrainer` به ما اجازه می‌دهد در صورت تنظیم `predict_with_generate=True` از آن روش برای ارزیابی استفاده کنیم.

{/if}

معیار سنتی مورد استفاده برای ترجمه، [امتیاز BLEU](https://en.wikipedia.org/wiki/BLEU) است که در [مقاله‌ای در سال ۲۰۰۲](https://aclanthology.org/P02-1040.pdf) توسط کیشور پاپیننی و همکارانش معرفی شد. امتیاز BLEU میزان نزدیکی ترجمه‌ها به برچسب‌هایشان را ارزیابی می‌کند. این معیار، میزان فهم یا صحت دستوری خروجی‌های تولید شده توسط مدل را اندازه‌گیری نمی‌کند، بلکه از قوانین آماری برای اطمینان از اینکه تمام کلمات موجود در خروجی‌های تولید شده در اهداف نیز ظاهر می‌شوند، استفاده می‌کند. در علاوه بر این، قوانینی وجود دارد که تکرار کلمات یکسان را جریمه می‌کند، اگر آنها در اهداف نیز تکرار نشده باشند (برای جلوگیری از تولید جملاتی مانند `"the the the the the"` توسط مدل) و جملاتی را تولید می‌کند که کوتاه‌تر از جملات موجود در اهداف هستند (برای جلوگیری از تولید جملاتی مانند `"the"` توسط مدل).

یکی از نقاط ضعف BLEU این است که انتظار دارد متن از قبل توکن‌سازی شده باشد، که مقایسه امتیازها بین مدل‌هایی که از توکن‌سازهای مختلف استفاده می‌کنند را دشوار می‌کند. بنابراین، رایج‌ترین معیار مورد استفاده برای ارزیابی مدل‌های ترجمه امروزی [SacreBLEU](https://github.com/mjpost/sacrebleu) است که با استانداردسازی مرحله توکن‌سازی، این نقطه ضعف (و نقاط ضعف دیگر) را برطرف می‌کند. برای استفاده از این معیار، ابتدا باید کتابخانه SacreBLEU را نصب کنیم:

```py
!pip install sacrebleu
```

سپس می‌توانیم آن را از طریق `evaluate.load()` مانند کاری که در [فصل 3](/course/chapter3) انجام دادیم، بارگذاری کنیم:

برای تبدیل خروجی‌های مدل به متن قابل استفاده برای معیار، از متد `tokenizer.batch_decode()` استفاده می‌کنیم. فقط باید همه‌ی `-100`ها را از برچسب‌ها پاک کنیم؛ توکِن‌ساز همین کار را برای توکِن padding خودکار انجام می‌دهد. تابعی تعریف می‌کنیم که مدل و دیتاسِت را بگیرد و معیارها را محاسبه کند. همچنین برای افزایش چشمگیر عملکرد، کد تولید را با [XLA](https://www.tensorflow.org/xla)، کامپایلر جبر خطی شتاب‌یافته‌ی TensorFlow، کامپایل می‌کنیم. XLA نمودار محاسباتی مدل را بهینه می‌کند و سرعت و مصرف حافظه را بهبود می‌دهد. طبق توضیح [وبلاگ](https://huggingface.co/blog/tf-xla-generate)، چون XLA با شکل‌های ورودی مشابه بهتر کار می‌کند، ورودی‌ها را به مضرب‌های ۱۲۸ هم‌طول می‌کنیم و دیتاسِت تازه‌ای می‌سازیم. دکوراتور `@tf.function(jit_compile=True)` کل تابع تولید را برای کامپایل با XLA علامت می‌زند.

```py
import numpy as np
import tensorflow as tf
from tqdm import tqdm

generation_data_collator = DataCollatorForSeq2Seq(
    tokenizer, model=model, return_tensors="tf", pad_to_multiple_of=128
)

tf_generate_dataset = model.prepare_tf_dataset(
    tokenized_datasets["validation"],
    collate_fn=generation_data_collator,
    shuffle=False,
    batch_size=8,
)


@tf.function(jit_compile=True)
def generate_with_xla(batch):
    return model.generate(
        input_ids=batch["input_ids"],
        attention_mask=batch["attention_mask"],
        max_new_tokens=128,
    )


def compute_metrics():
    all_preds = []
    all_labels = []

    for batch, labels in tqdm(tf_generate_dataset):
        predictions = generate_with_xla(batch)
        decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)
        labels = labels.numpy()
        labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
        decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)
        decoded_preds = [pred.strip() for pred in decoded_preds]
        decoded_labels = [[label.strip()] for label in decoded_labels]
        all_preds.extend(decoded_preds)
        all_labels.extend(decoded_labels)

    result = metric.compute(predictions=all_preds, references=all_labels)
    return {"bleu": result["score"]}
```

{:else}

برای اینکه از خروجی‌های مدل، متن‌هایی که معیار می‌تواند استفاده کند را دریافت کنیم، از متد `tokenizer.batch_decode()` استفاده خواهیم کرد. فقط باید تمام `-100`های موجود در برچسب‌ها را پاک کنیم (توکن‌ساز به طور خودکار همین کار را برای توکن padding انجام می‌دهد):

```py
import numpy as np


def compute_metrics(eval_preds):
    preds, labels = eval_preds
    # In case the model returns more than the prediction logits
    if isinstance(preds, tuple):
        preds = preds[0]

    decoded_preds = tokenizer.batch_decode(preds, skip_special_tokens=True)

    # Replace -100s in the labels as we can't decode them
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # Some simple post-processing
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]

    result = metric.compute(predictions=decoded_preds, references=decoded_labels)
    return {"bleu": result["score"]}
```

پس از این کار همه‌چیز را برای کامپایل و تعلیم مدل آماده می‌کنیم. توجه کنید که `tf.keras.mixed_precision.set_global_policy("mixed_float16")` به کِراس می‌گوید از float16 استفاده کند؛ این کار روی GPUهای پشتیبان (Nvidia 20xx/V100 یا جدیدتر) می‌تواند سرعت را بسیار افزایش دهد.

```python
from transformers import create_optimizer
from transformers.keras_callbacks import PushToHubCallback
import tensorflow as tf

# The number of training steps is the number of samples in the dataset, divided by the batch size then multiplied
# by the total number of epochs. Note that the tf_train_dataset here is a batched tf.data.Dataset,
# not the original Hugging Face Dataset, so its len() is already num_samples // batch_size.
num_epochs = 3
num_train_steps = len(tf_train_dataset) * num_epochs

optimizer, schedule = create_optimizer(
    init_lr=5e-5,
    num_warmup_steps=0,
    num_train_steps=num_train_steps,
    weight_decay_rate=0.01,
)
model.compile(optimizer=optimizer)

# Train in mixed-precision float16
tf.keras.mixed_precision.set_global_policy("mixed_float16")
```

## یک حلقه آموزشی سفارشی[[a-custom-training-loop]]

حالا حلقه‌ی کامل تعلیم را بررسی می‌کنیم تا بتوانید بخش‌های لازم را به‌سادگی سفارشی کنید. این حلقه بسیار شبیه کاری است که در [بخش ۲](/course/chapter7/2) و [فصل ۳](/course/chapter3/4) انجام دادیم.

### آماده‌سازی همه‌چیز برای آموزش[[preparing-everything-for-training]]

شما همه این‌ها را چندین بار دیده‌اید، بنابراین خیلی سریع کد را بررسی می‌کنیم. ابتدا `DataLoader`ها را از دیتاسِت‌های خود می‌سازیم، پس از تنظیم دیتاسِت‌ها به فرمت `"torch"`، تانسورهای PyTorch را دریافت می‌کنیم:

```py
from torch.utils.data import DataLoader

tokenized_datasets.set_format("torch")
train_dataloader = DataLoader(
    tokenized_datasets["train"],
    shuffle=True,
    collate_fn=data_collator,
    batch_size=8,
)
eval_dataloader = DataLoader(
    tokenized_datasets["validation"], collate_fn=data_collator, batch_size=8
)
```

سپس مدل را دوباره نمونه‌سازی می‌کنیم تا کوک کردن قبلی را ادامه ندهیم و دوباره از مدل از پیش تعلیم‌دیده شروع کنیم:

```py
model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint)
```

سپس به یک بهینه‌ساز نیاز داریم:

```py

```

وقتی همه آن اشیاء را داشتیم، می‌توانیم آنها را به متد `accelerator.prepare()` ارسال کنیم. به یاد داشته باشید که اگر می‌خواهید روی TPUها در یک نوت‌بوک Colab آموزش دهید، باید تمام این کد را به یک تابع آموزشی منتقل کنید و این تابع نباید هیچ سلولی را که یک `Accelerator` را نمونه‌سازی می‌کند، اجرا کند.

```py
from accelerate import Accelerator

accelerator = Accelerator()
model, optimizer, train_dataloader, eval_dataloader = accelerator.prepare(
    model, optimizer, train_dataloader, eval_dataloader
)
```

حالا که `train_dataloader` خود را به `accelerator.prepare()` ارسال کرده‌ایم، می‌توانیم از طول آن برای محاسبه تعداد مراحل آموزش استفاده کنیم. به یاد داشته باشید که همیشه باید این کار را پس از آماده‌سازی dataloader انجام دهیم، زیرا این روش طول `DataLoader` را تغییر می‌دهد. ما از یک زمانبندی خطی کلاسیک از نرخ یادگیری تا ۰ استفاده می‌کنیم:

```py
from transformers import get_scheduler

num_train_epochs = 3
num_update_steps_per_epoch = len(train_dataloader)
num_training_steps = num_train_epochs * num_update_steps_per_epoch

lr_scheduler = get_scheduler(
    "linear",
    optimizer=optimizer,
    num_warmup_steps=0,
    num_training_steps=num_training_steps,
)
```

### حلقه آموزشی[[training-loop]]

اکنون آماده‌ایم حلقه‌ی کامل تعلیم را بنویسیم. برای ساده کردن ارزیابی، تابع `postprocess()` را تعریف می‌کنیم که پیش‌بینی‌ها و برچسب‌ها را می‌گیرد و به فهرست رشته‌هایی تبدیل می‌کند که شیء `metric` انتظار دارد:

```py
def postprocess(predictions, labels):
    predictions = predictions.cpu().numpy()
    labels = labels.cpu().numpy()

    decoded_preds = tokenizer.batch_decode(predictions, skip_special_tokens=True)

    # Replace -100 in the labels as we can't decode them.
    labels = np.where(labels != -100, labels, tokenizer.pad_token_id)
    decoded_labels = tokenizer.batch_decode(labels, skip_special_tokens=True)

    # Some simple post-processing
    decoded_preds = [pred.strip() for pred in decoded_preds]
    decoded_labels = [[label.strip()] for label in decoded_labels]
    return decoded_preds, decoded_labels
```

حلقه آموزشی بسیار شبیه به حلقه‌های موجود در [بخش ۲](/course/chapter7/2) و [فصل ۳](/course/chapter3) است، با چند تفاوت در بخش ارزیابی -- پس بیایید روی آن تمرکز کنیم!

نخست توجه کنید که برای محاسبه‌ی پیش‌بینی‌ها از متد `generate()` استفاده می‌کنیم، اما این متد روی مدل پایه قرار دارد، نه مدل پوشانده‌شده‌ای که 🤗 Accelerate در متد `prepare()` ساخته است. بنابراین ابتدا مدل را از پوشش خارج می‌کنیم و سپس این متد را فراخوانی می‌کنیم.

نکته دوم این است که، مانند [توکِن classification](/course/chapter7/2)، ممکن است دو فرآیند ورودی‌ها و برچسب‌ها را به شکل‌های مختلف پر کرده باشند، بنابراین ما از `accelerator.pad_across_processes()` استفاده می‌کنیم تا پیش‌بینی‌ها و برچسب‌ها را قبل از فراخوانی متد `gather()` به شکل یکسانی درآوریم. اگر این کار را نکنیم، ارزیابی یا با خطا مواجه می‌شود یا برای همیشه متوقف می‌شود.

```py
from tqdm.auto import tqdm
import torch

progress_bar = tqdm(range(num_training_steps))

for epoch in range(num_train_epochs):
    # Training
    model.train()
    for batch in train_dataloader:
        outputs = model(**batch)
        loss = outputs.loss
        accelerator.backward(loss)

        optimizer.step()
        lr_scheduler.step()
        optimizer.zero_grad()
        progress_bar.update(1)

    # Evaluation
    model.eval()
    for batch in tqdm(eval_dataloader):
        with torch.no_grad():
            generated_tokens = accelerator.unwrap_model(model).generate(
                batch["input_ids"],
                attention_mask=batch["attention_mask"],
                max_length=128,
            )
        labels = batch["labels"]

        # Necessary to pad predictions and labels for being gathered
        generated_tokens = accelerator.pad_across_processes(
            generated_tokens, dim=1, pad_index=tokenizer.pad_token_id
        )
        labels = accelerator.pad_across_processes(labels, dim=1, pad_index=-100)

        predictions_gathered = accelerator.gather(generated_tokens)
        labels_gathered = accelerator.gather(labels)

        decoded_preds, decoded_labels = postprocess(predictions_gathered, labels_gathered)
        metric.add_batch(predictions=decoded_preds, references=decoded_labels)

    results = metric.compute()
    print(f"epoch {epoch}, BLEU score: {results['score']:.2f}")

    # Save and upload
    accelerator.wait_for_everyone()
    unwrapped_model = accelerator.unwrap_model(model)
    unwrapped_model.save_pretrained(output_dir, save_function=accelerator.save)
    if accelerator.is_main_process:
        tokenizer.save_pretrained(output_dir)
        repo.push_to_hub(
            commit_message=f"Training in progress epoch {epoch}", blocking=False
        )
```
