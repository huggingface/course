## استفاده از embeddingها برای جست‌وجوی معنایی[[using-embeddings-for-semantic-search]]

همان‌طور که در [فصل ۱](/course/chapter1) دیدیم، مدل‌های زبانی مبتنی بر ترنسفورمر هر توکِن موجود در یک بازه‌ی متنی را به‌صورت یک _بردار embedding_ نمایش می‌دهند. مشخص شده است که می‌توان embeddingهای جداگانه را برای ساختن نمایش برداریِ جمله‌ها، پاراگراف‌ها یا (در برخی موارد) سندهای کامل، «تجمیع» کرد. سپس می‌توان با محاسبه‌ی شباهت ضرب داخلی (یا معیار شباهت دیگری) بین هر embedding، از این embeddingها برای یافتن سندهای مشابه در پیکره استفاده کرد و سندهایی را برگرداند که بیشترین همپوشانی را دارند.

در این بخش از embeddingها برای ساختن یک موتور جست‌وجوی معنایی استفاده می‌کنیم. این موتورهای جست‌وجو نسبت به روش‌های متداولی که بر تطبیق کلمات کلیدیِ یک پرس‌وجو با سندها تکیه دارند، چند مزیت ارائه می‌کنند.

در `load_dataset()`، split پیش‌فرض `train` را مشخص کرده‌ایم؛ بنابراین این تابع به‌جای یک `DatasetDict`، یک `Dataset` برمی‌گرداند. نخستین کار، حذف pull requestهاست، چون معمولاً به‌ندرت برای پاسخ‌گویی به پرسش‌های کاربران استفاده می‌شوند و به موتور جست‌وجوی ما نویز اضافه می‌کنند. همان‌طور که تا اینجا باید با آن آشنا شده باشید، می‌توانیم از تابع `Dataset.filter()` برای حذف این ردیف‌ها از دیتاست استفاده کنیم. در همین حین، ردیف‌هایی را که comment ندارند نیز حذف می‌کنیم، چون پاسخی برای پرسش‌های کاربران ارائه نمی‌کنند:

<div dir="ltr">

```py
issues_dataset = issues_dataset.filter(

issues_dataset
```

## ساختن embeddingهای متن[[creating-text-embeddings]]

در [فصل ۲](/course/chapter2) دیدیم که می‌توان با استفاده از کلاس `AutoModel`، embeddingهای توکِن را به دست آورد. تنها کاری که باید انجام دهیم، انتخاب یک نقطه‌ی تعلیم مناسب برای بارگذاری مدل است. خوشبختانه کتابخانه‌ای به نام `sentence-transformers` وجود دارد که به ساخت embedding اختصاص یافته است. همان‌طور که در [مستندات کتابخانه](https://www.sbert.net/examples/applications/semantic-search/README.html#symmetric-vs-asymmetric-semantic-search) توضیح داده شده است، کاربرد ما نمونه‌ای از _جست‌وجوی معنایی نامتقارن_ است؛ چون یک پرس‌وجوی کوتاه داریم و می‌خواهیم پاسخ آن را در سندی طولانی‌تر، مانند یک comment مربوط به issue، پیدا کنیم. جدول مفید [مرور مدل‌ها](https://www.sbert.net/docs/pretrained_models.html#model-overview) در مستندات نشان می‌دهد که نقطه‌ی تعلیم `multi-qa-mpnet-base-dot-v1` بهترین عملکرد را برای جست‌وجوی معنایی دارد، پس در برنامه‌ی خود از آن استفاده می‌کنیم. توکِنایزر را نیز با همین نقطه‌ی تعلیم بارگذاری خواهیم کرد:

{#if fw === 'pt'}

<div dir="ltr">

```py
from transformers import AutoTokenizer, AutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = AutoModel.from_pretrained(model_ckpt)
```

</div>

برای سرعت بخشیدن به فرایند ساخت embedding، بهتر است مدل و ورودی‌ها را روی یک دستگاه GPU قرار دهیم؛ پس همین کار را انجام می‌دهیم:

<div dir="ltr">

```py
import torch

device = torch.device("cuda")
model.to(device)
```

</div>

{:else}

<div dir="ltr">

```py
from transformers import AutoTokenizer, TFAutoModel

model_ckpt = "sentence-transformers/multi-qa-mpnet-base-dot-v1"
tokenizer = AutoTokenizer.from_pretrained(model_ckpt)
model = TFAutoModel.from_pretrained(model_ckpt, from_pt=True)
```

</div>

توجه کنید که آرگومان `from_pt=True` را به متد `from_pretrained()` داده‌ایم. دلیلش این است که نقطه‌ی تعلیم `multi-qa-mpnet-base-dot-v1` فقط وزن‌های PyTorch را دارد؛ بنابراین تنظیم `from_pt=True` آن‌ها را به‌طور خودکار به قالب TensorFlow تبدیل می‌کند. همان‌طور که می‌بینید، جابه‌جایی بین فریم‌ورک‌ها در 🤗 Transformers بسیار ساده است!

{/if}

همان‌طور که پیش‌تر گفتیم، می‌خواهیم هر ورودی موجود در پیکره‌ی issueهای GitHub را به‌صورت یک بردار واحد نمایش دهیم؛ بنابراین باید embeddingهای توکِن را به شکلی «تجمیع» یا میانگین‌گیری کنیم. یک روش رایج، انجام *تجمیع CLS* روی خروجی‌های مدل است؛ در این روش فقط وضعیت پنهان نهاییِ توکِن ویژه‌ی `[CLS]` را جمع‌آوری می‌کنیم. تابع زیر این کار را برای ما انجام می‌دهد:

<div dir="ltr">

```py
def cls_pooling(model_output):
    return model_output.last_hidden_state[:, 0]
```

</div>

در گام بعد، تابع کمکی‌ای می‌سازیم که فهرستی از سندها را توکِن‌سازی کند، تِنسورها را روی GPU قرار دهد، آن‌ها را به مدل بدهد و در نهایت تجمیع CLS را روی خروجی‌ها اعمال کند:

{#if fw === 'pt'}

<div dir="ltr">

```py
def get_embeddings(text_list):
    encoded_input = tokenizer(
        text_list, padding=True, truncation=True, return_tensors="pt"
    )
    encoded_input = {k: v.to(device) for k, v in encoded_input.items()}
    model_output = model(**encoded_input)
    return cls_pooling(model_output)
```

برای بررسی عملکرد تابع، می‌توانیم نخستین ورودی متنی پیکره را به آن بدهیم و شکل خروجی را بررسی کنیم:

```py
embedding = get_embeddings(comments_dataset["text"][0])
embedding.shape
```

```python out
torch.Size([1, 768])
```

</div>

عالی است، نخستین ورودی پیکره را به برداری با ۷۶۸ بُعد تبدیل کردیم! می‌توانیم تابع `get_embeddings()` را با `Dataset.map()` روی هر ردیف پیکره اعمال کنیم؛ پس ستون جدید `embeddings` را به شکل زیر می‌سازیم:

<div dir="ltr">

```py
embeddings_dataset = comments_dataset.map(
    lambda x: {"embeddings": get_embeddings(x["text"]).detach().cpu().numpy()[0]}
)
```

</div>

## استفاده از FAISS برای جست‌وجوی کارآمد بر اساس شباهت[[using-faiss-for-efficient-similarity-search]]

حالا که دیتاستی از embeddingها داریم، به راهی برای جست‌وجو در آن‌ها نیاز داریم. برای این کار از ساختار داده‌ی ویژه‌ای در 🤗 Datasets به نام _اندیس FAISS_ استفاده می‌کنیم. [FAISS](https://faiss.ai/) (مخفف Facebook AI Similarity Search) کتابخانه‌ای است که الگوریتم‌های کارآمدی برای جست‌وجو و خوشه‌بندی سریع بردارهای embedding ارائه می‌کند.

ایده‌ی اصلی FAISS ساختن ساختار داده‌ی ویژه‌ای به نام _اندیس_ است که امکان می‌دهد embeddingهای مشابه یک embedding ورودی را پیدا کنیم. ساختن یک اندیس FAISS در 🤗 Datasets ساده است — از تابع `Dataset.add_faiss_index()` استفاده می‌کنیم و مشخص می‌کنیم کدام ستون دیتاست را می‌خواهیم اندیس‌گذاری کنیم:

<div dir="ltr">

```py
embeddings_dataset.add_faiss_index(column="embeddings")
```

</div>

اکنون می‌توانیم با جست‌وجوی نزدیک‌ترین همسایه و استفاده از تابع `Dataset.get_nearest_examples()` روی این اندیس پرس‌وجو انجام دهیم. بیایید ابتدا یک پرسش را embedding کنیم:

{#if fw === 'pt'}

<div dir="ltr">

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).cpu().detach().numpy()
question_embedding.shape
```

```python out
torch.Size([1, 768])
```

</div>

{:else}

<div dir="ltr">

```py
question = "How can I load a dataset offline?"
question_embedding = get_embeddings([question]).numpy()
question_embedding.shape
```

```python out
(1, 768)
```

</div>

{/if}

درست مانند سندها، اکنون برداری با ۷۶۸ بُعد داریم که پرس‌وجو را نمایش می‌دهد. می‌توانیم آن را با کل پیکره مقایسه کنیم تا مشابه‌ترین embeddingها را پیدا کنیم:

<div dir="ltr">

```py
scores, samples = embeddings_dataset.get_nearest_examples(
    "embeddings", question_embedding, k=5
)
```

</div>

تابع `Dataset.get_nearest_examples()` تاپلی از امتیازها برمی‌گرداند که میزان همپوشانی بین پرس‌وجو و سند را رتبه‌بندی می‌کنند، و مجموعه‌ی متناظری از نمونه‌ها را نیز برمی‌گرداند (در اینجا ۵ تطبیق برتر). بیایید آن‌ها را در یک `pandas.DataFrame` جمع کنیم تا بتوانیم به‌سادگی مرتبشان کنیم:

<div dir="ltr">

```py
import pandas as pd

samples_df = pd.DataFrame.from_dict(samples)
samples_df["scores"] = scores
samples_df.sort_values("scores", ascending=False, inplace=True)
```

</div>

حالا می‌توانیم روی چند ردیف اول پیمایش کنیم تا ببینیم پرس‌وجوی ما تا چه اندازه با commentهای موجود تطبیق دارد:

<div dir="ltr">

```py
for _, row in samples_df.iterrows():
    print(f"COMMENT: {row.comments}")
    print(f"SCORE: {row.scores}")
    print(f"TITLE: {row.title}")
    print(f"URL: {row.html_url}")
    print("=" * 50)
    print()
```
