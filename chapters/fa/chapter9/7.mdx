در بخش‌های قبلی، دمویی را با استفاده از کلاس `Interface` ایجاد کرده‌ایم. در این بخش، API سطح پایین **تازه توسعه یافته** خود را به نام `gradio.Blocks` معرفی می کنیم.

حالا، تفاوت بین `Interface` و `Blocks` چیست؟

- ⚡ `Interface`: یک API سطح بالا که به شما امکان می‌دهد به سادگی با ارائه فهرستی از ورودی‌ها و خروجی‌ها، یک نسخه نمایشی کامل از یادگیری ماشین ایجاد کنید.

- 🧱 `Blocks`: یک API سطح پایین که به شما امکان کنترل کامل بر جریان داده‌ها و طرح‌بندی برنامه‌تان را می‌دهد. می‌توانید با استفاده از `Blocks` (مانند "بلوک‌های سازنده") برنامه‌های بسیار پیچیده و چند مرحله‌ای بسازید.


### چرا Blocks؟ 🧱[[why-blocks-]]

همانطور که در بخش های قبلی دیدیم، کلاس `Interface` به شما این امکان را می دهد که به راحتی فقط با چند خط کد، دموهای یادگیری ماشینی کامل ایجاد کنید. `Interface` API بسیار آسان برای استفاده است اما فاقد انعطاف پذیری است که `Blocks` API فراهم می کند. برای مثال، ممکن است بخواهید:

- دموهای مرتبط را به عنوان چندین برگه در یک برنامه وب با هم گروه بندی کنید
- طرح نمایشی خود را تغییر دهید، برای مثال، برای تعیین محل قرارگیری ورودی ها و خروجی ها
- دارای رابط های چند مرحله ای، که در آن خروجی یک مدل به ورودی مدل بعدی تبدیل می شود، یا به طور کلی جریان های داده انعطاف پذیرتری دارند.
- ویژگی‌های یک مؤلفه (برای مثال، انتخاب‌های یک کشویی) یا نمایان بودن آن را بر اساس ورودی کاربر تغییر دهید

در ادامه تمامی این مفاهیم را بررسی خواهیم کرد.

### ایجاد یک دمو ساده با Blocks[[creating-a-simple-demo-using-blocks]]

پس از نصب Gradio، کد زیر را به عنوان یک اسکریپت پایتون، یک نوت بوک Jupyter یا یک نوت بوک Colab اجرا کنید.

```py
import gradio as gr


def flip_text(x):
    return x[::-1]


demo = gr.Blocks()

with demo:
    gr.Markdown(
        """
    # Flip Text!
    Start typing below to see the output.
    """
    )
    input = gr.Textbox(placeholder="Flip this text")
    output = gr.Textbox()

    input.change(fn=flip_text, inputs=input, outputs=output)

demo.launch()
```

این مثال ساده در بالا 4 مفهوم را معرفی می کند که زیربنای بلوک‌ها هستند:

1. بلوک‌ها به شما امکان می دهند برنامه های کاربردی وب بسازید که نشانه گذاری، HTML، دکمه ها و اجزای تعاملی را به سادگی با نمونه سازی اشیاء در پایتون در داخل یک زمینه `with gradio.Blocks` ترکیب می کنند.

> [!TIP]
> 🙋اگر با دستور `with` در پایتون آشنا نیستید، توصیه می‌کنیم [آموزش عالی](https://realpython.com/python-with-statement/) از Real Python را ببینید. بعد از خواندن آن به اینجا برگردید 🤗

ترتیبی که مؤلفه‌ها را در آن نمونه‌سازی می‌کنید اهمیت دارد زیرا هر عنصر به ترتیبی که ایجاد شده در برنامه وب ارائه می‌شود. (طرح های پیچیده تر در زیر مورد بحث قرار می گیرند)

2. شما می توانید توابع معمولی پایتون را در هر جایی از کد خود تعریف کنید و آنها را با ورودی کاربر با استفاده از `Blocks` اجرا کنید. در مثال ما، یک تابع ساده داریم که متن ورودی را «تغییر» می‌کند، اما می‌توانید هر تابع پایتون را بنویسید، از یک محاسبه ساده گرفته تا پردازش پیش‌بینی‌های یک مدل یادگیری ماشین.

3. می توانید رویدادها را به هر جزء `Blocks` اختصاص دهید. هنگامی که مؤلفه کلیک می‌شود، تغییر می‌کند و غیره، عملکرد شما را اجرا می‌کند. وقتی رویدادی را اختصاص می‌دهید، سه پارامتر را ارسال می‌کنید: `fn`: تابعی که باید فراخوانی شود، `inputs`: (لیست) مؤلفه(های) ورودی و `outputs`: (لیست) مؤلفه‌های خروجی که باید فراخوانی شوند.

در مثال بالا، زمانی که مقدار `Textbox` با نام ورودی `input` تغییر می کند، تابع `flip_text()` را اجرا می کنیم. رویداد مقدار را در `input` می خواند، آن را به عنوان پارامتر نام به `flip_text()` ارسال می کند، که سپس مقداری را برمی گرداند که به `Textbox` دوم ما به نام `output` نسبت داده می شود.

برای مشاهده لیستی از رویدادهایی که هر جزء پشتیبانی می کند، به Gradio [مستندات](https://www.gradio.app/docs/) مراجعه کنید.

4. بلوک‌ها به طور خودکار تشخیص می دهند که آیا یک مؤلفه باید تعاملی باشد (ورودی کاربر را بپذیرد) یا خیر، بر اساس محرک های رویدادی که شما تعریف می کنید. در مثال ما، جعبه متن اول تعاملی است، زیرا مقدار آن توسط تابع `flip_text()` استفاده می شود. جعبه متن دوم تعاملی نیست، زیرا مقدار آن هرگز به عنوان ورودی استفاده نمی شود. در برخی موارد، ممکن است بخواهید این مورد را لغو کنید، که می‌توانید با ارسال یک بولی به پارامتر `interactive` مؤلفه (به عنوان مثال `gr.Textbox(placeholder="Flip this text", interactive=True)`) انجام دهید.

### سفارشی‌سازی چیدمان دمو[[customizing-the-layout-of-your-demo]]

چگونه می توانیم از `Blocks` برای سفارشی کردن طرح نمایشی خود استفاده کنیم؟ به طور پیش فرض، `Blocks` اجزایی را که شما به صورت عمودی ایجاد می کنید در یک ستون رندر می کند. می‌توانید آن را با ایجاد ستون‌های اضافی `with gradio.Column():` یا ردیف‌های `with gradio.Row():` و ایجاد مؤلفه‌ها در آن زمینه‌ها تغییر دهید.

هر مؤلفه‌ای که زیر یک `Column` ساخته شود (که حالت پیش‌فرض هم هست) به‌صورت عمودی چیده می‌شود. هر مؤلفه‌ای که زیر یک `Row` ساخته شود، مشابه [مدل flexbox در توسعه‌ی وب](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Flexible_Box_Layout/Basic_Concepts_of_Flexbox) به‌صورت افقی قرار می‌گیرد.

در نهایت می‌توانید با استفاده از مدیر زمینه‌ی `with gradio.Tabs()` برای دمو خود تب بسازید. در این زمینه با تعیین فرزند `with gradio.TabItem(name_of_tab):` چند تب ایجاد می‌کنید. هر مؤلفه‌ای که درون زمینه‌ی `with gradio.TabItem(name_of_tab):` ساخته شود در همان تب نمایش داده می‌شود.

حالا بیایید یک تابع `flip_image()` را به نسخه نمایشی خود اضافه کنیم و یک برگه جدید اضافه کنیم که تصاویر را برگرداند. در زیر یک مثال با 2 تب و همچنین از یک ردیف استفاده شده است:

```py
import numpy as np
import gradio as gr

demo = gr.Blocks()


def flip_text(x):
    return x[::-1]


def flip_image(x):
    return np.fliplr(x)


with demo:
    gr.Markdown("Flip text or image files using this demo.")
    with gr.Tabs():
        with gr.TabItem("Flip Text"):
            with gr.Row():
                text_input = gr.Textbox()
                text_output = gr.Textbox()
            text_button = gr.Button("Flip")
        with gr.TabItem("Flip Image"):
            with gr.Row():
                image_input = gr.Image()
                image_output = gr.Image()
            image_button = gr.Button("Flip")

    text_button.click(flip_text, inputs=text_input, outputs=text_output)
    image_button.click(flip_image, inputs=image_input, outputs=image_output)

demo.launch()
```

### کاوش رویدادها و وضعیت[[exploring-events-and-state]]

همانطور که می‌توانید طرح‌بندی را کنترل کنید، `Blocks` به شما کنترل دقیقی بر روی رویدادهایی که فراخوانی‌های تابع را آغاز می‌کنند، می‌دهد. هر مؤلفه و بسیاری از طرح‌بندی‌ها رویدادهای خاصی دارند که از آنها پشتیبانی می‌کنند.

برای مثال، مولفه `Textbox` دارای 2 رویداد است: `change()` (زمانی که مقدار داخل جعبه متن تغییر می کند) و `submit()` (زمانی که کاربر کلید enter را در حالی که روی جعبه متن متمرکز است فشار می دهد). اجزای پیچیده‌تر می‌توانند حتی رویدادهای بیشتری داشته باشند: برای مثال، مؤلفه `Audio` همچنین رویدادهای جداگانه‌ای برای زمانی که فایل صوتی پخش می‌شود، پاک می‌شود، متوقف می‌شود، و غیره دارد. مستندات رویدادهایی را که هر مؤلفه پشتیبانی می‌کند، ببینید.

می توانید ماشه رویداد را به هیچ یک، یک یا چند مورد از این رویدادها پیوست کنید. شما با فراخوانی نام رویداد در نمونه جزء به عنوان یک تابع، یک راه‌انداز رویداد ایجاد می‌کنید - برای مثال، `textbox.change(...)` یا `btn.click(...)`. همانطور که در بالا توضیح داده شد تابع دارای سه پارامتر است:

- `fn`: تابعی که باید اجرا شود
- `inputs`: (لیست) مؤلفه(هایی) که مقادیر آنها باید به عنوان پارامترهای ورودی به تابع ارائه شود. مقدار هر مؤلفه به ترتیب به پارامتر تابع مربوطه نگاشت می‌شود. اگر تابع هیچ پارامتری نگیرد، این پارامتر می‌تواند None باشد.
- `outputs`: (فهرست) مؤلفه(هایی) که مقادیر آن باید بر اساس مقادیر برگردانده شده توسط تابع به روز شود. هر مقدار بازگشتی مقدار مولفه مربوطه را به ترتیب تنظیم می کند. اگر تابع چیزی برنگرداند، این پارامتر می تواند None باشد.

حتی می توانید کاری کنید که مولفه ورودی و خروجی یک مولفه باشند، همانطور که در این مثال از یک مدل GPT برای تکمیل متن استفاده می کنیم:

```py
import gradio as gr

api = gr.Interface.load("huggingface/EleutherAI/gpt-j-6B")


def complete_with_gpt(text):
    # Use the last 50 characters of the text as context
    return text[:-50] + api(text[-50:])


with gr.Blocks() as demo:
    textbox = gr.Textbox(placeholder="Type here and press enter...", lines=4)
    btn = gr.Button("Generate")

    btn.click(complete_with_gpt, textbox, textbox)

demo.launch()
```

### ایجاد دموهای چندمرحله‌ای[[creating-multi-step-demos]]

در برخی موارد، ممکن است یک نسخه ی نمایشی _چند مرحله ای بخواهید که در آن از خروجی یک تابع به عنوان ورودی برای تابع بعدی مجددا استفاده کنید. انجام این کار با `Blocks` واقعاً آسان است، زیرا می‌توانید از یک مؤلفه برای ورودی یک ماشه رویداد اما خروجی دیگری استفاده کنید. به مؤلفه متن در مثال زیر نگاهی بیندازید، مقدار آن نتیجه مدل گفتار به متن است، اما به مدل تحلیل احساسات نیز منتقل می شود:

```py
from transformers import pipeline

import gradio as gr

asr = pipeline("automatic-speech-recognition", "facebook/wav2vec2-base-960h")
classifier = pipeline("text-classification")


def speech_to_text(speech):
    text = asr(speech)["text"]
    return text


def text_to_sentiment(text):
    return classifier(text)[0]["label"]


demo = gr.Blocks()

with demo:
    audio_file = gr.Audio(type="filepath")
    text = gr.Textbox()
    label = gr.Label()

    b1 = gr.Button("Recognize Speech")
    b2 = gr.Button("Classify Sentiment")

    b1.click(speech_to_text, inputs=audio_file, outputs=text)
    b2.click(text_to_sentiment, inputs=text, outputs=label)

demo.launch()
```

### به‌روزرسانی ویژگی‌های مؤلفه[[updating-component-properties]]

تاکنون نحوه ایجاد رویدادها برای به روز رسانی مقدار یک جزء دیگر را دیده ایم. اما چه اتفاقی می‌افتد اگر بخواهید سایر ویژگی‌های یک مؤلفه را تغییر دهید، مانند نمایان بودن یک جعبه متن یا انتخاب‌های یک گروه دکمه رادیویی؟ شما می توانید این کار را با برگرداندن متد `update()` یک کلاس جزء به جای مقدار بازگشتی معمولی از تابع خود انجام دهید.

این به راحتی با یک مثال نشان داده می شود:

```py
import gradio as gr


def change_textbox(choice):
    if choice == "short":
        return gr.Textbox.update(lines=2, visible=True)
    elif choice == "long":
        return gr.Textbox.update(lines=8, visible=True)
    else:
        return gr.Textbox.update(visible=False)


with gr.Blocks() as block:
    radio = gr.Radio(
        ["short", "long", "none"], label="What kind of essay would you like to write?"
    )
    text = gr.Textbox(lines=2, interactive=True)

    radio.change(fn=change_textbox, inputs=radio, outputs=text)
    block.launch()
```
