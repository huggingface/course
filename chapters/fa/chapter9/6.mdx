اکنون که می‌توانیم یک رابط اصلی بسازیم و به اشتراک بگذاریم، اجازه دهید برخی از ویژگی‌های پیشرفته‌تر مانند حالت و تفسیر را بررسی کنیم.

### استفاده از وضعیت برای حفظ داده‌ها[[using-state-to-persist-data]]

Gradio از *وضعیت نشست* پشتیبانی می‌کند؛ داده‌ها در چندین ارسال در طول بارگذاری یک صفحه حفظ می‌شوند.
وضعیت نشست برای ساخت دموهایی مانند چت‌بات‌ها مفید است؛ جاهایی که می‌خواهید با تعامل کاربر با مدل، داده‌ها حفظ شوند.
توجه کنید که وضعیت نشست داده‌ها را بین کاربران مختلف مدل شما به اشتراک نمی‌گذارد.

برای ذخیره داده ها در حالت جلسه، باید سه کار را انجام دهید:

۱. یک *پارامتر اضافی* به تابع خود بدهید که وضعیت رابط را نشان می‌دهد.
۲. در پایان تابع، مقدار به‌روزشده‌ی وضعیت را به‌عنوان یک *مقدار بازگشتی اضافی* برگردانید.
۳. هنگام ساختن `Interface`، مؤلفه‌های ورودی و خروجیِ «state» را اضافه کنید.

نمونه چت بات را در زیر ببینید:

```py
import random

import gradio as gr


def chat(message, history):
    history = history or []
    if message.startswith("How many"):
        response = random.randint(1, 10)
    elif message.startswith("How"):
        response = random.choice(["Great", "Good", "Okay", "Bad"])
    elif message.startswith("Where"):
        response = random.choice(["Here", "There", "Somewhere"])
    else:
        response = "I don't know"
    history.append((message, response))
    return history, history


iface = gr.Interface(
    chat,
    ["text", "state"],
    ["chatbot", "state"],
    allow_screenshot=False,
    allow_flagging="never",
)
iface.launch()
```

توجه کنید که چگونه وضعیت مولفه خروجی در سراسر ارسال‌ها باقی می‌ماند.
توجه: می‌توانید یک مقدار پیش‌فرض به پارامتر `state` بدهید که به‌عنوان مقدار اولیه‌ی `state` استفاده می‌شود.

### استفاده از تفسیر برای درک پیش‌بینی‌ها[[using-interpretation-to-understand-predictions]]

اکثر مدل های یادگیری ماشین جعبه سیاه هستند و منطق داخلی عملکرد از کاربر نهایی پنهان است. برای تشویق شفافیت، اضافه کردن تفسیر به مدل شما را با تنظیم کلمه کلیدی تفسیر در کلاس Interface به صورت پیش فرض بسیار آسان کرده ایم. این به کاربران شما اجازه می دهد تا بفهمند چه بخش هایی از ورودی مسئول خروجی هستند. به رابط ساده زیر نگاهی بیندازید که یک طبقه‌بندی کننده تصویر را نشان می‌دهد که شامل تفسیر نیز می‌شود:

```py
import requests
import tensorflow as tf

import gradio as gr

inception_net = tf.keras.applications.MobileNetV2()  # load the model

# Download human-readable labels for ImageNet.
response = requests.get("https://git.io/JJkYN")
labels = response.text.split("\n")


def classify_image(inp):
    inp = inp.reshape((-1, 224, 224, 3))
    inp = tf.keras.applications.mobilenet_v2.preprocess_input(inp)
    prediction = inception_net.predict(inp).flatten()
    return {labels[i]: float(prediction[i]) for i in range(1000)}


image = gr.Image(shape=(224, 224))
label = gr.Label(num_top_classes=3)

title = "Gradio Image Classifiction + Interpretation Example"
gr.Interface(
    fn=classify_image, inputs=image, outputs=label, interpretation="default", title=title
).launch()
```

تابع تفسیر را با ارسال یک ورودی و سپس کلیک بر روی تفسیر در زیر مولفه خروجی آزمایش کنید.

علاوه بر روش تفسیر پیش‌فرض Gradio، می‌توانید `shap` را برای پارامتر `interpretation` تعیین کنید و پارامتر `num_shap` را تنظیم کنید. این از تفسیر مبتنی بر Shapley استفاده می کند، که می‌توانید اطلاعات بیشتری درباره‌ی آن در [اینجا](https://christophm.github.io/interpretable-ml-book/shap.html) بخوانید.
در نهایت، شما همچنین می توانید تابع تفسیر خود را به پارامتر `interpretation` منتقل کنید. نمونه‌ای را در صفحه شروع Gradio [اینجا](https://gradio.app/getting_started/) ببینید.

این بررسی عمیق ما از کلاس `Interface` گریدیو را کامل می‌کند. همان‌طور که دیدیم، این کلاس ساخت دموهای یادگیری ماشین را تنها با چند خط کد پایتون ساده می‌کند. بااین‌حال، گاهی می‌خواهید با تغییر چیدمان یا زنجیره‌کردن چند تابع پیش‌بینی، دموی خود را سفارشی کنید. خوب نیست اگر می‌توانستیم `Interface` را به «بلوک‌های» قابل‌تنظیم تقسیم کنیم؟ خوشبختانه چنین امکانی وجود دارد! این موضوع بخش پایانی است.
