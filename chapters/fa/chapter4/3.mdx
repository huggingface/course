## استفاده از API `push_to_hub`[[using-the-pushtohub-api]]

{#if fw === 'pt'}

<Youtube id="Zh0FfmVrKX0"/>

{:else}

<Youtube id="pUh5cGmNV8Y"/>

{/if}

ساده‌ترین راه برای بارگذاری فایل‌ها در هاب، استفاده از API `push_to_hub` است.

پیش از ادامه، باید یک توکِن احراز هویت بسازید تا API `huggingface_hub` بداند شما چه کسی هستید و به کدام فضای نام دسترسی نوشتن دارید. مطمئن شوید در محیطی هستید که `transformers` در آن نصب شده است (به [راه‌اندازی](/course/chapter0) مراجعه کنید). اگر در یک نوت‌بوک هستید، می‌توانید برای ورود به سیستم از تابع زیر استفاده کنید:

<div dir="ltr">

```python
from huggingface_hub import notebook_login

notebook_login()
```

</div>

در یک ترمینال، می‌توانید دستور زیر را اجرا کنید:

<div dir="ltr">

```bash
huggingface-cli login
```

</div>

در هر دو حالت، از شما خواسته می‌شود نام کاربری و گذرواژه‌ی خود را وارد کنید؛ همان اطلاعاتی که برای ورود به هاب استفاده می‌کنید. اگر هنوز نمایه‌ای در هاب ندارید، می‌توانید [از اینجا](https://huggingface.co/join) یکی بسازید.

عالی است! حالا توکِن احراز هویت شما در پوشه‌ی cache ذخیره شده است. بیایید چند مخزن ایجاد کنیم!

{#if fw === 'pt'}

اگر با API `Trainer` برای تعلیم یک مدل کار کرده‌اید، ساده‌ترین راه برای بارگذاری آن در هاب این است که هنگام تعریف `TrainingArguments`، مقدار `push_to_hub=True` را تنظیم کنید:

<div dir="ltr">

```py
from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)
```

</div>

وقتی `trainer.train()` را فراخوانی می‌کنید، `Trainer` مدل شما را هر بار که ذخیره شود (در اینجا در پایان هر epoch) در یک مخزن در فضای نام شما بارگذاری می‌کند. نام آن مخزن مانند پوشه‌ی خروجی‌ای خواهد بود که انتخاب کرده‌اید (در اینجا `bert-finetuned-mrpc`)، اما می‌توانید با `hub_model_id = "a_different_name"` نام دیگری انتخاب کنید.

برای بارگذاری مدل در یک سازمان که عضو آن هستید، کافی است مقدار `hub_model_id = "my_organization/my_repo_name"` را به آن بدهید.

پس از پایان تعلیم، باید یک بار نهایی `trainer.push_to_hub()` را اجرا کنید تا آخرین نسخه‌ی مدل بارگذاری شود. این کار همچنین یک model card با تمام فراداده‌ی مرتبط ایجاد می‌کند و ابرپارامترهای استفاده‌شده و نتایج ارزیابی را گزارش می‌دهد! در ادامه نمونه‌ای از محتوایی را می‌بینید که ممکن است در چنین model cardای پیدا کنید:

<div class="flex justify-center">
  <img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/model_card.png" alt="An example of an auto-generated model card." width="100%"/>
</div>

{:else}

اگر برای تعلیم مدل خود از Keras استفاده می‌کنید، ساده‌ترین راه برای بارگذاری آن در هاب این است که هنگام فراخوانی `model.fit()`، یک `PushToHubCallback` به آن بدهید:

<div dir="ltr">

```py
from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)
```

</div>

سپس باید `callbacks=[callback]` را به فراخوانی `model.fit()` خود اضافه کنید. callback هر بار که مدل ذخیره شود (در اینجا در پایان هر epoch)، آن را در یک مخزن در فضای نام شما بارگذاری می‌کند. نام آن مخزن مانند پوشه‌ی خروجی‌ای خواهد بود که انتخاب کرده‌اید (در اینجا `bert-finetuned-mrpc`)، اما می‌توانید با `hub_model_id = "a_different_name"` نام دیگری انتخاب کنید.

برای بارگذاری مدل در یک سازمان که عضو آن هستید، کافی است مقدار `hub_model_id = "my_organization/my_repo_name"` را به آن بدهید.

{/if}

در سطحی پایین‌تر، می‌توان با استفاده از متد `push_to_hub()` مستقیماً روی مدل‌ها، توکِنایزرها و اشیای پیکربندی به هاب دسترسی داشت. این متد هم ایجاد مخزن و هم push کردن فایل‌های مدل و توکِنایزر را مستقیماً در مخزن بر عهده می‌گیرد. برخلاف APIای که در ادامه می‌بینیم، به مدیریت دستی نیازی نیست.

برای درک نحوه‌ی کار، ابتدا یک مدل و یک توکِنایزر را مقداردهی اولیه می‌کنیم:

{#if fw === 'pt'}
<div dir="ltr">

```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```

</div>
{:else}
<div dir="ltr">

```py
from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```

</div>
{/if}

با این‌ها آزاد هستید هر کاری که می‌خواهید انجام دهید — توکِن‌هایی به توکِنایزر اضافه کنید، مدل را تعلیم دهید یا آن را کوک کنید. وقتی از مدل، وزن‌ها و توکِنایزر حاصل راضی بودید، می‌توانید از متد `push_to_hub()` که مستقیماً روی شیء `model` در دسترس است استفاده کنید:

<div dir="ltr">

```py
model.push_to_hub("dummy-model")
```

</div>

این کار مخزن جدید `dummy-model` را در نمایه‌ی شما ایجاد و آن را با فایل‌های مدل پر می‌کند. همین کار را با توکِنایزر نیز انجام دهید تا همه‌ی فایل‌ها در این مخزن در دسترس باشند:

<div dir="ltr">

```py
tokenizer.push_to_hub("dummy-model")
```

</div>

اگر عضو یک سازمان هستید، کافی است برای بارگذاری در فضای نام آن سازمان، آرگومان `organization` را مشخص کنید:

<div dir="ltr">

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface")
```

</div>

اگر می‌خواهید از یک توکِن مشخص هاگینگ‌فِیس استفاده کنید، می‌توانید آن را به متد `push_to_hub()` نیز بدهید:

<div dir="ltr">

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")
```

</div>

اکنون به هاب مدل بروید تا مدل تازه‌بارگذاری‌شده‌ی خود را پیدا کنید: *https://huggingface.co/user-or-organization/dummy-model*.

روی زبانه‌ی «Files and versions» کلیک کنید؛ باید فایل‌ها را مانند تصویر زیر ببینید:

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/push_to_hub_dummy_model.png" alt="Dummy model containing both the tokenizer and model files." width="80%"/>
</div>
{:else}
<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/push_to_hub_dummy_model_tf.png" alt="Dummy model containing both the tokenizer and model files." width="80%"/>
</div>
{/if}

> [!TIP]
> ✏️ **امتحان کنید!** مدل و توکِنایزر مربوط به نقطه تعلیم `bert-base-cased` را بردارید و با استفاده از متد `push_to_hub()` آن‌ها را در مخزنی در فضای نام خود بارگذاری کنید. پیش از حذف مخزن، دوباره بررسی کنید که به‌درستی در صفحه‌ی شما ظاهر شده باشد.

همان‌طور که دیدید، متد `push_to_hub()` چندین آرگومان می‌پذیرد و به شما امکان می‌دهد در مخزن یا فضای نام سازمانی مشخصی بارگذاری کنید یا از توکِن API متفاوتی استفاده کنید. پیشنهاد می‌کنیم برای آشنایی با امکانات موجود، نگاهی به مشخصات این متد در [مستندات 🤗 Transformers](https://huggingface.co/transformers/model_sharing) بیندازید.

متد `push_to_hub()` بر پایه‌ی بسته‌ی پایتونی [`huggingface_hub`](https://github.com/huggingface/huggingface_hub) ساخته شده است که API مستقیمی برای هاب مدل‌ها و دیتاست‌ها ارائه می‌دهد. این بسته در 🤗 Transformers و چندین کتابخانه‌ی دیگر یادگیری ماشین، مانند [`allenlp`](https://github.com/allenai/allennlp)، یکپارچه شده است. اگرچه در این فصل بر یکپارچه‌سازی با 🤗 Transformers تمرکز داریم، یکپارچه‌سازی آن با کتابخانه یا کد خودتان ساده است.

برای دیدن نحوه‌ی بارگذاری فایل‌ها در مخزن تازه‌ساخته‌شده، به بخش آخر بروید!

## استفاده از کتابخانه‌ی پایتونی `huggingface_hub`[[using-the-huggingfacehub-python-library]]

کتابخانه‌ی پایتونی `huggingface_hub` بسته‌ای است که مجموعه‌ای از ابزارها را برای هاب‌های مدل و دیتاست ارائه می‌دهد. این کتابخانه روش‌ها و کلاس‌های ساده‌ای برای کارهای متداول، مانند دریافت اطلاعات مخزن‌ها در هاب و مدیریت آن‌ها، فراهم می‌کند. APIهای ساده‌ی آن بر پایه‌ی git کار می‌کنند تا محتوای مخزن‌ها و یکپارچه‌سازی هاب با پروژه‌ها و کتابخانه‌های شما را مدیریت کنند.

مشابه استفاده از API `push_to_hub`، در اینجا نیز باید توکِن API خود را در cache ذخیره کرده باشید. برای این کار باید از دستور `login` در CLI استفاده کنید؛ همان‌طور که در بخش قبل گفته شد (دوباره یادآوری می‌کنیم که اگر در Google Colab هستید، این دستورات را با نویسه‌ی `!` آغاز کنید):

<div dir="ltr">

```bash
huggingface-cli login
```

</div>

بسته‌ی `huggingface_hub` روش‌ها و کلاس‌های مفیدی برای هدف ما ارائه می‌دهد. ابتدا چند روش برای مدیریت ایجاد و حذف مخزن و کارهای دیگر داریم:

<div dir="ltr">

```python no-format
from huggingface_hub import (
    # User management
    login,
    logout,
    whoami,

    # Repository creation and management
    create_repo,
    delete_repo,
    update_repo_visibility,

    # And some methods to retrieve/change information about the content
    list_models,
    list_datasets,
    list_metrics,
    list_repo_files,
    upload_file,
    delete_file,
)
```

</div>

علاوه بر این، کلاس بسیار قدرتمند `Repository` را برای مدیریت یک مخزن محلی در اختیار داریم. در بخش بعدی، این روش‌ها و کلاس را بررسی می‌کنیم تا نحوه‌ی استفاده از آن‌ها را بهتر بفهمیم.

از متد `create_repo` می‌توان برای ایجاد یک مخزن جدید در هاب استفاده کرد:

<div dir="ltr">

```py
from huggingface_hub import create_repo

create_repo("dummy-model")
```

</div>

این کار مخزن `dummy-model` را در فضای نام شما ایجاد می‌کند. اگر بخواهید مخزن به یک سازمان تعلق داشته باشد، می‌توانید با استفاده از آرگومان `organization` مشخص کنید متعلق به کدام سازمان باشد:

<div dir="ltr">

```py
from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")
```

</div>

این کار مخزن `dummy-model` را در فضای نام `huggingface` ایجاد می‌کند، البته به شرطی که عضو آن سازمان باشید. آرگومان‌های مفید دیگر عبارت‌اند از:

<div dir="rtl">

- `private` برای مشخص کردن اینکه مخزن برای دیگران قابل مشاهده باشد یا نه.
- `token` برای جایگزین کردن توکِن ذخیره‌شده در cache با توکِنی که خودتان می‌دهید.
- `repo_type` برای ایجاد `dataset` یا `space` به‌جای یک مدل. مقادیر پذیرفته‌شده `"dataset"` و `"space"` هستند.

</div>

پس از ایجاد مخزن، باید فایل‌هایی به آن اضافه کنیم! برای دیدن سه روش انجام این کار به بخش بعدی بروید.

## استفاده از رابط وب[[using-the-web-interface]]

رابط وب ابزارهایی برای مدیریت مستقیم مخزن‌ها در هاب ارائه می‌دهد. با استفاده از این رابط، می‌توانید به‌سادگی مخزن بسازید، فایل‌ها (حتی فایل‌های بزرگ!) را اضافه کنید، مدل‌ها را بررسی کنید، تفاوت‌ها را ببینید و کارهای بسیار بیشتری انجام دهید.

برای ایجاد یک مخزن جدید، به [huggingface.co/new](https://huggingface.co/new) بروید:

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/new_model.png" alt="Page showcasing the model used for the creation of a new model repository." width="80%"/>
</div>

ابتدا مالک مخزن را مشخص کنید: این مالک می‌تواند خود شما یا هر سازمانی باشد که به آن وابسته‌اید. اگر یک سازمان را انتخاب کنید، مدل در صفحه‌ی سازمان نمایش داده می‌شود و همه‌ی اعضای آن سازمان امکان مشارکت در مخزن را خواهند داشت.

سپس نام مدل خود را وارد کنید. این نام، نام مخزن نیز خواهد بود. در نهایت می‌توانید مشخص کنید مدل عمومی یا خصوصی باشد. مدل‌های خصوصی از دید عموم پنهان هستند.

پس از ایجاد مخزن مدل، باید صفحه‌ای مانند صفحه‌ی زیر ببینید:

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/empty_model.png" alt="An empty model page after creating a new repository." width="80%"/>
</div>

در اینجا مدل شما میزبانی خواهد شد. برای شروع پر کردن مخزن، می‌توانید یک فایل README را مستقیماً از رابط وب اضافه کنید.

<div class="flex justify-center">
<img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/dummy_model.png" alt="The README file showing the Markdown capabilities." width="80%"/>
</div>

فایل README با Markdown نوشته می‌شود — پس با خیال راحت هر طور می‌خواهید آن را بسازید! بخش سوم این فصل به ساختن model card اختصاص دارد. این کارت‌ها برای ارزشمند کردن مدل شما اهمیت زیادی دارند، چون در آن‌ها به دیگران می‌گویید مدل شما چه کاری می‌تواند انجام دهد.

## بارگذاری فایل‌های مدل[[uploading-the-model-files]]

سامانه‌ی مدیریت فایل‌ها در هاب هاگینگ‌فِیس برای فایل‌های معمولی بر git و برای فایل‌های بزرگ‌تر بر git-lfs (که مخفف [Git Large File Storage](https://git-lfs.github.com/) است) تکیه دارد.

در بخش بعدی، سه روش متفاوت بارگذاری فایل‌ها در هاب را بررسی می‌کنیم: از طریق `huggingface_hub` و از طریق دستورات git.

### روش `upload_file`[[the-uploadfile-approach]]

برای استفاده از `upload_file` لازم نیست git و git-lfs روی سیستم شما نصب باشند. این روش فایل‌ها را با درخواست‌های HTTP POST مستقیماً به 🤗 هاب push می‌کند. محدودیت آن این است که فایل‌های بزرگ‌تر از ۵GB را مدیریت نمی‌کند. اگر فایل‌های شما بزرگ‌تر از ۵GB هستند، از دو روش دیگری که در ادامه توضیح داده می‌شوند استفاده کنید.

API را می‌توان به شکل زیر به کار برد:

<div dir="ltr">

```py
from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)
```

</div>

این کار فایل `config.json` موجود در `<path_to_file>` را با نام `config.json` در ریشه‌ی مخزن `dummy-model` بارگذاری می‌کند. آرگومان‌های مفید دیگر عبارت‌اند از:

<div dir="rtl">

- `token` برای جایگزین کردن توکِن ذخیره‌شده در cache با توکِنی که خودتان می‌دهید.
- `repo_type` برای بارگذاری در یک `dataset` یا `space` به‌جای مدل. مقادیر پذیرفته‌شده `"dataset"` و `"space"` هستند.

</div>

### کلاس `Repository`[[the-repository-class]]

کلاس `Repository` یک مخزن محلی را به روشی شبیه git مدیریت می‌کند. این کلاس بسیاری از دشواری‌های کار با git را انتزاع می‌کند تا همه‌ی قابلیت‌های موردنیاز ما را فراهم کند.

برای استفاده از این کلاس باید git و git-lfs نصب باشند؛ بنابراین پیش از شروع مطمئن شوید git-lfs را نصب کرده و راه‌اندازی کرده‌اید (دستورالعمل نصب را [اینجا](https://git-lfs.github.com/) ببینید).

برای شروع کار با مخزنی که همین حالا ایجاد کرده‌ایم، آن را با clone کردن مخزن راه دور در یک پوشه‌ی محلی مقداردهی اولیه می‌کنیم:

<div dir="ltr">

```py
from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")
```

</div>

این کار پوشه‌ی `<path_to_dummy_folder>` را در شاخه‌ی کاری ما ایجاد می‌کند. این پوشه فقط فایل `.gitattributes` را دارد، چون هنگام ایجاد مخزن با `create_repo` تنها همین فایل ایجاد می‌شود.

از اینجا به بعد، می‌توانیم از چند متد سنتی git استفاده کنیم:

<div dir="ltr">

```py
repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()
```

</div>

و متدهای دیگر! برای آشنایی با همه‌ی آن‌ها، پیشنهاد می‌کنیم مستندات `Repository` را [اینجا](https://github.com/huggingface/huggingface_hub/tree/main/src/huggingface_hub#advanced-programmatic-repository-management) ببینید.

در حال حاضر یک مدل و یک توکِنایزر داریم که می‌خواهیم آن‌ها را به هاب push کنیم. مخزن را با موفقیت clone کرده‌ایم، بنابراین اکنون می‌توانیم فایل‌ها را در آن مخزن ذخیره کنیم.

ابتدا مطمئن می‌شویم clone محلی ما با pull کردن آخرین تغییرات به‌روز است:

<div dir="ltr">

```py
repo.git_pull()
```

</div>

حالا فایل‌های مدل و توکِنایزر را ذخیره می‌کنیم:

<div dir="ltr">

```py
model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

</div>

پوشه‌ی `<path_to_dummy_folder>` اکنون همه‌ی فایل‌های مدل و توکِنایزر را دارد. با پیروی از روند معمول git، فایل‌ها را به ناحیه‌ی stage اضافه می‌کنیم، commit می‌کنیم و به هاب push می‌کنیم:

<div dir="ltr">

```py
repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()
```

</div>

تبریک می‌گوییم! شما همین حالا نخستین فایل‌های خود را به هاب push کردید.

### روش مبتنی بر git[[the-git-based-approach]]

این روش بسیار پایه‌ایِ بارگذاری فایل‌هاست: مستقیماً از git و git-lfs استفاده می‌کنیم. بیشتر دشواری‌ها در روش‌های قبلی انتزاع شده‌اند، اما روش زیر چند نکته‌ی مهم دارد؛ بنابراین یک مورد کاربردی پیچیده‌تر را دنبال می‌کنیم.

برای استفاده از این کلاس باید git و git-lfs نصب باشند؛ بنابراین پیش از شروع مطمئن شوید [git-lfs](https://git-lfs.github.com/) را نصب و راه‌اندازی کرده‌اید.

ابتدا git-lfs را مقداردهی اولیه کنید:

<div dir="ltr">

```bash
git lfs install
```

```bash
Updated git hooks.
Git LFS initialized.
```

</div>

پس از آن، نخستین گام clone کردن مخزن مدل است:

<div dir="ltr">

```bash
git clone https://huggingface.co/<namespace>/<your-model-id>
```

</div>

نام کاربری من `lysandre` است و از نام مدل `dummy` استفاده کرده‌ام، بنابراین دستور من به شکل زیر خواهد بود:

<div dir="ltr">

```
git clone https://huggingface.co/lysandre/dummy
```

</div>

اکنون پوشه‌ای با نام *dummy* در شاخه‌ی کاری خود دارم. می‌توانم با `cd` وارد پوشه شوم و محتوای آن را ببینم:

<div dir="ltr">

```bash
cd dummy && ls
```

```bash
README.md
```

</div>

اگر مخزن را با روش `create_repo` از هاب هاگینگ‌فِیس ایجاد کرده باشید، این پوشه فقط فایل مخفی `.gitattributes` را خواهد داشت. اگر در بخش قبل با استفاده از رابط وب مخزن را ایجاد کرده باشید، همان‌طور که در تصویر زیر می‌بینید، پوشه باید یک فایل *README.md* در کنار فایل مخفی *.gitattributes* داشته باشد.

افزودن فایل‌های معمولی، مانند فایل پیکربندی، فایل واژگان یا تقریباً هر فایل کوچک‌تر از چند مگابایت، دقیقاً مانند هر سامانه‌ی مبتنی بر git انجام می‌شود. بااین‌حال، برای push کردن فایل‌های بزرگ‌تر به *huggingface.co*، باید آن‌ها را از طریق git-lfs ثبت کنید.

بیایید برای مدتی به پایتون برگردیم و مدل و توکِنایزری تولید کنیم که می‌خواهیم در مخزن ساختگی خود commit کنیم:

```py
checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)

model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```
