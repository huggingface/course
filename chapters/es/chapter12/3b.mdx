Profundicemos en nuestra comprensión de GRPO para que podamos mejorar el proceso de entrenamiento de nuestro modelo.

GRPO evalúa directamente las respuestas generadas por el modelo comparándolas dentro de grupos de generación para optimizar el modelo de política, en lugar de entrenar un modelo de valor independiente (Crítico / *Critic*). ¡Este enfoque conduce a una reducción significativa en el costo computacional!

GRPO se puede aplicar a cualquier tarea verificable donde se pueda determinar la corrección de la respuesta. Por ejemplo, en el razonamiento matemático, la corrección de la respuesta se puede verificar fácilmente comparándola con el valor real (*ground truth*).

Ahora que tenemos una descripción visual, desglosemos cómo funciona GRPO paso a paso.

## El algoritmo GRPO

La innovación central de GRPO es su enfoque para evaluar y aprender de múltiples respuestas generadas simultáneamente. En lugar de depender de un modelo de recompensa independiente, compara las respuestas dentro del mismo grupo para determinar cuáles deben reforzarse.

Repasemos cada paso del algoritmo en detalle:

### Paso 1: Muestreo de grupos (*Group Sampling*)

El primer paso es generar múltiples respuestas posibles para cada pregunta. Esto crea un conjunto diverso de salidas que se pueden comparar entre sí.

Para cada pregunta \\( q \\), el modelo generará \\( G \\) salidas (tamaño del grupo) a partir de la política entrenada: { \\( {o_1, o_2, o_3, \dots, o_G}\sim\pi_{\theta_{\text{old}}} \\) }, \\( G=8 \\) donde cada \\( o_i \\) representa una terminación del modelo.

#### Ejemplo

Para concretar esto, veamos un problema aritmético simple:

**Pregunta** 

\\( q \\) : \\( \text{Calcular}\space2 + 2 \times 6 \\)

**Salidas** 

\\( (G = 8) \\): \\( \{o_1:14 \text{ (correcta)}, o_2:16 \text{ (incorrecta)}, o_3:10 \text{ (incorrecta)}, \ldots, o_8:14 \text{ (correcta)}\} \\)

Observa cómo algunas de las respuestas generadas son correctas (14) mientras que otras son incorrectas (16 o 10). Esta diversidad es crucial para el siguiente paso.

### Paso 2: Cálculo de la ventaja (*Advantage Calculation*)

Una vez que tenemos múltiples respuestas, necesitamos una forma de determinar cuáles son mejores que otras. Aquí es donde entra el cálculo de la ventaja (*advantage*).

#### Distribución de recompensas

Primero, asignamos una puntuación de recompensa a cada respuesta generada. En este ejemplo, usaremos un modelo de recompensa, pero como aprendimos en la sección anterior, podemos usar cualquier función que devuelva recompensas.

Asignamos una puntuación RM a cada una de las respuestas generadas en función de la corrección \\( r_i \\) *(por ejemplo, 1 para respuesta correcta, 0 para respuesta incorrecta)* y luego, para cada \\( r_i \\), calculamos el siguiente valor de ventaja (*Advantage*).

#### Fórmula del valor de ventaja

La idea clave de GRPO es que no necesitamos medidas absolutas de calidad: podemos comparar las salidas dentro del mismo grupo. Esto se hace mediante estandarización:

$$A_i = \frac{r_i - \text{media}(\{r_1, r_2, \ldots, r_G\})}{\text{desv\_est}(\{r_1, r_2, \ldots, r_G\})}$$

#### Ejemplo

Continuando con nuestro ejemplo aritmético anterior, imagina que tenemos 8 respuestas, 4 de las cuales son correctas y el resto incorrectas, por lo tanto:

| Métrica | Valor |
|---------|-------|
| Promedio del grupo | \\( mean(r_i) = 0.5 \\) |
| Desviación estándar | \\( std(r_i) = 0.53 \\) |
| Valor de ventaja (Respuesta correcta) | \\( A_i = \frac{1 - 0.5}{0.53}= 0.94 \\) |
| Valor de ventaja (Respuesta incorrecta) | \\( A_i = \frac{0 - 0.5}{0.53}= -0.94 \\) |

#### Interpretación

Ahora que hemos calculado los valores de ventaja, comprendamos qué significan:

Esta estandarización (es decir, la ponderación \\( A_i \\)) permite al modelo evaluar el rendimiento relativo de cada respuesta, guiando el proceso de optimización hacia respuestas favorables que son mejores que el promedio (alta recompensa) y desalentando aquellas que son peores. Por ejemplo, si \\( A_i > 0 \\), entonces \\( o_i \\) es una respuesta mejor que el nivel promedio dentro de su grupo; y si \\( A_i < 0 \\), entonces la calidad de la respuesta es inferior al promedio (es decir, calidad/rendimiento deficiente).

Para el ejemplo anterior, si \\( A_i = 0.94 \text{ (salida correcta)} \\), entonces durante los pasos de optimización se incrementará su probabilidad de generación.

Con nuestros valores de ventaja calculados, ya estamos listos para actualizar la política.

### Paso 3: Actualización de la política (*Policy Update*)

El paso final es usar estos valores de ventaja para actualizar nuestro modelo de modo que sea más probable que genere buenas respuestas en el futuro.

La función objetivo para la actualización de la política es:

$$J_{GRPO}(\theta) = \left[\frac{1}{G} \sum_{i=1}^{G} \min \left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} A_i, \text{clip}\left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}, 1 - \epsilon, 1 + \epsilon \right) A_i \right)\right]- \beta D_{KL}(\pi_{\theta} \| \pi_{ref})$$

Esta fórmula puede parecer intimidante al principio, pero está construida a partir de varios componentes que cumplen un propósito importante. Desglosémoslos uno por uno.

## Componentes clave de la función objetivo

La función de actualización de GRPO combina varias técnicas para garantizar un aprendizaje estable y eficaz. Examinemos cada componente:

### 1. Razón de probabilidad (*Probability Ratio*)

La razón de probabilidad se define como:

\\( \left(\frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}\right) \\) 

Intuitivamente, la fórmula compara cuánto difiere la probabilidad de respuesta del nuevo modelo de la probabilidad de respuesta del modelo anterior, incorporando al mismo tiempo una preferencia por las respuestas que mejoran el resultado esperado.

#### Interpretación

- Si \\( \text{razón} > 1 \\), el nuevo modelo asigna una mayor probabilidad a la respuesta \\( o_i \\) que el modelo anterior.
- Si \\( \text{razón} < 1 \\), el nuevo modelo asigna una menor probabilidad a \\( o_i \\) 

Esta razón nos permite controlar cuánto cambia el modelo en cada paso, lo que nos lleva al siguiente componente.

### 2. Función de recorte (*Clip Function*)

La función de recorte se define como:

\\( \text{clip}\left( \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}, 1 - \epsilon, 1 + \epsilon\right) \\) 

Limita la razón discutida anteriormente para que esté dentro de \\( [1 - \epsilon, 1 + \epsilon] \\) con el fin de evitar o controlar cambios drásticos o actualizaciones excesivas y alejarse demasiado de la política anterior. En otras palabras, limita cuánto puede aumentar la razón de probabilidad para ayudar a mantener la estabilidad al evitar actualizaciones que empujen al nuevo modelo demasiado lejos del anterior.

#### Ejemplo (ε = 0.2)

Veamos dos escenarios diferentes para comprender mejor esta función de recorte:

- **Caso 1**: si la nueva política tiene una probabilidad de 0.9 para una respuesta específica y la política anterior tiene una probabilidad de 0.5, significa que esta respuesta está siendo reforzada por la nueva política para tener una mayor probabilidad, pero dentro de un límite controlado que es el recorte para moderar su magnitud.
	- \\( \text{Razón}: \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} = \frac{0.9}{0.5} = 1.8  → \text{Recorte a}\space1.2 \\) (límite superior 1.2) 
- **Caso 2**: Si la nueva política no está a favor de una respuesta (menor probabilidad, por ejemplo, 0.2), lo que significa que si la respuesta no es beneficiosa el aumento podría ser incorrecto, y el modelo sería penalizado.
	- \\( \text{Razón}: \frac{\pi_{\theta}(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} = \frac{0.2}{0.5} = 0.4  → \text{Recorte a}\space0.8 \\) (límite inferior 0.8)

#### Interpretación

- La fórmula anima al nuevo modelo a favorecer respuestas que el modelo anterior subestimaba **si mejoran el resultado**.
- Si el modelo anterior ya favorecía una respuesta con alta probabilidad, el nuevo modelo aún puede reforzarla **pero solo dentro de un límite controlado \\( [1 - \epsilon, 1 + \epsilon] \\), \\( \text{(por ejemplo, }\epsilon = 0.2, \space \text{es decir, } \space [0.8-1.2]) \\)**.
- Si el modelo anterior sobrestimó una respuesta que rinde mal, se **desalienta** al nuevo modelo de mantener esa alta probabilidad.
- Por lo tanto, intuitivamente, al incorporar la razón de probabilidad, la función objetivo asegura que las actualizaciones a la política sean proporcionales a la ventaja \\( A_i \\) al tiempo que se moderan para evitar cambios drásticos.

Si bien la función de recorte ayuda a prevenir cambios drásticos, necesitamos una salvaguarda más para garantizar que nuestro modelo no se desvíe demasiado de su comportamiento original.

### 3. Divergencia KL (*KL Divergence*)

El término de divergencia KL es:

\\( \beta D_{KL}(\pi_{\theta} \| \pi_{ref}) \\)

En el término de divergencia KL, \\( \pi_{ref} \\) es básicamente la salida del modelo previa a la actualización, `per_token_logps`, y \\( \pi_{\theta} \\) es la salida del nuevo modelo, `new_per_token_logps`. Teóricamente, la divergencia KL se minimiza para evitar que el modelo se desvíe demasiado de su comportamiento original durante la optimización. Esto ayuda a lograr un equilibrio entre mejorar el rendimiento en función de la señal de recompensa y mantener la coherencia. En este contexto, minimizar la divergencia KL reduce el riesgo de que el modelo genere texto sin sentido o, en el caso del razonamiento matemático, produzca respuestas extremadamente incorrectas.

#### Interpretación

- Una penalización por divergencia KL mantiene las salidas del modelo cerca de su distribución original, evitando cambios extremos.
- En lugar de derivar hacia salidas completamente irracionales, el modelo refina su comprensión permitiendo cierta exploración.

#### Definición matemática

Para aquellos interesados en los detalles matemáticos, veamos la definición formal:

Recordemos que la distancia KL se define de la siguiente manera:
$$D_{KL}(P \| Q) = \sum_{x \in X} P(x) \log \frac{P(x)}{Q(x)}$$
En RLHF, las dos distribuciones de interés son a menudo la distribución de la nueva versión del modelo, P(x), y la distribución de la política de referencia, Q(x).

#### El papel del parámetro β

El coeficiente \\( \beta \\) controla con qué fuerza aplicamos la restricción de divergencia KL:

- **Mayor β (Penalización KL más fuerte)**
    - Mayor restricción en las actualizaciones de la política. El modelo se mantiene cercano a su distribución de referencia.
    - Puede ralentizar la adaptación: El modelo puede tener dificultades para explorar mejores respuestas.
- **Menor β (Penalización KL más débil)**
    - Mayor libertad para actualizar la política: El modelo puede desviarse más de la referencia.
    - Adaptación más rápida pero riesgo de inestabilidad: El modelo podría aprender comportamientos de piratería de recompensas (*reward-hacking*).
	- Riesgo de sobreoptimización: Si el modelo de recompensa es defectuoso, la política podría generar salidas sin sentido.
- El artículo original de [DeepSeekMath](https://arxiv.org/abs/2402.03300) estableció \\( \beta = 0.04 \\).

## Ejemplo resuelto con GRPO

Para consolidar nuestra comprensión de GRPO, repasemos un ejemplo completo de principio a fin.

### Problema de ejemplo

$$\text{P: Calcular}\space2 + 2 \times 6$$

### Paso 1: Muestreo de grupos

Primero, generamos múltiples respuestas a partir de nuestro modelo.

Generamos \\( (G = 8) \\) respuestas, \\( 4 \\) de las cuales son la respuesta correcta (\\( 14, \text{recompensa=} 1 \\)) y \\( 4 \\) incorrectas \\( \text{(recompensa= 0)} \\). Por lo tanto:

$${o_1:14 \text{ (correcta)}, o_2:10 \text{ (incorrecta)}, o_3:16 \text{ (incorrecta)}, \dots, o_G:14 \text{ (correcta)}}$$

### Paso 2: Cálculo de la ventaja

A continuación, calculamos los valores de ventaja para determinar qué respuestas son mejores que el promedio:

| Estadística | Valor |
|-------------|-------|
| Promedio del grupo | \\( mean(r_i) = 0.5 \\) |
| Desviación estándar | \\( std(r_i) = 0.53 \\) |
| Valor de ventaja (Respuesta correcta) | \\( A_i = \frac{1 - 0.5}{0.53}= 0.94 \\) |
| Valor de ventaja (Respuesta incorrecta) | \\( A_i = \frac{0 - 0.5}{0.53}= -0.94 \\) |

### Paso 3: Actualización de la política

Finalmente, actualizamos nuestro modelo para reforzar las respuestas correctas:

- Suponiendo que la probabilidad de la política anterior (\\( \pi_{\theta_{old}} \\)) para una salida correcta \\( o_1 \\) sea \\( 0.5 \\) y la nueva política la aumente a \\( 0.7 \\), entonces:
$$\text{Razón}: \frac{0.7}{0.5} = 1.4  → \text{tras Recorte}\space1.2 \space (\epsilon = 0.2)$$
- Luego, cuando se repondera la función objetivo, el modelo tiende a reforzar la generación de la salida correcta, y la \\( \text{Divergencia KL} \\) limita la desviación de la política de referencia.

## Ejemplo de implementación

Unamos todo en un ejemplo práctico. El siguiente código demuestra cómo implementar GRPO en PyTorch:

### 1. Cargar el modelo y generar respuestas

Primero, debemos cargar un modelo y generar múltiples respuestas para una pregunta determinada:

```python
import torch
import torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer

# Cargar el modelo y tokenizador
model_name = "Qwen/Qwen2-Math-1.5B"
model = AutoModelForCausalLM.from_pretrained(model_name)
tokenizer = AutoTokenizer.from_pretrained(model_name)
model.eval()

# Mover el modelo a GPU si está disponible
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model.to(device)

# Prompt de entrada
prompt = "Solve y = 2x + 1 for x = 2, y = "  # Respuesta correcta: 5
inputs = tokenizer(prompt, return_tensors="pt", padding=True)
input_ids = inputs["input_ids"].to(device)  # Forma: (1, prompt_len)
attention_mask = inputs["attention_mask"].to(device)

# Paso 1: Generar 8 respuestas (B = 2 grupos, G = 4 respuestas por grupo)
batch_size, num_generations = 2, 4
outputs = model.generate(
    input_ids=input_ids,  # Forma: (1, prompt_len)
    attention_mask=attention_mask,
    max_new_tokens=1,  # seq_len = 1 (un solo token por respuesta)
    num_return_sequences=batch_size * num_generations,  # 8 respuestas en total
    do_sample=True,
    top_k=10,
    temperature=0.7,
    pad_token_id=tokenizer.eos_token_id,
    return_dict_in_generate=True,
    output_scores=True,
)
```

Esta generación inicial (antes de cualquier paso) producirá algo como esto:

```text
Output 1: 5.0
Output 2: 6.0
Output 3: 7.0
Output 4: 5.0
Output 5: 10.0
Output 6: 2.0
Output 7: 5.0
Output 8: 5.0
```

### 2. Calcular recompensas

Ahora debemos determinar qué respuestas son correctas y asignar recompensas en consecuencia:

Con GRPO, a partir del mismo prompt de muestra generamos múltiples terminaciones. Así, por ejemplo, para nuestros prompts `"Solve y = 2x + 1 for x = 2, y = "` y `"Solve y = 2x + 1 for x = 4, y = "` tenemos dos grupos de salidas generadas para el prompt dado: uno es, por ejemplo:
- `[5, 6, 7, 5]` y el otro es 
- `[10, 2, 9, 9]`, mientras que las respuestas correctas son 5 y 9.

Ten en cuenta que, en la práctica, estas puntuaciones de recompensa se obtienen mediante una función de recompensa basada en reglas que asigna recompensas según la corrección de la respuesta, o un modelo más complejo basado en redes neuronales entrenado para asignar recompensas según la corrección de la respuesta, o una combinación de ambos. Pero por simplicidad digamos que nuestra recompensa por respuesta es 1 si la respuesta es correcta y 0 si es incorrecta; por lo tanto:

```python
reward_1 = [1, 0, 0, 1]
reward_2 = [0, 0, 1, 1]
```

A continuación obtenemos la media y desviación estándar de las recompensas por grupo:

```python
# Forma: (B * G,) = (8,) porque tenemos 2 grupos de 4 generaciones que aplanamos
rewards = torch.tensor([1, 0, 0, 1, 0, 0, 1, 1], dtype=torch.float32)
num_generations = 4

# Recompensas agrupadas: Forma (B, G) = (2, 4)
rewards_grouped = rewards.view(-1, num_generations)

# Media por grupo: Forma (B,) = (2,)
mean_grouped_rewards = rewards_grouped.mean(dim=1)

# Desv. est. por grupo: Forma (B,) = (2,)
std_grouped_rewards = rewards_grouped.std(dim=1)

# Difundir (broadcast) para coincidir con rewards y normalizar: Forma (B * G,) = (8,)
# ¿Por qué necesitamos difundir? Porque necesitamos calcular los valores de ventaja para cada respuesta dentro del grupo
mean_grouped_rewards = mean_grouped_rewards.repeat_interleave(num_generations, dim=0)
std_grouped_rewards = std_grouped_rewards.repeat_interleave(num_generations, dim=0)
```

Esto generará:

```text
Grouped Rewards: tensor([[1., 0., 0., 1.],
                        [0., 0., 1., 1.]])
Mean per group: tensor([0.5000, 0.5000])
Std per group: tensor([0.5774, 0.5774])
Broadcasted Mean: tensor([0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000, 0.5000])
Broadcasted Std: tensor([0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774, 0.5774])
```

Ahora podemos calcular los valores de ventaja para cada respuesta:

```python
# Ventajas: Forma (B * G,) = (8,)
advantages = (rewards - mean_grouped_rewards) / (std_grouped_rewards + 1e-8)
```

Esto generará:

```text
Advantages: tensor([ 0.8659, -0.8660, -0.8660,  0.8659, -0.8660, -0.8660,  0.8659,  0.8659])
```

Lo cual proviene de la fórmula de ventaja anterior:

```text
Para reward_1 = [1, 0, 0, 1]:
1 - 0.5 / 0.5774 ≈ 0.8659
0 - 0.5 / 0.5774 ≈ -0.8660
Para reward_2 = [0, 0, 1, 1]: Mismo patrón.
```

Sin embargo, la forma aquí es `(B*G,) = (8,)`, pero en la práctica necesitamos tener la forma `(B, G) = (2, 4)` para coincidir con la forma de los logits, ¿verdad? Por lo tanto, necesitamos expandir dimensiones (`unsqueeze`) en el tensor de ventajas para tener la forma `(B*G, 1) = (8, 1)` y coincidir con la forma de los logits.

```python
# Forma (B * G, 1) = (8, 1) para coincidir con la forma de logits
advantages = advantages.unsqueeze(1)
```

Lo que producirá:

```text
Advantages: tensor([[ 0.8659],
                    [-0.8660],
                    [-0.8660],
                    [ 0.8659],
                    [-0.8660],
                    [-0.8660],
                    [ 0.8659],
                    [ 0.8659]])
```

Ahora que todo está listo, pasemos al siguiente paso: actualizar el modelo de política en función de los valores de ventaja.

### 3. Actualizar la política
Por último, usamos los valores de ventaja para actualizar nuestro modelo:

```python
# Calcular razón de probabilidad entre la política nueva y la antigua
ratio = torch.exp(
    new_per_token_logps - per_token_logps
)  # Forma: (B*G, seq_len) donde seq_len es la longitud de la salida, es decir, el número de tokens generados, por lo que aquí por simplicidad supongamos que es 1 # (8, 1)
```

Ten en cuenta que `per_token_logps` se puede obtener pasando las salidas generadas al modelo para obtener los logits y luego aplicando la función softmax para obtener las probabilidades `F.softmax(logits, dim=-1)`.

```python
# Función de recorte
eps = self.cliprange  # ej. 0.2
pg_losses1 = -advantages * ratio  # Forma: (B*G, seq_len)  #(8, 1)
pg_losses2 = -advantages * torch.clamp(
    ratio, 1.0 - eps, 1.0 + eps
)  # Forma: (B*G, seq_len) #(8, 1)
pg_loss_max = torch.max(pg_losses1, pg_losses2)  # Forma: (B*G, seq_len) #(8, 1)


# Ahora combinar con penalización KL # Forma: (B*G, seq_len) #(8, 1)
per_token_loss = pg_loss_max + self.beta * per_token_kl
```

`per_token_kl` también se puede calcular de la siguiente manera:

```python
# Forma: (B*G, seq_len) #(8, 1)
per_token_kl = F.kl_div(
    F.log_softmax(new_per_token_logps, dim=-1),
    F.softmax(per_token_logps, dim=-1),
    reduction="none",
).sum(dim=-1, keepdim=True)
```

## Resumen y próximos pasos

¡Felicitaciones! Has aprendido sobre Group Relative Policy Optimization (GRPO). Para recapitular lo que hemos cubierto:

1. GRPO compara múltiples salidas dentro de un grupo para determinar cuáles son mejores que otras, sin requerir un modelo de valor independiente.
2. El cálculo de la ventaja estandariza las recompensas para identificar qué respuestas están por encima o por debajo del promedio.
3. La actualización de la política utiliza una función objetivo recortada con una penalización por divergencia KL para garantizar un aprendizaje estable.

Este enfoque es particularmente poderoso para tareas de razonamiento matemático, donde la corrección se puede verificar objetivamente. El método GRPO permite un entrenamiento más eficiente en comparación con los enfoques tradicionales de RLHF que requieren un modelo de crítico independiente.

A medida que continúes explorando GRPO, considera experimentar con diferentes tamaños de grupo, funciones de recompensa y coeficientes de penalización KL para ver cómo afectan el rendimiento de tu modelo.
