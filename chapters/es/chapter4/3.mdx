En los pasos a continuación, veremos las formas más fáciles de compartir modelos preentrenados en el Hub de 🤗. Hay herramientas y utilidades disponibles que simplifican el proceso de compartir y actualizar modelos directamente en el Hub, las cuales exploraremos a continuación.

<Youtube id="9yY3RB_GSPM"/>

Animamos a todos los usuarios que entrenan modelos a contribuir compartiéndolos con la comunidad: compartir modelos, incluso cuando se entrenan en conjuntos de datos muy específicos, ayudará a otros ahorrándoles tiempo y recursos de cómputo y brindándoles acceso a artefactos entrenados útiles. ¡A cambio, tú puedes beneficiarte del trabajo que otros han realizado!

Hay tres formas de crear nuevos repositorios de modelos:

- Usando la API `push_to_hub`
- Usando la biblioteca de Python `huggingface_hub`
- Usando la interfaz web

Una vez que hayas creado un repositorio, puedes subirle archivos a través de git y git-lfs. Te guiaremos a través de la creación de repositorios de modelos y la subida de archivos en las siguientes secciones.


## Usando la API `push_to_hub`[[using-the-pushtohub-api]]

{:else}

<Youtube id="pUh5cGmNV8Y"/>

La forma más sencilla de subir archivos al Hub es aprovechando la API `push_to_hub`.

Antes de continuar, deberás generar un token de autenticación para que la API `huggingface_hub` sepa quién eres y a qué espacios de nombres tienes acceso de escritura. Asegúrate de estar en un entorno donde tengas instalado `transformers` (consulta la sección de [Instalación](/course/chapter0)). Si estás en un notebook, puedes usar la siguiente función para iniciar sesión:

```python
from huggingface_hub import notebook_login

notebook_login()
```

En una terminal, puedes ejecutar:

```bash
huggingface-cli login
```

En ambos casos, se te solicitará tu nombre de usuario y contraseña, que son los mismos que utilizas para iniciar sesión en el Hub. Si aún no tienes un perfil en el Hub, deberías crear uno [aquí](https://huggingface.co/join).

¡Genial! Ahora tienes tu token de autenticación almacenado en tu carpeta de caché. ¡Creemos algunos repositorios!

{#if fw === 'pt'}

Si has experimentado con la API `Trainer` para entrenar un modelo, la forma más fácil de subirlo al Hub es configurar `push_to_hub=True` cuando defines tus `TrainingArguments`:

```py
from transformers import TrainingArguments

training_args = TrainingArguments(
    "bert-finetuned-mrpc", save_strategy="epoch", push_to_hub=True
)
```

Cuando llamas a `trainer.train()`, el `Trainer` subirá tu modelo al Hub cada vez que se guarde (aquí en cada época) en un repositorio dentro de tu espacio de nombres. Ese repositorio se nombrará como el directorio de salida que elegiste (aquí `bert-finetuned-mrpc`), pero puedes elegir un nombre diferente con `hub_model_id = "un_nombre_diferente"`.

Para subir tu modelo a una organización de la que eres miembro, simplemente indícalo con `hub_model_id = "mi_organizacion/nombre_de_mi_repo"`.

Una vez que termine tu entrenamiento, debes hacer un `trainer.push_to_hub()` final para subir la última versión de tu modelo. ¡Esto también generará una ficha de modelo con todos los metadatos relevantes, indicando los hiperparámetros utilizados y los resultados de evaluación! Aquí hay un ejemplo del contenido que podrías encontrar en dicha ficha de modelo:

<div class="flex justify-center">
  <img src="https://huggingface.co/datasets/huggingface-course/documentation-images/resolve/main/en/chapter4/model_card.png" alt="Un ejemplo de una ficha de modelo generada automáticamente." width="100%"/>
</div>

{:else}

Si estás utilizando Keras para entrenar tu modelo, la forma más fácil de subirlo al Hub es pasar un `PushToHubCallback` cuando llamas a `model.fit()`:

```py
from transformers import PushToHubCallback

callback = PushToHubCallback(
    "bert-finetuned-mrpc", save_strategy="epoch", tokenizer=tokenizer
)
```

Luego debes agregar `callbacks=[callback]` en tu llamada a `model.fit()`. El callback subirá tu modelo al Hub cada vez que se guarde (aquí en cada época) en un repositorio dentro de tu espacio de nombres. Ese repositorio se nombrará como el directorio de salida que elegiste (aquí `bert-finetuned-mrpc`), pero puedes elegir un nombre diferente con `hub_model_id = "un_nombre_diferente"`.

Para subir tu modelo a una organización de la que eres miembro, simplemente indícalo con `hub_model_id = "mi_organizacion/nombre_de_mi_repo"`.

{/if}

A un nivel más bajo, el acceso al Model Hub se puede realizar directamente en modelos, tokenizadores y objetos de configuración a través de su método `push_to_hub()`. Este método se encarga tanto de la creación del repositorio como de subir los archivos del modelo y del tokenizador directamente al repositorio. No se requiere manipulación manual, a diferencia de la API que veremos a continuación.

Para tener una idea de cómo funciona, primero inicialicemos un modelo y un tokenizador:

{#if fw === 'pt'}
```py
from transformers import AutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = AutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{:else}
```py
from transformers import TFAutoModelForMaskedLM, AutoTokenizer

checkpoint = "camembert-base"

model = TFAutoModelForMaskedLM.from_pretrained(checkpoint)
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
```
{/if}

Eres libre de hacer lo que quieras con ellos: agregar tokens al tokenizador, entrenar el modelo, ajustarlo. Una vez que estés satisfecho con el modelo resultante, los pesos y el tokenizador, puedes aprovechar el método `push_to_hub()` disponible directamente en el objeto `model`:

```py
model.push_to_hub("dummy-model")
```

Esto creará el nuevo repositorio `dummy-model` en tu perfil y lo poblará con los archivos de tu modelo.
Haz lo mismo con el tokenizador, para que todos los archivos estén ahora disponibles en este repositorio:

```py
tokenizer.push_to_hub("dummy-model")
```

Si perteneces a una organización, simplemente especifica el argumento `organization` para subirlo al espacio de nombres de esa organización:

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface")
```

Si deseas utilizar un token de Hugging Face específico, también puedes indicarlo en el método `push_to_hub()`:

```py
tokenizer.push_to_hub("dummy-model", organization="huggingface", use_auth_token="<TOKEN>")
```

Ahora dirígete al Model Hub para encontrar tu modelo recién subido: *https://huggingface.co/user-or-organization/dummy-model*.

Haz clic en la pestaña "Files and versions", y deberías ver los archivos visibles en la siguiente captura de pantalla:

Te recomendamos echar un vistazo a la especificación del método disponible directamente en la [documentación de 🤗 Transformers](https://huggingface.co/transformers/model_sharing) para darte una idea de lo que es posible.

El método `push_to_hub()` está respaldado por el paquete de Python [`huggingface_hub`](https://github.com/huggingface/huggingface_hub), que ofrece una API directa al Hub de Hugging Face. Está integrado dentro de 🤗 Transformers y en varias otras bibliotecas de aprendizaje automático, como [`allenlp`](https://github.com/allenai/allennlp). Aunque en este capítulo nos centramos en la integración con 🤗 Transformers, integrarlo en tu propio código o biblioteca es muy sencillo.

## Usando la biblioteca de Python `huggingface_hub`[[using-the-huggingfacehub-python-library]]

La biblioteca de Python `huggingface_hub` es un paquete que ofrece un conjunto de herramientas para los hubs de modelos y conjuntos de datos. Proporciona métodos y clases sencillos para tareas comunes como obtener información sobre repositorios en el hub y administrarlos. Ofrece APIs simples que funcionan sobre git para gestionar el contenido de esos repositorios e integrar el Hub en tus proyectos y bibliotecas.

De manera similar a utilizar la API `push_to_hub`, esto requerirá que tengas guardado tu token de API en tu caché. Para hacer esto, deberás utilizar el comando `login` de la CLI, como se mencionó en la sección anterior (nuevamente, asegúrate de anteponer a estos comandos el caracter `!` si estás ejecutando en Google Colab):

```bash
huggingface-cli login
```

El paquete `huggingface_hub` ofrece varios métodos y clases que son útiles para nuestro propósito. En primer lugar, hay algunos métodos para gestionar la creación y eliminación de repositorios, entre otros:

```python no-format
from huggingface_hub import (
    # Gestión de usuarios
    login,
    logout,
    whoami,

    # Creación y gestión de repositorios
    create_repo,
    delete_repo,
    update_repo_visibility,

    # Y algunos métodos para recuperar/cambiar información sobre el contenido
    list_models,
    list_datasets,
    list_metrics,
    list_repo_files,
    upload_file,
    delete_file,
)
```

Además, ofrece la muy potente clase `Repository` para gestionar un repositorio local. Exploraremos estos métodos y esa clase en las siguientes secciones para entender cómo aprovecharlos.

El método `create_repo` se puede utilizar para crear un nuevo repositorio en el hub:

```py
from huggingface_hub import create_repo

create_repo("dummy-model")
```

Esto creará el repositorio `dummy-model` en tu espacio de nombres. Si lo deseas, puedes especificar a qué organización debe pertenecer el repositorio utilizando el argumento `organization`:

```py
from huggingface_hub import create_repo

create_repo("dummy-model", organization="huggingface")
```

Esto creará el repositorio `dummy-model` en el espacio de nombres `huggingface`, asumiendo que perteneces a esa organización.
Otros argumentos que pueden ser útiles son:

- `private`, para especificar si el repositorio debe ser visible para otros o no.
- `token`, si deseas anular el token almacenado en tu caché con un token específico.
- `repo_type`, si deseas crear un `dataset` o un `space` en lugar de un modelo. Los valores aceptados son `"dataset"` y `"space"`.

Una vez creado el repositorio, ¡debemos agregarle archivos! Salta a la siguiente sección para ver las tres formas en que se puede manejar esto.

## Subiendo los archivos del modelo[[uploading-the-model-files]]

El sistema para administrar archivos en el Hugging Face Hub se basa en git para archivos normales y git-lfs (que significa [Git Large File Storage](https://git-lfs.github.com/)) para archivos más grandes.

En la siguiente sección, repasamos tres formas diferentes de subir archivos al Hub: a través de `huggingface_hub` y a través de comandos de git.

### El enfoque con `upload_file`[[the-uploadfile-approach]]

Usar `upload_file` no requiere tener git y git-lfs instalados en tu sistema. Envía archivos directamente al Hub de 🤗 mediante solicitudes HTTP POST. Una limitación de este enfoque es que no maneja archivos que superen los 5 GB de tamaño.
Si tus archivos superan los 5 GB, sigue los otros dos métodos detallados a continuación.

La API se puede utilizar de la siguiente manera:

```py
from huggingface_hub import upload_file

upload_file(
    "<path_to_file>/config.json",
    path_in_repo="config.json",
    repo_id="<namespace>/dummy-model",
)
```

Esto subirá el archivo `config.json` disponible en `<path_to_file>` a la raíz del repositorio como `config.json`, en el repositorio `dummy-model`.
Otros argumentos que pueden ser útiles son:

- `token`, si deseas anular el token almacenado en tu caché por un token determinado.
- `repo_type`, si deseas subir a un `dataset` o un `space` en lugar de un modelo. Los valores aceptados son `"dataset"` y `"space"`.


### La clase `Repository`[[the-repository-class]]

La clase `Repository` administra un repositorio local de una manera similar a git. Abstrae la mayor parte de las dificultades que uno puede encontrar con git para proporcionar todas las funcionalidades que requerimos.

El uso de esta clase requiere tener instalados git y git-lfs, así que asegúrate de tener git-lfs instalado (consulta [aquí](https://git-lfs.github.com/) las instrucciones de instalación) y configurado antes de comenzar.

Para empezar a interactuar con el repositorio que acabamos de crear, podemos inicializarlo en una carpeta local clonando el repositorio remoto:

```py
from huggingface_hub import Repository

repo = Repository("<path_to_dummy_folder>", clone_from="<namespace>/dummy-model")
```

Esto creó la carpeta `<path_to_dummy_folder>` en nuestro directorio de trabajo. Esta carpeta solo contiene el archivo `.gitattributes`, ya que es el único archivo creado al instanciar el repositorio a través de `create_repo`.

A partir de este momento, podemos aprovechar varios de los métodos tradicionales de git:

```py
repo.git_pull()
repo.git_add()
repo.git_commit()
repo.git_push()
repo.git_tag()
```

¡Y otros! Recomendamos consultar la documentación de `Repository` disponible [aquí](https://github.com/huggingface/huggingface_hub/tree/main/src/huggingface_hub#advanced-programmatic-repository-management) para ver una descripción general de todos los métodos disponibles.

En este momento, tenemos un modelo y un tokenizador que nos gustaría enviar al hub. Hemos clonado el repositorio con éxito, por lo que podemos guardar los archivos dentro de ese repositorio.

Primero nos aseguramos de que nuestro clon local esté actualizado descargando los últimos cambios:

```py
repo.git_pull()
```

Una vez hecho esto, guardamos los archivos del modelo y del tokenizador:

```py
model.save_pretrained("<path_to_dummy_folder>")
tokenizer.save_pretrained("<path_to_dummy_folder>")
```

La carpeta `<path_to_dummy_folder>` ahora contiene todos los archivos del modelo y del tokenizador. Seguimos el flujo de trabajo habitual de git añadiendo archivos al área de preparación (*staging*), confirmándolos (*commit*) y enviándolos (*push*) al hub:

```py
repo.git_add()
repo.git_commit("Add model and tokenizer files")
repo.git_push()
```

¡Felicidades! Acabas de subir tus primeros archivos al hub.

### El enfoque basado en git[[the-git-based-approach]]

Este es el enfoque más básico para subir archivos: lo haremos con git y git-lfs directamente. La mayor parte de la dificultad está abstraída por los enfoques anteriores, pero hay algunas particularidades con el siguiente método, por lo que seguiremos un caso de uso más complejo.

El uso de este método requiere tener instalados git y git-lfs, así que asegúrate de tener [git-lfs](https://git-lfs.github.com/) instalado (consulta aquí las instrucciones de instalación) y configurado antes de comenzar.

Primero comienza inicializando git-lfs:

```bash
git lfs install
```

```bash
Updated git hooks.
Git LFS initialized.
```

Una vez hecho esto, el primer paso es clonar tu repositorio de modelos:

```bash
git clone https://huggingface.co/<namespace>/<your-model-id>
```

Mi nombre de usuario es `lysandre` y he usado el nombre de modelo `dummy`, por lo que para mí el comando se ve de la siguiente manera:

```
git clone https://huggingface.co/lysandre/dummy
```

Ahora tengo una carpeta llamada *dummy* en mi directorio de trabajo. Puedo hacer `cd` a la carpeta y ver el contenido:

```bash
cd dummy && ls
```

```bash
README.md
```

Si acabas de crear tu repositorio usando el método `create_repo` del Hub de Hugging Face, esta carpeta solo debería contener un archivo `.gitattributes` oculto. Si seguiste las instrucciones de la sección anterior para crear un repositorio usando la interfaz web, la carpeta debería contener un solo archivo *README.md* junto con el archivo oculto `.gitattributes`, como se muestra aquí.

Agregar un archivo de tamaño normal, como un archivo de configuración, un archivo de vocabulario o básicamente cualquier archivo de menos de unos pocos megabytes, se hace exactamente como se haría en cualquier sistema basado en git. Sin embargo, los archivos más grandes deben registrarse a través de git-lfs para poder enviarlos a *huggingface.co*.
