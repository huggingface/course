En las secciones anteriores hemos explorado y creado demos utilizando la clase `Interface`. En esta sección presentaremos nuestra API de bajo nivel llamada `gradio.Blocks`.

Ahora bien, ¿cuál es la diferencia entre `Interface` y `Blocks`?

- ⚡ `Interface`: una API de alto nivel que te permite crear una demo completa de aprendizaje automático simplemente proporcionando una lista de entradas y salidas.

- 🧱 `Blocks`: una API de bajo nivel que te permite tener un control total sobre los flujos de datos y el diseño (*layout*) de tu aplicación. Puedes construir aplicaciones muy complejas y de múltiples pasos usando `Blocks` (como en "bloques de construcción").

### ¿Por qué Blocks 🧱?[[why-blocks-]]

Como vimos en las secciones anteriores, la clase `Interface` te permite crear fácilmente demos completas de aprendizaje automático con solo unas pocas líneas de código. La API `Interface` es extremadamente fácil de usar pero carece de la flexibilidad que brinda la API `Blocks`. Por ejemplo, podrías querer:

- Agrupar demos relacionadas en múltiples pestañas en una sola aplicación web.
- Cambiar el diseño de tu demo, por ejemplo para especificar dónde se ubican las entradas y salidas.
- Tener interfaces de múltiples pasos, en las que la salida de un modelo se convierte en la entrada del siguiente modelo, o tener flujos de datos más flexibles en general.
- Cambiar las propiedades de un componente (por ejemplo, las opciones en un menú desplegable) o su visibilidad según la entrada del usuario.

Exploraremos todos estos conceptos a continuación.

### Creando una demo simple con Blocks[[creating-a-simple-demo-using-blocks]]

Una vez que hayas instalado Gradio, ejecuta el código siguiente como un script de Python, en un notebook de Jupyter o en un notebook de Colab:

```py
import gradio as gr


def flip_text(x):
    return x[::-1]


demo = gr.Blocks()

with demo:
    gr.Markdown(
        """
    # Flip Text!
    Start typing below to see the output.
    """
    )
    input = gr.Textbox(placeholder="Flip this text")
    output = gr.Textbox()

    input.change(fn=flip_text, inputs=input, outputs=output)

demo.launch()
```

Este sencillo ejemplo anterior introduce 4 conceptos fundamentales de Blocks:

1. Blocks te permite crear aplicaciones web que combinan Markdown, HTML, botones y componentes interactivos simplemente instanciando objetos en Python dentro de un contexto `with gradio.Blocks`.
> [!TIP]
> 🙋 Si no estás familiarizado con la sentencia `with` en Python, te recomendamos consultar el excelente [tutorial](https://realpython.com/python-with-statement/) de Real Python. ¡Regresa aquí después de leerlo 🤗!
El orden en que instancias los componentes importa, ya que cada elemento se representa en la aplicación web en el orden en que fue creado (los diseños más complejos se discuten a continuación).

2. Puedes definir funciones regulares de Python en cualquier parte de tu código y ejecutarlas con la entrada del usuario usando `Blocks`. En nuestro ejemplo, tenemos una función simple que "invierte" el texto de entrada, pero puedes escribir cualquier función de Python, desde un cálculo simple hasta procesar las predicciones de un modelo de aprendizaje automático.

3. Puedes asignar eventos a cualquier componente de `Blocks`. Esto ejecutará tu función cuando se haga clic en el componente, cambie su valor, etc. Cuando asignas un evento, pasas tres parámetros: `fn`: la función a la que se debe llamar, `inputs`: la (lista de) componentes de entrada, y `outputs`: la (lista de) componentes de salida que se deben actualizar.

   En el ejemplo anterior, ejecutamos la función `flip_text()` cuando cambia el valor en el `Textbox` llamado `input`. El evento lee el valor en `input`, lo pasa a `flip_text()`, que luego devuelve un valor que se asigna a nuestro segundo `Textbox` llamado `output`.

   Para ver una lista de los eventos que admite cada componente, consulta la [documentación de Gradio](https://www.gradio.app/docs/).

4. Blocks determina automáticamente si un componente debe ser interactivo (aceptar entradas del usuario) o no, según los disparadores de eventos que definas. En nuestro ejemplo, el primer cuadro de texto es interactivo, ya que su valor es utilizado por la función `flip_text()`. El segundo cuadro de texto no es interactivo, ya que su valor nunca se usa como entrada. En algunos casos, es posible que desees anular esto, lo cual puedes hacer pasando un booleano al parámetro `interactive` del componente (por ejemplo, `gr.Textbox(placeholder="Flip this text", interactive=True)`).

### Personalizando el diseño de tu demo[[customizing-the-layout-of-your-demo]]

¿Cómo podemos usar `Blocks` para personalizar el diseño de nuestra demo? De forma predeterminada, `Blocks` representa los componentes que creas verticalmente en una columna. Puedes cambiar eso creando columnas adicionales `with gradio.Column():` o filas `with gradio.Row():` y creando componentes dentro de esos contextos.

Esto es lo que debes tener en cuenta: cualquier componente creado bajo una `Column` (este también es el valor predeterminado) se dispondrá verticalmente. Cualquier componente creado bajo una `Row` se dispondrá horizontalmente, similar al [modelo flexbox en desarrollo web](https://developer.mozilla.org/es/docs/Web/CSS/CSS_Flexible_Box_Layout/Basic_Concepts_of_Flexbox).

Por último, también puedes crear pestañas para tu demo utilizando el administrador de contexto `with gradio.Tabs():`. Dentro de este contexto, puedes crear múltiples pestañas especificando elementos secundarios `with gradio.TabItem(name_of_tab):`. Cualquier componente creado dentro de un contexto `with gradio.TabItem(name_of_tab):` aparecerá en esa pestaña.

Ahora agreguemos una función `flip_image()` a nuestra demo y agreguemos una nueva pestaña que invierta imágenes. A continuación se muestra un ejemplo con 2 pestañas y que también usa una fila:

```py
import numpy as np
import gradio as gr

demo = gr.Blocks()


def flip_text(x):
    return x[::-1]


def flip_image(x):
    return np.fliplr(x)


with demo:
    gr.Markdown("Flip text or image files using this demo.")
    with gr.Tabs():
        with gr.TabItem("Flip Text"):
            with gr.Row():
                text_input = gr.Textbox()
                text_output = gr.Textbox()
            text_button = gr.Button("Flip")
        with gr.TabItem("Flip Image"):
            with gr.Row():
                image_input = gr.Image()
                image_output = gr.Image()
            image_button = gr.Button("Flip")

    text_button.click(flip_text, inputs=text_input, outputs=text_output)
    image_button.click(flip_image, inputs=image_input, outputs=image_output)

demo.launch()
```

### Explorando eventos y estado[[exploring-events-and-state]]

Así como puedes controlar el diseño, `Blocks` te brinda un control detallado sobre qué eventos activan las llamadas a funciones. Cada componente y muchos diseños tienen eventos específicos que admiten.

Por ejemplo, el componente `Textbox` tiene 2 eventos: `change()` (cuando cambia el valor dentro del cuadro de texto) y `submit()` (cuando el usuario presiona la tecla enter mientras está enfocado en el cuadro de texto). Los componentes más complejos pueden tener aún más eventos: por ejemplo, el componente `Audio` también tiene eventos separados para cuando el archivo de audio se reproduce, se borra, se pausa, etc. Consulta la documentación para conocer los eventos admitidos por cada componente.

Puedes adjuntar activadores de eventos a ninguno, a uno o a varios de estos eventos. Creas un disparador de eventos llamando al nombre del evento en la instancia del componente como una función, por ejemplo `textbox.change(...)` o `btn.click(...)`. La función toma tres parámetros, como se explicó anteriormente:

- `fn`: la función a ejecutar.
- `inputs`: una (lista de) componente(s) cuyos valores se deben suministrar como parámetros de entrada a la función. El valor de cada componente se asigna al parámetro de función correspondiente, en orden. Este parámetro puede ser `None` si la función no toma ningún parámetro.
- `outputs`: una (lista de) componente(s) cuyos valores se deben actualizar en función de los valores devueltos por la función. Cada valor devuelto establece el valor del componente correspondiente, en orden. Este parámetro puede ser `None` si la función no devuelve nada.

Incluso puedes hacer que el componente de entrada y salida sea el mismo componente, como hacemos en este ejemplo que usa un modelo GPT para completar texto:

```py
import gradio as gr

api = gr.Interface.load("huggingface/EleutherAI/gpt-j-6B")


def complete_with_gpt(text):
    # Use the last 50 characters of the text as context
    return text[:-50] + api(text[-50:])


with gr.Blocks() as demo:
    textbox = gr.Textbox(placeholder="Type here and press enter...", lines=4)
    btn = gr.Button("Generate")

    btn.click(complete_with_gpt, textbox, textbox)

demo.launch()
```

### Creando demos de múltiples pasos[[creating-multi-step-demos]]

En algunos casos, es posible que desees una _demo de múltiples pasos_, en la que reutilices la salida de una función como la entrada de la siguiente. Esto es realmente fácil de hacer con `Blocks`, ya que puedes usar un componente para la entrada de un disparador de eventos pero como la salida de otro. Echa un vistazo al componente de texto en el ejemplo siguiente: su valor es el resultado de un modelo de voz a texto (*speech-to-text*), pero también se pasa a un modelo de análisis de sentimientos (*sentiment analysis*):

```py
from transformers import pipeline

import gradio as gr

asr = pipeline("automatic-speech-recognition", "facebook/wav2vec2-base-960h")
classifier = pipeline("text-classification")


def speech_to_text(speech):
    text = asr(speech)["text"]
    return text


def text_to_sentiment(text):
    return classifier(text)[0]["label"]


demo = gr.Blocks()

with demo:
    audio_file = gr.Audio(type="filepath")
    text = gr.Textbox()
    label = gr.Label()

    b1 = gr.Button("Recognize Speech")
    b2 = gr.Button("Classify Sentiment")

    b1.click(speech_to_text, inputs=audio_file, outputs=text)
    b2.click(text_to_sentiment, inputs=text, outputs=label)

demo.launch()
```

### Actualizando propiedades de los componentes[[updating-component-properties]]

Hasta ahora, hemos visto cómo crear eventos para actualizar el valor de otro componente. Pero, ¿qué sucede si deseas cambiar otras propiedades de un componente, como la visibilidad de un cuadro de texto o las opciones en un grupo de botones de opción (*radio buttons*)? Puedes hacer esto devolviendo el método `update()` de la clase del componente en lugar de un valor de retorno normal desde tu función.

Esto se ilustra más fácilmente con un ejemplo:

```py
import gradio as gr


def change_textbox(choice):
    if choice == "short":
        return gr.Textbox.update(lines=2, visible=True)
    elif choice == "long":
        return gr.Textbox.update(lines=8, visible=True)
    else:
        return gr.Textbox.update(visible=False)


with gr.Blocks() as block:
    radio = gr.Radio(
        ["short", "long", "none"], label="What kind of essay would you like to write?"
    )
    text = gr.Textbox(lines=2, interactive=True)

    radio.change(fn=change_textbox, inputs=radio, outputs=text)
    block.launch()
```
