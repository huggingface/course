Ahora que podemos construir y compartir una interfaz básica, exploremos algunas características más avanzadas como el estado (*state*) y la interpretación (*interpretation*).

### Usando el estado para persistir datos[[using-state-to-persist-data]]

Gradio admite el *estado de sesión*, donde los datos persisten a través de múltiples envíos dentro de una misma carga de página. El estado de sesión es útil para construir demos de, por ejemplo, chatbots donde deseas conservar datos a medida que el usuario interactúa con el modelo. Ten en cuenta que el estado de sesión no comparte datos entre diferentes usuarios de tu modelo.

Para almacenar datos en un estado de sesión, debes hacer tres cosas:

1. Pasar un *parámetro adicional* a tu función, que represente el estado de la interfaz.
1. Al final de la función, devolver el valor actualizado del estado como un *valor de retorno adicional*.
1. Agregar los componentes de entrada 'state' y de salida 'state' al crear tu `Interface`.

Mira el ejemplo de chatbot a continuación:

```py
import random

import gradio as gr


def chat(message, history):
    history = history or []
    if message.startswith("How many"):
        response = random.randint(1, 10)
    elif message.startswith("How"):
        response = random.choice(["Great", "Good", "Okay", "Bad"])
    elif message.startswith("Where"):
        response = random.choice(["Here", "There", "Somewhere"])
    else:
        response = "I don't know"
    history.append((message, response))
    return history, history


iface = gr.Interface(
    chat,
    ["text", "state"],
    ["chatbot", "state"],
    allow_screenshot=False,
    allow_flagging="never",
)
iface.launch()
```

### Usando la interpretación para entender las predicciones[[using-interpretation-to-understand-predictions]]

La mayoría de los modelos de aprendizaje automático son cajas negras y la lógica interna de la función está oculta para el usuario final. Para fomentar la transparencia, hemos facilitado mucho la adición de interpretación a tu modelo simplemente configurando la palabra clave `interpretation` en la clase `Interface` como `"default"`. Esto permite a tus usuarios comprender qué partes de la entrada son responsables de la salida. Echa un vistazo a la sencilla interfaz a continuación que muestra un clasificador de imágenes que también incluye interpretación:

```py
import requests
import tensorflow as tf

import gradio as gr

inception_net = tf.keras.applications.MobileNetV2()  # load the model

# Download human-readable labels for ImageNet.
response = requests.get("https://git.io/JJkYN")
labels = response.text.split("\n")


def classify_image(inp):
    inp = inp.reshape((-1, 224, 224, 3))
    inp = tf.keras.applications.mobilenet_v2.preprocess_input(inp)
    prediction = inception_net.predict(inp).flatten()
    return {labels[i]: float(prediction[i]) for i in range(1000)}


image = gr.Image(shape=(224, 224))
label = gr.Label(num_top_classes=3)

title = "Gradio Image Classifiction + Interpretation Example"
gr.Interface(
    fn=classify_image, inputs=image, outputs=label, interpretation="default", title=title
).launch()
```

Prueba la función de interpretación enviando una entrada y haciendo clic en "Interpret" debajo del componente de salida.

Además del método de interpretación predeterminado que proporciona Gradio, también puedes especificar `"shap"` para el parámetro `interpretation` y configurar el parámetro `num_shap`. Esto utiliza una interpretación basada en valores de Shapley, sobre la cual puedes leer más [aquí](https://christophm.github.io/interpretable-ml-book/shap.html).
Por último, también puedes pasar tu propia función de interpretación al parámetro `interpretation`. Consulta un ejemplo en la página de primeros pasos de Gradio [aquí](https://gradio.app/getting_started/).
