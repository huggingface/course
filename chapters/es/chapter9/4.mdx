Ahora que has construido una demo, probablemente querrás compartirla con los demás. Las demos de Gradio se pueden compartir de dos maneras: utilizando un ***enlace temporal para compartir*** o mediante un ***alojamiento permanente en Spaces***.

Cubriremos ambos enfoques en breve. Pero antes de compartir tu demo, quizás quieras darle un toque final y pulirla 💅.

Para agregar contenido adicional a tu demo, la clase `Interface` admite algunos parámetros opcionales:
    - `title`: puedes darle un título a tu demo, que aparece _por encima_ de los componentes de entrada y salida.
    - `description`: puedes dar una descripción (en texto, Markdown o HTML) para la interfaz, que aparece encima de los componentes de entrada y salida y debajo del título.
    - `article`: también puedes escribir un artículo ampliado (en texto, Markdown o HTML) explicando la interfaz. Si se proporciona, aparece _debajo_ de los componentes de entrada y salida.
    - `theme`: ¿no te gustan los colores predeterminados? Configura el tema para usar uno de `default`, `huggingface`, `grass`, `peach`. También puedes agregar el prefijo `dark-`, por ejemplo `dark-peach` para el tema oscuro (o simplemente `dark` para el tema oscuro predeterminado).
    - `examples`: para que tu demo sea *mucho más fácil de usar*, puedes proporcionar algunos ejemplos de entrada para la función. Estos aparecen debajo de los componentes de la interfaz de usuario y se pueden utilizar para rellenar la interfaz. Deben proporcionarse como una lista anidada, en la que la lista externa consta de muestras y cada lista interna consta de una entrada correspondiente a cada componente de entrada.
    - `live`: si deseas que tu demo sea "en vivo" (*live*), lo que significa que tu modelo se vuelve a ejecutar cada vez que cambia la entrada, puedes configurar `live=True`. Esto tiene sentido utilizarlo con modelos rápidos (veremos un ejemplo al final de esta sección).

Usando las opciones anteriores, obtenemos una interfaz más completa. Ejecuta el código a continuación para poder chatear con Rick y Morty:

```py
title = "Ask Rick a Question"
description = """
The bot was trained to answer questions based on Rick and Morty dialogues. Ask Rick anything!
<img src="https://huggingface.co/spaces/course-demos/Rick_and_Morty_QA/resolve/main/rick.png" width=200px>
"""

article = "Check out [the original Rick and Morty Bot](https://huggingface.co/spaces/kingabzpro/Rick_and_Morty_Bot) that this demo is based off of."

gr.Interface(
    fn=predict,
    inputs="textbox",
    outputs="text",
    title=title,
    description=description,
    article=article,
    examples=[["What are you doing?"], ["Where should we time travel to?"]],
).launch()
```

### Compartiendo tu demo con enlaces temporales[[sharing-your-demo-with-temporary-links]]

Ahora que tenemos una demo funcional de nuestro modelo de aprendizaje automático, aprendamos a compartir fácilmente un enlace a nuestra interfaz.
Las interfaces se pueden compartir públicamente de forma muy sencilla estableciendo `share=True` en el método `launch()`:

```python
gr.Interface(classify_image, "image", "label").launch(share=True)
```

¡Esto genera un enlace público y compartible que puedes enviar a cualquiera! Cuando envías este enlace, el usuario del otro lado puede probar el modelo en su navegador por hasta 72 horas. Dado que el procesamiento se realiza en tu dispositivo (¡siempre que tu dispositivo permanezca encendido!), no tienes que preocuparte por empaquetar ninguna dependencia. Si estás trabajando desde un notebook de Google Colab, siempre se crea automáticamente un enlace para compartir. Suele verse algo como esto: **XXXXX.gradio.app**. Aunque el enlace se sirve a través de un enlace de Gradio, solo actuamos como un proxy para tu servidor local y no almacenamos ningún dato enviado a través de las interfaces.

Ten en cuenta, sin embargo, que estos enlaces son accesibles públicamente, ¡lo que significa que cualquiera puede usar tu modelo para hacer predicciones! Por lo tanto, asegúrate de no exponer ninguna información confidencial a través de las funciones que escribas, ni permitir que ocurran cambios críticos en tu dispositivo. Si configuras `share=False` (el valor predeterminado), solo se crea un enlace local.

### Alojando tu demo en Hugging Face Spaces[[hosting-your-demo-on-hugging-face-spaces]]

Un enlace para compartir que puedas pasar a tus compañeros es genial, pero ¿cómo puedes alojar permanentemente tu demo y hacer que exista en su propio "espacio" en Internet?

¡Hugging Face Spaces proporciona la infraestructura para alojar permanentemente tu modelo de Gradio en Internet, **de forma gratuita**! Spaces te permite crear y hacer push a un repositorio (público o privado), donde el código de tu interfaz de Gradio residirá en un archivo `app.py`. [Lee un tutorial paso a paso](https://huggingface.co/blog/gradio-spaces) para comenzar, o mira el video de ejemplo a continuación.

## ✏️ ¡Apliquémoslo![[lets-apply-it]]

Utilizando lo que acabamos de aprender en las secciones anteriores, creemos la demo de reconocimiento de bocetos que vimos en la [sección uno de este capítulo](/course/chapter9/1). Agreguemos algo de personalización a nuestra interfaz y configuremos `share=True` para crear un enlace público que podamos compartir.

Podemos cargar las etiquetas desde [class_names.txt](https://huggingface.co/spaces/dawood/Sketch-Recognition/blob/main/class_names.txt) y cargar el modelo preentrenado de PyTorch desde [pytorch_model.bin](https://huggingface.co/spaces/dawood/Sketch-Recognition/blob/main/pytorch_model.bin). Descarga estos archivos siguiendo el enlace y haciendo clic en descargar en la esquina superior izquierda de la vista previa del archivo. Echemos un vistazo al código a continuación para ver cómo usamos estos archivos para cargar nuestro modelo y crear una función `predict()`:

```py
from pathlib import Path
import torch
import gradio as gr
from torch import nn

LABELS = Path("class_names.txt").read_text().splitlines()

model = nn.Sequential(
    nn.Conv2d(1, 32, 3, padding="same"),
    nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Conv2d(32, 64, 3, padding="same"),
    nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Conv2d(64, 128, 3, padding="same"),
    nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Flatten(),
    nn.Linear(1152, 256),
    nn.ReLU(),
    nn.Linear(256, len(LABELS)),
)
state_dict = torch.load("pytorch_model.bin", map_location="cpu")
model.load_state_dict(state_dict, strict=False)
model.eval()


def predict(im):
    x = torch.tensor(im, dtype=torch.float32).unsqueeze(0).unsqueeze(0) / 255.0
    with torch.no_grad():
        out = model(x)
    probabilities = torch.nn.functional.softmax(out[0], dim=0)
    values, indices = torch.topk(probabilities, 5)
    return {LABELS[i]: v.item() for i, v in zip(indices, values)}
```

Ahora que tenemos una función `predict()`, el siguiente paso es definir y lanzar nuestra interfaz de Gradio:

```py
interface = gr.Interface(
    predict,
    inputs="sketchpad",
    outputs="label",
    theme="huggingface",
    title="Sketch Recognition",
    description="Who wants to play Pictionary? Draw a common object like a shovel or a laptop, and the algorithm will guess in real time!",
    article="<p style='text-align: center'>Sketch Recognition | Demo Model</p>",
    live=True,
)
interface.launch(share=True)
```

Observa el parámetro `live=True` en `Interface`, lo que significa que la demo de bocetos realiza una predicción cada vez que alguien dibuja en el bloc de bocetos (¡sin botón de envío!).

Además, también establecemos el argumento `share=True` en el método `launch()`. Esto creará un enlace público que puedes enviar a cualquiera. Al enviar este enlace, el usuario del otro lado podrá probar el modelo de reconocimiento de bocetos. Reiterando lo anterior, también podrías alojar el modelo en Hugging Face Spaces, que es como podemos incrustar la demo de arriba.
