# Evaluación[[evaluacion]]

Con un modelo ajustado finamente a través de SFT o LoRA SFT, debemos evaluarlo en puntos de referencia (*benchmarks*) estándar. Como ingenieros de aprendizaje automático, deben mantener un conjunto de evaluaciones relevantes para su dominio específico de interés. En esta página, analizaremos algunos de los puntos de referencia más comunes y cómo utilizarlos para evaluar tu modelo. También veremos cómo crear puntos de referencia personalizados para tu caso de uso específico.

## Puntos de referencia automáticos

Los puntos de referencia automáticos sirven como herramientas estandarizadas para evaluar modelos de lenguaje en diferentes tareas y capacidades. Si bien proporcionan un punto de partida útil para comprender el rendimiento del modelo, es importante reconocer que representan solo una pieza de una estrategia de evaluación integral.

## Comprender los puntos de referencia automáticos

Los benchmarks automáticos consisten típicamente en conjuntos de datos seleccionados con tareas predefinidas y métricas de evaluación. Estos puntos de referencia tienen como objetivo evaluar varios aspectos de la capacidad del modelo, desde la comprensión básica del lenguaje hasta el razonamiento complejo. La principal ventaja de utilizar puntos de referencia automáticos es su estandarización: permiten una comparación consistente entre diferentes modelos y proporcionan resultados reproducibles.

Sin embargo, es fundamental comprender que el rendimiento en los puntos de referencia no siempre se traduce directamente en efectividad en el mundo real. Un modelo que sobresale en puntos de referencia académicos aún puede tener dificultades con aplicaciones en dominios específicos o casos de uso prácticos.

## Puntos de referencia de conocimiento general

[MMLU](https://huggingface.co/datasets/cais/mmlu) (*Massive Multitask Language Understanding*) evalúa el conocimiento en 57 materias, desde ciencias hasta humanidades. Aunque es exhaustivo, puede que no refleje la profundidad de experiencia necesaria para dominios específicos. TruthfulQA evalúa la tendencia de un modelo a reproducir conceptos erróneos comunes, aunque no puede capturar todas las formas de desinformación.

## Puntos de referencia de razonamiento

[BBH](https://huggingface.co/datasets/lukaemon/bbh) (*Big Bench Hard*) y [GSM8K](https://huggingface.co/datasets/openai/gsm8k) se centran en tareas de razonamiento complejas. BBH pone a prueba el pensamiento lógico y la planificación, mientras que GSM8K se dirige específicamente a la resolución de problemas matemáticos. Estos puntos de referencia ayudan a evaluar las capacidades analíticas, pero es posible que no capturen el razonamiento matizado requerido en escenarios del mundo real.

## Comprensión del lenguaje

[HELM](https://github.com/stanford-crfm/helm) proporciona un marco de evaluación holístico. Puntos de referencia como HELM ofrecen información sobre las capacidades de procesamiento del lenguaje en aspectos como el sentido común, el conocimiento del mundo y el razonamiento. Sin embargo, es posible que no representen plenamente la complejidad de la conversación natural o la terminología específica del dominio.

## Puntos de referencia específicos de dominio

Veamos algunos puntos de referencia que se centran en dominios específicos como matemáticas, programación y conversación.

El [punto de referencia MATH](https://huggingface.co/papers/2103.03874) es otra herramienta de evaluación importante para el razonamiento matemático. Consta de 12.500 problemas de competiciones matemáticas, que cubren álgebra, geometría, teoría de números, conteo, probabilidad y más. Lo que hace que MATH sea particularmente desafiante es que requiere razonamiento de varios pasos, comprensión de la notación matemática formal y la capacidad de generar soluciones paso a paso. A diferencia de tareas aritméticas más simples, los problemas de MATH a menudo exigen estrategias sofisticadas de resolución de problemas y aplicaciones de conceptos matemáticos.

El [benchmark HumanEval](https://github.com/openai/human-eval) es un conjunto de datos de evaluación centrado en la programación que consta de 164 problemas de programación. El punto de referencia prueba la capacidad de un modelo para generar código Python funcionalmente correcto que resuelva las tareas de programación dadas. Lo que hace que HumanEval sea particularmente valioso es que evalúa tanto las capacidades de generación de código como la corrección funcional mediante la ejecución real de casos de prueba, en lugar de una mera similitud superficial con soluciones de referencia. Los problemas varían desde la manipulación básica de cadenas hasta algoritmos y estructuras de datos más complejos.

[Alpaca Eval](https://tatsu-lab.github.io/alpaca_eval/) es un marco de evaluación automatizado diseñado para evaluar la calidad de los modelos de lenguaje que siguen instrucciones. Utiliza GPT-4 como juez para evaluar las salidas del modelo en varias dimensiones, incluyendo utilidad, honestidad e inocuidad. El marco incluye un conjunto de datos de 805 prompts cuidadosamente seleccionados y puede evaluar respuestas contra múltiples modelos de referencia como Claude, GPT-4 y otros. Lo que hace que Alpaca Eval sea particularmente útil es su capacidad para proporcionar evaluaciones consistentes y escalables sin requerir anotadores humanos, al tiempo que captura aspectos matizados del rendimiento del modelo que las métricas tradicionales podrían pasar por alto.

## Enfoques de evaluación alternativos

Muchas organizaciones han desarrollado métodos de evaluación alternativos para abordar las limitaciones de los puntos de referencia estándar:

### LLM como juez (*LLM-as-Judge*)

El uso de un modelo de lenguaje para evaluar las salidas de otro se ha vuelto cada vez más popular. Este enfoque puede proporcionar una retroalimentación más matizada que las métricas tradicionales, aunque tiene sus propios sesgos y limitaciones.

### Arenas de evaluación

Las arenas de evaluación como [Chatbot Arena](https://lmarena.ai/) ofrecen un enfoque único para la evaluación de LLMs a través de la retroalimentación colectiva (*crowdsourced*). En estas plataformas, los usuarios participan en "batallas" anónimas entre dos LLMs, haciendo preguntas y votando por qué modelo ofrece mejores respuestas. Este enfoque captura patrones de uso y preferencias del mundo real a través de preguntas diversas y desafiantes, y los estudios muestran una fuerte concordancia entre los votos de la multitud y las evaluaciones de expertos. Si bien son potentes, estas plataformas tienen limitaciones que incluyen el sesgo potencial de la base de usuarios, distribuciones sesgadas de prompts y un enfoque principal en la utilidad más que en las consideraciones de seguridad.

### Suites de evaluación personalizadas

Las organizaciones a menudo desarrollan suites internas de evaluación adaptadas a sus necesidades y casos de uso específicos. Estas pueden incluir pruebas de conocimiento específicas del dominio o escenarios de evaluación que reflejen las condiciones reales de implementación.

## Evaluación personalizada

Si bien los puntos de referencia estándar proporcionan una línea de base útil, no deberían ser tu único método de evaluación. A continuación se explica cómo desarrollar un enfoque más completo:

1. Comienza con puntos de referencia estándar relevantes para establecer una línea de base y permitir la comparación con otros modelos.

2. Identifica los requisitos y desafíos específicos de tu caso de uso. ¿Qué tareas realizará realmente tu modelo? ¿Qué tipo de errores serían los más problemáticos?

3. Desarrolla conjuntos de datos de evaluación personalizados que reflejen tu caso de uso real. Esto podría incluir:
   - Consultas de usuarios reales de tu dominio
   - Casos límite (*edge cases*) comunes que hayas encontrado
   - Ejemplos de escenarios particularmente desafiantes

4. Considera implementar una estrategia de evaluación multinivel:
   - Métricas automatizadas para retroalimentación rápida
   - Evaluación humana para una comprensión matizada
   - Revisión de expertos de dominio para aplicaciones especializadas
   - Pruebas A/B en entornos controlados

## Implementar evaluaciones personalizadas

En esta sección, implementaremos la evaluación para nuestro modelo ajustado finamente. Podemos usar [`lighteval`](https://github.com/huggingface/lighteval) para evaluar nuestro modelo en puntos de referencia estándar, que contiene una amplia gama de tareas integradas en la librería. Solo necesitamos definir las tareas que deseamos evaluar y los parámetros para la evaluación.

Las tareas de LightEval se definen mediante un formato específico:

```
{suite}|{task}|{num_few_shot}|{auto_reduce}
```

| Parámetro | Descripción |
|-----------|-------------|
| `suite` | La suite del punto de referencia (ej., 'mmlu', 'truthfulqa') |
| `task` | Tarea específica dentro de la suite (ej., 'abstract_algebra') |
| `num_few_shot` | Número de ejemplos a incluir en el prompt (0 para zero-shot) |
| `auto_reduce` | Si se deben reducir automáticamente los ejemplos few-shot si el prompt es demasiado largo (0 o 1) |

Ejemplo: `"mmlu|abstract_algebra|0|0"` evalúa en la tarea de álgebra abstracta de MMLU con inferencia zero-shot.

## Ejemplo de pipeline de evaluación

Configuremos un pipeline de evaluación para nuestro modelo ajustado finamente. Evaluaremos el modelo en un conjunto de subtareas relacionadas con el dominio de la medicina.

Aquí hay un ejemplo completo de evaluación en puntos de referencia automáticos relevantes para un dominio específico utilizando Lighteval con el backend VLLM:

```bash
lighteval accelerate \
    "pretrained=your-model-name" \
    "mmlu|anatomy|0|0" \
    "mmlu|high_school_biology|0|0" \
    "mmlu|high_school_chemistry|0|0" \
    "mmlu|professional_medicine|0|0" \
    --max_samples 40 \
    --batch_size 1 \
    --output_path "./results" \
    --save_generations true
```

Los resultados se muestran en un formato tabular:

```
|                  Task                  |Version|Metric|Value |   |Stderr|
|----------------------------------------|------:|------|-----:|---|-----:|
|all                                     |       |acc   |0.3333|±  |0.1169|
|leaderboard:mmlu:_average:5             |       |acc   |0.3400|±  |0.1121|
|leaderboard:mmlu:anatomy:5              |      0|acc   |0.4500|±  |0.1141|
|leaderboard:mmlu:high_school_biology:5  |      0|acc   |0.1500|±  |0.0819|
```

Lighteval también incluye una API de Python para tareas de evaluación más detalladas, lo cual es útil para manipular los resultados de una manera más flexible. Consulta la [documentación de Lighteval](https://huggingface.co/docs/lighteval/using-the-python-api) para obtener más información.

> [!TIP]
> ✏️ **¡Pruébalo!** Evalúa tu modelo ajustado en una tarea específica en lighteval.
