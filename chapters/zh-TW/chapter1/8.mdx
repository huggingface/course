到目前為止，我們已經從一系列離散任務（如文字分類或摘要）的角度探討了 Transformer 架構。然而，大型語言模型最常用於文字生成，這也是本章要探討的內容。

在本頁中，我們將探討大型語言模型（LLM）推論背後的核心概念，帶你全面了解這些模型如何生成文字，以及推論過程涉及的關鍵元件。

## 理解基礎概念

讓我們從基本原理開始。推論是指使用已訓練好的 LLM，根據給定的輸入提示，生成類似人類的文字。語言模型會運用訓練中獲得的知識，一次一個詞地組織出回應。模型利用從數十億個參數中學到的機率，預測並生成序列中的下一個標記。正是這種依序生成的方式，讓 LLM 能夠產生連貫且與上下文相關的文字。

## 注意力的作用

注意力機制賦予了 LLM 理解上下文並生成連貫回應的能力。在預測下一個詞時，句子中的每個詞並非同等重要——例如，在句子*「法國的首都是……」*中，「法國」和「首都」這兩個詞，是判斷下一個詞應該是「巴黎」的關鍵。這種聚焦於相關資訊的能力，就是我們所說的注意力。

<img src="https://huggingface.co/datasets/agents-course/course-images/resolve/main/en/unit1/AttentionSceneFinal.gif" alt="Visual Gif of Attention" width="60%">

事實證明，這種找出最相關詞彙來預測下一個標記的做法極為有效。儘管訓練 LLM 的基本原理——預測下一個標記——自 BERT 和 GPT-2 以來大致保持不變，但在擴大神經網路規模，以及讓注意力機制能以越來越低的成本處理越來越長的序列方面，已經有了重大進展。

> [!TIP]
> 簡而言之，注意力機制是 LLM 得以生成既連貫、又能感知上下文的文字的關鍵，也讓現代 LLM 有別於前幾代語言模型。

### 上下文長度與注意力範圍

了解注意力之後，讓我們來看看 LLM 實際上能處理多少上下文。這就要談到上下文長度，也就是模型的「注意力範圍」。

上下文長度是指 LLM 一次最多能處理的標記數量（單詞或單詞的一部分）。你可以把它想成模型工作記憶體的大小。

這些能力受到幾個實際因素的限制：
- 模型的架構與大小
- 可用的運算資源
- 輸入與期望輸出的複雜度

在理想的世界裡，我們可以給模型無限的上下文，但硬體限制與運算成本使這並不切實際。這就是為什麼不同的模型會被設計成不同的上下文長度，以便在能力與效率之間取得平衡。

> [!TIP]
> 上下文長度是模型在生成回應時，一次最多能考慮的標記數量。

### 提示的藝術

當我們向 LLM 傳遞資訊時，我們會以能引導 LLM 生成期望輸出的方式來組織輸入。這稱為_提示_（prompting）。

了解 LLM 如何處理資訊，有助於我們設計出更好的提示。由於模型的主要任務是透過分析每個輸入標記的重要性來預測下一個標記，因此輸入序列的措辭就變得非常關鍵。

> [!TIP]
> 精心設計的提示，能讓你更容易**引導 LLM 生成期望的輸出**。

## 兩階段推論過程

現在我們已經了解基本元件，接著來看 LLM 實際上是如何生成文字的。這個過程可以分成兩個主要階段：預填充（prefill）與解碼（decode）。這兩個階段就像一條裝配線般協同運作，各自都是產生連貫文字不可或缺的一環。

### 預填充階段

預填充階段就像烹飪前的準備工作——所有初始食材都在這個階段處理並準備就緒。這個階段包含三個關鍵步驟：

1. **標記化**：將輸入文字轉換成標記（可以把標記想成模型能理解的基本建構單位）
2. **嵌入轉換**：將這些標記轉換成能捕捉其語意的數值表示
3. **初始處理**：將這些嵌入送進模型的神經網路處理，以建立對上下文的豐富理解

這個階段的運算量很大，因為它需要一次處理所有輸入標記。你可以把它想成在開始寫回應之前，先讀完並理解整段文字。

### 解碼階段

預填充階段處理完輸入後，就進入解碼階段——真正的文字生成就發生在這裡。模型會以我們所說的自回歸過程，一次生成一個標記（每個新標記都取決於所有先前的標記）。

解碼階段包含幾個關鍵步驟，每生成一個新標記都會重複一次：
1. **注意力計算**：回頭檢視所有先前的標記以理解上下文
2. **機率計算**：判斷每個可能的下一個標記出現的可能性
3. **標記選擇**：根據這些機率選出下一個標記
4. **繼續與否的檢查**：決定要繼續還是停止生成

這個階段會大量佔用記憶體，因為模型需要持續追蹤所有先前生成的標記及其關係。

### 理解標記選擇：從機率到具體選擇

當模型需要選擇下一個標記時，它會先取得詞彙表中每個詞的原始機率（稱為 logits）。但我們要如何把這些機率轉換成實際的選擇呢？讓我們來拆解這個過程：

![image](https://huggingface.co/reasoning-course/images/resolve/main/inference/1.png)

1. **原始 Logits**：可以把它們想成模型對每個可能的下一個詞的最初直覺
2. **溫度控制**：就像創意旋鈕——較高的設定（>1.0）會讓選擇更隨機、更有創意，較低的設定（<1.0）則會讓選擇更專注、更具確定性
3. **Top-p（核）取樣**：不考慮所有可能的詞，只看機率加總達到我們所設門檻（例如前 90%）的最可能詞彙
4. **Top-k 過濾**：另一種做法，只考慮最有可能的 k 個下一個詞

### 管理重複：讓輸出保持新鮮

LLM 常見的一個挑戰，是它們傾向於重複自己——就像演講者不斷回到同樣的重點。為了解決這個問題，我們使用兩種懲罰：

1. **存在懲罰**：對任何先前出現過的標記施加固定懲罰，不論出現的頻率高低。這有助於避免模型重複使用相同的詞。
2. **頻率懲罰**：一種隨標記使用次數增加而遞增的懲罰。一個詞出現得越多，再次被選取的可能性就越低。

![image](https://huggingface.co/reasoning-course/images/resolve/main/inference/2.png)

這些懲罰會在標記選擇過程的早期套用，在其他取樣策略生效之前先調整原始機率。你可以把它們想成一種溫和的推力，鼓勵模型探索新的詞彙。

### 控制生成長度：設定邊界

就像一個好故事需要適當的節奏與篇幅，我們也需要方法來控制 LLM 生成多少文字。這對實際應用非常關鍵——無論是要生成推文長度的回應，還是完整的部落格文章。

我們可以用幾種方式來控制生成長度：
1. **Token 數量限制**：設定最少與最多的 token 數
2. **停止序列**：定義特定模式，用來標示生成結束
3. **序列結束偵測**：讓模型自然地結束它的回應

舉例來說，如果我們想生成單一段落，可以設定最多 100 個 token，並以 "\n\n" 作為停止序列。這樣能確保輸出保持聚焦，且長度適合其用途。

![image](https://huggingface.co/reasoning-course/images/resolve/main/inference/3.png)

### 束搜尋：往前看，換取更好的連貫性

我們到目前為止討論的策略，都是一次決定一個標記，而束搜尋則採取更全面的方式。它不會在每一步都只選定單一選項，而是同時探索多條可能的路徑——就像棋手會往前思考好幾步棋一樣。

![image](https://huggingface.co/reasoning-course/images/resolve/main/inference/4.png)

運作方式如下：
1. 每一步都維持多個候選序列（通常是 5 到 10 個）
2. 針對每個候選序列，計算下一個標記的機率
3. 只保留最有希望的序列與下一個標記的組合
4. 持續這個過程，直到達到期望的長度或停止條件
5. 選出整體機率最高的序列

## 實際挑戰與最佳化

在結束對 LLM 推論的探討之際，讓我們來看看部署這些模型時會遇到的實際挑戰，以及如何衡量並最佳化它們的效能。

### 關鍵效能指標

使用 LLM 時，有四個關鍵指標會影響你的實作決策：

1. **首個標記時間（Time to First Token，TTFT）**：你多快能拿到第一個回應？這對使用者體驗非常關鍵，且主要受預填充階段影響。
2. **每個輸出標記時間（Time Per Output Token，TPOT）**：後續的標記能生成得多快？這決定了整體的生成速度。
3. **吞吐量**：你能同時處理多少個請求？這會影響可擴展性與成本效益。
4. **VRAM 使用量**：你需要多少 GPU 記憶體？在實際應用中，這通常會成為主要的限制。

### 上下文長度的挑戰

LLM 推論中最重大的挑戰之一，就是有效管理上下文長度。較長的上下文能提供更多資訊，但也伴隨相當大的成本：

- **記憶體使用量**：隨上下文長度呈二次方成長
- **處理速度**：上下文越長，速度呈線性下降
- **資源配置**：需要謹慎平衡 VRAM 的使用

像 [Qwen2.5-1M](https://huggingface.co/Qwen/Qwen2.5-14B-Instruct-1M) 這樣的近期模型，提供了多達 100 萬標記的上下文視窗，相當可觀，但代價是推論速度明顯變慢。關鍵在於為你的特定使用案例找到合適的平衡。

### KV 快取最佳化

為了應對這些挑戰，最強大的最佳化技術之一是 KV（鍵值）快取。這項技術透過儲存並重複使用中間計算結果，大幅提升推論速度。這項最佳化能夠：
- 減少重複計算
- 提升生成速度
- 讓長上下文的生成變得可行

代價是需要額外的記憶體，但效能上的好處通常遠遠超過這項成本。

## 結論

理解 LLM 推論，對於有效部署並最佳化這些強大的模型非常重要。我們已經涵蓋了這些關鍵元件：

- 注意力與上下文的基礎作用
- 兩階段推論過程
- 控制生成的各種取樣策略
- 實際挑戰與最佳化

掌握這些概念後，你就能更有能力打造出有效且高效運用 LLM 的應用程式。

請記住，LLM 推論領域正快速演進，新的技術與最佳化方法不斷出現。保持好奇心，持續嘗試不同做法，找出最適合你特定使用案例的方案。
